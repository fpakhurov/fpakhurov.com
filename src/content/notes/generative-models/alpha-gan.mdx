A generator can produce a plausible object without telling us how to encode an observed one. Adding an encoder supplies that route, but creates another distribution to control: the codes obtained from actual inputs may occupy a different region from the noise used for generation. A reconstruction can be accurate while a fresh sample is poor.

Consider a small sensor with readings −2, 1 and 7 occurring with probabilities 1/2, 1/3 and 1/6. We will compress them into three codes. All quantities can be enumerated, so reconstruction quality and code-distribution matching can be examined separately before considering images.

## What each family is missing \{#what-each-family-is-missing\}

Let $P$ be the data distribution, $p(z)$ the chosen prior, $q(z\mid x)$ an encoder distribution and $G(z)$ a deterministic decoder. A deterministic encoder is the special case $z=E(x)$; a noisy encoder can instead use $z=E(x,\varepsilon)$. Averaging over data gives the **aggregate posterior**:

$$
q(z)=\mathbb E_{x\sim P}q(z\mid x).
$$

The word posterior here names the encoder distribution. Training an autoencoder does not automatically make it the exact Bayesian posterior of a specified generative model.

A [VAE](/notes/generative-models/vae#where-the-elbo-comes-from) defines a decoder likelihood and penalizes each conditional encoder distribution relative to the prior. When the KL terms are finite, splitting the density ratio inside the logarithm gives

$$
\begin{aligned}
\mathbb E_P D_{\mathrm{KL}}(q(z\mid x)\|p(z))
&=I_q(X;Z)+D_{\mathrm{KL}}(q(z)\|p(z)),\\
\log\frac{q(z\mid x)}{p(z)}
&=\log\frac{q(z\mid x)}{q(z)}+\log\frac{q(z)}{p(z)}.
\end{aligned}
$$

The first averaged log ratio measures information about the input; the second measures marginal mismatch. A discriminator that sees only a code cannot inspect the first term. Replacing the full conditional KL by marginal matching therefore changes the objective.

Reconstruction loss also depends on its definition. Squared error selects the conditional mean: differentiating the expected squared distance to a proposed reconstruction gives twice its difference from that mean. Absolute error selects a median. Averaging different plausible images can smooth detail, but blur is not a theorem about every VAE. Likewise, an adversarial image objective does not guarantee sharpness, coverage or successful optimization.

## Adversarial autoencoders: a discriminator on codes \{#adversarial-autoencoders-a-discriminator-on-codes\}

An **adversarial autoencoder**, introduced by [Makhzani et al.](#references), combines reconstruction with a classifier distinguishing prior samples from encoded data. Call this classifier $C(z)$ and give prior samples the positive label. With equal class weights, its minimized binary loss is

$$
L_C=-\mathbb E_p\log C(Z)-\mathbb E_q\log(1-C(Z)).
$$

At a fixed code, differentiate with respect to its predicted probability. Setting the derivative to zero gives

$$
\begin{aligned}
-\frac{p(z)}{C}+\frac{q(z)}{1-C}&=0,\\
C^*(z)&=\frac{p(z)}{p(z)+q(z)}.
\end{aligned}
$$

The differentiation assumes positive p and q. At a zero boundary mass, the same optimum follows by choosing the appropriate endpoint probability. The pointwise formula assumes an unrestricted classifier and positive total mass. A finite trained network only approximates it. The encoder receives a separate adversarial update, often minimizing the non-saturating loss $-\mathbb E_q\log C(Z)$ while the classifier's parameters are frozen. The classifier must remain differentiable with respect to its input so that gradients can reach the encoder.

Reconstruction constrains the pairing between an input and its decoded code. The code game constrains how frequently regions of code space are used. Under the ideal conditions $q=p$ and $G(Z)=X$ almost surely for the encoder's joint distribution, generation is correct: $Z\sim p$ has the same distribution as an encoded code, whose decoded value has distribution $P$. Either condition alone is insufficient.

### What the code discriminator matches \{#what-the-code-discriminator-matches\}

Choose the following stochastic encoder for the sensor readings. Each row sums to one.

| Reading | Probability | Code 0 | Code 1 | Code 2 |
|---|---:|---:|---:|---:|
| −2 | 1/2 | 1 | 0 | 0 |
| 1 | 1/3 | 0 | 1/2 | 1/2 |
| 7 | 1/6 | 0 | 0 | 1 |

Multiplying each row by its input probability and summing columns yields aggregate probabilities 1/2, 1/6 and 1/3. Against a uniform prior, the three KL quantities, in nats, are

$$
\begin{aligned}
\mathbb E_P D_{\mathrm{KL}}(q(z\mid x)\|p(z))&\approx0.867563228481,\\
I_q(X;Z)&\approx0.780355204521,\\
D_{\mathrm{KL}}(q(z)\|p(z))&\approx0.087208023961.
\end{aligned}
$$

The first number is the sum of the other two. For code 2, readings 1 and 7 each contribute joint probability 1/6. The least-squares decoder consequently returns their mean, 4; the other two reconstructions are −2 and 1. The total mean squared error is 3.

Alternatively, let every input produce a uniformly random code. The aggregate now exactly matches the prior, but the code contains no input information. Every least-squares reconstruction becomes the overall mean, 1/2, with error 41/4. A perfect code-distribution match has not produced useful reconstruction.

## α-GAN: a discriminator on images as well \{#alpha-gan-a-discriminator-on-images-as-well\}

[Rosca et al.](#references) add an image discriminator to the encoder, decoder and code discriminator. Their hybrid objective combines reconstruction with discriminator log odds; their practical procedure also presents fresh prior-generated samples to the image discriminator. This adds a distributional test of decoded objects alongside the paired reconstruction test.

Write $\hat X=G(Z_q)$ for a reconstruction, where $X\sim P$ and $Z_q\sim q(z\mid X)$, and $\tilde X=G(Z_p)$ for a fresh sample, where $Z_p\sim p$. Define $R$ as the distribution of reconstructions and $S$ as that of fresh samples. An explicitly normalized fake mixture is

$$
M=\tfrac12 R+\tfrac12 S.
$$

With equal real/fake class weights, the image-classifier optimum is $D^*(x)=P(x)/(P(x)+M(x))$, using masses or densities where defined. Its log odds compare the real marginal with this fake mixture. They do not evaluate a conditional decoder likelihood for each input.

For a concrete hybrid convention, let $\ell_D(x)=\log(D(x)/(1-D(x)))$ and define $\ell_C$ similarly. Use these finite log-odds expressions on common positive real/fake and prior/code support, with both classifier outputs strictly between zero and one. We can minimize

$$
\begin{aligned}
L_{EG}={}&\lambda\mathbb E\|X-\hat X\|_1\\
&-\mathbb E\ell_D(\hat X)-\mathbb E\ell_D(\tilde X)\\
&-\eta\mathbb E\ell_C(Z_q),
\end{aligned}
$$

with positive weights $\lambda,\eta$. This states the reduction convention; coefficients and update schedules vary between implementations. A normalized discriminator mixture and two unnormalized generator terms can coexist, but their scale must be documented. Practical approximate classifiers and a code-only marginal ratio do not turn this hybrid loss into an exactly computable ELBO.

### Why all three parts are needed \{#why-all-three-parts-are-needed\}

The sensor example already separates code matching from reconstruction. We can also keep the aggregate code probabilities fixed and change the decoder to return one constant. The code discriminator sees the same inputs, while reconstructions and generated samples collapse. An image discriminator can detect the resulting marginal error; it cannot determine which original reading should correspond to a particular reconstruction.

Class weights affect the meaning of its probabilities. If real examples have effective class probability $\pi$, with $0<\pi<1$, Bayes' rule gives

$$
\begin{aligned}
D^*(x)&=\frac{\pi P(x)}{\pi P(x)+(1-\pi)M(x)},\\
\frac{P(x)}{M(x)}&=\frac{1-\pi}{\pi}\frac{D^*(x)}{1-D^*(x)}.
\end{aligned}
$$

One equally weighted real batch and two equally weighted fake batches correspond to $\pi=1/3$. The log odds then differ from the log density ratio by $-\log 2$. This offset does not change a generator gradient when fixed, but it changes reported values and any claim that those values directly equal a KL. Weighting the real loss twice restores equal total class weights.

## α-WGAN: two Wasserstein critics \{#alpha-wgan-two-wasserstein-critics\}

[Kwon, Han and Kim](#references) use real-valued Wasserstein critics for images and codes in an autoencoding GAN. A critic output is a score, not a class probability, so it has no discriminator-odds interpretation. With $D$ for images and $C$ for codes, their two-fake-stream convention leads to the minimized losses

$$
\begin{aligned}
L_D={}&\mathbb E D(\hat X)+\mathbb E D(\tilde X)\\
&-2\mathbb E D(X)+\gamma_x\operatorname{GP}_D,\\
L_C={}&\mathbb E C(Z_q)-\mathbb E C(Z_p)\\
&+\gamma_z\operatorname{GP}_C,\\
L_{EG}={}&\lambda\mathbb E\|X-\hat X\|_1\\
&-\mathbb E D(\hat X)-\mathbb E D(\tilde X)\\
&-\mathbb E C(Z_q).
\end{aligned}
$$

The doubled real term balances the two fake expectations. Dividing that critic objective by two also changes the relative penalty coefficient unless it is rescaled. Adding a constant to a critic leaves its balanced real/fake difference unchanged; it shifts the numerical generator loss by a constant while leaving its parameter gradients unchanged.

For a critic $f$, the gradient penalty introduced by [Gulrajani et al.](#references) uses interpolation points $U$ between the distributions being compared:

$$
\operatorname{GP}_f=\mathbb E_U(\|\nabla f(U)\|_2-1)^2.
$$

The image penalty must specify how its endpoints sample the two fake streams. This is a soft sampled penalty, not proof of a global Lipschitz bound. Training-mode batch normalization also makes a critic's output depend on other batch items, conflicting with a simple per-example gradient interpretation; the WGAN-GP paper uses alternatives without that coupling.

## Worked example: a code critic in one dimension \{#worked-example-a-code-critic-in-one-dimension\}

For our three code locations 0, 1 and 2, the uniform prior and encoded distribution give optimal equal-class probabilities 2/5, 2/3 and 1/2. If prior examples instead receive effective class probability 1/3, the values become 1/4, 1/2 and 1/3. Multiplying their odds by two restores the same prior-to-aggregate ratios.

A small parametric change makes the gradient explicit. Set

$$
q_\theta=(\theta,(1-\theta)/3,2(1-\theta)/3),\quad 0<\theta<1.
$$

At $\theta=1/2$, differentiate the finite KL sum. Terms from differentiating the normalization cancel, leaving

$$
\begin{aligned}
K'(\theta)&=\sum_j q'_\theta(j)\log\frac{q_\theta(j)}{p(j)},\\
K'(1/2)&=\log(3/2)-\tfrac13\log(1/2)\\
&\approx0.636514168295.
\end{aligned}
$$

A step of size 0.1 changes the parameter to about 0.436348583171 and decreases marginal KL from 0.087208023961 to 0.054818030399. This is an enumerated probability-vector update, not backpropagation through a discrete sampling operation. With the classifier held at its current exact optimum, differentiating the expectation of negative log odds gives this same local derivative. Differentiating an arbitrary trained classifier need not do so.

Geometry changes the objective. On these unit-spaced code locations, the one-dimensional transport cost is the sum of absolute cumulative-mass differences. It equals 1/6: the aggregate has excess mass 1/6 at code 0 and a matching deficit at code 1, so that mass moves one unit. For the linear critic $C_a(z)=az$, the prior-minus-aggregate expectation is $a/6$. A hard unit Lipschitz constraint allows at most 1/6. A soft penalty with coefficient 2 instead maximizes

$$
\begin{aligned}
J(a)&=a/6-2(|a|-1)^2,\\
a^*&=25/24,\\
J(a^*)&=49/288>1/6.
\end{aligned}
$$

On the positive branch, differentiating gives $1/6-4(a-1)=0$; the negative branch gives a smaller value. The maximizing slope exceeds one. Thus a penalized training score need not equal the Wasserstein distance even when every expectation is exact.

## Training: four networks, three optimizers \{#training-four-networks-three-optimizers\}

A possible implementation groups the encoder and decoder in one optimizer and gives each critic its own optimizer. That grouping is an implementation choice, not a defining theorem about α-GAN. Separate losses and gradient paths still need explicit control.

During critic updates, treat encoded codes, reconstructions and prior samples as fixed inputs. Detaching them prevents unintended encoder/decoder updates. During the joint encoder–decoder update, freeze critic parameters but retain differentiation through critic inputs. Detaching the critic output would remove the adversarial signal entirely. The fresh-sample image term updates the decoder; the reconstruction image term can update both networks; the code term updates the encoder.

Clear gradients between phases and recompute forward passes after parameter changes. A previously built graph can refer to stale parameters. Gradient-penalty differentiation also needs the input-gradient computation to remain differentiable with respect to critic parameters. Monitor reconstruction, fresh-sample quality and code mismatch separately: their differently weighted sum can conceal deterioration in one component. Update counts and weights are hyperparameters rather than guarantees of convergence.

## Latent interpolation: lerp or slerp? \{#latent-interpolation-lerp-or-slerp\}

Once observed inputs have codes, we can explore a path between them. Linear interpolation is $z_t=(1-t)u+tv$. For independent standard Gaussian endpoints in $d$ dimensions, independence and zero means give

$$
\mathbb E\|z_t\|^2=d((1-t)^2+t^2).
$$

At the midpoint the expected squared radius is halved. This describes the distribution of random endpoints; it does not say that every particular midpoint is implausible. High-dimensional radius concentration explains why the effect can matter.

For nonzero equal-length endpoints of radius $r$, with angle $0<\omega<\pi$, spherical interpolation is

$$
z_t=\frac{\sin((1-t)\omega)}{\sin\omega}u+\frac{\sin(t\omega)}{\sin\omega}v.
$$

To check its radius, write $u=re_1$ and $v=r(\cos\omega\,e_1+\sin\omega\,e_2)$ in an orthonormal basis. Substitution reduces the path to $r(\cos(t\omega)e_1+\sin(t\omega)e_2)$, whose squared norm is $r^2$.

Use the newly chosen endpoints $u=(2,-1,2)$ and $v=(-2,2,1)$. Both have radius 3 and their angle has cosine −4/9. Their linear midpoint has squared norm 5/2, while the spherical midpoint has norm 3. These are geometric calculations, not measured image-quality results.

<LerpSlerp />

Unequal endpoint lengths require another decision. For endpoints $u$ and $2v$, applying the same sine coefficients directly gives midpoint norm about 5.108815909778. An alternative first interpolates unit directions and then linearly interpolates the radius, giving midpoint radius 4.5. Neither construction automatically preserves a Gaussian prior distribution. Equal-radius paths constrain radius; Gaussian radii themselves vary. [White](#references) motivates spherical paths for generative-model exploration, without supplying a universal guarantee for every learned decoder.

At coincident directions, use the continuous limiting direction. At exactly opposite directions the shortest great-circle path is not unique; choose and document an orthogonal direction. Zero vectors have no direction. Near these cases, a numerical implementation needs explicit tolerances rather than division by a nearly zero sine.

## Where it breaks \{#where-it-breaks\}

A classifier reporting chance performance may be weak, undertrained or evaluated on an inappropriate sample. It does not establish equality of distributions. Evaluate a separate held-out discriminator if using such a test, and remember that its failure to distinguish is still relative to its hypothesis class and statistical power.

A deterministic encoder applied to a finite empirical dataset produces a finite atomic code distribution. It cannot exactly equal an atomless Gaussian prior. More generally, a Lipschitz image of an intrinsically lower-dimensional smooth data manifold has zero higher-dimensional volume, so it cannot acquire a full-dimensional density merely by increasing code width. Such distributions can be singular even when their topological supports intersect. Added encoder noise changes this restriction and the reconstruction problem. Take a compact coordinate subset of dimension $m<d$ on which the smooth chart has bounded derivative. Composing this chart with the Lipschitz encoder is Lipschitz. The coordinate subset needs $O(\delta^{-m})$ small boxes. A Lipschitz map sends each into a ball of radius $O(\delta)$, so their total ambient volume is $O(\delta^{d-m})\to0$. A countable covering by such patches preserves the zero-volume conclusion.

Reconstruction pressure can discourage some forms of collapse without proving generalization or protecting rare examples in a weighted average. Marginal matching leaves the meaning and ordering of codes unidentified. A visually smooth interpolation does not certify disentanglement, calibrated likelihood or a semantically correct path. Image and medical-data benchmarks additionally require their own data access, privacy and evaluation procedures; the finite calculations here establish none of those outcomes.

## What changed \{#what-changed\}

Compared with a generator-only GAN, the encoder provides an input-dependent code and a paired reconstruction objective. AAE adds a marginal code constraint; α-GAN additionally evaluates decoded objects adversarially. Wasserstein critics change the comparison and its geometry. These choices introduce distinct tests and optimization problems rather than a single guarantee of sample quality.

## What you should remember \{#what-you-should-remember\}

- Code-only discrimination tests the aggregate posterior, not every conditional distribution.
- Reconstruction and marginal matching need separate checks.
- Class weights determine the probability-to-density-ratio correction.
- Wasserstein scores are not classifier probabilities; a soft penalty is not a hard bound.
- Interpolation geometry and prior sampling are different contracts.

## Code \{#notebook\}

The following independent standard-library calculation checks the code-classifier values and marginal KL. It uses the explicit finite probabilities above and downloads nothing.

```python
from fractions import Fraction as F
from math import log

p = [F(1, 3)] * 3
q = [F(1, 2), F(1, 6), F(1, 3)]
balanced = [a / (a + b) for a, b in zip(p, q)]
skewed = [a / (a + 2*b) for a, b in zip(p, q)]
assert [2*c/(1-c) for c in skewed] == [a/b for a,b in zip(p,q)]
kl = sum(float(b)*log(float(b/a)) for a,b in zip(p,q))
print('equal class weights:', ', '.join(map(str, balanced)))
print('prior class probability 1/3:', ', '.join(map(str, skewed)))
print('marginal KL: %.12f' % kl)
```

```text
equal class weights: 2/5, 2/3, 1/2
prior class probability 1/3: 1/4, 1/2, 1/3
marginal KL: 0.087208023961
```
