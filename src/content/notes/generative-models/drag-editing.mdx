You have a photo of a cat and want its ear a little higher. A text prompt can describe the move, but does not reliably enforce an exact displacement such as "40 pixels up". The [editing tools of latent diffusion](/notes/generative-models/latent-diffusion#editing-with-the-same-model) provide several kinds of control; here the input is explicitly geometric: a **handle point** $p$ on the object and a **target point** $g$ where it should end up.

Moving pixels alone leaves a hole at the old position and requires filling the newly exposed region. Point-based generative editing instead changes a model's *latent code*. **DragGAN** ([Pan et al., 2023](#references)) edits the code of StyleGAN2; **DragDiffusion** ([Shi et al., 2024](#references)) edits a noisy Stable Diffusion latent. The latter covers a broader range of scenes, but reconstruction and precise control remain imperfect.

## What a drag edit asks for

The user gives handles $p_1, \dots, p_n$, their targets $g_1, \dots, g_n$ (we write $g$ for "goal" because $t$ will be a diffusion step), and optionally a binary mask $M$, equal to 1 where the image may change. The result should be **precise**, with each handle ending at its target, and **general**, working for any object the model knows. A [conditional GAN](/notes/generative-models/gans#conditional-gan) driven by face keypoints is specialized to that kind of input and does not by itself ensure arbitrary-object control.

The tool brings one more property. If every intermediate image is an output of a pretrained generator, the generator acts as a prior: when DragGAN opens a lion's mouth, teeth appear inside. The prior is only a tendency. Being in the generator's range is weaker than lying where its training data put mass, and an optimized code can drift into regions that produce artefacts or change a person's identity.

Two things remain to be built. We need a differentiable way to say "this point should move one step that way", and a way to know where the point is after each step.

## The generator DragGAN edits \{#the-stylegan2-generator-in-brief\}

DragGAN uses a StyleGAN2 trained on one category: faces, cats, cars. Two of its properties, derived in the [StyleGAN note](/notes/generative-models/stylegan), matter here.

The first is the extended latent space $\mathcal W^+$. Each synthesis-layer style has its own code $w_j \in \mathbb R^{512}$. The [style-mixing experiments](/notes/generative-models/stylegan#style-mixing-coarse-middle-and-fine-styles) show a tendency for early styles to affect coarse structure and later styles to affect texture. DragGAN optimizes only $w_1,\dots,w_6$ to favor geometric changes; this does not guarantee unchanged color or identity.

The second is that generator features can distinguish positions. Let $F_q(w) \in \mathbb R^C$ denote the feature at image position $q$, obtained by resizing the sixth synthesis block's $256\times256$ map. Bilinear interpolation provides values between grid points and piecewise derivatives with respect to coordinates. The block choice is an empirical result of the paper's ablation, not a universal rule for other generators.

## Editing a real photo: GAN inversion

A generated image comes with its code. A photograph $x$ does not, so it is first **inverted**: we look for the code whose image reproduces it,

$$
w^* = \arg\min_{w}\ \ell\big(G(w),\ x\big),
$$

where $\ell$ is an image distance, often [LPIPS](/notes/generative-models/lpips) plus squared error ([Xia et al., 2023](#references)). Per-image optimization spends compute fitting the code; an encoder $E:x\mapsto w$ amortizes this work into training and a forward pass. Their reconstruction and editing quality depend on the encoder, objective, latent space and compute budget.

The space matters. $\mathcal W^+$ has more degrees of freedom than $\mathcal W$, which can improve reconstruction. Codes far from the mapping network's usual outputs can be harder to edit: the desired transformation need not remain well behaved there. This is the distortion–editability trade-off discussed in the survey.

**Pivotal tuning inversion** (PTI, [Roich et al., 2022](#references)) first finds a pivot $w_p$ in $\mathcal W$, then fixes it and fine-tunes generator weights to improve reconstruction. A locality penalty discourages changes at sampled codes around the pivot; it does not keep the generator exactly unchanged everywhere else. DragGAN's real-photo pipeline uses this preparation before optimizing the drag code.

Inversion limits a category-specific editor. A solver can return a code for an out-of-domain photo, but a face generator cannot faithfully reproduce arbitrary full-body scenes or vehicles merely because an optimization ran.

## DragGAN: motion supervision and point tracking

DragGAN starts from $w_0$, features $F^0=F(w_0)$ and initial handles $p_i^0$. **Motion supervision** updates the code toward a local feature-matching target; **point tracking** then estimates the new handle positions. During this drag stage, the prepared generator weights remain fixed. The method exposition and schematic below adapt [Pan et al.'s paper, v2](https://arxiv.org/abs/2305.10973v2), licensed [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); [attribution and changes](/licenses/draggan-paper.txt) identify the scope. The numeric toy is a separate project fixture, not the paper's experiment.

### Motion supervision

Let $d_i = (g_i - p_i)/\lVert g_i - p_i \rVert_2$ be the unit vector from a handle to its goal, $\Omega_1(p, r_1)$ the disc of grid positions at distance strictly less than $r_1$ from $p$, and $\mathrm{sg}[\cdot]$ the **stop-gradient**: its value passes forward, its gradient is zero. The loss of one iteration is

$$
\begin{aligned}
\mathcal L(w) = {}&\sum_{i=1}^{n} \sum_{q \in \Omega_1(p_i, r_1)} \big\lVert F_{q + d_i}(w) - \mathrm{sg}\big[F_q(w)\big] \big\rVert_1 \\
&+ \lambda\, \big\lVert \big(F(w) - F^0\big) \odot (1 - M) \big\rVert_1 ,
\end{aligned}
$$

where $\lVert \cdot \rVert_1$ is the sum of absolute values. The first term compares the patch of features around each handle with the same patch shifted by one pixel toward the goal. The second, used when a mask is drawn, penalizes changes to features outside the movable region. When a handle reaches its goal, $d_i$ is set to 0 and its term vanishes.

### Why the reference is frozen

The stop-gradient decides the direction of the edit. Take one position $q$ and one channel, and write $a = F_{q + d}(w)$ for the shifted feature and $b = F_q(w)$ for the reference. With the reference frozen, the term is $|a - \mathrm{sg}[b]|$, and the chain rule through $a$ alone, with $d|y|/dy = \operatorname{sign}(y)$, gives its gradient. One gradient step with learning rate $\eta$ then changes $a$, to first order, by

$$
\begin{aligned}
\nabla_w \mathcal L &= \operatorname{sign}(a - b)\, \nabla_w a \\
w' - w &= -\eta\, \operatorname{sign}(a - b)\, \nabla_w a \\
a' - a &\approx (\nabla_w a)^\top (w' - w) \\
&= -\eta\, \operatorname{sign}(a - b)\, \lVert \nabla_w a \rVert^2 .
\end{aligned}
$$

The third line is a first-order Taylor expansion. For a nonzero residual and a sufficiently small step, it moves $a$ toward the *current frozen value* of $b$. At zero residual we use the zero subgradient of the absolute value. After updating $w$, both features are recomputed; neither an exact one-pixel displacement nor monotonic decrease of the recomputed loss follows from this local calculation.

To see that this is a *forward* motion, take a generator that only translates its content: $F_x(s) = \phi(x - s)$ for a bump $\phi$ centred at a position $s$, the latent. Write $u = q - s$. The reference is $b = \phi(u)$, and the frozen-reference loss is zero when $\phi(q + d - s') = \phi(u)$, which holds at $s' = s + d$: the bump shifted by one step toward the goal. (A symmetric bump also matches at a mirrored position; a second, odd channel such as the one in the example below rules it out.) Away from a stationary point, with $\phi'(u)\ne0$, and for a sufficiently small nonzero $d$, the gradient at the current $s$ has a fixed sign on either flank:

$$
\begin{aligned}
a - b &= \phi(u + d) - \phi(u) \approx d\, \phi'(u) \\
\operatorname{sign}(a - b) &= \operatorname{sign}(d)\, \operatorname{sign}\big(\phi'(u)\big) \\
\frac{\partial a}{\partial s} &= -\phi'(u + d) \approx -\phi'(u) \\
\frac{\partial \mathcal L}{\partial s} &= \operatorname{sign}(a - b)\, \frac{\partial a}{\partial s} \\
&\approx -\operatorname{sign}(d)\, \operatorname{sign}\big(\phi'(u)\big)\, \phi'(u) \\
&= -\operatorname{sign}(d)\, \lvert \phi'(u) \rvert .
\end{aligned}
$$

The first line is a Taylor expansion in $d$. The second takes its sign with $\operatorname{sign}(xy) = \operatorname{sign}(x)\, \operatorname{sign}(y)$: the size of $d$ drops out, and only its direction and the sign of the slope remain. The third line is the chain rule with $\partial(x - s)/\partial s = -1$. The fifth substitutes the second and the third, and in the last the sign of the slope meets the slope itself: $\operatorname{sign}(y)\, y = |y|$ cancels it. Gradient descent changes $s$ by $+\eta\, \operatorname{sign}(d)\, |\phi'(u)|$: toward the goal in this local approximation on either flank. At stationary points the first-order sign argument does not apply, and finite updates can overshoot.

Without stop-gradient the derivative is $\operatorname{sign}(a-b)(\nabla_w a-\nabla_w b)$. In a smooth translation field, nearby positions can have similar Jacobians, so this subtraction can cancel much of the update or reverse its direction. This is a mechanism illustrated by the following fixture, not a claim that every learned feature map has nearly identical neighboring derivatives.

**Worked example.** Take a bump of width $\sigma = 2$ read in two channels,

$$
\begin{aligned}
F_x(s) &= \Big(\phi(x - s),\ \tfrac{x - s}{\sigma}\, \phi(x - s)\Big), \\
\phi(u) &= e^{-u^2 / (2\sigma^2)} ,
\end{aligned}
$$

where the second channel tells the left flank from the right one. Let $s = 0$, the handle $p = 1$, the goal $g = 4$, so $d = 1$, and a patch of one position, $\Omega_1 = \{1\}$ (toy numbers):

| Quantity | Value |
| --- | --- |
| reference $F_1(0)$ | $(0.8825,\ 0.4412)$ |
| shifted feature $F_2(0)$ | $(0.6065,\ 0.6065)$ |
| loss | $0.276 + 0.165 = 0.441$ |
| $\partial \mathcal L / \partial s$ with the stop-gradient | $-0.3033$ |
| $\partial \mathcal L / \partial s$ without it, first channel only | $-0.0826$ |
| $\partial \mathcal L / \partial s$ without it, both channels | $+0.2483$ |

With the stop-gradient, descent increases $s$ and the bump moves toward the goal. The frozen-reference loss is a sum of absolute values, so it is never negative. At $s = 1$ it is zero, because the generator only translates: $F_2(1)$ reads the bump at $u = 1$, as $F_1(0) = b$ does. Zero is the smallest possible value, so the shift by $d$ is a minimum. It is the only one: the first channel matches only at $u = \pm 1$, that is $s = 1$ or $s = 3$, and at $s = 3$ the second channel has the wrong sign. The Code section gives $0.253$ at $s = 0.5$ and $0.286$ at $s = 1.5$. Without it, the first channel alone still pushes forward, 3.7 times more weakly, and the second channel flips the sign: descent moves the bump away from the goal.

### Point tracking

After the step the content has moved, by an amount the loss does not fix: one gradient step can move it by less than a pixel or by more. If the next step supervised the old position, it would push the wrong content. DragGAN therefore re-locates each handle by nearest-neighbour search in feature space,

$$
p_i \leftarrow \arg\min_{q \in \Omega_2(p_i, r_2)} \big\lVert F_q(w') - f_i \big\rVert_1 ,
$$

where $w'$ is the updated code, $f_i = F_{p_i^0}(w_0)$ the feature of the handle in the original image, and $\Omega_2(p, r_2)$ the square of grid positions at distance strictly less than $r_2$ from $p$ along each axis. Keeping the original feature avoids replacing it by a drifting sequence of references; it does not prevent a wrong match or a drifting search window.

In the worked example, after the bump has moved to $s = 1$, the candidates $x = -1, 0, 1, 2, 3$ have distances $1.324, 0.882, 0.559, 0, 0.441$ to $f = (0.8825, 0.4412)$, and the handle is found at $x = 2 = p + d$. On the paper's face test, which moves the landmarks of one generated face onto those of another, a single handle ends 2.44 pixels from its goal on average, against 12.93 before editing; with an optical-flow network (RAFT) as the tracker it ends 13.43 pixels away ([Pan et al., 2023](#references), Table 1).

### The loop

The optimizer is Adam on the six codes. For a $512 \times 512$ image the paper uses $r_1 = 3$, $r_2 = 12$ and $\lambda = 20$, and stops when every handle is within 1 pixel of its goal, or 2 pixels when there are more than five handles. The authors report roughly 30 to 200 iterations and a few seconds in their hardware configuration; this is not a runtime guarantee. The toy below runs the whole loop in two dimensions, with the position of a blob as the latent.

## DragDiffusion: the same loop in a diffusion latent

DragGAN edits only what a category-specific GAN can draw. A text-to-image diffusion model covers far more images, but it has no single code like $w$: an image is the end of a chain of denoising steps. DragDiffusion keeps DragGAN's two sub-steps and changes the variable: one noisy latent of Stable Diffusion 1.5 at one intermediate step ([Shi et al., 2024](#references)). The diffusion symbols $z_t$, $\bar\alpha_t$, $\varepsilon_\theta$ and the text encoder $\tau$ are those of the [latent diffusion note](/notes/generative-models/latent-diffusion#diffusion-in-the-latent).

1. Identity-preserving fine-tuning trains LoRA weights of the U-Net on the input image alone.
2. DDIM inversion turns the image latent $z_0$ into the noisy latent $z_{35}$, 35 steps of a 50-step schedule away from the image.
3. Latent optimization moves the handles by motion supervision and point tracking on U-Net features; only $z_{35}$ changes.
4. Denoising with reference-latent-control takes the edited latent back to an image, borrowing keys and values from the denoising of the original latent.

### Identity-preserving fine-tuning

Inverting a photo and denoising it again does not return exactly the photo, and after an edit the gap grows. Before editing, DragDiffusion fine-tunes the U-Net on the one image with [LoRA](/notes/nlp/peft#lora-a-low-rank-update) updates $\Delta\theta$ of rank 16 in the attention projections. The loss is the usual noise-prediction objective restricted to the single latent $z_0$ of the photo,

$$
\mathcal L_{\text{ft}}(\Delta\theta) = \mathbb E_{\varepsilon, t}\Big[\big\lVert \varepsilon - \varepsilon_{\theta + \Delta\theta}(z_t,\ t,\ \tau(y))\big\rVert_2^2\Big] ,
$$

with $z_t = \sqrt{\bar\alpha_t}\, z_0 + \sqrt{1 - \bar\alpha_t}\, \varepsilon$, frozen weights $\theta$ and a short prompt $y$ that describes the image. The authors use 80 updates and report about 25 seconds on an A100. Their ablation supports better reconstruction and identity preservation; fine-tuning does not guarantee either.

### DDIM inversion to a single step

Sampling with [DDIM](/notes/generative-models/latent-diffusion#fewer-steps) is deterministic when its added-noise parameter is zero ($\eta=0$). Here indices count positions of the chosen sampling schedule, so $\bar\alpha_t$ is the cumulative noise coefficient at that selected level, not necessarily training timestep $t$. One step predicts the clean latent and re-noises it to the next level along the predicted noise:

$$
\begin{aligned}
\hat z_0(z_t) &= \frac{z_t - \sqrt{1 - \bar\alpha_t}\; \varepsilon_\theta(z_t, t)}{\sqrt{\bar\alpha_t}} , \\
z_{t-1} &= \sqrt{\bar\alpha_{t-1}}\; \hat z_0(z_t) + \sqrt{1 - \bar\alpha_{t-1}}\; \varepsilon_\theta(z_t, t) .
\end{aligned}
$$

**DDIM inversion** runs the same update upward, from $z_t$ to $z_{t+1}$, with the noise predicted at $z_t$ standing in for the noise at the unknown $z_{t+1}$. The substitution is an approximation: it is accurate only to the extent that the prediction changes little across the adjacent states and levels. Smaller steps can help but do not ensure exact recovery ([Song, Meng and Ermon, 2021](#references), Section 4.3). DragDiffusion inverts for 35 of 50 steps and edits $z_{35}$; classifier-free guidance is switched off for real photos, because it amplifies the inversion error.

**A scalar round trip.** Choose two levels with $\bar\alpha_A=0.64$, $\bar\alpha_B=0.36$, start at $z_A=1$, and define the toy predictor $\varepsilon_\theta(z,t)=z/2$. These are independently specified scalar inputs, not a trained diffusion model. The upward step gives

$$
\begin{aligned}
\hat z_0^A &= \frac{1-0.6(0.5)}{0.8}=0.875, \\
z_B &= 0.6(0.875)+0.8(0.5)=0.925.
\end{aligned}
$$

The downward step recomputes the prediction as $0.925/2=0.4625$. Consequently $\hat z_0^B=(0.925-0.8(0.4625))/0.6=0.925$, and $z_A'=0.8(0.925)+0.6(0.4625)=1.0175$. Reusing the old prediction $0.5$ would return exactly 1, but evaluating the predictor at the new state does not. Determinism alone is not invertibility of these discrete updates.

The paper motivates a single editable latent by the tendency of coarse structure to form early in denoising. It avoids differentiating through the whole sampling chain. Its timestep ablation finds a trade-off between movement and identity preservation; neither the preferred step nor this behavior is guaranteed for other models and images.

### Latent optimization on U-Net features

Motion supervision carries over with the latent in place of $w$ and the features of the U-Net's third upsampling block in place of the generator's. Here $\Omega(p,r)$ is a **square** of grid positions with each coordinate difference at most $r$, unlike DragGAN's strict disc. With $\hat z_t^k$ the latent after $k$ updates and $\hat z_t^0 = z_t$,

$$
\begin{aligned}
\mathcal L_{\text{ms}}(\hat z_t^k) = {}&\sum_{i=1}^{n} \sum_{q \in \Omega(p_i^k, r_1)} \big\lVert F_{q + d_i}(\hat z_t^k) - \mathrm{sg}\big[F_q(\hat z_t^k)\big] \big\rVert_1 \\
&+ \lambda\, \big\lVert \big(\hat z_{t-1}^k - \mathrm{sg}[\hat z_{t-1}^0]\big) \odot (1 - M) \big\rVert_1 .
\end{aligned}
$$

The stop-gradient plays the role derived above. The mask term acts on latents rather than features, with the mask resized to the latent grid: $\hat z_{t-1}^k$ is one DDIM step of denoising from the current latent and $\hat z_{t-1}^0$ the same step from the unedited one, so outside the mask changes to the next, slightly cleaner latent are penalized. Tracking is DragGAN's nearest-neighbour search, with U-Net features and the original feature $F_{p_i^0}(z_t)$ as the reference. Its tracking square also uses inclusive coordinate bounds. Adam runs for at most 80 steps with $r_1 = 1$, $r_2 = 3$ and $\lambda = 0.1$.

### Reference-latent-control

After optimization, $\hat z_t$ is denoised for the remaining $t$ steps and decoded. **Reference-latent-control** runs the denoising of the original $z_t$ alongside and, in the self-attention layers of the U-Net's upsampling blocks, replaces the keys and values of the edited branch by those of the original:

$$
\begin{aligned}
\hat Q &= \hat\varphi W_Q, \\
K &= \varphi W_K, \\
V &= \varphi W_V, \\
\mathrm{Attention}(\hat Q, K, V) &= \operatorname{softmax}\Big(\frac{\hat Q K^\top}{\sqrt{d_k}}\Big) V ,
\end{aligned}
$$

Here $\hat\varphi$ and $\varphi$ are matrices whose rows are token features of the edited and reference branches; $d_k$ is the key dimension. The output is a weighted mixture of reference values. Queries decide the mixture, so sharing values does not force the same spatial layout or guarantee identity preservation. The mechanism is credited to MasaCtrl ([Cao et al., 2023](#references)).

**Two reference tokens.** Fix $K_1=(1,0)$, $K_2=(0,1)$, $V_1=(2,-1)$, $V_2=(-2,3)$ and $d_k=2$. For query $\hat Q_A=(\sqrt2\log3,0)$ the scaled logits are $(\log3,0)$, so the weights are $(3/4,1/4)$ and the output is $(1,0)$. Swapping the query coordinates gives weights $(1/4,3/4)$ and output $(-1,2)$. Nothing in the reference changed; only its mixture did. This separately specified arithmetic fixture illustrates attention, not image quality.

### Evaluation on DragBench

DragBench has 205 images with 349 handle–target pairs in ten categories ([Shi et al., 2024](#references), Section 4.2 and Appendix A). Two measures pull in opposite directions. **Image fidelity**, $\mathrm{IF} = 1 - \mathrm{LPIPS}(x, x_{\text{edit}})$, is 1 for an unchanged image. **Mean distance** (MD) locates the handle's content in the edited image with diffusion-feature correspondence ([Tang et al., 2023](#references)) and averages its distance to the goal. Doing nothing scores perfect fidelity. IF is an index derived from LPIPS, not a percentage of preserved pixels or a guaranteed [0,1] probability.

In the authors' reported category tables, DragDiffusion has lower MD in all ten categories and higher IF in nine. Their DragGAN baseline selects the generator category using CLIP similarity; upper-body and full-body IF values are 0.33 and 0.31 ([Shi et al., 2024](#references), Appendix I, Tables 1–2). These scores are not percentages of image content preserved, and we have not rerun this benchmark.

## Where it breaks

Tracking can slip where many positions look alike. In the worked example, keep only the first channel, the bump itself, which is symmetric. After the move to $s = 1$, the candidates $x = -1, 0, 1, 2, 3$ have distances $0.276, 0, 0.118, 0, 0.276$ to the handle's original value $0.8825$: the mirror position $x = 0$, on the far flank of the bump, ties with the right answer $x = 2$. The search returns the first minimum, $x = 0$, and the next motion-supervision step pushes the wrong content. Texture-less regions cause the same failure, which is why DragGAN recommends handles on textured parts.

Other failures come from the setup. A few points do not determine a unique edit, and a soft mask penalty does not strictly freeze protected pixels. Optimizing a code can leave the useful part of a generator's range; both methods may miss targets or alter identity. The described real-photo pipelines add per-image PTI or LoRA preparation, while generated inputs already have model latents. An edited photograph is synthetic content, not evidence that the depicted pose or event occurred.

## What you should remember

- A drag edit optimizes a generator's latent; the generator invents the uncovered content.
- Motion supervision: $\lVert F_{q+d}(w) - \mathrm{sg}[F_q(w)] \rVert_1$ sets a local feature target one step toward the goal; the actual movement is determined by optimization and tracking.
- Without stop-gradient, subtraction of neighboring feature Jacobians can weaken or reverse the update.
- Tracking: nearest neighbour of the handle's original feature after every step.
- DragGAN moves $w_1, \dots, w_6$ in $\mathcal W^+$; real photos enter through PTI.
- DragDiffusion: LoRA on the photo, DDIM inversion to $t = 35$ of 50, one latent optimized, keys and values borrowed when denoising.

## Code

The worked example in NumPy, with the gradients written out: the stop-gradient keeps the reference's derivative out of the sum. A finite-difference check confirms both gradients.

```python
import numpy as np

sigma = 2.0

def feat(x, s):
    """Toy generator: a bump at position s, read at positions x; two channels."""
    u = x - s
    phi = np.exp(-u**2 / (2 * sigma**2))
    return np.array([phi, u / sigma * phi])

def dfeat_ds(x, s):
    """Derivative of both channels with respect to the latent s (d/ds = -d/du)."""
    u = x - s
    phi = np.exp(-u**2 / (2 * sigma**2))
    dphi = -u / sigma**2 * phi
    return -np.array([dphi, (phi + u * dphi) / sigma])

p, g, s = 1.0, 4.0, 0.0
d = np.sign(g - p)                              # unit step from the handle toward the goal
a, b = feat(p + d, s), feat(p, s)               # shifted feature and reference
sign = np.sign(a - b)
grad_sg = sign @ dfeat_ds(p + d, s)             # sg[F_p]: only the shifted feature moves
grad_no = sign @ (dfeat_ds(p + d, s) - dfeat_ds(p, s))
print(np.round(b, 4), np.round(a, 4), round(np.abs(a - b).sum(), 4))
print(round(grad_sg, 4), round(grad_no, 4), round(sign[0] * (dfeat_ds(p + d, s) - dfeat_ds(p, s))[0], 4))
# [0.8825 0.4412] [0.6065 0.6065] 0.4412
# -0.3033 0.2483 -0.0826

h = 1e-6                                        # finite-difference check of both gradients
L_sg = lambda t: np.abs(feat(p + d, t) - b).sum()
L_no = lambda t: np.abs(feat(p + d, t) - feat(p, t)).sum()
print(round((L_sg(h) - L_sg(-h)) / (2 * h), 4), round((L_no(h) - L_no(-h)) / (2 * h), 4))
# -0.3033 0.2483
print([round(float(L_sg(t)), 3) for t in (0.5, 1.0, 1.5)])   # zero at s = d
# [0.253, 0.0, 0.286]

# Point tracking once the content has moved by d (s = 1), with both channels and with the first only
xs = np.arange(-1.0, 4.0)                       # strict Omega_2 around p = 1 with r2 = 3
dist2 = np.abs(feat(xs, 1.0) - b[:, None]).sum(0)
dist1 = np.abs(feat(xs, 1.0)[0] - b[0])
print(xs[dist2.argmin()], np.round(dist2, 3))
print(xs[dist1.argmin()], np.round(dist1, 3))
# 2.0 [1.324 0.882 0.559 0.    0.441]
```

## Next

These editing procedures return a modified image without evaluating its likelihood. That is a property of the editing procedure, not a claim that diffusion models have no probabilistic objective. The [autoregressive-model note](/notes/generative-models/autoregressive-models) studies a different interface: a joint distribution built from normalized conditionals, with explicit log-likelihood evaluation.
