You have a photo of a cat and want its ear a little higher. A prompt cannot say "40 pixels up", and the [editing tools of latent diffusion](/notes/generative-models/latent-diffusion#editing-with-the-same-model) steer *what* an image shows and say nothing about *where* things are. Many edits are geometric: open a mouth, turn a head, make a car taller. They can be stated with two clicks, a **handle point** $p$ on the object and a **target point** $g$ where it should end up.

Moving the pixels of the ear would leave a hole where it was and a seam where it lands. Point-based editing moves the *latent code* of a generative model instead, so that every intermediate result is an image the model can draw, with the uncovered fur invented by the model. **DragGAN** ([Pan et al., 2023](#references)) does this in a StyleGAN2; **DragDiffusion** ([Shi et al., 2024](#references)) carries the same loop into Stable Diffusion, which can represent almost any photograph.

## What a drag edit asks for

The user gives handles $p_1, \dots, p_n$, their targets $g_1, \dots, g_n$ (we write $g$ for "goal" because $t$ will be a diffusion step), and optionally a binary mask $M$, equal to 1 where the image may change. The result should be **precise**, with each handle ending at its target, and **general**, working for any object the model knows. A [conditional GAN](/notes/generative-models/gans#conditional-gan) driven by face keypoints is precise and not general.

The tool brings one more property. If every intermediate image is an output of a pretrained generator, the generator acts as a prior: when DragGAN opens a lion's mouth, teeth appear inside. The prior is only a tendency. Being in the generator's range is weaker than lying where its training data put mass, and an optimized code can drift into regions that produce artefacts or change a person's identity.

Two things remain to be built. We need a differentiable way to say "this point should move one step that way", and a way to know where the point is after each step.

## The generator DragGAN edits \{#the-stylegan2-generator-in-brief\}

DragGAN uses a StyleGAN2 trained on one category: faces, cats, cars. Two of its properties, derived in the [StyleGAN note](/notes/generative-models/stylegan), matter here.

The first is the extended latent space $\mathcal W^+$. Each layer of the synthesis network receives its own code $w_j \in \mathbb R^{512}$, and the [style-mixing experiments](/notes/generative-models/stylegan#style-mixing-coarse-middle-and-fine-styles) show that the codes of the coarse layers set pose and shape, while the later ones set colour and texture. DragGAN optimizes only the first six codes $w_1, \dots, w_6$: the content moves without being repainted.

The second is that the intermediate feature maps of the generator tell positions apart. We write $F_q(w) \in \mathbb R^C$ for the feature vector at position $q$ of the map after the sixth synthesis block, resized to the image size. At a non-integer $q$ it is interpolated bilinearly from the four neighbouring positions, which keeps it a differentiable function of both $w$ and $q$. Among the blocks the paper tried, this one gave the most precise edits: earlier blocks are coarse, later ones less discriminative.

## Editing a real photo: GAN inversion

A generated image comes with its code. A photograph $x$ does not, so it is first **inverted**: we look for the code whose image reproduces it,

$$
w^* = \arg\min_{w}\ \ell\big(G(w),\ x\big),
$$

where $\ell$ is a distance between images, usually [LPIPS](/notes/generative-models/lpips) plus a squared error ([Xia et al., 2022](#references)). Optimization-based methods solve this problem by gradient descent for each photo, accurately and slowly; encoder-based methods train a network $E: x \mapsto w$ once and invert in one pass, less exactly.

The space matters. $\mathcal W^+$ has many more numbers than $\mathcal W$ and reproduces photos more closely. A code found far from the codes the mapping network produces, however, edits badly, because the generator was never trained there; the survey calls this the trade-off between distortion and editability.

**Pivotal tuning inversion** (PTI, [Roich et al., 2022](#references)) changes the generator instead of the code. It inverts the photo into $\mathcal W$, giving a pivot $w_p$ that edits well, and then fine-tunes the generator's weights so that $G(w_p)$ matches the photo, with a regularizer that keeps the generator unchanged away from $w_p$. DragGAN edits real photos this way: PTI first, then the drag loop.

Inversion bounds what a GAN editor can do. A face model can invert a portrait but not a person in full figure, and a cat model cannot invert a car.

## DragGAN: motion supervision and point tracking

DragGAN starts from a code $w_0$, its features $F^0 = F(w_0)$ and the initial handles $p_i^0$. Each iteration has two sub-steps ([Pan et al., 2023](#references), Section 3). **Motion supervision** takes one gradient step on $w$ that pushes the content around every handle a small step toward its goal. **Point tracking** then finds where each handle went. Nothing is trained: the generator stays frozen, and the only variable is the code of the image being edited.

### Motion supervision

Let $d_i = (g_i - p_i)/\lVert g_i - p_i \rVert_2$ be the unit vector from a handle to its goal, $\Omega_1(p, r_1)$ the disc of positions within distance $r_1$ of $p$, and $\mathrm{sg}[\cdot]$ the **stop-gradient**: its value passes forward, its gradient is zero. The loss of one iteration is

$$
\begin{aligned}
\mathcal L(w) = {}&\sum_{i=1}^{n} \sum_{q \in \Omega_1(p_i, r_1)} \big\lVert F_{q + d_i}(w) - \mathrm{sg}\big[F_q(w)\big] \big\rVert_1 \\
&+ \lambda\, \big\lVert \big(F(w) - F^0\big) \odot (1 - M) \big\rVert_1 ,
\end{aligned}
$$

where $\lVert \cdot \rVert_1$ is the sum of absolute values. The first term compares the patch of features around each handle with the same patch shifted by one pixel toward the goal. The second, used when a mask is drawn, keeps the features outside the movable region equal to those of the original image. When a handle reaches its goal, $d_i$ is set to 0 and its term vanishes.

### Why the reference is frozen

The stop-gradient decides the direction of the edit. Take one position $q$ and one channel, and write $a = F_{q + d}(w)$ for the shifted feature and $b = F_q(w)$ for the reference. With the reference frozen, the term is $|a - \mathrm{sg}[b]|$, and the chain rule through $a$ alone, with $d|y|/dy = \operatorname{sign}(y)$, gives its gradient. One gradient step with learning rate $\eta$ then changes $a$, to first order, by

$$
\begin{aligned}
\nabla_w \mathcal L &= \operatorname{sign}(a - b)\, \nabla_w a \\
w' - w &= -\eta\, \operatorname{sign}(a - b)\, \nabla_w a \\
a' - a &\approx (\nabla_w a)^\top (w' - w) \\
&= -\eta\, \operatorname{sign}(a - b)\, \lVert \nabla_w a \rVert^2 .
\end{aligned}
$$

The third line is a first-order Taylor expansion of $a$ around $w$. The last line says that $a$ moves toward $b$: if $a$ is above $b$ it goes down, if below it goes up. The features one step ahead of the handle become what the features at the handle are now, so the content is copied one step along $d$.

To see that this is a *forward* motion, take a generator that only translates its content: $F_x(s) = \phi(x - s)$ for a bump $\phi$ centred at a position $s$, the latent. Write $u = q - s$. The reference is $b = \phi(u)$, and the frozen-reference loss is zero when $\phi(q + d - s') = \phi(u)$, which holds at $s' = s + d$: the bump shifted by one step toward the goal. (A symmetric bump also matches at a mirrored position; a second, odd channel such as the one in the example below rules it out.) For a step $d$ small next to the width of the bump, the gradient at the current $s$ has a fixed sign on either flank:

$$
\begin{aligned}
a - b &= \phi(u + d) - \phi(u) \approx d\, \phi'(u) \\
\operatorname{sign}(a - b) &= \operatorname{sign}(d)\, \operatorname{sign}\big(\phi'(u)\big) \\
\frac{\partial a}{\partial s} &= -\phi'(u + d) \approx -\phi'(u) \\
\frac{\partial \mathcal L}{\partial s} &= \operatorname{sign}(a - b)\, \frac{\partial a}{\partial s} \\
&\approx -\operatorname{sign}(d)\, \operatorname{sign}\big(\phi'(u)\big)\, \phi'(u) \\
&= -\operatorname{sign}(d)\, \lvert \phi'(u) \rvert .
\end{aligned}
$$

The first line is a Taylor expansion in $d$. The second takes its sign with $\operatorname{sign}(xy) = \operatorname{sign}(x)\, \operatorname{sign}(y)$: the size of $d$ drops out, and only its direction and the sign of the slope remain. The third line is the chain rule with $\partial(x - s)/\partial s = -1$. The fifth substitutes the second and the third, and in the last the sign of the slope meets the slope itself: $\operatorname{sign}(y)\, y = |y|$ cancels it. Gradient descent changes $s$ by $+\eta\, \operatorname{sign}(d)\, |\phi'(u)|$: toward the goal, whatever the slope at the handle.

Without the stop-gradient, $b$ depends on $w$ too and the gradient becomes $\operatorname{sign}(a - b)\,(\nabla_w a - \nabla_w b)$. The loss can now also be lowered by moving $b$ toward $a$, which pulls the content backwards, or by flattening the patch until all positions look alike. And because neighbouring positions see almost the same content, $\nabla_w a$ and $\nabla_w b$ are nearly equal: their difference is small and its sign depends on the curvature of the features rather than on $d$.

**Worked example.** Take a bump of width $\sigma = 2$ read in two channels,

$$
\begin{aligned}
F_x(s) &= \Big(\phi(x - s),\ \tfrac{x - s}{\sigma}\, \phi(x - s)\Big), \\
\phi(u) &= e^{-u^2 / (2\sigma^2)} ,
\end{aligned}
$$

where the second channel tells the left flank from the right one. Let $s = 0$, the handle $p = 1$, the goal $g = 4$, so $d = 1$, and a patch of one position, $\Omega_1 = \{1\}$ (toy numbers):

| Quantity | Value |
| --- | --- |
| reference $F_1(0)$ | $(0.8825,\ 0.4412)$ |
| shifted feature $F_2(0)$ | $(0.6065,\ 0.6065)$ |
| loss | $0.276 + 0.165 = 0.441$ |
| $\partial \mathcal L / \partial s$ with the stop-gradient | $-0.3033$ |
| $\partial \mathcal L / \partial s$ without it, first channel only | $-0.0826$ |
| $\partial \mathcal L / \partial s$ without it, both channels | $+0.2483$ |

With the stop-gradient, descent increases $s$ and the bump moves toward the goal. The frozen-reference loss is a sum of absolute values, so it is never negative. At $s = 1$ it is zero, because the generator only translates: $F_2(1)$ reads the bump at $u = 1$, as $F_1(0) = b$ does. Zero is the smallest possible value, so the shift by $d$ is a minimum. It is the only one: the first channel matches only at $u = \pm 1$, that is $s = 1$ or $s = 3$, and at $s = 3$ the second channel has the wrong sign. The Code section gives $0.253$ at $s = 0.5$ and $0.286$ at $s = 1.5$. Without it, the first channel alone still pushes forward, 3.7 times more weakly, and the second channel flips the sign: descent moves the bump away from the goal.

### Point tracking

After the step the content has moved, by an amount the loss does not fix: one gradient step can move it by less than a pixel or by more. If the next step supervised the old position, it would push the wrong content. DragGAN therefore re-locates each handle by nearest-neighbour search in feature space,

$$
p_i \leftarrow \arg\min_{q \in \Omega_2(p_i, r_2)} \big\lVert F_q(w') - f_i \big\rVert_1 ,
$$

where $w'$ is the updated code, $f_i = F_{p_i^0}(w_0)$ the feature of the handle in the original image, and $\Omega_2(p, r_2)$ the square of positions within $r_2$ of $p$ along each axis. The reference is always the original feature, so small tracking errors do not accumulate.

In the worked example, after the bump has moved to $s = 1$, the candidates $x = -1, 0, 1, 2, 3$ have distances $1.324, 0.882, 0.559, 0, 0.441$ to $f = (0.8825, 0.4412)$, and the handle is found at $x = 2 = p + d$. On the paper's face test, which moves the landmarks of one generated face onto those of another, a single handle ends 2.44 pixels from its goal on average, against 12.93 before editing; with an optical-flow network (RAFT) as the tracker it ends 13.43 pixels away ([Pan et al., 2023](#references), Table 1).

### The loop

The optimizer is Adam on the six codes. For a $512 \times 512$ image the paper uses $r_1 = 3$, $r_2 = 12$ and $\lambda = 20$, and stops when every handle is within 1 pixel of its goal, or 2 pixels when there are more than five handles. An edit takes 30 to 200 iterations, a few seconds on one GPU. The toy below runs the whole loop in two dimensions, with the position of a blob as the latent.

<DragToy />

Two features of the toy carry over. The loss does not decrease from one iteration to the next; it stays between 7.4 and 8.5, because each iteration defines a new patch at the new handle position, so progress is read from the distance to the goal. And tracking returns grid positions while the content moves continuously: at the end the content has moved by $(9.11, 4.01)$, and the tracked handle is 0.11 pixel from where the handle's content really is.

## DragDiffusion: the same loop in a diffusion latent

DragGAN edits only what a category-specific GAN can draw. A text-to-image diffusion model covers far more images, but it has no single code like $w$: an image is the end of a chain of denoising steps. DragDiffusion keeps DragGAN's two sub-steps and changes the variable: one noisy latent of Stable Diffusion 1.5 at one intermediate step ([Shi et al., 2024](#references)). The diffusion symbols $z_t$, $\bar\alpha_t$, $\varepsilon_\theta$ and the text encoder $\tau$ are those of the [latent diffusion note](/notes/generative-models/latent-diffusion#diffusion-in-the-latent).

<DragDiffusionFlow />

1. Identity-preserving fine-tuning trains LoRA weights of the U-Net on the input image alone.
2. DDIM inversion turns the image latent $z_0$ into the noisy latent $z_{35}$, 35 steps of a 50-step schedule away from the image.
3. Latent optimization moves the handles by motion supervision and point tracking on U-Net features; only $z_{35}$ changes.
4. Denoising with reference-latent-control takes the edited latent back to an image, borrowing keys and values from the denoising of the original latent.

### Identity-preserving fine-tuning

Inverting a photo and denoising it again does not return exactly the photo, and after an edit the gap grows. Before editing, DragDiffusion fine-tunes the U-Net on the one image with [LoRA](/notes/nlp/peft#lora-a-low-rank-update) updates $\Delta\theta$ of rank 16 in the attention projections. The loss is the usual noise-prediction objective restricted to the single latent $z_0$ of the photo,

$$
\mathcal L_{\text{ft}}(\Delta\theta) = \mathbb E_{\varepsilon, t}\Big[\big\lVert \varepsilon - \varepsilon_{\theta + \Delta\theta}(z_t,\ t,\ \tau(y))\big\rVert_2^2\Big] ,
$$

with $z_t = \sqrt{\bar\alpha_t}\, z_0 + \sqrt{1 - \bar\alpha_t}\, \varepsilon$, frozen weights $\theta$ and a short prompt $y$ that describes the image. Eighty steps, about 25 seconds on one GPU, make the model reconstruct this image closely; without them the edited faces change identity.

### DDIM inversion to a single step

Sampling with [DDIM](/notes/generative-models/latent-diffusion#fewer-steps) is deterministic. One step predicts the clean latent and re-noises it to the next level along the predicted noise:

$$
\begin{aligned}
\hat z_0(z_t) &= \frac{z_t - \sqrt{1 - \bar\alpha_t}\; \varepsilon_\theta(z_t, t)}{\sqrt{\bar\alpha_t}} , \\
z_{t-1} &= \sqrt{\bar\alpha_{t-1}}\; \hat z_0(z_t) + \sqrt{1 - \bar\alpha_{t-1}}\; \varepsilon_\theta(z_t, t) .
\end{aligned}
$$

**DDIM inversion** runs the same update upward, from $z_t$ to $z_{t+1}$, with the noise predicted at $z_t$ standing in for the noise at the unknown $z_{t+1}$. The substitution is the approximation: with small steps, $\varepsilon_\theta$ changes little between neighbouring levels, and denoising the inverted latent returns close to the original ([Song, Meng and Ermon, 2021](#references), Section 4.3). DragDiffusion inverts for 35 of 50 steps and edits $z_{35}$; classifier-free guidance is switched off for real photos, because it amplifies the inversion error.

Why is one latent enough? A drag changes layout, and the layout of a diffusion sample is settled early in the chain, at high noise; later steps add detail. Optimizing one latent costs one forward and one backward pass through the U-Net per iteration, instead of a backward pass through the whole chain. A smaller $t$ is too constrained to make the move, and a larger one is free to lose the identity ([Shi et al., 2024](#references), Section 4.5).

### Latent optimization on U-Net features

Motion supervision carries over with the latent in place of $w$ and the features of the U-Net's third upsampling block in place of the generator's. With $\hat z_t^k$ the latent after $k$ updates and $\hat z_t^0 = z_t$,

$$
\begin{aligned}
\mathcal L_{\text{ms}}(\hat z_t^k) = {}&\sum_{i=1}^{n} \sum_{q \in \Omega(p_i^k, r_1)} \big\lVert F_{q + d_i}(\hat z_t^k) - \mathrm{sg}\big[F_q(\hat z_t^k)\big] \big\rVert_1 \\
&+ \lambda\, \big\lVert \big(\hat z_{t-1}^k - \mathrm{sg}[\hat z_{t-1}^0]\big) \odot (1 - M) \big\rVert_1 .
\end{aligned}
$$

The stop-gradient plays the role derived above. The mask term acts on latents rather than features: $\hat z_{t-1}^k$ is one DDIM step of denoising from the current latent and $\hat z_{t-1}^0$ the same step from the unedited one, so outside the mask the next, slightly cleaner latent must not change. Tracking is DragGAN's nearest-neighbour search, with U-Net features and the original feature $F_{p_i^0}(z_t)$ as the reference. Adam runs for at most 80 steps with $r_1 = 1$, $r_2 = 3$ and $\lambda = 0.1$.

### Reference-latent-control

After optimization, $\hat z_t$ is denoised for the remaining $t$ steps and decoded. **Reference-latent-control** runs the denoising of the original $z_t$ alongside and, in the self-attention layers of the U-Net's upsampling blocks, replaces the keys and values of the edited branch by those of the original:

$$
\begin{aligned}
\hat Q &= W_Q\, \hat\varphi, \\
K &= W_K\, \varphi, \\
V &= W_V\, \varphi, \\
\mathrm{Attention}(\hat Q, K, V) &= \operatorname{softmax}\Big(\frac{\hat Q K^\top}{\sqrt{d_k}}\Big) V ,
\end{aligned}
$$

where $\hat\varphi$ and $\varphi$ are the flattened features of the edited and the original branch and $d_k$ the key dimension. Each position of the edited image looks up the positions of the original whose keys match its query and copies their values, so a cat whose ear has moved still gets the fur of the original cat. The mechanism comes from MasaCtrl ([Cao et al., 2023](#references)).

### Evaluation on DragBench

DragBench has 205 images with 349 handle–target pairs in ten categories ([Shi et al., 2024](#references), Section 4.2). Two measures pull in opposite directions. **Image fidelity**, $\mathrm{IF} = 1 - \mathrm{LPIPS}(x, x_{\text{edit}})$, is 1 for an unchanged image. **Mean distance** (MD) locates the handle's content in the edited image with diffusion-feature correspondence ([Tang et al., 2023](#references)) and averages its distance to the goal. Doing nothing scores perfect fidelity.

DragDiffusion leaves the handles closer to their goals in all ten categories and keeps more of the image in nine. For DragGAN, each photo goes through a StyleGAN of the best-matching category, and on upper and full bodies its fidelity falls to 0.33 and 0.31: the inverted images lose most of the original ([Shi et al., 2024](#references), Table 1).

## What changed

| | DragGAN | DragDiffusion |
| --- | --- | --- |
| Model | StyleGAN2 of one category | Stable Diffusion 1.5 |
| Variable | $w_1, \dots, w_6$ of $\mathcal W^+$: $6 \cdot 512 = 3072$ numbers | $z_{35}$: $4 \cdot 64 \cdot 64 = 16{,}384$ numbers |
| Features | generator, after block 6 | U-Net, third upsampling block |
| Keeping the rest | $\lambda$ on features outside the mask | $\lambda$ on the next latent, LoRA, reference-latent-control |
| Real photos | through PTI | through LoRA and DDIM inversion |

## Where it breaks

Tracking can slip where many positions look alike. In the worked example, keep only the first channel, the bump itself, which is symmetric. After the move to $s = 1$, the candidates $x = -1, 0, 1, 2, 3$ have distances $0.276, 0, 0.118, 0, 0.276$ to the handle's original value $0.8825$: the mirror position $x = 0$, on the far flank of the bump, ties with the right answer $x = 2$. The search returns the first minimum, $x = 0$, and the next motion-supervision step pushes the wrong content. Texture-less regions cause the same failure, which is why DragGAN recommends handles on textured parts.

Other failures come from the setup. A few points do not determine an image: without a mask, DragGAN may move a whole dog when only its head was dragged. DragGAN cannot leave its GAN's domain, and unusual poses produce artefacts. DragDiffusion sometimes leaves handles short of their targets. Both methods need a per-image training run on photos, PTI or LoRA, and both make it easy to change the pose or expression of a real person.

## What you should remember

- A drag edit optimizes a generator's latent; the generator invents the uncovered content.
- Motion supervision: $\lVert F_{q+d}(w) - \mathrm{sg}[F_q(w)] \rVert_1$ copies the patch one step toward the goal.
- Without the stop-gradient the gradient is a difference of near-equal terms and can point backwards.
- Tracking: nearest neighbour of the handle's original feature after every step.
- DragGAN moves $w_1, \dots, w_6$ in $\mathcal W^+$; real photos enter through PTI.
- DragDiffusion: LoRA on the photo, DDIM inversion to $t = 35$ of 50, one latent optimized, keys and values borrowed when denoising.

## Code

The worked example in NumPy, with the gradients written out: the stop-gradient keeps the reference's derivative out of the sum. A finite-difference check confirms both gradients.

```python
import numpy as np

sigma = 2.0

def feat(x, s):
    """Toy generator: a bump at position s, read at positions x; two channels."""
    u = x - s
    phi = np.exp(-u**2 / (2 * sigma**2))
    return np.array([phi, u / sigma * phi])

def dfeat_ds(x, s):
    """Derivative of both channels with respect to the latent s (d/ds = -d/du)."""
    u = x - s
    phi = np.exp(-u**2 / (2 * sigma**2))
    dphi = -u / sigma**2 * phi
    return -np.array([dphi, (phi + u * dphi) / sigma])

p, g, s = 1.0, 4.0, 0.0
d = np.sign(g - p)                              # unit step from the handle toward the goal
a, b = feat(p + d, s), feat(p, s)               # shifted feature and reference
sign = np.sign(a - b)
grad_sg = sign @ dfeat_ds(p + d, s)             # sg[F_p]: only the shifted feature moves
grad_no = sign @ (dfeat_ds(p + d, s) - dfeat_ds(p, s))
print(np.round(b, 4), np.round(a, 4), round(np.abs(a - b).sum(), 4))
print(round(grad_sg, 4), round(grad_no, 4), round(sign[0] * (dfeat_ds(p + d, s) - dfeat_ds(p, s))[0], 4))
# [0.8825 0.4412] [0.6065 0.6065] 0.4412
# -0.3033 0.2483 -0.0826

h = 1e-6                                        # finite-difference check of both gradients
L_sg = lambda t: np.abs(feat(p + d, t) - b).sum()
L_no = lambda t: np.abs(feat(p + d, t) - feat(p, t)).sum()
print(round((L_sg(h) - L_sg(-h)) / (2 * h), 4), round((L_no(h) - L_no(-h)) / (2 * h), 4))
# -0.3033 0.2483
print([round(float(L_sg(t)), 3) for t in (0.5, 1.0, 1.5)])   # zero at s = d
# [0.253, 0.0, 0.286]

# Point tracking once the content has moved by d (s = 1), with both channels and with the first only
xs = np.arange(-1.0, 4.0)                       # Omega_2 around p = 1 with r2 = 2
dist2 = np.abs(feat(xs, 1.0) - b[:, None]).sum(0)
dist1 = np.abs(feat(xs, 1.0)[0] - b[0])
print(xs[dist2.argmin()], np.round(dist2, 3))
print(xs[dist1.argmin()], np.round(dist1, 3))
# 2.0 [1.324 0.882 0.559 0.    0.441]
# 0.0 [0.276 0.    0.118 0.    0.276]
```

## Next

Both methods move an image along the range of a model that produces the whole picture at once, from a latent code or by denoising the whole latent, and neither gives the probability of the result. The last family of the course builds an image one piece at a time: [autoregressive models](/notes/generative-models/autoregressive-models) factor the density of an image into a product of conditionals, predict one pixel or one token at a time, and compute the likelihood exactly.
