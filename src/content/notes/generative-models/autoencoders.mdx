A digit written by hand and resized to $64 \times 64$ is 4096 numbers, yet almost all of them are predictable from a few facts: which digit it is, how thick the stroke is, how it slants. Can a network find such a short description on its own, without labels? Train it to reproduce its input after squeezing it through a layer of 512 numbers. The copy is only the pretext. What we want is the code the network is forced to build on the way, and later, a way to make new digits from codes ([Hinton and Salakhutdinov, 2006](#references); [Goodfellow, Bengio and Courville, 2016](#references), chapter 14).

Such a network is an **autoencoder**. Training a network to pass its input through a narrow hidden layer and back already appears as the "encoding problem" of [Rumelhart, Hinton and Williams (1986)](#references). It uses the convolution, batch-norm and LeakyReLU blocks of the [previous note](/notes/generative-models/training-background).

## Architecture: downsample, bottleneck, upsample

An **encoder** $f_\varphi$ with parameters $\varphi$ maps an image $x$ to a **latent code** $z$, and a **decoder** $g_\theta$ with parameters $\theta$ maps the code back to a reconstruction $\hat x$:

$$
\begin{aligned}
z &= f_\varphi(x), \\
\hat{x} &= g_\theta(z) .
\end{aligned}
$$

The letters follow the [VAE](/notes/generative-models/vae): $\varphi$ belongs to the encoder and $\theta$ to the decoder. The code is smaller than the input, so the network cannot pass the pixels through unchanged; it must keep what it needs to rebuild the image and drop the rest. Every image becomes a point in a learned, lower-dimensional **latent space**.

With a linear encoder and decoder and squared error, the best the network can do is project onto the top principal components: a linear autoencoder learns the PCA subspace ([autoencoders as nonlinear PCA](/notes/ml/dimensionality-reduction#autoencoders-nonlinear-pca)). Nonlinear layers let the code follow curved structure that PCA cannot.

The MNIST digits are resized from $28 \times 28$ to $64 \times 64$, with pixel values in $[0, 1]$. The encoder halves the side four times with stride-2 convolutions, $64 \to 32 \to 16 \to 8 \to 4$ (the [output-size formula](/notes/generative-models/training-background#a-convolution-layer)), and the decoder doubles it four times. A side divisible by $2^4 = 16$ makes the mirrored decoder return to the input size. At 28 the encoder would give $28 \to 14 \to 7 \to 4 \to 2$, and four doublings would end at 32.

<AEPipeline />

Every encoder block is a $3 \times 3$ convolution with stride 2, batch norm and LeakyReLU with slope 0.2; a last stride-1 convolution produces the code. Every decoder block upsamples by 2 with bilinear interpolation and then applies a $3 \times 3$ convolution, batch norm and LeakyReLU. A final convolution maps 16 channels to 1, followed by a sigmoid.

| Tensor | Shape (channels × height × width) | Numbers |
| --- | --- | --- |
| input $x$ | $1 \times 64 \times 64$ | $4096$ |
| encoder blocks 1, 2, 3 | $16 \times 32^2$, $32 \times 16^2$, $32 \times 8^2$ | $16384$, $8192$, $2048$ |
| code $z$ after block 4 and the last convolution | $32 \times 4 \times 4$ | $512$ |
| decoder blocks 1, 2, 3 | $32 \times 8^2$, $32 \times 16^2$, $32 \times 32^2$ | $2048$, $8192$, $32768$ |
| decoder block 4 | $16 \times 64 \times 64$ | $65536$ |
| output $\hat x$ | $1 \times 64 \times 64$ | $4096$ |

The code holds 512 numbers: 8 times fewer than the resized image, but only 1.5 times fewer than the original 784 pixels. The compression is mild. What matters is how the code is organized.

## How to read the encoder and decoder

No layer is told to compress. The first encoder block even expands 4096 values to 16384 activations; the code becomes small only because the shapes narrow toward the bottleneck. Each halving is a learned stride-2 convolution, so the network decides what survives it, where max or average pooling would apply a fixed rule. In image classifiers, replacing max pooling by a stride-2 convolution cost no accuracy ([Springenberg et al., 2015](#references)).

The decoder is not an upscaler. Bilinear upsampling has no parameters; the learned convolution after it fills in the detail. In trained convolutional classifiers, early layers respond to edges and deeper layers, whose receptive fields are larger, to parts ([Zeiler and Fergus](/notes/generative-models/training-background#a-convolution-layer)). The same growth of receptive fields lets these channels encode stroke fragments and larger parts of a digit; this run did not visualize them.

## Reconstruction loss

The standard loss is the mean squared error between output and input, averaged over the $n$ values of a batch:

$$
\mathrm{MSE}(\hat x, x) = \frac{1}{n}\sum_{i=1}^{n} \left(x_i - \hat{x}_i\right)^2 .
$$

PyTorch's `nn.MSELoss()` averages over every pixel of the batch: $n = 64 \cdot 64 \cdot 64 = 262144$ for 64 images. Since pixels lie in $[0, 1]$, binary cross-entropy is the natural alternative:

$$
\begin{aligned}
\mathrm{BCE}(\hat x, x) = -\frac{1}{n}\sum_{i=1}^{n}\Big[
&x_i \log \hat x_i \\
&+ (1 - x_i)\log(1 - \hat x_i)\Big] .
\end{aligned}
$$

Each loss is a negative log-likelihood. A Gaussian decoder with fixed variance $s^2$ on $D$ pixels has the density $(2\pi s^2)^{-D/2} \exp\big(-\lVert x - \hat x\rVert^2/(2s^2)\big)$; taking minus its logarithm,

$$
-\log \mathcal N\big(x;\, \hat x,\, s^2 I\big) = \frac{\lVert x - \hat x\rVert^2}{2s^2} + \frac D2 \log(2\pi s^2),
$$

so MSE is the Gaussian negative log-likelihood up to a positive factor and a constant. BCE is the negative log-likelihood of independent Bernoulli pixels with means $\hat x_i$. That reading holds only for binary pixels. The resized digits have many grey values. For those BCE is still minimized at $\hat x_i = x_i$: its derivative in $\hat x_i$, $-x_i/\hat x_i + (1 - x_i)/(1 - \hat x_i)$, vanishes there. But it is no longer the log of a normalized density on $[0, 1]$: for $\hat x_i = 0.9$, $\int_0^1 0.9^{x}\, 0.1^{1-x}\, dx = 0.8/\ln 9 = 0.364$, not 1 ([Loaiza-Ganem and Cunningham, 2019](#references)). The VAE builds on this [reading of the loss as a likelihood](/notes/generative-models/vae#variational-approximation-and-the-elbo).

Two practical traps follow. With a sigmoid already applied in `forward`, BCE must be `nn.BCELoss`: `nn.BCEWithLogitsLoss` applies its own sigmoid, and the pair would apply it twice. The stabler option is to drop the sigmoid and pass logits to `BCEWithLogitsLoss`. And the input range must suit the output: colour images are often mapped to $[-1, 1]$ by $x \mapsto 2x - 1$, which rules out a [sigmoid output](#why-a-sigmoid-at-the-output) and BCE, whose targets must lie in $[0, 1]$.

## Emergent structure

Nothing in the loss asks for an organized latent space, and no labels are used. Still, structure emerges. A t-SNE projection ([van der Maaten and Hinton, 2008](#references)) of the 512-dimensional codes of the test set, coloured by digit, shows clusters by class that are cleaner than before training. Most digits form one compact cluster; the 2s split into two groups and the 1s form an elongated band.

t-SNE draws neighbourhoods. It keeps each code's nearest neighbours near it in the plane, with the perplexity, 30 here, setting roughly how many count. Cluster sizes and the gaps between clusters carry little information ([Wattenberg, Viégas and Johnson, 2016](#references); [reading t-SNE](/notes/ml/dimensionality-reduction#t-sne-and-umap-neighbourhoods-instead-of-variance)). The plot shows whether a code's neighbours share its label, and even that only qualitatively.

<aside class="callout"><strong>The baseline is not chance.</strong> The t-SNE of the randomly initialized encoder already shows clusters for most digits, with 4 and 9 overlapping. Random convolutional networks give surprisingly useful features (<a href="#references">Saxe et al., 2011</a>, for convolution and pooling). Training sharpens the clusters; it does not create them from nothing.</aside>

A number comes from a **probe**: freeze the encoder, compute the codes of labelled images, train a simple classifier on them and report its accuracy on held-out images ([Alain and Bengio, 2016](#references); the [linear probe](/notes/deep-learning/self-supervised-learning#the-linear-probe) of the Deep Learning course). The classifier sees only the code, so its accuracy measures how much class information the code keeps in an easily readable form. The fair baseline is the same probe on an untrained encoder of the same architecture. The same codes can also replace Inception features in [FID](/notes/generative-models/fid#fid-with-a-custom-encoder) when the images are unlike ImageNet.

### Why the codes do not generate

Two experiments ask whether the latent space can be used to make images.

Interpolation encodes a 7 and a 2 and decodes $z_\alpha = (1 - \alpha) z_1 + \alpha z_2$ for eight values of $\alpha$ from 0 to 1. The endpoints are clean digits; the middle frames are overlays of the two strokes, not digits morphing into each other.

Sampling fits an axis-aligned Gaussian to the training codes of each digit, using the per-coordinate mean and standard deviation, draws one code per class and decodes it. In the saved run six of the ten samples are recognisable; the 2, 4, 5 and 8 are badly distorted.

Both failures have the same cause. Training asks only that the codes of training images decode back to those images. It says nothing about where in $\mathbb R^{512}$ the codes sit or what lies between them, so an arbitrary point can decode to anything. The codes follow no distribution we know how to sample from: the diagonal Gaussians ignore correlations between coordinates, and they needed labels. A plain autoencoder learns a representation; it is **not yet a generative model**. The [variational autoencoder](/notes/generative-models/vae#from-autoencoders-to-generation) closes this gap by making the distribution of codes part of the training objective.

## Variants

### Denoising autoencoder

A denoising autoencoder ([Vincent et al., 2008](#references)) changes the task and keeps the architecture. It corrupts the input with a random $q(\tilde x \mid x)$, reconstructs from the corrupted version, $\hat x = g_\theta(f_\varphi(\tilde x))$, and compares the result with the clean $x$. The original paper zeroes a random fraction of the input; additive Gaussian noise is the other common choice ([Vincent et al., 2010](#references)). Copying the input no longer works, so the network must learn which structure is signal and which is noise.

<DenoisingPipeline />

Here the corruption is $\tilde x = x + 0.2\,\varepsilon$ with $\varepsilon \sim \mathcal N(0, I)$, without clipping, and every block also applies `Dropout2d(0.3)`, which drops whole feature maps during training. After 5 epochs the training loss is $0.0102$ against the plain model's $0.0021$. The task is harder, so the numbers are not directly comparable. On noisy test digits the model removes the noise completely, with slightly thicker strokes and lost small details such as a short hook at the top of a 0. Its codes cluster like the plain model's.

The idea returns later in the course. With Gaussian corruption, training a denoiser is equivalent to score matching on a smoothed data density ([Vincent, 2011](#references); [derived](/notes/generative-models/score-matching#two-cheaper-objectives) in the score-matching note), and a diffusion model's [noise-prediction objective](/notes/generative-models/ddpm-training-objective#from-means-to-noise) trains one denoiser for many noise levels.

### Sparse autoencoder

A sparse autoencoder adds a penalty that makes each hidden unit active for only a small fraction of inputs ([Ng, 2011](#references)). The hidden layer can then be large, even larger than the input, without the network simply copying. Two forms are common.

The **KL penalty** reads a sigmoid unit's mean activation $\hat\rho_j$ over a batch as a firing rate and compares it with a target rate $\rho$ through the [KL divergence](/notes/generative-models/entropy-and-divergences#kullbackleibler-divergence) between two coins:

$$
\begin{aligned}
\mathcal L &= \mathrm{MSE}(\hat x, x) + \beta \sum_{j} D_{\mathrm{KL}}(\rho \,\|\, \hat\rho_j), \\
D_{\mathrm{KL}}(\rho \,\|\, \hat\rho_j) &= \rho \log\frac{\rho}{\hat\rho_j} + (1-\rho)\log\frac{1-\rho}{1-\hat\rho_j} ,
\end{aligned}
$$

with $\rho = 0.05$ and $\beta = 0.001$ here. [Ng (2011)](#references) averages over the training set; the batch mean estimates it. The penalty fixes only each unit's average rate, which a unit firing weakly at 0.05 for every input also satisfies; sparsity per input has to come from the interplay with the reconstruction loss. This model's decoder uses transposed convolutions with kernel 4, stride 2 and padding 1, which double the side: the [output size](/notes/deep-learning/convolution#transposed-convolution-going-up-in-resolution) $(H - 1)\,s - 2p + (k - 1) + 1$ becomes $(H - 1) \cdot 2 - 2 + 4 = 2H$.

<SparseActivations />

The **L1 penalty** adds $\lambda = 0.001$ times the mean absolute value of the 512 code entries:

$$
\mathcal L = \mathrm{MSE}(\hat x, x) + \frac{\lambda}{512}\sum_{k=1}^{512} |z_k| .
$$

Its subgradient $\operatorname{sign}(z_k)$ has constant size, so it keeps pulling small entries toward zero where a squared penalty's pull vanishes. One coordinate shows the effect: minimizing $\tfrac12(z - a)^2 + \lambda |z|$, the subgradient condition $0 \in z - a + \lambda\,\partial|z|$ gives $z = \operatorname{sign}(a)\max(|a| - \lambda, 0)$, exactly zero whenever $|a| \le \lambda$ ([Goodfellow, Bengio and Courville, 2016](#references), section 7.1.2). Plain gradient training steps past zero instead of landing on it, so it only drives entries close to zero.

### Where the sparsity penalties break

Neither penalty works here, for opposite reasons, and both are worth computing.

The KL penalty is too heavy. It sums over every channel and position of the four intermediate encoder layers:

$$
16\cdot 32^2 + 32 \cdot 16^2 + 32 \cdot 8^2 + 32 \cdot 4^2 = 27136 \text{ terms.}
$$

At initialization batch norm centres the sigmoids' inputs at $\beta = 0$, and $\sigma(-u) = 1 - \sigma(u)$ puts the mean of a sigmoid of a roughly symmetric input near 0.5. With $D_{\mathrm{KL}}(0.05 \,\|\, 0.5) = 0.05 \ln 0.1 + 0.95 \ln 1.9 = 0.495$, the penalty starts at about

$$
27136 \cdot 0.001 \cdot D_{\mathrm{KL}}(0.05 \,\|\, 0.5) \approx 13 .
$$

The plain model's reconstruction error is $0.002$, nearly four orders of magnitude smaller. The logged sum of both terms falls from $8.85$ in the first epoch to $0.214$ in the fifth and is still falling fast, so training has not converged; only the sum was logged, and logging the terms separately would show the split. The result is visible anyway: worse reconstructions, a fragmented t-SNE plot, and class-wise samples that are only fragments of strokes. With 27136 terms, a weight near $10^{-6}$ would start the penalty at $0.013$, on the scale of the reconstruction loss in the first epoch.

The L1 penalty is too light, and it can be dodged. Its loss ends at $0.0022$, within noise of the plain model's $0.0021$, and the codes and reconstructions look the same. The first decoder block applies bilinear upsampling and a bias-free convolution, both linear, and then batch norm, which [divides out the scale of its input](/notes/generative-models/training-background#the-rest-of-the-layer). Replacing $z$ by $r z$ for any $r > 0$ leaves the decoder's output unchanged, up to batch norm's $\varepsilon$, and scales the penalty by $r$, so the encoder can lower the penalty by shrinking $z$ without making it sparse. This run did not measure the scale of $z$; comparing the mean of $\lvert z_k\rvert$ before and after training would show whether it happened. A sparsity penalty needs a weight tuned against the reconstruction loss and an architecture in which it cannot be bypassed.

### Transposed convolution or upsample + conv?

Both double the size. A transposed convolution learns its own upsampling filter, but when the kernel size is not divisible by the stride the kernel footprints overlap unevenly and produce checkerboard artifacts; resizing followed by a convolution avoids the uneven overlap and is the safer default ([Odena, Dumoulin and Olah, 2016](#references)). Two caveats from the same study: its best results came with nearest-neighbour resizing, and bilinear resizing, which the plain model here uses, gave the authors trouble. A kernel divisible by the stride, such as 4 with stride 2 in the KL model, removes the uneven overlap: every output pixel then receives exactly $k/s = 2$ taps per dimension. Learned kernels can still produce artifacts. The two decoders here differ in other ways too, so they are not a controlled comparison.

## Why a sigmoid at the output?

Inside the network the blocks use LeakyReLU, $\max(0.2x, x)$ ([Maas, Hannun and Ng, 2013](#references)), for the [gradient reasons](/notes/generative-models/training-background#common-remedies) of the previous note. The output needs something else: the decoder's last convolution is unbounded, and the targets are pixel intensities in $[0, 1]$. The sigmoid maps any real number into that range,

$$
\sigma(x) = \frac{1}{1 + e^{-x}} ,
$$

with $\sigma(0) = \tfrac12$. In the KL-sparse model it is also the hidden activation, because the Bernoulli penalty needs activations readable as rates.

<Activations />

For targets in $[-1, 1]$ the sigmoid can never produce a negative value. The usual output is then

$$
\tanh(x) = 2\,\sigma(2x) - 1 ,
$$

a sigmoid stretched to $(-1, 1)$ (multiply the numerator and denominator of $\tanh x = (e^x - e^{-x})/(e^x + e^{-x})$ by $e^{-x}$ to get $(1 - e^{-2x})/(1 + e^{-2x}) = 2\sigma(2x) - 1$), as at the end of the DCGAN generator, whose images are scaled to $[-1, 1]$ ([Radford, Metz and Chintala, 2016](#references), sections 3–4). With MSE a linear output also works, clipped to the valid range for display.

## What you should remember

- An autoencoder learns $z = f_\varphi(x)$ and $\hat x = g_\theta(z)$ by reconstruction; the code is the product.
- MSE is a Gaussian negative log-likelihood, BCE a Bernoulli one, exact only for binary pixels.
- Codes cluster by class without labels, but random encoders already cluster; compare against them with a probe.
- Arbitrary points of the latent space decode to garbage: nothing in training says where codes lie.
- Denoising changes the task and connects to score matching; sparsity penalties need their weight matched to the reconstruction loss.
