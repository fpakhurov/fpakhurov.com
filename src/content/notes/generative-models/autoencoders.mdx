An autoencoder is trained to reproduce its own input. The reconstruction target is only the pretext: the real product is the **representation** the network is forced to build on the way.

## Architecture: downsample, bottleneck, upsample

An encoder $f_\phi$ maps an input $x$ to a latent code $z$, and a decoder $g_\theta$ maps the code back to input space:

$$
z = f_\phi(x), \qquad \hat{x} = g_\theta(z) = g_\theta(f_\phi(x)).
$$

The data path follows a simple shape:

$$
\text{input} \;\xrightarrow{\ \text{downsample}\ }\; \text{bottleneck } z \;\xrightarrow{\ \text{upsample}\ }\; \text{reconstruction } \hat{x}.
$$

The bottleneck is narrower than the input, so the network cannot copy pixels through. It has to keep what is needed to rebuild the input and discard the rest. This is the **latent space** idea: every input becomes a point in a lower-dimensional space learned from the data.

**Input resolution.** In the seminar notebook, $28 \times 28$ images are upscaled to $64 \times 64$ before encoding. The larger input gives the encoder more room to downsample step by step, halving the spatial size several times, before it reaches the bottleneck.

**Latent size.** A convolutional bottleneck of shape $32 \times 4 \times 4$ (channels × height × width) holds $32 \cdot 4 \cdot 4 = 512$ numbers, so the latent code is 512-dimensional when flattened.

## How the encoder and decoder should be understood

- The **encoder works as a learned filter bank, not as a direct compression** algorithm. It is not a resize of the image: strided convolutions extract features while reducing spatial resolution.
- The **decoder is not an upscaler**. Each stage is an upsample step followed by a convolution (or an equivalent transposed convolution), so the decoder learns how to fill in detail.
- Compression is a consequence of the architecture's shape, not of an explicit "squeeze and unsqueeze" rule written by hand.
- Deeper layers learn **features, not pixels**.

## Reconstruction loss

The output is compared with the input. For real-valued data the standard choice is the mean squared error over all $n$ scalar components:

$$
\mathrm{MSE}(y, \hat y) = \frac{1}{n}\sum_{i=1}^{n} \left(y_i - \hat{y}_i\right)^2 .
$$

For an autoencoder $y = x$ and $\hat y = \hat x$.

MSE is sensitive to the scale of the data: multiplying all intensities by $c$ multiplies the loss by $c^2$. Normalize inputs consistently before comparing losses across experiments.

## Emergent structure

Nothing in the loss asks for an organized latent space, yet structure emerges: similar inputs tend to receive nearby codes because that makes reconstruction easier. This is why a plain autoencoder is useful for representation learning, and also why it is not yet a generative model — nothing guarantees that an arbitrary point of the latent space decodes to a plausible sample. Variational autoencoders address exactly that gap.

## Variants

### Denoising autoencoder (DAE)

1. Corrupt the input with noise: $\tilde x = x + \text{noise}$.
2. Reconstruct the **clean** input from the corrupted one: $\hat x = g_\theta(f_\phi(\tilde x))$, with the loss computed against $x$.
3. The result is a more robust representation.

It is the same idea as the plain autoencoder, but more stable: the network cannot succeed by learning the identity map and must model which structure in the data is signal.

### Sparse autoencoder

Same architecture, plus a **sparsity penalty** that encourages rare activations: for each input, only a few latent units should be strongly active. Typical penalties are an $L_1$ term on the code or a KL term between the average activation and a small target rate.

## Activation functions

**ReLU (Rectified Linear Unit)** — zero for negative inputs, identity for positive ones:

$$
\mathrm{ReLU}(x) = \max(0, x).
$$

**Sigmoid** — squashes any real number into $(0, 1)$ and passes through $0.5$ at $x = 0$:

$$
\sigma(x) = \frac{1}{1 + e^{-x}}.
$$

The sigmoid is a natural output activation when pixel intensities are scaled to $[0, 1]$.
