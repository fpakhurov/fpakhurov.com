A $256 \times 256$ colour image, read value by value, is a sequence of $196{,}608$ numbers. A PixelCNN predicts each of them from a fixed neighbourhood. A language model of the GPT family predicts each word from *all* earlier words, and it works for sequences of a few thousand tokens. Could we generate images the way GPT generates text?

The obstacle is length. Self-attention compares every position with every earlier one, so a sequence 100 times longer costs 10,000 times more per layer. The way around it is to change what a token is: a palette colour of a small image in ImageGPT, then a code of a learned discrete autoencoder in VQGAN, DALL·E and Parti. Once an image is a short sequence of codes, text-to-image becomes continuing a caption.

## From convolutions to attention

A decoder-only transformer is a stack of blocks, each a self-attention layer followed by a small network applied to every position separately, both with residual connections. Self-attention is the block of [SAGAN](/notes/generative-models/gan-scaling#the-self-attention-block): each position takes a weighted average of the values of the positions it sees, with softmax weights from query–key scores. Here it carries a **causal mask**: scores of later positions are set to $-\infty$ before the softmax, so their weights are $e^{-\infty} = 0$ and the first layer's output at position $i$ depends only on positions $1, \dots, i$. The per-position network and the residual connections mix nothing across positions, so by induction over the layers the same holds for every layer. If you have taken the NLP course, its [attention note](/notes/nlp/attention#masks) derives self-attention and its masks in full; it is optional background here.

The network models a token sequence $s = (s_1, \dots, s_N)$ from a vocabulary of $K$ tokens with the chain rule of the [previous note](/notes/generative-models/autoregressive-models#the-chain-rule-as-a-model), $p(s) = \prod_i p(s_i \mid s_{<i})$. A grid of $h \times w$ tokens is read row by row, so $N = hw$. Training is that of the [previous note](/notes/generative-models/autoregressive-models#parallel-training-sequential-sampling): one parallel pass with teacher forcing and a cross-entropy at every position.

Two details line up with PixelCNN. The mask keeps later tokens out, and a **shift** keeps the target itself out: the input is $(\text{BOS}, s_1, \dots, s_{N-1})$ with a start token BOS, and the output at input position $i$, which has seen $(\text{BOS}, s_1, \dots, s_{i-1})$, predicts $s_i$. Mask A of PixelCNN did both at once by hiding the centre. And there is no [blind spot](/notes/generative-models/autoregressive-models#the-blind-spot): every layer can attend to every earlier position.

The price is the number of pairs. Position $i$ attends to $i$ positions, so one layer compares

$$
\sum_{i=1}^{N} i = \frac{N(N+1)}{2}
$$

pairs, a cost that grows with the square of the sequence length and decides what the tokens of an image can be.

<SequenceLengths />

Sampling multiplies the cost again. Producing token $t$ by rerunning the network on the whole prefix of length $t$ compares $t(t+1)/2$ pairs per layer. To sum over $t$, factor the difference of two consecutive products:

$$
\begin{aligned}
&t(t+1)(t+2) - (t-1)t(t+1) \\
&\quad = t(t+1)\big[(t+2) - (t-1)\big] \\
&\quad = 3\,t(t+1) .
\end{aligned}
$$

Summed from $t = 1$ to $N$, the left side telescopes to $N(N+1)(N+2) - 0$, so $\sum_{t=1}^{N} t(t+1) = N(N+1)(N+2)/3$; halving gives the total without a cache. With a cache, step $t$ compares one new query with $t$ keys:

$$
\begin{aligned}
\text{no cache:}\quad \sum_{t=1}^{N} \frac{t(t+1)}{2} &= \frac{N(N+1)(N+2)}{6}, \\
\text{KV cache:}\quad \sum_{t=1}^{N} t &= \frac{N(N+1)}{2} .
\end{aligned}
$$

The keys and values of earlier positions do not change when a token is appended: by the induction above, the state of position $j$ in every layer depends only on tokens $1, \dots, j$. So a **KV cache** keeps them and computes attention only for the new query. For a grid of $N = 1024$ tokens that is 179,481,600 pairs per layer without the cache and 524,800 with it, $(N+2)/3 = 342$ times fewer. The memory price is two vectors per layer and position.

Three knobs turn a predicted distribution into a sample. **Temperature** $T$ divides the logits by $T$ before the softmax; for $T < 1$ the gaps between logits grow and the mass moves to the likeliest values. **Top-$k$** keeps the $k$ likeliest values, and **top-$p$** the smallest set of likeliest values whose probabilities sum to at least $p$; the kept values are renormalized. The Code section implements all three. On images they act like the [truncation trick](/notes/generative-models/gan-scaling#the-truncation-trick) of GANs, as the VQGAN numbers below show.

## Pixels as tokens: ImageGPT

ImageGPT ([Chen et al., 2020](#references)) applies GPT-2 to images with as little change as possible. A $224 \times 224 \times 3$ image is $150{,}528$ values; against GPT-2's context of 1024 tokens, the attention matrix would be $(150{,}528 / 1024)^2 = 147^2 = 21{,}609$ times larger. So the image is first downsampled to $32 \times 32$ or $48 \times 48$, and the three channels of each pixel are replaced by the nearest of 512 colours found by [k-means](/notes/ml/clustering): a sequence of 1024 or 2304 tokens over a vocabulary of 512. The palette is the simplest tokenizer, a VQ-VAE with an identity encoder and decoder. The largest model, iGPT-L, is GPT-2 with 48 layers and width 1536, 1.4 billion parameters.

The paper's main interest is representation. A model trained only to predict the next pixel learns features that classify CIFAR-10 with 96.3% accuracy by a linear classifier on top and 99.0% after fine-tuning. Its sequences describe only $32 \times 32$ or $48 \times 48$ images: pixel tokens do not scale to larger ones.

## Learned tokens: the two-stage recipe

The way out was already in the [VQ-VAE](/notes/generative-models/vae-variants#where-the-prior-went): train a discrete autoencoder first, then an autoregressive model over its codes. With a downsampling factor $f$, an $H \times W$ image becomes a grid of $(H/f) \times (W/f)$ tokens, and the transformer never sees a pixel.

<TwoStage />

The two stages divide the work as in [latent diffusion](/notes/generative-models/latent-diffusion), which came later from the same group as VQGAN: the tokenizer handles textures and local detail, and the transformer handles composition. The tokenizer must therefore compress hard and still reconstruct sharp images, which a plain VQ-VAE trained with a squared error does not do.

### VQGAN

VQGAN ([Esser, Rombach and Ommer, 2021](#references)) keeps the vector quantizer, the codebook and the commitment terms of the VQ-VAE and changes the reconstruction loss. The squared error is replaced by a perceptual loss, as in [LPIPS](/notes/generative-models/lpips), and a patch-based discriminator judges small patches of the reconstruction as real or not. The two losses have very different scales, and the adversarial one gets an adaptive weight

$$
\lambda = \frac{\lVert \nabla_{G_L} \mathcal L_{\text{rec}} \rVert}{\lVert \nabla_{G_L} \mathcal L_{\text{GAN}} \rVert + \delta},
$$

where $G_L$ is the last layer of the decoder and $\delta = 10^{-6}$ prevents division by zero. The gradient that reaches $G_L$ is $\nabla \mathcal L_{\text{rec}} + \lambda \nabla \mathcal L_{\text{GAN}}$, and with this $\lambda$ the second term has norm $\lVert \nabla \mathcal L_{\text{rec}} \rVert \cdot \lVert \nabla \mathcal L_{\text{GAN}} \rVert / (\lVert \nabla \mathcal L_{\text{GAN}} \rVert + \delta) \approx \lVert \nabla \mathcal L_{\text{rec}} \rVert$: neither loss overwhelms the other.

With $f = 16$, a $256 \times 256$ image becomes a $16 \times 16$ grid, and the paper's default codebook has $K = 1024$ entries:

| Quantity | Value |
| --- | --- |
| tokens per image | $16 \cdot 16 = 256$ |
| bits per token, $\log_2 1024$ | 10 |
| bits per image | 2,560 |
| raw pixels, $256 \cdot 256 \cdot 3 \cdot 8$ | 1,572,864 bits |

The tokens hold about 614 times fewer bits than the pixels. The second stage is a GPT-2-medium transformer with 307 million parameters, and 256 tokens was the longest sequence that fit its training on a 12 GB GPU. Conditions are prepended as tokens: a class label, or the codes of a segmentation or depth map from a second VQGAN. Images in the megapixel range are generated with a sliding attention window, each token predicted from a $16 \times 16$ neighbourhood of codes.

### Sampling knobs on images

The class-conditional ImageNet model of VQGAN, with 16,384 codes, shows how much sampling settings matter ([Esser, Rombach and Ommer, 2021](#references), Table 4):

| Sampling | FID |
| --- | --- |
| top-$k$, $k = 973$ | 29.20 |
| top-$k$, $k = 250$ | 15.98 |
| top-$k$ 973 and top-$p$ 0.88 | 15.78 |
| mixed $k$, best 5% by a ResNet-101 classifier | 5.88 |
| BigGAN, for comparison | 7.53 |

The rows filter by different scores. Top-$k$ and top-$p$ drop, at every step, the codes the model itself finds unlikely. The classifier row draws whole images and keeps the 5% with the highest ResNet-101 score for their class: it filters by the classifier's confidence, not by the model's likelihood. Every row only removes or reweights the model's own samples, so none adds samples where the model puts no mass; such filtering trades [recall for precision](/notes/generative-models/precision-recall#where-the-trade-off-appears). The FID improves because the remaining samples are more typical of their class; the model does not cover more of the data.

## Text to image: DALL·E

DALL·E ([Ramesh et al., 2021](#references)) applies the recipe at scale. Its tokenizer, a discrete VAE, turns a $256 \times 256$ image into a $32 \times 32$ grid over 8192 codes: 1024 tokens for $196{,}608$ values, 192 times fewer. The caption is encoded into at most 256 BPE tokens from a vocabulary of 16,384, and text and image tokens are concatenated into one sequence. A single decoder-only transformer with 12 billion parameters and sparse attention models the whole stream, trained on 250 million image–caption pairs. Generation is the continuation of a caption: feed the text tokens and sample the 1024 image tokens.

Samples are drawn in batches and reranked: a contrastive image–text model ([CLIP](/notes/deep-learning/vision-transformers#clip-contrastive-pretraining-on-images-and-captions)) scores each of 512 candidates against the caption, and the best are kept. Against DF-GAN, a GAN trained on MS-COCO, human raters preferred the DALL·E sample as more realistic 90.0% of the time and as better matching the caption 93.3% of the time, although DALL·E never trained on MS-COCO captions.

## Parti: an encoder–decoder at scale \{#parti-an-encoder-decoder-at-scale\}

Parti ([Yu et al., 2022](#references)) treats text-to-image as translation. An encoder reads the caption, and a decoder generates the 1024 image tokens of a ViT-VQGAN, a VQGAN whose encoder and decoder are vision transformers, with 8192 codes. A small super-resolution network raises the decoded $256 \times 256$ images to $1024 \times 1024$. Quality and agreement with the text keep improving from 350 million to 20 billion parameters; the largest model reaches a zero-shot FID of 7.23 on MS-COCO.

Two tools from other families improve the samples. [Classifier-free guidance](/notes/generative-models/latent-diffusion#classifier-free-guidance) works on logits as it works on scores: the model is trained with the caption sometimes dropped, and sampling combines the unconditional and conditional predictions with a weight above one. The [audio note](/notes/generative-models/audio-generation#classifier-free-guidance-on-logits) derives which distribution this samples. Reranking keeps the best of 16 samples per prompt instead of DALL·E's 512. The paper also introduced PartiPrompts, the set of over 1,600 prompts described in the [human evaluation note](/notes/generative-models/human-evaluation#how-good-and-does-it-match).

## Where it breaks

The tokenizer caps what the transformer can produce, because every sample is a decoder output. In VQGAN with $f = 16$, one token stands for a $16 \times 16$ patch of $16 \cdot 16 \cdot 3 \cdot 8 = 6144$ bits of pixels and carries 10 bits. Detail that the codebook cannot express, such as small text or a small face in a crowd, is lost in every sample. On ImageNet, reconstructions through a $16 \times 16$ grid have an [FID](/notes/generative-models/fid) of 7.94 to the validation images with 1024 codes and 4.98 with 16,384, against 32.01 for DALL·E's tokenizer, a $32 \times 32$ grid of 8192 codes trained without perceptual and adversarial losses ([Esser, Rombach and Ommer, 2021](#references), Table 5). The VQGAN paper reads this number as an estimate of the FID the second stage can reach. It is an empirical reference: it measures the reconstructions, and a prior that places its mass differently on decoder outputs can score higher or lower.

The sampling order is the second limit. A token, once drawn, is never revised, and an early mistake in the top-left corner shapes everything after it. A diffusion model refines the whole latent over 20 to 50 steps and can correct itself; an autoregressive model needs 1024 sequential passes for a $32 \times 32$ grid. Both families now share the rest: a separately trained autoencoder, text conditioning through attention and classifier-free guidance. The autoregressive one adds the exact likelihood of the tokens and the architecture, training code and scaling behaviour of language models.

## What you should remember

- A causal transformer is a PixelCNN without a blind spot; one layer costs $N(N+1)/2$ pairs.
- The KV cache cuts naive sampling from $N(N+1)(N+2)/6$ pairs per layer to $N(N+1)/2$.
- ImageGPT shortens pixel sequences with a small image and a 512-colour palette.
- Two stages: a discrete autoencoder makes tokens, a transformer models them.
- VQGAN: perceptual and adversarial losses with an adaptive weight make $16 \times 16$ tokens sharp.
- DALL·E puts the caption in the sequence, Parti in an encoder; top-$k$, top-$p$ and reranking trade diversity for typical samples.

## Code

A small decoder-only transformer in NumPy, with a causal mask, a KV cache and the sampling filters. It checks that cached and uncached logits agree, that changing a later token leaves earlier predictions unchanged, and the pair counts for $N = 1024$.

```python
import numpy as np

rng = np.random.default_rng(0)
V, d, L, max_len = 16, 32, 2, 64                   # vocabulary, width, layers, positions
emb, pos = rng.normal(size=(V, d)), rng.normal(size=(max_len, d))
Wq, Wk, Wv, Wo = (rng.normal(size=(L, d, d)) / np.sqrt(d) for _ in range(4))
head = rng.normal(size=(d, V)) / np.sqrt(d)

def softmax(z):
    z = np.exp(z - z.max(-1, keepdims=True))
    return z / z.sum(-1, keepdims=True)

def forward(tokens, cache=None, start=0):
    """Logits for tokens at positions start .. start+T-1; cache holds keys and values of earlier positions."""
    x = emb[tokens] + pos[start:start + len(tokens)]
    for l in range(L):
        q, k, v = x @ Wq[l], x @ Wk[l], x @ Wv[l]
        if cache is not None:
            k = np.concatenate([cache[l]['k'], k]) if cache[l] else k
            v = np.concatenate([cache[l]['v'], v]) if cache[l] else v
            cache[l] = {'k': k, 'v': v}
        scores = q @ k.T / np.sqrt(d)               # [T, S]: new queries against all visible keys
        qpos = start + np.arange(len(tokens))[:, None]
        scores[np.arange(k.shape[0])[None, :] > qpos] = -np.inf   # causal mask: no later keys
        x = x + softmax(scores) @ v @ Wo[l]
    return x @ head

def filter_logits(z, temperature=1.0, top_k=None, top_p=None):
    z = z / temperature
    if top_k is not None:                           # keep the k largest logits
        z = np.where(z < np.sort(z)[-top_k], -np.inf, z)
    if top_p is not None:                           # smallest set whose probability reaches top_p
        order = np.argsort(-z)
        p = softmax(z)[order]
        drop = np.cumsum(p) - p >= top_p            # mass before this token already reaches top_p
        z[order[drop]] = -np.inf
    return z

# generate 20 tokens with the cache, one new token per pass
cache = [{} for _ in range(L)]
seq = [1, 2, 3]
logits = forward(np.array(seq), cache)
for _ in range(20):
    probs = softmax(filter_logits(logits[-1], temperature=0.7, top_k=5))
    seq.append(int(rng.choice(V, p=probs)))
    logits = forward(np.array(seq[-1:]), cache, start=len(seq) - 1)

full = forward(np.array(seq[:-1]))                 # every position recomputed from scratch
c = [{} for _ in range(L)]                         # the same positions, one token per pass
step = np.concatenate([forward(np.array([t]), c, start=i) for i, t in enumerate(seq[:-1])])
print('max |cached - full| =', float(np.abs(full - step).max()))
a = np.array(seq[:10]); b = a.copy(); b[7] = (b[7] + 1) % V
print('earlier logits unchanged:', np.allclose(forward(a)[:7], forward(b)[:7]))

N = 1024                                           # pairs compared per layer while sampling N tokens
print(N * (N + 1) * (N + 2) // 6, N * (N + 1) // 2, (N + 2) / 3)

z = np.array([2.0, 1.5, 1.0, 0.0, -1.0])
for kw in [{}, {'temperature': 0.7}, {'top_k': 3}, {'top_p': 0.7}]:
    print(kw, softmax(filter_logits(z.copy(), **kw)).round(3))
```

The largest difference is the rounding error of 64-bit arithmetic. Top-$p$ with $p = 0.7$ keeps two tokens, because the first alone has 0.463 of the mass and the first two have 0.744.
