The sales total for 1 November changed from 3200 to 3500 cents. The table is still called `daily_sales`. Its name tells us where to look up the current value. To explain a result exported before the correction, we need to know which version the export used.

## Describe the dataset before using it

A **catalog** is an inventory of datasets and services. It lets us find the maintained daily-sales dataset, its owner, the meaning of a row, its update schedule and a way to request access. The logical dataset is distinct from a concrete distribution or delivery format. The same daily totals can be exposed as a warehouse table and a downloadable file. DCAT describes datasets and their distributions as separate entities. [W3C DCAT 3, §§6.6, 6.8](#references)

A storage address by itself does not say whether a value is authoritative. The catalog entry records why the dataset exists and the interface on which a consumer can rely. It may point to the data contract. A consumer still needs authorization to read the data. Discovery and access are two distinct operations.

## Record which run produced the value

**Lineage** records where data came from and how it was transformed. A statement such as “orders feed daily sales” describes a dependency. To explain a particular result, record the run and the versions at both ends. In the example, the job `sum_daily_sales` runs twice for the same day.

| Run | Source snapshot | Code revision | Result snapshot | Total in cents |
| --- | --- | --- | --- | --- |
| R17 | S1 | C3 | D7 | 3200 |
| R24 | S2 | C3 | D8 | 3500 |

Each run used the same code. The input snapshot changed. This evidence distinguishes an input correction from a new calculation. The W3C PROV model can describe a derivation through the activity that used an input entity and generated an output entity. OpenLineage separates a job definition, a particular run and the input and output datasets. Run events and facets can carry additional context such as the code version. [W3C PROV-DM, §5.2.1](#references) [OpenLineage, Object Model](#references)

## Follow the edges both ways

Starting from result D8, we can trace upstream to run R24 and source S2. Starting from D7, we can search downstream for consumers that read it. If an export run produced a file from D7, replacing the table does not replace that file. The export is a separate output with its own version and repair decision.

Lineage has a granularity. A dataset-level edge says an export depended on daily sales. It does not establish which input field contributed to one output column. Column-level lineage can record that `total_cents` depends on `amount_cents`. Reproducing a value still requires preserved inputs, transformation code and relevant parameters. If an uninstrumented script read the table or a source snapshot expired, an edge or a reproduction can be missing.
