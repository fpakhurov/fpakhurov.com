The [Markov decision processes](/notes/agents/markov-decision-processes) note computed optimal values by sweeping Bellman backups, and every backup read the transition probabilities $P(s' \mid s, a)$ and the rewards $R(s, a, s')$. The [games note](/notes/agents/games-and-tree-search) relaxed this only a little: Monte Carlo tree search does not need the probabilities written down, but it needs a simulator it can reset to any position. Most agents have neither. A robot does not know the friction of the floor, a trading agent does not know the market, and a language-model agent does not know what a tool will return until it calls it. What they can do is act and watch what happens, one transition at a time. **Reinforcement learning** is the study of agents that learn to act well from such experience. This note builds its first algorithms: how to explore when the values are unknown, how to estimate values from sampled episodes, and how the same idea gives SARSA and Q-learning, the two basic control methods.

**Notation.** We keep the notation of the MDP note: states $s$, actions $a$, transitions $P(s' \mid s, a)$, rewards $R(s, a, s')$, discount $\gamma$, the random state, action and reward $S_t, A_t, R_{t+1}$ at step $t$, a policy $\pi(a \mid s)$, the return $G_t$, the values $V^\pi, Q^\pi$ and the optimal values $V^\star, Q^\star$. New here: the agent's current estimates $V(s)$ and $Q(s, a)$ (no superscript), a step size $\alpha \in (0, 1]$, the TD error $\delta_t$, and an exploration probability $\varepsilon$. A **transition** is the tuple $(S_t, A_t, R_{t+1}, S_{t+1})$ that the agent observes after one step. In episodic tasks that end with probability 1 we allow $\gamma = 1$.

## Baseline: value iteration needs the model

The optimal action values satisfy the Bellman optimality equation of the [MDP note](/notes/agents/markov-decision-processes#the-bellman-optimality-equation), written for $Q^\star$:

$$
Q^\star(s, a) = \sum_{s'} P(s' \mid s, a) \Big( R(s, a, s') + \gamma \max_{a'} Q^\star(s', a') \Big).
$$

Value iteration evaluates the sum on the right exactly, for every state and action. An agent that does not know $P$ cannot. But it can take action $a$ in state $s$ and see one next state $S_{t+1}$ and one reward $R_{t+1}$, and the bracket evaluated at that sample has the right expectation:

$$
\mathbb E\Big[ R_{t+1} + \gamma \max_{a'} Q^\star(S_{t+1}, a') \,\Big|\, S_t = s, A_t = a \Big] = Q^\star(s, a).
$$

A sum weighted by unknown probabilities is an expectation, and an expectation can be estimated by averaging samples, as in the [Monte Carlo methods](/notes/probability/monte-carlo#plain-monte-carlo-and-its-error) of the Probability course. The average does not even have to be stored as a sum. The mean of $n$ numbers $x_1, \dots, x_n$ updates one sample at a time:

$$
\begin{aligned}
\bar x_n &= \frac1n \sum_{i=1}^{n} x_i = \frac1n \Big( x_n + (n - 1)\, \bar x_{n-1} \Big) && \text{split off the last term} \\
&= \bar x_{n-1} + \frac1n \big( x_n - \bar x_{n-1} \big). && \text{rearrange}
\end{aligned}
$$

Every algorithm of this note has this form: *estimate ← estimate + step × (target − estimate)*. With the step $1/n$ the estimate is the exact sample mean; with a constant step $\alpha$ it is an exponentially weighted mean that forgets old samples, which suits targets that change as the agent learns. Two problems come with the samples, and they organize the note. The agent chooses which actions it samples, so it must decide how much to explore. And in the equation above the target contains $Q^\star$ itself, which is unknown, so the agent must learn from targets built on its own estimates.

## Exploration first: the multi-armed bandit

Strip the problem down to one state. A **multi-armed bandit** has $k$ actions, or arms; pulling arm $a$ gives a random reward with unknown mean $q^\star(a)$. Over $T$ pulls the agent wants as much reward as possible. Its estimate of each arm is the sample mean $Q_t(a)$ of the rewards it has seen from that arm, after $N_t(a)$ pulls. The loss against always pulling the best arm, the **regret**, is

$$
\begin{aligned}
L_T &= T \max_a q^\star(a) - \mathbb E\Big[\sum_{t=1}^{T} R_t\Big] = \sum_a \Delta_a\, \mathbb E[N_T(a)], \\
\Delta_a &= \max_b q^\star(b) - q^\star(a),
\end{aligned}
$$

where the second form follows by grouping the pulls by arm: every pull of arm $a$ loses $\Delta_a$ in expectation. A good strategy pulls bad arms rarely, and it can only know which arms are bad by pulling them. This is the **exploration–exploitation dilemma** in its purest form.

**Greedy.** Always pull the arm with the largest estimate. One unlucky first reward from the best arm can make its estimate low, and then it is never pulled again, so its estimate is never corrected. Greedy can be wrong forever, and its regret grows linearly in $T$.

**ε-greedy.** With probability $\varepsilon$ pull an arm chosen uniformly at random, otherwise act greedily. Every arm is then pulled infinitely often, so by the [law of large numbers](/notes/probability/law-of-large-numbers) every estimate converges to its mean and the greedy choice becomes right. The price is that a fraction $\varepsilon (k - 1)/k$ of the pulls goes to wrong arms forever: regret still grows linearly, only more slowly.

**Upper confidence bound (UCB).** Pull the arm whose estimate *could* plausibly be the highest:

$$
\boxed{\; A_t = \arg\max_a \Big[\, Q_t(a) + c \sqrt{\frac{\ln t}{N_t(a)}} \,\Big] \;}
$$

with arms that have never been pulled tried first. The bonus is the width of a confidence interval: the standard error of a sample mean shrinks like $1/\sqrt{N_t(a)}$, and the slowly growing $\ln t$ makes sure that every arm is eventually revisited. The principle is **optimism in the face of uncertainty**: act as if each arm were as good as the data still allow. An arm that is pulled because of its bonus either turns out good, and the agent gains, or turns out bad, and its bonus shrinks. With rewards in $[0, 1]$ and $c = \sqrt 2$, the regret of this rule, UCB1, is at most a constant times $\sum_{a : \Delta_a > 0} \ln T / \Delta_a$ for every $T$ ([Auer, Cesa-Bianchi and Fischer, 2002](#references)), and no strategy can do better than logarithmic regret on every bandit ([Lai and Robbins, 1985](#references)).

**Worked example.** At $t = 100$, three arms have estimates $Q = (1.2, 1.0, 0.3)$ after $N = (80, 15, 5)$ pulls, and $c = 2$. The bonuses are $2\sqrt{\ln 100 / 80} = 0.480$, $2\sqrt{\ln 100 / 15} = 1.108$ and $2 \sqrt{\ln 100 / 5} = 1.919$, so the scores are $1.680$, $2.108$ and $2.219$. UCB pulls the third arm, the one with the lowest estimate, because five pulls say too little about it to rule it out. Greedy would pull the first; ε-greedy with $\varepsilon = 0.1$ would pull the third with probability $0.1/3$.

The standard test of these rules is the **10-armed testbed** ([Sutton and Barto, 2018](#references), section 2.3): 2000 random bandits whose arm means are drawn from $\mathcal N(0, 1)$, with rewards drawn from $\mathcal N(q^\star(a), 1)$.

<BanditCurves />

Greedy levels off near $1.0$ and picks the best arm on only about a third of the steps. A little exploration, $\varepsilon = 0.01$, already lifts the average to about $1.3$, and $\varepsilon = 0.1$ explores fast enough to find the best arm 80% of the time within a thousand steps but keeps paying for its random pulls. UCB is the best of the four after the first steps, at about $1.48$. It is worst in the first ten steps, where it must try every arm once.

An MDP has a bandit problem in every state, with the complication that an action's value depends on what the agent will do later. The algorithms below use ε-greedy exploration, which is crude but simple and works in any state space. The UCB idea also drives tree search, where [UCT](/notes/agents/games-and-tree-search#selection-as-a-bandit-problem-ucb1-and-uct) applies it to the choice of a move at each node, and the count-based bonuses used for exploration in large state spaces; exploring well when states never repeat remains an open problem.

## Monte Carlo prediction

Before control, take the simpler problem of **prediction**: estimate $V^\pi$ for a fixed policy $\pi$ from episodes that $\pi$ generates. The value is an expected return, $V^\pi(s) = \mathbb E_\pi[G_t \mid S_t = s]$, so the most direct estimate waits until an episode ends, computes the return $G_t$ that followed each visit to a state, and moves the estimate towards it:

$$
V(S_t) \leftarrow V(S_t) + \alpha \big( G_t - V(S_t) \big).
$$

This is **Monte Carlo prediction** ([Sutton and Barto, 2018](#references), chapter 5). Its target is an unbiased sample of the value, by definition of $V^\pi$, and it uses nothing about the structure of the problem: the Markov property is not needed. Its weaknesses are the two sides of the same fact. It must wait for the episode to end, which is useless in tasks that never end. And $G_t$ adds up every random reward and every random transition until the end, so its variance grows with the length of the episode.

## TD(0): learning a guess from a guess

The Bellman expectation equation of the [MDP note](/notes/agents/markov-decision-processes#the-bellman-expectation-equation) says that the value of a state is the expected one-step reward plus the discounted value of the next state:

$$
V^\pi(s) = \mathbb E_\pi\big[ R_{t+1} + \gamma V^\pi(S_{t+1}) \,\big|\, S_t = s \big].
$$

Take one sample of the expectation, and replace the unknown $V^\pi(S_{t+1})$ by the current estimate. The result is the **TD(0)** update of [Sutton (1988)](#references):

$$
\boxed{
\begin{gathered}
V(S_t) \leftarrow V(S_t) + \alpha\, \delta_t, \\
\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)
\end{gathered}
}
$$

with $V(S_{t+1}) = 0$ when $S_{t+1}$ is terminal. The quantity $\delta_t$ is the **temporal-difference error**: the difference between two estimates of the same value made at successive times, one before the step and one after it. Using an estimate inside the target is called **bootstrapping**.

<aside class="callout"><strong>Key idea.</strong> A value function must be consistent with itself: the value of a state equals the expected reward of one step plus the discounted value of the next state. TD learning does not wait for the true return. After every step it measures how far the current estimates are from this consistency and moves them closer. The target is a guess, but a guess made one step later, with one more real reward in it.</aside>

The running example is a **random walk** ([Sutton and Barto, 2018](#references), example 6.2): five states A to E in a row, starting in C; each step goes left or right with probability $1/2$; leaving on the left gives reward 0, leaving on the right gives reward 1, and $\gamma = 1$. The value of a state is the probability of leaving on the right, which by the [gambler's ruin](/notes/probability/markov-chains#hitting-probabilities-the-gamblers-ruin) is $1/6, 2/6, \dots, 5/6$ from A to E. One step of learning, in the middle of training:

<TdBackup />

1. **Act.** In C, the walk steps right to D with reward $R_{t+1} = 0$.
2. **TD target.** The reward plus the estimate of the next state: $0 + 1 \cdot V(\text{D}) = 0.60$.
3. **TD error.** The target minus the current estimate: $\delta_t = 0.60 - 0.50 = 0.10$.
4. **Update at once.** With $\alpha = 0.1$, $V(\text{C}) \leftarrow 0.50 + 0.1 \cdot 0.10 = 0.51$, and the agent continues from D.
5. **Monte Carlo, for contrast.** It waits. This episode goes on to E and leaves on the right, so $G_t = 1$ and $V(\text{C}) \leftarrow 0.50 + 0.1 \cdot (1 - 0.50) = 0.55$, but only after the episode has ended.

## Which target is better: bias against variance

The two targets estimate the same value with different errors.

**The Monte Carlo target is unbiased.** $\mathbb E_\pi[G_t \mid S_t = s] = V^\pi(s)$ by definition. Its variance includes the randomness of every remaining step.

**The TD target is biased while the estimates are wrong.** By linearity and the Bellman equation,

$$
\begin{aligned}
\mathbb E_\pi\big[ R_{t+1} + \gamma V(S_{t+1}) \mid S_t = s \big]
&= \mathbb E_\pi\big[ R_{t+1} + \gamma V^\pi(S_{t+1}) \mid S_t = s \big] + \gamma\, \mathbb E_\pi\big[ V(S_{t+1}) - V^\pi(S_{t+1}) \mid S_t = s \big] && \text{add and subtract } \gamma V^\pi \\
&= V^\pi(s) + \gamma\, \mathbb E_\pi\big[ V(S_{t+1}) - V^\pi(S_{t+1}) \mid S_t = s \big]. && \text{Bellman expectation equation}
\end{aligned}
$$

The bias is the discounted error of the estimates one step ahead, and it disappears as they become right. Its variance comes from a single reward and a single transition.

**The two errors are related exactly.** Hold $V$ fixed during an episode that ends at step $T$. The Monte Carlo error is the discounted sum of the TD errors along the way:

$$
\begin{aligned}
G_t - V(S_t) &= R_{t+1} + \gamma G_{t+1} - V(S_t) && G_t = R_{t+1} + \gamma G_{t+1} \\
&= \big( R_{t+1} + \gamma V(S_{t+1}) - V(S_t) \big) + \gamma \big( G_{t+1} - V(S_{t+1}) \big) && \text{add and subtract } \gamma V(S_{t+1}) \\
&= \delta_t + \gamma \big( G_{t+1} - V(S_{t+1}) \big) && \text{definition of } \delta_t \\
&= \delta_t + \gamma \delta_{t+1} + \gamma^2 \big( G_{t+2} - V(S_{t+2}) \big) = \dots = \sum_{k=0}^{T - t - 1} \gamma^k \delta_{t+k}, && \text{repeat; } G_T = V(S_T) = 0
\end{aligned}
$$

so a Monte Carlo update is the sum of all the TD updates of the episode, applied at the end. TD applies each piece as soon as it is known and, through bootstrapping, passes on what it learned about $S_{t+1}$ to $S_t$ without waiting for the rest of the episode to repeat. The same identity returns in [Policy gradients and actor-critic](/notes/agents/policy-gradients), where a weighted version of this sum becomes the generalized advantage estimator.

On the random walk the lower variance wins:

<RandomWalkRms />

After 100 episodes TD(0) with $\alpha = 0.05$ is at an error of about $0.035$, while the better of the two Monte Carlo curves is at about $0.08$. The step size trades speed for precision in both methods: a large $\alpha$ falls quickly and then fluctuates at a higher level, because each new target moves the estimate by a fixed fraction however much data came before.

**What the two methods converge to on a fixed batch.** Suppose the experience is a fixed set of episodes and each method is applied to it repeatedly until the estimates stop changing. Monte Carlo then gives the average return observed after each state. TD(0) gives the values of the Markov chain whose transition probabilities are the observed frequencies, the **maximum-likelihood model** of the data, a solution called certainty equivalence ([Sutton, 1988](#references); [Sutton and Barto, 2018](#references), section 6.3). The two can differ a lot. With eight episodes, one that went A → B and ended with reward 0, six that started in B and ended with reward 1, and one that started in B and ended with 0, both methods give $V(\text{B}) = 6/8 = 0.75$. For A, Monte Carlo gives 0, the return of its only episode, while TD gives $0 + V(\text{B}) = 0.75$, because every observed step from A led to B. If the process is Markov, the TD answer is the better one: it uses the transitions from B that were observed in other episodes.

## From prediction to control: SARSA and Q-learning

To improve a policy without a model, the agent needs action values. Greedy improvement with respect to $V$ requires $\sum_{s'} P(s' \mid s, a)(\dots)$, which needs $P$; greedy improvement with respect to $Q$ is just $\arg\max_a Q(s, a)$. Control methods therefore learn $Q$ and act ε-greedily with respect to it, so that evaluation and improvement are interleaved at every step, as in policy iteration but without waiting for the evaluation to finish.

**SARSA** applies TD(0) to action values. It uses the five quantities $(S_t, A_t, R_{t+1}, S_{t+1}, A_{t+1})$ that give it its name ([Rummery and Niranjan, 1994](#references)):

$$
Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \big[ R_{t+1} + \gamma\, Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t) \big],
$$

where $A_{t+1}$ is the action the agent will actually take next, drawn from its ε-greedy policy. The target is a sample of the Bellman expectation equation for $Q^\pi$, with $\pi$ the policy being followed. SARSA is **on-policy**: it learns the value of the policy that generates the data, exploration included.

**Q-learning** ([Watkins, 1989](#references); [Watkins and Dayan, 1992](#references)) replaces the next action by the best one:

$$
\boxed{\; Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \Big[ R_{t+1} + \gamma \max_{a} Q(S_{t+1}, a) - Q(S_t, A_t) \Big] \;}
$$

The target is a sample of the Bellman optimality equation from the baseline section. The expectation in that equation is over the environment only, the next state and reward given $(s, a)$, and not over the agent's next action. That is why the behaviour can be anything that keeps visiting every state and action: Q-learning is **off-policy**, and it learns $Q^\star$, the values of the greedy policy, while following an exploratory one. Between the two lies **expected SARSA**, whose target averages the next action over the policy, $R_{t+1} + \gamma \sum_a \pi(a \mid S_{t+1}) Q(S_{t+1}, a)$; Q-learning is expected SARSA with a greedy target policy.

The whole agent is a loop:

1. Initialize $Q(s, a)$, for example to 0, and observe the start state $S_0$.
2. Choose $A_t$ ε-greedily from $Q(S_t, \cdot)$, take it, observe $R_{t+1}$ and $S_{t+1}$.
3. Update $Q(S_t, A_t)$ with the target of the chosen method (for SARSA, first choose $A_{t+1}$, then use it both in the target and as the next action).
4. If $S_{t+1}$ is terminal, start a new episode; otherwise set $t \leftarrow t + 1$ and go to 2.

## Cliff walking: what on-policy and off-policy learn

The difference between the two methods shows on a grid where exploration is dangerous ([Sutton and Barto, 2018](#references), example 6.6). The grid has 4 rows and 12 columns. The agent starts at the bottom left and must reach the bottom right. The ten cells between them are a cliff: stepping into it gives $-100$ and sends the agent back to the start. Every other step gives $-1$, $\gamma = 1$, and both agents explore with $\varepsilon = 0.1$ and learn with $\alpha = 0.5$.

<CliffWalking />

Q-learning learns $Q^\star$, whose greedy path runs right along the edge of the cliff: 13 steps, a return of $-13$. But the agent does not follow the greedy path; it follows the ε-greedy one, and on a path next to the cliff one random step in forty is a step down. The exact expected return of ε-greedy behaviour on $Q^\star$ is $-45.8$, and Q-learning's curve sits near $-50$. SARSA learns the value of the policy it follows, random steps included, and the states along the edge look bad to it. It settles on a path one row higher, whose 15 steps cost two more but keep a row between the agent and the cliff. The best ε-greedy policy has an expected return of $-20.7$; SARSA's curve, with the constant step $0.5$ keeping its estimates noisy, sits near $-27$.

**Worked example: one update next to the cliff.** Take the cell in the second row from the bottom and the seventh column, on the edge, and the step right from its neighbour, with reward $-1$. With the values at their limits, $Q^\star$ in the new cell is $-6$ for right, $-8$ for up and left, and $-113$ for down, which is $-100$ for the fall plus $-13$ for the walk from the start. Q-learning's target is $-1 + \max_a Q^\star = -1 - 6 = -7$. SARSA's next action is greedy with probability $0.925$ and each other action with probability $0.025$, so its target averages to

$$
-1 + 0.925 \cdot (-6) + 0.025 \cdot (-8 - 8 - 113) = -1 - 5.55 - 3.225 = -9.775 .
$$

Every cell on the edge carries this extra $-2.8$, the expected cost of a random fall, and SARSA's greedy choice routes around them.

Which answer is right depends on what the values are for. If exploration will be switched off after learning, Q-learning has found the better policy. If the agent must keep learning while it acts, as a robot or a deployed system does, SARSA's caution is worth having: it optimizes what actually happens. If $\varepsilon$ decays to zero over time, both converge to the optimal path.

## When the estimates converge

The tabular methods come with guarantees. They are stated here, not proved; the proofs view each update as a stochastic approximation, in the sense of [Robbins and Monro (1951)](#references), of the fixed point of a contraction such as the Bellman operator of the [MDP note](/notes/agents/markov-decision-processes#value-iteration). Assume a finite MDP with bounded rewards and $\gamma < 1$, or episodes that end with probability 1, and per-pair step sizes $\alpha_t(s, a)$ that satisfy

$$
\begin{aligned}
\sum_{t} \alpha_t(s, a) &= \infty, \\
\sum_{t} \alpha_t(s, a)^2 &< \infty,
\end{aligned}
$$

for example $\alpha = 1/N(s, a)$, one over the number of visits. The first condition lets the estimates travel any distance; the second makes the noise of the targets average out. [Stochastic variational inference](/notes/bayesian-methods/stochastic-variational-inference#step-sizes-the-robbinsmonro-conditions) needs the same conditions for the same reason. Then:

- **TD(0) prediction** converges to $V^\pi$ with probability 1 if every state is visited infinitely often ([Sutton, 1988](#references); [Dayan, 1992](#references); [Jaakkola, Jordan and Singh, 1994](#references)).
- **Q-learning** converges to $Q^\star$ with probability 1 if every state–action pair is updated infinitely often, whatever the behaviour policy ([Watkins and Dayan, 1992](#references); [Tsitsiklis, 1994](#references)).
- **SARSA** converges to $Q^\star$ with probability 1 if, in addition, the policy is **greedy in the limit with infinite exploration** (GLIE): every pair is tried infinitely often and the policy becomes greedy, for example ε-greedy with $\varepsilon$ decaying like one over the number of visits to the state ([Singh, Jaakkola, Littman and Szepesvári, 2000](#references)).

Three caveats matter in practice. With a constant $\alpha$, as in the figures, the estimates do not converge but keep fluctuating around the limit. The guarantees say nothing about speed: with $\alpha = 1/N$, the time Q-learning needs can grow exponentially in $1/(1 - \gamma)$, while steps $1/N^\omega$ with $\omega \in (1/2, 1)$ make it polynomial ([Even-Dar and Mansour, 2003](#references)). And everything rests on the table: one separate estimate per state. With function approximation the guarantees fail, which is the subject of the next note.

## Between one step and the whole episode: n-step returns and eligibility traces

TD(0) looks one step ahead and Monte Carlo looks to the end. The **n-step return** looks $n$ steps ahead and then bootstraps:

$$
G_{t:t+n} = R_{t+1} + \gamma R_{t+2} + \dots + \gamma^{n-1} R_{t+n} + \gamma^n V(S_{t+n}),
$$

with $G_{t:t+n} = G_t$ if the episode ends before $t + n$. $n = 1$ is TD(0) and $n = \infty$ is Monte Carlo; in between, bias falls and variance grows with $n$, and intermediate values often learn fastest ([Sutton and Barto, 2018](#references), chapter 7).

Instead of choosing one $n$, the **λ-return** averages all of them with geometrically decreasing weights:

$$
G_t^\lambda = (1 - \lambda) \sum_{n=1}^{\infty} \lambda^{n-1} G_{t:t+n}, \qquad \lambda \in [0, 1],
$$

and the weights $(1 - \lambda)\lambda^{n-1}$ sum to 1. With $\lambda = 0.5$ the one-, two- and three-step returns get $0.5$, $0.25$ and $0.125$; with $\lambda = 0.9$ they get $0.1$, $0.09$ and $0.081$, and the tail stretches far into the episode. $\lambda = 0$ is TD(0) and $\lambda = 1$ is Monte Carlo.

The λ-return looks into the future, but it can be computed by looking back. **TD(λ)** keeps an **eligibility trace** $z(s)$ for every state, a decaying memory of how recently and how often it was visited. At every step all traces decay by $\gamma\lambda$, the trace of the current state grows by 1, and every state is updated in proportion to its trace:

$$
z(s) \leftarrow \gamma \lambda\, z(s) + \mathbb 1[s = S_t], \qquad V(s) \leftarrow V(s) + \alpha\, \delta_t\, z(s) \quad \text{for all } s .
$$

One TD error is thus credited to all recently visited states at once, the most recent most. Summed over an episode with $V$ held fixed, these updates equal the updates towards the λ-returns, the identity of the previous section with $\gamma\lambda$ in place of $\gamma$ ([Sutton, 1988](#references); [Sutton and Barto, 2018](#references), chapter 12). The same mixture of horizons reappears in the multi-step targets of deep Q-networks and in the advantage estimator of policy gradients.

## What changed

| | value iteration | TD learning |
| --- | --- | --- |
| what the agent knows | $P$ and $R$ | only the transitions it experiences |
| update | a full backup, an expectation over $s'$ | a sample backup from one transition |
| target | exact | bootstrapped: $R_{t+1} + \gamma V(S_{t+1})$ or $\max_a Q(S_{t+1}, a)$ |
| which states | all of them, in sweeps | those the agent visits |
| new problem | none | exploration: the agent chooses its own data |
| guarantee | geometric convergence | convergence with probability 1, under visit and step-size conditions |

## Limitations

- **One estimate per state.** Tables do not generalize: a state never visited has an arbitrary value, and two nearly identical states are learned separately. Board games, images and texts have far more states than any table can hold.
- **ε-greedy explores blindly.** It spends the same effort on actions known to be terrible as on promising ones, and in tasks where reward requires a long precise sequence of actions, random exploration practically never finds it.
- **Step sizes and exploration rates need tuning.** The guarantees hold for decaying schedules; practice uses constants, and the results depend on them, as the figures show.
- **Q-learning overestimates.** The maximum of noisy estimates is biased upwards, a problem the next note treats with Double Q-learning.
- **Sample inefficiency.** Every transition is used once and thrown away. Replaying stored transitions, or learning a model and planning with it, are the two remedies of the next notes.

## What you should remember

- Without a model, an agent estimates expectations by averaging samples: *estimate ← estimate + α (target − estimate)*.
- Exploration is necessary because the agent chooses its own data. Greedy can fail forever; ε-greedy has linear regret; UCB's optimistic bonus $c\sqrt{\ln t / N_t(a)}$ gives logarithmic regret on bandits.
- Monte Carlo uses the return: unbiased, high variance, only at the end of an episode. TD(0) uses $R_{t+1} + \gamma V(S_{t+1})$: biased while $V$ is wrong, low variance, after every step. The Monte Carlo error is the discounted sum of TD errors.
- SARSA is on-policy and learns the value of the policy it follows; Q-learning is off-policy and learns $Q^\star$ from any sufficiently exploratory behaviour. On cliff walking SARSA takes the safe path, Q-learning the optimal one, which costs it more while it explores.
- Tabular TD and Q-learning converge with probability 1 when every pair is visited infinitely often and the step sizes satisfy $\sum \alpha = \infty$, $\sum \alpha^2 < \infty$; SARSA needs GLIE exploration as well.
- n-step returns and the λ-return interpolate between TD(0) and Monte Carlo; eligibility traces compute the λ-return online.

## Code

The 10-armed testbed with greedy, ε-greedy and UCB; TD(0) against constant-α Monte Carlo on the random walk; SARSA and Q-learning on cliff walking; and the exact limits of cliff walking, from value iteration and from the Bellman equation of the best ε-greedy policy. NumPy only, seeds fixed. The figures run the same experiments at build time with a different random generator and agree to the precision quoted in the text; exact digits also differ across platforms. The script runs in about 20 seconds.

```python
import numpy as np

# 1. the 10-armed testbed, vectorized over 2000 independent bandits; sample-average estimates
def bandit(eps=0.0, c=None, runs=2000, steps=1000, k=10, seed=0):
    rng = np.random.default_rng(seed)
    q = rng.normal(size=(runs, k))                              # true values q*(a)
    Q, N = np.zeros((runs, k)), np.zeros((runs, k))
    rows, reward, optimal = np.arange(runs), np.zeros(steps), np.zeros(steps)
    for t in range(steps):
        if c is None:                                           # epsilon-greedy, ties broken at random
            greedy = np.argmax(Q + 1e-9 * rng.random((runs, k)), axis=1)
            a = np.where(rng.random(runs) < eps, rng.integers(k, size=runs), greedy)
        else:                                                   # UCB: untried arms first
            bonus = np.where(N > 0, c * np.sqrt(np.log(t + 1) / np.maximum(N, 1)), np.inf)
            a = np.argmax(Q + bonus + 1e-9 * rng.random((runs, k)), axis=1)
        R = q[rows, a] + rng.normal(size=runs)
        N[rows, a] += 1
        Q[rows, a] += (R - Q[rows, a]) / N[rows, a]             # incremental sample average
        reward[t], optimal[t] = R.mean(), (a == q.argmax(1)).mean()
    return reward, optimal

for name, kw in [('greedy', {}), ('eps=0.01', {'eps': 0.01}), ('eps=0.1', {'eps': 0.1}), ('UCB c=2', {'c': 2})]:
    rew, opt = bandit(**kw)
    print(f'{name:9s} reward steps 901-1000 {rew[900:].mean():.2f}  optimal action {opt[900:].mean():.2f}')
# greedy    reward steps 901-1000 1.02  optimal action 0.35
# eps=0.01  reward steps 901-1000 1.29  optimal action 0.58
# eps=0.1   reward steps 901-1000 1.37  optimal action 0.80
# UCB c=2   reward steps 901-1000 1.48  optimal action 0.85

t, Q, N = 100, np.array([1.2, 1.0, 0.3]), np.array([80, 15, 5])    # the worked example of UCB
print((Q + 2 * np.sqrt(np.log(t) / N)).round(3))                    # [1.68  2.108 2.219]

# 2. prediction on the random walk A..E (start C, reward 1 on the right exit): TD(0) against constant-alpha MC
true_v = np.arange(1, 6) / 6
def walk(method, alpha, runs=100, episodes=100, seed=0):
    rng, rms = np.random.default_rng(seed), np.zeros(episodes + 1)
    for _ in range(runs):
        V = np.full(5, 0.5)
        rms[0] += np.sqrt(np.mean((V - true_v) ** 2)) / runs
        for ep in range(1, episodes + 1):
            s, visited = 2, [2]
            while True:
                s2 = s + (1 if rng.random() < 0.5 else -1)
                r, done = float(s2 == 5), s2 in (-1, 5)
                if method == 'td':                              # V(s) += alpha [r + V(s') - V(s)]
                    V[s] += alpha * (r + (0.0 if done else V[s2]) - V[s])
                if done:
                    break
                s = s2; visited.append(s)
            if method == 'mc':                                  # V(s) += alpha [G - V(s)], G = r at the exit
                for x in visited:
                    V[x] += alpha * (r - V[x])
            rms[ep] += np.sqrt(np.mean((V - true_v) ** 2)) / runs
    return rms

for method, alpha in [('td', 0.05), ('td', 0.1), ('mc', 0.02), ('mc', 0.04)]:
    e = walk(method, alpha)
    print(method, alpha, 'RMS after 10, 50, 100 episodes:', ' '.join(f'{e[i]:.3f}' for i in (10, 50, 100)))
# td 0.05 RMS after 10, 50, 100 episodes: 0.175 0.055 0.038
# td 0.1 RMS after 10, 50, 100 episodes: 0.131 0.051 0.059
# mc 0.02 RMS after 10, 50, 100 episodes: 0.196 0.112 0.077
# mc 0.04 RMS after 10, 50, 100 episodes: 0.182 0.112 0.101

# 3. cliff walking: 4 x 12 grid, -1 per step, -100 and back to the start for stepping into the cliff
ROWS, COLS, START, GOAL = 4, 12, 36, 47
MOVES = [(-1, 0), (0, 1), (1, 0), (0, -1)]                      # up, right, down, left
def step(s, a):
    r, c = divmod(s, COLS)
    r, c = min(ROWS - 1, max(0, r + MOVES[a][0])), min(COLS - 1, max(0, c + MOVES[a][1]))
    return (START, -100) if r == 3 and 1 <= c <= 10 else (r * COLS + c, -1)

def control(method, runs=100, episodes=500, alpha=0.5, eps=0.1, seed=0):
    rng, returns = np.random.default_rng(seed), np.zeros(episodes)
    def act(Q, s):                                              # epsilon-greedy with random tie-breaking
        if rng.random() < eps:
            return int(rng.integers(4))
        return int(rng.choice(np.flatnonzero(Q[s] == Q[s].max())))
    for _ in range(runs):
        Q = np.zeros((ROWS * COLS, 4))
        for ep in range(episodes):
            s, a, total = START, act(Q, START), 0
            while s != GOAL:
                s2, r = step(s, a)
                a2 = act(Q, s2)
                nxt = 0.0 if s2 == GOAL else (Q[s2, a2] if method == 'sarsa' else Q[s2].max())
                Q[s, a] += alpha * (r + nxt - Q[s, a])          # the only line in which the two differ: nxt
                s, a, total = s2, a2, total + r
            returns[ep] += total / runs
    return returns

for method in ('sarsa', 'q'):
    g = control(method)
    print(f'{method:5s} return per episode: episodes 1-50 {g[:50].mean():.1f}, episodes 401-500 {g[400:].mean():.1f}')
# sarsa return per episode: episodes 1-50 -110.1, episodes 401-500 -27.3
# q     return per episode: episodes 1-50 -114.9, episodes 401-500 -49.6

# 4. the exact limits: Q* (value iteration) and the best epsilon-greedy policy (its own Bellman equation)
def backup(V):
    Q = np.zeros((ROWS * COLS, 4))
    for s in range(ROWS * COLS):
        for a in range(4):
            if s != GOAL:
                s2, r = step(s, a); Q[s, a] = r + V[s2]
    return Q
def eps_value(Q, eps=0.1, iters=5000):                         # expected return of epsilon-greedy(Q), gamma = 1
    V = np.zeros(ROWS * COLS)
    pi = np.full((ROWS * COLS, 4), eps / 4); pi[np.arange(ROWS * COLS), Q.argmax(1)] += 1 - eps
    for _ in range(iters):
        V = (pi * backup(V)).sum(1); V[GOAL] = 0
    return V[START]
V = np.zeros(ROWS * COLS)
for _ in range(100):
    V = backup(V).max(1); V[GOAL] = 0
Qstar = backup(V)
U = np.zeros(ROWS * COLS)
for _ in range(5000):
    Qs = backup(U); U = 0.9 * Qs.max(1) + 0.1 * Qs.mean(1); U[GOAL] = 0
print('optimal return', V[START], '| eps-greedy on Q*', round(eps_value(Qstar), 2), '| best eps-greedy policy', round(U[START], 2))
# optimal return -13.0 | eps-greedy on Q* -45.8 | best eps-greedy policy -20.71

s2 = 2 * COLS + 6                                               # the worked example: the edge cell, seventh column
pi = np.full(4, 0.025); pi[Qstar[s2].argmax()] += 0.9
print(Qstar[s2], -1 + Qstar[s2].max(), round(-1 + pi @ Qstar[s2], 3))   # [  -8.   -6. -113.   -8.] -7.0 -9.775
```

## Next

Every method in this note keeps one number per state or per state–action pair. The cliff has 48 states; a frame of an Atari game has more possible screens than any memory could index, and a robot's joint angles are continuous. The values must be computed by a function with far fewer parameters than there are states, which also lets what is learned in one state carry over to similar ones. The [next note](/notes/agents/deep-q-networks) replaces the table by a neural network, shows why that combination can diverge, and builds the deep Q-network, whose experience replay and target network made it work on Atari.
