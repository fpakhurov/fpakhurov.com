The [previous note](/notes/agents/what-an-agent-is) classified agents by how much they compute before acting. A goal-based agent is told which states it wants and works out how to reach them. When the world is fully observable, deterministic and known, this can be done entirely in advance: the agent imagines sequences of actions with its model of the world, finds one that ends in a goal, and then executes it without needing to look. Finding that sequence is **search**. This note formulates the search problem, solves it with three algorithms of increasing cleverness, proves that the last of them, A\*, returns an optimal solution, and then describes the planning languages that let one formulation cover a whole family of problems. Both ideas come back later in the course, inside agents built on language models.

**Notation.** A state is $s$, an action $a$; $\mathrm{Actions}(s)$ is the set of actions applicable in $s$, $\mathrm{Result}(s, a)$ the state they lead to, and $c(s, a, s') > 0$ the cost of the step. A **node** $n$ of a search is a state together with the path that reached it; $g(n)$ is the cost of that path, $g^\star(n)$ the cost of the cheapest path to the state of $n$, $h(n)$ a heuristic estimate of the cheapest cost from $n$ to a goal, and $h^\star(n)$ that cheapest cost itself. $C^\star$ is the cost of an optimal solution. $b$ is the branching factor (the number of successors of a node), $d$ the depth of the shallowest goal and $\varepsilon > 0$ the smallest step cost.

## Formulating a problem

A search problem has five parts ([Russell and Norvig, 2021](#references), section 3.1):

1. a set of **states**, and an **initial state** $s_0$;
2. a **goal test**, which says whether a state is a goal (a set of goal states, or a predicate);
3. the **actions** $\mathrm{Actions}(s)$ available in each state;
4. a **transition model** $\mathrm{Result}(s, a)$;
5. an **action cost** $c(s, a, s')$.

A **solution** is a sequence of actions that leads from $s_0$ to a goal state; an **optimal** solution has the smallest total cost $C^\star$. The states and actions form a directed graph, the **state space**, and every solution is a path in it. On a road map the states are towns, the actions are roads and the costs are lengths. In the 8-puzzle, eight numbered tiles on a 3 × 3 board with one blank, a state is an arrangement of the tiles, an action slides a tile into the blank, and every action costs 1; half of the $9!$ arrangements can be reached from any given one, so the state space has $9!/2 = 181{,}440$ states.

Formulating a problem is a choice of abstraction. A route planner leaves out the weather, the radio and the exact position of the wheel; an abstraction is good if every abstract solution can be turned into a real one and the abstract problem is much smaller than the real one.

A search algorithm explores the state space from $s_0$ without building it in full. It keeps a **frontier** of nodes that have been reached but not yet expanded, and repeatedly **expands** one: it removes it from the frontier and adds the nodes for all its successors. Since the same state can be reached by several paths, a **graph search** also remembers which states it has reached, and keeps only the cheapest known path to each. The algorithms below differ in one thing only: which frontier node they expand next.

## Baseline: breadth-first search

**Breadth-first search** expands the shallowest node first, with a first-in, first-out queue as the frontier. It reaches every state at depth 1 before any at depth 2, and so on, so the first goal it reaches lies at the smallest depth $d$; it can check the goal test as soon as a node is generated. When every action costs the same, the shallowest goal is also the cheapest one, and breadth-first search is optimal.

The price is memory. With $b$ successors per node, it generates

$$
1 + b + b^2 + \dots + b^d = O(b^d)
$$

nodes and keeps all of them, because each reached state must be remembered. For $b = 10$ and $d = 12$ that is $10^{12}$ nodes, far more than a computer holds. And as soon as costs differ it is not optimal: a path of two expensive roads can be shallower than a path of three cheap ones.

## Uniform-cost search

**Uniform-cost search** expands the node with the smallest path cost $g(n)$, using a priority queue as the frontier. It is Dijkstra's algorithm for shortest paths ([Dijkstra, 1959](#references)), started from one source and stopped at the goal. Two details matter.

- **The goal test is applied when a node is expanded, not when it is generated.** On the graph of the figure below, uniform-cost search first reaches G through C with $g = 8$; only later does it reach G through D with $g = 7$. Stopping at the first G it generates would return the worse path.
- **Step costs must be positive**, at least some $\varepsilon > 0$. Then the costs of expanded nodes never decrease, the first goal expanded is optimal, and the search terminates. With zero-cost loops it could run forever; with negative costs Dijkstra's argument fails.

Uniform-cost search is optimal for any positive costs, but it is blind: it spreads out from $s_0$ in every direction, in order of cost, whether or not the direction leads to the goal. Its work grows like $b^{1 + \lfloor C^\star / \varepsilon \rfloor}$.

## A\*: guessing the remaining cost

<aside class="callout"><strong>Key idea.</strong> Add to the cost already paid an estimate of the cost still to pay, and expand the node whose total is smallest: $f(n) = g(n) + h(n)$. If the estimate never overstates the true remaining cost, the first goal expanded is optimal, and the better the estimate, the fewer nodes the search expands.</aside>

**A\*** search ([Hart, Nilsson and Raphael, 1968](#references)) expands the frontier node with the smallest

$$
f(n) = g(n) + h(n),
$$

an estimate of the cost of the cheapest solution that passes through $n$. With $h = 0$ it is uniform-cost search. Two properties of $h$ decide what A\* guarantees:

- $h$ is **admissible** if it never overestimates: $h(n) \le h^\star(n)$ for every $n$, and so $h = 0$ at goals.
- $h$ is **consistent** if it satisfies a triangle inequality along every step:

$$
h(n) \le c(n, a, n') + h(n') \qquad \text{for every action } a \text{ from } n \text{ to } n' = \mathrm{Result}(n, a), \qquad h(\text{goal}) = 0 .
$$

Consistency implies admissibility. Take a cheapest path $n = n_0, n_1, \dots, n_k$ from $n$ to a goal $n_k$ and apply the inequality $k$ times: $h(n_0) \le c(n_0, n_1) + h(n_1) \le c(n_0, n_1) + c(n_1, n_2) + h(n_2) \le \dots \le \sum_{i} c(n_i, n_{i+1}) + h(n_k) = h^\star(n)$. The converse fails, but most admissible heuristics met in practice are consistent too.

**Worked example.** The graph has seven nodes; the heuristic, shown next to each node, is consistent on every edge:

1. **Expand S** ($g = 0$, $f = 0 + 6 = 6$). A enters the frontier with $f = 2 + 5 = 7$, B with $f = 3 + 4 = 7$. The tie goes to the deeper node, B.
2. **Expand B** ($g = 3$, $f = 7$). C enters with $g = 4$, $f = 4 + 4 = 8$, and E with $g = 5$, $f = 5 + 5 = 10$.
3. **Expand A** ($g = 2$, $f = 7$). D enters with $g = 6$, $f = 6 + 1 = 7$. A also offers a path to C, of cost 5, worse than the 4 already known, so it is discarded.
4. **Expand D** ($g = 6$, $f = 7$). G enters with $g = 7$, $f = 7 + 0 = 7$.
5. **Expand G**: it is the goal, with cost 7, along S–A–D–G.

C and E are never expanded: their $f$ values, 8 and 10, are larger than $C^\star = 7$. Uniform-cost search on the same graph expands all seven nodes.

### Why A\* returns an optimal solution

The argument for graph search with a consistent heuristic has three steps.

**Step 1: $f$ never decreases along a path.** If $n'$ is a successor of $n$, then

$$
\begin{aligned}
f(n') &= g(n') + h(n') && \text{definition of } f \\
&= g(n) + c(n, a, n') + h(n') && \text{the path to } n' \text{ extends the path to } n \\
&\ge g(n) + h(n) && \text{consistency: } c(n, a, n') + h(n') \ge h(n) \\
&= f(n) .
\end{aligned}
$$

**Step 2: when A\* expands a node, it has found the cheapest path to it.** Suppose A\* is about to expand a node $n$ with $g(n) > g^\star(n)$. Look at a cheapest path from $s_0$ to the state of $n$. Its first node is expanded (it is $s_0$) and its last is not, so some node $n''$ on it is on the frontier with all its predecessors on the path expanded; and since $n''$ was reached along the cheapest path, $g(n'') = g^\star(n'')$. Then

$$
\begin{aligned}
f(n'') &= g^\star(n'') + h(n'') && n'' \text{ lies on a cheapest path} \\
&\le g^\star(n) + h(n) && \text{Step 1 along the rest of that path} \\
&< g(n) + h(n) = f(n) && \text{the assumption } g(n) > g^\star(n),
\end{aligned}
$$

so A\* would have expanded $n''$ before $n$, a contradiction. Hence $g(n) = g^\star(n)$ at expansion.

**Step 3: the first goal expanded is optimal.** Apply Step 2 to the first goal node A\* expands: its $g$ is the cheapest cost to that goal. Any other goal reached later has, by Step 1, an $f$ at least as large, and at a goal $f = g$ because $h = 0$ there. Hence

$$
\boxed{\; \text{with a consistent } h, \text{ A* expands nodes in nondecreasing order of } f, \text{ and the first goal it expands has cost } C^\star \;}
$$

Two consequences follow. A\* expands every node with $f(n) < C^\star$, and none with $f(n) > C^\star$: the set of expanded nodes is a contour of $f$ around the start, as in the figure where C and E lie outside the contour at $f = 7$. And no other optimal algorithm that is given the same heuristic and extends paths from the start can be sure of optimality while skipping a node with $f(n) < C^\star$, because the remaining cost might be as low as $h$ promises; A\* is **optimally efficient** in this sense, up to ties at $f = C^\star$ ([Russell and Norvig, 2021](#references), section 3.5).

For tree search, which does not remember reached states, admissibility alone is enough. If a suboptimal goal $G_2$ with $g(G_2) > C^\star$ is on the frontier, some node $n$ of an optimal path is also on the frontier, and $f(n) = g(n) + h(n) \le g(n) + h^\star(n) = C^\star < g(G_2) = f(G_2)$, so $n$ is expanded first; repeating the argument, the optimal goal is expanded before $G_2$.

### Where heuristics come from

A good heuristic is the exact cost of a **relaxed problem**, one with some constraints removed. On a grid with walls, removing the walls gives the Manhattan distance $|r - r_G| + |c - c_G|$. In the 8-puzzle, letting a tile move to any adjacent square, occupied or not, gives the sum of the tiles' Manhattan distances to their places. A relaxed problem has more solutions, so its optimal cost cannot exceed the real one: the heuristic is admissible. It is also consistent, because it is the exact cost in a problem with the same moves and more freedom, and exact costs satisfy the triangle inequality.

If $h_2(n) \ge h_1(n)$ for every $n$ and both are admissible, $h_2$ **dominates** $h_1$, and A\* with $h_2$ never expands a node that A\* with $h_1$ leaves alone (up to ties): every node with $f_2(n) = g(n) + h_2(n) < C^\star$ also has $f_1(n) < C^\star$. The ideal heuristic is $h^\star$ itself, which leads A\* straight to the goal; it costs as much to compute as the problem it solves, and the art is to find a cheap function close to it.

## Classical planning: STRIPS and PDDL

Each problem above came with its own code for $\mathrm{Actions}$ and $\mathrm{Result}$. Planning languages describe a whole family of problems with one **factored** representation, so that one general algorithm can solve all of them, and the description itself can be inspected to derive heuristics automatically.

In the **STRIPS** representation ([Fikes and Nilsson, 1971](#references)), a state is a set of ground facts, such as `on(C, A)` and `clear(B)`; every fact not in the set is false. An **action schema** has parameters and three lists of facts:

- **preconditions**, which must all hold for the action to apply;
- an **add list** of facts that become true;
- a **delete list** of facts that become false.

For an applicable action the transition model is set arithmetic:

$$
\mathrm{Result}(s, a) = \big(s \setminus \mathrm{Del}(a)\big) \cup \mathrm{Add}(a), \qquad \text{applicable if } \mathrm{Pre}(a) \subseteq s .
$$

**PDDL**, the Planning Domain Definition Language ([McDermott et al., 1998](#references)), is the standard syntax for such descriptions, used by the International Planning Competition since 1998. A **domain file** defines the predicates and action schemas; a **problem file** lists the objects, the initial state and the goal. In the blocks world, blocks sit on a table or on each other and one clear block can be moved at a time. One of its three actions, written in PDDL:

```lisp
(:action move-to-table
  :parameters (?x ?y)
  :precondition (and (on ?x ?y) (clear ?x))
  :effect (and (on-table ?x) (clear ?y) (not (on ?x ?y))))
```

The other two move a clear block from a block or from the table onto another clear block. A problem:

```lisp
(:init (on C A) (on-table A) (on-table B) (clear C) (clear B))
(:goal (and (on A B) (on B C)))
```

**Worked example.** Breadth-first search over the sets of facts, from this initial state, applies the 18 ground actions of three blocks and finds the three-step plan: move C to the table, move B onto C, move A onto B. It reaches all 13 states of the three-block world on the way, as the Code section prints. This little problem, the **Sussman anomaly**, is famous for another reason. A planner that achieves one goal at a time fails on it: putting A on B first means moving C off A and then A onto B, after which B cannot be put on C without taking A off again; putting B on C first buries A under C and B. The goals interact, and only a search over whole states finds the plan.

The number of states of the blocks world grows faster than exponentially: 13 for three blocks, 501 for five, 58,941,091 for ten. Planners therefore search with heuristics, and the factored form gives them for free. The most useful relaxation **ignores the delete lists**: once true, a fact stays true. The cost of the optimal relaxed plan, $h^+$, is admissible but NP-hard to compute; its approximations, the admissible $h_{\max}$ and the more informative but inadmissible $h_{\text{add}}$ and the FF heuristic, made heuristic forward search the dominant approach to classical planning ([Bonet and Geffner, 2001](#references); [Hoffmann and Nebel, 2001](#references)).

## Why this matters for language-model planners

A language model asked to plan in text does none of this explicitly: it writes a plan in one pass, without a frontier, without a goal test and without backtracking. On problems that need search, such as the blocks world with more blocks, its plans are often invalid ([Valmeekam et al., 2023](#references)). The ideas of this note return in three ways, each developed in [Planning with language models](/notes/agents/planning-with-language-models).

- **The model formulates, a planner searches.** In LLM+P ([Liu et al., 2023](#references)) the model translates a problem stated in natural language into a PDDL problem file, a classical planner finds a plan, and the model translates the plan back. The planner contributes the guarantees of this note; the model contributes the formulation, which is the part people find hard to automate.
- **The model is the successor function and the heuristic.** Tree of Thoughts ([Yao et al., 2023](#references)) runs breadth-first or depth-first search over partial solutions, the "thoughts". The model proposes the successors of a node and also rates how promising each one is, playing the part of $h$. On the Game of 24, combining four numbers with arithmetic to reach 24, GPT-4 prompted to reason step by step solved 4% of the test problems, and the same model inside a breadth-first search that keeps the five best partial solutions at each step solved 74% (the paper's own test set of 100 hard puzzles, 2023). The model's ratings are not admissible, so the optimality argument above does not apply; the search makes the model's mistakes recoverable instead.
- **Something must check the plan.** A heuristic may be wrong; a goal test and the preconditions of each action may not. Systems that pair a model that proposes with an external verifier that checks, the "LLM-Modulo" pattern ([Kambhampati et al., 2024](#references)), are the planning version of the separation between the agent and its environment.

## What changed

| | breadth-first | uniform-cost | A\* |
| --- | --- | --- | --- |
| expands next | the shallowest node | the cheapest $g(n)$ | the smallest $g(n) + h(n)$ |
| optimal when | all step costs are equal | step costs are at least $\varepsilon > 0$ | $h$ is consistent (graph search) or admissible (tree search) |
| goal test | when generated | when expanded | when expanded |
| uses knowledge of the goal | no | no | yes, through $h$ |
| on the grid | 139 states reached | 136 cells expanded | 80 cells expanded |

And from problem-specific code to planning: a factored state of facts, action schemas with preconditions and add and delete lists, one general search, and heuristics computed from the description itself.

## Limitations

- **Memory.** A\* keeps every reached state. Its time can be acceptable while its memory is not; variants such as iterative-deepening A\* trade time for memory.
- **Exponential in the end.** A heuristic shrinks the exponent but rarely removes it: when its error grows in proportion to the true remaining cost, as it does for most practical heuristics, the number of nodes A\* expands still grows exponentially with the solution length.
- **The assumptions are strong.** Full observability, determinism and a known model are rare outside puzzles, games against nature and logistics. When outcomes are random, a plan must branch; that is the subject of the [next note](/notes/agents/markov-decision-processes).
- **Formulation is done by people.** The state space, the actions and the costs are given; deciding what to leave out is the hard part, and the part a language model is now asked to do.
- **Planning languages are rigid.** Classical STRIPS cannot express time, resources or uncertainty; extensions of PDDL can, at the price of harder planning.

## What you should remember

- A search problem is a state space with an initial state, a goal test, actions, a transition model and action costs; a solution is a path, an optimal one is cheapest.
- Breadth-first search is optimal only for equal costs; uniform-cost search is optimal for positive costs and tests the goal when it expands a node.
- A\* expands the smallest $f = g + h$. With a consistent $h$, $f$ never decreases along a path, every node is expanded with its cheapest $g$, and the first goal expanded is optimal. Admissibility suffices for tree search.
- Good heuristics are exact costs of relaxed problems; a dominating heuristic expands fewer nodes. Weighting $h$ by $w > 1$ saves work at a cost of at most a factor $w$.
- STRIPS and PDDL describe states as sets of facts and actions by preconditions, add lists and delete lists; ignoring delete lists gives planning heuristics. Language-model planners reuse these pieces: the model formulates, proposes or evaluates, and a search or a verifier supplies the guarantees.

## Code

A best-first search with $f = g + w\, h$ (uniform-cost search, A\* and weighted A\*), run on the graph of the worked example and on the grid, breadth-first search on the grid, and a STRIPS planner for the blocks world. NumPy and the standard library only; the script runs in well under a second and has no randomness.

```python
import heapq, itertools
from collections import deque
from math import comb, factorial
import numpy as np

# 1. best-first search: f = g + w h. w = 0 is uniform-cost search, w = 1 is A*, w > 1 is weighted A*
def best_first(start, goal, neighbours, h, w=1.0):
    tie = itertools.count()
    frontier = [(w * h(start), 0, next(tie), start)]          # (f, -g, insertion order, state): ties go to deeper nodes
    g, parent, closed = {start: 0}, {start: None}, []
    while frontier:
        f, _, _, n = heapq.heappop(frontier)
        if n in closed: continue                               # a stale entry: n was reached more cheaply before
        closed.append(n)
        if n == goal:                                          # the goal test, at expansion
            path = [n]
            while parent[path[-1]] is not None: path.append(parent[path[-1]])
            return path[::-1], g[n], closed
        for m, cost in neighbours(n):
            if m not in closed and g[n] + cost < g.get(m, np.inf):
                g[m], parent[m] = g[n] + cost, n
                heapq.heappush(frontier, (g[m] + w * h(m), -g[m], next(tie), m))
    return None, np.inf, closed

# 2. the graph of the worked example, with a consistent heuristic
edges = {('S','A'): 2, ('S','B'): 3, ('A','C'): 3, ('B','C'): 1, ('A','D'): 4, ('C','G'): 4, ('D','G'): 1, ('B','E'): 2, ('E','G'): 6}
adj = {}
for (u, v), c in edges.items():
    adj.setdefault(u, []).append((v, c)); adj.setdefault(v, []).append((u, c))
H = dict(S=6, A=5, B=4, C=4, D=1, E=5, G=0)
assert all(H[u] <= c + H[v] and H[v] <= c + H[u] for (u, v), c in edges.items())   # consistent
for w in (0, 1):
    path, cost, closed = best_first('S', 'G', lambda n: adj[n], H.get, w)
    print(w, path, cost, ''.join(closed))
# 0 ['S', 'A', 'D', 'G'] 7 SABCEDG
# 1 ['S', 'A', 'D', 'G'] 7 SBADG

# 3. a grid with walls: 4 moves of cost 1, Manhattan distance as the heuristic
MAP = ["................",
       "...........#....",
       ".....####..#....",
       "........#..#....",
       "........#..#....",
       ".S......#..#..G.",
       "........#..#....",
       "........#.......",
       ".....####.......",
       "................"]
wall = np.array([[ch == '#' for ch in row] for row in MAP])
S = next((r, c) for r, row in enumerate(MAP) for c, ch in enumerate(row) if ch == 'S')
T = next((r, c) for r, row in enumerate(MAP) for c, ch in enumerate(row) if ch == 'G')
def grid_neighbours(n):
    for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
        r, c = n[0] + dr, n[1] + dc
        if 0 <= r < wall.shape[0] and 0 <= c < wall.shape[1] and not wall[r, c]:
            yield (r, c), 1
manhattan = lambda n: abs(n[0] - T[0]) + abs(n[1] - T[1])
for w in (0, 0.5, 1, 1.5, 2, 3, 5):
    path, cost, closed = best_first(S, T, grid_neighbours, manhattan, w)
    print(w, cost, len(closed), end=' | ')
print()
# 0 21 136 | 0.5 21 123 | 1 21 80 | 1.5 23 75 | 2 25 68 | 3 25 65 | 5 25 60     (w, path cost, cells expanded)

def bfs(start, goal, neighbours):                              # optimal here: every step costs 1
    depth, queue = {start: 0}, deque([start])
    while queue:
        n = queue.popleft()
        if n == goal: return depth[n], len(depth)
        for m, _ in neighbours(n):
            if m not in depth: depth[m] = depth[n] + 1; queue.append(m)
print(bfs(S, T, grid_neighbours))                              # (21, 139): path length, states reached

# 4. STRIPS: a state is a set of facts; an action has preconditions, an add list and a delete list
blocks = 'ABC'
def actions():
    for x, y, z in itertools.permutations(blocks + 'T', 3):    # move block x from y onto z; T is the table
        if x == 'T': continue
        pre = {f'on {x} {y}', f'clear {x}'} | ({f'clear {z}'} if z != 'T' else set())
        add = {f'on {x} {z}'} | ({f'clear {y}'} if y != 'T' else set())
        dele = {f'on {x} {y}'} | ({f'clear {z}'} if z != 'T' else set())
        yield f'move({x},{y},{z})', frozenset(pre), frozenset(add), frozenset(dele)
ACTIONS = list(actions())
init = frozenset({'on C A', 'on A T', 'on B T', 'clear C', 'clear B'})   # C sits on A; A and B are on the table
goal = {'on A B', 'on B C'}
def plan_bfs(init, goal):
    parent, queue = {init: None}, deque([init])
    while queue:
        s = queue.popleft()
        if goal <= s:
            plan = []
            while parent[s]: s, a = parent[s]; plan.append(a)
            return plan[::-1], len(parent)
        for name, pre, add, dele in ACTIONS:
            if pre <= s:                                       # applicable: Pre(a) is a subset of s
                t = (s - dele) | add                           # Result(s, a) = (s minus Del(a)) union Add(a)
                if t not in parent: parent[t] = (s, name); queue.append(t)
print(len(ACTIONS), plan_bfs(init, goal))
# 18 (['move(C,A,T)', 'move(B,T,C)', 'move(A,T,B)'], 13)

# the number of states of the blocks world: ways to arrange n labelled blocks into stacks
print([sum(factorial(n) // factorial(k) * comb(n - 1, k - 1) for k in range(1, n + 1)) for n in (3, 5, 10)])
```

## Next

Search assumed that every action has one known outcome, so a plan is a fixed sequence that can be executed with closed eyes. In most worlds that agents meet, an action can fail or have several outcomes, and the agent must decide what to do in every state it might end up in, weighing outcomes by their probabilities and rewards that arrive over time. The [next note](/notes/agents/markov-decision-processes) sets up that problem as a Markov decision process and solves it with the Bellman equations.
