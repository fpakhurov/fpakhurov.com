The NLP Tasks section adapted a pretrained model to one task at a time: a head, a labelled dataset, a fine-tuning run. Its last note ended with a different kind of model. An instruction-tuned decoder of 0.5 B parameters summarized news articles from a prompt, with no summarization training at all ([summarization note](/notes/nlp/summarization#language-models-as-summarizers)). One model that does many tasks, each described in words, is what is now called an assistant. This note describes how such a model is made from a base model.

The [GPT note](/notes/nlp/gpt#what-a-base-model-does) showed a base model given "Find the value of n in the equation n + 2 = 6." It solved the equation and then kept producing more equations, because that is what follows such text on the web. The same model, after two further training stages, answers in a few lines and stops. They do not touch the architecture; they change the weights and the format of the input.

**Notation.** A prompt $x$ and a response $y$; the policy $\pi_\theta(y \mid x)$ is the language model being trained; $\pi_{\text{ref}}$ is a frozen copy it started from; a reward model $r_\phi(x, y)$ scores responses; $y_w \succ y_l$ means a human preferred $y_w$ to $y_l$. A templated training sequence is $s_1, \dots, s_T$, and $m_t \in \{0, 1\}$ marks the positions that carry loss.

## Baseline: the base model and the chat template

Before any training, compare a base checkpoint, Llama 3.2 1B, with its instruction-tuned sibling. Their printed module trees are identical, string for string: same 16 blocks, same attention, same vocabulary. What differs is the weights, and one more thing: the tuned model expects its input wrapped in a **chat template**. For a one-turn conversation the tokenizer produces

```
<|begin_of_text|><|start_header_id|>system<|end_header_id|>

Cutting Knowledge Date: December 2023
Today Date: 13 Nov 2025

<|eot_id|><|start_header_id|>user<|end_header_id|>

Find the value of n in the equation n + 2 = 6.<|eot_id|>
```

and the model continues with an assistant header and its answer, ending with `<|eot_id|>`. The special tokens mark roles and turn boundaries; the model has learned to stop at `<|eot_id|>` and the serving code stops decoding there. Its answer to the equation: "Subtract 2 from both sides … n = 4. So, the value of n is 4." Then it stops. The template is part of the model's contract; given raw text without it, the tuned model tends toward base-model behaviour (continuing the text instead of answering, not stopping cleanly).

## The stages of LLM training

The two stages of the figure are the end of a longer pipeline. Every stage keeps the architecture, starts from the weights of the stage before, and changes two things: the data and the objective. The stages after pretraining are together called **post-training**.

| Stage | Data | Objective | What it adds |
| --- | --- | --- | --- |
| Pretraining | trillions of tokens of raw text | next token, every token | knowledge and language |
| Supervised fine-tuning (SFT) | thousands to millions of instruction–response dialogues | next token, response tokens only | the format of an answer: follow the instruction, answer, stop |
| Preference optimization | prompts with a preferred and a rejected response | reward model + RL with a KL penalty (RLHF), or the DPO loss | which of several well-formed answers people prefer |
| RL with verifiable rewards (optional) | prompts whose answer a program can check | reward from the check, with a KL penalty | correctness on checkable tasks |

**Pretraining** is the base model of the [GPT note](/notes/nlp/gpt) at scale. The loss is the next-token cross-entropy on every token of the text,

$$
\mathcal L_{\text{PT}} = -\sum_{t=1}^{T} \log \pi_\theta(s_t \mid s_{<t}),
$$

and the purpose is everything the later stages rely on: grammar, facts, code, and the ability to continue a pattern shown in the prompt. Almost all of the compute is spent here. How large the model should be and how many tokens it should see for a given budget is the subject of the [scaling laws note](/notes/nlp/scaling-laws); which text goes in, and how it is cleaned and mixed, is the subject of the [pretraining data note](/notes/nlp/pretraining-data).

**SFT** and **preference optimization** are the two sections below. SFT uses the same loss on far less, far more structured text; preference optimization is the first stage whose data says that one response is worse than another.

**RL with verifiable rewards** (RLVR) replaces the learned reward model by a check: a maths problem with a known final answer, a coding problem with unit tests, an instruction with a testable constraint. The objective keeps the KL penalty of RLHF ([Lambert et al., 2024](#references), §6, Eqs. 7–8):

$$
\max_\theta\; \mathbb E_{x,\, y \sim \pi_\theta}\big[v(x, y)\big] - \beta\, D_{\mathrm{KL}}\big(\pi_\theta(\cdot \mid x)\,\|\,\pi_{\text{ref}}(\cdot \mid x)\big),
$$

where the reward $v(x, y)$ is a constant $\alpha$ if the answer in $y$ is verified correct and $0$ otherwise. Tülu 3 runs this stage after DPO, with PPO and $\alpha = 10$. DeepSeek-R1 trains with rule-based accuracy and format rewards on maths, code and logic problems and avoids neural reward models for them, because its authors observed reward hacking with those at scale ([DeepSeek-AI, 2025](#references), §2.2). The purpose is correctness where correctness can be checked; the stage does not apply to an open-ended request such as a cover letter, which has no checker.

## Supervised fine-tuning

<aside class="callout"><strong>Key idea.</strong> Show the model what an answer looks like. Collect dialogues in which a user asks and an assistant responds well, format them with the template, and train the model with the ordinary next-token loss on the assistant's tokens.</aside>

**Supervised fine-tuning** (SFT) is the fine-tuning of the [fine-tuning note](/notes/nlp/fine-tuning#task-fine-tuning-and-instruction-tuning) with a different dataset and no new head: the objective is the pretraining objective,

$$
\mathcal L_{\text{SFT}} = -\sum_{t \in \text{response}} \log \pi_\theta(y_t \mid x, y_{<t}),
$$

usually with the loss masked to the response tokens so that the model is not trained to reproduce the prompts. SFT with LoRA or QLoRA on a 7 B model fits on one GPU; the whole pipeline of this note is routinely run that way.

### A training example in the chat template

A dialogue is rendered by the chat template into one token sequence $s_1, \dots, s_T$: the system turn, the user turn, the assistant header, and the response with its end-of-turn token. The model reads all of it. The loss is the pretraining loss with a mask,

$$
\boxed{\;\mathcal L_{\text{SFT}} = -\frac{1}{\sum_t m_t} \sum_{t=1}^{T} m_t \log \pi_\theta(s_t \mid s_{<t})\;}
$$

where $m_t = 1$ for the response tokens and $m_t = 0$ for everything else. The two objectives differ only in $m$:

$$
\begin{aligned}
\text{pretraining:}\quad & m_t = 1 \text{ for every } t && \text{(raw text, every token is a target)} \\
\text{SFT:}\quad & m_t = 1 \text{ only inside the response} && \text{(the prompt is context, not a target).}
\end{aligned}
$$

With the mask, the sum over $t$ is the sum over response tokens of the formula above, since $s_{<t}$ for a response token is the prompt $x$ followed by $y_{<t}$. In code the mask is the label: positions with $m_t = 0$ get the label $-100$, which the cross-entropy skips, the same device as for padded targets in the [summarization note](/notes/nlp/summarization#abstractive-summarization).

**Worked example.** The sequence in the figure has 25 positions and 7 with $m_t = 1$: the six tokens of `2 + 2 = 4 .` and the closing end-of-turn token. If the model gives each of the seven targets probability 0.9, the loss is $-\log 0.9 = 0.105$, whatever it predicts on the other 18 positions; under the pretraining loss those 18 positions, including the question, would count too. The end-of-turn token is a target, and it is the token that teaches the model to stop.

### What SFT teaches

The same base model, the same loss; what changes is which continuations the data shows. SFT teaches behaviour:

- **Answering instead of continuing.** The response follows the instruction rather than extending the prompt's text.
- **Following the instruction's constraints:** length, language, a list or a table, JSON with given fields.
- **Turn structure.** Where a turn starts and ends, that the end-of-turn token comes after the answer, and how to use earlier turns of a multi-turn dialogue.
- **Refusals.** Declining the requests that the data declines, in the way the data does.
- **Style.** A consistent tone and persona, the level of detail, when to ask a clarifying question.
- **Formats for tools,** such as the function-call syntax of the [tools and agents note](/notes/nlp/tools-and-agents), when the dialogues contain them.

What it does not reliably add is knowledge that pretraining did not provide; the limitations below return to this.

### Where the data comes from

The data is the whole method. Four sources are used, usually mixed:

- **Written by people.** The InstructGPT work ([Ouyang et al., 2022](#references), §3.2 and §3.4) had about 40 contractors write demonstrations for about 13,000 SFT training prompts. OpenAssistant Conversations ([Köpf et al., 2023](#references)) collected 161,443 messages in 35 languages from more than 13,500 volunteers. Open datasets such as UltraChat, No Robots and MathInstruct supply tens of thousands to millions of dialogues. People are the most reliable source of good answers and the most expensive one.
- **Real user prompts.** Most InstructGPT prompts were submitted by users of the OpenAI API, filtered for personal information, with answers written by the labellers ([Ouyang et al., 2022](#references), §3.2). Logged prompts show what people actually ask, which no list of benchmark tasks covers.
- **Existing NLP datasets, rephrased as instructions.** FLAN ([Wei et al., 2022](#references), §2.1) turned 62 labelled datasets in twelve task clusters into instructions with ten hand-written templates per dataset ("Does the premise entail the hypothesis? OPTIONS: yes / it is not possible to tell / no"), and fine-tuned a 137 B-parameter model on the mixture. Evaluated zero-shot on task clusters held out from tuning, it beat zero-shot 175 B GPT-3 on 20 of 25 datasets; in that setup, at 8 B parameters and below, the same tuning hurt the held-out tasks (§4.2, Figure 7). The later Flan collection grew to 1,836 tasks ([Chung et al., 2024](#references)). Converted datasets are cheap and correct but narrow in style: short answers, academic tasks.
- **Generated by a model** (synthetic data, distillation):
  - **Self-instruct / Alpaca** ([Wang et al., 2023](#references); [Taori et al., 2023](#references)): start from 175 human-written seed instructions, prompt a strong model to generate more instructions and their answers (52,000 for Alpaca), and fine-tune on the result. Self-Instruct, with GPT-3 generating its own data, improved GPT-3 by 33 points absolute on Super-NaturalInstructions. The student model inherits the generator's behaviour, which is a form of distillation, including the generator's errors.
  - **Instruction pretraining** ([Cheng et al., 2024](#references)): generate instruction–response pairs from the pretraining documents themselves, so that the instruction data is as broad as the corpus.

### Quality and diversity over quantity

<aside class="callout"><strong>Key idea.</strong> SFT data teaches a format, and a format needs few examples. What matters is that the answers are good, since the model learns to imitate them, and that the prompts are diverse, so that the format generalizes beyond them.</aside>

LIMA ([Zhou et al., 2023](#references)) is the evidence for this. A 65 B-parameter LLaMA was fine-tuned with the ordinary SFT loss on 1,000 curated prompt–response pairs and no preference stage: 750 questions and answers selected from community forums (Stack Exchange, wikiHow, Reddit) for quality and diversity, and 250 written by the authors. On 300 test prompts, human raters judged its answers equivalent to or better than GPT-4's in 43 % of cases (§1 and Figure 1). That is a pairwise preference on one prompt set, not a benchmark score, and GPT-4 is still preferred in the majority of cases. The ablations, on a 7 B model with 2,000 examples per run and a model as judge, separate the factors (§5):

- **Diversity:** diverse Stack Exchange prompts gave better answers than the same number of homogeneous wikiHow prompts with equally good answers.
- **Quality:** filtering Stack Exchange answers for quality and style improved the score by 0.5 on a 6-point scale over unfiltered answers.
- **Quantity:** increasing the filtered set up to 16-fold did not improve the score.

The authors' reading, the *superficial alignment hypothesis*, is that the knowledge and abilities come from pretraining and SFT selects the format in which to use them. The same paper lists the cost: 1,000 such examples take much careful effort, and the model is less robust than product-grade ones to an unlucky sample or an adversarial prompt (§7).

### What demonstrations cannot express

After SFT the model answers. What SFT lacks is a signal about *which* alternatives are bad. The softmax is normalized, so raising the shown token lowers the others: with three tokens at equal logits, one gradient step of size 1 on $-\log p_1$ moves the logits by $e_1 - p = (2/3, -1/3, -1/3)$, and the probabilities go from $(1/3, 1/3, 1/3)$ to $(0.576, 0.212, 0.212)$. Each alternative's logit is pushed down in proportion to its current probability, whether it is a fluent, confident wrong answer or a harmless paraphrase, and demonstrations can also generalize to prompts they never covered. What the loss never contains is a response marked as worse than another. Preference optimization adds exactly that comparative signal.

## Preference optimization

After SFT, the responses a model can give to one prompt are mostly well formed, and they still differ in ways that matter. One is correct and another confidently wrong; one is concise and another padded; one helps with a harmless request that another refuses, and one complies with a harmful request that another declines. InstructGPT states the target as a model that is *helpful, honest and harmless*, following Askell et al. ([Ouyang et al., 2022](#references), §3.6). Preference optimization aims at these properties, and at tone and style as people judge them. They are properties of a whole response compared with other responses, and comparing two answers is often easier than writing the best one: a labeller who could not write the ideal answer can still say which of two is better. A demonstration says "this is good"; a comparison says "this is better than that", which no demonstration can express.

### With a reward model: RLHF

[Ouyang et al. (2022)](#references), following [Christiano et al. (2017)](#references) and [Stiennon et al. (2020)](#references), add a stage that uses comparisons rather than demonstrations:

1. For each prompt, sample several responses from the SFT model (different seeds, temperatures).
2. Humans rank them. A ranking of $k$ responses yields $\binom{k}{2}$ pairs $(y_w, y_l)$.
3. Train a **reward model** $r_\phi$, usually the SFT model with a scalar head, to agree with the comparisons under the Bradley–Terry model:
   $$
   P(y_w \succ y_l \mid x) = \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big), \qquad
   \mathcal L_{\text{RM}} = -\log \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big).
   $$
   The reward is defined only up to a constant and only on the distribution of responses it was trained on.
4. Optimize the policy with reinforcement learning (PPO) to maximize the reward while staying near the SFT model:
   $$
   \max_\theta\; \mathbb E_{x,\, y \sim \pi_\theta}\big[r_\phi(x, y)\big] - \beta\, D_{\mathrm{KL}}\big(\pi_\theta(\cdot \mid x)\,\|\,\pi_{\text{ref}}(\cdot \mid x)\big).
   $$

The KL term is what keeps the method honest: without it the policy finds responses that score high on $r_\phi$ and are nonsense, because the reward model is accurate only near the data it saw (**reward hacking**). $\beta$ sets how far the policy may move.

The empirical result that made the method standard: human raters preferred the outputs of the 1.3 B-parameter InstructGPT model to those of the 175 B-parameter GPT-3 ([Ouyang et al., 2022](#references), abstract and Figure 1). Preference training changed what the model does more than a hundredfold increase in size did.

### Without a reward model: DPO

PPO is expensive (four models in memory: policy, reference, reward, value) and fragile to tune. [Rafailov et al. (2023)](#references) showed that the KL-regularized objective above has a closed-form optimum,

$$
\pi^*(y \mid x) \propto \pi_{\text{ref}}(y \mid x)\, \exp\!\big(r(x, y)/\beta\big),
$$

which can be inverted: the reward is a function of the policy, $r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \text{const}$. Substituting into the Bradley–Terry likelihood eliminates $r$ and gives a loss on the policy alone:

$$
\mathcal L_{\text{DPO}} = -\log \sigma\!\Big(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\Big).
$$

**Direct preference optimization** trains the policy on preference pairs with a classification-style loss: raise the log-ratio of the preferred response, lower that of the rejected one, each relative to the reference. No reward model, no sampling during training, two models in memory.

What DPO removes and what it keeps:

| | RLHF with PPO | DPO |
| --- | --- | --- |
| Preference pairs $(x, y_w, y_l)$ | needed, to train $r_\phi$ | needed, directly in the loss |
| Separate reward model $r_\phi$ | trained, then frozen | none; the reward is implicit in $\pi_\theta / \pi_{\text{ref}}$ |
| RL loop (sampling from $\pi_\theta$, value model) | yes | no; a supervised loss on a fixed dataset |
| Reference model $\pi_{\text{ref}}$ | in the KL penalty | in the loss, usually the SFT model |
| Models in memory during training | four | two |

The reference model is not optional. The loss is derived from the KL-regularized objective, and $\pi_{\text{ref}}$ is the distribution that objective keeps the policy near: each response is scored by how much more likely the policy makes it than the reference does, and $\beta$ sets the scale. Rafailov et al. set $\pi_{\text{ref}}$ to the SFT model when it is available, since the preference data was sampled from it ([Rafailov et al., 2023](#references), §4). The derivation is exact for the objective; whether DPO or PPO yields the better model in practice depends on the data and is still argued, and both are implemented in Hugging Face's TRL library.

## Evaluating an assistant

Perplexity says nothing about helpfulness, and a single reference answer does not exist. The usual instruments, developed further in the [LLM evaluation note](/notes/nlp/llm-evaluation):

- **Pairwise human preference at scale.** Chatbot Arena shows users two anonymous responses and asks which is better; an Elo-style rating is computed from many such votes.
- **Model-judged benchmarks.** MT-Bench scores multi-turn answers with a strong model as the judge; AlpacaEval compares a model's answers with a reference model's and reports a win rate.
- **Capability benchmarks** of the base model (reasoning, knowledge) still apply and can drop after alignment, the **alignment tax**.

## Choosing a model to adapt

Three practical rules, all empirical and time-dependent:

- Prefer a checkpoint that has been through SFT and preference optimization unless the task is pure completion; its behaviour is the one the template and the serving stack assume.
- Do not pretrain. Continued pretraining on a domain is sometimes worth it; starting from scratch almost never is outside a few organizations.
- A recent small model (around 1–10 B parameters) usually beats an older large one on general tasks, and a large aligned model often needs no fine-tuning for classification or summarization, only a well-written prompt with the expected output format.

## What changed

| | Pretrained base | After SFT | After preference optimization |
| --- | --- | --- | --- |
| Trained on | Web text, next token | Instruction–response dialogues | Preference pairs |
| Loss counted on | Every token | Response tokens only | Preferred against rejected response |
| Behaviour | Continues text | Answers and stops | Answers in ways people prefer |
| Learns from rejected responses | No | No | Yes |
| Architecture | Same | Same | Same |
| Input format | Raw text | Chat template | Chat template |

## Limitations

- **The data defines the behaviour**, including its errors and biases; demonstrations written for one audience train a model for that audience.
- **Reward hacking and sycophancy.** A reward learned from human ratings rewards what raters like, which includes confident tone and agreement.
- **Alignment tax.** Some capabilities of the base model regress.
- **Not a knowledge source.** Both stages are meant to shape behaviour, how the model answers. The updated weights can pick up facts present in the training dialogues, incidentally or by design, but these stages are not a reliable replacement for broad pretraining or for retrieval.
- **Evaluation is the hard part.** Preferences are noisy and judges are models; the [LLM evaluation note](/notes/nlp/llm-evaluation) returns to this.

## What you should remember

- An instruction-tuned model is the base architecture with different weights and a chat template of special role tokens; without the template it tends toward base-model behaviour.
- Training an LLM: pretraining (next token on raw text: knowledge and language) → SFT (next token on response tokens: the format of an answer) → preference optimization (comparisons: which answer is better) → optionally RL with verifiable rewards (a checker as the reward).
- SFT: next-token loss on assistant responses in formatted dialogues, with the prompt masked (label $-100$) and the end-of-turn token as a target; it teaches answering, constraints, turns, refusals and style.
- SFT data comes from people, user prompts, converted NLP datasets (FLAN) and stronger models (self-instruct, Alpaca). LIMA: 1,000 good and diverse examples gave a strong assistant from a 65 B base model; quality and diversity mattered, quantity alone did not.
- Preference optimization targets what demonstrations cannot say: that one well-formed answer is more helpful, honest or harmless than another.
- RLHF: rank samples, fit a Bradley–Terry reward model, optimize reward minus $\beta$ KL to the SFT model with PPO. A 1.3 B RLHF model was preferred to the 175 B GPT-3.
- DPO: the same objective's optimum written as a loss on the policy, $-\log\sigma(\beta\Delta\log\text{-ratio})$, with no reward model and no RL loop; it still needs the preference pairs and the reference model.
- Evaluate assistants by pairwise preference and judged benchmarks, and watch for the alignment tax.
