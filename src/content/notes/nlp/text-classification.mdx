Classification is the task every representation in this course was tested on, so most of its content is already written. This note is the summary that the course owes it: a clean formulation, the metrics, the full table of results on the two datasets used, the two ways the task is done today, and the pitfalls that are specific to classification rather than to evaluation in general.

**Notation.** Input text $x$, label $y \in \{1, \dots, K\}$; a model outputs $p(y \mid x)$ and predicts $\hat y = \arg\max_y p(y \mid x)$.

## Task formulation

Map a text to one of $K$ predefined labels. Variants differ in the output structure:

| Variant | Output | Loss | Examples |
| --- | --- | --- | --- |
| Binary | one of two | binary cross-entropy | sentiment (SST-2), spam |
| Multi-class | one of $K$ | softmax cross-entropy | topic (AG News, $K = 4$), intent |
| Multi-label | any subset of $K$ | $K$ binary cross-entropies | tags, toxicity types |
| Ordinal | one of $K$ ordered | cross-entropy or regression | star ratings |

The input is a document of arbitrary length; every model needs a fixed-size representation of it first (counts, a pooled vector, a special token's state), and the differences between approaches are mostly differences in how that representation is built.

## Metrics

From the [evaluation note](/notes/nlp/corpora-and-evaluation#precision-recall-and-f1): accuracy for balanced classes with equal error costs; per-class precision, recall and $F_1$ otherwise, macro-averaged when every class matters equally. AG News is balanced (30,000 per class) and SST-2 nearly so (44/56), so both datasets are reported with accuracy; a production classifier with a rare class of interest should not be.

| Regime | Trained parameters | Accuracy |
| --- | --- | --- |
| [Linear probing](/notes/nlp/fine-tuning#linear-probing-train-only-the-head) | 1.5 K | 0.737 |

Three readings. First, a tuned count baseline is a strong classifier for topic, and nothing trained from scratch on 120,000 documents beat it. Second, pretraining is what moves the number: the only clear improvement over 0.92 came from a model trained on three billion words first. Third, the training *regime* on a pretrained model matters as much as the model: on SST-2 the spread between regimes of the same 124 M-parameter network is 24 points.

## The Transformer-era approaches

**Encoder with a classification head.** A pretrained encoder, a linear layer on the `[CLS]` vector (or the mean of token vectors), fine-tuned with a small learning rate or with LoRA. This is the default for a task with labelled data: one forward pass per document, no decoding, the highest accuracy per parameter, and a model that is cheap to serve and to evaluate. The choice between full fine-tuning and LoRA is a cost decision; the accuracy is the same within noise.

**Language model with constrained output.** Describe the classes in a prompt and ask an instruction-tuned decoder for the label. It works without any labelled data and competes with fine-tuned encoders only for large models; it costs a generation per document; and its raw output is text, which must be parsed. The parsing problem has a clean solution: **constrained decoding** restricts the sampled tokens at each step to those that can still complete a valid output. With a schema `Literal["Positive", "Negative", "Neutral"]` the model can produce nothing else, and with a JSON schema it produces a parseable object with typed fields; the [RAG note](/notes/nlp/rag) uses the same mechanism for structured extraction. Without constraints, the model "classifies" with explanations, hedges and formatting that break a parser on some fraction of inputs.

| | Fine-tuned encoder | Prompted decoder |
| --- | --- | --- |
| Labelled data | Required (hundreds to thousands) | None, or a few examples in the prompt |
| Cost per document | One encoder pass | One generation |
| Accuracy | Highest with data | Depends on model size and prompt |
| Output | Logits | Text; constrain it |
| Changing the label set | Retrain the head | Edit the prompt |
| Explanations | No | Can be asked for (not necessarily faithful) |

## What improved, and what did not

Pretrained encoders raised AG News accuracy from 0.92 to 0.95 with the same labels. The gain is larger when labels are scarce: with a few hundred examples, count models and from-scratch networks collapse and fine-tuned encoders stay usable ([Howard and Ruder, 2018](#references)). What did not change: the task still needs a label set that matches the data (the zero-shot experiment lost a class to a label name), the metrics still hide class-level failures unless asked, and a 95 % model still errs on 1 in 20 documents, which for some applications is too many and for others is irrelevant.

## Evaluation pitfalls specific to classification

- **Per-class blindness.** 0.456 overall hid 0.03 on one class. Always print the confusion matrix.
- **Truncation.** Encoders truncate at 128–512 tokens; a label that depends on the end of a long document is unreachable. Check where the signal is before choosing the limit.
- **Label leakage through artefacts.** A source tag, a URL or a date in the text can predict the label without reading it; the leave-one-token-out probe of the [CNN note](/notes/nlp/cnn-text-classification#seeing-what-the-classifier-uses) finds such shortcuts.
- **Threshold choice.** For binary and multi-label tasks, accuracy at the 0.5 threshold is one point on a precision–recall curve; report the curve or the threshold chosen on validation.
- **Prompt sensitivity.** A prompted classifier's accuracy changes with wording, label names and example order; evaluate the prompt that will be deployed, with the sampler it will use.
- **Test contamination.** A pretrained model may have seen the benchmark; a prompted one may have seen it with labels.

## Limitations

A classifier answers one fixed question. Changing the question means new labels and a new head, or a new prompt and a new evaluation. Tasks whose answer is a span, a set of entities or a sentence need the models of the following notes, and tasks whose answer depends on information outside the text need retrieval, which the [LLM systems section](/notes/nlp/semantic-search) builds.

## What you should remember

- Classification maps text to one of $K$ labels; binary, multi-class and multi-label variants differ in the output layer and loss.
- AG News: TF-IDF 0.918 → BERT fine-tuned 0.949; nothing from scratch beat the count baseline. SST-2: the training regime of one model spans 0.663 to 0.900.
- With labels, fine-tune an encoder (full or LoRA). Without labels, prompt a decoder with constrained output.
- Report per-class metrics, check truncation and artefacts, and evaluate the exact prompt and sampler that will be used.
