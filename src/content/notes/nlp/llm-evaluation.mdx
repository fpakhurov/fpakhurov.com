The [evaluation note](/notes/nlp/corpora-and-evaluation) at the start of the course assumed a test set with labels and a model that outputs one of them. The systems of this section break both assumptions: the output is text, the "model" is a pipeline of retrieval, generation and tool calls, and the quantity of interest (was the answer helpful, faithful, safe, fast enough, cheap enough) has no label. This note lays out the instruments that exist for each layer and what each can and cannot tell you, with one experiment that calibrates how much a model's judgement is worth.

**Notation.** A prompt $x$, a system output $y$, a score $s(x, y)$; human raters $A, B$; a judge model $J$. Pearson correlation $r$ between two sets of scores; Cohen's $\kappa$ for categorical agreement.

## Task-level benchmarks

The first layer asks what the base model can do: knowledge (MMLU), commonsense completion (HellaSwag), science questions (ARC), resistance to common falsehoods (TruthfulQA), and so on. Each is a dataset with a fixed prompt format and a scoring rule, and the value of the layer comes from running every model through the *same* format and rule. The **lm-evaluation-harness** ([Gao et al., 2024](#references)) standardizes this: a task is a YAML file that names the dataset, says how to build the prompt from a record (`doc_to_text`), how to read the target (`doc_to_target`), the choices if any, the few-shot setup and the metrics; every model implements three calls, `loglikelihood(context, continuation)`, `loglikelihood_rolling(text)` and `generate(prompt)`; and results are aggregated across sub-tasks into one report.

Two scoring modes matter for reading results. **Log-likelihood** scoring never generates: for a multiple-choice question, each option is appended to the prompt and the option with the highest model probability wins (variants normalize by length or by an unconditional baseline). It is deterministic, cheap and measures something slightly different from "can the model answer", namely "does the model find the right continuation more probable". **Generative** scoring samples an answer and compares it with the target by exact match, F1, BLEU or ROUGE, which depends on decoding settings and on parsing the answer out of the text.

What a benchmark score cannot say: whether the model will do your task (benchmarks are proxies), whether the number is stable under prompt changes (a different template moves MMLU by points), and whether the model has seen the test set (**contamination**: web-scale pretraining corpora contain the benchmarks, and a memorized answer is not a capability). A score reported without the harness version, the prompt format, the number of shots and the decoding settings is not reproducible.

## Retrieval evaluation

The second layer is the one the [semantic search note](/notes/nlp/semantic-search#measuring-a-retriever) built: a golden set of (query, relevant passage) and Hit@$k$ with MRR. It is cheap, exact, and bounds everything downstream; in a RAG system, retrieval recall at the context size is the ceiling of the answer accuracy, and it is measured first.

## A model as judge

The third layer scores free text. For open-ended answers there is no reference and no rule; the alternative to asking people is asking a model, with a rubric ([Zheng et al., 2023](#references)). It is fast and cheap, and its value depends entirely on how well it agrees with people, which can be measured.

### The experiment

A dataset of question–answer pairs with two independent human ratings each on a four-point scale (bad, could be improved, acceptable, excellent). A 1 B-parameter instruction-tuned model is used as the judge on 28 sampled pairs where the two humans agreed.

| Comparison | Pearson $r$ |
| --- | --- |
| Human rater A vs human rater B (full dataset) | 0.563 |
| Judge, naive prompt (score 0–10 as a float, no rubric) vs humans | **−0.169** |
| Judge, improved prompt (1–4 integer scale, rubric text per level, written evaluation before the score) vs humans | 0.192 |

Three readings, in order of importance.

**The naive judge is worse than useless.** A negative correlation on 28 items means its scores carry no information about human judgement, and the sign is noise. Asking a small model for a float on a 0–10 scale produces numbers that look like scores and are not.

**Prompt structure matters and is not enough.** A small integer scale with a described meaning for each level, and a required written evaluation before the number, moves the correlation to 0.19. That is a real change in behaviour and still far below the human–human 0.56. A 1 B model is not a usable judge for this task; the notebook's own narration, which calls 0.19 "close to human-level", is contradicted by its numbers. Larger judge models do better, but the point stands: a judge's agreement with people has to be *measured*, on your task, before its scores are used.

**The ceiling is the humans.** Two people agree at 0.56; a perfect judge cannot exceed the reliability of the labels it is compared with. Noisy rubrics produce noisy ground truth.

### Practice

What raises judge quality, from the literature and the experiment: a small integer scale (1–4 or 1–5) rather than a wide or continuous one; a rubric that defines each level; evaluation text before the score; a reference answer when one exists; few-shot examples of scored answers; an additive rubric (one point per criterion met) when the judgement decomposes; structured output so that the score is parsed rather than regexed out of prose; temperature 0; and, for pairwise comparisons, presenting both orders to cancel **position bias**. Known systematic biases of judge models include a preference for longer answers (verbosity bias) and for their own style (self-preference), both documented in [Zheng et al. (2023)](#references). Cost control: in a RAG pipeline, judge only the reranked top candidates, not every retrieved chunk.

### Agreement for categorical labels

When the judge's output is a category (relevant / not relevant, pass / fail), Pearson is the wrong statistic. **Cohen's $\kappa$** measures agreement between two labellers beyond what chance would produce:

$$
\kappa = \frac{p_o - p_e}{1 - p_e},
$$

with $p_o$ the observed proportion of agreements and $p_e$ the agreement expected from each labeller's marginal frequencies. Toy example: on 100 items, rater A marks 60 % relevant and rater B 70 %, and they agree on 80 items. Then $p_e = 0.6 \times 0.7 + 0.4 \times 0.3 = 0.54$ and $\kappa = (0.80 - 0.54)/0.46 = 0.565$. The 80 % raw agreement looked good; nearly half of it was expected by chance. $\kappa = 1$ is perfect, 0 is chance, below 0 is systematic disagreement; the usual (and arbitrary) reading has 0.4–0.6 as moderate and above 0.8 as near-perfect ([Landis and Koch, 1977](#references)). $\kappa$ falls when one labeller uses a category much more often than the other, even at high raw agreement, so report both.

## Human evaluation

People are the reference for everything above and expensive, so the design of a human evaluation is about getting reliable labels from few judgements.

- **Pairwise preference** is more reliable than absolute scores: show two outputs for the same prompt, ask which is better. Chatbot Arena collects such votes from users and fits a Bradley–Terry model (the same one as the reward model of the [instruction tuning note](/notes/nlp/instruction-tuning#with-a-reward-model-rlhf)) to rank models.
- **Rubrics and training** for raters, and a measured inter-rater agreement ($\kappa$ or correlation) reported with the result; the 0.56 above is a typical number for a four-point helpfulness scale.
- **Sampling.** A few hundred prompts, stratified by type, judged by two or more raters each, with disagreements adjudicated. Confidence intervals, since the sample is small.
- **Blinding.** Raters must not know which system produced which output.

## The system, not the model

The layers above score a model or a stage. What ships is a workflow, and it is evaluated on three more axes:

**End-to-end task success.** Did the user get what they needed? For a RAG assistant: fraction of golden questions answered correctly *and* faithfully. For an agent: fraction of tasks completed, at what number of steps. Failures are attributed to the stage that caused them (retrieval miss, bad context, unfaithful generation, wrong tool call), which is why each stage keeps its own metric.

**Latency and cost.** Time to first token and tokens per second for interactive use; total wall-clock for batch use; tokens in and out per request, which is money and, for agents, grows with every step (the 9,500-token weather lookup of the [previous note](/notes/nlp/tools-and-agents#the-protocol)). A model that scores two points higher and doubles the cost per query has not necessarily improved the product.

**Reliability.** The rate of unparseable outputs (which structured output drives to zero), of tool errors, of timeouts, of refusals on legitimate requests; variance across repeated runs of the same prompt at the deployed temperature; and behaviour on adversarial and out-of-distribution inputs, including injection attempts through retrieved or tool-returned text.

These are measured on a fixed **regression suite** that runs on every change to a prompt, a model version, an index or a tool, with the same discipline as a test suite for code, and continued in production by sampling live traffic for human or judge review.

| | Classifier evaluation | LLM-system evaluation |
| --- | --- | --- |
| Ground truth | labels | references (sometimes), rubrics, preferences |
| Scorer | exact comparison | metrics per stage; model judges validated against people |
| Unit | one model | a pipeline; failures attributed by stage |
| Reproducibility | split + metric | + prompt format, shots, decoding, harness version |
| Non-quality axes | rarely | latency, cost, reliability, safety |

## Limitations

- **Benchmarks saturate and leak.** A score near the ceiling or on a contaminated set says little.
- **Judges inherit the generator's weaknesses.** Verbosity and self-preference biases, and low agreement with people for small judges, as measured above.
- **Human labels are noisy** (0.56 between raters here) and bound every automated metric.
- **Small samples.** 28 items give a correlation estimate with a wide interval; the sign of the naive judge's $-0.17$ is not meaningful, only its magnitude relative to 0.56.
- **Metrics drift from goals.** A system optimized for a judge score optimizes for the judge's biases.

## What you should remember

- Benchmarks are standardized prompts plus scoring rules; report format, shots, decoding and harness version; watch for contamination.
- Retrieval recall at the context size bounds a RAG system; measure it first.
- A model judge is only as good as its measured agreement with humans: naive 0–10 float prompt $r = -0.17$, structured 1–4 rubric $r = 0.19$, human–human $r = 0.56$ with a 1 B judge. Use small integer scales, rubrics, reasoning first, references, structured output, temperature 0, both orders for pairs.
- Cohen's $\kappa$ corrects categorical agreement for chance; report it with raw agreement.
- Evaluate the workflow: end-to-end success attributed by stage, latency, cost, reliability, on a regression suite that runs on every change.
