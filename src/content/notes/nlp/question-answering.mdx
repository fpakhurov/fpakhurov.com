NER labels tokens that are there to be labelled. Question answering asks the model to *find* something: given a question and a passage, return the part of the passage that answers it. The Transformer-era formulation makes this a prediction of two positions, and almost all of the engineering is in getting the data into and out of that form.

**Notation.** Question $q$, context passage $c$; the answer is a span $c[a_s : a_e]$ given as a character offset and a text; after tokenization the span is a pair of token indices $(s, e)$; the encoder gives a vector $h_j$ per token.

## Task formulation

**Extractive QA**: the answer is a contiguous span of the given passage. The SQuAD 1.1 benchmark ([Rajpurkar et al., 2016](#references)) has 87,599 training and 10,570 validation question–passage–answer triples drawn from Wikipedia, with the answer stored as text plus its start character:

```json
{"context": "Barack Obama was born in Honolulu and ...",
 "question": "Where was Barack Obama born?",
 "answers": {"text": ["Honolulu"], "answer_start": [25]}}
```

The end offset is implied by the text's length. Every answer is guaranteed to exist in the passage; SQuAD 2.0 ([Rajpurkar, Jia and Liang, 2018](#references)) adds unanswerable questions, for which the model must abstain.

**Open-domain QA** drops the given passage: the system must find candidate passages in a corpus first, then extract or generate the answer. **Generative QA** lets a decoder write the answer in its own words ([below](#extractive-or-generative)). The extractive setting isolates the reading step and is where the mechanics are clearest.

## Baseline: match the question against the passage

Early neural readers encoded the question and the passage separately and built an attention matrix between them, so that each passage token knew which question tokens it resembled; BiDAF ([Seo et al., 2017](#references)) reached about 77 $F_1$ on SQuAD 1.1 with that design over LSTMs. The Transformer formulation removes the separate encoders: feed both texts into one encoder and let self-attention do the matching.

<aside class="callout"><strong>Key idea.</strong> Concatenate question and passage into one sequence. Every passage token then attends to every question token through the encoder. Train two scorers over positions, one for "the answer starts here" and one for "the answer ends here", and read the answer off as the best start–end pair.</aside>

## The input

`[CLS] question [SEP] passage [SEP]`, with `token_type_ids` marking the two segments. Three complications are handled at preprocessing time:

**Long passages.** The encoder reads at most 384 tokens here (512 is the model's limit). The question is never truncated (`truncation="only_second"`); a long passage is cut into overlapping **windows** of the remaining length with a stride of 128 tokens, each window paired with the full question, so that an answer near a cut is wholly inside at least one window. One example may become several; `overflow_to_sample_mapping` records which original example each window came from. A 128-token window with stride 32 turns one SQuAD example into three.

**Characters to tokens.** The answer is a character offset; the model needs token indices. `return_offsets_mapping=True` gives each token's `(start_char, end_char)` in the original text:

| token | `[CLS]` | Barack | Obama | was | born | in | Hawaii | . | `[SEP]` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| offsets | (0, 0) | (0, 6) | (7, 12) | (13, 16) | (17, 21) | (22, 24) | (25, 31) | (31, 32) | (0, 0) |

The start token is the last one whose start character $\le$ `answer_start`, and the end token the first one whose end character $\ge$ `answer_start + len(text)`, searched only within the passage segment (`sequence_ids` tells which tokens belong to the question, the passage, or neither).

**Windows without the answer.** If the answer is not fully inside a window, both targets are set to position 0, the `[CLS]` token. The model thus learns a "no answer in this window" output, which is also how SQuAD 2.0 abstention is represented.

## The model and its loss

Two linear scorers on top of the encoder, implemented as one `nn.Linear(768, 2)` whose two outputs are split:

$$
\begin{aligned}
s_j &= w_s \cdot h_j, \qquad e_j = w_e \cdot h_j, \\
P_{\text{start}}(j) &= \operatorname{softmax}_j(s), \quad P_{\text{end}}(j) = \operatorname{softmax}_j(e).
\end{aligned}
$$

Each softmax runs *over positions*, not over classes: "which of the $m$ tokens is the start" is one $m$-way classification and "which is the end" another. This is not the three-class token tagging (start / end / neither) it might look like: that formulation would allow several starts in one passage and has no way to prefer one; the position softmax yields exactly one of each and a joint score for any pair. The loss is the mean of the two cross-entropies,

$$
\mathcal L = \tfrac12\big(-\log P_{\text{start}}(s^*) - \log P_{\text{end}}(e^*)\big),
$$

and the prediction is the pair $(j, k)$ maximizing $s_j + e_k$ subject to $j \le k$ and $k - j$ below a maximum answer length, scored across all windows of the example; the plain argmax of each head separately can return an end before the start.

### What a frozen encoder gives

Freeze BERT-base-cased, train only the 1,538-parameter head on 2,000 training windows for three epochs, and ask *Where was Barack Obama born?* over *Barack Obama was born in Hawaii. He was elected president in 2008.* Decoded with a separate argmax per head, the answer is `Barack Obama born? [SEP] Barack Obama`: the independent argmaxes land in the question segment, the end precedes the start, and the decoded span runs across the separator. Decoding with the rule above (context tokens only, start before end, bounded length) removes the malformed span. How good the frozen head is beyond that one example is not known: the run is small (2,000 windows) and saved no exact match or $F_1$. So it shows the weakness of this setup, not that a frozen encoder cannot extract spans. Frozen MLM features were not trained to mark where an answer starts, and task-specific fine-tuning generally improves them; to say by how much, a frozen baseline and the fine-tuned model need the same constrained decoder and the same evaluation set. Fine-tuned BERT-base reaches 88.5 $F_1$ and 80.8 exact match on SQuAD 1.1 ([Devlin et al., 2019](#references), Table 2); the published recipe is three epochs over the full training set at learning rate $3 \times 10^{-5}$ with all parameters trained.

## Metrics

**Exact match** (EM): 1 if the predicted text equals one of the gold answers after normalization (lowercase, strip punctuation and articles), else 0. **F1**: token-level overlap between prediction and gold, with the maximum taken over the gold answers when there are several, averaged over questions. EM punishes `in Honolulu` against `Honolulu`; F1 gives it $2 \cdot 1 \cdot 0.5 / 1.5 = 0.67$. Both are computed on *text*, so the character-to-token round trip must be inverted exactly: decode the predicted token span back to the original characters with the offsets, not to a re-tokenized string.

## Extractive or generative

Generative QA keeps the input and changes the output. An encoder–decoder or a decoder-only model receives the question and the passage as text, in T5 for example as `question: … context: …` ([Raffel et al., 2020](#references), §2.3 and Appendix D), and writes the answer token by token. Training is the next-token cross-entropy on the answer tokens, as in [abstractive summarization](/notes/nlp/summarization#abstractive-summarization); the input positions carry no loss.

| | Extractive | Generative |
| --- | --- | --- |
| Output | two positions $(s, e)$ in the passage | answer text, token by token |
| Head and loss | two softmaxes over positions | a softmax over the vocabulary at each answer token |
| Answer inside the passage | guaranteed | not guaranteed: can paraphrase, combine or invent |
| No answer | position 0, `[CLS]` | a text such as "unanswerable", if trained to produce it |
| Decoding | best pair $(j, k)$ with $j \le k$ | greedy or beam search |

**Worked example** (toy probabilities). For *Where was Barack Obama born?* over *Barack Obama was born in Hawaii.*, the extractive target is the position of `Hawaii` for both heads. If the model gives it start probability 0.7 and end probability 0.6, the loss is $\tfrac12(-\ln 0.7 - \ln 0.6) = \tfrac12(0.357 + 0.511) = 0.434$. The generative target is the text `Hawaii` followed by the end-of-sequence token; with probabilities 0.8 and 0.9 for these two target tokens the loss, summed over them, is $-\ln 0.8 - \ln 0.9 = 0.223 + 0.105 = 0.329$. The extractive softmaxes range over the positions of this passage, so any prediction is a piece of it; the generative softmax ranges over the whole vocabulary at every step, which is what lets it rephrase and what lets it write an answer the passage does not contain.

## From a given passage to a retrieved one

Extractive QA assumes someone handed the model the right passage. In an open-domain system the passage comes from a retriever: embed the question, find the nearest passages in an index of a corpus, and run the reader on the top few ([Chen et al., 2017](#references); [Karpukhin et al., 2020](#references)). The reader's accuracy is then bounded by the retriever's recall, and the two have to be evaluated separately, which is the structure of the [semantic search](/notes/nlp/semantic-search) and [RAG](/notes/nlp/rag) notes. Generative readers (a decoder given the question and passages) replace span extraction by free text and inherit its advantages (paraphrase, synthesis across passages) and its risk (answers not in the passages).

## What changed

| | BiDAF-style reader | Pretrained encoder, two heads |
| --- | --- | --- |
| Question–passage matching | explicit attention layer | self-attention over the concatenation |
| Encoders | separate, from scratch | one, pretrained |
| Output | start/end over positions | start/end over positions |
| SQuAD 1.1 F1 | ≈ 77 | 88.5 (base), 90.9 (large) |
| Long passages | truncated | sliding windows |

## Limitations

- **Only spans.** Answers that need counting, combining or rephrasing cannot be extracted.
- **Abstention is hard.** Without unanswerable training data the model always finds a span; with it, the `[CLS]` score must be calibrated against the best span score.
- **Windows can split evidence.** An answer whose justification lies outside its window is guessed from local cues.
- **EM and F1 measure overlap**, not correctness; a wrong span with the right words scores well, and a correct paraphrase scores zero on EM.
- **Memorization.** Wikipedia-based benchmarks overlap pretraining corpora; a model may answer from memory rather than from the passage, which the retrieved-passage setting exposes.

## What you should remember

- Extractive QA: `[CLS] q [SEP] c [SEP]` → two softmaxes over positions (start, end) → best pair with $j \le k$.
- Preprocessing does the work: sliding windows with stride for long passages, offset mapping from characters to tokens, position 0 for windows without the answer.
- A small frozen-encoder run gave a malformed answer and no measured score; fine-tuning is the standard route (BERT-base: 88.5 F1 on SQuAD 1.1), and a fair comparison uses the same constrained decoder for both.
- Generative QA: question and passage go in as text, a decoder writes the answer, trained with next-token cross-entropy on the answer tokens. It can rephrase and combine, and nothing keeps it inside the passage.
- EM and token F1 on normalized text; decode spans via offsets.
- Open-domain QA = retriever + reader; the reader is bounded by retrieval recall.
