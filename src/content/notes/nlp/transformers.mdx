Self-attention, as left by the [previous note](/notes/nlp/attention), produces for each token a weighted average of value vectors. That is a mixing operation across positions. The weights depend non-linearly on the input through the softmax, but nothing transforms a token's own features non-linearly, and there is no depth, no order, no way to generate. The Transformer ([Vaswani et al., 2017](#references)) is self-attention plus the minimum needed to fix each of these, and the result is a block that can be stacked, trained in parallel over the sequence, and arranged in three ways depending on the task.

**Notation.** $x \in \mathbb R^{n \times d}$ is the block input (one row per position), $d$ the model width, $d_{\text{ff}}$ the feed-forward width, $L$ the number of blocks, $h$ the number of heads. $\operatorname{Attn}$ is multi-head self-attention and $\operatorname{FFN}$ the position-wise feed-forward network.

## Baseline: a stack of attention layers

Stack self-attention layers directly and two things fail. Each layer's output is linear in its values, so $L$ layers give a sum of products of content-dependent averaging matrices applied to the input and followed by fixed linear maps. The averaging weights depend on the input non-linearly, but a token's own features never pass through a non-linear function: for a one-token input every attention matrix is the scalar 1, and the whole stack is a linear map of that token. There is no per-token computation. Such a stack also degenerates with depth: without residual connections and feed-forward layers its output converges doubly exponentially fast to a rank-1 matrix, every token mapped to nearly the same vector ([Dong, Cordonnier and Loukas, 2021](#references)). And deep stacks of any kind suffer the gradient problems of the [RNN note](/notes/nlp/recurrent-networks#gradients-through-time): the signal at the top passes through $L$ transformations before reaching the bottom.

## The block

<aside class="callout"><strong>Key idea.</strong> Alternate two operations: attention moves information <em>between</em> positions, and a small two-layer network transforms each position <em>independently</em>. Wrap each in a residual connection so the block computes a correction to its input rather than a replacement, and normalize so that activations stay on a fixed scale however many blocks are stacked.</aside>

With pre-norm placement (the common modern choice) a block reads

$$
h' = h + \operatorname{Attn}(\operatorname{Norm}(h)), \qquad h'' = h' + \operatorname{FFN}(\operatorname{Norm}(h')).
$$

<BlockFlow />

Step by step, in the order of the numbers in the figure:

1. **Input.** Each token's embedding plus the vector of its position gives $h$, one row per token (where the position comes from is the subject of the [next note](/notes/nlp/positional-encoding)).
2. **Mix positions.** $h$ is normalized and goes through multi-head self-attention, the computation of the [previous note](/notes/nlp/attention#from-embeddings-to-q-k-and-v). This is the only step in which one position reads another.
3. **Add.** The attention output is added to $h$: $h' = h + \operatorname{Attn}(\operatorname{Norm}(h))$. The unchanged $h$ travels along the residual stream, the blue line.
4. **Transform each position.** $h'$ is normalized and goes through the FFN, the same two-layer network applied to every position separately.
5. **Add again.** $h'' = h' + \operatorname{FFN}(\operatorname{Norm}(h'))$.
6. **Stack.** $h''$ has the shape of $h$, so it is the input of the next block; $L$ blocks later, a task head reads the result.

### Position-wise feed-forward network

$$
\operatorname{FFN}(x) = \sigma(x W_1 + b_1)\, W_2 + b_2, \qquad W_1 \in \mathbb R^{d \times d_{\text{ff}}},\; W_2 \in \mathbb R^{d_{\text{ff}} \times d},
$$

applied to every row of $x$ separately with the same weights. $\sigma$ is ReLU in the original and GELU in BERT and GPT-2; Llama replaces the two-matrix form by a gated one with three matrices (`gate`, `up`, `down` in the module listing) and the SiLU activation. The width is conventionally $d_{\text{ff}} = 4d$: 3,072 for BERT-base, 8,192 for the 2,048-wide Llama 3.2 1B of the [GPT note](/notes/nlp/gpt). The softmax and LayerNorm are non-linear too, but the softmax only sets mixing weights and LayerNorm only standardizes each vector; the FFN is the block's learned non-linear transformation of each position on its own, and where most of its parameters live: $2 d d_{\text{ff}} = 8d^2$ against $4d^2$ for attention.

### Residual connections

$h + f(h)$ instead of $f(h)$. The derivative of block $l$ with respect to its input is $I + J_l$ with $J_l = \partial f_l/\partial h$. The chain rule still multiplies the factors of all $L$ blocks, but the product expands as

$$
\prod_{l=1}^{L} (I + J_l) = I + \sum_{l} J_l + \sum_{l < m} J_m J_l + \dots + J_L \cdots J_1 ,
$$

so besides the term through all $L$ Jacobians, the only one a recurrence has, the gradient gets an identity term that passes through no weight matrix and short terms through one or two blocks. Residuals do not remove the chain rule or guarantee stable gradients; they add short routes, and in practice that makes deep stacks trainable. This is why Transformers go deep: 12 blocks in BERT-base, 32 in a 7 B Llama, 96 in GPT-3, and the [translation note](/notes/nlp/transformer-machine-translation) gains 0.02 BLEU in one run by going from 1 block to 4 on 29,000 sentences. The requirement is that input and output of every block have the same width $d$, which fixes $d$ throughout the stack.

### Normalization

**Layer normalization** ([Ba, Kiros and Hinton, 2016](#references)) standardizes each position's vector across its $d$ features:

$$
\operatorname{LN}(x_i) = \gamma \odot \frac{x_i - \mu_i}{\sqrt{\sigma_i^2 + \epsilon}} + \beta, \qquad \mu_i = \frac1d\sum_{j=1}^d x_{ij},\;\; \sigma_i^2 = \frac1d\sum_{j=1}^d (x_{ij} - \mu_i)^2 .
$$

Unlike batch normalization (see the [Generative Models note](/notes/generative-models/training-background#batch-normalization)), the statistics are per example and per position, so they do not depend on the batch and behave the same at training and inference time; this matters for variable-length sequences with padding. $\gamma, \beta \in \mathbb R^d$ are learned.

**RMSNorm** ([Zhang and Sennrich, 2019](#references)), used by Llama, drops the mean subtraction and the shift $\beta$ and divides by the root mean square alone:

$$
\operatorname{RMSNorm}(x_i) = \gamma \odot \frac{x_i}{\sqrt{\frac1d \sum_{j=1}^d x_{ij}^2 + \epsilon}} .
$$

LayerNorm centres the vector and then scales it; RMSNorm only scales it. For $x_i = (1, 2, 3, 6)$, with $\gamma = 1$, $\beta = 0$ and $\epsilon$ left out: LayerNorm subtracts the mean 3 and divides by $\sqrt{3.5} = 1.871$, giving $(-1.069, -0.535, 0, 1.604)$, which has mean 0 and variance 1; RMSNorm divides by $\sqrt{(1 + 4 + 9 + 36)/4} = 3.536$, giving $(0.283, 0.566, 0.849, 1.697)$, which has mean square 1 and keeps its offset from zero. Skipping the mean saves one reduction over the $d$ features, and in the authors' experiments it trains as well as LayerNorm.

### Pre-norm versus post-norm

The original paper normalizes *after* the residual sum, $h' = \operatorname{LN}(h + \operatorname{Attn}(h))$; this is the **post-norm** block, and it is what BERT uses. Most later models normalize the *input* of each sub-layer, the **pre-norm** block written above (GPT-2, Llama). The difference is where the residual path goes: in pre-norm it is an unbroken identity from the bottom of the stack to the top, in post-norm it passes through a LayerNorm at every block. [Xiong et al. (2020)](#references) showed that at initialization the post-norm block gives large gradients to the parameters near the output, while in pre-norm they shrink with depth, which is why post-norm models need learning-rate warm-up and careful initialization, whereas pre-norm trains stably without warm-up. Post-norm, when it trains, is sometimes slightly better on the final metric; the trade is stability for a small amount of accuracy, and at scale stability wins.

<BlockVariants />

**Two separate choices.** *Which* normalization (LayerNorm or RMSNorm) and *where* it sits (after the residual sum or at the input of the sub-layer) are independent axes. The first decides what $\operatorname{Norm}$ computes: centre and scale, or scale only. The second decides whether the residual path stays an identity. Any combination is possible:

| | LayerNorm (centre and scale) | RMSNorm (scale only) |
| --- | --- | --- |
| Post-norm (after the residual sum) | Original Transformer, BERT | Possible; the axes do not constrain each other |
| Pre-norm (at the sub-layer input) | GPT-2, GPT-3 | Llama |

The stability argument of [Xiong et al. (2020)](#references) is about placement. Replacing LayerNorm with RMSNorm changes the cost of one operation and leaves the residual path where it was; moving LayerNorm from after the sum to the sub-layer input changes the residual path and leaves the operation as it was.

### Where the input comes from

Before the first block, token ids are embedded and position information is added: $x = E[\text{ids}] \cdot \sqrt d + P$, where $P$ encodes positions (the subject of the [next note](/notes/nlp/positional-encoding)). The $\sqrt d$ factor matches the scale of the embedding to that of the positional signal. Dropout is applied to the sum, to the attention weights, and after each sub-layer.

## Parameters of a block

Per block, ignoring biases and normalization vectors: $4d^2$ in attention (three projections plus the output map) and $8d^2$ in the FFN, $12d^2$ in total. The small AG News encoder below has $d = 32$ and, unusually, $d_{\text{ff}} = 32$:

| Component | Count |
| --- | --- |
| Token embeddings, $4{,}000 \times 32$ | 128,000 |
| Per block: attention $4 \times 32^2$ | 4,096 |
| Per block: FFN $2 \times (32 \times 32 + 32)$ | 2,112 |
| Per block: two LayerNorms, $2 \times 64$ | 128 |
| Four blocks | 25,344 |
| Classifier $32 \times 4 + 4$ | 132 |
| Sinusoidal position table $128 \times 32$ (fixed, but registered as a parameter) | 4,096 |
| **Total** | **157,572** |

The breakdown shows the usual proportions: the embedding table dominates a small model, and the blocks are tiny. For BERT-base ($d = 768$, $L = 12$, cased vocabulary of 28,996) the same arithmetic gives $12 \times 12 \times 768^2 = 84.9$ M in the blocks, 22.3 M in token embeddings, 0.4 M in position embeddings and 0.6 M in the pooler, about 108 M in all, which is the figure the [NER note](/notes/nlp/named-entity-recognition) prints.

## Three arrangements

The same block is used in three ways, distinguished by the mask and by whether there is a second sequence.

**Encoder-only.** Blocks with unmasked self-attention: every position sees every other, in both directions. The output is one contextual vector per token. Used for representation and understanding tasks: classification by pooling the vectors (the AG News model below averages the non-padding positions; BERT uses the first token), token labelling, span extraction. The [BERT note](/notes/nlp/bert) is the main example.

**Decoder-only.** Blocks with causal self-attention: position $t$ sees positions $\le t$ only. The output at $t$ predicts token $t + 1$, so the model is a language model trained on whole sequences in one pass. The mask is what makes that training legitimate: without it, position $t$ could read token $t + 1$, its own target, and the loss would be minimized by copying, the failure the [BERT note](/notes/nlp/bert#baseline-a-language-model-objective-on-an-encoder) starts from. The dominant arrangement for generation; the [GPT note](/notes/nlp/gpt).

**Encoder–decoder.** An encoder stack over the source, and a decoder stack whose blocks have a third sub-layer, **cross-attention**, in which the queries come from the decoder and the keys and values from the encoder output; this is the attention of the [pre-Transformer note](/notes/nlp/attention-before-transformers) with projections. The decoder's own self-attention is causal. Natural for translation and other input-to-output transformations; the [translation note](/notes/nlp/transformer-machine-translation) trains one.

<EncoderDecoder />

The three names describe information flow. Tokenization, training objective, data, decoding and evaluation all remain to be chosen, and the [model-families note](/notes/nlp/model-families) compares them along those axes.

## Original versus modern Transformer

The block above is the 2017 design with the normalization already moved to the sub-layer input. Decoder-only models of recent years change several more parts. It helps to separate two kinds of change. An **architecture** change alters the function the network computes, and with it the parameter count, the training behaviour or the memory needed at generation. An **implementation** change computes the same function with a different program; a model trained with one implementation runs unchanged with the other.

| Part | Original Transformer (2017) | Typical modern decoder | Kind | What it buys |
| --- | --- | --- | --- | --- |
| Norm placement | Post-norm | [Pre-norm](#pre-norm-versus-post-norm) | Architecture | Identity residual path; deep stacks train stably |
| Norm operation | LayerNorm | [RMSNorm](#normalization) | Architecture | Scale only; one reduction fewer |
| FFN | Two matrices, ReLU | SwiGLU: three matrices, gated | Architecture | Lower perplexity at equal size in the paper's T5 experiments |
| Positions | Sinusoidal or learned, added to the input | [RoPE](/notes/nlp/positional-encoding#relative-and-rotary-positions), a rotation of $q$ and $k$ | Architecture | Scores depend on relative offset; no table |
| Attention heads | Multi-head: every head has its own $K$, $V$ | Grouped-query: groups of query heads share one $K$, $V$ | Architecture | A smaller key–value cache at generation |
| FFN capacity | Dense: every token uses the one FFN | Optional mixture of experts: a router sends each token to a few of many FFNs | Architecture | More parameters at the same compute per token |
| Attention kernel | Standard: the $n \times n$ score matrix is written to GPU memory | FlashAttention: computed tile by tile, never stored | Implementation | Same output, far less memory traffic |

Three of the rows need a formula. The gated FFN of [Shazeer (2020)](#references) multiplies two projections elementwise before the output map:

$$
\operatorname{FFN}_{\text{SwiGLU}}(x) = \big(\operatorname{SiLU}(x W_{\text{gate}}) \odot x W_{\text{up}}\big)\, W_{\text{down}}, \qquad \operatorname{SiLU}(z) = z\,\sigma(z),
$$

with $W_{\text{gate}}, W_{\text{up}} \in \mathbb R^{d \times d_{\text{ff}}}$ and $W_{\text{down}} \in \mathbb R^{d_{\text{ff}} \times d}$: $3 d d_{\text{ff}}$ parameters instead of $2 d d_{\text{ff}}$, so the paper reduces $d_{\text{ff}}$ by a third to compare at equal size. **Grouped-query attention** ([Ainslie et al., 2023](#references)) keeps $h$ query heads but only $g$ key–value heads, each shared by $h/g$ query heads; the keys and values cached per token and block shrink from $2 h d_k$ numbers to $2 g d_k$, a factor of 4 for Llama 3.2 1B with $h = 32$ and $g = 8$. A **mixture of experts** ([Shazeer et al., 2017](#references)) replaces the FFN by $E$ expert FFNs and a router; each token is processed by the $k$ experts with the highest router scores, so the parameter count grows with $E$ and the compute per token with $k$. Mixtral 8x7B, for example, has 8 experts per layer and uses 2 per token ([Jiang et al., 2024](#references)).

FlashAttention ([Dao et al., 2022](#references)) is the one row that is not architecture: it returns the same attention output as the formula of the [self-attention note](/notes/nlp/attention#scaled-dot-product-attention), up to floating-point rounding, and only changes how the computation is laid out on the GPU. It and the mixture of experts are the subject of the [efficient Transformers note](/notes/nlp/efficient-transformers). The Llama 3.2 1B model of the [GPT note](/notes/nlp/gpt#two-models-by-the-numbers) has every architecture row of the right column except the mixture of experts.

## A small encoder on AG News

To put a number next to the architecture: a 4-block, 4-head encoder with $d = 32$ over a 4,000-entry WordPiece vocabulary, mean-pooled over non-padding tokens into a linear classifier, trained from random initialization for 20 epochs with Adam at $10^{-3}$ and batch size 256, reaches a test accuracy of **0.906** at its best epoch on AG News. That epoch was picked by looking at the test set, the pitfall of the [evaluation note](/notes/nlp/corpora-and-evaluation#pitfalls-that-survive-a-correct-split), so the figure is slightly optimistic. The TF-IDF baseline of the [bag-of-words note](/notes/nlp/bag-of-words-and-tf-idf) is 0.918 and the best convolutional model 0.911. A Transformer trained from scratch on 120,000 short documents is not better than the alternatives; its advantage appears when it is pretrained on far more text, which is the subject of the next section of the course. What the experiment does show is that the architecture trains without difficulty at this size and that its attention maps are inspectable.

## What changed

<Evolution />

The whole path from the [recurrent network](/notes/nlp/recurrent-networks) to this block, one change at a time. Against self-attention alone, the block adds the following:

| | Self-attention alone | Transformer block |
| --- | --- | --- |
| Per-position computation | None (weighted average) | FFN with $8d^2$ parameters |
| Depth | Products of averaging matrices; output degenerates towards rank 1 | $L$ residual blocks |
| Scale of activations | Uncontrolled | LayerNorm per position |
| Order | None | Positional signal added at the input |
| Generation | — | Causal mask in the decoder |
| Second sequence | — | Cross-attention |

## Limitations

- **Quadratic attention** is inherited; everything else in the block is linear in $n$.
- **Fixed width.** Residuals force one $d$ through the stack; capacity is added by depth or width everywhere.
- **Data appetite.** From scratch on small data, the architecture does not beat count baselines; it needs pretraining.
- **Position is an add-on.** Nothing in the block knows order; the quality of the positional scheme limits what the model can do with it.
- **Parameter count is not a design.** Two models with the same $L, d, h$ can differ in norm placement, activation, FFN form and positional scheme, and these change training behaviour more than the headline numbers suggest.

## What you should remember

- Block: $h' = h + \operatorname{Attn}(\operatorname{Norm}(h))$, $h'' = h' + \operatorname{FFN}(\operatorname{Norm}(h'))$. Attention mixes positions, FFN transforms each position, residuals keep an identity path, LayerNorm fixes the scale.
- $12d^2$ parameters per block ($4d^2$ attention, $8d^2$ FFN); the embedding table dominates small models.
- Pre-norm: identity residual path, stable deep training. Post-norm: original, needs warm-up.
- LayerNorm centres and scales, RMSNorm only scales; that choice is independent of where the norm is placed.
- A typical modern decoder: pre-norm, RMSNorm, SwiGLU, RoPE, grouped-query attention and optionally a mixture of experts (architecture), run with FlashAttention (implementation).
- Encoder (bidirectional), decoder (causal), encoder–decoder (cross-attention): same block, different masks.
- From scratch on AG News: 0.906 at the best epoch, below TF-IDF; pretraining is what makes the architecture pay off.
