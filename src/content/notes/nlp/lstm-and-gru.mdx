The plain recurrent cell of the [previous note](/notes/nlp/recurrent-networks#gradients-through-time) overwrites its whole state at every step through a multiplication by $W_h$, and the gradient across $k$ steps is a product of $k$ such factors. The fix proposed by [Hochreiter and Schmidhuber (1997)](#references) and simplified by [Cho et al. (2014)](#references) is architectural: give the cell a path along which the state is *added to* rather than transformed, and let the network learn, per coordinate and per step, how much to keep, write and read.

**Notation.** As before, $x_t \in \mathbb R^d$ is the input, $h_t \in \mathbb R^H$ the hidden state. The LSTM adds a **cell state** $c_t \in \mathbb R^H$. $\sigma$ is the logistic function with range $(0, 1)$; $\tanh$ has range $(-1, 1)$; $\odot$ is element-wise multiplication. Each gate has its own weights $W_{\cdot}$ (on $x_t$), $U_{\cdot}$ (on $h_{t-1}$) and bias $b_{\cdot}$.

## Baseline: one state, overwritten every step

$h_t = \tanh(W_x x_t + W_h h_{t-1} + b)$. The state is recomputed from scratch at each step; nothing in the cell can say "leave coordinate 7 alone". Whether old information survives depends on $W_h$, which is shared across all steps and all coordinates, and the gradient factor per step is $\mathrm{diag}(1 - h_t^2) W_h$.

<aside class="callout"><strong>Key idea.</strong> Split the state into a memory line that is updated by multiplication with a number in $(0, 1)$ followed by addition, and a working state that is read from it. Gates computed from the current input and previous state decide the numbers. The gradient along the memory line is then a product of gate values, which the network can hold near 1 when it needs to remember.</aside>

## LSTM

Four quantities are computed from $(x_t, h_{t-1})$, three of them gates in $(0, 1)$ and one a candidate value in $(-1, 1)$:

$$
\begin{aligned}
f_t &= \sigma(W_f x_t + U_f h_{t-1} + b_f) && \text{forget gate: how much of } c_{t-1} \text{ to keep},\\
i_t &= \sigma(W_i x_t + U_i h_{t-1} + b_i) && \text{input gate: how much of the candidate to write},\\
\tilde c_t &= \tanh(W_c x_t + U_c h_{t-1} + b_c) && \text{candidate: what to write},\\
o_t &= \sigma(W_o x_t + U_o h_{t-1} + b_o) && \text{output gate: how much of the memory to expose}.
\end{aligned}
$$

Then the memory is updated and the working state read from it:

$$
c_t = f_t \odot c_{t-1} + i_t \odot \tilde c_t, \qquad h_t = o_t \odot \tanh(c_t).
$$

Every operation is per coordinate. A coordinate of $c$ with $f \approx 1$ and $i \approx 0$ is copied unchanged for as many steps as the gates stay that way; one with $f \approx 0$ and $i \approx 1$ is overwritten. The sigmoid range makes the gates fractions and the $\tanh$ range makes the candidate and the exposed value bounded, so $c_t$ can grow only by repeated addition of bounded values, not geometrically.

### Worked example

One coordinate, one step. Previous memory $c_{t-1} = 2$, previous state $h_{t-1} = 1$, input $x_t = 1$. Take scalar weights (toy values) so that each pre-activation is a small sum:

| Gate | Pre-activation | Value |
| --- | --- | --- |
| forget $f$ | $1.63 \cdot 1 + 2.70 \cdot 1 + 1.62 = 5.95$ | $\sigma(5.95) = 0.997$ |
| input $i$ | $1.65 \cdot 1 + 2.00 \cdot 1 + 0.62 = 4.27$ | $\sigma(4.27) = 0.986$ |
| candidate $\tilde c$ | $0.94 \cdot 1 + 1.41 \cdot 1 - 0.32 = 2.03$ | $\tanh(2.03) = 0.966$ |
| output $o$ | $-0.19 \cdot 1 + 4.38 \cdot 1 + 0.59 = 4.78$ | $\sigma(4.78) = 0.992$ |

Memory update: $c_t = 0.997 \times 2 + 0.986 \times 0.966 = 1.995 + 0.953 = 2.948$. Exposed state: $h_t = 0.992 \times \tanh(2.948) = 0.992 \times 0.994 = 0.986$.

The old memory survived almost entirely (forget gate near 1) and a new value of about $0.95$ was added. Had the forget gate come out at $0.1$, the memory would have dropped to $0.2 + 0.95$: same input, different decision, chosen by weights that see $x_t$ and $h_{t-1}$.

### Why the gradient survives

Differentiate the memory update with respect to the previous memory:

$$
\frac{\partial c_t}{\partial c_{t-1}} = \mathrm{diag}(f_t) + (\text{terms through } f_t, i_t, \tilde c_t \text{ that depend on } h_{t-1}).
$$

The first term is the forget gate itself. Along the memory line the gradient across $k$ steps contains the product $\prod f_s$, and the network can keep that near 1 by keeping the forget gates near 1 wherever memory is needed, whereas the plain RNN's factor $\mathrm{diag}(1 - h^2) W_h$ is a fixed matrix power. This does not prove that LSTMs learn arbitrary long dependencies (the other terms still vanish or explode, and gates saturate), but it removes the geometric decay that made the plain cell fail at tens of steps; in practice LSTMs learn dependencies over hundreds of tokens. The bias $b_f$ is often initialized to 1 so that the forget gates start open ([Jozefowicz, Zaremba and Sutskever, 2015](#references)).

### Cost

Each of the four blocks has an $H \times d$ matrix, an $H \times H$ matrix and a bias, so an LSTM cell has $4(Hd + H^2 + H)$ parameters, four times the plain cell (PyTorch stores two bias vectors per block, giving $4(Hd + H^2 + 2H)$). The translation model of the [seq2seq note](/notes/nlp/seq2seq) uses $d = H = 128$: $4(128 \cdot 128 + 128 \cdot 128 + 2 \cdot 128) = 132{,}096$ parameters per direction. The computation per step is also four matrix products instead of one, and still strictly sequential.

## GRU

The gated recurrent unit ([Cho et al., 2014](#references)) merges the memory and the working state and uses two gates:

$$
\begin{aligned}
z_t &= \sigma(W_z x_t + U_z h_{t-1} + b_z) && \text{update gate},\\
r_t &= \sigma(W_r x_t + U_r h_{t-1} + b_r) && \text{reset gate},\\
\tilde h_t &= \tanh\big(W_h x_t + U_h (r_t \odot h_{t-1}) + b_h\big) && \text{candidate},\\
h_t &= (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t .
\end{aligned}
$$

The update gate plays the roles of both $f$ and $i$, tied as $f = 1 - z$: what is not kept is overwritten. The reset gate controls how much of the previous state the candidate may read. There is no output gate; $h_t$ is the memory. The parameter count is $3(Hd + H^2 + H)$, three quarters of an LSTM at the same size, and one fewer matrix product per step. The AG News classifier of the [previous note](/notes/nlp/recurrent-networks#rnn-as-a-classifier) is a GRU with $d = 100$ and $H = 128$.

| | Plain RNN | LSTM | GRU |
| --- | --- | --- | --- |
| States | $h$ | $h, c$ | $h$ |
| Gates | 0 | 3 ($f, i, o$) | 2 ($z, r$) |
| Memory update | overwrite | $f \odot c + i \odot \tilde c$ | $(1 - z) \odot h + z \odot \tilde h$ |
| Parameters | $Hd + H^2 + H$ | $4\times$ | $3\times$ |
| Gradient factor along memory | $\mathrm{diag}(1-h^2)W_h$ | $\approx \mathrm{diag}(f)$ | $\approx \mathrm{diag}(1 - z)$ |

Which cell is better is empirical and task-dependent; large comparisons find them close, with the GRU cheaper and the LSTM slightly ahead on some long-range tasks ([Greff et al., 2017](#references)).

## Reading in both directions

A recurrent state at position $t$ summarizes $x_{\le t}$ and knows nothing of $x_{> t}$. For a classifier or an encoder that sees the whole input at once, run a second cell from right to left and concatenate the two states at each position: the **bidirectional** RNN gives $[\overrightarrow{h}_t; \overleftarrow{h}_t] \in \mathbb R^{2H}$, a representation of each token informed by its full context, at twice the cost. The encoder in the [next note](/notes/nlp/seq2seq) is a bidirectional LSTM. A language model cannot be bidirectional, since it must not see the token it predicts; the [BERT note](/notes/nlp/bert) finds a different way to use both directions.

## What changed

| | Plain RNN | Gated RNN |
| --- | --- | --- |
| Can keep a coordinate unchanged | Only if $W_h$ happens to | Yes, by gating |
| Long dependencies | Tens of tokens | Hundreds, in practice |
| Parameters per cell | $1\times$ | $3\times$ (GRU), $4\times$ (LSTM) |
| Sequential | Yes | Yes |
| Fixed-size state | Yes | Yes |

## Limitations

- **Still sequential.** Step $t$ depends on step $t - 1$. Training and inference time grow with $T$, and the sequence dimension cannot be parallelized.
- **Still one vector.** However well it remembers, the state at the end is $H$ (or $2H$) numbers that must hold everything the next stage needs. The [seq2seq note](/notes/nlp/seq2seq) makes this failure visible in translation.
- **Gates saturate.** Sigmoids near 0 or 1 have small derivatives; a gate that has learned to close is slow to reopen.
- **Capacity costs.** Four matrices per step; a 2-layer bidirectional LSTM with $H = 512$ is 8 M parameters before any embedding.

## What you should remember

- LSTM: $c_t = f_t \odot c_{t-1} + i_t \odot \tilde c_t$, $h_t = o_t \odot \tanh(c_t)$; gates in $(0, 1)$ from $\sigma$, candidate in $(-1, 1)$ from $\tanh$.
- The additive memory update makes the gradient factor along $c$ approximately the forget gate, which the network can hold near 1.
- GRU: two gates, one state, $h_t = (1 - z_t)\odot h_{t-1} + z_t \odot \tilde h_t$; three quarters of the LSTM's parameters.
- Bidirectional cells give each position its full context; they cannot be used for next-token prediction.
- Gating fixes the gradient, not the sequential computation or the single-vector summary.
