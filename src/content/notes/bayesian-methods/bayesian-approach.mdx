The Machine Learning course fitted every model in the same way: write down a loss or a likelihood, find the one parameter vector that minimizes or maximizes it, and predict with that vector. The [Bayesian inference note](/notes/probability/bayesian-inference) of the probability course showed, for a single coin, a different way: keep a distribution over the parameter, update it with the data, and predict by averaging over it. This course takes that second way as the method for building machine learning models. A model is assembled from a few standard distributions, everything unknown in it receives a distribution, and learning is the computation of the posterior. This note sets up the vocabulary: what probability means in this approach, how Bayesian reasoning works on small problems with numbers, what a point estimate throws away, and how a model is drawn as a graph. It ends with the plan of the course.

**Notation.** $x$ or $X = (x_1, \dots, x_n)$ are the observed data, $\theta$ the unknown parameters. $p(\theta)$ is the **prior**, $p(X \mid \theta)$ the **likelihood**, $p(\theta \mid X)$ the **posterior** and $p(X) = \int p(X \mid \theta)\, p(\theta)\, d\theta$ the **evidence** or marginal likelihood. The probability course wrote the prior as $\pi(\theta)$; this course writes $p(\cdot)$ for every density and lets the argument say which one is meant. $\hat\theta$ is a point estimate. For supervised models, $T = (t_1, \dots, t_n)$ are the targets of the inputs $X$ and $w$ the weights.

## Two readings of probability

The rules of probability, the [sum and product rules and Bayes' formula](/notes/probability/conditional-probability-and-bayes#bayes-formula), are the same in both readings. What differs is what a probability is about, and therefore which quantities may carry one.

In the **frequentist** reading, a probability is the long-run frequency of an outcome in a repeatable experiment. A coin's probability of heads is a property of the coin. A parameter, such as that probability, is a fixed unknown number: it is not random, so it has no distribution, and statements about it are statements about procedures. A 95% confidence interval is a rule that covers the true value in 95% of repeated samples; maximum likelihood is justified by how its estimates behave as the sample grows.

In the **Bayesian** reading, a probability is a degree of belief in a statement, given the information at hand. Nothing needs to be repeatable. "The mass of Saturn lies between 95 and 96 Earth masses", "this email is spam", "the third weight of this network is positive": each has a probability once we state what we know. Every unknown quantity, a parameter included, may then carry a distribution, and learning from data is the change of belief that Bayes' formula prescribes.

| | Frequentist | Bayesian |
| --- | --- | --- |
| A probability is | a long-run frequency | a degree of belief, given information |
| A parameter $\theta$ is | a fixed unknown constant | a random variable with a prior |
| What is random | only the data | everything unknown |
| Inference returns | an estimate $\hat\theta$ and its sampling behaviour | the posterior $p(\theta \mid X)$ |
| Typical method | maximum likelihood, confidence intervals | Bayes' formula, credible intervals, predictive averages |
| When it is justified | asymptotically, $n \gg$ number of parameters | for any $n$, given the model and the prior |

The last row is the practical point for machine learning. A deep network or a topic model has more parameters than any sample can pin down, so the asymptotic arguments behind maximum likelihood do not apply, while Bayes' formula applies to any sample size. The price is a prior, which must be chosen and defended, and an integral, which must be computed.

### Why beliefs obey the rules of probability

*Optional depth: two arguments for treating degrees of belief as probabilities. The rest of the note does not depend on it.*

Why should degrees of belief add up and multiply like frequencies? Two classical arguments say they must. [Cox (1946)](#references) showed that if plausibilities are real numbers, agree with ordinary logic when statements are certain, and the plausibility of "$A$ and $B$" depends only on that of $A$ and that of $B$ given $A$, then some monotone rescaling of them satisfies the product and sum rules. [De Finetti (1937)](#references) argued through bets. Suppose someone prices a bet that pays 1 if $A$ happens at 0.6, and a bet that pays 1 if $A$ does not happen also at 0.6, so that their beliefs sum to 1.2. A bookmaker sells them both bets for 1.2, and exactly one bet pays 1: a sure loss of 0.2, whatever happens. Prices that cannot be exploited in this way, a "Dutch book", are exactly those that obey the axioms of probability.

## Baseline: fit one value, then plug it in

The working method of the Machine Learning course has two steps. Find the [maximum likelihood estimate](/notes/probability/maximum-likelihood#maximizing-it), or the MAP estimate when a penalty is added,

$$
\hat\theta_{\text{ML}} = \arg\max_\theta\, p(X \mid \theta), \qquad \hat\theta_{\text{MAP}} = \arg\max_\theta\, p(X \mid \theta)\, p(\theta),
$$

then answer every question with the fitted model: the probability of a new observation is $p(x_* \mid \hat\theta)$, a prediction for a new input is $p(t_* \mid x_*, \hat w)$.

Take a problem from [MacKay (2003)](#references), Section 2.3. Eleven urns are labelled $u = 0, 1, \dots, 10$; urn $u$ holds $u$ black balls and $10 - u$ white ones. Someone picks an urn at random, draws $N = 10$ balls with replacement and sees $n_B = 3$ black ones. The likelihood of urn $u$ is $f_u^{3} (1 - f_u)^{7}$, where $f_u = u/10$ is its fraction of black balls, and it is largest at $u = 3$. The plug-in answer to "what is the probability that the next ball is black?" is $f_3 = 0.3$.

That answer ignores that urns 2 and 4 explain the same data almost as well. With only three draws, all white, the defect becomes an error: maximum likelihood picks urn 0 and states that a black ball is impossible.

## Bayesian reasoning with numbers

### Which urn?

Each urn has prior probability $1/11$. Bayes' formula over the eleven hypotheses gives

$$
p(u \mid n_B, N) = \frac{f_u^{\,n_B} (1 - f_u)^{N - n_B} \cdot \frac{1}{11}}{\sum_{v=0}^{10} f_v^{\,n_B} (1 - f_v)^{N - n_B} \cdot \frac{1}{11}} .
$$

For $n_B = 3$ in $N = 10$ the posterior probabilities of urns 1 to 8 are $0.063, 0.221, 0.293, 0.236, 0.129, 0.047, 0.010, 0.001$, and urns 0, 9 and 10 are ruled out or nearly so. Urn 3 is the most probable, but it holds less than a third of the posterior mass. The probability that the next ball is black averages the fraction $f_u$ over this posterior, by the [law of total probability](/notes/probability/conditional-probability-and-bayes#the-law-of-total-probability):

$$
p(\text{black} \mid n_B = 3, N = 10) = \sum_{u=0}^{10} f_u\, p(u \mid n_B, N) = 0.333 ,
$$

the value MacKay reports, against $0.3$ for the plug-in. The Bayesian answer is larger because the posterior is skewed: urns with more black balls than 3 keep more mass than urns with fewer.

### A coin with an unknown bias

Replace the eleven urns by a continuum: a coin whose probability of heads $f$ can be any number in $[0, 1]$, with a uniform prior. The posterior after $n_B$ heads in $N$ flips is $\mathrm{Beta}(1 + n_B,\ 1 + N - n_B)$, the conjugate update derived in the [Bayesian inference note](/notes/probability/bayesian-inference#conjugate-priors-the-beta-binomial). For 3 heads in 10 it is $\mathrm{Beta}(4, 8)$, and the probability of heads on the next flip is its mean, $4/12 = 0.333$, Laplace's rule $(n_B + 1)/(N + 2)$. The urns were a grid of eleven values of $f$, and the grid already gives the continuous answer to three digits.

For three white balls in three draws, the urn posterior is $0.331, 0.241, 0.169, 0.113, \dots$ for $u = 0, 1, 2, 3, \dots$, and the probability that the next ball is black is $0.163$: small, but not zero. A model that predicted 0 and then saw a black ball would pay an infinite log loss; the predictive pays $-\ln 0.163 = 1.82$ nats.

### Sequential updating

Data that arrive in batches can be processed one batch at a time. If the batches $X_1$ and $X_2$ are independent given $\theta$, then $p(X_1, X_2 \mid \theta) = p(X_1 \mid \theta)\, p(X_2 \mid \theta)$, and

$$
p(\theta \mid X_1, X_2) \propto p(X_2 \mid \theta)\, p(X_1 \mid \theta)\, p(\theta) \propto p(X_2 \mid \theta)\, p(\theta \mid X_1) .
$$

The posterior after the first batch is the prior for the second, and the result does not depend on how the data were split or in which order the batches came. The Code section updates the urn posterior one ball at a time and recovers the batch answer to $10^{-12}$. This is what makes Bayesian learning natural for streaming data, and it is the idea that [stochastic variational inference](/notes/bayesian-methods/stochastic-variational-inference) scales to millions of documents.

## Prior, likelihood, posterior and predictive

The general scheme has four objects. The prior $p(\theta)$ states what is believed before the data. The likelihood $p(X \mid \theta)$ states how the data are generated for each value of the parameter. Bayes' formula combines them into the posterior,

$$
p(\theta \mid X) = \frac{p(X \mid \theta)\, p(\theta)}{p(X)}, \qquad p(X) = \int p(X \mid \theta)\, p(\theta)\, d\theta .
$$

The answer to a question about new data is the **predictive distribution**, the model's predictions averaged over the posterior:

$$
p(x_* \mid X) = \int p(x_* \mid \theta)\, p(\theta \mid X)\, d\theta .
$$

For a supervised model, the likelihood is that of the targets given the inputs, $p(T \mid X, w) = \prod_i p(t_i \mid x_i, w)$, the posterior is over the weights, and the prediction for a new input $x_*$ is

$$
p(t_* \mid x_*, X, T) = \int p(t_* \mid x_*, w)\, p(w \mid X, T)\, dw ,
$$

a vote of all the models the weights describe, each weighted by its posterior probability. Every step after writing the model is an integral. The evidence $p(X)$ normalizes the posterior; it does not change its shape, and it is the quantity by which [whole models are compared](/notes/bayesian-methods/bayesian-model-selection). For a few prior–likelihood pairs, the [conjugate pairs](/notes/bayesian-methods/conjugate-priors), these integrals have closed forms. For the rest, the course builds approximations.

<aside class="callout"><strong>Key idea.</strong> In the Bayesian approach, learning is conditioning. Every unknown gets a distribution, the data enter only through the likelihood, and every answer, a parameter estimate, a prediction or a choice between models, is read from the posterior by an integral rather than from a single fitted value.</aside>

## What a point estimate throws away

A point estimate replaces the posterior by a spike at one value, $p(\theta \mid X) \approx \delta(\theta - \hat\theta)$, and the predictive becomes the plug-in, $\int p(x_* \mid \theta)\, \delta(\theta - \hat\theta)\, d\theta = p(x_* \mid \hat\theta)$. The approximation is good when the posterior is a narrow peak, which is the large-sample regime of the [Bernstein–von Mises theorem](/notes/probability/bayesian-inference#priors-and-large-samples). Away from it, five things are lost.

- **Uncertainty.** After three white draws, ML and MAP with the uniform prior both pick urn 0 and predict black with probability 0; the predictive says $0.163$. A point estimate cannot say how much the data constrained the parameter.
- **Width of predictions.** The predictive is a mixture of the models' predictions and is wider than any one of them. For a normal mean, its variance is the noise variance plus the posterior variance of the mean ([Bayesian inference note](/notes/probability/bayesian-inference#predicting-with-the-posterior)); a plug-in keeps only the first.
- **Which summary.** The best single number depends on the loss it will be judged by: the posterior mean minimizes the expected squared error, the median the expected absolute error, and the mode is the limit for a 0–1 loss. After three white draws, the mode, median and mean of the fraction $f_u$ are $0$, $0.1$ and $0.163$: three different answers from one posterior. The MAP estimate also changes under a reparametrization of $\theta$, while the posterior does not ([Bayesian inference note](/notes/probability/bayesian-inference#map-estimation-and-regularization)).
- **Several explanations.** A posterior with several modes, such as that of a mixture whose components can be relabelled, is represented by one of them.
- **A way to compare models.** The best-fit likelihood $p(X \mid \hat\theta)$ never decreases as a model grows, so it always prefers the largest model. The evidence, an integral over all parameter values, does not, as the [model selection note](/notes/bayesian-methods/bayesian-model-selection) shows.

MAP estimation is still the workhorse of practice, and [ridge regression and weight decay are MAP estimates](/notes/ml/regularization#the-bayesian-reading). The Bayesian approach does not forbid them. It says what they approximate, so that we know when the approximation is safe.

## A model is a graph of standard blocks

Realistic models have many unknowns: parameters, hyperparameters that control the priors, and latent variables, one per observation, such as the cluster of a point in a [Gaussian mixture](/notes/ml/em-algorithm#the-gaussian-mixture-model). Writing their joint distribution directly is hopeless. A **Bayesian network**, or directed graphical model, writes it as a product of small conditional distributions, one per variable given its parents in a directed acyclic graph:

$$
p(v_1, \dots, v_m) = \prod_{j=1}^m p(v_j \mid \mathrm{pa}(v_j)) .
$$

Each factor is a standard block: a Bernoulli or categorical choice, a Gaussian whose mean is a linear function of its parents, a gamma distribution for a precision, a beta or Dirichlet distribution for probabilities. A repeated block, such as $n$ observations that share a parameter, is drawn once inside a box, a **plate**, with $n$ in its corner. Observed variables are shaded. Inference is always the same operation: condition on the shaded variables and marginalize the ones that are not asked about,

$$
p(\text{query} \mid \text{observed}) = \frac{\sum_{\text{rest}} p(\text{query}, \text{rest}, \text{observed})}{\sum_{\text{query}, \text{rest}} p(\text{query}, \text{rest}, \text{observed})} ,
$$

with sums replaced by integrals for continuous variables. Parameters are just more unobserved nodes, which is why the Bayesian approach needs no separate theory for them.

### Explaining away: a worked example

A house has a burglar alarm, a variant of the example of [Pearl (1988)](#references). A burglary $B$ and an earthquake $E$ happen independently, with $P(B = 1) = 0.01$ and $P(E = 1) = 0.02$; either can set off the alarm $A$; the radio $R$ reports earthquakes. The graph has arrows $B \to A$, $E \to A$ and $E \to R$, and the joint distribution is $p(b)\, p(e)\, p(a \mid b, e)\, p(r \mid e)$ with these tables:

| | $b = 0, e = 0$ | $b = 0, e = 1$ | $b = 1, e = 0$ | $b = 1, e = 1$ |
| --- | --- | --- | --- | --- |
| $P(A = 1 \mid b, e)$ | $0.001$ | $0.3$ | $0.9$ | $0.95$ |

and $P(R = 1 \mid E = 1) = 0.8$, $P(R = 1 \mid E = 0) = 0.001$.

<AlarmNetwork />

1. **No evidence.** The beliefs are the priors: $P(B = 1) = 0.010$, $P(E = 1) = 0.020$.
2. **The alarm rings.** Marginalizing the earthquake, $P(A = 1 \mid B = 1) = 0.98 \cdot 0.9 + 0.02 \cdot 0.95 = 0.901$ and $P(A = 1 \mid B = 0) = 0.98 \cdot 0.001 + 0.02 \cdot 0.3 = 0.00698$. Bayes' formula gives
$$
P(B = 1 \mid A = 1) = \frac{0.901 \cdot 0.01}{0.901 \cdot 0.01 + 0.00698 \cdot 0.99} = \frac{0.00901}{0.01592} = 0.566 ,
$$
and in the same way $P(E = 1 \mid A = 1) = 0.385$. A rare event becomes the likelier explanation.
3. **The radio reports an earthquake.** Now $P(E = 1 \mid A = 1, R = 1) = 0.998$, and the burglary falls back to $P(B = 1 \mid A = 1, R = 1) = 0.033$. The earthquake explains the alarm, and the evidence for a burglary is **explained away**.

Step 3 shows something the graph makes visible. $B$ and $E$ are independent a priori: knowing that there was an earthquake leaves $P(B = 1 \mid E = 1) = 0.01$. Once their common effect $A$ is observed they become dependent, and learning about $E$ changes the belief in $B$: $P(B = 1 \mid E = 1, A = 1) = 0.031$. The same pattern, independent causes made dependent by an observed effect, is why the posterior over the weights of a regression is correlated even when their prior is independent, and why the latent variables of most models in this course have no simple joint posterior.

### The models of this course as compositions

Every model of the course is a composition of the same few blocks, and the inference method follows from the composition:

| Model | Blocks | Posterior |
| --- | --- | --- |
| Beta–Bernoulli, normal–gamma | a conjugate prior and its likelihood | exact, closed form |
| Bayesian linear regression | Gaussian prior on $w$, linear-Gaussian likelihood | exact Gaussian |
| Relevance vector machine | the same with a gamma hyperprior per weight | evidence maximization |

## The plan of the course

The course follows one question through five sections: how to compute the posterior, and what to do when it cannot be computed exactly. The scope and order follow the course of [Vetrov and Kropotov (2015)](#references) at Moscow State University.

1. **Bayesian Modelling.** This note; [conjugate priors and the exponential family](/notes/bayesian-methods/conjugate-priors), the cases in which the posterior and the evidence have closed forms; and [Bayesian model selection](/notes/bayesian-methods/bayesian-model-selection), which compares models by their evidence and fits hyperparameters by maximizing it.
2. **Bayesian Linear Models.** [Bayesian linear regression](/notes/bayesian-methods/bayesian-linear-regression) with its Gaussian posterior and predictive; the [relevance vector machine](/notes/bayesian-methods/relevance-vector-machine), whose per-weight priors switch features off; and the [Laplace approximation](/notes/bayesian-methods/laplace-approximation), the first approximate posterior, for classification.
3. **Latent Variables and Approximate Inference.** [EM and Bayesian PCA](/notes/bayesian-methods/em-and-bayesian-pca), [variational inference](/notes/bayesian-methods/variational-inference) with its evidence lower bound, and [Gibbs sampling](/notes/bayesian-methods/gibbs-sampling): the three general methods for models whose posterior has no formula.
4. **Nonparametric Models.** [Gaussian processes](/notes/bayesian-methods/gaussian-processes), priors over functions; [Dirichlet processes](/notes/bayesian-methods/dirichlet-processes), mixtures with an unbounded number of components; and [latent Dirichlet allocation](/notes/bayesian-methods/latent-dirichlet-allocation), the topic model that combines the blocks of the first sections.
5. **Scalable Inference.** [Stochastic variational inference](/notes/bayesian-methods/stochastic-variational-inference) for large datasets, [black-box variational inference and the VAE](/notes/bayesian-methods/black-box-variational-inference) for models without conjugacy, and [Bayesian deep learning](/notes/bayesian-methods/bayesian-deep-learning), which asks what a posterior over the weights of a network adds.

The course assumes the [Bayesian inference](/notes/probability/bayesian-inference), [multivariate Gaussian](/notes/probability/multivariate-gaussian) and [Markov chain Monte Carlo](/notes/probability/markov-chain-monte-carlo) notes of the probability course and the linear models and [EM algorithm](/notes/ml/em-algorithm) of the Machine Learning course. Its last section leads into the variational and sampling methods of the Generative Models course, starting from the [variational autoencoder](/notes/generative-models/vae).

## What changed

| | Fit and plug in | The Bayesian approach |
| --- | --- | --- |
| Parameter | one value $\hat\theta$ | a distribution $p(\theta \mid X)$ |
| Prediction | $p(x_* \mid \hat\theta)$ | $\int p(x_* \mid \theta)\, p(\theta \mid X)\, d\theta$ |
| Urn, 3 black in 10 | next black: $0.3$ | $0.333$ |
| Urn, 3 white in 3 | next black: $0$ | $0.163$ |
| Prior knowledge | a penalty added by hand | the prior $p(\theta)$ |
| New data | refit | the posterior becomes the prior |
| Comparing models | validation | the evidence $p(X)$, or validation |
| Main difficulty | optimization | integration |

## Limitations

- **The prior must be chosen.** For small data it shapes the answer, and two analysts with different priors get different posteriors. Its choice has to be stated and its influence checked; the [model selection note](/notes/bayesian-methods/bayesian-model-selection) shows that the evidence is even more sensitive to it than the posterior.
- **The integrals are hard.** Exact posteriors exist only for conjugate pairs and linear-Gaussian models. Everything else in the course is an approximation with its own failure modes.
- **The model can be wrong.** Bayes' formula is coherent given the model. If the likelihood misdescribes the data, the posterior concentrates confidently on the least wrong parameter, as maximum likelihood does.
- **Computation scales poorly.** Enumeration, as in the alarm example, costs a number of terms exponential in the number of variables; graphs with many unobserved nodes need the approximate methods of the third and fifth sections.

## What you should remember

- Frequentist: a probability is a frequency and a parameter is a fixed constant. Bayesian: a probability is a degree of belief and every unknown, parameters included, gets a distribution.
- Posterior ∝ likelihood × prior; the evidence $p(X)$ normalizes it and compares models.
- Predict by averaging over the posterior, $p(x_* \mid X) = \int p(x_* \mid \theta)\, p(\theta \mid X)\, d\theta$, not by plugging in $\hat\theta$; in the urn problem, $0.333$ instead of $0.3$, and $0.163$ instead of $0$.
- For independent batches, the posterior after one batch is the prior for the next.
- ML and MAP replace the posterior by a spike: they lose its width, its shape, its other modes and the evidence; they are safe when the posterior is a narrow peak.
- A Bayesian network writes the joint distribution as a product of standard blocks, one per variable given its parents; inference conditions on the observed nodes and marginalizes the rest.
- Independent causes become dependent once their common effect is observed: explaining away.

## Code

The urn posterior and its predictive, the continuous coin, the three point estimates after three white draws, sequential updating, and the burglar alarm by enumeration. The script runs in about a second; exact numbers can differ in the last digit across platforms and library versions.

```python
import numpy as np
from itertools import product
from scipy import stats

# Which urn? Urn u holds u black and 10 - u white balls; an urn is picked uniformly, balls are drawn with replacement
u = np.arange(11)
f = u / 10                                      # the fraction of black balls in urn u
def urn_posterior(n_black, n_draws, prior=np.full(11, 1 / 11)):
    lik = f ** n_black * (1 - f) ** (n_draws - n_black)
    return lik * prior / (lik * prior).sum()    # Bayes' formula over the 11 hypotheses

post = urn_posterior(3, 10)
print(post.round(3))                            # [0.    0.063 0.221 0.293 0.236 0.129 0.047 0.01  0.001 0.    0.   ]
print(round(post @ f, 3), f[post.argmax()])     # 0.333 0.3: the predictive against the plug-in of the best urn

# the same question with a continuous bias and a uniform prior: Beta(1 + 3, 1 + 7)
print(round(stats.beta(4, 8).mean(), 3))        # 0.333

# three white balls in three draws: the point estimates say "never black"
post = urn_posterior(0, 3)
cdf = post.cumsum()
print(post[:4].round(3), f[post.argmax()], f[np.searchsorted(cdf, 0.5)], round(post @ f, 4))
# [0.331 0.241 0.169 0.113] 0.0 0.1 0.1625: posterior mode, median and mean of the fraction of black balls
print(round(-np.log(post @ f), 2))              # 1.82: the log loss of the predictive if the next ball is black

# sequential updating: one ball at a time gives the batch posterior
draws = [1, 0, 0, 1, 0, 0, 0, 1, 0, 0]          # 3 black in 10
p = np.full(11, 1 / 11)
for d in draws:
    p = urn_posterior(d, 1, prior=p)
print(np.abs(p - urn_posterior(3, 10)).max() < 1e-12)   # True

# the burglar alarm by enumeration of the joint distribution p(b) p(e) p(a | b, e) p(r | e)
pB, pE = 0.01, 0.02
pA = {(0, 0): 0.001, (0, 1): 0.3, (1, 0): 0.9, (1, 1): 0.95}   # P(a = 1 | b, e)
pR = {0: 0.001, 1: 0.8}                                        # P(r = 1 | e)
def joint(b, e, a, r):
    return ((pB if b else 1 - pB) * (pE if e else 1 - pE)
            * (pA[b, e] if a else 1 - pA[b, e]) * (pR[e] if r else 1 - pR[e]))
def prob(query, evidence):
    states = [dict(zip('bear', s)) for s in product((0, 1), repeat=4)]
    match = lambda s, c: all(s[k] == v for k, v in c.items())
    den = sum(joint(**s) for s in states if match(s, evidence))
    return sum(joint(**s) for s in states if match(s, evidence) and match(s, query)) / den

print(round(prob({'b': 1}, {}), 3), round(prob({'b': 1}, {'a': 1}), 3), round(prob({'b': 1}, {'a': 1, 'r': 1}), 3))
# 0.01 0.566 0.033: the alarm raises the belief in a burglary, the radio report explains it away
print(round(prob({'e': 1}, {'a': 1}), 3), round(prob({'e': 1}, {'a': 1, 'r': 1}), 3))   # 0.385 0.998
print(round(prob({'b': 1}, {'e': 1}), 3), round(prob({'b': 1}, {'e': 1, 'a': 1}), 3))   # 0.01 0.031: independent until the alarm is observed
```

## Next

Every Bayesian answer in this note was a sum over eleven urns or sixteen states of the alarm. With continuous parameters the sums become integrals, and the integral in the denominator of Bayes' formula usually has no formula. The [next note](/notes/bayesian-methods/conjugate-priors) finds the cases in which it does: priors that, combined with their likelihood, give a posterior of the same family, so that learning reduces to adding counts. They exist for every member of the exponential family, which includes almost all the standard blocks of this note.
