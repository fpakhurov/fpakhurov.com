## Отправная точка: обучение на сыром веб-обходе \{#baseline-train-on-the-raw-crawl\}

[Расчёт масштабирования](/ru/notes/nlp/scaling-laws/) рассматривал обработанный обучающий токен как единицу бюджета. Веб-коллекция приходит в другом виде. Статья может быть смешана с навигацией, повторять другую страницу, содержать ответ из оценочного набора или не иметь подтверждённого разрешения для нужного использования. Если считать всё одинаково, останутся незаметными решения, меняющие обучение и оценку.

Рабочая коллекция здесь состоит из пяти коротких документов, написанных для заметки. Это не выборка из веб-обхода и не замена репрезентативному языковому корпусу:

| ID | Исходный текст |
| --- | --- |
| d1 | Keep the amber crate beside the gate. |
| d2 | KEEP  the amber crate beside the gate! |
| d3 | Keep the amber crate beside the wall. |
| d4 | Move the blue box beside the gate. |
| d5 | The lamp is stored inside bay seven. |

Небольшие различия позволяют точно проверить нормализацию, поиск дубликатов и пересечений. Для запуска примера не нужен сторонний датасет.

## Конвейер от веб-обхода к батчам \{#the-pipeline-from-crawl-to-batches\}

Воспроизводимому конвейеру сначала нужен реестр, затем число токенов. Для каждого входа сохраните источник, ревизию или дату сбора, предполагаемое использование и решение о правах. Исходный идентификатор должен пережить извлечение и фильтрацию; далее фиксируются версии преобразований, причины исключения, группы дубликатов, назначение в выборку и вес в смеси.

Один полезный порядок: отобрать разрешённые источники; извлечь текст; проверить язык и качество; объединить дубликаты в группы; отложить оценочные материалы и проверить пересечения; собрать обучающую смесь; токенизировать и упаковать. Проверка приватности и запросы на удаление могут потребовать возврата к ранним стадиям. Это схема планирования для примера, а не утверждение об устройстве любого корпуса.

Права и техническое качество — отдельные решения. Чистый документ без повторов всё ещё может не подходить для использования. Лицензия программы сбора сама по себе не разрешает использование обрабатываемых ею документов. Здесь все примеры остаются в пределах новой самостоятельно составленной коллекции.

## Извлечение: от HTML к тексту \{#extraction-from-html-to-text\}

Извлечение текста определяет, какие символы попадут в обучающие наблюдения. Рассмотрим самостоятельно составленный фрагмент:

```html
<nav>Library</nav><p>Store <b>amber</b> crates.</p><script>secret()</script>
```

Небольшой парсер на стандартной библиотеке в сопутствующем расчёте собирает текстовые узлы, добавляет пробелы на границах абзацев и исключает содержимое `script` и `style`. Результат — `Library Store amber crates.` Статью он не выделил: навигация осталась. Удаление тегов и извлечение основного содержимого — разные операции.

Парсер не исполняет JavaScript. Это демонстрация для данного корректного фрагмента, а не универсальный браузерный движок, санитайзер или промышленный экстрактор. Изображения, таблицы, повреждённая разметка и зависящий от вёрстки порядок чтения требуют дополнительных решений. Сохраняйте границы документов и метаданные источников, достаточные для последующей проверки ошибок извлечения.

## Определение языка и фильтрация по качеству \{#language-identification-and-quality-filtering\}

Детектор языка выдаёт предсказание, а не гарантию. Для коротких текстов, смешанных языков и кода одна метка документа особенно груба. Оценка качества тоже отражает выбранную цель: фильтрация по сходству с эталонной коллекцией может исключить полезные тексты другого стиля.

Dodge et al. (§2 и §5–§6) исследуют влияние фильтров C4 на оставшиеся и исключённые материалы. В частности, словарный список блокировки удалял часть неоскорбительных текстов и по-разному затрагивал языковые варианты. Примеры и фильтры этого корпуса сюда не перенесены.

В реальном конвейере проверяйте образцы принятых и исключённых документов по языку, длине и источнику, показывайте доли сохранения. Наши пять документов не позволяют измерить эти эффекты. Даже их нормализация намеренно узкая: приведение к нижнему регистру и выделение слов `[a-z]+` подходит данным английским строкам, но удалит кириллицу и значимые цифры. Это нельзя превращать в правило многоязычной предобработки.

## Дедупликация \{#deduplication\}

Для точного сопоставления сначала нужно определить равенство. Исходные d1 и d2 различаются; после нашей нормализации оба становятся `keep the amber crate beside the gate`. Хеширование этой строки даёт одинаковый SHA-256. Храните версию нормализации вместе с хешем, а при разборе совпадения сравнивайте нормализованное содержимое. Дайджест удобен для поиска, но не доказывает авторство или смысловую идентичность.

Поиск почти-дубликатов отвечает на другой вопрос. Представим документ множеством соседних пар слов, то есть биграмм. Повторные вхождения учитываются в множестве один раз. Для d1 шесть элементов — `keep the`, `the amber`, `amber crate`, `crate beside`, `beside the` и `the gate`. В d3 последняя пара заменена на `the wall`. Для множеств $A$ и $B$ сходство Жаккара равно

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|}=\frac{5}{7}.
$$

Значение велико, хотя описанное местоположение изменилось. Порог вроде $0.7$ объединил бы две инструкции. Сохранять ли обе, зависит от приложения: текстовое пересечение не равно смысловой эквивалентности. Короткие шинглы также дают много случайных совпадений. Lee et al. (§4) разделяют точное сопоставление подстрок и приближённое сопоставление документов; они находят разные виды повторов.

MinHash оценивает пересечение множеств без хранения каждого попарного пересечения. В идеальной конструкции выберем равномерный случайный порядок элементов объединения и сохраним самый ранний элемент каждого непустого множества. Два представителя совпадают тогда и только тогда, когда первый элемент объединения находится в пересечении. Каждый элемент объединения имеет одинаковый шанс оказаться первым, поэтому

$$
\Pr[h(A)=h(B)]=\frac{|A\cap B|}{|A\cup B|}.
$$

Для объединения из семи элементов существует $7!=5040$ порядков. Полный перебор даёт 3600 совпадений, и $3600/5040=5/7$. Это проверка тождества на придуманной паре, а не масштабируемая реализация. Усреднение индикаторов совпадения по независимым порядкам оценивает сходство Жаккара. Li и Li (§1.1) приводят этот классический оцениватель; их новая циркулянтная конструкция здесь не рассматривается.

Реальные реализации заменяют идеальные порядки конкретными схемами хеширования и поиска кандидатов. Длина сигнатуры и пороги отбора влияют на ошибку; одно совпадение сигнатуры не подтверждает дубликат. Для пустых множеств нужно отдельное соглашение. Наш код присваивает двум пустым множествам шинглов сходство один, но такие документы следует обрабатывать отдельно до дедупликации корпуса.

## Очистка от оценочных наборов \{#decontamination-against-evaluation-sets\}

Повторы внутри обучения повышают вес отдельных текстов. Пересечение обучения с оценкой угрожает другому утверждению: насколько хорошо модель работает с ещё не встречавшимся материалом. Dodge et al. (§4.2) различают пересечение входов задачи и пересечение, включающее целевые метки или ответы. Проверять нужно оба случая, но степень раскрытия информации у них разная.

Возьмём придуманный оценочный вопрос `Where is the amber crate beside the wall?` Его множество биграмм имеет пять общих пар с d3: `the amber`, `amber crate`, `crate beside`, `beside the` и `the wall`. Лексическое правило может отметить эту связь, но не доказывает запоминание ответа моделью и не обнаруживает любой пересказ.

До обучения распределяйте по выборкам целые группы дубликатов и проверяйте отложенные примеры против окончательной обучающей коллекции. Сохраняйте свидетельства совпадения и принятое решение. Нельзя подобрать пороги удаления по финальной тестовой оценке и затем считать этот тест независимым. Отсутствие лексических совпадений — ограниченное свидетельство для данного правила, а не подтверждение отсутствия всей оценочной информации.

## Безопасность и персональные данные \{#safety-and-personal-data\}

Чувствительная информация встречается и в технически корректном тексте. Поиск шаблонов обнаруживает некоторые форматы, но ошибочно срабатывает и пропускает раскрытие, понятное только из контекста. Оценка токсичности не определяет, является ли фрагмент цитатой, критикой или инструкцией. Приватность, пригодность содержимого и разрешение источника требуют отдельных решений.

Для реальной коллекции определите, что можно хранить, кто имеет право это просматривать и как удалить документ из будущих версий. Не публикуйте исходные чувствительные примеры в журналах проверки. Хеш или идентификатор может поддерживать процедуру удаления без повторения текста в каждом отчёте. В пяти придуманных документах нет реальной персональной информации, поэтому пример не оценивает фильтр приватности.

## Веса смеси и эпохи \{#mixture-weights-and-epochs\}

После фильтрации веса смеси управляют частотой предъявления. Пусть в двух источниках доступно $T_1=80$ и $T_2=20$ токенов, а мы выбираем $B=200$ обучающих токенов с вероятностями источников $w_1=w_2=1/2$. Внутри каждого источника предположим равномерную выборку токенов с возвращением. Ожидаемое число предъявлений каждого токена источника $i$:

$$
e_i=\frac{Bw_i}{T_i}.
$$

Получаем $e_1=5/4$ и $e_2=5$. Равные веса источников дают вчетверо больше предъявлений на доступный токен малого источника. Это ожидаемые количества, а не гарантия одинакового числа появлений каждого токена. При равномерном выборе документов разной длины расчёт был бы другим.

Так видно и различие обработанных и уникальных токенов. Повышение веса малого источника меняет повторяемость вместе с балансом предметных областей. Записывайте единицу выборки и правила возвращения рядом с весами, иначе по одним процентам смесь не восстановить.

## Токенизация и батчи \{#tokenization-and-batches\}

Токенизация меняет длины, упаковка — совместное использование памяти и контекста. Пусть длины трёх документов равны четырём, трём и пяти, включая маркер конца. Дополнение каждого до длины пять занимает 15 позиций. Конкатенация 12 токенов в два блока ширины шесть убирает неиспользуемые позиции.

Удаление дополнения не определяет семантику внимания. Если документы остаются независимыми и сохраняют полные контексты, число разрешённых каузальных пар запрос–ключ равно

$$
\frac{4\cdot5}{2}+\frac{3\cdot4}{2}+\frac{5\cdot6}{2}=31.
$$

Два каузальных блока ширины шесть без дополнительных ограничений разрешают $2(6\cdot7/2)=42$ пары. Часть связывает разные документы; разрезание документа между блоками может убрать его прежний контекст. Один маркер конца не устанавливает границу внимания. Эти суммы описывают разные раскладки, а не эквивалентные вычисления или измеренное время.

Чтобы сохранить нужную цель на уровне документов, задайте маски границ, обработку позиций, маски целевых потерь и политику разделения документов. Независимые блоки с целыми документами могут воспроизвести их раздельные контексты; произвольная конкатенация в фиксированные окна обычно не может. Позиции дополнения не должны входить в знаменатель потерь языковой модели.

## Что изменилось \{#what-changed\}

От бюджета токенов теперь можно проследить проверяемый путь к документам и преобразованиям. Нормализация изменила равенство строк; шинглы выявили близкое совпадение; сопоставление с оценкой отметило возможную утечку; веса смеси изменили повторяемость; упаковка потребовала явной политики контекста. Каждое решение влияет на своё свойство итогового обучающего потока.

## Ограничения \{#limitations\}

Пять придуманных английских документов и корректный HTML-фрагмент устанавливают только точное поведение на этих входах. Они не проверяют многоязычное извлечение, промышленную скорость хеширования, смысловую очистку от оценочных данных, обнаружение персональной информации или качество модели. Веб-корпус не скачивается, модель не обучается. Статьи объясняют механизмы и наблюдения; доступность их датасетов не разрешает повторное использование каждого исходного документа.

## Что нужно запомнить \{#what-you-should-remember\}

Документируйте решения об источниках и преобразования до подсчёта токенов. Разделяйте точное равенство, приближённое пересечение и раскрытие оценочных данных. Проверяйте исключённые материалы вместе с сохранёнными. Указывайте единицу выборки для весов смеси и границы контекста при упаковке. Технически успешный конвейер не решает вопрос прав на источники.

## Код \{#code\}

Этот самостоятельный пример на стандартной библиотеке проверяет нормализацию, пересечение биграмм и все идеальные порядки для d1 и d3. Он ничего не загружает и использует только напечатанные выше строки.

```python
import itertools
import re
from fractions import Fraction

def words(text):
    return re.findall(r"[a-z]+", text.casefold())

def pairs(text):
    tokens = words(text)
    return set(zip(tokens, tokens[1:]))

d1 = "Keep the amber crate beside the gate."
d2 = "KEEP  the amber crate beside the gate!"
d3 = "Keep the amber crate beside the wall."
a, b = pairs(d1), pairs(d3)
match = total = 0
for order in itertools.permutations(sorted(a | b)):
    left = next(x for x in order if x in a)
    right = next(x for x in order if x in b)
    match += left == right
    total += 1
print(words(d1) == words(d2))
print(len(a & b), len(a | b), Fraction(len(a & b), len(a | b)))
print(match, total, Fraction(match, total))
```

```text
True
5 7 5/7
3600 5040 5/7
```
