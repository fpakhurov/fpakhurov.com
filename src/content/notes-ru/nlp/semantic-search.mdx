Поисковая система получает вопрос и возвращает документы, которые могут на него ответить. Прежде чем добавлять языковую модель, которая напишет ответ, проверим меньшую задачу: попал ли в выдачу документ с нужной информацией?

Для этого создан **BIASED Retrieval Lab**: 14 вымышленных документов справки и 10 запросов на русском и английском. Тексты, запросы и разметка релевантности подготовлены для этого примера с помощью ИИ. Они описывают придуманное учебное пространство; его правила не являются условиями или возможностями BIASED School.

## Корпус и разметка релевантности

У каждого документа постоянный идентификатор. Для каждого запроса указаны идентификаторы подходящих документов. Например:

| ID | Текст или задача |
| --- | --- |
| `d14` | Ошибка R17 означает, что папка для результата доступна только для чтения. Нужно сохранить результат в персональную папку и повторить команду. |
| `q01` | `Ошибка R17 папка результата`; подходящий документ: `d14`. |
| `d05` | Урок можно скачать перед поездкой. Его текст доступен без сети, а для отправки ответов нужно подключиться снова. |
| `q08` | `Заниматься в самолёте`; подходящий документ: `d05`. |

Первый запрос повторяет характерные слова из ответа. Второй описывает потребность другими словами. Это специально придуманные учебные случаи, а не выборка реальных пользовательских запросов.

Скачайте [датасет](/data/biased-retrieval-lab-v1/dataset.json), [описание происхождения и метода](/data/biased-retrieval-lab-v1/README.md) и [условия использования](/data/biased-retrieval-lab-v1/LICENSE). В исходных файлах находятся полные тексты на двух языках и разметка.

## Воспроизводимая лексическая базовая линия

BM25 ранжирует документы по совпадениям слов запроса. Слово, встречающееся в меньшем числе документов, вносит больший вклад; повторения дают убывающую прибавку; длина документа корректирует оценку. Для запроса $q$ и документа $d$ реализация использует

$$
S(q,d)=\sum_{t\in\operatorname{unique}(q)}
\log\left(1+\frac{N-n_t+0.5}{n_t+0.5}\right)
\frac{f_{t,d}(k_1+1)}{f_{t,d}+k_1(1-b+b|d|/\overline L)}.
$$

Здесь $N$ — число документов, $n_t$ — число документов со словом $t$, $f_{t,d}$ — число его вхождений в $d$, а $\overline L$ — средняя длина документа. Берём $k_1=1.2$ и $b=0.75$. Семейство этих оценок описано у [Робертсона и Сарагосы](#references).

Скрипт переводит текст в нижний регистр и выделяет слова Unicode, без стемминга и удаления стоп-слов. Он оценивает все документы, возвращает только положительные оценки, а равенства разрешает по ID документа. Эти решения — часть эксперимента: документ с нулевой оценкой не появится от простого увеличения размера выдачи.

## Проверяем идентификаторы в выдаче

Пусть $r_i$ — позиция первого подходящего документа для запроса $i$. Если подходящего документа нет, вклад этого запроса равен нулю. Для $Q$ запросов

$$
\operatorname{Hit@}k=\frac{1}{Q}\sum_{i=1}^{Q}\mathbf{1}[r_i\leq k],
\qquad
\operatorname{MRR}=\frac{1}{Q}\sum_{i=1}^{Q}\frac{1}{r_i}.
$$

Во второй сумме отсутствие подходящего документа означает обратный ранг, равный нулю. Релевантность проверяется по точному ID. Оценка не пытается угадать правильный ответ по похожести фрагментов текста.

Сохранённый запуск даёт одинаковые итоговые метрики для обоих языков:

| Случаи | Запросы | Первый подходящий документ |
| --- | --- | --- |
| Совпадения слов и случай с отвлекающим документом | `q01`–`q06`, `q09`, `q10` | На первом месте |
| Несовпадение слов | `q07`, `q08` | Не найден |
| Итог | Все 10 | Hit@1 = Hit@3 = MRR = 0.8 |

Английский запрос про самолёт не имеет совпадающих слов и не возвращает кандидатов. Русский вариант находит посторонние документы с общим предлогом, но всё равно пропускает `d05`. Разбор ошибок говорит больше итогового среднего: у нужного текста нет лексических совпадений при выбранной токенизации.

[Сохранённые результаты](/data/biased-retrieval-lab-v1/results.json) содержат ранги по запросам, оценки первых трёх документов, настройки метода и хеш байтов датасета.

## Зачем нужны эмбеддинги

Обученный энкодер превращает текст в вектор. Обучение может сблизить связанные смыслы, даже когда слова различаются. Поиск с двумя энкодерами заранее вычисляет векторы документов и сравнивает с ними вектор запроса; связанные подходы описаны в [Sentence-BERT](#references) и [DPR](#references).

Только для иллюстрации арифметики выберем вектор запроса $q=(1,0)$, вектор документа о чтении офлайн $u=(0.8,0.6)$ и вектор документа о лимите загрузки $v=(0,1)$. Длина каждого вектора равна единице, поэтому косинусное сходство равно скалярному произведению:

$$
\cos(q,u)=0.8,\qquad\cos(q,v)=0.
$$

Координаты выбраны вручную и не являются выходом модели. Они объясняют, как векторное ранжирование могло бы поставить чтение офлайн первым; они не доказывают, что обученная модель сделает именно это. Нейросетевой поиск в этом примере не запускался.

Следующий эксперимент должен сохранить те же ID документов и разметку, запустить явно указанную модель эмбеддингов и сравнить каждое изменение ранга с лексической базовой линией. На большом корпусе сначала отбирают кандидатов, а затем можно оценить каждую пару «запрос — документ» более дорогой совместной моделью. Улучшение от этих шагов нужно измерять.

## Запускаем и меняем эксперимент

Сохраните [скрипт](/data/biased-retrieval-lab-v1/retrieval-example.py) рядом с `dataset.json` и выполните:

```sh
python3 retrieval-example.py --dataset dataset.json --output results.json
```

Достаточно стандартной библиотеки Python. Внешние данные, загрузка моделей и платные сервисы не нужны. Тот же эксперимент есть в [самодостаточном ноутбуке с данными и сохранёнными выводами](/data/biased-retrieval-lab-v1/nlp-retrieval-lab.ipynb).

Сначала измените один запрос, сохранив ID подходящего документа. Предскажите совпадения слов, запустите скрипт и проверьте ранг именно этого запроса. Затем добавьте посторонний документ, который повторяет слово запроса: высокая лексическая оценка ещё не доказывает наличие ответа.

## Ограничения

Десять запросов написаны вместе с корпусом для демонстрации конкретных ошибок. Это не отложенный бенчмарк, а 0.8 не оценивает качество на реальных пользователях. Один запрос меняет Hit@k на 0.1. У двух языков разные совпадения слов: одинаковые итоговые метрики не означают одинаковую выдачу. Нейросетевой поиск, переранжирование и генерация ответов здесь не измерены.

Для подробного разбора арифметики пригодятся [векторы и линейные отображения](/ru/notes/math/vectors-and-linear-maps), для расширения скрипта — [функции Python](/ru/notes/python/functions). Полезная привычка — хранить рядом документы, разметку, настройки ранжирования и наблюдаемые результаты.
