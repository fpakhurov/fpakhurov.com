[Предыдущая заметка](/ru/notes/python/lists-and-tuples) закончилась на ограничении списка: он находит элемент по позиции за постоянное время, но поиск элемента по значению, `x in xs`, сравнивает с элементами по одному. Счётчик слов, который для каждого из миллиона слов спрашивает «встречалось ли мне это слово?», провёл бы всю жизнь в поиске. Эта заметка вводит структуру данных, которая отвечает на такие вопросы в среднем за постоянное время, — **хеш-таблицу** (hash table) — и два её облика в Python: **словарь** (dictionary), `dict`, который сопоставляет ключам значения, и **множество** (set), которое хранит одни ключи. Она показывает, как CPython раскладывает словарь в памяти, как находится ключ, когда таблица растёт, почему ключами могут быть не все объекты и что происходит, когда средние оценки не работают.

**Обозначения.** $n$ — число ключей в таблице, $m$ — число ячеек в её массиве индексов, в CPython всегда степень двойки. **Коэффициент заполнения** (load factor) — это $\alpha = n/m$, доля занятых ячеек. `hash(k)` — хеш ключа `k`, целое число, а `&` — побитовое И: при $m = 2^b$ выражение `h & (m - 1)` оставляет младшие $b$ битов `h`, то есть равно `h % m` при $h \ge 0$.

## Отправная точка: список пар \{#baseline-a-list-of-pairs\}

Словарь мог бы быть списком пар `(key, value)`. Поиск ключа означает проход по списку со сравнением каждого ключа через `==`, пока какой-то не совпадёт: $O(n)$ на поиск. На этой машине (CPython 3.14.7, Apple M1) проверка, есть ли в списке последнее из $10^5$ целых чисел, занимает около 790 000 нс; та же проверка для множества занимает 34 нс и всё так же 34 нс при $10^6$ элементах, когда списку нужно 8 мс. Остальная часть заметки объясняет, как множеству удаётся не смотреть на остальные элементы.

## Хеширование: от ключа к ячейке \{#hashing-from-a-key-to-a-slot\}

<aside class="callout"><strong>Ключевая идея.</strong> Хеш-таблица превращает сам ключ в позицию. **Хеш-функция** (hash function) отображает ключ в целое число, младшие биты этого числа выбирают ячейку, и ключ хранится там, поэтому поиск вычисляет ту же ячейку и проверяет одного-двух кандидатов, а не все $n$. Работу обеспечивают два правила: равные ключи должны иметь равные хеши, а хеш ключа никогда не должен меняться, пока ключ лежит в таблице. Таблица заполняется не больше чем на две трети, и это ограничивает ожидаемое число просмотренных ячеек константой, а при заполнении она увеличивается вдвое или вчетверо, и это сохраняет амортизированную стоимость вставки $O(1)$, как у списка.</aside>

**Правило.** `hash(obj)` возвращает целое число, такое что из `a == b` следует `hash(a) == hash(b)`. Обратное не обязано выполняться: разные ключи могут иметь общий хеш — это **коллизия** (collision). Ключ словаря должен быть **хешируемым** (hashable): его тип определяет `__hash__`, и хеш остаётся одним и тем же всё время жизни объекта ([глоссарий Python, hashable](#references)).

```text
>>> hash(3), hash(-1), hash(2**61 - 1), hash(2**61)
(3, -2, 0, 1)
>>> hash(1) == hash(1.0) == hash(True)
True
>>> hash([1, 2])
Traceback (most recent call last):
  ...
TypeError: unhashable type: 'list'
>>> import sys
>>> sys.hash_info.algorithm, sys.hash_info.modulus == 2**61 - 1
('siphash13', True)
```

**Откуда эти числа.** Хеш `int` — его значение по модулю простого числа $2^{61} - 1$, поэтому малые целые хешируются сами в себя, а $2^{61}$ — в 1; единственное исключение — $-1$, хеш которого равен $-2$, потому что $-1$ в C-коде CPython сигнализирует об ошибке. `float` или `bool`, равные целому числу, хешируются как это число, и правило «из равенства следует равенство хешей» соблюдается между числовыми типами ([документация Python, хеширование числовых типов](#references)). Строки и байты хешируются функцией SipHash с ключом: начиная с Python 3.11 по умолчанию используется вариант SipHash-1-3, а ключ выбирается случайно при запуске интерпретатора ([PEP 456](#references)). Поэтому одна и та же строка в двух запусках программы получает разные хеши, если `PYTHONHASHSEED` не фиксирует ключ, и то же касается порядка обхода множества строк. Списки изменяемы, и их тип устанавливает `__hash__` в `None`.

**От хеша к ячейке.** Когда ячеек $m$, первая ячейка, которую пробует ключ, — это `hash(key) & (m - 1)`. У нового словаря $m = 8$, поэтому первая ячейка — младшие 3 бита хеша:

```text
>>> d = {17: 'a', 3: 'b', 9: 'c'}
>>> [(k, hash(k) & 7) for k in d]
[(17, 1), (3, 3), (9, 1)]
>>> d[9]
'c'
```

Ключи 17 и 9 оба начинают с ячейки 1. Таблица должна положить один из них в другое место, а поиск `d[9]` должен найти его там.

## Открытая адресация: куда идёт ключ при коллизии \{#open-addressing-where-a-colliding-key-goes\}

**Правило.** CPython разрешает коллизии **открытой адресацией** (open addressing): каждый ключ живёт в самой таблице, а ключ, чья ячейка занята, пробует другие ячейки в фиксированном порядке — своей **последовательности проб** (probe sequence), — пока не найдёт свой ключ (поиск) или пустую ячейку (ключа нет, или туда можно вставить). Для таблицы из $m$ ячеек и хеша $h$ последовательность такова ([исходный код CPython, `Objects/dictobject.c`](#references)):

$$
\begin{aligned}
j_0 &= h \mathbin{\&} (m-1), \qquad \text{perturb}_0 = h,\\
\text{perturb}_{t+1} &= \text{perturb}_t \gg 5, \qquad j_{t+1} = (5\,j_t + 1 + \text{perturb}_{t+1}) \mathbin{\&} (m-1),
\end{aligned}
$$

где $\gg 5$ — сдвиг вправо на 5 битов. Одна лишь рекуррентная формула $j \mapsto 5j + 1 \bmod m$ обходит каждую ячейку таблицы размера степени двойки ровно один раз, прежде чем начать повторяться, поэтому пустая ячейка всегда находится. Добавка `perturb` подмешивает в первые несколько шагов старшие биты хеша, так что ключи, совпадающие в младших битах, например кратные 8, всё равно идут разными путями. Когда `perturb` доходит до 0, последовательность становится простой рекуррентной формулой.

При поиске каждая посещённая ячейка проверяется на совпадение с ключом в три шага возрастающей стоимости: тот ли это самый объект (`is`), равен ли сохранённый хеш, и только затем — верно ли `stored == key`. Сравнение хешей первым позволяет избежать большинства вызовов `__eq__`, которые для длинных строк или пользовательских классов могут быть дорогими.

<DictLookup />

1. `hash(9)` равен 9.
2. В таблице 8 ячеек, поэтому первая ячейка — $9 \mathbin{\&} 7 = 1$.
3. Ячейка 1 ссылается на запись 0, сохранённый хеш которой равен 17, а не 9. Ключи не могут быть равны, и `__eq__` не вызывается: это коллизия.
4. $\text{perturb} = 9 \gg 5 = 0$, поэтому следующая ячейка — $(5 \cdot 1 + 1 + 0) \mathbin{\&} 7 = 6$.
5. Ячейка 6 ссылается на запись 2 с хешем 9 и ключом 9, тем же самым объектом. Поиск возвращает `'c'`.

Вставка 9 прошла тот же путь и остановилась на первой пустой ячейке, 6. Массив индексов на рисунке — не реконструкция: чтение памяти словаря через `ctypes` в CPython 3.14.7 даёт ровно `[-1, 0, -1, 1, -1, -1, 2, -1]`, а раздел «Код» воспроизводит правило проб с тем же результатом.

## Компактная упорядоченная раскладка \{#the-compact-ordered-layout\}

На рисунке два массива, а не один. Начиная с CPython 3.6 словарь хранит свои записи (entries), каждая — тройка из хеша, ключа и значения (24 байта), в плотном массиве в порядке вставки, а собственно хеш-таблица — отдельный массив маленьких целых чисел, **индексов** (indices), которые хранят номера записей или $-1$ для пустых ячеек ([исходный код CPython](#references); эту схему предложил Раймонд Хеттингер в 2012 году). Индексы занимают по 1 байту в таблицах до 128 ячеек, по 2 байта до $2^{15}$, дальше по 4 и по 8.

**Зачем два массива.** До 3.6 таблица хранила 24-байтовые записи прямо в ячейках, а занято было не больше двух третей ячеек, так что треть памяти уходила на пустые записи. В компактной раскладке разреженными остаются только 1-байтовые индексы. При $m = 8$ старая раскладка занимала $8 \times 24 = 192$ байта таблицы; новая занимает 8 байт индексов плюс 5 записей, $5 \times 24 = 120$, всего 128.

**Порядок.** Обход словаря идёт по массиву записей, поэтому ключи выходят в том порядке, в каком были впервые вставлены. В CPython 3.6 это было деталью реализации; начиная с Python 3.7 это гарантирует язык ([What's New in Python 3.7](#references)). Удаление ключа опустошает его запись и помечает ячейку индексов как **фиктивную** (dummy), а не пустую, потому что последующий поиск должен продолжать пробы за ней; повторная вставка ключа добавляет новую запись в конец:

```text
>>> d = {17: 'a', 3: 'b', 9: 'c'}
>>> del d[3]
>>> d[3] = 'b'
>>> list(d)
[17, 9, 3]
```

Обновление значения существующего ключа, `d[17] = 'z'`, сохраняет его позицию. Множества не используют эту раскладку: множество хранит ключи прямо в разреженной таблице и никакого порядка не обещает.

## Коэффициент заполнения и расширение таблицы \{#the-load-factor-and-resizing\}

**Правило.** Таблица из $m$ ячеек принимает не больше $\lfloor 2m/3 \rfloor$ записей, то есть коэффициент заполнения не больше $2/3$. Вставка, которой не хватило места, заменяет таблицу таблицей из $m'$ ячеек — наименьшей степенью двойки не меньше $3n$, где $n$ — число ключей, хранящихся в этот момент, — и заново вставляет каждый ключ ([исходный код CPython](#references): `USABLE_FRACTION` и `GROWTH_RATE`). Удалённые записи не учитываются, поэтому таблица, полная фиктивных ячеек, перестраивается в том же размере или меньшем.

Начиная с 8 ячеек (5 доступных), шестой ключ запрашивает $3 \cdot 5 = 15$, так что $m' = 16$, из них 10 доступных; одиннадцатый запрашивает 30, значит 32, из них 21 доступная; затем 64, 128 и так далее. По измерениям `sys.getsizeof` размер меняется ровно при 6, 11, 22, 43, 86, 171, 342, 683 и 1366 ключах:

<DictGrowth />

Модель из подписи воспроизводит каждый измеренный размер с точностью до байта. Для 8 ячеек: $64 + 32 + 8 + 5 \cdot 24 = 224$. Для 256 ячеек, индексам которых нужно по 2 байта: $64 + 32 + 512 + 170 \cdot 24 = 4688$. Расширение переводит таблицу из $m$ в $2m$ (утроенное $2m/3$, округлённое вверх до степени двойки), поэтому амортизационное рассуждение из [заметки о списках](/ru/notes/python/lists-and-tuples#why-append-is-cheap-on-average) применимо с множителем 2: $n$ вставок в сумме заново вставляют меньше $2n$ ключей, амортизированно $O(1)$ на каждую.

**Почему две трети.** Именно ограничение на $\alpha$ делает поиск в среднем постоянным по времени. Предположим, что каждая проба попадает в ячейку, выбранную случайно и независимо от остальных, — идеализация хорошего хеша ([Cormen et al.](#references), §11.4).

1. Проба попадает в занятую ячейку с вероятностью $\alpha$ и в пустую с вероятностью $1 - \alpha$.
2. Поиск отсутствующего ключа останавливается на первой пустой ячейке. Он занимает ровно $t$ проб с вероятностью $\alpha^{t-1}(1-\alpha)$: $t - 1$ занятых ячеек, затем пустая.
3. Ожидаемое число проб — среднее этого геометрического распределения,

   $$
   \mathbb E[T] = \sum_{t \ge 1} t\,\alpha^{t-1}(1-\alpha) = \frac{1}{1-\alpha},
   $$

   где использовано $\sum_{t \ge 1} t x^{t-1} = 1/(1-x)^2$ при $|x| \lt 1$.
4. При $\alpha \le 2/3$:

   $$
   \boxed{\;\mathbb E[T] \le \frac{1}{1 - 2/3} = 3\;}
   $$

В среднем не больше трёх проб, каким бы ни было $n$. Поиск присутствующего ключа останавливается раньше, на самом ключе. Раздел «Код» проверяет формулу моделированием: 2.01, 2.99 и 9.99 пробы при коэффициентах заполнения 0.5, 2/3 и 0.9 против 2, 3 и 10. Последнее число показывает, зачем нужно ограничение: при $\alpha \to 1$ стоимость резко растёт. Последовательность проб CPython не случайна, но член `perturb` делает её поведение достаточно близким к случайному для хороших хешей; для последовательных целых чисел она работает даже лучше, поскольку они занимают последовательные ячейки вообще без коллизий.

## Почему ключи должны быть хешируемыми и неизменными \{#why-keys-must-be-hashable-and-must-not-change\}

Правило «у равных ключей равные хеши, и хеш ключа никогда не меняется» — это **контракт** (contract) между типом и каждой хеш-таблицей. Python не может его проверить; тип, который его нарушает, получает словарь, теряющий ключи. [Заметка о модели данных](/ru/notes/python/the-data-model#equality-and-hashing-__eq__-and-__hash__) показывает, как класс определяет `__eq__` и `__hash__`; здесь важны три следствия.

**Ключ, у которого изменился хеш, потерян.** Запись остаётся там, куда её поместил старый хеш, а поиск с новым хешем пробует другие ячейки:

```text
>>> class Key:
...     def __init__(self, v): self.v = v
...     def __eq__(self, other): return self.v == other.v
...     def __hash__(self): return hash(self.v)
...
>>> k = Key(1)
>>> d = {k: 'found'}
>>> k.v = 2
>>> k in d
False
>>> k in list(d)
True
>>> Key(1) in d
False
```

`k in d` вычисляет `hash(2)`, начинает пробы с ячейки 2, ничего не находит и отвечает `False`, хотя ключ в словаре есть, что подтверждает линейный поиск `k in list(d)`. `Key(1) in d` пробует правильную ячейку, но находит сохранённый ключ, у которого `v` теперь равно 2, — не равный. Ни один поиск больше никогда не доберётся до этой записи. Поэтому встроенные изменяемые типы, `list`, `dict` и `set`, не хешируемы: ошибка при вставке лучше, чем ключ, который молча пропадает. Кортеж хешируем, только когда хешируемо всё, что в нём лежит, а `frozenset` — неизменяемое хешируемое множество.

**`__eq__` без `__hash__` делает класс нехешируемым.** По умолчанию объект пользовательского класса равен только самому себе и хешируется по идентичности, что соответствует контракту. Класс, который определяет `__eq__`, но не `__hash__`, получает `__hash__ = None`, потому что хеш по идентичности, используемый по умолчанию, нарушил бы правило «из равенства следует равенство хешей»:

```text
>>> class P:
...     def __init__(self, v): self.v = v
...     def __eq__(self, other): return self.v == other.v
...
>>> P.__hash__ is None
True
>>> {P(1)}
Traceback (most recent call last):
  ...
TypeError: cannot use 'P' as a set element (unhashable type: 'P')
```

**Равные ключи — это один и тот же ключ.** Поскольку `1 == 1.0 == True` и их хеши совпадают, это один ключ: первый вставленный сохраняет своё место, а побеждает последнее значение:

```text
>>> {1: 'a', True: 'b', 1.0: 'c'}
{1: 'c'}
```

## Средний случай против худшего \{#average-against-worst-case\}

Каждая константа выше — среднее по ключам, которые хорошо хешируются. Ничто не мешает всем ключам иметь один хеш; тогда каждая вставка проходит пробами мимо всех прежних ключей и вызывает `__eq__` для каждого, поиск стоит $O(n)$, а построение таблицы — $O(n^2)$:

<DictWorstCase />

| Операция | В среднем | В худшем случае |
| --- | --- | --- |
| `d[k]`, `k in d`, `d[k] = v`, `del d[k]` | $O(1)$ | $O(n)$ |
| построение словаря из $n$ ключей | $O(n)$ | $O(n^2)$ |
| обход, `d.copy()` | $O(n)$ | $O(n)$ |

**Откуда худший случай берётся на практике.** Написанный вручную `__hash__`, который возвращает константу или использует только поле, которое редко меняется, даёт красную линию. Так же мог бы поступить злоумышленник, отправляя веб-серверу тысячи параметров запроса, подобранных так, чтобы они сталкивались, и заставляя один запрос стоить секунды процессорного времени; эта атака «хеш-флуд» (hash flooding) — причина, по которой хеширование строк по умолчанию использует секретный случайный ключ начиная с Python 3.3 ([PEP 456](#references)). Целые числа сохраняют предсказуемый хеш, потому что он быстр и в типичных случаях не даёт коллизий. Хороший `__hash__` комбинирует хеши ровно тех полей, которые сравнивает `__eq__`, проще всего как `hash((self.x, self.y))`.

## Множества и алгебра множеств \{#sets-and-set-algebra\}

**Правило.** `set` — неупорядоченная коллекция различных хешируемых объектов, хеш-таблица ключей без значений. Проверка принадлежности, `add` и `discard` стоят в среднем $O(1)$. Операторы алгебры множеств строят новые множества: `|` — объединение, `&` — пересечение, `-` — разность, `^` — симметрическая разность, а `<=` проверяет, является ли множество подмножеством. `{}` — пустой словарь; пустое множество — `set()`.

```text
>>> a = {1, 2, 3, 4}
>>> b = {3, 4, 5}
>>> a | b, a & b, a - b, a ^ b
({1, 2, 3, 4, 5}, {3, 4}, {1, 2}, {1, 2, 5})
>>> {3, 4} <= a
True
>>> words = ['to', 'be', 'or', 'not', 'to', 'be']
>>> len(set(words))
4
>>> list(dict.fromkeys(words))
['to', 'be', 'or', 'not']
```

`a & b` проходит по меньшему множеству и ищет каждый элемент в большем, $O(\min(|a|, |b|))$. `set(words)` удаляет повторы, но забывает порядок; `dict.fromkeys(words)` удаляет их и сохраняет порядок первого появления, поскольку словарь упорядочен.

Множество в CPython реализовано отдельно от словаря ([исходный код CPython, `Objects/setobject.c`](#references)): его таблица не компактна, оно пробует до 9 соседних ячеек, прежде чем прыгнуть по правилу `perturb`, что удобно для кэша, расширяется, когда занято 60% ячеек (считая фиктивные), и растёт до наименьшей степени двойки, превышающей учетверённое число ключей (удвоенное — при числе ключей больше 50 000). По измерениям `sys.getsizeof` множество последовательных целых чисел растёт при 5, 19, 77, 307 и 1229 элементах.

## Подсчёт и группировка: `Counter` и `defaultdict` \{#counting-and-grouping-counter-and-defaultdict\}

Два шаблона встречаются постоянно: подсчёт того, как часто встречается каждый ключ, и сбор элементов в группы по ключу. Оба работают с обычным словарём и `d.get(k, default)`, а в модуле `collections` для каждого есть свой тип ([документация Python, `collections`](#references)):

```text
>>> from collections import Counter, defaultdict
>>> words = 'the cat sat on the mat the end'.split()
>>> c = Counter(words)
>>> c.most_common(2)
[('the', 3), ('cat', 1)]
>>> c['dog']
0
>>> counts = {}
>>> for w in words:
...     counts[w] = counts.get(w, 0) + 1
...
>>> counts == c
True
>>> by_len = defaultdict(list)
>>> for w in words:
...     by_len[len(w)].append(w)
...
>>> dict(by_len)
{3: ['the', 'cat', 'sat', 'the', 'mat', 'the', 'end'], 2: ['on']}
```

`Counter` — подкласс словаря, у которого отсутствующие ключи дают счёт 0, а не возбуждают `KeyError`; `most_common(k)` возвращает $k$ наибольших счётчиков, при равенстве — в порядке первого появления. `defaultdict(list)` вызывает `list()`, чтобы создать значение ключа при первом обращении, поэтому `by_len[3].append(w)` работает без проверки, существует ли группа. Альтернатива для группировки на обычном словаре — `d.setdefault(k, []).append(w)`. Слияние двух словарей — `d1 | d2` (начиная с Python 3.9, [PEP 584](#references)), и при общих ключах побеждает правая часть.

**Ошибка.** `d[k]` для отсутствующего ключа возбуждает `KeyError`. Для проверки нужно `k in d`, для значения или `None` — `d.get(k)`, а когда значение по умолчанию имеет смысл — один из двух типов выше. У `defaultdict` обратная ловушка: простое чтение `by_len[7]` вставляет ключ 7 с пустым списком.

**Где это используется в курсах по ML.** Каждый конвейер NLP начинается со словаря: словарь токенов (vocabulary) сопоставляет каждому токену целочисленный идентификатор и обратно, а вектор мешка слов (bag of words) — это `Counter` токенов ([Мешок слов и TF-IDF](/ru/notes/nlp/bag-of-words-and-tf-idf)). Результаты собираются в словари метрик, конфигурации — словари гиперпараметров, а `state_dict()` модели PyTorch — словарь из имён параметров в тензоры.

## Что изменилось \{#what-changed\}

| | Список пар (отправная точка) | `dict` | `set` |
| --- | --- | --- | --- |
| Поиск по ключу | $O(n)$, перебор с `==` | $O(1)$ в среднем: хеш, затем примерно 1–3 пробы | $O(1)$ в среднем |
| Вставка | $O(1)$, добавление в конец, но возможны повторы | $O(1)$ амортизированно, одна запись на ключ | $O(1)$ амортизированно |
| Порядок | порядок вставки | порядок вставки (гарантирован начиная с 3.7) | нет |
| Ключи должны быть | сравнимыми через `==` | хешируемыми, с никогда не меняющимся хешем | хешируемыми |
| Память | один кортеж и одна ячейка на пару | $m$ байт индексов плюс место для $2m/3$ записей по 24 байта | $m$ ячеек по 16 байт (хеш и ключ), $m$ примерно от 1.7 до 8 раз больше $n$ |
| Худший случай | $O(n)$ | $O(n)$, когда ключи сталкиваются | $O(n)$ |

## Ограничения \{#limitations\}

- **Реализация CPython.** Правило проб, коэффициент заполнения 2/3, компактная раскладка и линейные пробы множества — детали CPython 3.14, которые другие реализации не обязаны разделять; язык гарантирует только поведение: операции в среднем за постоянное время, порядок вставки для `dict`, контракт хеширования.
- **Размеры и время — одной машины.** Числа байтов относятся к 64-битной сборке. Время измерено на одном Apple M1; сборка без GIL (free-threaded) добавляет блокировки на уровне объектов и даёт другое время.
- **Что не рассмотрено.** Словари с разделённой таблицей (split-table), которые разделяют ключи между экземплярами одного класса (они снова появятся в [заметке о классах](/ru/notes/python/classes-and-objects)), `types.MappingProxyType` для представлений только для чтения, `collections.OrderedDict` и `ChainMap`. Python 3.15, вышедший в октябре 2026 года, добавляет встроенный неизменяемый хешируемый `frozendict` ([PEP 814](#references)).

## Что нужно запомнить \{#what-you-should-remember\}

- `dict` и `set` — хеш-таблицы: хеш ключа выбирает ячейку, а поиск просматривает только ячейки из последовательности проб этого ключа. Средняя стоимость $O(1)$, худший случай $O(n)$.
- CPython пробует ячейки по правилу $j \mapsto 5j + 1 + \text{perturb}$ и сравнивает идентичность, затем сохранённый хеш, затем `==`.
- Словарь — это два массива: разреженные 1-байтовые индексы и плотные 24-байтовые записи в порядке вставки. Обход следует порядку вставки, это гарантировано начиная с 3.7.
- Таблица заполнена не больше чем на 2/3, что ограничивает ожидаемое число проб для отсутствующего ключа величиной $1/(1-\alpha) \le 3$; при заполнении она перестраивается в наименьшую степень двойки не меньше $3n$, поэтому вставка стоит $O(1)$ амортизированно.
- Ключи должны быть хешируемыми, а у равных ключей должны быть равные хеши, которые никогда не меняются. Изменяемые встроенные типы не хешируемы; вместо них — кортежи и frozenset. Определение одного лишь `__eq__` делает класс нехешируемым.
- Множества дают проверку принадлежности за $O(1)$ и алгебру множеств; `Counter` считает, `defaultdict` группирует, `dict.fromkeys` удаляет повторы с сохранением порядка.

## Код \{#code\}

Скрипт по порядку проверяет утверждения заметки: принадлежность в списке против множества, хеши чисел, таблицу индексов с рисунка, построенную по правилу проб CPython, рост словаря против модели размера, ожидаемое число проб при трёх коэффициентах заполнения моделированием, ключ, потерянный из-за изменения, худший случай с постоянным хешем, а также множества, `Counter` и `defaultdict`. Ему нужна только стандартная библиотека, и он выполняется меньше чем за секунду командой `python -I dicts.py`. Моделирование проб использует фиксированное начальное значение генератора; размеры — для 64-битной сборки, время меняется.

```python
"""Dictionaries and sets: hashing, probing, growth and the cost of a lookup (Python 3.14)."""
import random
import sys
import timeit
from collections import Counter, defaultdict

# 1. Отправная точка: принадлежность в списке сравнивает элемент за элементом, в множестве — хеширует
n = 100_000
xs = list(range(n)); s = set(xs); last = n - 1
t_list = min(timeit.repeat(lambda: last in xs, number=20, repeat=5)) / 20 * 1e9
t_set = min(timeit.repeat(lambda: last in s, number=20_000, repeat=5)) / 20_000 * 1e9
print(f"'x in list': {t_list:,.0f} ns   'x in set': {t_set:.0f} ns   (n = {n:,})")

# 2. Хеши: int хешируется сам в себя (mod 2**61 - 1); у равных чисел равные хеши; строки используют SipHash
print(hash(3), hash(-1), hash(2**61), hash(1) == hash(1.0) == hash(True), sys.hash_info.algorithm)

# 3. Таблица индексов {17: 'a', 3: 'b', 9: 'c'}: воспроизводим правило проб CPython
def probes(h, size):
    """The slots visited for hash h in a table of `size` slots (Objects/dictobject.c)."""
    mask, i, perturb = size - 1, h & (size - 1), h
    while True:
        yield i
        perturb >>= 5
        i = (i * 5 + perturb + 1) & mask

index = [-1] * 8
for entry, key in enumerate([17, 3, 9]):
    slot = next(j for j in probes(hash(key), 8) if index[j] == -1)
    index[slot] = entry
print("index table:", index)

# 4. Рост: sys.getsizeof против модели (доступно 2/3, расширение до степени двойки >= 3 * used)
def model_bytes(m):
    return 64 + 32 + m * (1 if m <= 128 else 2) + (2 * m // 3) * 24
d, changes = {}, []
for k in range(1, 1400):
    before = sys.getsizeof(d)
    d[k] = None
    if sys.getsizeof(d) != before:
        changes.append((k, sys.getsizeof(d)))
print("resizes at", [k for k, _ in changes])
print("model agrees:", [b for _, b in changes] == [model_bytes(8 * 2**i) for i in range(len(changes))])

# 5. Зачем ограничен коэффициент заполнения: при случайных пробах неудачный поиск занимает 1 / (1 - a) проб
random.seed(0)
def mean_probes(load, size=2**14, trials=20_000):
    full = set(random.sample(range(size), int(load * size)))
    total = 0
    for _ in range(trials):
        total += 1
        while random.randrange(size) in full:     # каждая проба попадает в случайную ячейку
            total += 1
    return total / trials
for a in (0.5, 2 / 3, 0.9):
    print(f"load {a:.2f}: {mean_probes(a):.2f} probes, theory {1 / (1 - a):.2f}")

# 6. Ключ, у которого изменился хеш, потерян
class Key:
    def __init__(self, v): self.v = v
    def __eq__(self, other): return self.v == other.v
    def __hash__(self): return hash(self.v)
k = Key(1)
d = {k: "found"}
k.v = 2
print("after mutation:", k in d, k in list(d), Key(1) in d)

# 7. Худший случай: все ключи сталкиваются
class Bad(Key):
    def __hash__(self): return 42
for cls in (Key, Bad):
    keys = [cls(i) for i in range(2000)]
    t = min(timeit.repeat(lambda: {key: None for key in keys}, number=1, repeat=3)) / 2000 * 1e9
    print(f"{cls.__name__}: {t:,.0f} ns per insertion with 2000 keys")

# 8. Множества, Counter и defaultdict
words = "the cat sat on the mat the end".split()
a, b = {1, 2, 3, 4}, {3, 4, 5}
print(a | b, a & b, a - b, a ^ b, Counter(words).most_common(2))
groups = defaultdict(list)
for w in words:
    groups[w[0]].append(w)
print(dict(groups), list(dict.fromkeys(words)))

# Вывод в CPython 3.14.7 на Apple M1, macOS (arm64); размеры — для 64-битной сборки, время меняется:
# 'x in list': 791,931 ns   'x in set': 34 ns   (n = 100,000)
# 3 -2 1 True siphash13
# index table: [-1, 0, -1, 1, -1, -1, 2, -1]
# resizes at [1, 6, 11, 22, 43, 86, 171, 342, 683, 1366]
# model agrees: True
# load 0.50: 2.01 probes, theory 2.00
# load 0.67: 2.99 probes, theory 3.00
# load 0.90: 9.99 probes, theory 10.00
# after mutation: False True False
# Key: 55 ns per insertion with 2000 keys
# Bad: 43,871 ns per insertion with 2000 keys
# {1, 2, 3, 4, 5} {3, 4} {1, 2} {1, 2, 5} [('the', 3), ('cat', 1)]
# {'t': ['the', 'the', 'the'], 'c': ['cat'], 's': ['sat'], 'o': ['on'], 'm': ['mat'], 'e': ['end']} ['the', 'cat', 'sat', 'on', 'mat', 'end']
```
