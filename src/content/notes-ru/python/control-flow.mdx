[Предыдущая заметка](/ru/notes/python/values-and-names) описала, с чем работает программа: с объектами и связанными с ними именами. Каждая программа до сих пор выполняла каждую свою строку ровно один раз, сверху вниз. Этого хватает для калькулятора и ни для чего больше. Программа должна выбирать между действиями в зависимости от данных, повторять действие для каждого полученного элемента и останавливаться, когда нашла то, что нужно. Эта заметка разбирает инструкции, которые это делают, — `if`, `while`, `for` и `match`, — и правило, стоящее за каждой: вопрос, который инструкция задаёт полученному объекту.

## Отправная точка: линейный код \{#baseline-straight-line-code\}

Программа без управления потоком выполнения (control flow) делает одно и то же при любых входных данных. Чтобы напечатать, жарко, умеренно или холодно, ей пришлось бы напечатать все три слова или ни одного. Чтобы сложить элементы списка, ей понадобилась бы одна строка на каждый элемент и отдельная программа для каждой длины. Инструкции управления потоком делают путь через код зависимым от значений, вычисленных во время выполнения.

## Выбор ветки: `if`, `elif`, `else` \{#choosing-a-branch-if-elif-else\}

**Правило.** `if` вычисляет своё условие. Если результат считается истинным, выполняется блок с отступом под ним, а остальная часть инструкции пропускается. Иначе по очереди проверяется каждое условие `elif`, и если ни одно не считается истинным, выполняется блок `else`, если он есть. Выполняется не больше одного блока.

```text
>>> temperature = 31
>>> if temperature > 30:
...     print("hot")
... elif temperature > 15:
...     print("mild")
... else:
...     print("cold")
...
hot
```

`temperature > 30` истинно, поэтому печатается `hot`. Условие `elif` `temperature > 15` тоже истинно, но оно даже не вычисляется: первая истинная ветка завершает инструкцию. Ветки следует упорядочивать от самой частной к самой общей.

**Блоки задаются отступами.** В Python нет фигурных скобок вокруг блоков. Строка, оканчивающаяся на `:`, открывает блок, и блок — это все следующие строки с отступом больше, чем у неё; блок заканчивается на первой строке с прежним отступом. По соглашению отступ — четыре пробела на уровень ([PEP 8](#references)). Отступы — часть синтаксиса, поэтому ошибка в них — ошибка компиляции, о которой сообщается до того, как что-либо выполнится:

```text
$ python ind.py
  File ".../ind.py", line 2
    print("indented?")
    ^^^^^
IndentationError: expected an indented block after 'if' statement on line 1
```

**Сравнения образуют цепочки.** `0 < x < 10` означает `0 < x and x < 10`, причём `x` вычисляется один раз. Так можно сцепить любые операторы сравнения, поэтому и `1 < 3 > 2` допустимо и истинно, хотя и неясно.

## Что считается истинным \{#what-counts-as-true\}

`if` не нужен `bool`. Его условием может быть любой объект, и Python спрашивает у объекта, считается ли тот истинным.

**Правило (проверка истинности, truth value testing).** Объект ложен, если это `None` или `False`, ноль любого числового типа (`0`, `0.0`) или пустая коллекция (`""`, `[]`, `()`, `{}`, `set()`, `range(0)`). Любой другой объект встроенных типов истинен ([документация Python, truth value testing](#references)). Для объектов других типов Python вызывает метод типа `__bool__`, если он есть, иначе `__len__` и считает нулевую длину ложью; объект без обоих методов истинен. `bool(x)` применяет ту же проверку и возвращает `True` или `False`.

```text
>>> [bool(v) for v in (None, False, 0, 0.0, "", [], (), {}, set(), range(0))]
[False, False, False, False, False, False, False, False, False, False]
>>> [bool(v) for v in (1, -0.5, "False", [0], (None,), {"a": 1})]
[True, True, True, True, True, True]
```

Строка `"False"` истинна, потому что это непустая строка, а `[0]` истинен, потому что это список длины 1; его элемент роли не играет. Благодаря этому `if items:` означает «если список не пуст», и это идиоматичная проверка.

**Почему это так устроено.** Компилятор превращает `if x:` в команду, которая преобразует `x` в `bool`, и условный переход. `dis` показывает и то, и другое:

```text
>>> import dis
>>> def check(x):
...     if x:
...         return "yes"
...     return "no"
...
>>> dis.dis(check)
  1           RESUME                   0

  2           LOAD_FAST_BORROW         0 (x)
              TO_BOOL
              POP_JUMP_IF_FALSE        3 (to L1)
              NOT_TAKEN

  3           LOAD_CONST               0 ('yes')
              RETURN_VALUE

  4   L1:     LOAD_CONST               1 ('no')
              RETURN_VALUE
```

`TO_BOOL` выполняет проверку истинности, вызывая при необходимости `__bool__` или `__len__`, а `POP_JUMP_IF_FALSE` переходит к метке `L1`, когда результат ложен. `if` — это переход через блок байт-кода. (`NOT_TAKEN` ничего не делает; он позволяет инструментам мониторинга, таким как coverage, видеть, в какую сторону пошло ветвление. CPython 3.11 компилирует ту же функцию без `TO_BOOL` и `NOT_TAKEN`, в один условный переход, который проверяет объект напрямую.)

**`and`, `or`, `not` возвращают операнды, а не `True` и `False`.** `a or b` вычисляет `a`; если `a` истинно, оно и есть результат, а `b` не вычисляется вовсе. Иначе результат — `b`. `a and b` возвращает `a`, если `a` ложно, иначе `b`. Только `not` всегда возвращает `bool`. Это правило **сокращённого вычисления** (short-circuit) даёт две идиомы — значение по умолчанию и защитное условие:

```text
>>> name = ""
>>> name or "anonymous"
'anonymous'
>>> [] and 1 / 0
[]
```

Вторая строка ничего не делит: `[]` ложно, поэтому `and` возвращает его, не вычисляя `1 / 0`.

**Ошибка.** `if x == 1 or 2:` читается как английская фраза «если x равно 1 или 2» и всегда истинно:

```text
>>> x = 5
>>> x == 1 or 2
2
>>> x == 1 or x == 2
False
>>> x in (1, 2)
False
```

`==` связывает сильнее, чем `or`, поэтому условие — это `(x == 1) or 2`. Левая часть равна `False`, поэтому `or` возвращает `2`, а это истинное значение. Нужно написать оба сравнения или использовать `in`.

## Повторение, пока выполнено условие: `while` \{#repeating-while-a-condition-holds-while\}

**Правило.** `while condition:` вычисляет условие; если оно считается истинным, выполняется блок, затем условие вычисляется снова, и так далее. Цикл заканчивается, как только условие впервые окажется ложным. Блок должен рано или поздно изменить что-то, от чего зависит условие.

```text
>>> n = 5
>>> total = 0
>>> while n > 0:
...     total += n
...     n -= 1
...
>>> total, n
(15, 0)
```

Блок выполнился пять раз, при `n`, равном 5, 4, 3, 2, 1; после пятого прохода `n` равно 0, условие ложно, и цикл заканчивается, сложив $5 + 4 + 3 + 2 + 1 = 15$. Если бы строки `n -= 1` не было, условие оставалось бы истинным вечно. Бесконечный цикл останавливают клавишами Ctrl-C, которые возбуждают в работающей программе `KeyboardInterrupt`.

`while` — подходящий цикл, когда число проходов заранее неизвестно: чтение ввода до его конца или итерации алгоритма до сходимости. Когда нужно пройти по коллекции, понятнее `for`.

## Повторение по элементам: `for` \{#repeating-over-items-for\}

**Правило.** `for target in iterable:` выполняет свой блок по разу для каждого элемента, который выдаёт итерируемый объект, перед каждым проходом связывая имя `target` с элементом. **Итерируемый объект** (iterable) — любой объект, который умеет выдавать свои элементы по одному: строки (свои символы), списки и кортежи (свои элементы), словари (свои ключи), файлы (свои строки), объекты `range` (свои числа) и многие другие.

```text
>>> for ch in "abc":
...     print(ch)
...
a
b
c
>>> list(range(5)), list(range(1, 4)), list(range(10, 0, -4))
([0, 1, 2, 3, 4], [1, 2, 3], [10, 6, 2])
```

`range(stop)` выдаёт $0, 1, \ldots, \text{stop} - 1$; `range(start, stop, step)` начинает с `start` и движется с шагом `step`, пока не дойдёт до `stop`. Конечное значение никогда не включается, поэтому в `range(n)` ровно `n` элементов — допустимые индексы списка длины `n`. `range` не хранит свои числа; он вычисляет каждое, когда его попросят.

Большинство потребностей покрывают три встроенных помощника: `enumerate(items)` выдаёт пары из индекса и элемента, `zip(a, b)` объединяет в пары элементы двух итерируемых объектов позиция за позицией, а `d.items()` выдаёт пары «ключ — значение» словаря. Каждая пара распаковывается в два имени:

```text
>>> for i, word in enumerate(["red", "green"]):
...     print(i, word)
...
0 red
1 green
>>> for name, year in zip(["ada", "alan"], [1815, 1912]):
...     print(name, year)
...
ada 1815
alan 1912
```

**Как `for` получает элементы.** Цикл один раз просит у объекта **итератор** (iterator), встроенной функцией `iter()`, а затем перед каждым проходом просит у итератора следующий элемент функцией `next()`. Когда элементов не осталось, `next()` возбуждает исключение `StopIteration`, и цикл заканчивается. Те же вызовы можно сделать вручную:

```text
>>> it = iter("ab")
>>> next(it)
'a'
>>> next(it)
'b'
>>> next(it)
Traceback (most recent call last):
  ...
StopIteration
```

Объект, который не поддерживает `iter()`, нельзя перебрать в цикле, и сообщение об ошибке говорит именно это: `for x in 42:` возбуждает `TypeError: 'int' object is not iterable`. [Заметка об итерации](/ru/notes/python/iteration-and-generators) полностью формулирует этот **протокол итератора** (iterator protocol) и показывает, как писать собственные итерируемые объекты; этой заметке нужны только два вызова.

**Ошибка.** Если менять список, пока цикл `for` по нему проходит, элементы пропускаются, потому что итератор движется по позициям:

```text
>>> nums = [1, 2, 2, 3]
>>> for n in nums:
...     if n == 2:
...         nums.remove(n)
...
>>> nums
[1, 2, 3]
```

Первая 2, на позиции 1, удаляется; вторая 2 сдвигается на позицию 1, а итератор продолжает с позиции 2, где теперь стоит 3. Одна 2 уцелела. Вместо этого нужно построить новый список, `[n for n in nums if n != 2]`, что даёт `[1, 3]`, или пройти по копии: `for n in nums[:]:`.

## Ранний выход: `break`, `continue` и `else` \{#leaving-early-break-continue-and-else\}

<aside class="callout"><strong>Ключевая идея.</strong> Каждая инструкция управления потоком задаёт своему объекту один вопрос по фиксированному протоколу. `if` и `while` спрашивают «считаешься ли ты истинным?», и отвечает `__bool__` или `__len__`. `for` спрашивает «дай мне итератор», а затем «дай следующий элемент», пока ответом не станет `StopIteration`. `match`, о котором ниже, спрашивает «у тебя такая форма?». `break` и `continue` меняют то, куда цикл пойдёт дальше, а блок `else` цикла выполняется, только если на вопрос «следующий элемент?» был получен ответ «больше нет».</aside>

**Правила.**

- `break` сразу завершает самый внутренний цикл. Выполнение продолжается после цикла, а блок `else` цикла, если он есть, пропускается.
- `continue` завершает текущий проход. Цикл `while` заново вычисляет условие; цикл `for` просит следующий элемент.
- У цикла может быть блок `else`. Он выполняется, когда цикл заканчивается обычным образом — потому что условие `while` стало ложным или итератор `for` исчерпан, — и не выполняется, когда из цикла вышли по `break`. Цикл, который ни разу не выполнил тело, всё равно выполняет свой `else`.

<LoopFlow />

1. `iter()` вызывается один раз и возвращает итератор.
2. Перед каждым проходом `next()` просит элемент.
3. Если он есть, переменная цикла связывается с ним и выполняется тело.
4. Когда тело заканчивается или встречается `continue`, цикл возвращается к шагу 2.
5. `break` переходит за конец цикла, пропуская блок `else`.
6. Когда элементы кончаются, выполняется блок `else`.
7. В любом случае выполнение продолжается с инструкции после цикла.

Ветка `else` предназначена для поиска: цикл что-то ищет и выполняет `break`, когда находит, а `else` обрабатывает случай «не найдено» без переменной-флага.

```text
>>> for n in (9, 15, 7, 21):
...     if n % 2 == 0:
...         print("found even", n)
...         break
... else:
...     print("no even number")
...
no even number
>>> for n in (9, 14, 7):
...     if n % 2 == 0:
...         print("found even", n)
...         break
... else:
...     print("no even number")
...
found even 14
```

В первом цикле ни один элемент не чётный, итератор исчерпывается после 21, и `else` выполняется. Во втором 14 вызывает `break`; 7 так и не проверяется, и `else` пропускается. Лучшим названием для этой ветки было бы `nobreak` («не было break»); так её и стоит читать.

`continue` пропускает остаток одного прохода:

```text
>>> for n in range(6):
...     if n % 3 == 0:
...         continue
...     print(n)
...
1
2
4
5
```

0 и 3 кратны 3, поэтому для них `continue` возвращает к `next()`, не доходя до `print`.

## Выбор по форме: `match` \{#choosing-by-shape-match\}

Цепочка `if`–`elif` сравнивает значения. Часто программе нужно задать другой вопрос: какой формы эти данные — пара или одиночный элемент, словарь с ключом `"type"`, строка из цифр — и каковы их части? Это делает инструкция `match`, добавленная в Python 3.10 ([PEP 634](#references)), — **сопоставление с образцом** (structural pattern matching).

**Правило.** `match subject:` один раз вычисляет субъект (subject) и сверху вниз пробует **образец** (pattern) каждой ветки `case`. Выполняется блок первого образца, который подошёл и чьё **охранное условие** (guard; необязательное `if condition` после образца) истинно; остальные ветки пропускаются. Подошедший образец может связать имена с частями субъекта. Если не подошла ни одна ветка, ничего не происходит.

Виды образцов, все они используются в двух примерах ниже:

| Образец | С чем сопоставляется | Что связывает |
| --- | --- | --- |
| `0`, `"quit"`, `None` (**литерал**, literal) | с равным значением (`None`, `True`, `False` — по идентичности) | ничего |
| `x` (голое имя, **захват**, capture) | с чем угодно | `x` с субъектом |
| `_` (**подстановочный образец**, wildcard) | с чем угодно | ничего |
| `(a, b)` или `[a, b]` (**последовательность**, sequence) | с последовательностью такой длины, но не со строкой | каждое имя с элементом |
| `[first, *rest]` | с последовательностью длины не меньше 1 | `rest` со списком остальных элементов |
| `{"type": t}` (**отображение**, mapping) | с отображением, у которого есть эти ключи; лишние ключи игнорируются | `t` со значением |
| `int()`, `str() as s` (**класс**, class) | с экземпляром этого типа | с `as` — `s` с субъектом |
| `"q" \| "Q"` (образец **ИЛИ**, OR) | с любой из альтернатив | одни и те же имена в каждой альтернативе |

**Разобранный пример: точки.** Субъект — пара координат:

```text
>>> def describe(point):
...     match point:
...         case (0, 0):
...             return "origin"
...         case (0, y):
...             return f"on the y-axis at {y}"
...         case (x, 0):
...             return f"on the x-axis at {x}"
...         case (x, y) if x == y:
...             return f"on the diagonal at {x}"
...         case (x, y):
...             return f"at {x}, {y}"
...         case _:
...             return "not a point"
...
>>> describe((0, 0)), describe((0, 5)), describe((3, 0))
('origin', 'on the y-axis at 5', 'on the x-axis at 3')
>>> describe((2, 2)), describe([4, 1]), describe("hi")
('on the diagonal at 2', 'at 4, 1', 'not a point')
```

Построчно: `(0, 0)` подходит только к двухэлементной последовательности, элементы которой равны 0 и 0. `(0, 5)` не подходит к первой ветке и подходит к `(0, y)`, связывая `y` с 5. `(2, 2)` не подходит к первым трём и подходит к `(x, y)` с истинным охранным условием `x == y`. `[4, 1]` — список, а образец-последовательность принимает любую последовательность, записан ли он в круглых или в квадратных скобках. `"hi"` — последовательность из двух символов, но образцы-последовательности никогда не сопоставляются со строками, поэтому он доходит до `_`. (Строки `f"..."` вставляют значения в текст; их объясняет [заметка о строках](/ru/notes/python/strings-and-text#f-strings-and-format-specifications).)

**Разобранный пример: события в виде словарей.** Данные, приходящие в программу извне, например сообщения JSON, часто представляют собой словарь, ключи которого говорят, что это такое:

```text
>>> def handle(event):
...     match event:
...         case {"type": "click", "x": x, "y": y}:
...             return f"click at {x}, {y}"
...         case {"type": "key", "key": "q" | "Q"}:
...             return "quit"
...         case {"type": "key", "key": str() as k}:
...             return f"key {k}"
...         case {"type": "scroll", "lines": int(n)} if n < 0:
...             return f"scroll up {-n}"
...         case {"type": t}:
...             return f"unknown event {t}"
...
>>> handle({"type": "click", "x": 3, "y": 4, "button": 1})
'click at 3, 4'
>>> handle({"type": "key", "key": "Q"})
'quit'
>>> handle({"type": "scroll", "lines": -2})
'scroll up 2'
>>> handle({"type": "scroll", "lines": 2})
'unknown event scroll'
>>> handle({"no": "type"}) is None
True
```

Щелчок подходит, хотя у него есть лишний ключ `"button"`: образцы-отображения проверяют только названные в них ключи. `int(n)` проверяет, что значение имеет тип `int`, и связывает его с `n`, а охранное условие отправляет прокрутку с положительным значением дальше, к последней ветке. Словарь без ключа `"type"` не подходит ни к одной ветке, поэтому `handle` доходит до конца и возвращает `None`.

**Ошибка: голое имя всегда захватывает.** Имя в образце никогда не сравнивается с существующей переменной; оно связывается с субъектом. Ветка, задуманная как сравнение с константой `RED`, вместо этого подходит ко всему, и компилятор отвергает инструкцию, если после этой ветки идут другие:

```text
$ python capture.py
  File ".../capture.py", line 4
    case RED:
         ^^^
SyntaxError: name capture 'RED' makes remaining patterns unreachable
```

Для сравнения с константой нужен литерал (`case "red":`) или имя с точкой (`case Color.RED:`), которое язык считает значением для сравнения ([PEP 636](#references)).

**Когда использовать `match`.** Когда ветки различаются структурой и коду нужны части данных: разобранные команды, сообщения, синтаксические деревья. Для простого сравнения одного значения с несколькими константами цепочка `if`–`elif` или поиск в словаре не менее понятны. Классы могут участвовать в сопоставлении своими атрибутами, `case Point(x=0)`; как именно, показывает [заметка о классах](/ru/notes/python/classes-and-objects).

## Выражения и инструкции \{#expressions-against-statements\}

**Выражение** (expression) — это код, который даёт значение: `3`, `x + 1`, `len(items) > 0`, `f(x)`. **Инструкция** (statement) — это код, который что-то делает и ничего не даёт: присваивание, `if`, `for`, `def`, `import`. Выражение может стоять везде, где нужно значение, — внутри другого выражения или в качестве аргумента; инструкция не может. REPL печатает значение выражения и ничего не печатает для инструкции; так их и различала [первая заметка](/ru/notes/python/running-python#baseline-the-interactive-prompt).

`if` — инструкция, поэтому она не может стоять там, где ожидается значение. Её форма-выражение — **условное выражение** (conditional expression):

```text
>>> n = 7
>>> "even" if n % 2 == 0 else "odd"
'odd'
```

`a if condition else b` сначала вычисляет условие, а затем только одно из `a` и `b`. Оно подходит для выбора между двумя значениями; всё, что длиннее, лучше читается в виде инструкции `if`.

Присваивание — инструкция, поэтому его нельзя вложить в выражение, и компилятор подсказывает, что, вероятно, имелось в виду:

```text
>>> y = (x = 5)
  File "<python-input-0>", line 1
    y = (x = 5)
         ^^^^^
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
```

**Выражение присваивания** (assignment expression) `name := value` (начиная с Python 3.8, [PEP 572](#references)) связывает имя и при этом даёт значение, что позволяет не вычислять что-то дважды:

```text
>>> data = [3, 1, 4, 1, 5, 9, 2, 6]
>>> if (n := len(data)) > 5:
...     print(f"long list: {n} items")
...
long list: 8 items
```

Курсы машинного обучения используют всё это в простом виде: `for epoch in range(n_epochs):` вокруг цикла обучения, `while`, пока изменение не станет меньше допуска, в [градиентном спуске](/ru/notes/ml/gradient-descent), условные выражения для небольших выборов и `break` из цикла по эпохам для [ранней остановки](/ru/notes/ml/training-deep-networks#learning-rate-schedules-warm-up-and-early-stopping), которая завершает обучение, когда функция потерь на валидации перестаёт улучшаться.

## Что изменилось \{#what-changed\}

| | Линейный код (отправная точка) | С управлением потоком |
| --- | --- | --- |
| Путь через код | каждая строка по разу, по порядку | выбирается во время выполнения по данным |
| Выбор | невозможен | `if`/`elif`/`else` по истинности любого объекта; `match` по его форме |
| Повторение | одна строка на каждое повторение | `while`, пока выполнено условие; `for` для каждого элемента итерируемого объекта |
| Ранняя остановка | невозможна | `break`; `continue` для одного прохода; `else` цикла для случая «не найдено» |
| Значения из выбора | нет | условное выражение `a if c else b` |

## Ограничения \{#limitations\}

- **Итерация лишь обозначена.** Как работают `iter()` и `next()` и как написать объект, который примет цикл `for`, — в [заметке об итерации](/ru/notes/python/iteration-and-generators), вместе с включениями и генераторами.
- **Исключения тоже меняют поток выполнения.** Исключение покидает все циклы и функции, пока что-нибудь его не обработает; `try` и `except` — в [заметке о файлах и исключениях](/ru/notes/python/files-and-exceptions).
- **Байт-код меняется.** Команды, которые показывает `dis`, относятся к CPython 3.14 и различаются между версиями; поведение, которое они реализуют, определено языком и не меняется.
- **У `match` есть ещё возможности.** Образцы классов с именованными атрибутами, `__match_args__` и образцы-значения для перечислений оставлены [заметке о классах](/ru/notes/python/classes-and-objects) и учебнику [PEP 636](#references).

## Что нужно запомнить \{#what-you-should-remember\}

- `if` выполняет не больше одной ветки: первую, условие которой считается истинным. Блоки задаются отступами.
- Проверка истинности: `None`, `False`, нули и пустые коллекции ложны; всё остальное истинно, если тип не определяет иначе через `__bool__` или `__len__`. `if items:` проверяет непустоту.
- `and` и `or` вычисляются сокращённо и возвращают один из своих операндов. `x == 1 or 2` всегда истинно.
- `while` повторяет, пока выполнено условие; `for` один раз просит у итерируемого объекта итератор и перед каждым проходом — следующий элемент, пока не получит `StopIteration`.
- `break` выходит из цикла и пропускает его `else`; `continue` переходит к следующему проходу; `else` цикла означает «не было break».
- `match` выбирает первую ветку, образец которой соответствует форме субъекта, и связывает его части; голое имя в образце всегда захватывает.
- Выражения дают значения; инструкции — нет. `a if c else b` и `:=` — формы-выражения выбора и присваивания.

## Код \{#code\}

Скрипт выполняет каждую конструкцию заметки на небольших входных данных: проверку истинности распространённых объектов, цикл `while`, который считает шаги Коллатца, `for` с `break` и `else` для поиска делителя, `continue` для фильтрации строк и `match` для разбора команд по их форме. Запуск — `python -I flow.py`; скрипт использует только стандартную библиотеку, и его вывод одинаков на любой платформе.

```python
"""Branches, loops and match, on small concrete inputs (Python 3.14)."""

# 1. Истинность: что `if x:` решает для распространённых объектов
for value in (0, 7, 0.0, "", "0", [], [0], None, {}, {"k": 1}):
    print(f"{value!r:>8} -> {'true' if value else 'false'}")

# 2. while: считаем шаги правила Коллатца, пока n не станет равно 1
def collatz_steps(n):
    steps = 0
    while n != 1:
        n = n // 2 if n % 2 == 0 else 3 * n + 1
        steps += 1
    return steps

print([collatz_steps(n) for n in (1, 6, 7, 27)])

# 3. for с break и else: наименьший делитель или «простое»
def smallest_divisor(n):
    for d in range(2, n):
        if d * d > n:
            break                  # до sqrt(n) делителей нет: прекращаем поиск
        if n % d == 0:
            return d
    return None

def classify(n):
    for d in range(2, n):
        if n % d == 0:
            result = f"{n} = {d} * {n // d}"
            break
    else:                          # выполняется, только если из цикла не вышли по break
        result = f"{n} is prime"
    return result

print([smallest_divisor(n) for n in (15, 49, 97)], classify(91), classify(97))

# 4. continue: пропускаем пустые строки и комментарии, остальное оставляем
lines = ["# settings", "rate = 0.1", "", "  # note", "epochs = 5"]
kept = []
for line in lines:
    if not line.strip() or line.strip().startswith("#"):
        continue
    kept.append(line)
print(kept)

# 5. match: разбираем простые команды по их форме
def run(command):
    match command.split():
        case []:
            return "nothing to do"
        case ["go", ("north" | "south" | "east" | "west") as direction]:
            return f"going {direction}"
        case ["go", other]:
            return f"cannot go {other!r}"
        case ["take", *things] if things:
            return f"taking {', '.join(things)}"
        case ["quit" | "exit"]:
            return "bye"
        case [verb, *_]:
            return f"unknown verb {verb!r}"

for c in ("", "go north", "go up", "take key lamp", "take", "quit", "dance now"):
    print(f"{c!r:16} -> {run(c)}")

# Вывод в CPython 3.14.7 (одинаковый на любой платформе):
#        0 -> false
#        7 -> true
#      0.0 -> false
#       '' -> false
#      '0' -> true
#       [] -> false
#      [0] -> true
#     None -> false
#       {} -> false
# {'k': 1} -> true
# [0, 8, 16, 111]
# [3, 7, None] 91 = 7 * 13 97 is prime
# ['rate = 0.1', 'epochs = 5']
# ''               -> nothing to do
# 'go north'       -> going north
# 'go up'          -> cannot go 'up'
# 'take key lamp'  -> taking key, lamp
# 'take'           -> unknown verb 'take'
# 'quit'           -> bye
# 'dance now'      -> unknown verb 'dance'
```

`"take"` без аргументов не проходит охранное условие `if things` (список `things` пуст, то есть ложен) и доходит до последней ветки. `smallest_divisor(97)` останавливается на `d = 10`, поскольку $10^2 > 97$, не найдя делителя, и возвращает `None`.
