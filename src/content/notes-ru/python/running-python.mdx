По пути он объясняет, что Python делает с каждой написанной строкой, вплоть до объектов в памяти и команд, которые выполняет интерпретатор: именно эта модель позволяет предсказывать, что сделает программа, а не гадать. Строки, начинающиеся с приглашения терминала `$`, набираются в терминале; само приглашение не входит в команду. Длинные отчёты об ошибках обрезаны до последних строк, а место разреза отмечено `...`.

## Что такое программа и интерпретатор \{#what-a-program-and-an-interpreter-are\}

**Программа** (program) — это список инструкций для компьютера, записанный в виде текста. Этот текст называется **исходным кодом** (source code), а файл с исходным кодом на Python имеет расширение `.py`. Процессор компьютера не умеет читать этот текст. Он выполняет **машинный код** (machine code): пронумерованные команды вроде «сложить два регистра» или «перейти по этому адресу», свои для каждого типа процессора. Между текстом и процессором должно что-то стоять.

Для Python это **интерпретатор** (interpreter) — тоже программа, обычно она называется `python`. Он читает исходный код и выполняет то, что в нём написано. Стандартный интерпретатор, CPython, написан на C, и именно его скачивают с python.org. Существуют и другие реализации (например, PyPy выполняет тот же язык другим движком), но когда говорят «Python», почти всегда имеют в виду CPython; этот курс — тоже.

**Версия языка** — это обещание о том, что означает исходный код. Python 3.14 вышел в октябре 2025 года; эту версию использует курс, и все примеры запускались в 3.14.7. Python 3.15 вышел следом, в октябре 2026 года, и заметки указывают, где он меняет что-то из того, что в них показано. Программа, написанная для 3.14, за редкими исключениями работает в 3.15, но не наоборот: новая версия добавляет возможности, которых старый интерпретатор не понимает.

## Установка Python 3.14 \{#installing-python-314\}

Есть два распространённых способа, и для всего курса подходит любой.

- **Официальный установщик.** Его можно скачать с [python.org/downloads](https://www.python.org/downloads/). В macOS это установщик `.pkg`, который добавляет команды `python3` и `python3.14`. В Windows начиная с 3.14 рекомендуется **менеджер установки Python** (Python install manager) с той же страницы или из Microsoft Store; `py install 3.14` устанавливает эту версию, а прежний полный установщик объявлен устаревшим ([документация Python, Using Python on Windows](#references)). В Linux менеджер пакетов дистрибутива обычно предлагает свежую версию.
- **uv.** [uv](https://docs.astral.sh/uv/) — быстрый инструмент, который устанавливает версии Python и управляет пакетами проекта. После установки самого uv команда `uv python install 3.14` скачивает CPython 3.14 и в свежих версиях uv добавляет команду `python3.14` в `~/.local/bin`. В папке проекта `uv run python` запускает интерпретатор проекта с пакетами проекта. Окружения подробно объясняет [заметка о модулях и окружениях](/ru/notes/python/modules-and-packages).

Проверим, что установлено:

```text
$ python3.14 --version
Python 3.14.7
```

Имя команды бывает разным: `python3` в macOS и большинстве систем Linux, `python` или `py` в Windows, `python` внутри активированного окружения. В курсе пишется `python`.

## Отправная точка: интерактивная оболочка \{#baseline-the-interactive-prompt\}

Проще всего запустить Python, набрав `python` без аргументов. Интерпретатор запускает **REPL** (read–evaluate–print loop, цикл «чтение — вычисление — печать»): он читает одну инструкцию, вычисляет её, печатает результат, если он есть, и ждёт следующую.

```text
$ python3.14
Python 3.14.7 (main, Sep  1 2026, 14:05:28) [Clang 22.1.3 ] on darwin
Type "help", "copyright", "credits" or "license" for more information.
>>> 2 + 3
5
>>> x = 7
>>> x * 6
42
>>> print("hello")
hello
```

Прочитаем по строкам. `2 + 3` — это **выражение** (expression), фрагмент кода, у которого есть значение, и REPL печатает это значение, `5`. `x = 7` — **присваивание** (assignment): оно даёт значению 7 имя `x` и собственного значения не имеет, поэтому ничего не печатается. `x * 6` использует это имя, и REPL печатает 42. `print("hello")` — вызов функции `print`, которая выводит свой аргумент в терминал; сам REPL больше ничего не печатает, потому что `print` не возвращает значения, которое стоило бы показать. `exit` или Ctrl-D завершают REPL.

REPL — самый быстрый способ проверить одну идею. Начиная с 3.13 это новая реализация с многострочным редактированием, цветом и историей целых инструкций; 3.14 добавляет подсветку синтаксиса и дополнение имён модулей после `import` по клавише Tab ([What's New in Python 3.14](#references)). Не справляется он со всем, что выходит за пределы одной идеи: когда REPL завершается, все имена и значения пропадают, а набранные инструкции не становятся программой, которую можно запустить ещё раз.

## Скрипт: `python file.py` \{#a-script-python-filepy\}

**Скрипт** (script) — это файл с исходным кодом, который интерпретатор выполняет сверху вниз. Сохраним эти три строки в файл `area.py`:

```python
width = 3
height = 4
print(width * height)
```

и запустим его:

```text
$ python area.py
12
```

Правила отличаются от REPL в двух отношениях. Инструкции выполняются по порядку, от первой строки до последней, а затем программа завершается. И скрипт печатает только то, что его попросили напечатать: голое выражение вроде `width * height` на отдельной строке вычисляется и выбрасывается, потому что нет REPL, который бы его показал. Всё, что стоит после имени файла, попадает в список `sys.argv`, поэтому скрипту можно сказать, с чем работать:

```text
$ cat args.py
import sys; print(sys.argv)
$ python args.py data.csv 10
['args.py', 'data.csv', '10']
```

Аргументы приходят в виде текста: `'10'`, а не число 10; почему эта разница важна, показывает [следующая заметка](/ru/notes/python/values-and-names).

## Модуль: `python -m` \{#a-module-python--m\}

`python -m name` находит модуль с именем `name` в пути поиска Python и запускает его как главную программу. Так запускаются многие инструменты, которые поставляются вместе с Python, и это гарантирует, что инструмент относится к тому же интерпретатору, что и набранный `python`:

| Команда | Что делает |
| --- | --- |
| `python -m venv .venv` | создаёт виртуальное окружение в папке `.venv` |
| `python -m pip install numpy` | устанавливает пакет в этот интерпретатор |
| `python -m timeit "expression"` | измеряет время небольшого фрагмента кода |
| `python -m json` | красиво печатает JSON, прочитанный из стандартного ввода (как команда — впервые в 3.14) |
| `python -m pytest` | запускает тесты проекта (после установки pytest) |

```text
$ python -m timeit '"-".join(str(n) for n in range(100))'
50000 loops, best of 5: 6.08 usec per loop
```

Это время — один запуск на описанной выше конфигурации, на других машинах оно будет другим. Разница между `python file.py` и `python -m name` в том, как находится файл: в первом случае по пути к нему, во втором — тем поиском модулей, который использует `import`. Этот поиск объясняет [заметка о модулях](/ru/notes/python/modules-and-packages).

## Ноутбуки \{#notebooks\}

**Ноутбук** (notebook; Jupyter или Google Colab, который выполняет ноутбуки Jupyter в браузере) — это документ из **ячеек** (cells). Ячейка с кодом отправляется запущенному интерпретатору, который называется **ядром** (kernel), и её вывод, включая таблицы и графики, сохраняется в документе под ячейкой. Текстовые ячейки (Markdown) содержат текст. С uv команда `uv run --with jupyter jupyter lab` запускает JupyterLab из папки проекта ([документация uv](#references)).

Ноутбуки сочетают непосредственность REPL с записью того, что было выполнено, поэтому ими пользуются в анализе данных и преподавании. К курсам NLP и генеративных моделей на этом сайте прилагаются ноутбуки. У них есть одна ловушка, которой нет у скриптов: ядро хранит все имена из всех выполненных ячеек в том порядке, в каком их выполняли, а он не обязан совпадать с порядком на странице. Ячейка, которая использует имя, определённое в ячейке ниже или в уже удалённой ячейке, сейчас работает, а у следующего читателя упадёт. Счётчик выполнения рядом с каждой ячейкой, `[3]`, записывает этот порядок. Прежде чем делиться ноутбуком, нужно перезапустить ядро и выполнить все ячейки сверху; если всё по-прежнему работает, сохранённые выходы — это то, что действительно выдаёт код.

## Что происходит при запуске файла \{#what-happens-when-you-run-a-file\}

<aside class="callout"><strong>Ключевая идея.</strong> CPython никогда не выполняет текст напрямую. Сначала он компилирует весь файл в **байт-код** (bytecode) — список простых команд для виртуальной машины, который хранится в **объекте кода** (code object). Затем цикл, написанный на C, выполняет эти команды одну за другой. Синтаксическая ошибка обнаруживается на первом этапе, до выполнения какой-либо строки; все остальные ошибки возникают на втором, во время работы программы.</aside>

<RunPipeline />

1. Исходный код — текстовый файл. Ещё ничего не выполнено.
2. **Компилятор** (compiler) читает весь файл. Он разрезает текст на **токены** (tokens: имена, числа, операторы), проверяет, что они образуют правильный код на Python, строит **синтаксическое дерево** (syntax tree) и переводит дерево в байт-код.
3. Результат — объект кода. Модуль `dis` печатает его команды; для третьей строки `area.py` он перечисляет девять, и рисунок показывает первые шесть в том порядке, в каком их перечисляет `dis` (оставшиеся три отбрасывают результат `print` и завершают модуль). `LOAD_NAME width` кладёт значение с именем `width` на стек значений, `BINARY_OP *` заменяет два верхних значения их произведением, а `CALL 1` вызывает `print` с одним аргументом.
4. **Цикл интерпретатора** (interpreter loop) выбирает каждую команду и выполняет реализующий её код на C.
5. `print` выводит 12 в терминал. Последняя команда выполняет возврат, и программа завершается.

Для файла, который импортируют, а не запускают, CPython сохраняет скомпилированный объект кода в файл `.pyc` в папке `__pycache__` рядом с ним, с именем интерпретатора в названии (`__pycache__/area.cpython-314.pyc`), и при следующем импорте компилятор пропускается, если исходный код не изменился. Главный скрипт компилируется заново при каждом запуске.

Из этого следуют два вывода, и оба видны в повседневной работе. Файл с синтаксической ошибкой в последней строке не печатает вообще ничего, даже вывода первой строки: компилятор останавливается до того, как что-либо выполнится. А код, ошибочный так, что компилятор этого не видит, например деление на число, которое оказалось нулём, работает до того момента, когда выполняется эта команда. Заметка [Как CPython выполняет код](/ru/notes/python/how-cpython-runs-code) подробно разбирает цикл интерпретатора и стек значений, а курс по архитектуре компьютера и ОС проходит тот же путь [вплоть до операционной системы](/ru/notes/acos/language-runtimes#cpython-from-source-to-system-call).

## Ошибки и как читать трассировку \{#errors-and-how-to-read-a-traceback\}

Когда инструкция завершается неудачей, Python возбуждает **исключение** (exception). Если в программе его ничто не обрабатывает (как это делать, показывает [заметка о файлах и исключениях](/ru/notes/python/files-and-exceptions)), интерпретатор печатает **трассировку стека** (traceback) и завершается с ненулевым кодом. Возьмём скрипт, который усредняет числа за две недели, причём одна неделя пуста:

```python
def average(values):
    return sum(values) / len(values)

def report(name, values):
    print(name, average(values))

report("week 1", [12, 15, 9])
report("week 2", [])
```

```text
$ python prices.py
week 1 12.0
Traceback (most recent call last):
  File ".../prices.py", line 8, in <module>
    report("week 2", [])
    ~~~~~~^^^^^^^^^^^^^^
  File ".../prices.py", line 5, in report
    print(name, average(values))
                ~~~~~~~^^^^^^^^
  File ".../prices.py", line 2, in average
    return sum(values) / len(values)
           ~~~~~~~~~~~~^~~~~~~~~~~~~
ZeroDivisionError: division by zero
```

(Путь к папке в каждом пути к файлу сокращён до `...`.) Правило чтения:

1. **Начинать с последней строки.** В ней указан тип исключения, `ZeroDivisionError`, и сообщение, `division by zero`. Это — что пошло не так.
2. **Строка над ней — где.** Каждая запись `File` — один активный вызов функции, **кадр** (frame), с его файлом, номером строки и именем функции. Список идёт от самого старого вызова сверху к самому последнему внизу: «most recent call last», последний вызов — последним. Нижний кадр, строка 2 внутри `average`, — место, где было возбуждено исключение.
3. **Значки под строкой кода указывают внутрь неё.** Начиная с Python 3.11 ([PEP 657](#references)) трассировка подчёркивает выражение, которое не выполнилось: `^` отмечает часть, возбудившую исключение (здесь `/`), а `~` — остальную часть выражения вокруг неё.
4. **Подниматься вверх, чтобы найти причину.** Строка, где произошёл сбой, часто правильна; плохое значение пришло выше. Здесь `average` поделила корректно, а пустой список пришёл из строки 8.

Первая строка вывода, `week 1 12.0`, тоже важна: первый вызов выполнился до конца, прежде чем второй завершился ошибкой. Инструкции выполняются по порядку, пока одна из них не возбудит исключение.

**Синтаксическая ошибка** (syntax error) выглядит иначе, потому что её находит компилятор, до того как что-либо выполнится. Кадров нет, есть только место в файле:

```text
$ python late.py
  File ".../late.py", line 2
    whille True:
    ^^^^^^
SyntaxError: invalid syntax. Did you mean 'while'?
```

Первой строкой файла была `print("start")`, и `start` так и не напечаталось. Подсказка «Did you mean 'while'?» появилась в 3.14; более ранние версии пишут только `invalid syntax`. Сообщения об ошибках улучшались в каждом выпуске начиная с 3.10, и их стоит читать внимательно. Ещё два сообщения, которые новичок встречает в первый же час:

```text
$ python name.py
Traceback (most recent call last):
  File ".../name.py", line 2, in <module>
    print(totl)
          ^^^^
NameError: name 'totl' is not defined. Did you mean: 'total'?
$ python paren.py
  File ".../paren.py", line 1
    print("hello"
         ^
SyntaxError: '(' was never closed
```

Курсы машинного обучения постоянно сталкиваются с трассировками, и большинство из них длинные, потому что строка со сбоем лежит глубоко внутри библиотеки вроде NumPy или PyTorch. Правило то же: прочитать последнюю строку, затем найти самый нижний кадр, который относится к собственному файлу. Обычно именно в этом кадре было передано неверное значение или неверная форма массива.

## Ограничения \{#limitations\}

- **Одна реализация.** Байт-код, имена файлов `.pyc` и точные формулировки сообщений об ошибках принадлежат CPython и меняются от версии к версии; правила языка в остальной части курса от них не зависят.
- **Одна машина.** Время выше получено за один запуск на одной машине и лишь иллюстрирует, что печатает `timeit`. Как измерять правильно, показывает [заметка об отладке и профилировании](/ru/notes/python/debugging-and-profiling).
- **Окружения отложены.** Установка пакетов в нужное место и фиксация версий проекта — тема [заметки о модулях и окружениях](/ru/notes/python/modules-and-packages). До неё всё в курсе требует только стандартной библиотеки.

## Что нужно запомнить \{#what-you-should-remember\}

- Интерпретатор — это программа, которая читает исходный код и выполняет его. Стандартный интерпретатор — CPython; курс использует 3.14.
- REPL выполняет по одной инструкции и печатает значение каждого выражения. Скрипт выполняет весь файл сверху вниз и печатает только то, что его просят. `python -m` запускает модуль, найденный по имени. Ноутбук хранит состояние интерпретатора между ячейками в том порядке, в каком их выполняли.
- CPython сначала компилирует весь файл в байт-код, а затем выполняет байт-код в цикле. Синтаксические ошибки останавливают всё до выполнения первой строки; остальные ошибки возникают, когда выполняется их строка.
- Трассировку читают снизу: исключение и его сообщение, затем самый последний кадр, затем вверх по вызывающим функциям, чтобы найти, откуда пришло плохое значение.

## Код \{#code\}

Скрипт проводит трёхстрочную программу этой заметки через все стадии: компилирует исходный текст в объект кода, перечисляет его байт-код, выполняет его, показывает, где был бы закэширован байт-код импортированного модуля, и перехватывает синтаксическую ошибку и ошибку времени выполнения, чтобы показать, как выглядит каждая. Ему нужна только стандартная библиотека; запускать его — `python -I stages.py`. Имена команд байт-кода — те, что в CPython 3.14, в других версиях они отличаются.

```python
"""Follow one small program through the stages of running it (Python 3.14)."""
import dis
import importlib.util
import sys
import traceback

source = "width = 3\nheight = 4\nprint(width * height)\n"

# 1. Какой интерпретатор выполняет этот файл
print(sys.version_info[:3], sys.implementation.name, sys.implementation.cache_tag)

# 2. Компиляция: исходный текст -> объект кода, который хранит байт-код
code = compile(source, "area.py", "exec")
print(type(code).__name__, code.co_names)
print([ins.opname for ins in dis.get_instructions(code)])

# 3. Выполняем объект кода; его имена попадают в новое пространство имён
namespace = {}
exec(code, namespace)
print(namespace["width"], namespace["height"])

# 4. Куда был бы закэширован байт-код импортированного модуля area.py
print(importlib.util.cache_from_source("area.py"))

# 5. Синтаксическая ошибка находится при компиляции, до выполнения чего-либо
try:
    compile("whille True:\n    pass\n", "typo.py", "exec")
except SyntaxError as err:
    print(f"{err.filename}, line {err.lineno}: {err.msg}")

# 6. Ошибка времени выполнения: трассировка перечисляет кадры, последний вызов внизу
def average(values):
    return sum(values) / len(values)

def report(values):
    return f"mean {average(values)}"

try:
    report([])
except ZeroDivisionError:
    tb = traceback.extract_tb(sys.exc_info()[2])
    print([frame.name for frame in tb])
    print(traceback.format_exc().splitlines()[-1])

# Вывод в CPython 3.14.7 на macOS (arm64); первая строка покажет установленную версию:
# (3, 14, 7) cpython cpython-314
# code ('width', 'height', 'print')
# ['RESUME', 'LOAD_SMALL_INT', 'STORE_NAME', 'LOAD_SMALL_INT', 'STORE_NAME', 'LOAD_NAME', 'PUSH_NULL', 'LOAD_NAME', 'LOAD_NAME', 'BINARY_OP', 'CALL', 'POP_TOP', 'LOAD_CONST', 'RETURN_VALUE']
# 12
# 3 4
# __pycache__/area.cpython-314.pyc
# typo.py, line 1: invalid syntax
# ['<module>', 'report', 'average']
# ZeroDivisionError: division by zero
```

Строка вывода `12` получается от `print` внутри выполняемой программы, между байт-кодом и пространством имён. `err.msg` равно `invalid syntax` без подсказки «Did you mean»: подсказка добавляется при выводе трассировки и не хранится в исключении.
