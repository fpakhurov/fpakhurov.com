[Предыдущая заметка](/ru/notes/python/running-python) запускала программы из шагов двух видов: создание значения, например `3` или `[12, 15, 9]`, и присвоение ему имени, например `width`. Эта заметка выясняет, что это за две вещи. Ответ короткий, и на нём держится весь остальной курс: каждое значение в Python — это **объект** (object), который где-то находится в памяти, имя — это **ссылка** (reference) на объект, а `=` прикрепляет имя к объекту, ничего не копируя. Большинство сюрпризов, с которыми встречаются новички, — список, который меняется «сам», аргумент по умолчанию, который что-то помнит, копия, которая не копия, — следуют из этого одного правила. Затем заметка разбирает четыре простейших типа, `int`, `float`, `bool` и `None`, и заканчивается тем, что значит динамическая, но строгая типизация Python.

## Отправная точка: переменная как коробка \{#baseline-a-variable-as-a-box\}

Распространённая первая картинка переменной, из школьной алгебры или из языков вроде C, — коробка с надписью. `x = 3` кладёт 3 в коробку `x`; `y = x` копирует 3 во вторую коробку `y`; изменение `y` не трогает `x`. Для чисел в Python эта картинка даёт правильные ответы. Для списка — нет:

```text
>>> a = [1, 2]
>>> b = a
>>> b.append(3)
>>> a
[1, 2, 3]
```

`b.append(3)` добавляет 3 в конец списка с именем `b`, и список с именем `a` тоже изменился. Если бы `b = a` копировало `a` в новую коробку, `a` по-прежнему было бы `[1, 2]`. Картинка с коробками неверна, а правильная должна объяснить и этот сеанс, и то, почему `x` и `y` вроде бы вели себя как коробки.

## Каждое значение — объект \{#every-value-is-an-object\}

**Правило.** Каждое значение в Python — число, строка, список, функция, даже `None` — это **объект**, и у каждого объекта есть три свойства ([справочник по языку Python, §3.1](#references)):

1. **идентичность** (identity), которая не меняется, пока объект существует; `id(obj)` возвращает её в виде целого числа, и в CPython это адрес объекта в памяти;
2. **тип** (type), который определяет, какие операции объект поддерживает; его возвращает `type(obj)`;
3. **значение** (value), его содержимое. Может ли значение меняться, зависит от типа.

```text
>>> x = 1000
>>> type(x)
<class 'int'>
>>> type([1, 2]), type("hi"), type(None), type(print)
(<class 'list'>, <class 'str'>, <class 'NoneType'>, <class 'builtin_function_or_method'>)
```

Идентичность делает объект вещью, а не числом, записанным на бумаге. Два списка могут содержать одинаковые значения и всё же быть двумя разными объектами, с двумя идентичностями, в двух местах памяти.

## Имена — ссылки, и присваивание ничего не копирует \{#names-are-references-and-assignment-copies-nothing\}

<aside class="callout"><strong>Ключевая идея.</strong> Имя — не коробка, которая хранит значение. Это ссылка на объект. Присваивание `name = expression` вычисляет выражение, получает объект и затем **связывает** (binds) имя с этим объектом; объект не копируется, а то, на что имя ссылалось раньше, не меняется. На один объект могут ссылаться несколько имён, и изменение объекта, сделанное через любое из них, видно через все.</aside>

Рисунок воспроизводит пять инструкций:

<NamesObjects />

1. `a = [1, 2]` создаёт объект-список и связывает с ним имя `a`.
2. `b = a` вычисляет `a`, что даёт тот же самый объект-список, и связывает с ним `b`. Ничего не копируется: один список, два имени.
3. `b.append(3)` просит объект, на который ссылается `b`, измениться. Это единственный существующий список, поэтому `a` тоже видит `[1, 2, 3]`.
4. `c = [1, 2, 3]` вычисляет новое выражение-список, которое создаёт новый список. `a` и `c` равны по значению и являются двумя объектами.
5. `b = b + [4]` вычисляет `b + [4]`. Для списков `+` строит **новый** список из двух операндов; затем `b` связывается с ним. Старый список не тронут, и `a` по-прежнему ссылается на него.

REPL подтверждает каждый шаг:

```text
>>> a = [1, 2]
>>> b = a
>>> b.append(3)
>>> a, a is b
([1, 2, 3], True)
>>> c = [1, 2, 3]
>>> a == c, a is c
(True, False)
>>> b = b + [4]
>>> a, b, a is b
([1, 2, 3], [1, 2, 3, 4], False)
```

**Почему это так устроено.** В CPython имя в пространстве имён — это запись, которая хранит указатель, восемь байт на 64-битной машине, каким бы ни был объект. Связывание имени записывает указатель, и это стоит одинаково для целого числа и для списка из миллиона элементов. Копирование должно было бы знать, насколько глубоко копировать, и сделало бы стоимость каждого присваивания пропорциональной размеру данных. Python делает дешёвую операцию поведением по умолчанию, а копию требует запрашивать явно: `list(a)`, `a.copy()` или `a[:]` для поверхностной копии (shallow copy) списка, `copy.deepcopy(a)` для копии всего, что внутри. Что значит «поверхностная», показывает [заметка о списках](/ru/notes/python/lists-and-tuples).

То же правило действует везде, где связывается имя, а не только при `=`: цикл `for` по очереди связывает переменную цикла с каждым элементом, `import math` связывает имя `math` с объектом-модулем, а вызов функции связывает имена её параметров с объектами-аргументами. Последнее объясняет, почему функция может изменить переданный ей список; этим занимается [заметка о функциях](/ru/notes/python/functions).

## `is` против `==` \{#is-against-\}

**Правило.** `a is b` истинно, когда `a` и `b` ссылаются на один и тот же объект, то есть когда `id(a) == id(b)`. `a == b` истинно, когда равны значения, в том смысле, как равенство определяет тип: два списка равны, когда у них равные элементы в том же порядке. `is` тип переопределить не может; `==` — метод типа, и его переопределить можно.

`==` используется для сравнения значений, а `is` — только для вопроса «это тот самый объект?». Единственное повседневное применение `is` — проверка на `None`, `x is None`, потому что объект `None` ровно один.

**Ошибка.** `is` для чисел или строк иногда как будто работает, потому что CPython повторно использует некоторые объекты:

```text
>>> a = 256
>>> b = 255 + 1
>>> a is b
True
>>> c = 257
>>> d = int("257")
>>> c is d
False
>>> c == d
True
```

CPython хранит по одному объекту для каждого целого числа от −5 до 256 и возвращает его каждый раз, когда создаётся такое число; 257 каждый раз создаётся заново ([Python C API, integer objects](#references)). Это оптимизация одной реализации, а не правило языка, и код, который на неё полагается, ломается на следующем же числе. Компилятор предупреждает, когда `is` используется с литералом:

```text
>>> x = 1000
>>> x is 1000
<python-input-1>:1: SyntaxWarning: "is" with 'int' literal. Did you mean "=="?
False
```

## Изменяемые и неизменяемые объекты \{#mutable-and-immutable-objects\}

**Правило.** Объект, значение которого может меняться после создания, называется **изменяемым** (mutable); объект, значение которого меняться не может, — **неизменяемым** (immutable). Списки, словари и множества изменяемы. Числа, строки, кортежи, `bool` и `None` неизменяемы. Неизменяемый объект не меняет ни одна операция; операция, которая как будто его меняет, создаёт новый объект и перепривязывает имя.

Это объясняет, почему картинка с коробками работала для чисел. После `y = x` оба имени ссылаются на один объект `int`, как и в случае списка. Но никакая операция не может изменить этот объект, поэтому общий доступ к нему никогда нельзя заметить; `x = x + 1` создаёт новый объект 1001 и перепривязывает `x`, оставляя `y` на 1000:

```text
>>> x = 1000
>>> y = x
>>> y is x
True
>>> x = x + 1
>>> x, y
(1001, 1000)
>>> y is x
False
```

**Составное присваивание зависит от типа.** `n += 1` для `int` создаёт новый объект и перепривязывает `n`. `nums += [3]` для списка расширяет тот же список на месте и затем снова связывает `nums` с тем же объектом:

```text
>>> nums = [1, 2]
>>> before = id(nums)
>>> nums += [3]
>>> id(nums) == before
True
>>> n = 10
>>> before = id(n)
>>> n += 1
>>> id(n) == before
False
```

Протокол, который за этим стоит: `x += y` сначала пробует метод `__iadd__` типа `x`, сложение на месте, и, если у типа его нет, переходит к `x = x + y`. У списка `__iadd__` есть, у `int` — нет ([справочник по языку Python, §7.2.1](#references)). Поэтому `b += [4]` на шаге 5 рисунка изменило бы список, на который ссылается и `a`, тогда как `b = b + [4]` этого не сделало. Как собственный класс участвует в таких протоколах, показывает [заметка о модели данных](/ru/notes/python/the-data-model).

**Неизменяемый не значит замороженный до самого дна.** Кортеж не может поменять, какие объекты он содержит, но если один из них — список, этот список может меняться:

```text
>>> t = ([1, 2], "x")
>>> t[0].append(3)
>>> t
([1, 2, 3], 'x')
>>> t[0] = [9]
Traceback (most recent call last):
  ...
TypeError: 'tuple' object does not support item assignment
```

## Неожиданности псевдонимов \{#aliasing-surprises\}

Два имени одного изменяемого объекта называются **псевдонимами** (aliases). Псевдонимы полезны — передача большого списка в функцию ничего не стоит, — но они порождают три классические ошибки. Диагноз у всех один: один объект там, где ожидалось несколько. Подтверждают его `id()` или `is`.

- **Изменённый аргумент.** Функция, которая добавляет элементы в переданный ей список, меняет список вызывающего кода, потому что параметр — ещё одно имя того же объекта.
- **Повторённый внутренний список.** `[[0] * 3] * 2` строит один внутренний список и двухэлементный список, элементы которого — две ссылки на него:

  ```text
  >>> grid = [[0] * 3] * 2
  >>> grid[0][0] = 1
  >>> grid, grid[0] is grid[1]
  ([[1, 0, 0], [1, 0, 0]], True)
  >>> grid = [[0] * 3 for _ in range(2)]
  >>> grid[0][0] = 1
  >>> grid
  [[1, 0, 0], [0, 0, 0]]
  ```

  Второй вариант вычисляет `[0] * 3` по одному разу для каждого ряда и поэтому строит два внутренних списка; `for` внутри квадратных скобок — это включение списка (list comprehension), тема [заметки об итерации](/ru/notes/python/iteration-and-generators).
- **Запомненное значение по умолчанию.** Функция, у которой аргумент по умолчанию — список, делит этот один список между всеми вызовами. Почему, объясняет [заметка о функциях](/ru/notes/python/functions#the-mutable-default-trap).

Курсы машинного обучения встречаются с псевдонимами в большем масштабе. Срез массива NumPy даёт **представление** (view), которое разделяет память с исходным массивом, так что запись в срез — это запись в массив ([Массивы NumPy](/ru/notes/python/numpy-arrays)), а операции PyTorch на месте меняют тензор, на который всё ещё ссылаются другие имена или вычисление градиента ([PyTorch и автоматическое дифференцирование](/ru/notes/deep-learning/pytorch-and-autograd#in-place-operations)).

## Числа: int, float, bool \{#numbers-int-float-bool\}

### `int`: целые числа без ограничения размера \{#int-integers-without-a-size-limit\}

`int` в Python — точное целое число любого размера. Переполнения нет:

```text
>>> 2 ** 100
1267650600228229401496703205376
>>> len(str(2 ** 10000))
3011
```

**Почему нет ограничения.** `int` в C — это фиксированное число битов, 32 или 64, и арифметика циклически переполняется, когда результат не помещается ([Биты, целые числа и порядок байтов](/ru/notes/acos/data-representation#overflow-and-wraparound)). CPython хранит `int` как заголовок, за которым следует массив **цифр** (digits) по основанию $2^{30}$, каждая в 4-байтовом целом C, и выделяет столько цифр, сколько нужно числу. Раскладку сообщает `sys.int_info`:

```text
>>> import sys
>>> sys.int_info
sys.int_info(bits_per_digit=30, sizeof_digit=4, default_max_str_digits=4300, str_digits_check_threshold=640)
>>> [sys.getsizeof(2**k) for k in (0, 29, 30, 59, 60, 89, 90)]
[28, 28, 32, 32, 36, 36, 40]
```

Заголовок занимает 24 байта в 64-битной сборке (счётчик ссылок, указатель на тип и поле, которое хранит знак и число цифр), и у каждого числа есть хотя бы одна цифра, поэтому наименьший `int` занимает 28 байт. Числу из $b$ битов нужно $\lceil b/30 \rceil$ цифр:

$$
\text{размер}(b) = 24 + 4\,\max\!\big(1, \lceil b / 30 \rceil\big) \text{ байт}.
$$

Для $2^{30}$, в котором 31 бит, это $24 + 4 \cdot 2 = 32$, как и измерено.

<IntSize />

Цена точности — скорость: каждая операция над `int` проходит циклом по его цифрам и выделяет новый объект для результата, тогда как сложение в C — одна команда. Для чисел повседневного кода (счётчиков, индексов, размеров) это одна цифра, и цикл короткий. NumPy хранит числа как машинные целые фиксированной ширины, что быстрее и может переполняться; где это важно, показывает [заметка о NumPy](/ru/notes/python/numpy-arrays). Одно намеренное ограничение существует: преобразование `int` длиннее 4300 десятичных цифр в строку возбуждает `ValueError`, если предел не поднят через `sys.set_int_max_str_digits` (начиная с Python 3.11), потому что преобразование занимает время, квадратичное по числу цифр, и им можно было бы застопорить сервер ([документация Python, ограничение длины преобразования целых чисел в строку](#references)).

**Деление.** `/` всегда даёт `float`, `//` — это **деление с округлением вниз** (floor division), которое округляет к минус бесконечности, а `%` даёт соответствующий ему остаток, так что всегда выполняется `a == (a // b) * b + a % b`:

```text
>>> 7 / 2, 7 // 2, -7 // 2, 7 % 3, -7 % 3
(3.5, 3, -4, 1, 2)
```

Для `-7 // 2` точное частное $-3.5$ округляется вниз до $-4$. Для `-7 % 3` частное с округлением вниз равно $-3$ (из $-2.33\ldots$), а остаток равен $-7 - (-3) \cdot 3 = 2$. Поэтому знак остатка совпадает со знаком делителя, и `i % n` — допустимый индекс в списке длины `n` для любого целого `i`. C вместо этого округляет к нулю, и его `%` может быть отрицательным.

### `float`: двойная точность IEEE 754 \{#float-ieee-754-double-precision\}

`float` — это 64-битное двоичное число с плавающей точкой IEEE 754, `double` из C: 53 значащих бита, что соответствует примерно 15–17 значащим десятичным цифрам ([Числа с плавающей точкой](/ru/notes/acos/floating-point#the-ieee-754-formats)). У большинства десятичных дробей нет точного двоичного представления, поэтому они хранятся округлёнными:

```text
>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False
>>> (0.1).as_integer_ratio()
(3602879701896397, 36028797018963968)
>>> from decimal import Decimal
>>> Decimal(0.1)
Decimal('0.1000000000000000055511151231257827021181583404541015625')
```

Литерал `0.1` становится ближайшим double, а это дробь $3602879701896397 / 2^{55}$, чуть больше одной десятой; `Decimal(0.1)` печатает это хранимое значение точно. `0.2` округляется так же, и сумма двух округлённых значений округляется к double, который на один шаг выше ближайшего к 0.3. [Заметка о числах с плавающей точкой](/ru/notes/acos/floating-point#why-01--02-is-not-03) проделывает эту арифметику бит за битом. Python добавляет к этому печать: `repr` числа float показывает самую короткую десятичную строку, которая читается обратно в тот же double, поэтому `0.1` отображается как `0.1`, хотя одной десятой не равно.

**Правило, которое отсюда следует.** Никогда не сравнивать результаты арифметики с плавающей точкой через `==`. Сравнивать с допуском: `math.isclose(a, b)` (относительный допуск $10^{-9}$ по умолчанию) или `abs(a - b) <= tol` с допуском, подходящим для задачи. Другие следствия той же модели:

```text
>>> round(2.675, 2)
2.67
>>> 2.0 ** 53 + 1
9007199254740992.0
>>> 1e308 * 10
inf
>>> float("nan") == float("nan")
False
```

`2.675` хранится как число чуть меньше 2.675, поэтому округляется вниз. Выше $2^{53}$ уже не все последовательные целые числа представимы, и $2^{53} + 1$ округляется до $2^{53}$. Переполнение даёт бесконечность, а не ошибку, а NaN («не число», not a number), результат неопределённых операций вроде `inf - inf`, не равен даже самому себе. Обучение сети в 32- или 16-битных числах с плавающей точкой, как в курсах глубокого обучения, усиливает каждый из этих эффектов ([Узкие форматы для машинного обучения](/ru/notes/acos/floating-point#narrow-formats-for-machine-learning)).

### `bool`: два целых числа с именами \{#bool-two-integers-with-names\}

`True` и `False` — единственные два объекта типа `bool`, который является подклассом `int`: в арифметике `True` ведёт себя как 1, а `False` — как 0.

```text
>>> True + True
2
>>> isinstance(True, int)
True
>>> sum([True, False, True, True])
3
```

Последняя строка — распространённая идиома: число элементов, прошедших проверку, равно сумме результатов проверок. Сравнения вроде `x > 0` дают `bool`, а [заметка об управлении потоком выполнения](/ru/notes/python/control-flow) показывает, как `if` превращает в него любой объект.

## `None`: отсутствие значения \{#none-the-absence-of-a-value\}

`None` — единственный объект типа `NoneType`. Он означает «здесь нет значения»: функция, которая заканчивается без `return`, возвращает `None`, и `None` — обычное значение по умолчанию для необязательного аргумента.

```text
>>> result = print("hi")
hi
>>> result is None
True
>>> None == 0, None == ""
(False, False)
```

`print` выводит текст и возвращает `None`; в REPL результат `None` не отображается, поэтому в предыдущей заметке `print("hi")` показал только `hi`. Поскольку `None` один, проверка пишется как `x is None`, а не `x == None`.

## Динамическая и строгая типизация \{#dynamic-and-strong-typing\}

**Динамическая типизация** (dynamic typing). У имени нет типа; тип есть у объекта, на который оно ссылается. Одно и то же имя может ссылаться сейчас на `int`, а потом на `str`, и ничего не проверяется до запуска программы:

```text
>>> x = 5
>>> type(x)
<class 'int'>
>>> x = "five"
>>> type(x)
<class 'str'>
```

**Строгая типизация** (strong typing). Каждая операция проверяет типы полученных объектов в момент выполнения, и Python не преобразует молча значения несвязанных типов друг в друга. Сложение строки с числом — ошибка, а не `"34"` и не `7`:

```text
>>> "3" + 4
Traceback (most recent call last):
  ...
TypeError: can only concatenate str (not "int") to str
>>> int("3") + 4, "3" * 4, 1 + 2.5
(7, '3333', 3.5)
```

Преобразование нужно написать явно: `int("3")`. Исключений немного, и они намеренные: числа свободно смешиваются (`1 + 2.5` преобразует `int` во `float`), а `bool` считается `int`. `"3" * 4` — не преобразование, а определённая операция, повторение строки. Поэтому многие ошибки в коде на Python обнаруживаются только тогда, когда выполняется строка, и это одна из причин писать [тесты](/ru/notes/python/testing) и — поскольку программа проверки может прочитать их до запуска — [аннотации типов](/ru/notes/python/type-hints).

## Ограничения \{#limitations\}

- **`id` и кэшированные целые числа — особенность CPython.** Другие реализации выдают идентичности иначе и кэшируют другие объекты; правило, что `is` сравнивает идентичность, верно везде, конкретные результаты — нет.
- **Размеры — для одной сборки.** Значения `sys.getsizeof` относятся к 64-битному CPython 3.14; в 32-битных сборках и в других версиях они другие, и они учитывают только сам объект, а не объекты, на которые он ссылается.
- **Контейнеры — позже.** Списки, кортежи, словари и множества здесь используются только для того, чтобы показать общий доступ. Их устройство, поверхностная копия и стоимость их операций — тема [раздела «Структуры данных»](/ru/notes/python/lists-and-tuples).
- **Другие числовые типы.** `complex`, `decimal.Decimal` (точная десятичная арифметика для денег) и `fractions.Fraction` (точные рациональные числа) есть в стандартной библиотеке, но здесь не рассматриваются.

## Что нужно запомнить \{#what-you-should-remember\}

- Каждое значение — объект с идентичностью, типом и значением. Имя — ссылка на объект.
- Присваивание связывает имя с объектом и ничего не копирует. Копии делаются только по запросу: `list(a)`, `a.copy()`, `copy.deepcopy(a)`.
- `==` сравнивает значения; `is` сравнивает идентичность. `is` нужен для `None` и почти ни для чего больше.
- Изменяемые объекты (списки, словари, множества) могут меняться, а значит, их можно изменить через любой псевдоним. Неизменяемые (числа, строки, кортежи) не могут; «изменение» такого объекта перепривязывает имя к новому объекту.
- `int` точен и не ограничен; `float` — double IEEE 754, поэтому результаты сравнивают с допуском; `bool` — разновидность `int`; `None` — один объект.
- Python проверяет типы во время выполнения (динамически) и не преобразует молча значения несвязанных типов (строго).

## Код \{#code\}

Скрипт по порядку проверяет каждое утверждение заметки: общий доступ и перепривязывание, с короткой меткой для идентичности каждого объекта; `+=` для неизменяемого и для изменяемого объекта; ловушку общих рядов; правила размера и деления для `int`; округление `float`; `bool` и `None`; строгую типизацию. Запуск — `python -I values.py`. Идентичности объектов меняются от запуска к запуску, поэтому скрипт печатает собственные метки, а не сырые значения `id`; размеры — для 64-битной сборки.

```python
"""Names, objects and the built-in scalar types, checked one claim at a time (Python 3.14)."""
import math
import sys

# 1. Присваивание связывает имя и никогда не копирует. Следим за объектами по идентичности.
labels = {}
def label(obj):
    """A short stable label for an object's identity: #1, #2, ... in order of first sight."""
    return labels.setdefault(id(obj), f"#{len(labels) + 1}")

a = [1, 2]
b = a                      # тот же объект
b.append(3)                # изменение видно через любое имя
c = [1, 2, 3]              # равный, но отдельный объект
print("a", label(a), a, "| b", label(b), b, "| c", label(c), c)
print("a is b:", a is b, " a == c:", a == c, " a is c:", a is c)
b = b + [4]                # + строит новый список; имя b перепривязывается
print("after b = b + [4]: a", label(a), a, "| b", label(b), b)

# 2. Неизменяемые объекты не меняются, поэтому «изменение» int перепривязывает имя
n = 1000
first = id(n)
n += 1
print("int += gives a new object:", id(n) != first)
nums = [1, 2]
first = id(nums)
nums += [3]
print("list += changes the same object:", id(nums) == first)

# 3. Ловушка общих рядов: на один внутренний список две ссылки
grid = [[0] * 3] * 2
grid[0][0] = 1
print("shared rows:", grid, grid[0] is grid[1])
grid = [[0] * 3 for _ in range(2)]
grid[0][0] = 1
print("separate rows:", grid)

# 4. У int нет фиксированной ширины: размер растёт на одну 30-битную цифру за раз
print(sys.int_info.bits_per_digit, [sys.getsizeof(2 ** k) for k in (0, 30, 60, 300)])
print(2 ** 100, (2 ** 100).bit_length())
print(7 // 2, -7 // 2, 7 % 3, -7 % 3)        # деление с округлением вниз округляет к минус бесконечности

# 5. float — это double IEEE 754: 53 значащих бита
print(0.1 + 0.2, 0.1 + 0.2 == 0.3, math.isclose(0.1 + 0.2, 0.3))
print((0.1).as_integer_ratio(), 2.0 ** 53 + 1 == 2.0 ** 53)
print(sys.float_info.epsilon, float("nan") == float("nan"))

# 6. bool — подкласс int; None — единственный объект
print(True + True, isinstance(True, int), None is None, type(None).__name__)

# 7. Строгая типизация: никаких молчаливых преобразований между str и int
try:
    "3" + 4
except TypeError as err:
    print("TypeError:", err)
print(int("3") + 4, "3" * 4, 1 + 2.5)

# Вывод в CPython 3.14.7 на 64-битной macOS (arm64); размеры — для 64-битной сборки:
# a #1 [1, 2, 3] | b #1 [1, 2, 3] | c #2 [1, 2, 3]
# a is b: True  a == c: True  a is c: False
# after b = b + [4]: a #1 [1, 2, 3] | b #3 [1, 2, 3, 4]
# int += gives a new object: True
# list += changes the same object: True
# shared rows: [[1, 0, 0], [1, 0, 0]] True
# separate rows: [[1, 0, 0], [0, 0, 0]]
# 30 [28, 32, 36, 68]
# 1267650600228229401496703205376 101
# 3 -4 1 2
# 0.30000000000000004 False True
# (3602879701896397, 36028797018963968) True
# 2.220446049250313e-16 False
# 2 True True NoneType
# TypeError: can only concatenate str (not "int") to str
# 7 3333 3.5
```
