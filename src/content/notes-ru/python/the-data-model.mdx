[Предыдущая заметка](/ru/notes/python/classes-and-objects) строила классы с атрибутами и методами. Её простые классы всё ещё ведут себя как чужие для языка: печатаются как `<__main__.Account object at 0x…>`, равны только самим себе и не работают с `len`, `+` и `for`. Встроенные типы всё это умеют, и не потому, что интерпретатор обращается с ними по-особому. Любой синтаксис, который работает с объектами, от `len(x)` до `x + y` и `with`, определён как вызов метода с именем в двойных подчёркиваниях — **специального (магического) метода** (special method) — у типа объекта. Совокупность этих методов и правил их вызова справочник языка называет **моделью данных** (data model). В этой заметке мы перечисляем самые важные протоколы, по одному добавляем их в класс `Vector` и заканчиваем двумя механизмами, которые лежат под ними: дескрипторами, на которых работают свойства и методы, и абстрактными базовыми классами, которые дают протоколу имя.

**Соглашения.** Специальные методы часто называют dunder-методами, от **d**ouble **under**score, «двойное подчёркивание»: `__len__` читается как «dunder len». Как и раньше, вывод получен на CPython 3.14.7; адреса вроде `0x1082f5e80` меняются при каждом запуске.

## Отправная точка: класс, которого Python не понимает \{#baseline-a-class-that-python-does-not-understand\}

Вектор чисел, записанный как простой класс, хранит свои компоненты и больше ничего:

```python
class Vector:
    def __init__(self, *components):
        self.components = tuple(float(x) for x in components)
```

```text
>>> v = Vector(3, 4)
>>> v
<__main__.Vector object at 0x1082f5e80>
>>> v == Vector(3, 4)
False
>>> len(v)
Traceback (most recent call last):
  ...
TypeError: object of type 'Vector' has no len()
>>> v + v
Traceback (most recent call last):
  ...
TypeError: unsupported operand type(s) for +: 'Vector' and 'Vector'
>>> for x in v: pass
...
Traceback (most recent call last):
  ...
TypeError: 'Vector' object is not iterable
```

Объект хранит правильные данные, но каждая встроенная операция либо отвергает его, либо делает что-то бесполезное. Можно добавить методы вроде `v.add(w)`, `v.length()` и `v.to_string()`; тогда у класса будет собственный словарь, который придётся учить каждому читателю, а функции, написанные для встроенных типов, такие как `sum`, `sorted` или `print`, всё равно его не поймут. Модель данных позволяет классу вместо этого отвечать на встроенный словарь языка.

## Специальные методы ищутся в типе \{#special-methods-are-looked-up-on-the-type\}

<aside class="callout"><strong>Ключевая идея.</strong> Каждая операция над объектами определена как вызов специального метода у **типа** операнда: `len(x)` — это `type(x).__len__(x)`, `x + y` начинается с `type(x).__add__(x, y)`, `for` вызывает `type(x).__iter__(x)`. Достаточно определить метод в классе, и синтаксис заработает на его объектах — вместе со всеми функциями, построенными на этом синтаксисе. Через собственный словарь экземпляра Python эти методы никогда не вызывает.</aside>

| Что мы пишем | Что вызывает Python | Протокол |
| --- | --- | --- |
| `repr(x)`, REPL показывает `x` | `__repr__` | представление |
| `str(x)`, `print(x)`, `f"{x}"` | `__str__` (запасной вариант — `__repr__`) | представление |
| `x == y`, `x != y` | `__eq__` (и `__ne__`, по умолчанию выводимый из него) | сравнение |
| `hash(x)`, `x` как ключ словаря или элемент множества | `__hash__` | хеширование |
| `len(x)` | `__len__` | размер |
| `x[i]`, `x[a:b]` | `__getitem__` | последовательность или отображение |
| `for item in x`, `list(x)`, распаковка | `__iter__` (запасной вариант — `__getitem__`) | итерируемый объект |
| `y in x` | `__contains__` (запасной вариант — итерация) | контейнер |
| `if x:`, `bool(x)` | `__bool__` (запасной вариант — `__len__`) | истинность |
| `x + y`, `x * y`, `x @ y`, `-x`, `abs(x)` | `__add__`, `__mul__`, `__matmul__`, `__neg__`, `__abs__` | числовой |
| `x(...)` | `__call__` | вызываемый объект |
| `with x as y:` | `__enter__`, `__exit__` | контекстный менеджер |

Правило «в типе» видно напрямую. Атрибут экземпляра с именем `__len__` функция `len` игнорирует:

```python
class Box:
    def __len__(self):
        return 3
```

```text
>>> b = Box()
>>> len(b), Box.__len__(b)
(3, 3)
>>> b.__len__ = lambda: 99
>>> len(b), b.__len__()
(3, 99)
```

`b.__len__()` — обычный поиск атрибута, который, как говорит [правило поиска](/ru/notes/python/classes-and-objects#where-attributes-live), сначала находит атрибут экземпляра. `len(b)` пропускает экземпляр и идёт прямо к типу. Причины — скорость и единообразие: интерпретатор хранит указатель на каждый специальный метод в C-структуре типа, поэтому `len(b)` стоит одного обращения по указателю вместо поиска в словаре, и все экземпляры типа ведут себя одинаково при одном и том же синтаксисе ([справочник Python, Data model, «Special method lookup»](#references)).

В обычном коде никогда не вызывайте специальные методы напрямую, как `v.__len__()`. Пишите `len(v)`: встроенная функция проверяет результат (`__len__` обязан вернуть неотрицательный `int`), а для операторов выполняет весь протокол, который прямой вызов пропускает, как покажет раздел об арифметике.

## Как объект печатается: `__repr__` и `__str__` \{#how-an-object-prints-\_\_repr\_\_-and-\_\_str\_\_\}

Первый шаг для `Vector` — сделать его читаемым. Методов два, потому что аудиторий две:

- `__repr__` — для программиста. Он должен быть однозначным и по возможности выглядеть как выражение, которое воссоздаёт объект. Им пользуются REPL, отладчик и контейнеры.
- `__str__` — для конечного пользователя. Им пользуются `print` и f-строки. Если класс определяет только `__repr__`, `str` берёт его.

Разницу показывает `datetime.date`:

```text
>>> import datetime
>>> d = datetime.date(2026, 10, 22)
>>> d
datetime.date(2026, 10, 22)
>>> print(d)
2026-10-22
>>> f"{d}", f"{d!r}"
('2026-10-22', 'datetime.date(2026, 10, 22)')
>>> [d]
[datetime.date(2026, 10, 22)]
```

Список печатает свои элементы через `repr`, даже внутри `print`, потому что `str` списка определён как его `repr`. Для `Vector` этот шаг — два метода; дальше каждый раздел добавляет методы в тот же класс, а полный класс приведён в разделе «Код».

```python
import math

class Vector:
    def __init__(self, *components):
        self._c = tuple(float(x) for x in components)

    def __repr__(self):
        return f"Vector({', '.join(repr(x) for x in self._c)})"

    def __str__(self):
        return "(" + ", ".join(f"{x:g}" for x in self._c) + ")"
```

```text
>>> v = Vector(3, 4)
>>> v
Vector(3.0, 4.0)
>>> print(v)
(3, 4)
>>> [v, Vector(1, -2)]
[Vector(3.0, 4.0), Vector(1.0, -2.0)]
```

Компоненты хранятся в кортеже под именем `_c` с подчёркиванием в начале: кортеж — внутренняя деталь, а интерфейсом станут протоколы ниже.

## Равенство и хеширование: `__eq__` и `__hash__` \{#equality-and-hashing-\_\_eq\_\_-and-\_\_hash\_\_\}

По умолчанию `==` сравнивает тождество: объект равен только самому себе — так работает `object.__eq__`. Тип-значение, такой как вектор, должен сравниваться по значению. У определения `__eq__` есть следствие, которое удивляет многих:

```python
class P:
    def __init__(self, x):
        self.x = x
    def __eq__(self, other):
        return isinstance(other, P) and self.x == other.x
```

```text
>>> P(1) == P(1)
True
>>> P.__hash__ is None
True
>>> {P(1)}
Traceback (most recent call last):
  ...
TypeError: cannot use 'P' as a set element (unhashable type: 'P')
```

**Правило.** Равные объекты обязаны иметь равные хеши: из `a == b` следует `hash(a) == hash(b)`. На это опираются словарь и множество: они сначала находят ключ по хешу и сравнивают через `==` только внутри корзины, которую выбрал хеш, как объясняет [заметка о словарях](/ru/notes/python/dicts-and-sets). `__hash__` по умолчанию берётся из тождества, что согласовано с `__eq__` по умолчанию. Класс, который переопределяет `__eq__` и сохраняет хеш по тождеству, нарушил бы правило, поэтому в таком классе Python присваивает `__hash__` значение `None`, и его экземпляры становятся нехешируемыми. Чтобы снова стать хешируемым, класс должен определить `__hash__` по тем же данным, которые сравнивает `__eq__`, и эти данные не должны меняться, пока объект лежит в множестве или словаре.

**Типичная ошибка: хеш, который меняется.** Здесь хеш зависит от поля, которое потом изменяется:

```python
class Key:
    def __init__(self, x):
        self.x = x
    def __eq__(self, other):
        return isinstance(other, Key) and self.x == other.x
    def __hash__(self):
        return hash(self.x)
```

```text
>>> k = Key(1)
>>> s = {k}
>>> k.x = 2
>>> k in s
False
>>> Key(1) in s
False
>>> Key(2) in s
False
>>> len(s)
1
```

Множество по-прежнему содержит один элемент, но больше не может найти его ни по какому ключу. `k in s` хеширует новое значение 2 и ищет не в той корзине; `Key(1)` находит нужную корзину, но уже не равен элементу. Хешируйте только то, что не может измениться. Поэтому списки нехешируемы, кортежи из хешируемых элементов хешируемы, а [классам данных из предыдущей заметки](/ru/notes/python/classes-and-objects#dataclasses) для хеша нужен `frozen=True`.

`Vector` хранит компоненты в неизменяемом кортеже, поэтому может быть хешируемым:

```python
    def __eq__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return self._c == other._c

    def __hash__(self):
        return hash(self._c)
```

Возврат `NotImplemented` (встроенный объект-одиночка, а не исключение) для чужого типа означает «я не умею сравниваться с этим». Тогда Python пробует `__eq__` другого операнда, а если и тот отказывается, сравнивает тождество, поэтому `Vector(3, 4) == (3, 4)` равно `False`, а не ошибке. То же значение управляет арифметическим протоколом ниже.

## Контейнеры: `__len__`, `__getitem__`, `__iter__`, `__contains__` \{#containers-\_\_len\_\_-\_\_getitem\_\_-\_\_iter\_\_-\_\_contains\_\_\}

Три метода делают `Vector` последовательностью чисел:

```python
    def __len__(self):
        return len(self._c)

    def __getitem__(self, index):
        if isinstance(index, slice):
            return Vector(*self._c[index])
        return self._c[index]

    def __iter__(self):
        return iter(self._c)
```

```text
>>> v = Vector(3, 4)
>>> len(v), v[0], v[-1], v[:1]
(2, 3.0, 4.0, Vector(3.0))
>>> list(v), 4.0 in v
([3.0, 4.0], True)
>>> x, y = v
>>> v == Vector(3.0, 4.0), v == (3, 4), {v, Vector(3, 4)}
(True, False, {Vector(3.0, 4.0)})
```

Правила:

- **`__getitem__` получает то, что стоит в квадратных скобках.** Для `v[0]` это целое число 0; для `v[:1]` — объект `slice`, `slice(None, 1, None)`. Метод выше передаёт целые числа кортежу, который сам обрабатывает отрицательные индексы и возбуждает `IndexError` при выходе за границы, а срезы оборачивает в новый `Vector`, чтобы срез вектора был вектором, как срез списка — списком.
- **`__iter__` возвращает итератор.** Это протокол из [заметки об итерации](/ru/notes/python/iteration-and-generators): `for` вызывает `iter(v)`, который вызывает `type(v).__iter__(v)`, а затем вызывает `next` на результате до `StopIteration`. Вернуть собственный итератор кортежа — простейшая правильная реализация; другая распространённая — написать `__iter__` как функцию-генератор с `yield`. Как только `__iter__` есть, работают и `list(v)`, распаковка `x, y = v`, `sum(v)`, `max(v)` и `zip`.
- **`in` использует `__contains__`, если класс его определяет.** Иначе он перебирает элементы и сравнивает каждый через `==`; если нет и `__iter__`, он вызывает `__getitem__` с 0, 1, 2, … до `IndexError`. Определяйте `__contains__`, когда класс может ответить быстрее полного просмотра, как множество со своей хеш-таблицей.
- **Истинность опирается на `__len__`.** Без `__bool__` объект ложен, когда его `__len__` возвращает 0, и истинен в остальных случаях; без обоих методов любой объект истинен. Вектор должен быть ложным, когда он нулевой, а это не то же самое, что пустой, поэтому `Vector` определяет `__bool__`.

```python
    def __abs__(self):
        return math.hypot(*self._c)

    def __bool__(self):
        return any(self._c)
```

```text
>>> abs(Vector(3, 4)), bool(Vector(0, 0)), bool(Vector(3, 4))
(5.0, False, True)
```

Старый запасной путь итерации через `__getitem__` стоит знать, потому что он объясняет одну неожиданность. Класс только с `__getitem__`, который в конце возбуждает `IndexError`, итерируем:

```python
class Seq:
    def __getitem__(self, i):
        if i >= 3:
            raise IndexError(i)
        return i * 10
```

```text
>>> list(Seq()), 20 in Seq(), 25 in Seq()
([0, 10, 20], True, False)
```

`Dataset` в PyTorch опирается на те же два метода: класс набора данных определяет `__len__` и `__getitem__`, а `DataLoader` запрашивает `len(dataset)` и индексирует его, чтобы собирать батчи ([конвейер обучения](/ru/notes/deep-learning/pytorch-and-autograd#the-training-pipeline)).

## Арифметика и `NotImplemented` \{#arithmetic-and-notimplemented\}

Теперь `Vector` поддерживает сложение, умножение на число с любой стороны, скалярное произведение через `@` (оператор матричного умножения, добавленный [PEP 465](#references) для NumPy) и смену знака:

```python
    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(*(a + b for a, b in zip(self, other, strict=True)))

    def __mul__(self, k):
        if not isinstance(k, (int, float)):
            return NotImplemented
        return Vector(*(k * x for x in self))

    def __rmul__(self, k):
        return self * k

    def __matmul__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return sum(a * b for a, b in zip(self, other, strict=True))

    def __neg__(self):
        return -1 * self
```

```text
>>> v, w = Vector(3, 4), Vector(1, -2)
>>> v + w
Vector(4.0, 2.0)
>>> 2 * v, v * 2
(Vector(6.0, 8.0), Vector(6.0, 8.0))
>>> v @ w
-5.0
>>> -w
Vector(-1.0, 2.0)
>>> v + 1
Traceback (most recent call last):
  ...
TypeError: unsupported operand type(s) for +: 'Vector' and 'int'
>>> v + Vector(1, 2, 3)
Traceback (most recent call last):
  ...
ValueError: zip() argument 2 is longer than argument 1
```

Интересна строка `2 * v`. Левый операнд — целое число 2, а `int` ничего не знает о векторах. Бинарные операторы следуют протоколу с двумя попытками:

<OperatorDispatch />

1. **Прямой метод левого операнда.** `x * y` вызывает `type(x).__mul__(x, y)`. Если результат — что угодно, кроме `NotImplemented`, это и есть значение выражения. Для `2 * v` вызов `int.__mul__(2, v)` возвращает `NotImplemented`.
2. **Отражённый метод правого операнда.** Если первый вызов вернул `NotImplemented` или метода нет, а типы операндов различаются, Python вызывает `type(y).__rmul__(y, x)` с переставленными операндами. Для `2 * v` это `Vector.__rmul__(v, 2)`, который возвращает `Vector(6.0, 8.0)`.
3. **`TypeError`.** Если оба вернули `NotImplemented`, операция не поддерживается. Для `v + 1` отказываются и `Vector.__add__(v, 1)`, и `int.__radd__(1, v)`, и Python возбуждает ошибку из сеанса выше.

Есть одно уточнение: если тип правого операнда — подкласс типа левого и у него есть собственный отражённый метод, шаг 2 выполняется раньше шага 1, чтобы подкласс мог переопределить операцию своей базы в обеих позициях ([справочник Python, Data model, «Emulating numeric types»](#references)).

**Почему возвращать `NotImplemented`, а не возбуждать исключение.** Метод, который сразу возбуждает `TypeError`, обрывает протокол и лишает другой операнд его очереди. Возврат `NotImplemented` говорит «не я, спросите другого». Именно это позволяет типу, определённому позже, например массиву NumPy или нашему `Vector`, взаимодействовать с типами, написанными до него, такими как `int`, хотя ни один из них не знает о другом. [Рисунок с оператором](#fig-operator-dispatch) показывает этот порядок; раздел «Код» печатает оба шага `2 * v`, вызывая их напрямую.

**Типичная ошибка: `sum` объектов.** `sum` начинает с целого числа 0, поэтому её первый шаг — `0 + v`:

```text
>>> sum([v, w])
Traceback (most recent call last):
  ...
TypeError: unsupported operand type(s) for +: 'int' and 'Vector'
>>> sum([v, w], Vector(0, 0))
Vector(4.0, 2.0)
```

Сообщение называет слева `int`, и это подсказка: передайте `sum` начальное значение своего типа или определите `__radd__`, принимающий 0.

**Составное присваивание** (augmented assignment). `v += w` вызывает `__iadd__`, если класс его определяет, и тот может изменить объект на месте. `Vector` его не определяет, поэтому Python переходит к `v = v + w`: новый объект, и имя `v` перепривязывается к нему. Другие имена, ссылавшиеся на старый вектор, ссылаются на него по-прежнему. У списка, который определяет `__iadd__`, `a += [2]` меняет список на месте, и изменение видят все имена, ссылающиеся на него: [заметка об именах](/ru/notes/python/values-and-names) показала разницу между перепривязкой и изменением, а здесь она сводится к наличию или отсутствию одного специального метода.

## Вызываемые объекты: `__call__` \{#callable-objects-\_\_call\_\_\}

Экземпляр, класс которого определяет `__call__`, можно вызывать как функцию. Это функция, которая хранит состояние:

```python
class Scale:
    def __init__(self, factor):
        self.factor = factor
        self.calls = 0
    def __call__(self, x):
        self.calls += 1
        return self.factor * x
```

```text
>>> double = Scale(2)
>>> double(21), double(5), double.calls
(42, 10, 2)
>>> callable(double), callable(42)
(True, False)
>>> list(map(double, [1, 2, 3]))
[2, 4, 6]
```

Это протокол, на котором держится каждая модель PyTorch. `model(x)` вызывает `nn.Module.__call__`, который выполняет зарегистрированные хуки, а затем написанный нами метод `forward`. Поэтому документация просит вызывать модуль, а не `forward` напрямую: прямой вызов пропускает хуки ([PyTorch, `nn.Module`](#references)). Сами функции — объекты, тип которых определяет `__call__`; на этом строится [следующая заметка](/ru/notes/python/closures-and-decorators).

## Контекстные менеджеры: `__enter__` и `__exit__` \{#context-managers-\_\_enter\_\_-and-\_\_exit\_\_\}

Инструкция `with` из [заметки о файлах](/ru/notes/python/files-and-exceptions) — протокол из двух методов. `with expr as name: body` делает следующее:

1. Вычисляет `expr` и получает объект **контекстного менеджера** (context manager) `cm`.
2. Вызывает `type(cm).__enter__(cm)` и связывает возвращённое значение с `name`.
3. Выполняет тело.
4. Как бы тело ни закончилось — нормально, исключением, через `return` или `break`, — вызывает `type(cm).__exit__(cm, exc_type, exc, tb)`. Три аргумента описывают исключение или все равны `None`, если его не было.
5. Если произошло исключение и `__exit__` вернул истинное значение, исключение подавляется; иначе оно распространяется дальше.

Транзакция, которая восстанавливает словарь, если её тело завершилось ошибкой, показывает оба пути:

```python
class Transaction:
    def __init__(self, data):
        self.data = data
    def __enter__(self):
        self.saved = dict(self.data)
        return self.data
    def __exit__(self, exc_type, exc, tb):
        if exc_type is not None:
            self.data.clear()
            self.data.update(self.saved)
            print("rolled back after", exc_type.__name__)
        return False
```

```text
>>> balances = {"ada": 100, "bob": 50}
>>> with Transaction(balances) as b:
...     b["ada"] -= 30
...     b["bob"] += 30
...
>>> balances
{'ada': 70, 'bob': 80}
>>> with Transaction(balances) as b:
...     b["ada"] -= 500
...     if b["ada"] < 0:
...         raise ValueError("overdrawn")
...
rolled back after ValueError
Traceback (most recent call last):
  ...
ValueError: overdrawn
>>> balances
{'ada': 70, 'bob': 80}
```

`__exit__` выполнился в обоих случаях. Он вернул `False`, поэтому `ValueError` после отката дошёл до REPL; возврат `True` проглотил бы его, а это редко то, что нужно. `contextlib.contextmanager` из стандартной библиотеки строит оба метода из функции-генератора: код до `yield` становится `__enter__`, а код после него — `__exit__`. `torch.no_grad()` — контекстный менеджер, который в `__enter__` выключает запись градиентов, а в `__exit__` восстанавливает её.

## Дескрипторы: на чём держатся свойства и методы \{#descriptors-what-powers-properties-and-methods\}

*Необязательное углубление: механизм, лежащий под свойствами, методами и правилом поиска атрибута. Остальная часть заметки от него не зависит.*

[Предыдущая заметка](/ru/notes/python/classes-and-objects#where-attributes-live) сформулировала простое правило поиска (сначала экземпляр, затем классы в порядке MRO) и назвала свойства исключением. И свойства, и методы — **дескрипторы** (descriptors): объекты, хранящиеся в классе и определяющие `__get__`, а возможно, и `__set__` или `__delete__`. Дескриптор с `__set__` или `__delete__` называется **дескриптором данных** (data descriptor), дескриптор только с `__get__` — **дескриптором не-данных** (non-data descriptor).

**Полное правило** чтения `obj.name` в том виде, как его реализует `object.__getattribute__` ([справочник Python, Data model, «Invoking descriptors»](#references)):

1. Найти `name` в классах `type(obj).__mro__`; первое совпадение назовём `attr`.
2. Если `attr` — дескриптор данных, вернуть `attr.__get__(obj, type(obj))`.
3. Иначе, если `name` есть в словаре экземпляра, вернуть это значение.
4. Иначе, если `attr` — дескриптор не-данных, вернуть `attr.__get__(obj, type(obj))`.
5. Иначе, если `attr` найден, вернуть его как есть.
6. Иначе вызвать `__getattr__` класса, если он есть, или возбудить `AttributeError`.

Присваивание `obj.name = value` вызывает `attr.__set__(obj, value)`, если `attr` — дескриптор данных, а иначе пишет в словарь экземпляра.

Функции — дескрипторы не-данных. Один этот факт объясняет связанные методы:

```text
>>> a = Account(100)
>>> f = Account.__dict__["deposit"]
>>> type(f), hasattr(f, "__get__"), hasattr(f, "__set__")
(<class 'function'>, True, False)
>>> bound = f.__get__(a, Account)
>>> bound
<bound method Account.deposit of <__main__.Account object at 0x10a5c9e80>>
>>> bound(5)
105
>>> a.deposit = "shadowed"
>>> a.deposit
'shadowed'
```

(`Account` здесь — класс из предыдущей заметки, у которого есть только баланс.) `a.deposit` доходит до шага 4 и вызывает `__get__` функции, который возвращает связанный метод, новый при каждом обращении. Поскольку функция — дескриптор не-данных, атрибут экземпляра с тем же именем побеждает на шаге 3, как показывают две последние строки. `property` определяет `__get__` и `__set__`, поэтому это дескриптор данных, и он побеждает на шаге 2 всё, что лежит в словаре экземпляра; поэтому `t.celsius = 100` в предыдущей заметке вызвал метод записи, а не сохранил 100 в `t.__dict__`.

Собственный дескриптор — это свойство, которое можно использовать повторно. Этот проверяет поле в любом классе, который его использует:

```python
class Positive:
    def __set_name__(self, owner, name):
        self.name = "_" + name
    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name)
    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(f"{self.name[1:]} must be positive, got {value}")
        setattr(obj, self.name, value)

class Layer:
    width = Positive()
    depth = Positive()
    def __init__(self, width, depth):
        self.width = width
        self.depth = depth
```

```text
>>> L = Layer(64, 3)
>>> L.width, L.__dict__
(64, {'_width': 64, '_depth': 3})
>>> L.depth = 0
Traceback (most recent call last):
  ...
ValueError: depth must be positive, got 0
```

`__set_name__` вызывается один раз, когда заканчивается тело класса, с именем, которому был присвоен дескриптор, поэтому каждый `Positive` знает, где хранить своё значение. Поля моделей Django, столбцы SQLAlchemy и `functools.cached_property` — дескрипторы. `nn.Module` в PyTorch использует соседний хук, `__setattr__`, который перехватывает каждое присваивание атрибуту модуля и регистрирует слои и параметры по мере присваивания.

## Абстрактные базовые классы против утиной типизации \{#abstract-base-classes-against-duck-typing\}

Код на Python обычно не проверяет типы. Функция, которая перебирает свой аргумент в цикле, работает со всем, у чего есть `__iter__`, а в остальных случаях падает с понятной ошибкой. Это **утиная типизация** (duck typing): объект судят по методам, которые у него есть, а не по классу, которым он объявлен. [Vector](#containers-__len__-__getitem__-__iter__-__contains__) нигде не объявлял, что он последовательность, и всё же `list(v)` и `x, y = v` работают.

Иногда программа всё же хочет спросить «последовательность ли это?», или библиотека хочет потребовать, чтобы подкласс реализовал определённые методы. **Абстрактные базовые классы** (abstract base classes, ABC) из модулей `collections.abc` и `abc` дают протоколам имена, которые понимает `isinstance`:

```text
>>> from collections.abc import Iterable, Sized, Sequence, Hashable
>>> v = Vector(3, 4)
>>> isinstance(v, Iterable), isinstance(v, Sized), isinstance(v, Hashable)
(True, True, True)
>>> isinstance(v, Sequence)
False
>>> Sequence.register(Vector)
<class 'vector.Vector'>
>>> isinstance(v, Sequence)
True
```

(Здесь `Vector` импортирован из файла `vector.py`, отсюда имя модуля в его `repr`.) ABC с одним методом — `Iterable`, `Sized`, `Hashable`, `Container` — распознают любой класс, определяющий этот метод, через хук `__subclasshook__`: это утиная типизация, ставшая проверяемой. Более богатые ABC, такие как `Sequence` и `Mapping`, по методам не определяются, потому что наличие `__len__` и `__getitem__` не доказывает, что класс подразумевает целые индексы от 0. Класс становится `Sequence`, **регистрируясь** в нём, как выше, или **наследуя** от него. Наследование вознаграждается: класс, который определяет `__len__` и `__getitem__` и наследует от `Sequence`, бесплатно получает `__contains__`, `__iter__`, `__reversed__`, `index` и `count`:

```python
from collections.abc import Sequence

class Countdown(Sequence):
    def __init__(self, n):
        self.n = n
    def __len__(self):
        return self.n
    def __getitem__(self, i):
        if not 0 <= i < self.n:
            raise IndexError(i)
        return self.n - i
```

```text
>>> c = Countdown(4)
>>> list(c), 2 in c, c.index(1), c.count(3), list(reversed(c))
([4, 3, 2, 1], True, 3, 1, [1, 2, 3, 4])
```

Чтобы определить собственный интерфейс, наследуйте от `abc.ABC` и отметьте обязательные методы декоратором `@abstractmethod`. Создать экземпляр такого класса нельзя, как и экземпляр подкласса, оставившего абстрактный метод неопределённым:

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...
    def describe(self):
        return f"{type(self).__name__} with area {self.area():.2f}"

class Square(Shape):
    def __init__(self, side):
        self.side = side
    def area(self):
        return self.side ** 2

class Circle(Shape):
    pass
```

```text
>>> Square(1.5).describe()
'Square with area 2.25'
>>> Circle()
Traceback (most recent call last):
  ...
TypeError: Can't instantiate abstract class Circle without an implementation for abstract method 'area'
```

Ошибка появляется при создании объекта, а не при первом вызове недостающего метода, — в этом и смысл ABC. **Что выбрать.** Утиная типизация — вариант по умолчанию, и она сохраняет общность кода. ABC нужны фреймворкам, которые выдают базовый класс, и тем немногим местам, где нужно ветвиться по тому, что умеет объект. Третий вариант проверяет протоколы без наследования и регистрации, ещё до запуска программы: `typing.Protocol`, которую вводит [заметка об аннотациях типов](/ru/notes/python/type-hints#structural-typing-with-protocol).

## Где модель данных используется в курсах по ML \{#where-the-ml-courses-use-the-data-model\}

- **Массивы NumPy и PyTorch** — классы, специальные методы которых выполняют арифметику: `a + b`, `a * b`, `a @ b`, `-a`, `a[1:, ::2]` и `len(a)` передаются в код на C. `__getitem__` там получает в качестве индексов кортежи и массивы — так работают `x[:, 0]` и булевы маски ([Массивы NumPy](/ru/notes/python/numpy-arrays)).
- **`nn.Module.__call__`** выполняет хуки, а затем `forward`; **`Dataset.__len__` и `__getitem__`** снабжают данными `DataLoader`; **`torch.no_grad()`** — контекстный менеджер ([Глубокое обучение](/ru/notes/deep-learning/pytorch-and-autograd#the-training-pipeline)).
- **pandas** использует `__getitem__` для выбора столбцов (`df["price"]`), операторы сравнения, возвращающие булевы маски, и `__len__` для числа строк ([pandas](/ru/notes/python/pandas)).

## Что изменилось \{#what-changed\}

| | Простой класс (отправная точка) | Класс с моделью данных |
| --- | --- | --- |
| Печать | `<__main__.Vector object at 0x…>` | `__repr__`: `Vector(3.0, 4.0)`; `__str__`: `(3, 4)` |
| `==` и хеширование | тождество | `__eq__` по значению; `__hash__` по тем же неизменяемым данным |
| `len`, индексация, `for`, `in` | `TypeError` | `__len__`, `__getitem__`, `__iter__`, `__contains__` |
| `+`, `*`, `@` | `TypeError` | прямые и отражённые методы, `NotImplemented` для отказа |
| Вызовы и `with` | невозможны | `__call__`; `__enter__` и `__exit__` |
| Работает с `sum`, `sorted`, `zip`, `print` | нет | да, потому что они построены на тех же протоколах |

## Ограничения \{#limitations\}

- Заметка охватывает протоколы, нужные большей части кода. В модели данных есть ещё расширенные сравнения (`__lt__` и остальные или `functools.total_ordering`), `__format__` для спецификаций формата, `__getattr__` и `__setattr__` для перехвата доступа к атрибутам, `__init_subclass__`, асинхронные протоколы (`__aiter__`, `__aenter__`), а также протоколы буфера и массива, которыми пользуется NumPy.
- Специальные методы, реализованные на Python, каждый раз стоят вызова на уровне Python. `Vector` — учебный пример; численный код использует массивы NumPy, специальные методы которых выполняют целые циклы на C.
- Правило дескрипторов выше — это `object.__getattribute__`. У классов и модулей свои варианты, а класс, переопределивший `__getattribute__`, может делать что угодно.

## Что нужно запомнить \{#what-you-should-remember\}

- Синтаксис — это протокол: `len(x)`, `x + y`, `for`, `in`, `with`, `x()` вызывают специальный метод у `type(x)` и никогда — через словарь экземпляра.
- `__repr__` — для программистов, `__str__` — для пользователей; сначала определяйте `__repr__`.
- Из `a == b` должно следовать `hash(a) == hash(b)`. Определение `__eq__` делает класс нехешируемым, пока он не определит `__hash__` по неизменяемым данным.
- Бинарный оператор пробует `type(x).__op__(x, y)`, затем `type(y).__rop__(y, x)`, затем возбуждает `TypeError`. Чтобы отказаться, возвращайте `NotImplemented` и никогда не возбуждайте исключение.
- `__exit__` выполняется, как бы ни закончилось тело `with`; истинное возвращённое значение подавляет исключение.
- Свойства и методы — дескрипторы: дескрипторы данных побеждают словарь экземпляра, дескрипторы не-данных ему уступают.
- Утиная типизация — вариант по умолчанию; ABC дают протоколу имя для `isinstance` и требуют реализации абстрактных методов при создании экземпляра.

## Код \{#code\}

Скрипт собирает полный `Vector` из заметки и проверяет каждый протокол: печать, равенство и хеширование, протокол последовательности, арифметику с явно выписанными двумя шагами `2 * v`, ошибки, которые даёт протокол, поиск специальных методов в типе, множество, теряющее элемент с изменившимся хешем, контекстный менеджер, вызываемый объект, дескриптор и проверки ABC. Ему нужна только стандартная библиотека; запуск — `python -I vector.py`.

```python
"""The data model: a Vector class that works with Python's syntax, plus the other protocols (Python 3.14)."""
import math
from collections.abc import Iterable, Sequence

class Vector:
    def __init__(self, *components):
        self._c = tuple(float(x) for x in components)

    # как объект печатается
    def __repr__(self):
        return f"Vector({', '.join(repr(x) for x in self._c)})"

    def __str__(self):
        return "(" + ", ".join(f"{x:g}" for x in self._c) + ")"

    # равенство и хеширование: у равных векторов равные хеши
    def __eq__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return self._c == other._c

    def __hash__(self):
        return hash(self._c)

    # протокол последовательности: len, индексация, срезы, итерация
    def __len__(self):
        return len(self._c)

    def __getitem__(self, index):
        if isinstance(index, slice):
            return Vector(*self._c[index])
        return self._c[index]

    def __iter__(self):
        return iter(self._c)

    # числовые протоколы
    def __abs__(self):
        return math.hypot(*self._c)

    def __bool__(self):
        return any(self._c)

    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(*(a + b for a, b in zip(self, other, strict=True)))

    def __mul__(self, k):
        if not isinstance(k, (int, float)):
            return NotImplemented
        return Vector(*(k * x for x in self))

    def __rmul__(self, k):
        return self * k

    def __matmul__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return sum(a * b for a, b in zip(self, other, strict=True))

    def __neg__(self):
        return -1 * self

v, w = Vector(3, 4), Vector(1, -2)
print(repr(v), str(v), [v, w])
print(v == Vector(3.0, 4.0), v == (3, 4), len({v, Vector(3, 4), w}))
print(len(v), v[0], v[-1], v[:1], list(v), 4.0 in v)
print(abs(v), bool(Vector(0, 0)), v + w, 2 * v, v @ w, -w)
print(int.__mul__(2, v), Vector.__rmul__(v, 2))          # два шага, из которых состоит 2 * v
for expr in ("v + 1", "sum([v, w])", "v + Vector(1, 2, 3)"):
    try:
        eval(expr)
    except (TypeError, ValueError) as err:
        print(f"{expr}: {type(err).__name__}: {err}")
print(sum([v, w], Vector(0, 0)))

# специальные методы ищутся в типе, а не в экземпляре
v.__len__ = lambda: 99
print(len(v), v.__len__())

# хеш меняется после того, как объект сохранён: множество его теряет
class Key:
    def __init__(self, x):
        self.x = x
    def __eq__(self, other):
        return isinstance(other, Key) and self.x == other.x
    def __hash__(self):
        return hash(self.x)

k = Key(1)
s = {k}
k.x = 2
print(k in s, Key(1) in s, Key(2) in s, len(s))

# контекстный менеджер: __enter__ и __exit__
class Transaction:
    def __init__(self, data):
        self.data = data
    def __enter__(self):
        self.saved = dict(self.data)
        return self.data
    def __exit__(self, exc_type, exc, tb):
        if exc_type is not None:
            self.data.clear()
            self.data.update(self.saved)
            print("rolled back after", exc_type.__name__)
        return False                     # не подавлять исключение

balances = {"ada": 100, "bob": 50}

        self.calls += 1

# дескриптор: то, из чего сделано свойство
class Positive:
    def __set_name__(self, owner, name):
        self.name = "_" + name
    def __get__(self, obj, objtype=None):
        return self if obj is None else getattr(obj, self.name)
    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(f"{self.name[1:]} must be positive, got {value}")
        setattr(obj, self.name, value)

class Layer:
    width = Positive()
    def __init__(self, width):
        self.width = width

layer = Layer(64)
print(layer.width, vars(layer))
try:
    layer.width = 0
```
