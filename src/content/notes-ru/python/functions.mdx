Программы [предыдущей заметки](/ru/notes/python/control-flow) уже повторяют себя: тот же цикл по другому списку, та же проверка, написанная дважды. **Функция** (function) даёт блоку кода имя и список входов, чтобы его можно было написать один раз и использовать многократно и чтобы читатель мог понимать программу по одному именованному куску за раз. Эта заметка точно формулирует, как вызов передаёт аргументы, — оказывается, это правило присваивания из заметки [Значения, типы и имена](/ru/notes/python/values-and-names), применённое ещё раз, — где функция ищет имя и что интерпретатор держит в памяти, пока функции вызывают друг друга и самих себя.

## Отправная точка: копирование и вставка \{#baseline-copy-and-paste\}

Без функций, чтобы вычислить среднее двух списков, вычисление приходится писать дважды:

```python
week1, week2 = [12, 15, 9], [7, 8]
total = 0
for v in week1:
    total += v
mean1 = total / len(week1)
total = 0
for v in week2:
    total += v
mean2 = total / len(week2)
```

Каждая копия — место, где может завестись своя ошибка, исправление нужно вносить в каждую копию, а читатель должен догадаться, что блоки делают одно и то же. Функция записывает вычисление один раз, даёт ему имя и делает меняющуюся часть, список, явным входом.

## Определение и вызов функции \{#defining-and-calling-a-function\}

**Правило.** `def name(parameters):` с последующим блоком с отступом создаёт **объект-функцию** (function object) и связывает с ним `name`. Блок пока не выполняется. **Вызов** (call), `name(arguments)`, выполняет блок, связав параметры с аргументами. `return expression` завершает вызов и делает значение выражения значением вызова. Функция, которая заканчивается без `return` или голым `return`, возвращает `None`.

```text
>>> def area(width, height):
...     return width * height
...
>>> area(3, 4)
12
>>> def greet(name):
...     print("hello,", name)
...
>>> r = greet("Ada")
hello, Ada
>>> print(r)
None
```

`greet` печатает, то есть производит побочный эффект (side effect), и не возвращает ничего полезного; `area` возвращает значение и ничего не печатает. Предпочтительны функции второго вида: значение можно напечатать, проверить в тесте, сохранить или передать дальше, а напечатанное можно только прочитать.

Два слова в правиле означают разное. **Параметры** (parameters) — это имена в определении, `width` и `height`. **Аргументы** (arguments) — это значения в вызове, `3` и `4`. Вызов связывает каждый параметр с аргументом.

## Как аргументы связываются с параметрами \{#how-arguments-are-bound-to-parameters\}

**Правило.** Вызов создаёт новое пространство имён для локальных имён функции и связывает каждый параметр с объектом-аргументом точно так же, как это сделало бы присваивание: объект не копируется. Аргументы сопоставляются с параметрами двумя способами:

- **позиционные** (positional) аргументы, `area(3, 4)`, заполняют параметры слева направо;
- **именованные** (keyword) аргументы, `area(height=4, width=3)`, называют параметр, который заполняют, в любом порядке, после всех позиционных.

Каждый параметр без значения по умолчанию должен получить ровно одно значение, и ни один аргумент не должен остаться лишним. У каждого нарушения своё сообщение:

```text
>>> area(3)
Traceback (most recent call last):
  ...
TypeError: area() missing 1 required positional argument: 'height'
>>> area(3, 4, 5)
Traceback (most recent call last):
  ...
TypeError: area() takes 2 positional arguments but 3 were given
>>> area(3, width=4)
Traceback (most recent call last):
  ...
TypeError: area() got multiple values for argument 'width'
>>> area(3, depth=4)
Traceback (most recent call last):
  ...
TypeError: area() got an unexpected keyword argument 'depth'
```

В третьем вызове 3 заполняет `width` по позиции, а затем именованный аргумент заполняет его ещё раз.

**Почему важно, что объект не копируется.** Параметр — ещё одно имя для объекта вызывающего кода. Если объект изменяемый, функция может его изменить, и вызывающий код увидит изменение:

```python
def add_total(numbers):
    numbers.append(sum(numbers))

values = [1, 2, 3]
add_total(values)
print(values)          # [1, 2, 3, 6]
```

Перепривязывание параметра, `numbers = [0]`, изменило бы только локальное имя функции и не тронуло бы `values`. Это правило иногда называют **передачей по соиспользованию** (call by sharing): это ни передача «по значению» (ничего не копируется), ни «по ссылке» (имя вызывающего кода нельзя перепривязать). Функция, которая меняет свой аргумент, должна говорить об этом в имени или в строке документации; функция, которая не должна его менять, может работать с копией, `list(numbers)`.

## Значения по умолчанию \{#default-values\}

У параметра может быть значение по умолчанию (default), `def power(base, exponent=2):`, которое используется, когда вызов не передаёт для него аргумент. Параметры со значениями по умолчанию должны идти после параметров без них.

```text
>>> def power(base, exponent=2):
...     return base ** exponent
...
>>> power(5), power(5, 3), power(base=2, exponent=10)
(25, 125, 1024)
>>> power.__defaults__
(2,)
```

**Правило, которое важно.** Значение по умолчанию вычисляется **один раз**, когда выполняется инструкция `def`, и хранится в объекте функции в `__defaults__`. Каждый вызов, в котором аргумент опущен, связывает параметр с этим самым хранимым объектом.

## Ловушка изменяемого значения по умолчанию \{#the-mutable-default-trap\}

Когда значение по умолчанию — изменяемый объект, из правила выше следует, что все вызовы делят его между собой:

```text
>>> def add_item(item, bag=[]):
...     bag.append(item)
...     return bag
...
>>> add_item("apple")
['apple']
>>> add_item("pear")
['apple', 'pear']
>>> add_item.__defaults__
(['apple', 'pear'],)
```

Построчно: `def` один раз вычислила `[]` и сохранила список в `__defaults__`. Первый вызов связал `bag` с этим списком и добавил `"apple"`. Второй вызов связал `bag` с **тем же** списком, в котором уже был `"apple"`. Значение по умолчанию — не «каждый раз новый пустой список»; это один конкретный список, и он растёт.

**Как её распознать.** Функция с каждым вызовом возвращает всё больше данных; или результаты зависят от того, что делали более ранние, никак не связанные вызовы. Линтеры отмечают изменяемые значения по умолчанию, а `__defaults__` показывает накопленное состояние.

**Исправление.** Использовать `None` как значение по умолчанию и создавать объект внутри функции, чтобы новый объект появлялся при каждом вызове, которому он нужен:

```text
>>> def add_item(item, bag=None):
...     if bag is None:
...         bag = []
...     bag.append(item)
...     return bag
...
>>> add_item("apple"), add_item("pear")
(['apple'], ['pear'])
```

То же правило срабатывает с любым значением по умолчанию, вычисленным из состояния мира: `def stamp(t=time.time()):` запоминает время, когда функция была определена, и каждый вызов возвращает его.

## Любое число аргументов: `*args` и `**kwargs` \{#any-number-of-arguments-args-and-kwargs\}

**Правило.** Параметр, записанный как `*args`, собирает в кортеж все позиционные аргументы, которые не забрал никакой другой параметр. Параметр, записанный как `**kwargs`, собирает в словарь все именованные аргументы, которые не забрал никакой другой параметр. Имена `args` и `kwargs` — соглашение; синтаксис — это звёздочки.

```text
>>> def total(*numbers):
...     print(type(numbers), numbers)
...     return sum(numbers)
...
>>> total(1, 2, 3)
<class 'tuple'> (1, 2, 3)
6
>>> def f(a, *args, **kwargs):
...     return a, args, kwargs
...
>>> f(1, 2, 3, x=4)
(1, (2, 3), {'x': 4})
```

В вызове звёздочки работают в обратную сторону: `*` распаковывает последовательность в позиционные аргументы, а `**` распаковывает словарь в именованные. Вместе они позволяют функции передать дальше всё, что она получила, и так пишутся обёртки:

```text
>>> values = [3, 4]
>>> area(*values)
12
>>> area(**{"width": 2, "height": 5})
10
>>> def scaled_area(*args, scale=1, **kwargs):
...     return scale * area(*args, **kwargs)
...
>>> scaled_area(3, 4), scaled_area(3, height=4, scale=10)
(12, 120)
```

Именно на этом шаблоне строится [заметка о декораторах](/ru/notes/python/closures-and-decorators). Библиотеки используют `**kwargs` для передачи параметров дальше: функция построения графика, которая принимает `**kwargs` и передаёт их функции, рисующей линию, — вот почему вызовы Matplotlib принимают так много именованных аргументов ([графики](/ru/notes/python/plotting)).

## Параметры только именованные и только позиционные \{#keyword-only-and-positional-only-parameters\}

Два маркера в списке параметров ограничивают способы передачи аргументов ([PEP 3102](#references), [PEP 570](#references)):

- Параметры после `*` (или после `*args`) — **только именованные** (keyword-only): их можно передать только по имени.
- Параметры до `/` — **только позиционные** (positional-only): их нельзя передать по имени.

```text
>>> def connect(host, *, port=80, timeout=5.0):
...     return f"{host}:{port} (timeout {timeout})"
...
>>> connect("example.org", port=8080)
'example.org:8080 (timeout 5.0)'
>>> connect("example.org", 8080)
Traceback (most recent call last):
  ...
TypeError: connect() takes 1 positional argument but 2 were given
>>> def clamp(x, /, low=0.0, high=1.0):
...     return min(max(x, low), high)
...
>>> clamp(1.7), clamp(-3, low=-1)
(1.0, -1)
>>> clamp(x=0.5)
Traceback (most recent call last):
  ...
TypeError: clamp() got some positional-only arguments passed as keyword arguments: 'x'
```

Только именованные параметры подходят для настроек, особенно для флагов: `connect("example.org", 8080)` было бы непонятно в месте вызова, а `fit(X, y, True)` — тем более. Только позиционные параметры подходят для аргументов, имя которых ничего не говорит вызывающему, вроде `x` в `clamp`, и оставляют автору свободу позже их переименовать. Полный порядок списка параметров: только позиционные, `/`, обычные, `*args` или `*`, только именованные, `**kwargs`. Раздел «Код» использует все пять видов параметров в одной сигнатуре.

## Функции — это объекты \{#functions-are-objects\}

`def` связывает имя с объектом-функцией, и этот объект можно использовать как любой другой: связать с другим именем, сохранить в списке, передать как аргумент, вернуть из другой функции.

```text
>>> def shout(text):
...     return text.upper() + "!"
...
>>> say = shout
>>> say("hi")
'HI!'
>>> words = ["kiwi", "fig", "banana"]
>>> sorted(words, key=len)
['fig', 'kiwi', 'banana']
>>> sorted(words, key=lambda w: w[-1])
['banana', 'fig', 'kiwi']
```

`sorted` вызывает функцию, переданную как `key`, для каждого элемента и сортирует по результатам: по длине, затем по последней букве. `lambda w: w[-1]` — это **лямбда-функция** (lambda), выражение, которое создаёт маленькую безымянную функцию, тело которой — одно выражение; она избавляет от `def` ради одноразового ключа. Передача функций в качестве аргументов проходит через все курсы машинного обучения: оптимизатор получает функцию потерь, которую надо минимизировать, загрузчик данных — преобразование, которое надо применить к каждому примеру.

## Где ищется имя: область видимости \{#where-a-name-is-looked-up-scope\}

<aside class="callout"><strong>Ключевая идея.</strong> Каждый вызов получает новый **кадр** (frame): собственное пространство локальных имён, в котором параметры связаны с объектами-аргументами. Внутри тела имя ищется в четырёх местах по порядку — **L**ocal (локальная область этого вызова), **E**nclosing (объемлющие функции, внутри которых определена эта), **G**lobal (глобальная область модуля) и **B**uilt-in (встроенные имена: `len`, `print`, …), — и побеждает первое найденное связывание. Какие имена локальны, решает компилятор: имя, которому тело где-либо присваивает значение, локально во всём теле.</aside>

```text
>>> x = "global"
>>> def outer():
...     x = "enclosing"
...     def inner():
...         return x
...     return inner()
...
>>> outer(), x
('enclosing', 'global')
```

У `inner` нет локального `x`, поэтому поиск продолжается в объемлющей функции `outer` и находит `"enclosing"`. Присваивание в `outer` создало локальный `x` функции `outer` и не тронуло глобальный. Чтобы прочитать глобальное имя из функции, ничего особенного не нужно; локальное имя создаёт именно присваивание.

**Ошибка: `UnboundLocalError`.** Функция, которая читает глобальную переменную, а затем присваивает ей значение, падает на чтении:

```text
>>> count = 0
>>> def increment():
...     count += 1
...
>>> increment()
Traceback (most recent call last):
  ...
  File "<python-input-1>", line 2, in increment
    count += 1
    ^^^^^
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

**Почему.** Компилятор определяет области видимости один раз, для всего тела функции, до того как оно выполнится. Он видит присваивание `count += 1` и делает `count` локальным везде в `increment`, включая правую часть этой же инструкции. Когда вызов выполняется, локальная `count` ещё не связана, и чтение завершается ошибкой. К глобальной `count` никто не обращается. (Скомпилированный код читает локальные имена командой `LOAD_FAST` из фиксированной ячейки кадра, а глобальные — командой `LOAD_GLOBAL` из словаря модуля; решение зафиксировано в байт-коде.)

Тот же порядок поиска объясняет менее заметную ошибку: связывание глобального имени, которое заслоняет встроенное. После `len = 5` вызов `len("abc")` первым находит глобальное `len` и падает с `TypeError: 'int' object is not callable`; `del len` удаляет глобальное имя, и поиск снова доходит до встроенного. Не стоит называть переменные `list`, `dict`, `str`, `sum`, `max` и `id`.

**`global` и `nonlocal`.** `global name` внутри функции направляет присваивания `name` в переменную модуля. `nonlocal name` направляет их в переменную ближайшей объемлющей функции:

```text
>>> def make_counter():
...     n = 0
...     def step():
...         nonlocal n
...         n += 1
...         return n
...     return step
...
>>> c = make_counter()
>>> c(), c(), c()
(1, 2, 3)
```

`make_counter` уже вернула управление, а её переменная `n` продолжает жить: на неё ссылается `step`, и каждый вызов `c` её увеличивает. Функция, которая сохраняет переменные функции, в которой она определена, называется **замыканием** (closure); переменная хранится в маленьком объекте — ячейке (cell), которую видно как `c.__closure__`. Замыкания — механизм, на котором держатся декораторы, и подробно их разбирает [заметка о замыканиях](/ru/notes/python/closures-and-decorators). `global` стоит использовать экономно: функцию, которая меняет состояние модуля, труднее тестировать и понимать, чем функцию, которая принимает входы и возвращает результат.

## Рекурсия и стек вызовов \{#recursion-and-the-call-stack\}

Функция может вызывать саму себя. Такой **рекурсивной** (recursive) функции нужен **базовый случай** (base case), в котором она возвращает значение, не вызывая себя, и каждый рекурсивный вызов должен приближаться к нему. Факториал $n! = n \cdot (n-1)!$ с $0! = 1$ переводится напрямую:

```python
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)
```

Как `n` может одновременно быть 3, 2 и 1? У каждого вызова свой кадр со своим `n`. Кадры образуют стек — **стек вызовов** (call stack): вызов кладёт новый кадр наверх, возврат снимает его и передаёт значение кадру ниже, который продолжает с того места, где ждал.

<CallStack />

1. Модуль вызывает `factorial(3)`, и тот получает кадр с `n = 3`.
2. Этот кадр доходит до `n * factorial(n - 1)`, вызывает `factorial(2)` и ждёт; кладётся кадр с `n = 2`.
3. То же происходит ещё раз: кадр с `n = 1`.
4. И ещё раз: кадр с `n = 0`.
5. Кадр с `n = 0` попадает в базовый случай и никого не вызывает.
6. Он возвращает 1, и его кадр уничтожается.
7. Кадр с `n = 1` завершает умножение, $1 \cdot 1 = 1$, и возвращает 1.
8. Кадр с `n = 2` вычисляет $2 \cdot 1 = 2$ и возвращает 2.
9. Кадр с `n = 3` вычисляет $3 \cdot 2 = 6$ и возвращает 6 модулю.

Версия, которая печатает на пути вниз и на пути вверх, показывает тот же порядок:

```text
>>> def factorial(n, depth=0):
...     print("  " * depth + f"call factorial({n})")
...     if n == 0:
...         result = 1
...     else:
...         result = n * factorial(n - 1, depth + 1)
...     print("  " * depth + f"factorial({n}) returns {result}")
...     return result
...
>>> factorial(3)
call factorial(3)
  call factorial(2)
    call factorial(1)
      call factorial(0)
      factorial(0) returns 1
    factorial(1) returns 1
  factorial(2) returns 2
factorial(3) returns 6
6
```

Трассировка — это распечатка этого стека в момент ошибки, самый старый кадр первым; одну такую читала [первая заметка](/ru/notes/python/running-python#errors-and-how-to-read-a-traceback). Стек — та же идея, которую процессор реализует аппаратно для процедур машинного кода ([Процедуры, стек и соглашения о вызовах](/ru/notes/acos/procedures-and-the-stack#the-stack-and-stack-frames)), с одним отличием: кадр CPython — это объект Python, который хранит локальные переменные функции, её позицию в байт-коде и собственный стек значений. Начиная с CPython 3.11 вызов функции Python из кода на Python не увеличивает стек C: интерпретатор устраивает новый кадр в памяти, которой управляет сам, и продолжает в том же цикле ([What's New in Python 3.11](#references)).

**Предел глубины рекурсии.** Каждый кадр стоит памяти, а рекурсия без достижимого базового случая никогда бы не остановилась. CPython считает кадры и возбуждает `RecursionError`, когда глубина превышает предел, по умолчанию 1000:

```text
>>> import sys
>>> sys.getrecursionlimit()
1000
>>> def down(n):
...     return down(n + 1)
...
>>> down(0)
Traceback (most recent call last):
  ...
  File "<python-input-0>", line 2, in down
    return down(n + 1)
  [Previous line repeated 992 more times]
RecursionError: maximum recursion depth exceeded
```

Трассировка сворачивает повторяющиеся кадры в одну строку. `sys.setrecursionlimit` поднимает предел, рискуя аварийным завершением, если более глубокий стек не поместится в памяти ([документация `sys`](#references)). Python не оптимизирует хвостовые вызовы (tail calls), поэтому рекурсию глубиной $10^5$ уровней, например обход связного списка из $10^5$ узлов, нужно писать циклом. Рекурсия естественна для данных, которые сами рекурсивны, например для дерева: [заметка о решающих деревьях](/ru/notes/ml/decision-trees#greedy-split-search-and-its-cost) курса машинного обучения строит дерево, выбирая разбиение и рекурсивно спускаясь в каждого потомка, и глубина рекурсии равна глубине дерева, далёкой от предела.

## Строки документации \{#docstrings\}

Строковый литерал, стоящий первой инструкцией тела функции, — её **строка документации** (docstring). Она хранится в объекте функции как `__doc__` и показывается функцией `help()` и редакторами:

```text
>>> def mean(xs):
...     """Return the arithmetic mean of a non-empty sequence of numbers."""
...     return sum(xs) / len(xs)
...
>>> mean.__doc__
'Return the arithmetic mean of a non-empty sequence of numbers.'
>>> help(mean)
Help on function mean:

mean(xs)
    Return the arithmetic mean of a non-empty sequence of numbers.
```

Соглашение ([PEP 257](#references)): одна строка, которая говорит, что делает функция, в повелительном наклонении, с точкой в конце; затем при необходимости пустая строка и более длинное описание аргументов, возвращаемого значения, побочных эффектов и возбуждаемых исключений. Строка документации формулирует контракт, чтобы вызывающему не нужно было читать тело. Здесь контракт говорит «non-empty» («непустой»), и это сообщает вызывающему, что `mean([])` — его ошибка. [Аннотации типов](/ru/notes/python/type-hints) формулируют типы в контракте в виде, который может проверить программа проверки.

<aside class="callout"><strong>Проверьте себя.</strong> (1) Что возвращает `def f(a, b=[]): b.append(a); return len(b)` для `f(1)`, `f(2)`, `f(3, [])`, `f(4)`? (2) Какие вызовы `def g(a, /, b, *, c): ...` допустимы: `g(1, 2, c=3)`, `g(a=1, b=2, c=3)`, `g(1, b=2, c=3)`, `g(1, 2, 3)`? (3) Почему `def h(): print(x); x = 1` возбуждает `UnboundLocalError`, даже если глобальная `x` существует? (4) Сколько кадров `factorial` существует одновременно, самое большее, пока выполняется `factorial(5)`? (5) Функции нужно обработать вложенную структуру списков глубиной 50 000 уровней. Почему не рекурсия и что вместо неё?<details><summary>Ответы</summary>(1) 1, 2, 1, 3. Список по умолчанию создаётся один раз и растёт при `f(1)`, `f(2)` и `f(4)`; `f(3, [])` передаёт собственный новый список. (2) `g(1, 2, c=3)` и `g(1, b=2, c=3)`. `g(a=1, ...)` передаёт только позиционный `a` по имени, а `g(1, 2, 3)` передаёт только именованный `c` по позиции. (3) Присваивание `x = 1` где угодно в теле делает `x` локальной во всём теле, поэтому `print(x)` читает локальное имя, которое ещё не связано; к глобальной переменной никто не обращается. (4) Шесть: для `n = 5, 4, 3, 2, 1, 0`, все они существуют, когда выполняется базовый случай (плюс кадр вызывающего кода под ними). (5) 50 000 кадров превышают предел по умолчанию 1000, а поднимать предел так высоко — значит рисковать нехваткой памяти под стек. Нужен цикл с явным списком в роли стека работы, которую ещё предстоит сделать.</details></aside>

## Что изменилось \{#what-changed\}

| | Копирование и вставка (отправная точка) | Функции |
| --- | --- | --- |
| Вычисление записывается | по разу на каждое использование | один раз и вызывается по имени |
| Входы | вписываются в каждую копию | параметры, связанные с аргументами, по позиции или по имени |
| Передача данных | — | связывание, а не копирование: изменяемый аргумент функция может изменить |
| Имена внутри | общие для всей программы | локальные для каждого вызова; порядок поиска: локальные, объемлющие, глобальные, встроенные |
| Повторение одной и той же структуры | только циклы | ещё и рекурсия, по кадру на вызов, по умолчанию до 1000 кадров |
| Документация | комментарии | строка документации в объекте функции |

## Ограничения \{#limitations\}

- **Замыкания и декораторы лишь обозначены.** Как замыкание сохраняет свои переменные, ловушка позднего связывания у замыканий, созданных в цикле, и функции, которые оборачивают функции, — в [заметке о замыканиях и декораторах](/ru/notes/python/closures-and-decorators).
- **Аннотации отложены.** Аннотации параметров и возвращаемого значения (`def area(w: float, h: float) -> float:`) и то, как 3.14 вычисляет их лениво, — в [заметке об аннотациях типов](/ru/notes/python/type-hints).
- **Стоимость вызова.** Вызов в Python выделяет кадр и связывает каждый аргумент, что стоит намного дороже вызова в C; когда это важно и что с этим делать — в заметке [Быстрый код на Python](/ru/notes/python/performance).
- **Генераторы и сопрограммы** — функции, которые могут приостановиться посреди своего кадра; они появятся в заметках об [итерации](/ru/notes/python/iteration-and-generators) и о [конкурентности](/ru/notes/python/concurrency).

## Что нужно запомнить \{#what-you-should-remember\}

- `def` создаёт объект-функцию и связывает с ним имя; вызов выполняет тело, связав параметры с аргументами; без `return` результат — `None`.
- Аргументы связываются, а не копируются. Функция может изменить изменяемый аргумент, и вызывающий код увидит изменение.
- Значения по умолчанию вычисляются один раз, во время выполнения `def`. Изменяемое значение по умолчанию использовать нельзя; вместо него — `None` и создание объекта внутри.
- `*args` собирает лишние позиционные аргументы в кортеж, `**kwargs` — лишние именованные аргументы в словарь; в вызове `*` и `**` распаковывают. Параметры после `*` — только именованные, до `/` — только позиционные.
- Имена ищутся в порядке: локальные, объемлющие, глобальные, встроенные. Любое присваивание в теле делает имя локальным во всём теле; `global` и `nonlocal` перенаправляют присваивание.
- У каждого вызова свой кадр в стеке вызовов; рекурсии нужен базовый случай, и по умолчанию она ограничена примерно 1000 уровней.
- Строка документации сообщает вызывающему, что делает функция.

## Код \{#code\}

Скрипт проверяет каждое правило заметки: одну сигнатуру со всеми пятью видами параметров, исследованную через `inspect.signature`; ловушку изменяемого значения по умолчанию и её исправление; аргумент, изменённый функцией; правила областей видимости, `UnboundLocalError` и `nonlocal`; кадры рекурсии, подсчитанные изнутри неё, и предел рекурсии; строку документации. Запуск — `python -I functions.py`; скрипт использует только стандартную библиотеку.

```python
"""Functions: parameters, defaults, scope, recursion and frames (Python 3.14)."""
import inspect
import sys

# 1. Все виды параметров в одной сигнатуре
def fit(data, /, model="linear", *extra, epochs=10, verbose=False, **options):
    """Pretend to fit a model and report how the arguments were bound."""
    return f"data={data} model={model} extra={extra} epochs={epochs} verbose={verbose} options={options}"

print(fit([1, 2]))
print(fit([1, 2], "tree", 3, 4, epochs=5, seed=0))
for name, p in inspect.signature(fit).parameters.items():
    print(f"  {name:8} {p.kind.name}")
for bad in ("fit(data=[1])", "fit([1], 'tree', 3, model='x')"):   # data=[1] попадает в **options
    try:
        eval(bad)
    except TypeError as err:
        print("TypeError:", err)

# 2. Значения по умолчанию вычисляются один раз, когда выполняется def
def append_to(item, bucket=[]):
    bucket.append(item)
    return bucket

print(append_to(1), append_to(2), append_to.__defaults__)   # оба вызова возвращают один и тот же список по умолчанию

def append_to_fixed(item, bucket=None):
    if bucket is None:          # новый список при каждом вызове, которому он нужен
        bucket = []
    bucket.append(item)
    return bucket

print(append_to_fixed(1), append_to_fixed(2))

# 3. Аргументы связываются с параметрами, а не копируются
def add_total(numbers):
    numbers.append(sum(numbers))

values = [1, 2, 3]
add_total(values)
print(values)

# 4. Области видимости: локальная, объемлющая, глобальная, встроенная
x = "global"
def outer():
    x = "enclosing"
    def inner():
        return x, len("abc")    # x из объемлющей функции, len из встроенных
    return inner()
print(outer(), x)

counter = 0
def broken_increment():
    counter += 1                # присваивание делает counter локальным во всей функции
try:
    broken_increment()
except UnboundLocalError as err:
    print("UnboundLocalError:", err)

def make_counter():
    count = 0
    def step():
        nonlocal count          # перепривязываем переменную объемлющей функции
        count += 1
        return count
    return step
c = make_counter()
print(c(), c(), c(), c.__code__.co_freevars)

# 5. Рекурсия: у каждого вызова свой кадр в стеке вызовов
def factorial(n):
    if n == 0:
        depth = 0
        frame = sys._getframe()
        while frame.f_code.co_name == "factorial":
            depth += 1
            frame = frame.f_back
        print("frames of factorial at the base case:", depth)
        return 1
    return n * factorial(n - 1)
print(factorial(5))

def depth(n):
    return depth(n + 1) if n < 10**6 else n
try:
    depth(0)
except RecursionError as err:
    print("RecursionError:", err, "| limit", sys.getrecursionlimit())

# 6. Строки документации хранятся в объекте функции
print(fit.__doc__)

# Вывод в CPython 3.14.7 (одинаковый на любой платформе):
# data=[1, 2] model=linear extra=() epochs=10 verbose=False options={}
# data=[1, 2] model=tree extra=(3, 4) epochs=5 verbose=False options={'seed': 0}
#   data     POSITIONAL_ONLY
#   model    POSITIONAL_OR_KEYWORD
#   extra    VAR_POSITIONAL
#   epochs   KEYWORD_ONLY
#   verbose  KEYWORD_ONLY
#   options  VAR_KEYWORD
# TypeError: fit() missing 1 required positional argument: 'data'
# TypeError: fit() got multiple values for argument 'model'
# [1, 2] [1, 2] ([1, 2],)
# [1] [2]
# [1, 2, 3, 6]
# ('enclosing', 3) global
# UnboundLocalError: cannot access local variable 'counter' where it is not associated with a value
# 1 2 3 ('count',)
# frames of factorial at the base case: 6
# 120
# RecursionError: maximum recursion depth exceeded | limit 1000
# Pretend to fit a model and report how the arguments were bound.
```

Две строки заслуживают второго взгляда. `fit(data=[1])` не жалуется, что `data` только позиционный: поскольку у `fit` есть `**options`, именованный аргумент `data` собирается туда, и тогда не хватает позиционного `data`. А `print(append_to(1), append_to(2), ...)` дважды показывает `[1, 2]`, потому что оба вызова возвращают один и тот же список по умолчанию, который печатается после того, как выполнились оба.
