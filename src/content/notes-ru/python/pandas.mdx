[Предыдущая заметка](/ru/notes/python/numpy-arrays) закончилась тем, чего массив хранить не может: таблицей, столбцы которой имеют разные типы, строки определяются ключом, а не позицией, и часть значений пропущена. Такую форму имеет почти любой набор данных, пока он не стал матрицей: список заказов с клиентом, категорией, суммой и датой. **pandas** представляет такую таблицу как таблицу данных (`DataFrame`): набор именованных столбцов, каждый — массив со своим dtype, с одним общим набором меток строк. Эта заметка сначала строит модель, потому что поведение, которое удивляет людей, от `KeyError` на `s[1]` до присваивания, которое молча ничего не делает, следует из неё. Затем она проходит по операциям, из которых складывается анализ: выбору, очистке, группировке, соединению и перестройке, и заканчивается ошибками, из-за которых код на pandas работает медленно, а оценка модели оказывается неверной.

**Условия.** pandas 3.0.6 с NumPy 2.5.4 на CPython 3.14.7, без установленного PyArrow; подразумеваются `import pandas as pd` и `import numpy as np`. Каждый пример использует маленькие таблицы, построенные в коде; ничего не скачивается.

## Отправная точка: словарь списков \{#baseline-a-dictionary-of-lists\}

Без pandas таблица — это словарь столбцов, каждый из которых список или массив:

```python
orders = {
    "customer": ["c1", "c2", "c1", "c3"],
    "category": ["books", "games", "games", "books"],
    "amount": [12.5, 40.0, 25.0, None],
}
```

Каждый вопрос к нему — цикл. «Сумма по каждой категории» требует [словаря сумм](/ru/notes/python/dicts-and-sets), построенного строка за строкой; «заказы больше 20» требуют позиций, где один столбец удовлетворяет условию, применённых к каждому другому столбцу; а `None` посередине ломает `sum`. Ничто не следит за тем, чтобы столбцы были одной длины и в одном порядке, так что если отсортировать один столбец и забыть про другой, каждый клиент молча окажется в паре с чужой суммой. Один NumPy не помогает: у массива один dtype, а структурированный массив с именованными полями не даёт ни группировки, ни соединения, ни пропущенных значений. pandas сохраняет идею словаря столбцов и добавляет две недостающие вещи: метки строк, общие для всех столбцов, и операции над целыми столбцами.

## Series и DataFrame \{#series-and-dataframe\}

<aside class="callout"><strong>Ключевая идея.</strong> `Series` — это одномерный массив значений плюс `Index` из меток, по одной на значение. `DataFrame` — набор столбцов с одним общим индексом строк `Index`; каждый столбец — Series со своим dtype, хранящаяся как массив NumPy или как массив-расширение pandas (extension array). Имена столбцов образуют второй `Index`. Операции между Series **выравниваются по меткам** (align), а не по позициям.</aside>

```text
>>> df = pd.DataFrame({"city": ["Oslo", "Lima", "Pune"],
...                    "temp": [4.0, 19.5, 31.0],
...                    "rain": [3, 0, 1]})
>>> df
   city  temp  rain
0  Oslo   4.0     3
1  Lima  19.5     0
2  Pune  31.0     1
>>> df.dtypes
city        str
temp    float64
rain      int64
dtype: object
>>> df.index
RangeIndex(start=0, stop=3, step=1)
>>> type(df["temp"]).__name__, df["temp"].to_numpy()
('Series', array([ 4. , 19.5, 31. ]))
```

Словарь задаёт столбцы по порядку. Если индекс не указан, pandas использует `RangeIndex` — метки 0, 1, 2, — который не занимает памяти: он хранит только начало, конец и шаг. У каждого столбца свой dtype: `float64` и `int64` — массивы NumPy, а `str` — строковый dtype по умолчанию в pandas 3.0 ([PDEP 14](#references)). `df["temp"]` — это Series, а `.to_numpy()` возвращает лежащий под ней массив NumPy.

<FrameModel />

**Почему по столбцам.** Таблица хранится по столбцам, потому что анализ идёт по столбцам: `df["temp"].mean()` — одна редукция NumPy по одному непрерывному массиву, со скоростью NumPy. Чтение одной *строки* — дорогое направление: нужно собрать значение из каждого столбца и при смешанных dtype упаковать их в объекты Python. Эта асимметрия решает, какой код на pandas быстр, что и измеряют последние разделы.

**Выравнивание.** Арифметика между двумя Series сопоставляет значения по меткам, а метка, которая есть только в одной из них, даёт пропущенное значение:

```text
>>> s = pd.Series([10, 20, 30], index=["a", "b", "c"])
>>> u = pd.Series([1, 2], index=["b", "c"])
>>> s + u
a     NaN
b    21.0
c    32.0
dtype: float64
```

Сложение идёт не по позициям — тогда оно не удалось бы на длинах 3 и 2, — а как `b + b` и `c + c`, и у `a` нет пары. Результат имеет тип `float64`, потому что `NaN`, пропущенного значения чисел с плавающей точкой, среди целых нет.

## Индекс: `loc` против `iloc` \{#the-index-loc-against-iloc\}

Поскольку у строк есть и метки, и позиции, и они могут различаться, в pandas два индексатора.

**Правило.**
- `.loc[...]` выбирает по **метке**. Срез меток включает оба конца: в `s.loc["a":"b"]` есть и `a`, и `b`.
- `.iloc[...]` выбирает по **позиции**, как в списке. Срез не включает конец: в `s.iloc[0:1]` один элемент.
- Оба принимают селектор строк и, для DataFrame, селектор столбцов: `df.loc[rows, columns]`.
- Просто `df[...]` выбирает **столбцы** по имени или строки, если ему дана булева Series. Для Series `s[...]` использует метки; начиная с pandas 3.0 целое число, которое не является меткой, вызывает `KeyError`, а не трактуется как позиция.

```text
>>> s = pd.Series([10, 20, 30], index=["a", "b", "c"])
>>> s.loc["b"], s.iloc[1], s.loc["a":"b"].tolist(), s.iloc[0:1].tolist()
(np.int64(20), np.int64(20), [10, 20], [10])
>>> s[1]
Traceback (most recent call last):
...
KeyError: 1
>>> t = pd.Series([10, 20, 30], index=[2, 1, 0])
>>> t.loc[0], t.iloc[0]
(np.int64(30), np.int64(10))
```

Последние две строки — та ошибка, от которой защищает правило. После сортировки или фильтрации `DataFrame` сохраняет исходные метки, так что метка 0 не обязательно первая строка. `t.loc[0]` — значение с меткой 0, которое стоит последним; `t.iloc[0]` — первое. Код, который имеет в виду «первую строку», должен писать `iloc`. `df.reset_index(drop=True)` перенумеровывает метки с 0, когда старые ничего не значат.

Индекс — это хеш-таблица из меток в позиции, как у [словаря](/ru/notes/python/dicts-and-sets), так что `loc` с меткой — это поиск по таблице, а не просмотр всех строк. Осмысленный индекс, например идентификатор клиента или дата, — то, благодаря чему работают выравнивание, соединения и временные ряды.

## Копирование при записи: pandas 3.0 \{#copy-on-write-pandas-30\}

**Правило** ([pandas, Copy-on-Write](#references); PDEP 7). В pandas 3.0 любой объект, полученный из DataFrame или Series индексированием или методом, **ведёт себя как копия**. Изменение производного объекта никогда не меняет исходный, и единственный способ изменить DataFrame — присваивание в самом этом DataFrame: `df.loc[rows, col] = value` или `df[col] = values`. Чтобы это было дёшево, копия ленивая — это **копирование при записи** (Copy-on-Write): производный объект разделяет массивы исходного, пока в один из них не начнут писать, и только тогда данные копируются.

```text
>>> df = pd.DataFrame({"city": ["Oslo", "Lima", "Pune"],
...                    "temp": [4.0, 19.5, 31.0], "rain": [3, 0, 1]})
>>> warm = df[df["temp"] > 10]
>>> warm["rain"] = 99
>>> df["rain"].tolist(), warm["rain"].tolist()
([3, 0, 1], [99, 99])
>>> col = df["temp"]
>>> np.shares_memory(col.to_numpy(), df["temp"].to_numpy())
True
>>> col.iloc[0] = -1.0
>>> np.shares_memory(col.to_numpy(), df["temp"].to_numpy()), df["temp"].tolist()
(False, [4.0, 19.5, 31.0])
```

`warm` — отфильтрованная таблица; присваивание её столбцу меняет только `warm`. `col` начинается как столбец, разделяющий память с `df`, и запись `col.iloc[0] = -1.0` запускает копирование, так что `df` не меняется и они больше не разделяют память. При копировании при записи `col.to_numpy()` доступен только для чтения: запись в массив в обход pandas обошла бы ленивую копию.

**Что изменилось по сравнению с pandas 2.** До 3.0 ответ на вопрос «меняет ли это исходный объект?» зависел от того, вернул ли pandas представление или копию, а это зависит от dtype и вида индексирования. `col = df["temp"]; col.iloc[0] = -1.0` меняло `df` через представление, а `warm["rain"] = 99` вызывало знаменитое `SettingWithCopyWarning`, потому что pandas не мог понять, хотел ли пользователь изменить `df`. Копирование при записи снимает вопрос, и в pandas 3.0 это предупреждение удалено ([What's new in 3.0.0](#references)).

**Цепочечное присваивание никогда не работает.** `df["temp"][0] = 100.0` сначала вычисляет `df["temp"]`, новую Series, а затем присваивает её элементу; при копировании при записи эта Series ведёт себя как копия, так что `df` никогда не меняется. pandas распознаёт этот шаблон и предупреждает:

```text
>>> df["temp"][0] = 100.0
<python-input-8>:1: ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment.
Such chained assignment never works to update the original DataFrame or Series, because the intermediate object on which we are setting values always behaves as a copy (due to Copy-on-Write).
...
>>> df["temp"].tolist()
[4.0, 19.5, 31.0]
>>> df.loc[0, "temp"] = 100.0
>>> df["temp"].tolist()
[100.0, 19.5, 31.0]
```

(Предупреждение сокращено; дальше оно советует `.loc`.) `ChainedAssignmentError` — это `Warning`, а не исключение, поэтому программа продолжает работу с неизменённым `df`. Исправление — одна операция индексирования на самом `df`: `df.loc[0, "temp"] = 100.0`. Это та же ошибка, что `a[mask][0] = 99` для [массива NumPy](/ru/notes/python/numpy-arrays#indexing-basic-fancy-and-boolean), где `a[mask]` — настоящая копия; в pandas 3.0 так ведёт себя каждый промежуточный результат.

## Пропущенные значения и dtype \{#missing-values-and-dtypes\}

**Правило.** pandas обозначает пропущенное значение в зависимости от dtype столбца:

| dtype | пропущенное значение | примечания |
| --- | --- | --- |
| `float64` | `NaN` | целочисленный столбец с пропуском становится `float64` |
| `Int64`, `boolean` (допускающие пропуски, nullable; заглавная I) | `pd.NA` | сохраняет целые точными |
| `str` (по умолчанию для текста в 3.0) | `NaN` | `StringDtype` с `na_value=nan` |
| `datetime64` | `NaT` | «not a time», «не время» |
| `object` | `None` или `NaN` | любые объекты Python; медленно |

`isna()` находит пропущенные значения, каким бы маркером они ни были обозначены; `fillna(v)` заменяет их; `dropna()` удаляет строки, где они есть. Редукции по умолчанию их пропускают: `sum` считает их отсутствующими, `mean` делит на число присутствующих значений, `count` считает присутствующие.

```text
>>> m = pd.Series([1, None, 3])
>>> m.dtype, m.isna().tolist(), m.sum(), m.mean()
(dtype('float64'), [False, True, False], np.float64(4.0), np.float64(2.0))
>>> pd.Series([1, None, 3], dtype="Int64").tolist()
[1, <NA>, 3]
>>> st = pd.Series(["a", None, "c"])
>>> st.dtype
<StringDtype(storage='python', na_value=nan)>
>>> st.str.upper().tolist()
['A', nan, 'C']
>>> pd.Series(["a", 1]).dtype
dtype('O')
```

Целые 1 и 3 с пропуском превращаются в `1.0`, `NaN`, `3.0`: у `int64` из NumPy нет свободного битового шаблона для «пропущено», поэтому pandas переходит к числам с плавающей точкой. Допускающий пропуски `Int64` хранит отдельную маску пропущенных позиций и остаётся точным. Текст с pandas 3.0 по умолчанию имеет dtype `str`, который опирается на PyArrow, если тот установлен, а иначе на строки Python — это и есть показанное здесь `storage='python'`; до 3.0 текстовые столбцы имели тип `object`. Его методы `.str` пропускают пропущенные значения. Столбец, смешивающий текст и числа, откатывается к `object` — массиву указателей на объекты Python, то есть к медленной модели «список объектов» из [отправной точки заметки о NumPy](/ru/notes/python/numpy-arrays#baseline-a-list-of-numbers).

Ошибка, которую нужно узнавать: `NaN == NaN` в арифметике с плавающей точкой равно `False` ([почему](/ru/notes/acos/floating-point#special-values)), так что `df[df["x"] == np.nan]` не выбирает ничего. Проверяйте через `isna()`.

## Фильтрация, groupby, merge и pivot \{#filtering-groupby-merge-and-pivot\}

Остаток заметки использует одну маленькую таблицу заказов, прочитанную из текста CSV в памяти:

```text
>>> import io
>>> csv = """order,customer,category,amount,date
... 1,c1,books,12.5,2026-01-03
... 2,c2,games,40.0,2026-01-03
... 3,c1,games,25.0,2026-01-10
... 4,c3,books,,2026-01-17
... 5,c2,books,8.0,2026-02-01
... 6,c3,music,15.0,2026-02-07
... """
>>> orders = pd.read_csv(io.StringIO(csv), parse_dates=["date"])
>>> orders.dtypes
order                int64
customer               str
category               str
amount             float64
date        datetime64[us]
dtype: object
```

**Чтение CSV.** `pd.read_csv` принимает путь, URL или любой файлоподобный объект; `io.StringIO` заставляет строку вести себя как файл ([заметка о файлах](/ru/notes/python/files-and-exceptions)). Функция читает заголовок как имена столбцов и выводит dtype каждого столбца из его текста: целые, числа с плавающей точкой, а пустое поле заказа 4 — как `NaN`. Даты остаются текстом, если их не назвать в `parse_dates`; pandas 3.0 сам определяет разрешение и здесь хранит микросекунды, `datetime64[us]`. Для идентификаторов вывод типа может ошибаться: почтовый индекс `007` читается как целое 7. Передавайте `dtype={"code": "str"}` для таких столбцов, `usecols`, чтобы читать только некоторые столбцы, и `na_values` для маркеров, которыми ваши данные обозначают «пропущено».

**Фильтрация** выбирает строки булевой Series, условия соединяются через `&` (и), `|` (или) и `~` (не):

```text
>>> orders[(orders["amount"] > 10) & (orders["category"] == "games")]
   order customer category  amount       date
1      2       c2    games    40.0 2026-01-03
2      3       c1    games    25.0 2026-01-10
>>> orders[orders["category"].isin(["books", "music"])]["order"].tolist()
[1, 4, 5, 6]
```

Скобки обязательны. `&` связывает сильнее, чем `>` и `==`, поэтому без них `orders["amount"] > 10 & orders["category"] == "games"` сначала вычисляет `10 & orders["category"]` и вызывает `TypeError`. Ключевые слова `and` и `or` тоже не работают: они запрашивают истинностное значение целой Series, которое неоднозначно, и вызывают `ValueError`.

### groupby: разделение, применение, объединение \{#groupby-split-apply-combine\}

**Правило.** `df.groupby(key)[column].agg(f)` выполняет группировку в три шага — разделение–применение–объединение (split–apply–combine; [Wickham, 2011](#references)):

1. **Разделить** строки на группы по значению ключа.
2. **Применить** функцию к столбцу внутри каждой группы, получив одно значение на группу.
3. **Объединить** результаты в Series с индексом из ключей групп, по умолчанию отсортированных.

<SplitApplyCombine />

```text
>>> orders.groupby("category")["amount"].sum()
category
books    20.5
games    65.0
music    15.0
Name: amount, dtype: float64
>>> orders.groupby("category").agg(n=("order", "size"), paid=("amount", "count"),
...                                 total=("amount", "sum"), mean=("amount", "mean"))
          n  paid  total   mean
category
books     3     2   20.5  10.25
games     2     2   65.0  32.50
music     1     1   15.0  15.00
>>> orders.groupby("customer")["amount"].transform("sum").tolist()
[37.5, 48.0, 37.5, 15.0, 48.0, 15.0]
```

Построчно: в группе books суммы 12.5, `NaN` и 8.0, и `sum` пропускает отсутствующую — получается 20.5. **Именованная агрегация** (named aggregation), `name=(column, function)`, вычисляет несколько сводок сразу. `size` считает строки, 3 заказа books, а `count` считает присутствующие значения, 2; разница — пропущенная сумма, и это первое, что стоит проверить, когда два счёта расходятся. `transform` возвращает одно значение на каждую исходную строку, а не на группу — здесь итог по клиенту каждого заказа, — выровненное со строками, так что оно может стать новым столбцом. Строки с пропущенным ключом выпадают из групп, если не указать `dropna=False`.

**Почему это быстро.** pandas один раз факторизует столбец ключей, превращая каждую категорию в целочисленный код, а затем выполняет скомпилированный цикл по кодам, который прибавляет каждую сумму к ячейке её группы. Для встроенных редукций, заданных строками вроде `"sum"` или `"mean"`, на строку или группу не выполняется никакой код Python. Функция Python, `agg(lambda v: ...)`, вызывается по разу на группу, что нормально для нескольких групп и медленно для миллиона.

### merge и join \{#merge-and-join\}

`left.merge(right, on=key, how=...)` объединяет две таблицы, сопоставляя значения ключа, как соединение (join) в SQL:

- `how="inner"` (по умолчанию): только ключи, которые есть в обеих;
- `how="left"`: каждая строка `left`, с пропущенными значениями там, где в `right` нет совпадения;
- `how="outer"`: каждый ключ из любой из сторон;
- `indicator=True` добавляет столбец `_merge`, который говорит, откуда пришла каждая строка.

```text
>>> customers = pd.DataFrame({"customer": ["c1", "c2", "c4"],
...                           "region": ["north", "south", "east"]})
>>> orders.merge(customers, on="customer", how="left")[["order", "customer", "region"]]
   order customer region
0      1       c1  north
1      2       c2  south
2      3       c1  north
3      4       c3    NaN
4      5       c2  south
5      6       c3    NaN
>>> orders.merge(customers, on="customer").shape, orders.merge(customers, on="customer", how="outer").shape
((4, 6), (7, 6))
```

Клиента c3 нет в `customers`, поэтому левое соединение сохраняет заказы c3 с пропущенным регионом, а внутреннее их отбрасывает: 4 строки. Внешнее соединение добавляет c4, у которого нет заказов: 7 строк.

**Типичная ошибка.** Если ключ встречается справа дважды, каждая совпавшая строка слева повторяется, по разу на каждое совпадение. Клиент, записанный в двух регионах, превращает каждый свой заказ в две строки, и каждый итог, вычисленный после этого, завышен. Передавайте `validate="many_to_one"`, который вызывает `MergeError`, если ключи справа не уникальны, и сравнивайте число строк до и после слияния. `df.join(other)` — та же операция, но сопоставление идёт по индексу, а не по столбцу.

### Сводные таблицы \{#pivot-tables\}

`pivot_table` — это groupby по двум ключам, результат которого разложен в сетку: один ключ по строкам, другой по столбцам.

```text
>>> m = orders.merge(customers, on="customer", how="left")
>>> m["region"] = m["region"].fillna("unknown")
>>> m.pivot_table(index="region", columns="category", values="amount",
...               aggfunc="sum", fill_value=0)
category  books  games  music
region
north      12.5   25.0    0.0
south       8.0   40.0    0.0
unknown     0.0    0.0   15.0
```

Без `fillna` у строк c3 регион пропущен, а сводная таблица, как и groupby, отбрасывает пропущенные ключи, так что 15.0 заказа music молча исчезли бы из таблицы. `fill_value=0` пишет 0 там, где у комбинации нет строк; для суммы это правильно, для среднего — нет. Обратная операция — `melt`: она превращает столбцы обратно в строки.

### Временные ряды вкратце \{#time-series-in-brief\}

Столбец `datetime64` поддерживает арифметику дат и аксессор `.dt` (`.dt.month`, `.dt.day_name()`). Если даты сделать индексом, `resample` группирует по календарным периодам, а `rolling` считает скользящие окна:

```text
>>> ts = orders.set_index("date")["amount"]
>>> ts.resample("MS").sum()
date
2026-01-01    77.5
2026-02-01    23.0
Freq: MS, Name: amount, dtype: float64
>>> orders["date"].dt.day_name().tolist()[:2]
['Saturday', 'Saturday']
```

`resample("MS")` — это groupby по месяцу с меткой начала месяца: заказы января в сумме дают $12.5 + 40 + 25 = 77.5$. `"W"` дал бы недели, заканчивающиеся воскресеньем, `"D"` — дни, причём для суммы пустые периоды заполняются нулём. Временные ряды — отдельная тема (часовые пояса, нерегулярная дискретизация, лаги); её разбирает [глава 11 книги Маккинни](#references).

## Ловушка: циклы по строкам медленные \{#pitfall-row-loops-are-slow\}

Код, написанный построчно, через `iterrows` или `apply(..., axis=1)`, отказывается от хранения по столбцам, которое делает pandas быстрым. Одно и то же вычисление — цена, умноженная на количество, для каждой строки таблицы из двух столбцов `price` и `qty` — пятью способами на описанной выше машине, лучшее из трёх запусков:

| строк | `df.price * df.qty` | `zip(df.price, df.qty)` | `itertuples()` | `apply(f, axis=1)` | `iterrows()` |
| --- | --- | --- | --- | --- | --- |
| 1000 | 0.033 мс | 0.12 мс | 0.42 мс | 3.1 мс | 9.6 мс |
| 100 000 | 0.090 мс | 12.6 мс | 34 мс | 310 мс | 1048 мс |

<RowLoops />

Для 100 000 строк векторизованное произведение занимает 0.09 мс, а `iterrows` — больше секунды, примерно в 12 000 раз дольше. Причина — хранение по столбцам в [модели выше](#series-and-dataframe). `iterrows` строит для каждой строки новую Series: собирает по значению из каждого столбца, находит для них общий dtype и создаёт индекс — около 10 мкс работы на строку. `apply(f, axis=1)` делает то же самое и затем вызывает `f`. `itertuples` вместо этого строит лёгкий именованный кортеж, здесь примерно в тридцать раз дешевле, а `zip` по двум столбцам перебирает их значения как числа `float` Python — ещё дешевле, но это всё равно цикл Python, около 0.13 мкс на строку. Векторизованное выражение — одно умножение NumPy.

Практическое правило: записывайте вычисление как операции над целыми столбцами (арифметика, сравнения, `np.where` для условий, методы `.str` и `.dt`, `groupby` со встроенными редукциями, `merge` вместо цикла с поиском). Если без цикла по строкам не обойтись, самый дешёвый цикл — `itertuples`. Прежде чем переписывать, профилируйте ([профилирование](/ru/notes/python/debugging-and-profiling#profiling-where-the-time-goes)): медленный цикл часто не тот, на который думаешь, а [заметка о производительности](/ru/notes/python/performance) перечисляет другие средства.

## Ловушка: утечка при предобработке \{#pitfall-leakage-when-preprocessing\}

pandas позволяет легко очистить целую таблицу одной строкой, и в этом ловушка, если таблицу потом разделят на обучающие и тестовые данные. Заполнение пропущенных значений средним по столбцу, стандартизация столбца или кодирование категории средним значением целевой переменной, сделанные на всей таблице до разбиения, вычисляют статистику по тестовым строкам и записывают её в обучающие. Модель тогда видит информацию о тестовой выборке, и её оценка на тесте оказывается слишком оптимистичной. Курс по машинному обучению называет это [загрязнением выборки](/ru/notes/ml/data-features-and-leakage#traintest-contamination) (train–test contamination) и показывает, насколько сильно оно может сдвинуть оценку.

```python
# неправильно: значение для заполнения вычислено с участием тестовых строк
df["income"] = df["income"].fillna(df["income"].mean())
train, test = df.iloc[:800], df.iloc[800:]

# правильно: сначала разбиение, каждая статистика — только по обучающим строкам
train, test = df.iloc[:800].copy(), df.iloc[800:].copy()
fill = train["income"].mean()
train["income"] = train["income"].fillna(fill)
test["income"] = test["income"].fillna(fill)
```

То же правило действует для любого `groupby(...).transform("mean")` по целевой переменной — это [наивное целевое кодирование](/ru/notes/ml/data-features-and-leakage#why-the-naive-target-encoding-leaks): вычисляйте его внутри каждого обучающего фолда. Раздел «Код» ниже измеряет разницу на небольшой синтетической таблице.

## Что изменилось \{#what-changed\}

| | Словарь списков (отправная точка) | DataFrame pandas |
| --- | --- | --- |
| Столбцы | списки, одинаковую длину которых поддерживают вручную | массивы со своими dtype и одним общим индексом |
| Строки | только позиции | метки (`loc`) и позиции (`iloc`) |
| Сочетание двух столбцов | цикл, по позиции | векторизованно, с выравниванием по меткам |
| Пропущенные значения | `None` ломает арифметику | `NaN`, `pd.NA`, `NaT`; редукции их пропускают |
| Итоги по группам | словарь, построенный в цикле | `groupby(...).agg(...)` |
| Соединение таблиц | вложенные циклы или словарь для поиска | `merge` |
| Изменение производной таблицы | меняет исходную, если данные общие | никогда не меняет исходную (копирование при записи, pandas 3.0) |

## Ограничения \{#limitations\}

- **Память и размер.** pandas держит всю таблицу в памяти, а операции создают новые таблицы (лениво при копировании при записи, но запись всё равно копирует). Таблица, которая не помещается в память с запасом в несколько раз, требует чтения по частям (`read_csv(chunksize=...)`) или другого движка, например Polars или DuckDB, которые здесь не рассматриваются.
- **Текст без PyArrow.** Без установленного PyArrow dtype `str` хранит строки Python с поштучной стоимостью памяти объектов из [заметки о значениях](/ru/notes/python/values-and-names). Установка PyArrow заставляет pandas использовать компактные строковые массивы Arrow.
- **Зависимость от версии.** Копирование при записи, `str` по умолчанию и удалённый откат `s[1]` к позиции — поведение pandas 3.0. Код, написанный для pandas 1 или 2, может опираться на старое поведение; [руководство по миграции](#references) перечисляет изменения.
- **Одна машина.** Время измерено на Apple M1 с pandas 3.0.6. Отношения между циклами по строкам и векторизованным кодом велики на любой машине; точные числа — нет.

## Что нужно запомнить \{#what-you-should-remember\}

- DataFrame — это именованные столбцы, каждый — типизированный массив, с одним общим индексом строк. Операции между Series выравниваются по меткам.
- `loc` выбирает по метке и включает конец среза; `iloc` выбирает по позиции и не включает его. После фильтрации или сортировки метки и позиции различаются.
- В pandas 3.0 каждый производный объект ведёт себя как копия. Меняйте DataFrame только одной операцией индексирования на нём самом: `df.loc[rows, col] = value`. Цепочечное присваивание никогда не работает.
- Пропущенные значения — это `NaN` в числах с плавающей точкой, `pd.NA` в типах, допускающих пропуски, `NaT` в датах; проверяйте через `isna()`. Целочисленный столбец с пропуском становится `float64`, если он не `Int64`. Текст имеет dtype `str`.
- `groupby` разделяет, применяет и объединяет; предпочитайте встроенные редукции по имени. `size` считает строки, `count` — значения.
- Проверяйте число строк вокруг каждого `merge`; используйте `validate`. Заполняйте пропущенные ключи перед сводной таблицей.
- Пишите операции над столбцами, а не циклы по строкам: `iterrows` и `apply(axis=1)` на больших таблицах в тысячи раз медленнее.
- Вычисляйте каждую статистику предобработки только по обучающим строкам.

## Код \{#code\}

Скрипт строит синтетическую таблицу из 1000 заказов и проходит по заметке: dtype, метка против позиции, копирование при записи и цепочечное присваивание, пропущенные значения, groupby, слияние с повторяющимся ключом, сводная таблица, помесячная передискретизация, время циклов по строкам против выражения над столбцами и утечка значения для заполнения, вычисленного до разбиения. Запуск: `python -I frames.py`; нужны pandas 3.0 и NumPy, работа занимает несколько секунд. Время меняется от машины к машине и от запуска к запуску; остальные строки точны для pandas 3.0.6 и NumPy 2.5.4.

```python
"""Data frames with pandas 3.0: the model, Copy-on-Write, grouping, joining and pitfalls (Python 3.14)."""
import io
import timeit
import warnings

import numpy as np
import pandas as pd

print("pandas", pd.__version__, "numpy", np.__version__)
rng = np.random.default_rng(0)

# 1. Синтетическая таблица: 1000 заказов, записанных в текст CSV и прочитанных обратно
n = 1000
raw = pd.DataFrame({
    "customer": rng.choice(["c1", "c2", "c3", "c4", "c5"], size=n),
    "category": rng.choice(["books", "games", "music"], size=n, p=[0.5, 0.3, 0.2]),
    "price": rng.uniform(5, 60, size=n).round(2),
    "qty": rng.integers(1, 5, size=n),
    "date": pd.date_range("2026-01-01", periods=n, freq="8h"),
})
raw.loc[rng.choice(n, size=50, replace=False), "price"] = np.nan        # 5% цен пропущено
df = pd.read_csv(io.StringIO(raw.to_csv(index=False)), parse_dates=["date"])
print(df.shape, df.dtypes.astype(str).to_dict())

# 2. Метки против позиций после сортировки
s = df.sort_values("price", ascending=False)["price"]
print(s.index[0], s.loc[0] == df["price"].iloc[0], s.iloc[0] == df["price"].max())

# 3. Копирование при записи: производные объекты не меняют исходный; цепочечное присваивание не работает
cheap = df[df["price"] < 10]
cheap["qty"] = 0
with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    df["qty"][0] = 100                                   # цепочечное: ни на что не влияет
print((df["qty"] == 0).sum(), df["qty"].iloc[0] != 100, caught[0].category.__name__)
df.loc[0, "qty"] = 100                                   # одна операция индексирования на самом df
print(df["qty"].iloc[0])

# 4. Пропущенные значения: редукции их пропускают; size против count
df["revenue"] = df["price"] * df["qty"]
print(df["price"].isna().sum(), df["revenue"].isna().sum(), round(df["price"].mean(), 2))
print(df.groupby("category").agg(rows=("price", "size"), priced=("price", "count"),
                                 revenue=("revenue", "sum")).round(1).to_dict("index"))

# 5. Слияние с повторяющимся ключом справа размножает строки; validate это ловит
regions = pd.DataFrame({"customer": ["c1", "c2", "c3", "c4", "c4"],
                        "region": ["north", "south", "east", "west", "north"]})
joined = df.merge(regions, on="customer", how="left")
print(len(df), len(joined))
try:
    df.merge(regions, on="customer", how="left", validate="many_to_one")
except pd.errors.MergeError as err:
    print("MergeError:", str(err).splitlines()[0])

# 6. Сводная таблица и помесячная передискретизация
print(joined.pivot_table(index="region", columns="category", values="qty", aggfunc="sum", fill_value=0))
print(df.set_index("date")["revenue"].resample("MS").sum().round(1).tolist())

# 7. Циклы по строкам против выражения над столбцами
def best(fn, number):
    return min(timeit.repeat(fn, number=number, repeat=3)) / number

for name, fn, number in [
    ("vectorized", lambda: df["price"] * df["qty"], 200),
    ("zip", lambda: [p * q for p, q in zip(df["price"], df["qty"])], 20),
    ("itertuples", lambda: [r.price * r.qty for r in df.itertuples()], 5),
    ("apply", lambda: df.apply(lambda r: r["price"] * r["qty"], axis=1), 1),
    ("iterrows", lambda: [r["price"] * r["qty"] for _, r in df.iterrows()], 1),
]:
    print(f"{name:11} {best(fn, number) * 1e3:8.3f} ms for {len(df)} rows")

# 8. Утечка: значение для заполнения, вычисленное с участием тестовых строк. Цены со временем растут,
#    поэтому последние 200 заказов (тестовая выборка) дороже первых 800.
drift = df.copy()
drift["price"] = drift["price"] + np.arange(n) * 0.05
train_mean = drift["price"].iloc[:800].mean()
all_mean = drift["price"].mean()
print(round(train_mean, 2), round(all_mean, 2), "difference", round(all_mean - train_mean, 2))

# Вывод на CPython 3.14.7, pandas 3.0.6 и NumPy 2.5.4 на Apple M1 (macOS); время меняется:
# pandas 3.0.6 numpy 2.5.4
# (1000, 5) {'customer': 'str', 'category': 'str', 'price': 'float64', 'qty': 'int64', 'date': 'datetime64[us]'}
# 805 True True
# 0 True ChainedAssignmentError
# 100
# 50 50 31.61
# {'books': {'rows': 503, 'priced': 480, 'revenue': 40236.3}, 'games': {'rows': 295, 'priced': 279, 'revenue': 21835.1}, 'music': {'rows': 202, 'priced': 191, 'revenue': 13818.8}}
# 1000 1209
# MergeError: Merge keys are not unique in right dataset; not a many-to-one merge
# category  books  games  music
# region
# east        260    143     98
# north       518    307    181
# south       187    161     96
# west        288    139     85
# [7028.4, 6352.5, 7241.7, 6248.9, 6522.5, 5929.3, 6764.7, 7623.4, 6894.9, 7855.9, 7427.8]
# vectorized     0.028 ms for 1000 rows
# zip            0.115 ms for 1000 rows
# itertuples     1.167 ms for 1000 rows
# apply          3.246 ms for 1000 rows
# iterrows      11.710 ms for 1000 rows
# 51.0 56.66 difference 5.66
```

Как читать вывод: после сортировки по цене первая строка имеет метку 805, а не 0. `0` в четвёртой строке — число строк `df`, у которых количество стало 0: изменение `cheap` не дошло до `df`, как и цепочечное присваивание. Из 1000 заказов у 50 цена пропущена, поэтому `size` и `count` различаются в каждой категории. Левое слияние выросло с 1000 до 1209 строк, потому что клиент c4 записан в двух регионах, и сводная таблица учитывает заказы c4 в обоих регионах. `itertuples` занимает здесь 1.2 мс против 0.42 мс в таблице выше, потому что в этой таблице шесть столбцов, а не два, и каждый именованный кортеж содержит их все. Последняя строка — утечка: цены растут со временем, и значение для заполнения, вычисленное по всем строкам, на 5.66 больше среднего по обучающим строкам, потому что оно видело более дорогой тестовый период.
