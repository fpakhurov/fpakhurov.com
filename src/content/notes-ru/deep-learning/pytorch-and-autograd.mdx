[Предыдущая заметка](/ru/notes/deep-learning/deep-learning) свела обучение любой сети к одному циклу: взять батч, выполнить прямой проход модели, вычислить функцию потерь, выполнить обратный проход ради градиента, сделать шаг. Для этого цикла библиотека должна предоставить четыре вещи: массивы, в которых хранятся батчи и параметры, прямой проход, который запоминает, что он вычислил, обратный проход, который превращает эту память в градиенты, и оптимизаторы, которые их применяют. В этой заметке разобрано, как PyTorch предоставляет каждую из них, начиная с тензора и его правил распространения размерностей. Затем мы построим обратный проход с нуля для скаляров — около сорока строк на Python, которые совпадают с PyTorch с точностью до ошибки округления, — и соберём полный конвейер обучения. Заканчивается заметка ошибками, с которыми конвейер работает без сообщений об ошибках и всё равно плохо обучается.

**Обозначения.** Как и в [заметке об обратном распространении ошибки](/ru/notes/ml/backpropagation), $L$ — скалярная функция потерь, а $\bar u = \partial L / \partial u$ — **сопряжённая величина** (adjoint) для величины $u$, той же формы, что и $u$. **Форма** (shape) тензора — это кортеж его размеров по каждой размерности, записываемый как `(64, 10)`; размерность 0 — первая. $\eta$ — шаг обучения (learning rate).

## Отправная точка: градиенты, написанные вручную \{#baseline-gradients-written-by-hand\}

Если есть только NumPy, каждому слою нужны два куска кода: прямое вычисление и формула для обратного прохода. Заметка об обратном распространении ошибки выписала оба для двухслойной сети: $\bar W = \bar z\, h^\top$, $\bar z = \varphi'(z) \odot \bar h$ и так далее. Для одной архитектуры это работает. Но каждый новый слой, функция потерь или связь требуют вывести и запрограммировать новую формулу обратного прохода, а ошибка в ней часто не приводит к падению программы: функция потерь всё равно убывает, только медленнее, и выявляет ошибку лишь [проверка конечными разностями](/ru/notes/ml/backpropagation#checking-gradients-by-finite-differences).

PyTorch избавляет от второго куска. Мы пишем только прямой проход, обычным кодом на Python над тензорами; библиотека записывает, какие операции выполнялись, и по этой записи выводит обратный проход. Каждая операция приносит свою локальную производную, остальное делает цепное правило.

## Тензоры \{#tensors\}

**Тензор** (tensor) — это $n$-мерный массив с формой, типом данных (`dtype`) и устройством. Вещественный тип по умолчанию — 32-битный (`torch.float32`): он занимает вдвое меньше памяти, чем 64-битные числа, и гораздо быстрее работает на GPU, а точность у него — около 7 значащих цифр ([форматы IEEE 754](/ru/notes/acos/floating-point#the-ieee-754-formats)); для проверки градиентов используется `torch.float64`. Устройство — это CPU или GPU, и `x.to('cuda')` переносит тензор на GPU, если он есть. Всё в этом курсе выполняется на CPU.

Тензор — это взгляд на блок памяти, описанный формой и **шагами** (strides): сколько элементов нужно пропустить, чтобы сдвинуться на одну позицию вдоль каждой размерности. Изменение формы и транспонирование обычно меняют только описание, а не данные. **Разобранный пример.** `x = torch.arange(6.0)` хранит $0, 1, \dots, 5$; `v = x.view(2, 3)` — та же память, прочитанная как две строки по три элемента, с шагами $(3, 1)$. Присваивание `v[0, 0] = 100` меняет и `x[0]`. У транспонированного `v.t()` шаги $(1, 3)$: при чтении по строкам он прыгает по памяти, поэтому он не **непрерывный** (contiguous), и `.view` отказывается менять его форму. `.reshape` копирует данные, когда это необходимо, а `.contiguous()` делает копию явной. Общая память — то, что делает представления (view) дешёвыми; по той же причине изменение на месте может затронуть тензоры, которые выглядят не связанными между собой.

## Распространение размерностей \{#broadcasting\}

Операции между тензорами разных форм не требуют явного копирования. **Распространение размерностей** (broadcasting) сравнивает две формы, начиная с последней размерности. Два размера совместимы, если они равны, если один из них равен 1 или если у одного тензора размерности закончились (недостающая размерность считается равной 1). По каждой размерности результат имеет больший из двух размеров, а размерность размера 1 используется так, как если бы она была повторена:

$$
\begin{gathered}
\text{размер результата}_k = \max(a_k, b_k), \\
\text{допустимо, только если } a_k = b_k \text{ или } \min(a_k, b_k) = 1 .
\end{gathered}
$$

**Разобранный пример: центрирование батча.** У батча $X$ формы `(2, 3)` со строками $(1, 2, 3)$ и $(3, 6, 9)$ средние по столбцам равны $(2, 4, 6)$, форма `(3,)`. В `X - X.mean(0)` среднее читается как тензор формы `(1, 3)` и повторяется для обеих строк, что даёт $(-1, -2, -3)$ и $(1, 2, 3)$. Ни цикла, ни копии среднего писать не нужно.

То же правило порождает одну из самых частых незаметных ошибок. Сеть для регрессии обычно выдаёт предсказания формы `(n, 1)`, один столбец, а цели хранятся в форме `(n,)`. Тогда разность `pred - target` распространяется до `(n, n)`: её элемент $(i, j)$ равен $\hat y_i - y_j$, то есть каждое предсказание сравнивается с каждой целью.

<BroadcastTrap />

Для предсказаний $(1, 2, 3)$, в точности совпадающих с целями $(1, 2, 3)$, задуманная среднеквадратичная ошибка (MSE) равна 0. Распространённая усредняет девять квадратов разностей $(i - j)^2$: $(0 + 1 + 4 + 1 + 0 + 1 + 4 + 1 + 0)/9 = 12/9 = 1.333$. Обучение на ней тянет каждое предсказание к среднему всех целей. Ничего не падает; `F.mse_loss` лишь выводит предупреждение о том, что размер цели отличается от размера входа. Лекарство — сделать формы одинаковыми до вычисления функции потерь, здесь с помощью `pred.squeeze(1)`, и печатать формы всякий раз, когда функция потерь выглядит странно.

## Граф вычислений \{#the-computational-graph\}

<aside class="callout"><strong>Ключевая идея.</strong> Дифференцированию в обратном режиме (reverse mode) нужны от каждой операции только две вещи: её локальные производные, вычисленные по значениям, увиденным при прямом проходе, и её место в графе. Обходя узлы в порядке, обратном порядку их вычисления, каждый узел передаёт свою сопряжённую величину, умноженную на локальную производную, узлам, из которых он вычислен, а узел, использованный несколько раз, складывает всё, что получил.</aside>

Любое вычисление $L$ — это ориентированный ациклический граф, узлы которого — промежуточные значения. В [заметке об обратном распространении ошибки](/ru/notes/ml/backpropagation#the-computational-graph) сформулировано правило, которое превращает его в градиенты: если $u$ используется узлами $v_1, \dots, v_k$, то

$$
\bar u = \sum_{c=1}^{k} \bar v_c\, \frac{\partial v_c}{\partial u} .
$$

**Разобранный пример: узел, использованный дважды.** Возьмём $L = (ab + a)^2$ при $a = 2$, $b = -3$, вычисленное как $c = ab$, $d = c + a$, $L = d^2$. Значение $a$ входит в два узла, $c$ и $d$.

- Прямой проход: $c = 2 \cdot (-3) = -6$, $d = -6 + 2 = -4$, $L = 16$.
- Обратный проход от $\bar L = 1$: $\bar d = 2d \cdot \bar L = -8$; сложение передаёт его без изменений, так что $\bar c = -8$, и $a$ получает $-8$ через $d$.
- Произведение передаёт $\bar c$, умноженное на другой множитель: $\bar b = \bar c \cdot a = -16$, а $a$ получает $\bar c \cdot b = 24$ через $c$.
- $a$ складывает полученное: $\bar a = 24 + (-8) = 16$.

Проверка вручную: $L = a^2 (b + 1)^2$, поэтому $\partial L / \partial a = 2a(b + 1)^2 = 16$ и $\partial L / \partial b = 2a^2 (b + 1) = -16$.

<ScalarGraph />

1. $c = ab = -6$; произведение запоминает оба множителя, которые и являются его локальными производными.
2. $d = c + a = -4$; у суммы локальная производная по каждому входу равна 1.
3. $L = d^2 = 16$; квадрат запоминает $2d = -8$.
4. Обратный проход начинается с $\bar L = 1$ и даёт $\bar d = -8$.
5. Через сумму: $\bar c = -8$, и первый вклад в $\bar a$ равен $-8$.
6. Через произведение: $\bar b = \bar c\, a = -16$, а второй вклад в $\bar a$ равен $\bar c\, b = 24$, так что $\bar a = 16$.

Порядок важен. $\bar a$ полна только после того, как и $c$, и $d$ передали свои вклады, а $\bar c$ — только после того, как свой вклад передал $d$. Обработка узлов в обратном **топологическом порядке** (topological order), то есть в порядке, где каждый узел идёт после всех узлов, из которых он вычислен, гарантирует, что каждый узел собрал свою сопряжённую величину полностью, прежде чем что-либо передавать дальше.

## Скалярное автоматическое дифференцирование с нуля \{#a-scalar-autograd-from-scratch\}

Правило умещается в один небольшой класс. `Value` хранит число, его сопряжённую величину `grad`, узлы, из которых оно вычислено, и локальную производную по каждому из них, вычисленную при прямом проходе. Арифметика над `Value` строит граф как побочный эффект, а `backward` упорядочивает граф и применяет правило:

```python
import math

class Value:
    """A scalar that remembers how it was computed."""
    def __init__(self, data, parents=(), local_grads=()):
        self.data, self.grad = data, 0.0
        self.parents = parents          # узлы, из которых вычислен этот
        self.local_grads = local_grads  # d(self)/d(parent) для каждого родителя, при значениях прямого прохода

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data + other.data, (self, other), (1.0, 1.0))

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data * other.data, (self, other), (other.data, self.data))

    def __pow__(self, k):               # k — обычное число
        return Value(self.data ** k, (self,), (k * self.data ** (k - 1),))

    def relu(self):
        return Value(max(self.data, 0.0), (self,), (float(self.data > 0),))

    def exp(self):
        e = math.exp(self.data)
        return Value(e, (self,), (e,))

    def log(self):
        return Value(math.log(self.data), (self,), (1.0 / self.data,))

    __radd__, __rmul__ = __add__, __mul__
    def __neg__(self): return self * -1.0
    def __sub__(self, other): return self + (-other)

    def backward(self):
        # 1. упорядочить граф так, чтобы каждый узел шёл после всех узлов, из которых он вычислен
        order, seen = [], set()
        def visit(v):
            if id(v) not in seen:
                seen.add(id(v))
                for p in v.parents:
                    visit(p)
                order.append(v)
        visit(self)
        # 2. задать градиент выхода и идти назад: каждый узел передаёт родителям grad * локальную производную
        self.grad = 1.0
        for v in reversed(order):
            for p, d in zip(v.parents, v.local_grads):
                p.grad += v.grad * d    # += : узел, использованный дважды, собирает оба вклада

# разобранный пример: L = (a b + a)^2 при a = 2, b = -3
a, b = Value(2.0), Value(-3.0)
L = (a * b + a) ** 2
L.backward()
print(L.data, a.grad, b.grad)   # 16.0 16.0 -16.0

# 100 случайных слоёв из двух ReLU-нейронов с softmax и кросс-энтропией, против torch.autograd в двойной точности
import random, torch
random.seed(0)
worst = 0.0
for trial in range(100):
    x = [random.uniform(-2, 2) for _ in range(3)]
    w = [[random.uniform(-1, 1) for _ in range(3)] for _ in range(2)]
    y = random.randrange(2)
    W = [[Value(v) for v in row] for row in w]
    h = [sum((W[k][j] * x[j] for j in range(3)), Value(0.0)).relu() for k in range(2)]
    loss = (h[0].exp() + h[1].exp()).log() - h[y]
    loss.backward()
    Wt = torch.tensor(w, dtype=torch.float64, requires_grad=True)
    ht = torch.relu(Wt @ torch.tensor(x, dtype=torch.float64))
    lt = torch.nn.functional.cross_entropy(ht[None], torch.tensor([y]))
    lt.backward()
    diffs = [abs(loss.data - lt.item())] + [abs(W[k][j].grad - Wt.grad[k, j].item()) for k in range(2) for j in range(3)]
    worst = max(worst, *diffs)
print(f"{worst:.1e}")   # 4.4e-16: наибольшая разность в функции потерь или градиенте, только ошибка округления
```

Обход в глубину `visit` добавляет узел только после всех его родителей, а это и есть топологический порядок; проход по нему в обратную сторону посещает каждый узел после всех, кто его использует. Каждая операция хранит числа, а не формулы: произведение хранит другой множитель, экспонента — собственное значение, ReLU — 0 или 1. На 100 случайных слоях с softmax и кросс-энтропией функции потерь и все шесть градиентов по весам совпадают с PyTorch с точностью до $4.4 \cdot 10^{-16}$, то есть до ошибки округления в двойной точности.

Этот класс отделяют от PyTorch два упрощения. Он работает со скалярами, поэтому произведение двух матриц $n \times n$ превращается в порядка $n^3$ узлов графа, каждый из которых — объект Python. Узлы PyTorch — это целые операции над тензорами, и каждая реализует **произведение вектора на матрицу Якоби** (vector–Jacobian product): по сопряжённой величине своего выхода она возвращает сопряжённые величины входов, никогда не формируя саму матрицу Якоби, как $\bar h = W^\top \bar z$ для линейного слоя; почему такой порядок дешевле, объясняет [цепное правило как произведение якобианов](/ru/notes/math/gradients-jacobians-hessians#the-chain-rule-a-product-of-jacobians). Кроме того, класс хранит каждый граф вечно, а PyTorch освобождает сохранённые значения графа, как только `backward` их использовал.

## Как PyTorch записывает граф \{#how-pytorch-records-the-graph\}

Тензор, созданный с `requires_grad=True`, как и любой параметр модуля, — это **лист** (leaf) графа. Каждая операция над такими тензорами возвращает результат с `grad_fn` — узлом, который умеет передавать сопряжённые величины назад своим входам и связан с узлами этих входов через `grad_fn.next_functions`. Для $L = (ab + a)^2$ у результата `grad_fn` — это `PowBackward0`, вход которого — `AddBackward0`, а входы того — `MulBackward0` и узел, собирающий градиент листа $a$ (`AccumulateGrad`). `L.backward()` проходит эту цепочку в обратном топологическом порядке, как и `Value.backward`, и прибавляет сопряжённую величину каждого листа к его `.grad`: `a.grad` равно 16, а `b.grad` равно $-16$.

| наш `Value` | PyTorch | роль |
| --- | --- | --- |
| `Value(2.0)` | `torch.tensor(2.0, requires_grad=True)` | лист |
| `parents`, `local_grads` | `grad_fn`, `next_functions`, сохранённые тензоры | записанный граф |
| `p.grad += ...` | к `.grad` прибавляют, его никогда не перезаписывают | отсюда `zero_grad()` |
| граф хранится вечно | граф освобождается после `backward()` | второй `backward()` вызывает ошибку, если не указать `retain_graph=True` |
| запись нельзя остановить | `with torch.no_grad():` и `.detach()` | оценка модели и значения, которые считаются константами |

`torch.no_grad()` выключает запись: вычисления внутри него не строят граф и не хранят активации, что экономит память. `.detach()` возвращает тензор с теми же данными и без истории, так что градиенты через него не проходят.

## Конвейер обучения \{#the-training-pipeline\}

Цикл из предыдущей заметки превращается в пять объектов PyTorch:

- **`Dataset`** сообщает, сколько в нём примеров (`__len__`), и возвращает один пример по индексу (`__getitem__`), здесь — пару из изображения в 64 пикселя и его метки.
- **`DataLoader`** выбирает индексы, при `shuffle=True` в новом случайном порядке в каждой эпохе, и собирает примеры в батчи. При 1437 обучающих изображениях и `batch_size=64` в эпохе $\lceil 1437 / 64 \rceil = 23$ батча; в последнем $1437 - 22 \cdot 64 = 29$ изображений, поскольку `drop_last` по умолчанию выключен.
- **`nn.Module`** хранит параметры и определяет `forward`. Каждый `nn.Parameter` или подмодуль, присвоенный как атрибут, регистрируется, так что `model.parameters()` находит их все: у сети $64 \to 128 \to 10$ из раздела «Код» их $64 \cdot 128 + 128 + 128 \cdot 10 + 10 = 9610$.
- **Функция потерь**, например `F.cross_entropy`, которая принимает логиты и целочисленные метки; функциям потерь посвящена [следующая заметка](/ru/notes/deep-learning/losses-and-regularization).
- **Оптимизатор** хранит ссылки на параметры. `opt.step()` обновляет каждый из них по его `.grad`, для обычного SGD — вычитая $\eta$, умноженное на `.grad`, а `opt.zero_grad()` обнуляет градиенты. Оптимизаторы с памятью, такие как импульс (momentum) и Adam, — предмет заметки [Оптимизация глубоких сетей](/ru/notes/deep-learning/optimizing-deep-networks).

Тогда один шаг обучения — это `opt.zero_grad()`, прямой проход, `loss.backward()` и `opt.step()`, в этом порядке или с `zero_grad()` в конце предыдущего шага.

Два переключателя меняют то, что делает прямой проход. **`model.train()` и `model.eval()`** задают режим слоёв, которые при обучении ведут себя иначе: дропаут (dropout) выключает нейроны только в режиме обучения, а батч-нормализация (batch normalization, предмет заметки [Нормализация и инициализация](/ru/notes/deep-learning/normalization-and-initialization)) при обучении использует статистики батча, а в режиме оценки — сохранённые средние. В разделе «Код» два прямых прохода одного и того же изображения различаются в режиме обучения и совпадают в режиме оценки. **`torch.no_grad()`** от режима не зависит: он останавливает запись графа. Для оценки модели нужны оба: `eval()` — ради правильного поведения, `no_grad()` — ради памяти. На цифрах этот конвейер с SGD и импульсом достигает доли правильных ответов (accuracy) на тесте 0.864 после одной эпохи и 0.964 после пяти.

## Типичные ошибки \{#common-bugs\}

Знать стоит те ошибки, которые не вызывают исключений. Конвейер работает, функция потерь меняется, а модель неправильная.

### Забытый `zero_grad` \{#forgetting-zero_grad\}

`backward()` прибавляет к `.grad`. Без `zero_grad()` градиент, используемый на шаге $k$, — это сумма всех градиентов до него.

Вот к чему это приводит. Для одного веса с градиентами $g_0, g_1, \dots$ обновление становится таким:

$$
\boxed{\; w_{k+1} = w_k - \eta \sum_{j=0}^{k} g_j \;}
$$

вместо $w_{k+1} = w_k - \eta\, g_k$: это [импульс](/ru/notes/ml/stochastic-and-adaptive-optimizers#momentum-remember-the-direction) с памятью, которая никогда не затухает. На квадратичной функции $L(w) = \tfrac12 (w - 3)^2$ с градиентом $g = w - 3$ обозначим ошибку через $e_k = w_k - 3$, а накопленный градиент через $S_k = \sum_{j \le k} e_j$. Тогда

$$
\begin{aligned}
e_{k+1} &= e_k - \eta S_k, \\
S_{k+1} &= S_k + e_{k+1} = e_k + (1 - \eta) S_k .
\end{aligned}
$$

Первая строка — обновление с накопленным градиентом; вторая прибавляет к сумме новый градиент $e_{k+1}$ и подставляет первую строку. Пара $(e_k, S_k)$ на каждом шаге умножается на матрицу $\begin{pmatrix} 1 & -\eta \\ 1 & 1 - \eta \end{pmatrix}$, определитель которой равен $(1 - \eta) + \eta = 1$, а след — $2 - \eta$. Поэтому при $0 < \eta < 4$ её собственные значения — комплексно-сопряжённая пара модуля 1, $e^{\pm i\vartheta}$, где $\cos\vartheta = 1 - \eta/2$: каждый шаг поворачивает пару, не уменьшая её. Вес вечно колеблется вокруг минимума с периодом $2\pi/\vartheta$ шагов.

**Разобранный пример.** При $\eta = 0.1$ и $w_0 = 0$ правильные шаги дают $w = 0.3, 0.57, 0.813, \dots$ и $2.995$ после 60 шагов. Без `zero_grad` первый шаг тот же, $0.3$, но второй использует $g_0 + g_1 = -3 - 2.7 = -5.7$ и даёт $0.87$. Дальше вес качается между $-0.04$ и $6.04$, при этом $\cos\vartheta = 0.95$, $\vartheta = 0.318$, а период равен $19.8$ шага.

На настоящей сети эффект зависит от поверхности функции потерь, но симптом тот же: функция потерь колеблется или расходится при шаге обучения, который должен быть безопасным. Иногда накопление нужно намеренно, чтобы имитировать батч, слишком большой для памяти: сложить градиенты $k$ маленьких батчей, разделив каждую функцию потерь на $k$, затем сделать шаг и обнулить градиенты.

### Операции на месте \{#in-place-operations\}

Операция, имя которой заканчивается подчёркиванием, например `x.mul_(2)`, и составное присваивание, например `x += 1`, перезаписывают память тензора — это операции на месте (in-place). Механизм автоматического дифференцирования (autograd) мог сохранить этот тензор для обратного прохода: производная сигмоиды равна $\sigma(z)(1 - \sigma(z))$, поэтому `torch.sigmoid` сохраняет свой выход. Каждый тензор несёт счётчик версий, который увеличивается при каждой операции на месте, и `backward` сравнивает его с сохранённой версией. Поэтому если изменить выход сигмоиды на месте, `backward` выдаст ошибку «one of the variables needed for gradient computation has been modified by an inplace operation». Эта ошибка хотя бы заявляет о себе. Незаметный вариант — изменение на месте через представление (view), которое меняет базовый тензор, который другой код всё ещё читает. Если память не критична, лучше писать `x = x * 2`, а не `x *= 2`.

### Softmax не по той размерности \{#softmax-over-the-wrong-dimension\}

Логиты для батча имеют форму `(batch, classes)`, и softmax должен нормировать каждую строку, `dim=1` (или `dim=-1`). С `dim=0` он нормирует каждый столбец, то есть по примерам батча. **Разобранный пример.** Для логитов со строками $(2, 1, 0)$ и $(0, 0, 3)$ `softmax(dim=1)` даёт строки $(0.665, 0.245, 0.090)$ и $(0.045, 0.045, 0.909)$, каждая из которых в сумме равна 1. `softmax(dim=0)` даёт $(0.881, 0.731, 0.047)$ и $(0.119, 0.269, 0.953)$, суммы строк которых равны $1.659$ и $1.341$. Это не распределения, и «вероятности» каждого примера теперь зависят от того, какие ещё примеры попали с ним в батч. Функции потерь в PyTorch снимают этот вопрос, принимая логиты, так что самое надёжное исправление — вообще не применять softmax перед функцией потерь.

Ещё три ошибки, которые стоят часов:

- **Формы, которые распространяются**, как в примере `(n, 1)` против `(n,)` выше.
- **Оценка в режиме обучения.** Если забыть `model.eval()`, дропаут остаётся включённым при тестировании, и сообщаемая доля правильных ответов оказывается ниже и шумной.
- **Накопление тензора функции потерь.** `total += loss` сохраняет граф каждого батча, пока `total` не освобождён; `total += loss.item()` хранит число.

## Что изменилось \{#what-changed\}

| | NumPy с градиентами, написанными вручную | PyTorch |
| --- | --- | --- |
| Обратный проход | выводится и программируется для каждого слоя | выводится из записанного прямого прохода |
| Единица графа | нет: одна формула на слой | одна операция над тензорами с её произведением вектора на матрицу Якоби |
| Новый слой или функция потерь | новый код производной | только код прямого прохода |
| Батчи и перемешивание | пишутся вручную | `Dataset` и `DataLoader` |
| Параметры и обновления | хранятся в переменных | регистрируются в `nn.Module`, обновляются оптимизатором |
| Типичные незаметные ошибки | неверная производная | распространение размерностей, пропущенный `zero_grad`, неверный `dim`, неверный режим |

## Ограничения \{#limitations\}

- **Autograd дифференцирует программу, а не математику.** Для операций с изломами принимается соглашение (производная ReLU в 0 равна 0), дискретные операции, такие как `argmax`, не пропускают градиент, а численно неустойчивые формулы дают неустойчивые градиенты.
- **Память.** Обратный режим хранит активации прямого прохода, пока их не использует обратный проход, поэтому память растёт с глубиной и размером батча.
- **Накладные расходы Python.** Каждая операция вызывается из Python; много крошечных операций работают медленно, поэтому работу объединяют в большие операции над тензорами, и поэтому наш скалярный класс годится только для обучения.
- **Незаметные ошибки остаются незаметными.** Библиотека проверяет формы на совместимость, а не на соответствие замыслу, и проверяет версии сохранённых тензоров, а не логику цикла обучения.

## Что нужно запомнить \{#what-you-should-remember\}

- Тензор — это форма, шаги, dtype и устройство поверх блока памяти; представления (view) разделяют эту память.
- Распространение размерностей выравнивает формы справа и растягивает размерности размера 1; `(n, 1)` против `(n,)` незаметно даёт `(n, n)`.
- Обратному режиму нужны локальные производные каждой операции и топологический порядок; узел, использованный дважды, складывает свои вклады. Сорок строк на Python воспроизводят градиенты PyTorch с точностью до ошибки округления.
- PyTorch записывает узлы `grad_fn` во время прямого прохода и прибавляет градиенты к `.grad`; отсюда `zero_grad()` перед каждым шагом.
- Конвейер: `Dataset`, `DataLoader`, `nn.Module`, функция потерь на логитах, оптимизатор; `model.eval()` и `torch.no_grad()` для оценки.
- Без `zero_grad` обновление — это импульс с $\beta = 1$: на квадратичной функции оно колеблется вечно.

## Код \{#code\}

Тензоры и представления, распространение размерностей, граф разобранного примера, полный конвейер на встроенном наборе цифр и три ошибки. Скалярное автоматическое дифференцирование и его сверка с PyTorch — в разделе выше. Начальные значения генератора (seed) зафиксированы; точные числа могут немного отличаться на разных платформах и версиях библиотек. Скрипт выполняется за несколько секунд на процессоре ноутбука.

```python
import torch
from torch import nn
from sklearn.datasets import load_digits

# 1. тензоры: форма, dtype и представление (view), разделяющее память с базовым тензором
x = torch.arange(6.0)
v = x.view(2, 3)
v[0, 0] = 100.0
print(x.dtype, v.shape, x[0].item(), v.t().is_contiguous())   # torch.float32 torch.Size([2, 3]) 100.0 False

# 2. распространение размерностей: центрирование столбцов батча и ловушка (3, 1) против (3,)
X = torch.tensor([[1.0, 2.0, 3.0], [3.0, 6.0, 9.0]])
print((X - X.mean(0)).tolist())                                 # [[-1.0, -2.0, -3.0], [1.0, 2.0, 3.0]]
pred, target = torch.tensor([[1.0], [2.0], [3.0]]), torch.tensor([1.0, 2.0, 3.0])
print((pred - target).shape, round(((pred - target) ** 2).mean().item(), 4), ((pred.squeeze(1) - target) ** 2).mean().item())
# torch.Size([3, 3]) 1.3333 0.0

# 3. граф, который PyTorch записывает для L = (a b + a)^2 при a = 2, b = -3
a, b = torch.tensor(2.0, requires_grad=True), torch.tensor(-3.0, requires_grad=True)
L = (a * b + a) ** 2
print(type(L.grad_fn).__name__, [type(f).__name__ for f, _ in L.grad_fn.next_functions])   # PowBackward0 ['AddBackward0']
L.backward()
print(a.grad.item(), b.grad.item())                             # 16.0 -16.0

# 4. конвейер: Dataset, DataLoader, Module, функция потерь и оптимизатор
class Digits(torch.utils.data.Dataset):
    def __init__(self, X, y):
        self.X, self.y = torch.tensor(X / 16.0, dtype=torch.float32), torch.tensor(y)
    def __len__(self):
        return len(self.y)
    def __getitem__(self, i):
        return self.X[i], self.y[i]

class MLP(nn.Module):
    def __init__(self, d_in=64, d_hidden=128, k=10, p=0.2):
        super().__init__()
        self.body = nn.Sequential(nn.Linear(d_in, d_hidden), nn.ReLU(), nn.Dropout(p))
        self.head = nn.Linear(d_hidden, k)
    def forward(self, x):
        return self.head(self.body(x))

Xd, yd = load_digits(return_X_y=True)
g = torch.Generator().manual_seed(0)
train, test = torch.utils.data.random_split(Digits(Xd, yd), [1437, 360], generator=g)
loader = torch.utils.data.DataLoader(train, batch_size=64, shuffle=True, generator=g)
print(len(loader), [xb.shape for xb, _ in loader][-1])          # 23 torch.Size([29, 64])

torch.manual_seed(0)
model = MLP()
print(sum(p.numel() for p in model.parameters()))               # 9610
opt = torch.optim.SGD(model.parameters(), lr=0.1, momentum=0.9)
Xte, yte = torch.stack([test[i][0] for i in range(len(test))]), torch.stack([test[i][1] for i in range(len(test))])

def evaluate():
    model.eval()                                                # дропаут выключен
    with torch.no_grad():                                       # без графа
        acc = (model(Xte).argmax(1) == yte).float().mean().item()
    model.train()
    return acc

for epoch in range(1, 11):
    for xb, yb in loader:
        opt.zero_grad()
        loss = nn.functional.cross_entropy(model(xb), yb)
        loss.backward()
        opt.step()
    if epoch in (1, 5, 10):
        print(epoch, round(evaluate(), 3))
# 1 0.864 | 5 0.964 | 10 0.964   (эпоха, доля правильных ответов на тесте)

# режим обучения случаен, режим оценки — нет
model.train(); out1, out2 = model(Xte[:1]), model(Xte[:1])
model.eval(); out3, out4 = model(Xte[:1]), model(Xte[:1])
print(torch.equal(out1, out2), torch.equal(out3, out4))         # False True

# 5. ошибка: нет zero_grad. L(w) = (w - 3)^2 / 2, w0 = 0, шаг 0.1; буфер .grad хранит сумму всех прошлых градиентов
for zero in (True, False):
    w = torch.tensor(0.0, requires_grad=True)
    opt = torch.optim.SGD([w], lr=0.1)
    path = []
    for step in range(60):
        if zero:
            opt.zero_grad()
        ((w - 3) ** 2 / 2).backward()
        opt.step()
        path.append(w.item())
    print(zero, [round(path[k], 3) for k in (0, 1, 2, 9, 29, 59)])
# True [0.3, 0.57, 0.813, 1.954, 2.873, 2.995]
# False [0.3, 0.87, 1.653, 5.982, 5.935, 0.16]

# 6. ошибка: изменение на месте тензора, который ещё нужен обратному проходу
z = torch.tensor([0.5, -1.0], requires_grad=True)
s = torch.sigmoid(z)        # обратный проход сигмоиды повторно использует её выход s
s.mul_(2)
try:
    s.sum().backward()
except RuntimeError as e:
    print(str(e).split(':')[0])
# one of the variables needed for gradient computation has been modified by an inplace operation

# 7. ошибка: softmax не по той размерности. Логиты для батча из 2 примеров и 3 классов
logits = torch.tensor([[2.0, 1.0, 0.0], [0.0, 0.0, 3.0]])
for dim in (1, 0):
    p = torch.softmax(logits, dim=dim)
    print(dim, [[round(v, 3) for v in row] for row in p.tolist()], [round(v, 3) for v in p.sum(1).tolist()])
# 1 [[0.665, 0.245, 0.09], [0.045, 0.045, 0.909]] [1.0, 1.0]   строки — распределения
# 0 [[0.881, 0.731, 0.047], [0.119, 0.269, 0.953]] [1.659, 1.341]   столбцы — распределения, строки — нет
```
