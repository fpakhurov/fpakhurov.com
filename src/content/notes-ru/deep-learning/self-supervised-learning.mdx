Каждая сеть из раздела «Свёрточные сети» училась по разметке: класс на изображение, рамка на объект, класс на пиксель. Разметка — дорогая часть набора данных, а попиксельные маски из [предыдущей заметки](/ru/notes/deep-learning/semantic-segmentation) — самая дорогая из всех, тогда как неразмеченные изображения почти ничего не стоят. **Обучение с самоконтролем** (self-supervised learning) обучает сеть только на изображениях, с задачей, цели которой вычисляются из самих изображений, а затем переиспользует признаки сети для задачи, у которой разметка есть. Эта заметка разбирает три семейства таких задач: от ранних вспомогательных задач через контрастивное обучение, которое сделало признаки без разметки такими же хорошими, как признаки с разметкой, до маскированного моделирования изображений, аналога [BERT](/ru/notes/nlp/bert) для изображений, — и линейный зонд, который измеряет, чего стоят признаки. В конце SimCLR обучается на неразмеченных цифрах, и его признаки обходят исходные пиксели, когда доступно только пять меток на класс.

**Обозначения.** Энкодер $f$ переводит изображение $x$ в **представление** (representation) $h = f(x) \in \mathbb R^d$ — признаки, которые сохраняются. Случайная **аугментация** $t$ из семейства $\mathcal T$ даёт **вид** (view) $t(x)$ изображения. Небольшая **проекционная голова** (projection head) $g$ переводит $h$ в $z = g(h)$ — вектор, который сравнивает функция потерь; $\bar z = z / \lVert z \rVert$ — его нормированная форма. Батч из $N$ изображений даёт $2N$ видов с индексами $i$, а $p(i)$ — индекс другого вида того же изображения. $s_{ik} = \bar z_i^\top \bar z_k$ — косинусное сходство двух видов, $\tau > 0$ — **температура**.

## Отправная точка: предобучение по разметке \{#baseline-pretrain-on-labels\}

Стандартный рецепт [предыдущего раздела](/ru/notes/deep-learning/cnn-architectures#transfer-learning-from-imagenet-backbones) предобучает базовую сеть (backbone) на 1.28 миллиона размеченных изображений ImageNet и дообучает её на целевой задаче. Он работает, и примерно до 2020 года ни один метод, обучавшийся без разметки, с ним не сравнялся. Его цена — разметка: человек должен посмотреть на каждое изображение, а обвести каждый объект для сегментации гораздо труднее, чем назвать один класс. Другое его ограничение в том, что признаки учат только то, чего требуют 1000 названий классов, например различать породы собак, и ничего сверх того, о чём разметка не спрашивает.

Вопрос этой заметки — могут ли одни изображения, без единой метки, обучить базовую сеть, признаки которой так же полезны, как признаки предобучения с разметкой. Метод обучения с самоконтролем отвечает **вспомогательной задачей** (pretext task): задачей предсказания, цель которой можно вычислить из изображения и которую решают только как средство получить хорошие признаки. Чего она стоит, измеряют потом, на задаче с разметкой.

## Вспомогательные задачи: метки из самого изображения \{#pretext-tasks-labels-made-from-the-image\}

Первые вспомогательные задачи преобразуют изображение известным способом и спрашивают сеть, какое преобразование было применено.

- **Поворот** ([Gidaris, Singh and Komodakis, 2018](#references)). Каждое изображение поворачивают на 0°, 90°, 180° или 270°, и сеть классифицирует поворот: кросс-энтропия на четыре класса, где метка — номер поворота. Чтобы понять, где верх, сеть должна найти объект и узнать его части, а это и есть знание, нужное классификатору.
- **Пазл** (jigsaw; [Noroozi and Favaro, 2016](#references)). Изображение режут на сетку плиток $3 \times 3$, плитки перемешивают одной из фиксированного набора перестановок, и сеть классифицирует, какая перестановка была применена. Из $9! = 362\,880$ возможных порядков авторы используют подмножество из 1000, выбранное так, чтобы любые два порядка различались во многих позициях.

Обе задачи страдают от **лазеек** (shortcuts): низкоуровневых признаков, которые решают задачу без всякого понимания содержания. Плитки пазла можно упорядочить, сопоставляя края соседних плиток или цветные каймы, которые объективы камер добавляют к краям изображения; поэтому плитки вырезают со случайными зазорами между ними и случайно искажают их цветовые каналы. Лазейка решает вспомогательную задачу и ничему не учит. Признаки вспомогательных задач приблизились к предобучению с разметкой на некоторых задачах переноса — для поворота на 2.4 пункта ниже него на детекции PASCAL VOC, — но при линейном зонде на ImageNet остались намного ниже, и каждую задачу приходилось придумывать вручную под свой вид данных.

## Контрастивное обучение \{#contrastive-learning\}

<aside class="callout"><strong>Ключевая идея.</strong> Вместо того чтобы предсказывать свойство одного изображения, сравнивать изображения. Две случайные аугментации одного изображения — <strong>положительная пара</strong> (positive pair), любые два вида разных изображений — <strong>отрицательная пара</strong> (negative pair). Энкодер обучают так, чтобы вид был ближе к своему партнёру, чем к любому другому виду в батче. Тогда признаки должны сохранять то, что переживает аугментации, — содержание изображения — и могут отбрасывать то, что аугментации меняют.</aside>

### SimCLR: два вида, энкодер и проекционная голова \{#simclr-two-views-an-encoder-and-a-projection-head\}

SimCLR ([Chen et al., 2020a](#references)) — простейшая полная форма этой идеи. Для каждого изображения батча он берёт две аугментации и пропускает оба вида через одну и ту же сеть:

$$
x \;\xrightarrow{\;t,\ t' \sim \mathcal T\;}\; t(x),\ t'(x) \;\xrightarrow{\;f\;}\; h,\ h' \;\xrightarrow{\;g\;}\; z,\ z' .
$$

Энкодер $f$ — ResNet, выход которого после глобального усредняющего пулинга и есть $h$; голова $g$ — небольшая сеть с одним скрытым слоем, $z = W_2\, \operatorname{ReLU}(W_1 h)$. Функция потерь сравнивает $z$ всех $2N$ видов батча сразу; она описана ниже. После обучения голову выбрасывают, а переиспользуют представление $h$.

<SimClrPipeline />

1. Для каждого из $N$ изображений берутся две случайные аугментации; батч превращается в $2N$ видов.
2. Энкодер $f$, общий для всех видов, переводит каждый вид в его представление $h$.
3. Голова $g$ переводит $h$ в $z$, который нормируется к единичной длине.
4. Вычисляется косинусное сходство каждой пары видов и делится на $\tau$; вид не сравнивается сам с собой.
5. Каждая строка — классификация среди остальных $2N - 1$ видов, где верный класс — парный вид; функция потерь — её кросс-энтропия, усреднённая по строкам.

### Функция потерь NT-Xent \{#the-nt-xent-loss\}

Для вида $i$ функция потерь равна

$$
\begin{gathered}
\boxed{\;\ell_i = -\log \frac{\exp\!\big(s_{i,p(i)}/\tau\big)}{\sum_{k \ne i} \exp\!\big(s_{ik}/\tau\big)}\;}, \\
L = \frac{1}{2N} \sum_{i=1}^{2N} \ell_i .
\end{gathered}
$$

[Chen et al. (2020a)](#references) называют её **NT-Xent** — нормированная кросс-энтропия с температурой (normalized temperature-scaled cross-entropy); это функция потерь InfoNCE из работы [van den Oord, Li and Vinyals (2018)](#references), применённая к парам видов. Её стоит читать как классификацию. Логиты вида $i$ — его сходства с $2N - 1$ другими видами, делённые на $\tau$; «класс», который нужно предсказать, — его партнёр $p(i)$; функция потерь — [кросс-энтропия по логитам](/ru/notes/deep-learning/losses-and-regularization#classification-cross-entropy-from-logits) этой задачи на $(2N-1)$ классов. Оба вида изображения по очереди служат якорями (anchors), так что каждая положительная пара входит в потерю дважды.

Градиент следует из градиента кросс-энтропии $\partial \ell / \partial(\text{logit}) = q - e_{p(i)}$, где логит равен $s_{ik}/\tau$, а $q_{ik} = \exp(s_{ik}/\tau) / \sum_{k' \ne i} \exp(s_{ik'}/\tau)$ — softmax по кандидатам:

$$
\frac{\partial \ell_i}{\partial s_{ik}} = \frac{1}{\tau}\Big(q_{ik} - \mathbb 1[k = p(i)]\Big) .
$$

Положительный пример притягивается с силой $(1 - q_{i,p(i)})/\tau$, а каждый отрицательный отталкивается с силой $q_{ik}/\tau$ — пропорционально его вероятности под softmax. Отрицательный пример, который уже выглядит непохожим, почти не получает градиента; **трудный отрицательный пример** (hard negative) — вид другого изображения, который выглядит похожим, — получает большую его часть. Нормировка важна: при $\bar z$ на единичной сфере каждое сходство лежит в $[-1, 1]$, так что уменьшить потерю можно только расположением направлений, а не раздуванием длин.

**Разобранный пример.** Два изображения $a$ и $b$, по два вида каждого, в порядке $(a, b, a', b')$, с нормированными двумерными эмбеддингами $\bar z_a = (1, 0)$, $\bar z_b = (0, 1)$, $\bar z_{a'} = (0.8, 0.6)$, $\bar z_{b'} = (-0.6, 0.8)$. Сходства равны $s_{aa'} = 0.8$, $s_{bb'} = 0.8$, $s_{ba'} = 0.6$, $s_{ab'} = -0.6$ и $s_{ab} = s_{a'b'} = 0$. При $\tau = 0.5$ у якоря $b$ логиты $0$ для $a$, $1.2$ для $a'$ и $1.6$ для его партнёра $b'$:

$$
\ell_b = -\log \frac{e^{1.6}}{e^{0} + e^{1.2} + e^{1.6}} = -\log \frac{4.953}{1 + 3.320 + 4.953} = -\log 0.534 = 0.627 .
$$

У якоря $a$ логиты $0$, $1.6$ и $-1.2$, так что $\ell_a = -\log(4.953 / 6.254) = 0.233$; по симметрии $\ell_{a'} = \ell_b$ и $\ell_{b'} = \ell_a$, и $L = 0.430$. У якоря $b$ потеря больше, потому что $a'$ — трудный отрицательный пример: он почти так же близок к $b$ ($0.6$), как собственный партнёр $b$ ($0.8$). Веса softmax равны $q = (0.108, 0.358, 0.534)$, поэтому трудный отрицательный пример $a'$ получает толчок $0.358/0.5 = 0.716$, а лёгкий $a$ — только $0.216$.

### Почему важна температура \{#why-the-temperature-matters\}

Температура задаёт, насколько резко softmax различает кандидатов. Отношение градиентов на двух отрицательных примерах со сходствами $s$ и $s'$ равно

$$
\frac{q_{ik}}{q_{ik'}} = \exp\!\Big(\frac{s - s'}{\tau}\Big),
$$

так что при малом $\tau$ в градиенте доминируют самые трудные отрицательные примеры, а при большом $\tau$ он распределяется равномерно. В разобранном примере трудный отрицательный пример $a'$ якоря $b$ получает в $e^{0.6} = 1.8$ раза больший градиент, чем лёгкий, при $\tau = 1$, в $e^{1.2} = 3.3$ раза при $\tau = 0.5$ и в $e^{6} = 403$ раза при $\tau = 0.1$. Потеря $b$ падает с $0.819$ до $0.627$ и $0.127$, потому что деление на малое $\tau$ ещё и растягивает разрыв между положительным примером и отрицательными.

Ни одна из крайностей не хороша. При очень большом $\tau$ все отрицательные примеры весят одинаково, и функция потерь почти не отличает хорошее расположение от плохого; при очень малом $\tau$ градиент приходит от горстки отрицательных примеров, часть из которых на самом деле не отрицательные (две разные фотографии кошек), и расталкивание их портит признаки. С ResNet-50, батчами по 4096 и 100 эпохами доля правильных ответов (accuracy) линейного зонда SimCLR на ImageNet была 59.7% при $\tau = 0.05$, 64.4% при $\tau = 0.1$, 60.7% при $0.5$ и 58.0% при $1$; без нормировки сеть чаще решала контрастивную задачу (92% против 88% при $\tau = 0.1$), а её признаки были хуже, 57% ([Chen et al., 2020a](#references), таблица 5). То же масштабирование логитов температурой встречается при [сэмплировании из языковой модели](/ru/notes/nlp/gpt#temperature), где оно обменивает надёжность на разнообразие.

### Почему важны большие батчи \{#why-large-batches-matter\}

Каждый якорь классифицируется против $2N - 2$ отрицательных примеров, поэтому размер батча задаёт трудность задачи. Отсюда два следствия. Если бы все сходства были равны, каждое $q_{ik}$ было бы $1/(2N - 1)$, а потеря — $\log(2N - 1)$, то есть $6.236$ при $N = 256$; это начальная точка обучения и шкала, на которой измеряют прогресс. А [van den Oord, Li and Vinyals (2018)](#references), раздел 2.3, показывают, что функция потерь InfoNCE с $K$ кандидатами ограничивает снизу взаимную информацию (mutual information) между двумя видами, $I \ge \log K - \ell$: поскольку $\ell \ge 0$, эта граница никогда не превосходит $\log K$, так что батч из 256 изображений ($K = 511$) может подтвердить не больше $6.24$ ната (nats) общей информации между видами, как бы хорош ни был энкодер. Больше отрицательных примеров — труднее задача и выше потолок.

В экспериментах SimCLR большие батчи помогали больше всего при коротком обучении: при 100 эпохах доля правильных ответов линейного зонда стабильно росла с размером батча от 256 до 8192, а при более долгом обучении разрывы сокращались ([Chen et al., 2020a](#references), раздел 5.2 и рисунок 9). Батч из 4096 изображений, значение по умолчанию, требует многих ускорителей — это практическая слабость, которую устраняет MoCo, описанный ниже.

### Какие аугментации и почему голову выбрасывают \{#which-augmentations-and-why-the-head-is-thrown-away\}

Аугментации определяют, что признаки игнорируют, а значит, решают, что они содержат. SimCLR использует случайные кадрирования, растянутые обратно до полного размера, искажение цвета и гауссово размытие, и обнаружил, что решающая комбинация одна: кадрирование вместе с искажением цвета. У одних кадрирований есть лазейка: два фрагмента одной фотографии имеют общую цветовую гистограмму, которая опознаёт изображение без всякого распознавания его содержания; независимое искажение цветов в каждом виде убирает эту лазейку ([Chen et al., 2020a](#references), раздел 3.1 и рисунок 6). Контрастивному обучению к тому же нужна более сильная аугментация, чем обучению с учителем: по мере усиления искажения цвета доля правильных ответов линейного зонда SimCLR росла с 59.6% до 64.5%, а доля правильных ответов ResNet-50, обученной с учителем с той же аугментацией, падала с 77.0% до 75.4% (раздел 3.2, таблица 1). Аугментации должны сохранять метку целевой задачи: как и при [аугментации в обучении с учителем](/ru/notes/deep-learning/losses-and-regularization#data-augmentation), горизонтальное отражение подходит для фотографий и неверно для цифр.

Голову выбрасывают, потому что функция потерь делает $z$ инвариантным к аугментациям, а эта инвариантность уничтожает информацию, например о цвете или ориентации, которая может понадобиться целевой задаче. Голова даёт сети место, где эту информацию можно отбросить: $h$, до головы, сохраняет больше. С нелинейной головой линейный классификатор на $h$ был больше чем на 10 пунктов лучше классификатора на $z$, а нелинейная голова обошла линейную на 3 пункта и вариант без головы — больше чем на 10 ([Chen et al., 2020a](#references), раздел 4.2 и рисунок 8).

Со всем этим линейный классификатор на признаках SimCLR достиг доли правильных ответов top-1 69.3% на ImageNet с ResNet-50 и 76.5% с вчетверо более широкой ResNet-50 — уровня ResNet-50, обученной с учителем ([Chen et al., 2020a](#references), таблица 6).

## MoCo: очередь отрицательных примеров и энкодер со скользящим средним \{#moco-a-queue-of-negatives-and-a-momentum-encoder\}

SimCLR берёт отрицательные примеры из текущего батча, так что для большего их числа нужен больший батч. **MoCo** ([He et al., 2020](#references)) разделяет одно и другое. Он хранит **очередь** (queue) закодированных ключей $k$ недавних батчей как словарь отрицательных примеров: на каждом шаге ключи текущего батча добавляются, а самые старые удаляются. Вид-запрос $q$ изображения сравнивается со своим ключом $k_+$, другим видом, и с $K$ ключами очереди той же функцией потерь InfoNCE, $\ell_q = -\log\big(e^{q \cdot k_+/\tau} / \sum_{i=0}^{K} e^{q \cdot k_i/\tau}\big)$, где сумма идёт по $k_+$ и $K$ ключам из очереди; MoCo использует $K = 65\,536$ и $\tau = 0.07$ с обычными батчами по 256 изображений.

Ключи в очереди должны оставаться сравнимыми, хотя они были вычислены много шагов назад. Если бы энкодером ключей был сам энкодер запросов, его веса менялись бы на каждом шаге, и старые ключи оказались бы закодированы другой сетью. Поэтому MoCo вычисляет ключи отдельным энкодером (momentum encoder), веса которого $\theta_k$ следуют за весами энкодера запросов $\theta_q$ как медленное скользящее среднее, а обратным распространением ошибки обучаются только $\theta_q$:

$$
\theta_k \leftarrow m\, \theta_k + (1 - m)\, \theta_q, \qquad m = 0.999 .
$$

**Разобранный пример.** При $m = 0.999$ энкодер ключей усредняет примерно последние $1/(1 - m) = 1000$ версий энкодера запросов: если $\theta_q$ переходит к новому значению и остаётся там, $\theta_k$ проходит $1 - 0.999^{1000} = 63\%$ расстояния за 1000 шагов. Очередь из 65 536 ключей вмещает 256 батчей по 256, так что её самые старые ключи были закодированы 256 шагов назад энкодером ключей, который с тех пор сдвинулся лишь на $1 - 0.999^{256} = 23\%$ пути к любому изменению энкодера запросов: старые и новые ключи получены почти одной и той же сетью. С очередью из 4096 коэффициент обновления (momentum) имел значение: доля правильных ответов линейного зонда была 55.2% при $m = 0.9$, 57.8% при $0.99$, 59.0% при $0.999$ и 58.9% при $0.9999$, а при $m = 0$, когда энкодер ключей — копия энкодера запросов, обучение не сходилось ([He et al., 2020](#references), раздел 4.1). С ResNet-50 MoCo достиг 60.6% при линейном зонде, а его признаки, дообученные для детекции и сегментации, превзошли предобучение на ImageNet с учителем в 7 задачах на PASCAL VOC, COCO и других наборах данных (разделы 4.1 и 4.2).

## Без отрицательных примеров: BYOL и SimSiam \{#without-negatives-byol-and-simsiam\}

*Для углублённого чтения: два метода, которые обходятся без отрицательных примеров. Остальная часть заметки от этого раздела не зависит.*

Отрицательные примеры нужны, чтобы предотвратить **коллапс** (collapse): без них функцию потерь «виды одного изображения должны совпадать» минимизирует энкодер, который переводит каждое изображение в один и тот же вектор. **BYOL** ([Grill et al., 2020](#references)) всё равно отказывается от отрицательных примеров и избегает коллапса за счёт асимметрии. Онлайн-сеть (online network) с дополнительным **предиктором** (predictor) $q_\theta$ предсказывает нормированную проекцию другого вида, вычисленную целевой сетью (target network), а функция потерь — квадрат расстояния между двумя нормированными векторами, $\lVert \bar q_\theta(z) - \bar z'_\xi \rVert^2 = 2 - 2 \cos\big(q_\theta(z), z'_\xi\big)$. В целевую сеть градиент не проходит; её веса $\xi$ — скользящее среднее весов онлайн-сети $\theta$, как в MoCo. BYOL достиг 74.3% с ResNet-50 при линейном зонде. **SimSiam** ([Chen and He, 2021](#references)) показал, что не нужно даже скользящее среднее: с предиктором на одной стороне и **остановкой градиента** (stop-gradient) на другой одна общая сеть не коллапсирует и достигает 67.7% после 100 эпох. Если убрать только остановку градиента, сеть коллапсирует в константу с долей правильных ответов 0.1% — уровнем угадывания среди 1000 классов. Почему асимметрия предотвращает коллапс, до сих пор понятно лишь отчасти; обе статьи предлагают объяснения, а не доказательства.

## Маскированное моделирование изображений: MAE \{#masked-image-modelling-mae\}

Другое семейство возвращается к предсказанию, теперь самого изображения. [BERT](/ru/notes/nlp/bert#masked-language-modelling) прячет 15% токенов предложения и предсказывает их по остальным. **Маскированный автоэнкодер** (masked autoencoder, MAE, [He et al., 2022](#references)) делает то же с изображением, разрезанным на патчи, используя Vision Transformer из [следующей заметки](/ru/notes/deep-learning/vision-transformers), который обрабатывает изображение как последовательность патчей:

1. Разрезать изображение на патчи $16 \times 16$ пикселей и спрятать случайные 75% из них.
2. Энкодер видит только видимые 25%; токен маски он не видит никогда.
3. Небольшой декодер получает закодированные видимые патчи и токены маски на скрытых позициях и восстанавливает пиксели скрытых патчей; в лучшем варианте каждый целевой патч нормируется своим средним и стандартным отклонением.
4. Функция потерь — среднеквадратичная ошибка (MSE) только на скрытых патчах, как функция потерь BERT считается только на замаскированных токенах.

Доля маскирования (masking ratio) — главное отличие от BERT. Текст плотен по смыслу, поэтому 15% скрытых слов уже дают трудную задачу; изображения избыточны, и пропущенный патч можно восстановить по соседям, если большинство из них тоже не исчезло. При 75% задача требует модели объектов и сцен, а не интерполяции, а поскольку энкодер обрабатывает четверть патчей, предобучение идёт в три и более раза быстрее. ViT-Huge, предобученный так только на ImageNet-1K, достиг 87.8% после дообучения при разрешении 448. Маскированный автоэнкодер — это [шумоподавляющий автоэнкодер](/ru/notes/generative-models/autoencoders#denoising-autoencoder), шум которого — маскирование.

Признаки MAE показывают, почему одной оценки недостаточно. С ViT-Large они дают 84.9%, когда дообучается вся сеть, но лишь 73.5% при линейном зонде — меньше, чем контрастивные признаки той же сети; дообучение одного последнего блока уже даёт 81.0% ([He et al., 2022](#references), раздел 4.1, таблица 1 и раздел 4.3). Признаки, обученные на восстановлении пикселей, хуже линейно разделимы, но сильны, как только несколько слоёв подстраиваются.

## Линейный зонд \{#the-linear-probe\}

Признаки обучения с самоконтролем оценивают на размеченной задаче. Стандартный протокол — **линейный зонд** (linear probe): заморозить энкодер, вычислить $h$ для каждого размеченного изображения и обучить поверх только линейный классификатор (логистическую регрессию). Его доля правильных ответов показывает, сколько информации о классе признаки несут в линейно доступной форме. Его дополняют три протокола:

- **Дообучение** (fine-tuning): обучить всю сеть, начиная с предобученных весов, на размеченной задаче. Оно измеряет признаки как инициализацию, а именно так их используют на практике ([перенос обучения](/ru/notes/deep-learning/cnn-architectures#transfer-learning-from-imagenet-backbones)).
- **Мало меток**: зонд или дообучение с 1% или 10% меток — там, где предобучение важнее всего.
- **Перенос**: другие наборы данных и задачи, например детекция и сегментация.

Зонду нужна точка отсчёта. Случайный, необученный энкодер — нижняя планка, которую даёт одна архитектура; исходные пиксели — ещё одна. Зонд, который обходит обе, показывает, что информацию туда поместило предобучение, а не архитектура.

## Ограничения \{#limitations\}

- **Аугментации — это априорное знание.** Контрастивные признаки инвариантны ровно к тому, что меняют аугментации. Признаки, инвариантные к цвету, не годятся для задачи о цвете, а выбор аугментаций для медицинских изображений или спектрограмм — такая же работа по проектированию, как старые вспомогательные задачи.
- **Ложные отрицательные примеры.** Два изображения одного класса в батче расталкиваются как отрицательные. При многих классах это редкость; при немногих классах или малой температуре это тянет признаки против меток целевой задачи.
- **Вычисления.** Контрастивным методам нужны большие батчи или очереди и сотни эпох; результаты на ImageNet выше потребовали от 100 до 1000 эпох, у SimCLR — с батчами по 4096 изображений.
- **Одно число не ранжирует методы.** Линейный зонд, дообучение и перенос могут упорядочивать методы по-разному, как показывает MAE; результаты разных протоколов, архитектур или числа эпох несравнимы.
- **Коллапс — реальный режим отказа.** Методы без отрицательных примеров зависят от асимметрий (предиктор, остановка градиента, скользящее среднее), удаление которых приводит к коллапсу и работа которых объяснена лишь отчасти.

## Что нужно запомнить \{#what-you-should-remember\}

- Обучение с самоконтролем обучает сеть на задаче, цели которой берутся из данных, а затем переиспользует признаки; их измеряет линейный зонд на замороженных признаках.
- Вспомогательные задачи (поворот, пазл) работают, но открывают лазейки; контрастивные и маскированные цели пришли им на смену.
- SimCLR: два аугментированных вида, общий энкодер $f$, проекционная голова $g$ и NT-Xent, $\ell_i = -\log\big(e^{s_{i,p(i)}/\tau} / \sum_{k \ne i} e^{s_{ik}/\tau}\big)$, — кросс-энтропия на $(2N - 1)$ классов по косинусным сходствам. $h$ сохраняют, $g$ выбрасывают.
- Градиент на отрицательном примере равен $q_{ik}/\tau$: температура решает, насколько доминируют самые трудные отрицательные примеры. Размер батча задаёт число отрицательных примеров и потолок потери $\log(2N - 1)$.
- MoCo хранит 65 536 отрицательных примеров в очереди, закодированной энкодером со скользящим средним, $\theta_k \leftarrow 0.999\,\theta_k + 0.001\,\theta_q$; BYOL и SimSiam не нуждаются в отрицательных примерах, но против коллапса зависят от предиктора и остановки градиента.
- MAE прячет 75% патчей и восстанавливает их — цель BERT для изображений; его признаки превосходны после дообучения и слабее при линейном зонде.
- На цифрах с пятью метками на класс признаки SimCLR дают долю правильных ответов зонда 0.942 против 0.825 на исходных пикселях.

## Код \{#code\}

Разобранный пример NT-Xent при трёх температурах, потеря энкодера, который не различает виды, SimCLR на неразмеченных цифрах и линейные зонды на пикселях, случайном энкодере и обученном. Начальные значения генераторов зафиксированы; точные числа могут отличаться на разных платформах и версиях библиотек. Скрипт работает около 20 секунд на процессоре ноутбука, почти всё время уходит на обучение.

```python
import math, numpy as np, torch
from torch import nn
import torch.nn.functional as F
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
torch.set_num_threads(1)                    # маленькие свёртки быстрее работают в одном потоке

def nt_xent(z, tau):
    """NT-Xent for 2N views ordered (x_1..x_N, x'_1..x'_N): view i's positive is view i + N (mod 2N)."""
    z = F.normalize(z, dim=1)
    s = z @ z.T / tau
    s.fill_diagonal_(float('-inf'))                       # вид никогда не бывает собственным кандидатом
    n = len(z) // 2
    target = torch.cat([torch.arange(n, 2 * n), torch.arange(n)])
    return F.cross_entropy(s, target, reduction='none')   # одна потеря на якорь

# 1. разобранный пример: два изображения, по два вида, двумерные эмбеддинги; порядок (a, b, a', b')
z = torch.tensor([[1.0, 0.0], [0.0, 1.0], [0.8, 0.6], [-0.6, 0.8]])
print([[round(v, 2) for v in row] for row in (F.normalize(z) @ F.normalize(z).T).tolist()])
# [[1.0, 0.0, 0.8, -0.6], [0.0, 1.0, 0.6, 0.8], [0.8, 0.6, 1.0, 0.0], [-0.6, 0.8, 0.0, 1.0]]
for tau in (1.0, 0.5, 0.1):
    l = nt_xent(z, tau)
    print(tau, [round(v, 4) for v in l.tolist()], round(l.mean().item(), 4))
# 1.0 [0.5282, 0.8189, 0.8189, 0.5282] 0.6736
# 0.5 [0.2333, 0.6271, 0.6271, 0.2333] 0.4302
# 0.1 [0.0003, 0.1272, 0.1272, 0.0003] 0.0638

# 2. при случайных признаках (все сходства равны) потеря равна log(2N - 1): один положительный среди 2N - 1 кандидатов
N = 256
print(round(nt_xent(torch.ones(2 * N, 8), 0.5).mean().item(), 4), round(math.log(2 * N - 1), 4))   # 6.2364 6.2364

# 3. данные: 1078 обучающих цифр используются без меток, 719 тестовых; метки нужны только линейному зонду
X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.4, random_state=0, stratify=y)
Xtr, Xte = [torch.tensor(a, dtype=torch.float32).view(-1, 1, 8, 8) for a in (Xtr, Xte)]

def augment(x):
    """A random view: rotation up to 15 degrees, scale 0.9-1.1, shift up to 1 pixel, contrast, pixel noise."""
    n = len(x)
    angle = (torch.rand(n) * 2 - 1) * math.radians(15)
    scale = 1 + (torch.rand(n) * 2 - 1) * 0.1
    shift = (torch.rand(n, 2) * 2 - 1) * 0.25           # 0.25 в единицах сетки = 1 пиксель из 8
    cos, sin = torch.cos(angle) / scale, torch.sin(angle) / scale
    theta = torch.stack([torch.stack([cos, -sin, shift[:, 0]], 1), torch.stack([sin, cos, shift[:, 1]], 1)], 1)
    out = F.grid_sample(x, F.affine_grid(theta, x.shape, align_corners=False), align_corners=False)
    return out * (0.7 + 0.6 * torch.rand(n, 1, 1, 1)) + 0.1 * torch.randn_like(out)

def encoder():                              # f: изображение 8 x 8 -> h из R^64
    return nn.Sequential(nn.Conv2d(1, 16, 3, padding=1), nn.BatchNorm2d(16), nn.ReLU(),
                         nn.Conv2d(16, 32, 3, padding=1), nn.BatchNorm2d(32), nn.ReLU(), nn.MaxPool2d(2),
                         nn.Conv2d(32, 64, 3, padding=1), nn.BatchNorm2d(64), nn.ReLU(),
                         nn.AdaptiveAvgPool2d(1), nn.Flatten())

def features(net, x):
    net.eval()
    with torch.no_grad():
        return net(x).numpy()

def probe(Htr, Hte, per_class=None, draws=5):
    """Linear probe: logistic regression on frozen, standardized features; test accuracy, mean over label draws."""
    mu, sd = Htr.mean(0), Htr.std(0) + 1e-6
    Htr, Hte = (Htr - mu) / sd, (Hte - mu) / sd
    accs = []
    for d in range(draws if per_class else 1):
        rng = np.random.default_rng(d)
        idx = (np.concatenate([rng.choice(np.where(ytr == c)[0], per_class, replace=False) for c in range(10)])
               if per_class else np.arange(len(ytr)))
        accs.append(LogisticRegression(max_iter=2000).fit(Htr[idx], ytr[idx]).score(Hte, yte))
    return np.mean(accs)

# 4. SimCLR: два вида на изображение, энкодер f, проекционная голова g, NT-Xent, батчи по 256 изображений
TAU = 0.5
torch.manual_seed(0)
random_f = encoder()                        # точка отсчёта: тот же энкодер, никогда не обучавшийся
torch.manual_seed(0)
f, g = encoder(), nn.Sequential(nn.Linear(64, 64), nn.ReLU(), nn.Linear(64, 32))
opt = torch.optim.Adam([*f.parameters(), *g.parameters()], lr=1e-3)
for epoch in range(50):
    f.train(); g.train()
    perm = torch.randperm(len(Xtr))
    for i in range(0, len(Xtr) - N + 1, N):  # 4 шага на эпоху, последний неполный батч отбрасывается
        xb = Xtr[perm[i:i + N]]
        loss = nt_xent(g(f(torch.cat([augment(xb), augment(xb)]))), TAU).mean()
        opt.zero_grad(); loss.backward(); opt.step()
    if epoch in (0, 49):
        print(epoch + 1, round(loss.item(), 3))
```
