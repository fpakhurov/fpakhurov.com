[Предыдущая заметка](/ru/notes/acos/risc-v-instructions) разобрала вычислительные команды до отдельных битов. Каждая программа, построенная из них до сих пор, выполняется прямо от первой команды до последней и держит все свои данные в 32 регистрах. Этого достаточно для калькулятора, но не для программы: нельзя повторить шаг столько раз, сколько станет известно только во время выполнения, выбрать одно из двух действий или работать с данными, которые не помещаются в регистры. Эта заметка добавляет два недостающих элемента. Ветвления и переходы меняют `pc`, и с их помощью мы вручную компилируем `if`, `while` и `for`. Загрузки и сохранения перемещают байты, полуслова и слова между регистрами и памятью, и это даёт нам массивы и строки. Заметка заканчивается удобствами, которые делают длинные программы терпимыми: псевдокомандами, именованными константами, макросами и включаемыми файлами.

**Обозначения.** `label` — адрес в программе. $x[r]$ — значение в регистре $r$, $M[a]$ — байт по адресу $a$. $\operatorname{sext}$ и $\operatorname{zext}$ расширяют значение до 32 бит, копируя его знаковый бит или дописывая нули. **Полуслово** (halfword) — 2 байта, **слово** (word) — 4 байта.

## Отправная точка: линейный код \{#baseline-straight-line-code\}

Возьмём задачу сложить шесть чисел: 12, −7, 30, 5, −2 и 19. Тем, что у нас есть, программа записывается как шесть команд `li` и пять `add`, по одной на число. Она работает, но не годится ни в одном важном отношении:

- программа растёт вместе с данными: тысяча чисел требует двух тысяч команд;
- число значений фиксируется при написании программы, а не при её выполнении;
- все значения должны одновременно помещаться в регистры, а пригодных регистров 31;
- программа не может реагировать на свои данные: не может остановиться на нуле, пропустить отрицательное число или выбрать большее из двух.

Это исправляют два механизма. **Поток управления** (control flow): команды, которые записывают в `pc` что-то кроме адреса следующей команды, так что код можно пропустить или повторить. **Обращения к памяти**: команды, которые читают и пишут память по адресу, вычисленному во время выполнения, так что одни и те же команды могут обходить элемент за элементом.

## Ветвления и переходы \{#branches-and-jumps\}

**Условное ветвление** (conditional branch) сравнивает два регистра и, если условие выполнено, переходит на метку; иначе выполнение продолжается со следующей команды:

| Команда | Переходит, когда |
| --- | --- |
| `beq rs1, rs2, label` | $x[rs1] = x[rs2]$ |
| `bne rs1, rs2, label` | $x[rs1] \ne x[rs2]$ |
| `blt rs1, rs2, label` | $x[rs1] < x[rs2]$ как числа со знаком |
| `bge rs1, rs2, label` | $x[rs1] \ge x[rs2]$ как числа со знаком |
| `bltu rs1, rs2, label` | $x[rs1] < x[rs2]$ как числа без знака |
| `bgeu rs1, rs2, label` | $x[rs1] \ge x[rs2]$ как числа без знака |

Метка хранится как смещение от самого ветвления в формате B из [предыдущей заметки](/ru/notes/acos/risc-v-instructions#encoding-by-hand), поэтому ветвление достаёт на ±4 КиБ вокруг себя. Безусловный переход `jal rd, label` достаёт на ±1 МиБ и записывает в `rd` адрес следующей команды; при `rd` = `zero` этот адрес выбрасывается и остаётся только переход, который ассемблер предлагает как `j label`. Сохранение адреса возврата — то, что делает возможными процедуры, тему [следующей заметки](/ru/notes/acos/procedures-and-the-stack).

Шести ветвлений достаточно, потому что остальные — те же проверки с переставленными операндами: $a > b$ — это $b < a$, так что `bgt a, b, L` — псевдокоманда для `blt b, a, L`, а `ble a, b, L` — для `bge b, a, L`. Сравнения с нулём используют `zero` как второй операнд: `beqz t0, L` — это `beq t0, zero, L`, и аналогично `bnez`, `bltz`, `bgez`, `blez`, `bgtz`.

**Разобранный пример.** Пусть `t0` = −1, то есть слово `0xffffffff`, и `t1` = 1. `blt t0, t1, L` переходит, потому что $-1 < 1$. `bltu t0, t1, L` не переходит, потому что как число без знака `t0` равен 4 294 967 295. Биты одни и те же; что они значат, решает команда, в точности как у `slt` и `sltu`. У беззнакового прочтения есть практическое применение: для индекса `i` и длины `n` ≥ 0 одна команда `bgeu i, n, out_of_range` ловит и `i` ≥ `n`, и отрицательное `i`, потому что отрицательное `i` — огромное число без знака.

## if/else и циклы на ассемблере \{#ifelse-and-loops-in-assembly\}

<aside class="callout"><strong>Ключевая идея.</strong> Каждый структурный оператор превращается в условные ветвления по обратному условию плюс безусловные переходы. `if` при ложном условии перепрыгивает *через* свою then-часть; `else` добавляет в конце then-части переход через себя; цикл — это `if`, последняя команда которого переходит назад к проверке.</aside>

Шаблоны, записанные для условия `a < b`:

| C | Ассемблер |
| --- | --- |
| `if (a < b) S1;` | `bge a, b, end` · S1 · `end:` |
| `if (a < b) S1; else S2;` | `bge a, b, else` · S1 · `j end` · `else:` S2 · `end:` |
| `while (a < b) S;` | `loop: bge a, b, end` · S · `j loop` · `end:` |
| `do S; while (a < b);` | `loop:` S · `blt a, b, loop` |
| `for (i = 0; i < n; i++) S;` | `li i, 0` · `loop: bge i, n, end` · S · `addi i, i, 1` · `j loop` · `end:` |

В цикле `while` каждая итерация выполняет две управляющие команды: проверку вверху и `j` внизу. Компиляторы обычно переносят проверку в конец цикла, как в `do` (loop rotation), и ставят одну дополнительную проверку перед ним, чтобы пропустить цикл, который не должен выполниться ни разу; тогда на каждой итерации остаётся одно ветвление. Сумма массива ниже делает именно так.

**Разобранный пример.** Итерация Коллатца: пока $n \ne 1$, чётное $n$ делится пополам, а нечётное $n$ заменяется на $3n + 1$; шаги считаются, а наибольшее встреченное значение запоминается. Здесь есть цикл, if/else внутри него и второй `if` для максимума:

```riscv
loop:   beq  t0, t3, done           # while (n != 1): выйти, когда n == 1 (в t3 лежит 1)
        andi t4, t0, 1              # t4 = младший бит n
        bnez t4, odd                # если n нечётное, перепрыгнуть then-часть
        srli t0, t0, 1              # then: n = n / 2
        j    next                   # и перепрыгнуть else-часть
odd:    slli t4, t0, 1              # else: n = 3n + 1, вычисляется как 2n + n + 1
        add  t0, t0, t4
        addi t0, t0, 1
next:   addi t1, t1, 1              # steps++
        ble  t0, t2, loop           # if (n > max) max = n ...
        mv   t2, t0
        j    loop                   # ... и назад к проверке
```

<CollatzFlow />

1. Проверка цикла стоит первой; когда `t0` = 1, `beq` выводит из цикла к `done`.
2. `if` проверяет младший бит командой `andi`, и `bnez` перепрыгивает then-часть, когда число нечётное: ветвление проверяет условие, обратное условию в C.
3. Then-часть делит $n$ пополам сдвигом и заканчивается командой `j next` — переходом через else-часть.
4. Else-части переход не нужен: выполнение просто продолжается в `next`, где обе ветви сходятся.
5. `next` считает шаг; `ble` переходит назад к проверке, когда новое $n$ не больше максимума, а иначе `mv` запоминает его и `j loop` возвращает к проверке.

Начиная с $n = 27$, цикл выполняется 111 раз, а наибольшее значение равно 9232. Вся программа с подготовкой и выводом выполняет 864 команды (раздел «Код» печатает оба числа).

## Загрузки и сохранения: байты, полуслова и слова \{#loads-and-stores-bytes-halves-and-words\}

Память — массив байтов, и адрес называет один байт. **Загрузка** (load) копирует байты из памяти в регистр; **сохранение** (store) копирует их из регистра в память. В RISC-V один режим адресации: адрес — это регистр плюс 12-битное смещение со знаком, записывается `offset(base)`:

$$
\text{адрес} = x[rs1] + \operatorname{sext}(imm), \qquad -2048 \le imm \le 2047 .
$$

| Команда | Действие |
| --- | --- |
| `lw rd, imm(rs1)` | $x[rd]$ = 4 байта по этому адресу |
| `lh rd, imm(rs1)`, `lhu rd, imm(rs1)` | $x[rd]$ = $\operatorname{sext}$ или $\operatorname{zext}$ от 2 байтов по этому адресу |
| `lb rd, imm(rs1)`, `lbu rd, imm(rs1)` | $x[rd]$ = $\operatorname{sext}$ или $\operatorname{zext}$ от байта по этому адресу |
| `sw rs2, imm(rs1)` | 4 байта по этому адресу = $x[rs2]$ |
| `sh rs2, imm(rs1)`, `sb rs2, imm(rs1)` | младшие 2 байта или младший байт $x[rs2]$ записываются по этому адресу |

Регистр всегда содержит 32 бита, поэтому загрузка меньшего числа байтов должна решить, чем заполнить остальное. Знаковые загрузки `lb` и `lh` копируют старший бит прочитанного значения во все старшие биты, что сохраняет отрицательное число; `lbu` и `lhu` заполняют их нулями, что сохраняет число без знака. Сохранениям такой выбор не нужен: они записывают только младшие байты регистра. Многобайтовые значения хранятся младшим байтом вперёд — это [порядок байтов](/ru/notes/acos/data-representation#byte-order) little-endian, а расширение следует правилам [знакового расширения и расширения нулями](/ru/notes/acos/data-representation#sign-and-zero-extension).

<LoadExtension />

**Разобранный пример.** Четыре байта по адресу `w`: `f6 00 80 ff`, и `t0` = `w`.

| Загрузка | Прочитанные байты | 32-битный результат | Значение |
| --- | --- | --- | --- |
| `lb a0, 0(t0)` | `f6` | `0xfffffff6` | −10 |
| `lbu a0, 0(t0)` | `f6` | `0x000000f6` | 246 |
| `lh a0, 2(t0)` | `80 ff` | `0xffffff80` | −128 |
| `lhu a0, 2(t0)` | `80 ff` | `0x0000ff80` | 65 408 |
| `lw a0, 0(t0)` | `f6 00 80 ff` | `0xff8000f6` | −8 388 362 |

`sb` значения `0x7f` по адресу `3(t0)` меняет только старший байт; следующая `lw` возвращает `0x7f8000f6`. Выбор загрузки важен ровно тогда, когда старший бит прочитанного значения равен 1: символ с кодом больше 127, прочитанный через `lb`, становится отрицательным.

**Выравнивание** (alignment). Обращение к слову должно использовать адрес, кратный 4, а обращение к полуслову — кратный 2. Что происходит иначе, спецификация оставляет решать среде выполнения ([RISC-V Unprivileged ISA](#references), команды загрузки и сохранения): одни процессоры выполняют такое обращение медленно, другие вызывают ловушку. RARS останавливает программу с ошибкой невыровненного адреса, так же поступает и программа проверки примеров, поэтому данные размещаются по выровненным адресам.

## Данные в памяти: директивы и выравнивание \{#data-in-memory-directives-and-alignment\}

Сегмент данных заполняется директивами по порядку, в RARS — начиная с `0x10010000`. `.byte`, `.half` и `.word` выдают по 1, 2 и 4 байта на значение, `.asciz` — байты строки и ноль, `.space n` резервирует `n` нулевых байтов, а `.align k` переходит к следующему адресу, кратному $2^k$ байт. RARS сам выравнивает данные `.half` и `.word`; явная директива `.align` делает промежуток видимым.

**Разобранный пример.**

| Строка | Адрес | Размер |
| --- | --- | --- |
| `a: .byte 1` | `0x10010000` | 1 |
| `.align 1`, затем `b: .half 2` | `0x10010002` (пропущен один байт) | 2 |
| `.align 2`, затем `c: .word 3` | `0x10010004` | 4 |
| `s: .asciz "hi"` | `0x10010008` | 3 |
| `.align 2`, затем `d: .word 4` | `0x1001000c` (пропущен один байт) | 4 |

`.eqv NAME, value` даёт константе имя, не выделяя памяти: каждое последующее использование `NAME` заменяется на `value`. Метка в `.word` сохраняет адрес метки, так что `.word a, b, c` строит таблицу адресов, которую печатает раздел «Код».

## Массивы и адресная арифметика \{#arrays-and-address-arithmetic\}

Массив слов — это ряд последовательных слов; элемент $i$ массива, начинающегося с адреса `base`, находится по адресу

$$
\text{адрес}(a[i]) = \text{base} + 4i ,
$$

а в общем случае $\text{base} + i \cdot \text{size}$ для элементов размером `size` байт. Умножение на 4 — это сдвиг влево на 2. Из этой формулы следуют два способа обойти массив.

**Индексная форма.** Хранить `i` и на каждой итерации заново вычислять адрес: `slli t3, t1, 2`, `add t3, t0, t3`, `lw t4, 0(t3)`. С проверкой вверху это прямой перевод `for (i = 0; i < n; i++) sum += a[i];`.

**Форма с указателем.** Хранить в регистре `p` сам адрес и прибавлять размер элемента после каждого элемента; остановиться, когда `p` дойдёт до `end` = base + 4n, адреса на один элемент дальше последнего:

```riscv
sum:    lw   t4, 0(t0)              # t4 = *p
        add  a0, a0, t4
        addi t0, t0, 4              # p++ сдвигается на 4 байта, одно слово
        bne  t0, t2, sum            # повторять, пока p != end
```

**Разобранный пример.** Для шести чисел из отправной точки, 12, −7, 30, 5, −2 и 19, обе формы печатают 57. Индексная форма с проверкой вверху выполняет 7 команд на элемент плюс заключительную проверку, 43 для шести элементов; форма с указателем и проверкой внизу выполняет 4 команды на элемент, 24. Форму с указателем компилятор C обычно и выдаёт, как бы ни был записан цикл.

**Строка** в C и в RARS — массив байтов, заканчивающийся нулевым байтом. Её длину находят, проходя байтовым указателем до нуля:

```riscv
strl:   lbu  t2, 0(t1)              # t2 = *p, один байт, расширенный нулями
        beqz t2, strend             # нулевой байт завершает строку
        addi t1, t1, 1              # p++ сдвигается на 1 байт
        j    strl
strend: sub  a0, t1, t0             # длина = p - start
```

Для `"RISC-V assembly"` получается 15. Здесь указатель сдвигается на 1, потому что элементы — байты; `lbu` вместо `lb` оставляет символы с кодами больше 127 положительными, хотя в этом цикле важно только сравнение с нулём.

<aside class="callout"><strong>Проверьте себя.</strong> (1) Массив полуслов начинается с адреса `0x10010010`. Где находится элемент 5? (2) Какой загрузкой его прочитать, чтобы значение 40 000 вернулось правильно? (3) Зачем сумме в форме с указателем нужна проверка перед циклом?<details><summary>Ответы</summary>(1) `0x10010010` + 2 · 5 = `0x1001001a`. (2) `lhu`: 40 000 больше 32 767, поэтому `lh` знаково расширила бы `0x9c40` до −25 536. (3) С проверкой внизу тело выполняется хотя бы один раз; для пустого массива `p` = `end` с самого начала, и без проверки цикл прочитал бы слово по адресу `end` и ушёл бы дальше, потому что `bne` больше никогда не увидел бы `p` = `end`.</details></aside>

## Псевдокоманды, макросы и включаемые файлы \{#pseudo-instructions-macros-and-includes\}

**Псевдокоманды** (pseudo-instructions) — имена, которые ассемблер принимает и раскрывает в настоящие команды. Те, что встречались до сих пор:

| Псевдокоманда | Раскрытие |
| --- | --- |
| `li rd, c` | `addi rd, zero, c`, если $-2048 \le c \le 2047$; иначе `lui` + `addi` |
| `la rd, label` | `auipc rd, hi` + `addi rd, rd, lo` |
| `lw rd, label` | `auipc rd, hi` + `lw rd, lo(rd)` |
| `mv rd, rs` | `addi rd, rs, 0` |
| `not rd, rs`, `neg rd, rs` | `xori rd, rs, -1`, `sub rd, zero, rs` |
| `j label` | `jal zero, label` |
| `beqz rs, label`, `bnez rs, label` | `beq rs, zero, label`, `bne rs, zero, label` |
| `bgt a, b, label`, `ble a, b, label` | `blt b, a, label`, `bge b, a, label` |
| `nop` | `addi zero, zero, 0` |

**Макрос** (macro) идёт на шаг дальше: это именованный фрагмент исходного текста с параметрами, который ассемблер вставляет везде, где встречается его имя. В RARS макрос определяется между `.macro` и `.end_macro`, а параметры записываются как `%name`; `.include "file"` вставляет другой файл, обычно библиотеку макросов ([RARS](#references), директивы ассемблера). Тогда печать целого числа и символа занимает по одной строке:

```riscv
# macros.s: здесь не запускается (в программе проверки примеров нет .macro и .include); работает в RARS
        .macro print_int (%reg)     # напечатать целое число из регистра %reg
        li   a7, 1
        mv   a0, %reg
        ecall
        .end_macro

        .macro print_char (%c)      # напечатать символьную константу %c
        li   a7, 11
        li   a0, %c
        ecall
        .end_macro
```

```riscv
# main.s: здесь не запускается; работает в RARS, если macros.s лежит в той же папке
        .include "macros.s"
        .text
        .globl main
main:
        li   t1, 57
        print_int (t1)              # превращается в: li a7, 1 / mv a0, t1 / ecall
        print_char ('\n')           # превращается в: li a7, 11 / li a0, 10 / ecall
        li   a7, 10
        ecall
# Output in RARS: 57
```

Макрос экономит набор текста, а не команды: каждое использование заново вставляет всё его тело, так что десять использований `print_int` добавляют в программу 30 команд. Кроме того, макрос не может вызвать сам себя, а регистры, которые он использует (здесь `a0` и `a7`), молча перезаписываются при каждом использовании. RARS при каждом раскрытии переименовывает метки, определённые внутри макроса, так что макрос может содержать цикл. Фрагмент кода, который существует в одном экземпляре и *в который переходят* из многих мест, — это процедура, тема следующей заметки.

## Что изменилось \{#what-changed\}

| | Отправная точка: линейный код | Ветвления, переходы, загрузки и сохранения |
| --- | --- | --- |
| Повторение | одна копия кода на каждое повторение | цикл: одна копия, обратное ребро |
| Решения | нет | `if`/`else` как ветвления по обратному условию |
| Объём данных | не больше 31 значения, все в регистрах | сколько угодно, в памяти, доступ по адресу |
| Число элементов | фиксируется при написании программы | известно во время выполнения |
| Стоимость на элемент (сумма массива) | 2 команды, но код растёт вместе с данными | 4 команды в цикле с указателем, размер кода фиксирован |

## Ограничения \{#limitations\}

- **Адреса никто не проверяет.** Загрузка из `end` или по устаревшему указателю читает то, что там лежит; программу останавливает только невыровненный или неотображённый адрес. Выход за границы массива — классическая ошибка ассемблера и C.
- **Со знаком или без знака — выбор программиста в каждой команде**: `blt` или `bltu`, `lb` или `lbu`. Неправильный вариант работает для небольших положительных значений и ломается на остальных.
- **Дальность ветвлений ограничена**: ±4 КиБ для условных ветвлений. Большой функции нужно ветвление через `j`, а ассемблер не всегда вставляет его сам.
- **Ветвления стоят времени.** На конвейерном процессоре выполненное ветвление нарушает поток команд, что разбирает [заметка о конвейере](/ru/notes/acos/pipelining); расположение циклов и код без ветвлений входят в настройку производительности.
- **Макросы дублируют код** и без предупреждения портят регистры; процедур они не заменяют.

## Что нужно запомнить \{#what-you-should-remember\}

- Шесть условных ветвлений, `beq`, `bne`, `blt`, `bge`, `bltu`, `bgeu`, со смещениями ±4 КиБ; `jal` (и `j`) для безусловных переходов на ±1 МиБ. Остальные сравнения — это они же с переставленными операндами.
- `if` перепрыгивает then-часть по обратному условию; `else` добавляет `j` через себя; циклы переходят назад к своей проверке. Если поставить проверку внизу, на итерацию остаётся одно ветвление.
- Загрузки и сохранения используют адреса вида `offset(base)`. `lb`/`lh` расширяют знаком, `lbu`/`lhu` — нулями; сохранения записывают младшие байты. Слова хранятся в порядке little-endian и должны быть выровнены на 4 байта.
- Элемент $i$ массива из элементов размером `size` байт находится по адресу base + $i \cdot$ size. Обход указателем до заранее вычисленного конца — дешёвый цикл: 4 команды на слово в сумме.
- Строка — массив байтов, заканчивающийся нулём; её длина — расстояние от её начала до этого нуля.
- Псевдокоманды раскрываются в одну или две настоящие команды; макросы вставляют текст при каждом использовании; `.include` вставляет файлы; `.eqv` даёт имена константам.

## Код \{#code\}

Цикл Коллатца с подготовкой и выводом:

```riscv
        .text
        .globl main
main:
        li   t0, 27                 # n
        li   t1, 0                  # steps
        mv   t2, t0                 # наибольшее значение, встреченное до сих пор
        li   t3, 1
loop:   beq  t0, t3, done           # while (n != 1): выйти, когда n == 1
        andi t4, t0, 1              # t4 = младший бит n
        bnez t4, odd                # if (n чётное) ... else goto odd
        srli t0, t0, 1              # then: n = n / 2
        j    next                   # пропустить else-часть
odd:    slli t4, t0, 1              # else: n = 3n + 1, вычисляется как 2n + n + 1
        add  t0, t0, t4
        addi t0, t0, 1
next:   addi t1, t1, 1              # steps++
        ble  t0, t2, loop           # if (n > max) max = n; затем назад к проверке
        mv   t2, t0
        j    loop
done:   mv   a0, t1
        li   a7, 1
        ecall                       # печатает 111
        li   a0, ' '
        li   a7, 11
        ecall
        mv   a0, t2
        li   a7, 1
        ecall                       # печатает 9232
        li   a7, 10
        ecall
# Output: 111 9232
# (выполнено 864 команды)
```

Одно слово, прочитанное пятью загрузками и затем изменённое сохранением байта. Как и в предыдущей заметке, значения печатает короткая подпрограмма `show`, в которую попадают через `jal ra, show` и из которой выходят через `ret`:

```riscv
        .data
w:      .byte 0xf6, 0x00, 0x80, 0xff    # слово 0xff8000f6, младший байт первым

        .text
        .globl main
main:
        la   t0, w
        lb   a0, 0(t0)              # байт 0xf6, знаковое расширение
        jal  ra, show               # -10 0xfffffff6
        lbu  a0, 0(t0)              # байт 0xf6, расширение нулями
        jal  ra, show               # 246 0x000000f6
        lh   a0, 2(t0)              # полуслово 0xff80 (байты 0x80, 0xff), знаковое расширение
        jal  ra, show               # -128 0xffffff80
        lhu  a0, 2(t0)              # то же полуслово, расширение нулями
        jal  ra, show               # 65408 0x0000ff80
        lw   a0, 0(t0)              # все четыре байта
        jal  ra, show               # -8388362 0xff8000f6
        li   t1, 0x7f
        sb   t1, 3(t0)              # перезаписать только старший байт
        lw   a0, 0(t0)
        jal  ra, show               # 2139095286 0x7f8000f6
        li   a7, 10
        ecall

show:                               # напечатать a0 в десятичном и шестнадцатеричном виде в одной строке
        mv   t6, a0
        li   a7, 1
        ecall
        li   a0, ' '
        li   a7, 11
        ecall
        mv   a0, t6
        li   a7, 34
        ecall
        li   a0, 10
        li   a7, 11
        ecall
        ret
# Output:
# -10 0xfffffff6
# 246 0x000000f6
# -128 0xffffff80
# 65408 0x0000ff80
# -8388362 0xff8000f6
# 2139095286 0x7f8000f6
```

Сумма массива в обеих формах и длина строки:

```riscv
        .data
arr:    .word 12, -7, 30, 5, -2, 19
n:      .word 6
str:    .asciz "RISC-V assembly"

        .text
        .globl main
main:
        # for (i = 0; i < n; i++) sum += arr[i];   индексная форма, проверка вверху
        la   t0, arr                # t0 = адрес arr[0]
        lw   t2, n                  # t2 = n
        li   t1, 0                  # t1 = i
        li   a0, 0                  # a0 = sum
for:    bge  t1, t2, endfor         # выйти, когда i >= n
        slli t3, t1, 2              # t3 = 4 * i, смещение arr[i] в байтах
        add  t3, t0, t3             # t3 = &arr[i]
        lw   t4, 0(t3)              # t4 = arr[i]
        add  a0, a0, t4
        addi t1, t1, 1              # i++
        j    for
endfor: li   a7, 1
        ecall                       # печатает 57
        li   a0, ' '
        li   a7, 11
        ecall

        # та же сумма с указателем, который идёт до конца; проверка внизу
        la   t0, arr                # t0 = p = &arr[0]
        lw   t2, n
        slli t2, t2, 2
        add  t2, t0, t2             # t2 = end = &arr[n], на один элемент дальше последнего
        li   a0, 0
        beq  t0, t2, endsum         # пустой массив пропускает цикл
sum:    lw   t4, 0(t0)              # t4 = *p
        add  a0, a0, t4
        addi t0, t0, 4              # p++ сдвигается на 4 байта, одно слово
        bne  t0, t2, sum            # повторять, пока p != end
endsum: li   a7, 1
        ecall                       # печатает 57
        li   a0, ' '
        li   a7, 11
        ecall

        # strlen: считать байты до завершающего нуля
        la   t0, str                # t0 = start
        mv   t1, t0                 # t1 = p
strl:   lbu  t2, 0(t1)              # t2 = *p, один байт, расширенный нулями
        beqz t2, strend             # нулевой байт завершает строку
        addi t1, t1, 1              # p++ сдвигается на 1 байт
        j    strl
strend: sub  a0, t1, t0             # длина = p - start
        li   a7, 1
        ecall                       # печатает 15
        li   a7, 10
        ecall
# Output: 57 57 15
```

Куда директивы данных помещают значения:

```riscv
        .data
a:      .byte 1                     # 1 байт
        .align 1
b:      .half 2                     # 2 байта, по чётному адресу
        .align 2
c:      .word 3                     # 4 байта, по адресу, кратному 4

        .align 2
d:      .word 4
        .eqv  NLABELS, 5            # именованная константа

        .text
        .globl main
main:
        la   t0, addrs              # напечатать пять адресов, хранящихся в таблице ниже
        li   t1, NLABELS
next:   lw   a0, 0(t0)
        li   a7, 34
        ecall
        li   a0, 10                 # перевод строки
        li   a7, 11
        ecall
        addi t0, t0, 4
        addi t1, t1, -1
        bnez t1, next
        li   a7, 10
        ecall

        .data
addrs:  .word a, b, c, s, d         # .word может хранить адрес метки
# Output:
# 0x10010000
# 0x10010002
# 0x10010004
# 0x10010008
# 0x1001000c
```

    n = n // 2 if n % 2 == 0 else 3 * n + 1
