[Предыдущая заметка](/ru/notes/acos/processor-and-isa) запустила первые программы и рассматривала каждую команду как мнемонику с операндами. Процессор ничего этого не видит: он видит 32-битные слова, такие как `0x006283b3` для `add t2, t0, t1` и пару `0x0fc10517`, `0xffc50513`, которую ассемблер сделал из `la a0, greeting`. Эта заметка разбирает обе стороны такого перевода. Она перечисляет команды, которые вычисляют (арифметику, логику, сдвиги, сравнения, умножение и деление), а затем открывает слова: шесть форматов, три команды, закодированные вручную, причину, по которой константы команд сохранения и ветвления разрезаны на части и перемешаны, и рецепт из двух команд для любой 32-битной константы.

**Обозначения.** `rd` — регистр-приёмник (destination register), `rs1` и `rs2` — регистры-источники (source registers), `imm` — константа, хранящаяся внутри команды (**непосредственное значение**, immediate). $x[r]$ — значение в регистре $r$. Для слова $w$ запись $w[a{:}b]$ обозначает поле из битов с $a$ по $b$ (по убыванию), где бит 0 — младший. $\operatorname{sext}(v)$ расширяет узкое число в дополнительном коде до 32 бит, копируя его знаковый бит. Арифметика ведётся над 32-битными словами, то есть по модулю $2^{32}$. $\ll$ — сдвиг влево; $\gg_u$ и $\gg_s$ — логический (вдвигаются нули) и арифметический (вдвигаются копии знакового бита) сдвиги вправо.

## Отправная точка: поля команды в порядке записи \{#baseline-lay-out-each-instruction-as-it-is-written\}

Самое прямое кодирование записывает операнды после кода операции в том порядке, в каком их перечисляет строка ассемблера: `addi rd, rs1, imm` — как код операции, `rd`, `rs1`, `imm`; `sw rs2, imm(rs1)` — как код операции, `rs2`, `imm`, `rs1`; `add rd, rs1, rs2` — как код операции, `rd`, `rs1`, `rs2`. Каждая команда получает подходящую ей раскладку полей. Это работает, но ломается в двух местах.

- **Не всё помещается.** При 128 кодах операций (7 бит) и 32 регистрах (5 бит на регистр) у команды с двумя регистрами на константу остаётся $32 - 7 - 10 = 15$ бит. 32-битная константа или адрес никогда не поместится в 32-битную команду рядом с кодом операции.
- **Декодер должен декодировать, прежде чем читать.** Если `rs1` в одной команде стоит в битах 11–7, а в другой — в битах 19–15, процессор не может начать чтение регистрового файла, пока не выяснит, какая перед ним команда. Чтение регистров лежит на критическом пути каждой команды, поэтому эта задержка замедляет все команды, а не только необычные.

RISC-V решает обе проблемы: небольшое число форматов с полями регистров на фиксированных местах, константы из 12 или 20 бит с отдельным способом строить более широкие и константа, уложенная вокруг полей регистров везде, где осталось место.

## Арифметика, логика и сдвиги \{#arithmetic-logic-and-shifts\}

Вычислительные команды RV32I бывают двух видов. Команды **регистр–регистр** берут два регистра-источника: `add rd, rs1, rs2` вычисляет $x[rd] = x[rs1] + x[rs2]$. Команды **регистр–константа** берут один регистр и 12-битную константу, которая перед использованием знаково расширяется до 32 бит: `addi rd, rs1, imm` вычисляет $x[rd] = x[rs1] + \operatorname{sext}(imm)$, так что константа лежит в диапазоне от −2048 до 2047.

| Операция | Регистр–регистр | Регистр–константа | Результат |
| --- | --- | --- | --- |
| сложение, вычитание | `add`, `sub` | `addi` | сумма или разность по модулю $2^{32}$ |
| побитовая логика | `and`, `or`, `xor` | `andi`, `ori`, `xori` | бит за битом |
| сдвиг влево | `sll` | `slli` | $x[rs1] \ll s$ |
| сдвиг вправо, логический | `srl` | `srli` | $x[rs1] \gg_u s$ |
| сдвиг вправо, арифметический | `sra` | `srai` | $x[rs1] \gg_s s$ |
| установить, если меньше, со знаком | `slt` | `slti` | 1, если $x[rs1] < $ второго операнда при сравнении чисел со знаком, иначе 0 |
| установить, если меньше, без знака | `sltu` | `sltiu` | то же сравнение для чисел без знака |
| старшая часть константы | | `lui`, `auipc` | $imm \ll 12$ или $pc + (imm \ll 12)$ |

Величина сдвига $s$ — это младшие 5 бит `rs2` или константы: сдвигать 32-битное слово на 32 позиции и более бессмысленно, и `sll t0, t0, t1` при `t1` = 33 сдвигает на 1. Команды `subi` нет, потому что `addi` с отрицательной константой делает то же самое.

**Расширение M** добавляет умножение и деление:

| Команда | Результат |
| --- | --- |
| `mul rd, rs1, rs2` | младшие 32 бита 64-битного произведения |
| `mulh`, `mulhu`, `mulhsu` | старшие 32 бита произведения для случаев «со знаком × со знаком», «без знака × без знака» и «со знаком × без знака» |
| `div`, `divu` | частное, округлённое к нулю |
| `rem`, `remu` | остаток со знаком делимого |

Трёх вещей, которые есть у других процессоров, здесь нет. **Нет флагов условий** (condition flags): ни одна команда не записывает попутно перенос, переполнение или признак нулевого результата, так что любой результат попадает в регистр. **Переполнение проходит молча**: `add` возвращает сумму по модулю $2^{32}$. И **арифметика не вызывает ловушек** (traps): [предыдущая заметка](/ru/notes/acos/processor-and-isa#the-instruction-set-as-a-contract) показала, что возвращает деление на ноль. Когда программе нужно знать о переносе или переполнении, она вычисляет его сравнением. Сумма без знака дала перенос ровно тогда, когда она меньше одного из слагаемых, поэтому после `add t3, t1, t2` команда `sltu t4, t3, t1` записывает в `t4` перенос ([RISC-V Unprivileged ISA](#references), целочисленные вычислительные команды; там же приведена проверка переполнения со знаком из трёх команд).

Несколько частых операций — частные случаи, и ассемблер предлагает их как псевдокоманды: `not rd, rs` — это `xori rd, rs, -1`; `neg rd, rs` — это `sub rd, zero, rs`; `seqz rd, rs` (set if zero, установить, если ноль) — это `sltiu rd, rs, 1`, потому что как число без знака меньше 1 только 0; `snez rd, rs` — это `sltu rd, zero, rs`.

**Разобранный пример.** Пусть `t0` = −20, то есть слово `0xffffffec`.

| Команда | Результат в шестнадцатеричном виде | Как число со знаком | Почему |
| --- | --- | --- | --- |
| `srai a0, t0, 2` | `0xfffffffb` | −5 | слева вдвигаются копии знакового бита 1: деление на 4 |
| `srli a0, t0, 2` | `0x3ffffffb` | 1 073 741 819 | вдвигаются нули: те же биты, прочитанные как число без знака 4 294 967 276, делятся на 4 |
| `slli a0, t0, 2` | `0xffffffb0` | −80 | умножение на 4 |
| `slti a0, t0, 1` | `0x00000001` | 1 | $-20 < 1$ как числа со знаком |
| `sltiu a0, t0, 1` | `0x00000000` | 0 | 4 294 967 276 как число без знака не меньше 1 |

Ещё два случая с более широкими числами: `0xfffffff0` + `0x20` даёт `0x10`, что меньше `0xfffffff0`, так что `sltu` сообщает перенос 1; а $2^{16} \cdot 2^{16} = 2^{32}$ не помещается, поэтому `mul` возвращает 0, а `mulhu` — 1, старшую половину 64-битного произведения. Раздел «Код» выполняет все эти примеры.

## Шесть форматов \{#six-formats\}

<aside class="callout"><strong>Ключевая идея.</strong> Каждая команда RV32I — одно 32-битное слово в одном из шести форматов. Код операции, `rd`, `rs1`, `rs2`, funct3 и funct7 стоят в одних и тех же битах во всех форматах, где они есть, поэтому процессор может начать читать регистры, ещё не зная, что это за команда. Константа занимает оставшиеся биты, при необходимости разрезанная на части, и её знак всегда находится в бите 31.</aside>

<InstructionFormats />

У полей фиксированный смысл:

- **opcode** (код операции), биты 6–0, называет класс команды: `0110011` для арифметики регистр–регистр (OP), `0010011` для арифметики регистр–константа (OP-IMM), `0000011` для загрузок, `0100011` для сохранений, `1100011` для ветвлений, `0110111` для `lui`, `0010111` для `auipc`, `1101111` для `jal`, `1100111` для `jalr`, `1110011` для `ecall` и других системных команд. Два младших бита у каждой 32-битной команды равны `11`; сжатые 16-битные команды расширения C используют три других значения, так что процессор узнаёт длину команды по её первым двум битам.
- **funct3**, биты 14–12, и **funct7**, биты 31–25, выбирают операцию внутри класса. У `add` и `sub` общие код операции и funct3 `000`, а различаются они funct7: `0000000` для `add`, `0100000` для `sub`. Расширение M использует funct7 `0000001`.
- **rd**, биты 11–7; **rs1**, биты 19–15; **rs2**, биты 24–20: номера регистров от 0 до 31.

Шесть форматов и команды, которые их используют:

| Формат | Поля | Используется |
| --- | --- | --- |
| R | funct7, rs2, rs1, funct3, rd, opcode | арифметикой регистр–регистр, `mul`, `div` |
| I | imm[11:0], rs1, funct3, rd, opcode | арифметикой регистр–константа, загрузками, `jalr`, `ecall` |
| S | imm[11:5], rs2, rs1, funct3, imm[4:0], opcode | сохранениями |
| B | imm[12], imm[10:5], rs2, rs1, funct3, imm[4:1], imm[11], opcode | условными ветвлениями |
| U | imm[31:12], rd, opcode | `lui`, `auipc` |
| J | imm[20], imm[10:1], imm[11], imm[19:12], rd, opcode | `jal` |

Сдвиги на константу используют формат I с одной особенностью: величиной сдвига служат только младшие 5 бит константы, а бит 30 отличает `srai` (1) от `srli` (0) — тот же бит, что отличает `sub` от `add`.

## Кодирование вручную \{#encoding-by-hand\}

**Разобранный пример 1: `sub a0, a1, a2`**, команда типа R. `a0`, `a1` и `a2` — это `x10`, `x11` и `x12`.

| Поле | funct7 | rs2 = a2 | rs1 = a1 | funct3 | rd = a0 | opcode |
| --- | --- | --- | --- | --- | --- | --- |
| Биты | 31–25 | 24–20 | 19–15 | 14–12 | 11–7 | 6–0 |
| Значение | `0100000` | 12 = `01100` | 11 = `01011` | `000` | 10 = `01010` | `0110011` |

Целиком слово записывается как `0100000 01100 01011 000 01010 0110011`. Если перегруппировать его по четыре бита слева, `0100 0000 1100 0101 1000 0101 0011 0011`, получится `0x40c58533`.

**Разобранный пример 2: `addi sp, sp, -16`**, команда типа I с отрицательной константой. −16 в 12-битном дополнительном коде — это $2^{12} - 16 = 4080$ = `1111 1111 0000`; `sp` — это `x2`.

| Поле | imm[11:0] | rs1 = sp | funct3 | rd = sp | opcode |
| --- | --- | --- | --- | --- | --- |
| Значение | `111111110000` | `00010` | `000` | `00010` | `0010011` |

Слово равно `1111 1111 0000 0001 0000 0001 0001 0011` = `0xff010113`. Выполняя его, процессор знаково расширяет 12 бит: бит 11 равен 1, поэтому слева дописываются 20 единиц, и константа становится `0xfffffff0`, снова −16.

**Разобранный пример 3: `bne t0, t1, -12`**, ветвление типа B. Стоя в конце цикла из четырёх команд, оно переходит на 12 байт назад, к первой команде цикла, когда `t0` ≠ `t1`. Смещение отсчитывается от адреса самой команды ветвления.

<BranchEncoding />

1. Смещение −12 как 13-битное число в дополнительном коде — это `1 1111 1111 0100` (биты с 12 по 0). Цели ветвлений всегда находятся по чётным адресам, поэтому бит 0 равен 0 и не хранится. Это удваивает дальность: 12 хранимых бит достают на ±4 КиБ.
2. Остальные биты расходятся по четырём местам: бит 12 (знак) в бит 31, биты 10–5 (`111111`) в биты 30–25, биты 4–1 (`1010`) в биты 11–8, а бит 11 (`1`) в бит 7.
3. Прочие поля такие же, как в любом формате: `rs2` = `t1` = `x6` = `00110`, `rs1` = `t0` = `x5` = `00101`, funct3 = `001` для `bne`, код операции `1100011`.
4. Слово `1111111 00110 00101 001 1010 1 1100011`, перегруппированное по четыре бита, равно `1111 1110 0110 0010 1001 1010 1110 0011` = `0xfe629ae3`.
5. Память с порядком байтов little-endian хранит его как байты `e3 9a 62 fe` — в этом порядке их показывает дизассемблер, печатающий байты.

Декодирование проходит те же шаги в обратном порядке: прочитать код операции, который определяет формат, затем выбрать поля. Раздел «Код» кодирует эти три команды и ещё три несколькими строками на Python; результаты совпадают со словами, которые для тех же строк выдаёт ассемблер LLVM (`llvm-mc -triple=riscv32 -show-encoding`).

## Почему константы S и B разрезаны и перемешаны \{#why-the-s-and-b-immediates-are-split-and-scrambled\}

**S: разрезана.** У команды сохранения два регистра-источника — базовый адрес в `rs1` и значение в `rs2` — и нет приёмника. Её 12-битная константа не может стоять в битах 31–20, как в формате I, потому что `rs2` должен остаться в битах 24–20. Поэтому константа обходит его: биты 11–5 константы стоят в битах 31–25, а биты 4–0 — в битах 11–7, на месте, которое в других форматах занимает `rd` и которое команде сохранения не нужно. Поля регистров остаются там, где их ждёт регистровый файл.

**B: перемешана.** У ветвления тоже два регистра-источника, поэтому его константа должна использовать те же биты, что и у сохранения. Но смещение ветвления чётно, его бит 0 можно не хранить, и 12 доступных бит вмещают биты 12–1. Привычное решение поставило бы биты 12–1 туда, где в S стоят биты 11–0, сдвинув всю константу на одну позицию. RISC-V вместо этого оставляет биты 10–5 и 4–1 точно там, где они стоят в S, ставит знак (бит 12) в бит 31, как и любой другой знак, а оставшийся бит 11 переносит в позицию, где в S стоит бит 0, — в бит 7 команды. Формат J так же обходится с U: биты 19–12 остаются там, где они стоят в U, биты 10–1 стоят там, где они в I, бит 11 занимает бит 20, а знак находится в бите 31 ([RISC-V Unprivileged ISA](#references), варианты кодирования констант).

**Чем это помогает.** Прежде чем команда сможет выполниться, аппаратура должна собрать её 32-битную константу, и перед каждым битом константы стоит мультиплексор, который в зависимости от формата выбирает, какой бит команды на него подать. При раскладке RISC-V биты 10–5 константы во всех форматах, где они есть, берутся из битов 30–25 команды, биты 4–1 — из одного из двух мест, а знак — всегда из бита 31, так что знаковое расширение может начаться до того, как формат известен. Если для каждого бита константы посчитать, сколько разных битов команды могут питать его в форматах I, S, B, U и J, получится 58 входов мультиплексоров, не больше 3 на бит; если бы B и J были просто сдвинутыми копиями S и U, их было бы 86, до 4 на бит (раздел «Код» их подсчитывает). По оценке спецификации, такая раскладка примерно вдвое уменьшает стоимость мультиплексоров и коэффициент разветвления (fanout) сигналов команды. Платят за это люди и программы, которые кодируют команды: ассемблер, JIT-компилятор и эта заметка.

## Загрузка 32-битной константы: lui и addi \{#loading-a-32-bit-constant-lui-and-addi\}

Ни одна команда не может вместить 32-битную константу, поэтому константы вне диапазона −2048..2047 требуют двух команд. `lui rd, hi` (load upper immediate, загрузить старшую часть константы, формат U) записывает в `rd` значение $hi \ll 12$: 20-битную константу в старших битах и нули в младших 12. Затем `addi rd, rd, lo` прибавляет 12-битную константу. Вопрос в том, как разбить константу $c$ на $hi$ и $lo$.

Очевидное разбиение берёт старшие 20 бит в $hi$, а младшие 12 бит — в $lo$. Оно не работает, когда бит 11 числа $c$ равен 1, потому что `addi` знаково расширяет свою константу: младшие 12 бит `0xeef` читаются как $3823 - 4096 = -273$, и сумма получается на 4096 меньше нужной. Исправление — принять знаковое прочтение младших битов как есть и дать $hi$ поглотить разницу:

$$
\boxed{
\begin{aligned}
lo &= \operatorname{sext}(c[11{:}0]) \in [-2048,\, 2047], \\
hi &= \frac{c - lo}{2^{12}} \bmod 2^{20}
\end{aligned}
}
$$

$$
\begin{aligned}
c[11{:}0] < 2048 &\;\Rightarrow\; lo = c[11{:}0],\; c - lo = c[31{:}12] \cdot 2^{12} &&\Rightarrow\; hi = c[31{:}12] \\
c[11{:}0] \ge 2048 &\;\Rightarrow\; lo = c[11{:}0] - 2^{12},\; c - lo = (c[31{:}12] + 1) \cdot 2^{12} &&\Rightarrow\; hi = c[31{:}12] + 1 \\
\text{в обоих случаях} &\;\Rightarrow\; hi = \left\lfloor (c + 2^{11}) / 2^{12} \right\rfloor \bmod 2^{20} . &&
\end{aligned}
$$

Последняя строка верна, потому что прибавление $2^{11}$ = `0x800` даёт перенос в бит 12 ровно тогда, когда бит 11 числа $c$ равен 1. В обоих случаях `lui`, за которой следует `addi`, даёт $hi \cdot 2^{12} + lo = c$ по модулю $2^{32}$.

**Разобранный пример.** Для $c$ = `0x12345678` младшие 12 бит равны `0x678` = 1656, это меньше 2048: `lui a0, 0x12345`, затем `addi a0, a0, 1656` — наивное разбиение. Для $c$ = `0xdeadbeef` младшие 12 бит равны `0xeef` = 3823, поэтому $lo = 3823 - 4096 = -273$, а $hi$ = `0xdeadb` + 1 = `0xdeadc`:

| Команда | `a0` после неё |
| --- | --- |
| `lui a0, 0xdeadc` | `0xdeadc000` |
| `addi a0, a0, -273` | `0xdeadc000` − `0x111` = `0xdeadbeef` |

С наивной `lui a0, 0xdeadb` та же `addi` дала бы `0xdeadaeef`. Команду `addi a0, a0, 0xeef` ассемблер сразу отвергает, потому что 3823 не помещается в 12 бит со знаком.

Псевдокоманда `li rd, c` делает это разбиение за нас: одна `addi`, когда $c$ помещается в 12 бит, иначе `lui` и `addi`. `la rd, label` делает то же с `auipc`, которая прибавляет $hi \ll 12$ к адресу самой `auipc`, так что разбивается расстояние от команды до метки. Это и есть `la` из программы hello world предыдущей заметки: у расстояния `0x0fc0fffc` младшие 12 бит равны `0xffc`, то есть −4 как число со знаком, поэтому старшая часть становится `0x0fc0f` + 1 = `0x0fc10`.

## Что изменилось \{#what-changed\}

| | Отправная точка: своя раскладка для каждой команды | Форматы RISC-V |
| --- | --- | --- |
| Поля регистров | там, куда их ставит порядок операндов | фиксированы: rd 11–7, rs1 19–15, rs2 24–20 |
| Чтение регистров | ждёт декодера | начинается параллельно с декодированием |
| Знак константы | там, где кончается константа | всегда бит 31 |
| Константы | сколько осталось бит, у каждой команды по-своему | 12 бит (I, S, B) или 20 бит (U, J); более широкие — через `lui` + `addi` |
| Цена | просто кодировать, медленно декодировать | быстро декодировать, кропотливо кодировать вручную |

## Ограничения \{#limitations\}

- **Константы стоят команд.** Любая константа вне −2048..2047 и любой адрес требуют двух команд, а 64-битная константа в RV64 — ещё больше.
- **Короткая дальность.** Условное ветвление достаёт на ±4 КиБ, а `jal` — на ±1 МиБ. Для более далёких целей нужны `auipc` и `jalr`; это устраивают ассемблер и компоновщик ценой лишней команды.
- **Нет флагов.** Арифметика над многословными числами и проверки переполнения требуют явных сравнений и ветвлений, которые наборы команд с флагами получают даром.
- **Фиксированные 32-битные слова тратят место** на частые короткие команды; расширение C добавляет 16-битные формы ценой того, что команды уже не все выровнены на 4 байта.
- **Перемешанные константы трудно читать.** Декодирование слова типа B или J на глаз или генерация кода во время выполнения требуют перестановки битов.

## Что нужно запомнить \{#what-you-should-remember\}

- RV32I вычисляет с помощью `add`, `sub`, `and`, `or`, `xor`, сдвигов (`sll`, `srl`, `sra`) и сравнений (`slt`, `sltu`); у каждой есть форма с константой, которая принимает знаково расширяемую 12-битную константу; M добавляет `mul`, `mulh*`, `div*`, `rem*`. Нет флагов, нет ловушек при переполнении.
- Шесть форматов, R, I, S, B, U, J, все по 32 бита. Код операции в битах 6–0, rd в 11–7, funct3 в 14–12, rs1 в 19–15, rs2 в 24–20, funct7 в 31–25; знак любой константы в бите 31.
- Чтобы закодировать команду, нужно выбрать формат, записать каждое поле в двоичном виде, соединить поля и перегруппировать по четыре бита. `sub a0, a1, a2` = `0x40c58533`, `addi sp, sp, -16` = `0xff010113`, `bne t0, t1, -12` = `0xfe629ae3`.
- S разрезает свою константу вокруг rs2; B отбрасывает бит 0 (чётного) смещения и переносит бит 11 в бит 7 команды, так что у каждого бита константы мало возможных источников.
- 32-битная константа — это `lui hi` + `addi lo` с $lo = \operatorname{sext}(c[11{:}0])$ и $hi = (c + \texttt{0x800}) \gg 12$; `0xdeadbeef` — это `lui 0xdeadc`, `addi -273`.

## Код \{#code\}

Разобранные примеры из раздела об арифметике. Каждое значение печатает короткая подпрограмма `show`; `jal ra, show` переходит в неё, а её `ret` возвращает обратно — это механизм из [заметки о процедурах](/ru/notes/acos/procedures-and-the-stack).

```riscv
        .text
        .globl main
main:
        li   t0, -20
        srai a0, t0, 2              # арифметический сдвиг: слева вдвигаются копии знакового бита
        jal  ra, show               # -5 0xfffffffb
        srli a0, t0, 2              # логический сдвиг: слева вдвигаются нули
        jal  ra, show               # 1073741819 0x3ffffffb
        slli a0, t0, 2              # сдвиг влево на 2 умножает на 4
        jal  ra, show               # -80 0xffffffb0
        slti a0, t0, 1              # со знаком: -20 < 1
        jal  ra, show               # 1 0x00000001
        sltiu a0, t0, 1             # без знака: 4294967276 < 1 ложно
        jal  ra, show               # 0 0x00000000
        li   t1, 0xfffffff0         # без знака 4294967280
        li   t2, 0x20               # 32
        add  t3, t1, t2             # сумма переходит через ноль и равна 0x10
        sltu a0, t3, t1             # перенос = 1 ровно тогда, когда сумма меньше слагаемого
        jal  ra, show               # 1 0x00000001
        li   t1, 0x10000            # 2^16
        mul  a0, t1, t1             # 2^32 не помещается: младшие 32 бита равны 0
        jal  ra, show               # 0 0x00000000
        mulhu a0, t1, t1            # старшие 32 бита 64-битного произведения равны 1
        jal  ra, show               # 1 0x00000001
        li   a7, 10
        ecall

show:                               # напечатать a0 в десятичном и шестнадцатеричном виде в одной строке
        mv   t6, a0
        li   a7, 1
        ecall
        li   a0, ' '
        li   a7, 11
        ecall
        mv   a0, t6
        li   a7, 34
        ecall
        li   a0, 10
        li   a7, 11
        ecall
        ret
# Output:
# -5 0xfffffffb
# 1073741819 0x3ffffffb
# -80 0xffffffb0
# 1 0x00000001
# 0 0x00000000
# 1 0x00000001
# 0 0x00000000
# 1 0x00000001
```

Построение `0xdeadbeef` с поправкой и без неё:

```riscv
        .text
        .globl main
main:
        lui  a0, 0xdeadc            # a0 = 0xdeadc000
        addi a0, a0, -273           # a0 = 0xdeadc000 - 273
        li   a7, 34                 # PrintIntHex
        ecall                       # печатает 0xdeadbeef
        li   a0, ' '
        li   a7, 11                 # PrintChar
        ecall
        lui  a0, 0xdeadb            # наивная старшая часть, без поправки
        addi a0, a0, -273           # 0xeef, прочитанное как 12-битное число со знаком, равно -273
        li   a7, 34
        ecall                       # печатает 0xdeadaeef: на 4096 меньше
        li   a0, ' '
        li   a7, 11
        ecall
        li   a0, 0xdeadbeef         # псевдокоманда сама делает разбиение
        li   a7, 34
        ecall                       # печатает 0xdeadbeef
        li   a7, 10
        ecall
# Output: 0xdeadbeef 0xdeadaeef 0xdeadbeef
```

Кодировщик для шести форматов, декодирование фиксированных полей, разбиение константы и подсчёт источников битов константы:

```python
ABI = ['zero', 'ra', 'sp', 'gp', 'tp', 't0', 't1', 't2', 's0', 's1', 'a0', 'a1', 'a2', 'a3', 'a4', 'a5', 'a6', 'a7',
       's2', 's3', 's4', 's5', 's6', 's7', 's8', 's9', 's10', 's11', 't3', 't4', 't5', 't6']
x = {name: i for i, name in enumerate(ABI)}             # имя в ABI -> номер регистра

def bits(v, hi, lo):                                     # биты hi..lo числа v (для отрицательного v — в дополнительном коде)
    return (v >> lo) & ((1 << (hi - lo + 1)) - 1)

def r_type(f7, rs2, rs1, f3, rd, op):
    return f7 << 25 | x[rs2] << 20 | x[rs1] << 15 | f3 << 12 | x[rd] << 7 | op

def i_type(imm, rs1, f3, rd, op):
    assert -2048 <= imm <= 2047
    return bits(imm, 11, 0) << 20 | x[rs1] << 15 | f3 << 12 | x[rd] << 7 | op

def s_type(imm, rs2, rs1, f3, op):
    assert -2048 <= imm <= 2047
    return bits(imm, 11, 5) << 25 | x[rs2] << 20 | x[rs1] << 15 | f3 << 12 | bits(imm, 4, 0) << 7 | op

def b_type(off, rs2, rs1, f3, op=0b1100011):
    assert -4096 <= off <= 4094 and off % 2 == 0
    return (bits(off, 12, 12) << 31 | bits(off, 10, 5) << 25 | x[rs2] << 20 | x[rs1] << 15
            | f3 << 12 | bits(off, 4, 1) << 8 | bits(off, 11, 11) << 7 | op)

def u_type(imm20, rd, op):
    return bits(imm20, 19, 0) << 12 | x[rd] << 7 | op

def j_type(off, rd, op=0b1101111):
    assert -(1 << 20) <= off < (1 << 20) and off % 2 == 0
    return (bits(off, 20, 20) << 31 | bits(off, 10, 1) << 21 | bits(off, 11, 11) << 20
            | bits(off, 19, 12) << 12 | x[rd] << 7 | op)

for text, word in [
        ('sub  a0, a1, a2',  r_type(0b0100000, 'a2', 'a1', 0b000, 'a0', 0b0110011)),
        ('addi sp, sp, -16', i_type(-16, 'sp', 0b000, 'sp', 0b0010011)),
        ('sw   ra, 12(sp)',  s_type(12, 'ra', 'sp', 0b010, 0b0100011)),
        ('bne  t0, t1, -12', b_type(-12, 't1', 't0', 0b001)),
        ('lui  t0, 0x12345', u_type(0x12345, 't0', 0b0110111)),
        ('jal  ra, 2048',    j_type(2048, 'ra'))]:
    print(f'{text:<17} 0x{word:08x}')
# sub  a0, a1, a2   0x40c58533
# addi sp, sp, -16  0xff010113
# sw   ra, 12(sp)   0x00112623
# bne  t0, t1, -12  0xfe629ae3
# lui  t0, 0x12345  0x123452b7
# jal  ra, 2048     0x001000ef

def decode_fields(w):                                    # поля, которые стоят на одном месте во всех форматах
    return dict(opcode=bits(w, 6, 0), rd=ABI[bits(w, 11, 7)], funct3=bits(w, 14, 12),
                rs1=ABI[bits(w, 19, 15)], rs2=ABI[bits(w, 24, 20)], funct7=bits(w, 31, 25))
print(decode_fields(0x00a00893))   # opcode 0x13 (OP-IMM), rd a7, rs1 zero; imm = биты 31..20 = 10: li a7, 10
# {'opcode': 19, 'rd': 'a7', 'funct3': 0, 'rs1': 'zero', 'rs2': 'a0', 'funct7': 0}

def split(c):
    """lui/addi immediates for a 32-bit constant c: c = hi * 4096 + lo with lo in -2048..2047."""
    lo = ((c & 0xfff) ^ 0x800) - 0x800                   # младшие 12 бит, прочитанные как число со знаком
    hi = ((c - lo) >> 12) & 0xfffff                      # то же, что (c + 0x800) >> 12, по модулю 2^20
    return hi, lo

for c in (0x12345678, 0xdeadbeef, 0x00000800, 0x7ffff800):
    hi, lo = split(c)
    naive = ((c >> 12 << 12) + lo) % 2**32               # lui с неизменёнными старшими 20 битами
    print(f'0x{c:08x}: lui 0x{hi:05x}, addi {lo:5}  -> 0x{((hi << 12) + lo) % 2**32:08x}   naive 0x{naive:08x}')
# 0x12345678: lui 0x12345, addi  1656  -> 0x12345678   naive 0x12345678
# 0xdeadbeef: lui 0xdeadc, addi  -273  -> 0xdeadbeef   naive 0xdeadaeef
# 0x00000800: lui 0x00001, addi -2048  -> 0x00000800   naive 0xfffff800
# 0x7ffff800: lui 0x80000, addi -2048  -> 0x7ffff800   naive 0x7fffe800

# Какой бит команды питает бит k константы в каждом формате (None: константа 0). Число разных
# источников для каждого бита константы измеряет мультиплексоры перед константой.
def source(fmt, k):
    table = {
        'I': k + 20 if k <= 10 else 31,
        'S': (k + 7 if k <= 4 else k + 20) if k <= 10 else 31,
        'B': None if k == 0 else k + 7 if k <= 4 else k + 20 if k <= 10 else 7 if k == 11 else 31,
        'U': None if k < 12 else k,
        'J': None if k == 0 else k + 20 if k <= 10 else 20 if k == 11 else k if k <= 19 else 31,
        'B as S shifted': None if k == 0 else k + 6 if k <= 5 else k + 19 if k <= 11 else 31,
        'J as U shifted': None if k == 0 else min(k + 11, 31),
    }
    return table[fmt]
for formats in (['I', 'S', 'B', 'U', 'J'], ['I', 'S', 'B as S shifted', 'U', 'J as U shifted']):
    per_bit = [len({source(f, k) for f in formats} - {None}) for k in range(32)]
    print(sum(per_bit), max(per_bit))
# 58 3    раскладка RISC-V
# 86 4    если бы B и J были S и U, сдвинутыми на один бит
```
