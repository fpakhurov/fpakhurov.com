[Предыдущая заметка](/ru/notes/agents/chain-of-thought) дала модели место для вычислений до ответа, но не дала ни новой информации, ни способа что-либо изменить. Её стратегия умеет только писать текст. Действиями в [заметке о стратегии](/ru/notes/agents/language-model-as-a-policy) были строки, которые должен был распознать написанный вручную парсер, и всё, чего парсер не распознавал, терялось. Использование инструментов заменяет такой парсер контрактом. Каждый инструмент объявляется как типизированная функция, модель выдаёт вызов в фиксированной структуре, а среда выполнения (runtime) проверяет вызов, исполняет его и возвращает результат. [Заметка об инструментах и агентах](/ru/notes/nlp/tools-and-agents#the-protocol) курса NLP описывает этот протокол в четыре шага. Эта заметка подробно разбирает каждый шаг: что содержит определение функции, точные сообщения пути вызова туда и обратно, вызовы, сделанные параллельно, как можно ограничить декодирование, чтобы каждый вызов был допустим по построению, как модели вообще научились вызывать инструменты, код как действие и что делает среда выполнения, когда вызов не удаётся.

**Обозначения.** Инструменты $f_1, \dots, f_m$, у каждого есть имя, описание и схема $S_i$ его аргументов. Вызов — тройка (идентификатор, имя, аргументы), где аргументы — объект JSON. $V$ — словарь, $z \in \mathbb R^{|V|}$ — логиты на одном шаге декодирования и $p = \operatorname{softmax}(z)$; $\mathcal L$ — множество допустимых выходов, а префикс $u$ **живой** (live), если некоторая последовательность токенов продолжает его до элемента $\mathcal L$. $M(u) \subseteq V$ — множество токенов, разрешённых после $u$.

## Отправная точка: действия, разобранные из свободного текста \{#baseline-actions-parsed-from-free-text\}

Первые агенты на языковых моделях писали свои действия в специально придуманном формате, таком как `search[Dunmore]` в ReAct, и их читало регулярное выражение. Формат — соглашение, которому модель следует лишь с некоторой вероятностью. Она может написать `Search: Dunmore`, обернуть действие в предложение, поставить кавычку внутри аргумента без экранирования или назвать несуществующий инструмент. Каждая такая ошибка стоит шага, и на длинной задаче эти потери накапливаются. **Разобранный пример.** Если одно действие из 50 испорчено, $\varepsilon = 0.02$, агент, который делает 20 действий, выдаёт хотя бы одно испорченное действие с вероятностью

$$
1 - (1 - \varepsilon)^{20} = 1 - 0.98^{20} = 0.33 .
$$

Каждый третий запуск натыкается на ошибку разбора, хотя каждое отдельное действие правильно оформлено в 98% случаев. Аргументы добавляют вторую проблему: правильно оформленный вызов всё ещё может передать строку там, где ожидается число, или товар, которого в магазине нет.

<aside class="callout"><strong>Ключевая идея.</strong> Каждый инструмент объявляется как типизированная функция: имя, описание, написанное для модели, и JSON Schema его аргументов. Модель выдаёт вызовы как структурированные данные в отдельном канале, среда выполнения проверяет каждый вызов по его схеме, прежде чем исполнить, и возвращает каждый результат, включая ошибки, сообщением, привязанным к вызову. Там, где допустимость нужно гарантировать, декодирование ограничивается: на каждом шаге логит каждого токена, после которого выход невозможно завершить, приравнивается к $-\infty$.</aside>

## Определение функции \{#a-function-definition\}

Определение инструмента состоит из трёх частей. В формате, которым пользуется большинство поставщиков моделей, инструмент игрушечного магазина из раздела «Код» выглядит так:

```json
{
  "name": "get_price",
  "description": "Price of one item in the shop, in euros.",
  "parameters": {
    "type": "object",
    "properties": {
      "item": { "type": "string", "enum": ["lamp", "chair", "desk"] }
    },
    "required": ["item"],
    "additionalProperties": false
  }
}
```

- **Имя** — то, что пишет модель, чтобы вызвать инструмент. Оно должно говорить, что инструмент делает, потому что модель выбирает инструменты, читая.
- **Описание** — это промпт. Это единственная документация, которую видит модель, поэтому оно сообщает, что возвращает инструмент, в каких единицах, когда его использовать и когда нет.
- **Параметры** — это JSON Schema ([JSON Schema, 2020](#references)): тип каждого аргумента, какие аргументы обязательны, и ограничения, такие как `enum` (фиксированный список значений), `minimum` и `maximum`, `pattern` (регулярное выражение, которому должна соответствовать строка) и `additionalProperties: false` (никаких других ключей). Схема служит дважды: шаблон чата записывает её в контекст, чтобы модель знала, как вызывать, а среда выполнения по ней проверяет вызов.

Поставщики заворачивают одно и то же содержимое в немного разные обёртки: `parameters` в API OpenAI, `input_schema` в API Anthropic, `inputSchema` в Model Context Protocol. Определения входят в контекст каждого вызова, который делает агент, поэтому за их токены платят на каждом шаге; два определения из раздела «Код» занимают 530 символов, примерно 130 токенов при примерно четырёх символах на токен, а настоящие агенты с десятками инструментов тратят тысячи.

## Путь вызова инструмента туда и обратно \{#the-round-trip-of-a-tool-call\}

Модель, которая поддерживает инструменты, обучали на диалогах с определениями инструментов, вызовами и результатами в формате со специальными токенами вокруг вызовов ([Обучение на инструкциях и выравнивание](/ru/notes/nlp/instruction-tuning#what-sft-teaches)). Когда она решает сделать вызов, она пишет вместо текста блок вызова, и обслуживающий код возвращает его программе как структурированные данные, а не как сообщение для пользователя. Остальное делает программа, а не модель.

<ToolRoundTrip />

1. **Определение.** Среда выполнения отправляет определения инструментов и сообщение пользователя: *How much do three lamps, two chairs and a desk cost?* («Сколько стоят три лампы, два стула и стол?»)
2. **Вызов.** Модель отвечает тремя вызовами за один ход (turn), каждый с идентификатором: `c1` get_price(`lamps`), `c2` get_price(`chair`), `c3` get_price(`desk`).
3. **Проверка.** Среда выполнения проверяет каждый вызов по его схеме. `c1` не проходит: `lamps` нет в `enum`.
4. **Исполнение.** Два допустимых вызова выполняются одновременно; ход ждёт 0.8 с — время более медленного из них.
5. **Возврат.** Обратно идут три сообщения инструментов, каждое с идентификатором своего вызова: ошибка для `c1`, в которой названы допустимые значения, `41.0` для `c2`, `129.0` для `c3`.
6. **Продолжение.** Модель читает ошибку и вызывает get_price(`lamp`) как `c4`, затем калькулятор с `3 * 24.5 + 2 * 41.0 + 129.0` как `c5` и наконец отвечает: *Three lamps, two chairs and a desk cost 284.5 euros.*

Основную нагрузку несут три свойства протокола.

- **Идентификаторы связывают результаты с вызовами.** Ход может содержать несколько вызовов, а результаты могут прийти в любом порядке; какой результат отвечает на какой вызов, модели сообщает идентификатор, а не позиция.
- **Ошибки — это наблюдения.** Ошибка проверки для `c1` отправляется обратно как любой другой результат. Модель видит, почему вызов не прошёл, и исправляет его на следующем ходу; ничего не падает. Это тот же приём, что и вернуть программисту ошибку компилятора.
- **Модель никогда ничего не исполняет.** Она предлагает вызовы; среда выполнения решает, запускать ли их. Проверки, права доступа, подтверждения для действий с побочными эффектами и песочницы (sandbox) — всё это находится в среде выполнения, где текст в контексте не может их отговорить. Результат инструмента — данные, и текст внутри него, похожий на инструкцию, всё равно остаётся данными ([Безопасность агентов и инъекции в промпт](/ru/notes/agents/agent-security)).

**Параллельные вызовы.** Когда несколько вызовов не зависят друг от друга, модель может выдать их за один ход, а среда выполнения — исполнить их одновременно. В примере два допустимых вызова первого хода занимают по 0.8 с: параллельно ход длится 0.8 с, один за другим — 1.6 с, а вся задача — 1.7 с против 2.5 с. Экономия ходов модели важна не меньше: при одном вызове за ход понадобилось бы шесть ходов модели вместо четырёх, а каждый ход перечитывает весь контекст. Параллельными могут быть только независимые вызовы: калькулятору нужны цены, поэтому он ждёт следующего хода. LLMCompiler ([Kim et al., 2024](#references)) идёт дальше: модель сначала пишет план вызовов с их зависимостями, а затем каждый вызов отправляется на исполнение, как только готовы его входы; на своих бенчмарках он показал задержку до 3.7 раза меньше и стоимость до 6.7 раза меньше, чем цикл ReAct, вызывающий инструменты по одному.

## Ограниченное декодирование: допустимость по построению \{#constrained-decoding-valid-by-construction\}

Проверка ловит недопустимый вызов после того, как он сгенерирован. **Ограниченное декодирование** (constrained decoding) его предотвращает. Выход должен принадлежать множеству $\mathcal L$ допустимых строк, заданному грамматикой, регулярным выражением или JSON Schema. На каждом шаге декодер убирает токены, после которых выход невозможно завершить, и сэмплирует из оставшихся:

$$
\boxed{\;\tilde z_w = \begin{cases} z_w & \text{если } w \in M(u), \\ -\infty & \text{иначе,} \end{cases}
\qquad
\tilde p(w) = \frac{p(w)\,\mathbb 1[w \in M(u)]}{\sum_{w' \in M(u)} p(w')},
\qquad M(u) = \{\, w : u w \text{ живой} \,\}.\;}
$$

Токен конца последовательности разрешён только тогда, когда $u \in \mathcal L$. Почему каждый выход допустим: пустой префикс живой; если $u$ живой, каждый токен из $M(u)$ сохраняет его живым, а $M(u)$ не пусто, потому что некоторое продолжение существует; значит, каждый префикс, который когда-либо выдаёт декодер, живой, и остановиться он может только на законченном элементе $\mathcal L$. Допустимость сохраняется, какими бы ни были логиты модели.

**Разобранный пример.** Раздел «Код» ограничивает вызов формой `{"item": "…", "qty": …}` с товаром из `enum` магазина и целым количеством над игрушечным словарём из 17 токенов. После префикса `{"item": "` модель-заменитель предпочитает множественное число:

<LogitMask />

Токены `lamps`, `Sure` и `}` сделали бы вызов незавершаемым и маскируются. Остаются четыре токена. В ненормированном виде их веса равны $e^{1.5} + e^{0.2} + e^{0} + e^{-0.5} = 7.310$ из общей суммы $16.899$, так что $\sum_{w \in M(u)} p(w) = 0.433$, и деление на это число даёт `lamp` $0.613$, `chair` $0.167$, `de` $0.137$ и `desk` $0.083$. Токен `de` остаётся, потому что `desk` можно написать и как `de`, за которым следует `sk`; поэтому товар desk сохраняет вероятность $0.137 + 0.083 = 0.220$ через две токенизации. На 2000 сэмплах при $\tau = 1$ разбор и проверку схемой проходят 15.8% выходов без ограничения и 100% выходов с ограничением.

Работает ли это на практике, решают три детали.

- **Токены — не символы.** Токен вроде `", "qty": ` охватывает несколько символов грамматики, поэтому проверка прогоняет через автомат всю строку токена. А префикс, допустимый посимвольно, может быть мёртвым: в игрушечном словаре одиночный токен `"` после товара — допустимое начало `", "qty": `, но никакой токен его не продолжает, поэтому декодер должен проверять, жив ли префикс, по токенам, а не по символам. Эффективные реализации компилируют регулярное выражение или схему в конечный автомат и заранее вычисляют для каждого состояния множество токенов, ведущих в живые состояния, так что шаг стоит одного поиска в таблице ([Willard and Louf, 2023](#references)). Вложенным структурам, таким как объекты JSON внутри массивов произвольной глубины, нужен автомат с магазинной памятью или ограничение глубины.
- **Маскирование токен за токеном — не условие допустимости.** Распределение, которое нам хотелось бы получить, — распределение модели, ограниченное допустимыми строками, $p(y \mid y \in \mathcal L) \propto p(y)\,\mathbb 1[y \in \mathcal L]$. Маскирование вместо этого перенормирует на каждом шаге, не заглядывая вперёд, к какой допустимой вероятности ведёт каждая ветвь. **Разобранный пример.** Допустимые строки — `ab` и `cd`. Модель даёт `a` и `c` вероятность $0.5$ каждому; после `a` она кладёт $0.1$ на `b`, а остальное — на недопустимые токены, после `c` кладёт $0.9$ на `d`. Условие допустимости даёт $P(\texttt{ab}) = 0.05 / (0.05 + 0.45) = 0.1$ и $P(\texttt{cd}) = 0.9$. Маскирование оставляет оба первых токена с вероятностью $0.5$, а затем принудительно выбирает единственный допустимый второй токен, так что в половине случаев возвращает `ab` — строку, которую сама модель считает маловероятной. Park et al. ([2024](#references)) показывают это искажение на настоящих грамматиках и предлагают сэмплирование, которое его исправляет.
- **Допустимое — не значит правильное.** Схема гарантирует форму; она не выбирает правильный инструмент или правильный товар. А принудительный формат с первого токена может стоить качества: Tam et al. ([2024](#references)) обнаружили, что требование JSON или других строгих форматов снижало результаты моделей на задачах рассуждения. Распространённое средство — дать модели свободно порассуждать и ограничивать только вызов. Structured outputs OpenAI, появившиеся в августе 2024 года, применяют такое ограниченное декодирование к заданной схеме; на собственной оценке компании со сложными схемами модель с ограничением набрала 100% — ровно то, что гарантирует построение.

## Как модели научились вызывать инструменты: Toolformer \{#how-models-learned-to-call-tools-toolformer\}

Модель хорошо вызывает инструменты, только если обучение показало ей, когда вызов помогает. Toolformer ([Schick et al., 2023](#references)) получил такие обучающие данные без человеческой разметки, в три шага на корпусе обычного текста.

1. **Сэмплирование.** Промпт с несколькими примерами просит модель вставить в обычный текст вызовы-кандидаты, например `[Calculator(18 / 24) → ` перед долей в предложении об отношении. Позиции, где вероятность начать вызов у модели высока, сохраняются, и в каждой сэмплируется несколько вызовов.
2. **Исполнение** каждого вызова и вставка его результата.
3. **Фильтрация.** Вызов сохраняется, только если он делает последующий текст легче для предсказания. Пусть $L^+$ — взвешенная функция потерь модели на следующих токенах, когда перед ними вставлены вызов и его результат, а $L^-$ — меньшая из функций потерь без вызова и с вызовом, но без результата;

$$
\text{вызов сохраняется, если} \quad L^- - L^+ \ge \tau_f ,
$$

где $\tau_f = 1$ для большинства инструментов. Сравнение со случаем «вызов без результата» гарантирует, что помогает именно результат, а не само присутствие вызова. **Разобранный пример.** Перед текстом *… is 2.1 million* потери на следующих токенах равны $4.1$ без вызова, $4.0$ с вызовом `[QA(population of the city)]`, но без результата, и $1.2$ с его результатом. Тогда $L^- = \min(4.1, 4.0) = 4.0$ и $L^- - L^+ = 2.8 \ge 1$: вызов сохраняется. Вызов, результат которого снижает потери с $3.2$ до $3.0$, отбрасывается.

Затем модель дообучается на тексте с сохранёнными вызовами, и при выводе среда выполнения исполняет вызов всякий раз, когда модель его пишет. С GPT-J (6.7 млрд параметров) и инструментами для ответов на вопросы, калькулятором, поиском по Википедии, переводом и календарём доля правильных ответов zero-shot на текстовых математических задачах выросла с 7.5% до 40.4% на ASDiv, с 5.2% до 29.4% на SVAMP и с 9.9% до 44.0% на MAWPS — выше, чем 14.0%, 10.0% и 19.8% у GPT-3 175B в той же оценке. Использование инструментов помогало только начиная примерно с 775 млн параметров. Современные модели учатся вызывать инструменты при дообучении с учителем на диалогах с вызовами и всё чаще — обучением с подкреплением на задачах, исход которых зависит от вызовов; это тема заметки [Обучение агентов с подкреплением](/ru/notes/agents/agentic-rl).

## Код как действие \{#code-as-the-action\}

Вызов JSON называет одну функцию. Программа может вызвать много функций, объединить их результаты, выполнить цикл и ветвление — всё за одно действие. CodeAct ([Wang et al., 2024](#references)) делает пространством действий код на Python: модель пишет короткую программу, среда выполнения запускает её в интерпретаторе, а напечатанный вывод и любое сообщение об ошибке становятся наблюдением. На 17 моделях на API-Bank и на M3ToolEval, бенчмарке из 82 задач, которым нужно несколько инструментов, действия-код дали до 20 процентных пунктов больше успехов, чем действия в JSON или текстом; для `gpt-4-1106-preview` на M3ToolEval — 74.4% против 52.4% с JSON и 53.7% с текстом, в среднем за 5.5 хода вместо 7.6 и 7.7. [Курс NLP](/ru/notes/nlp/tools-and-agents#code-as-the-tool-interface) показывает в работе небольшого агента, который пишет код.

Цена в том, что такое действие может сделать всё, что может интерпретатор. Вызовы JSON проверяются по схеме и передаются функциям, которые написал разработчик; программу вместо этого нужно изолировать — в контейнере или виртуальной машине без сети и без учётных данных, которые ей не нужны ([Виртуальные машины и контейнеры](/ru/notes/acos/virtual-machines-and-containers#what-each-one-isolates)). Агентам для программирования, которые доводят эту идею до конца, посвящена заметка [Агенты для программирования](/ru/notes/agents/coding-agents).

## Ошибки и повторные попытки \{#errors-and-retries\}

Вызовы ломаются четырьмя способами, и у каждого своё место в среде выполнения.

| сбой | пример | кто его обрабатывает | как |
| --- | --- | --- | --- |
| испорченный выход | текст там, где ожидался вызов, сломанный JSON | декодер или среда выполнения | ограниченное декодирование или возврат модели ошибки разбора |
| недопустимые аргументы | `lamps` нет в `enum`, строка вместо числа | среда выполнения, затем модель | проверить по схеме; вернуть сообщение об ошибке как результат |
| ошибка исполнения | тайм-аут, ошибка сервера, исключение в инструменте | среда выполнения | повторять временные ошибки с задержкой; возвращать модели устойчивые ошибки |
| допустимо, но неправильно | правильная форма, неправильный товар или инструмент | модель, по последующим наблюдениям | в протоколе это ничто не ловит; помогает только проверка результата |

**Временные ошибки повторяет среда выполнения**, не тратя ход модели. Если попытка независимо проваливается с вероятностью $0.3$, все три попытки проваливаются с вероятностью $0.3^3 = 0.027$, так что вызов удаётся с вероятностью $0.973$. Пауза между попытками обычно удваивается (экспоненциальная задержка, exponential backoff), чтобы не нагружать ещё сильнее сервис, который и так под нагрузкой. В запуске с ненадёжным инструментом в разделе «Код» на четыре вызова понадобилось пять попыток, задача заняла 2.3 с вместо 1.7 с, и модель так и не увидела сбоев.

**Повторы модели не независимы.** Если спросить её снова с тем же контекстом, она склонна повторить ту же ошибку, так что повтор помогает, только если контекст меняется, — поэтому сообщение об ошибке и возвращается в него. Полезное сообщение об ошибке говорит, что было не так и что разрешено, как это делает ошибка `enum`.

**Вслепую можно повторять только идемпотентные вызовы.** Дважды прочитать цену безвредно. Дважды отправить платёж или письмо — нет, а тайм-аут не говорит среде выполнения, подействовала ли первая попытка. Вызовам с побочными эффектами нужен ключ идемпотентности (idempotency key), по которому принимающий сервис узнаёт повтор, или шаг подтверждения перед запуском, как в [курсе NLP](/ru/notes/nlp/tools-and-agents#agents-a-loop-around-tool-calls).

Инструменты не обязательно вписывать в собственную программу агента. **Model Context Protocol** (MCP), представленный Anthropic в ноябре 2024 года, позволяет отдельным серверам предлагать инструменты с теми же тремя полями — именем, описанием и `inputSchema`, — которые клиент находит, запрашивая их список, и вызывает, отправляя вызовы. Подробно его разбирает заметка [Рабочие процессы, фреймворки и протоколы](/ru/notes/agents/workflows-and-protocols).

## Что изменилось \{#what-changed\}

| | действия, разобранные из свободного текста | вызов функций |
| --- | --- | --- |
| формат действия | соглашение, которое читает регулярное выражение | блок вызова с именем, идентификатором и аргументами в JSON |
| что модель знает об инструменте | строку в промпте | определение с описанием и схемой |
| недопустимые действия | теряются или угадываются парсером | отвергаются проверкой и возвращаются как ошибки или исключаются ограниченным декодированием |
| несколько действий за ход | нет | параллельные вызовы, связанные с результатами идентификаторами |
| кто исполняет | программа агента | среда выполнения, с проверками, повторами и правами доступа |
| как модель этому научилась | примеры в промпте | обучение на вызовах: фильтр Toolformer, затем дообучение и RL |

## Ограничения \{#limitations\}

- **Схемы проверяют форму, а не смысл.** Допустимый вызов может оказаться не тем вызовом, и ничто в протоколе этого не заметит.
- **Ограниченное декодирование искажает распределение**, из которого сэмплирует, а принудительный формат с первого токена может вредить рассуждению.
- **Определения стоят контекста.** Описание каждого инструмента перечитывается на каждом шаге, а среди множества похожих инструментов модели выбирают менее надёжно; большим наборам инструментов нужен поиск инструментов или несколько более узких агентов.
- **Результатам инструментов нельзя доверять.** Результат — текст, который попадает в контекст, а текст может нести инструкции.
- **Побочные эффекты делают повторы опасными.** После тайм-аута состояние мира неизвестно.
- **Действиям-коду нужна песочница.** Они строго выразительнее вызовов JSON и строго труднее поддаются изоляции.

## Что нужно запомнить \{#what-you-should-remember\}

- Инструмент — это имя, описание, написанное для модели, и JSON Schema его аргументов. Схема записывается в контекст и снова используется средой выполнения для проверки.
- Путь туда и обратно: модель выдаёт вызовы с идентификаторами; среда выполнения проверяет, исполняет и возвращает по одному сообщению на вызов; ошибки возвращаются как результаты, чтобы модель могла исправить вызов.
- Независимые вызовы можно выдать за один ход и выполнить параллельно: задержка становится равной самому медленному вызову, а не сумме, и меньше ходов модели перечитывают контекст.
- Ограниченное декодирование приравнивает к $-\infty$ логиты токенов, после которых выход невозможно завершить, и перенормирует. Тогда каждый выход допустим — по индукции по живым префиксам. Проверка идёт по токенам, а не по символам, и маскирование на каждом шаге — не то же самое, что условие допустимости.
- Toolformer сохранял сэмплированный вызов, только если его результат снижал потери на последующем тексте хотя бы на $\tau_f$, и так превращал обычный текст в обучающие данные для использования инструментов.
- Код как действие объединяет много вызовов в одном шаге и требует песочницы.
- Среда выполнения повторяет временные ошибки с задержкой и только для идемпотентных вызовов; модель исправляет ошибки, которые ей показывают.

## Код \{#code\}

Реестр инструментов, валидатор для используемой части JSON Schema, среда выполнения, которая проверяет, исполняет параллельно и повторяет попытки, заскриптованная модель-заменитель, которая выдаёт вызовы и читает результаты, и ограниченный декодер над игрушечным словарём с проверкой живости по токенам. С настоящей моделью `toy_model` становится запросом к модели с определениями инструментов, а `toy_logits` — её логитами следующего токена внутри обслуживающего движка; реестр, валидатор, среда выполнения и маска остаются как есть. Начальные значения генератора фиксированы; точные числа могут немного различаться на разных платформах и версиях библиотек. Скрипт работает меньше секунды.

```python
import ast, json, operator, re
from functools import lru_cache
import numpy as np

# 1. реестр инструментов: функция Python плюс JSON Schema её аргументов
TOOLS = {}
def tool(name, description, parameters, latency):
    def register(fn):
        TOOLS[name] = {'fn': fn, 'latency': latency,
                       'definition': {'name': name, 'description': description, 'parameters': parameters}}
        return fn
    return register

PRICES = {'lamp': 24.5, 'chair': 41.0, 'desk': 129.0}            # игрушечный магазин
@tool('get_price', 'Price of one item in the shop, in euros.',
      {'type': 'object', 'properties': {'item': {'type': 'string', 'enum': list(PRICES)}},
       'required': ['item'], 'additionalProperties': False}, latency=0.8)
def get_price(item):
    return PRICES[item]

OPS = {ast.Add: operator.add, ast.Sub: operator.sub, ast.Mult: operator.mul, ast.Div: operator.truediv}
def arith(node):                                                  # +, -, *, / над числами, и ничего больше
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)): return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in OPS: return OPS[type(node.op)](arith(node.left), arith(node.right))
    raise ValueError('only numbers and + - * / are allowed')
@tool('calculator', 'Evaluate an arithmetic expression with + - * / and parentheses.',
      {'type': 'object', 'properties': {'expression': {'type': 'string', 'pattern': r'^[0-9+\-*/(). ]+$'}},
       'required': ['expression'], 'additionalProperties': False}, latency=0.1)
def calculator(expression):
    return arith(ast.parse(expression, mode='eval').body)

# 2. валидатор для используемой здесь части JSON Schema
TYPES = {'object': dict, 'string': str, 'integer': int, 'number': (int, float), 'boolean': bool, 'array': list}
def validate(x, schema, path='arguments'):
    if not isinstance(x, TYPES[schema['type']]): return [f'{path} must be of type {schema["type"]}']
    errors = []
    if schema['type'] == 'object':
        props = schema.get('properties', {})
        errors += [f'{path}.{k} is required' for k in schema.get('required', []) if k not in x]
        if schema.get('additionalProperties') is False:
            errors += [f'{path}.{k} is not allowed' for k in x if k not in props]
        for k, v in x.items():
            if k in props: errors += validate(v, props[k], f'{path}.{k}')
    if 'enum' in schema and x not in schema['enum']: errors.append(f'{path} must be one of {schema["enum"]}')
    if 'pattern' in schema and not re.search(schema['pattern'], x): errors.append(f'{path} does not match {schema["pattern"]}')
    return errors

# 3. среда выполнения: проверить, исполнить, повторить временные сбои и вернуть каждый результат сообщением инструмента
def execute(call, rng, flaky=0.0, retries=3):
    t = TOOLS.get(call['name'])
    if t is None: return {'error': f'unknown tool {call["name"]}'}, 0.0, 0
    try: args = json.loads(call['arguments'])
    except json.JSONDecodeError as e: return {'error': f'arguments are not JSON: {e.msg}'}, 0.0, 0
    errors = validate(args, t['definition']['parameters'])
    if errors: return {'error': '; '.join(errors)}, 0.0, 0          # модель видит причину и может исправить вызов
    waited = 0.0
    for attempt in range(1, retries + 1):
        waited += t['latency']
        if rng.random() >= flaky: return {'result': t['fn'](**args)}, waited, attempt
        waited += 0.5 * 2 ** (attempt - 1)                          # временный сбой: подождать и попробовать снова
    return {'error': 'tool unavailable, try later'}, waited, retries

# 4. заскриптованная замена модели: она читает сообщения и выдаёт вызовы или ответ
def toy_model(messages):
    results = {m['tool_call_id']: json.loads(m['content']) for m in messages if m['role'] == 'tool'}
    if not results:                                                 # три независимых вызова за один ход
        return {'role': 'assistant', 'tool_calls': [
            {'id': 'c1', 'name': 'get_price', 'arguments': '{"item": "lamps"}'},
            {'id': 'c2', 'name': 'get_price', 'arguments': '{"item": "chair"}'},
            {'id': 'c3', 'name': 'get_price', 'arguments': '{"item": "desk"}'}]}
    if any(r.get('error', '').startswith('tool unavailable') for r in results.values()):
        return {'role': 'assistant', 'content': 'A tool is unavailable right now; please try again later.'}
    if 'error' in results.get('c1', {}) and 'c4' not in results:   # прочитать ошибку, исправить аргумент
        return {'role': 'assistant', 'tool_calls': [{'id': 'c4', 'name': 'get_price', 'arguments': '{"item": "lamp"}'}]}
    if 'c5' not in results:
        lamp, chair, desk = (results[k]['result'] for k in ('c4', 'c2', 'c3'))
        return {'role': 'assistant', 'tool_calls': [
            {'id': 'c5', 'name': 'calculator', 'arguments': json.dumps({'expression': f'3 * {lamp} + 2 * {chair} + {desk}'})}]}
    return {'role': 'assistant', 'content': f'Three lamps, two chairs and a desk cost {results["c5"]["result"]} euros.'}

def agent(user, rng, flaky=0.0, max_turns=6):
    messages = [{'role': 'system', 'content': json.dumps([t['definition'] for t in TOOLS.values()])},
                {'role': 'user', 'content': user}]
    clock, sequential, attempts = 0.0, 0.0, 0
    for _ in range(max_turns):
        reply = toy_model(messages)
        messages.append(reply)
        if 'tool_calls' not in reply: return reply['content'], messages, clock, sequential, attempts
        outs = [execute(c, rng, flaky) for c in reply['tool_calls']]
        clock += max(w for _, w, _ in outs)                         # параллельные вызовы: ждать самого медленного
        sequential += sum(w for _, w, _ in outs)                    # один за другим: ждать все
        attempts += sum(k for _, _, k in outs)
        for c, (out, _, _) in zip(reply['tool_calls'], outs):
            messages.append({'role': 'tool', 'tool_call_id': c['id'], 'content': json.dumps(out)})
    return None, messages, clock, sequential, attempts

answer, messages, clock, sequential, attempts = agent('How much do three lamps, two chairs and a desk cost?', np.random.default_rng(0))
for m in messages[2:]: print(m['role'], m.get('tool_calls') or m.get('content'))
print(answer, round(clock, 2), round(sequential, 2), attempts)
print(len(messages[0]['content']))                                 # символов в определениях инструментов, которые отправляются каждый ход
# assistant [{'id': 'c1', 'name': 'get_price', 'arguments': '{"item": "lamps"}'}, {'id': 'c2', 'name': 'get_price', 'arguments': '{"item": "chair"}'}, {'id': 'c3', 'name': 'get_price', 'arguments': '{"item": "desk"}'}]
# tool {"error": "arguments.item must be one of ['lamp', 'chair', 'desk']"}
# tool {"result": 41.0}
# tool {"result": 129.0}
# assistant [{'id': 'c4', 'name': 'get_price', 'arguments': '{"item": "lamp"}'}]

# ненадёжный инструмент: среда выполнения повторяет попытки с задержкой; модель не видит временных сбоев
answer, _, clock, _, attempts = agent('How much do three lamps, two chairs and a desk cost?', np.random.default_rng(4), flaky=0.3)
print(answer, round(clock, 2), attempts)
print(round(1 - 0.3 ** 3, 3))                                      # успех за 3 независимые попытки
# Three lamps, two chairs and a desk cost 284.5 euros. 2.3 5
# 0.973

# 5. ограниченное декодирование: игрушечный словарь и проверка того, что выход ещё может стать допустимым
SEGS = [('lit', ['{"item": "']), ('lit', list(PRICES)), ('lit', ['", "qty": ']), ('int', None), ('lit', ['}'])]
def match(s, i=0, k=0, partial=True):
    """Can s[i:] be read as segments k, k+1, ... (only a prefix of them if partial)?"""
    if i == len(s): return partial or k == len(SEGS)
    if k == len(SEGS): return False
    kind, alts = SEGS[k]
    if kind == 'lit':
        for v in alts:
            n = min(len(v), len(s) - i)
            if s[i:i + n] == v[:n] and (match(s, i + n, k + 1, partial) if n == len(v) else partial): return True
        return False
    j = i                                                           # целое число: одна или несколько цифр
    while j < len(s) and s[j].isdigit():
        j += 1
        if match(s, j, k + 1, partial): return True
    return False

@lru_cache(maxsize=None)
def live(s, depth=0):
    """Can some sequence of vocabulary tokens complete s? (a legal character prefix is not enough)"""
    if match(s, partial=False): return True
    nxt = [w for w in VOCAB if w != '<eos>' and match(s + w)]
    return depth < 8 and any(live(s + w, depth + 1) for w in nxt)

VOCAB = ['{"', 'item', '": "', '{"item": "', 'lamp', 'lamps', 'chair', 'desk', 'de', 'sk', '", "qty": ',
         '"', '3', '12', '}', 'Sure', '<eos>']                                      # '"' в одиночку ведёт в тупик
def toy_logits(prefix):
    z = dict.fromkeys(VOCAB, -4.0)
    if prefix == '':                          z.update({'Sure': 1.0, '{"': 1.0, '{"item": "': 1.2})
    elif prefix.endswith('{"'):               z.update({'item': 3.0})
    elif prefix.endswith('item'):             z.update({'": "': 3.0})
    elif prefix.endswith('"item": "'):        z.update({'lamps': 2.0, 'lamp': 1.5, 'Sure': 0.5, 'chair': 0.2, 'de': 0.0, 'desk': -0.5, '}': -1.0})
    elif prefix.endswith('de'):               z.update({'sk': 3.0})
    elif re.search(r'"(lamps?|chair|desk)$', prefix): z.update({'", "qty": ': 2.0, '"': 1.0, '}': 0.5})
    elif prefix.endswith('": '):              z.update({'3': 2.0, '12': 1.0})
    elif re.search(r'\d$', prefix):           z.update({'}': 2.0, '12': 0.0})
    else:                                     z.update({'<eos>': 3.0})
    return np.array([z[w] for w in VOCAB])

def decode(rng, constrained, tau=1.0, max_tokens=12):
    out = ''
    for _ in range(max_tokens):
        z = toy_logits(out) / tau
        if constrained:                                             # замаскировать каждый токен, после которого завершение невозможно
            ok = [match(out, partial=False) if w == '<eos>' else match(out + w) and live(out + w) for w in VOCAB]
            z = np.where(ok, z, -np.inf)
        p = np.exp(z - z.max()); p /= p.sum()
        w = VOCAB[rng.choice(len(VOCAB), p=p)]
        if w == '<eos>': break
        out += w
    return out

def is_valid(s):
    try: x = json.loads(s)
    except json.JSONDecodeError: return False
    schema = {'type': 'object', 'properties': {'item': {'type': 'string', 'enum': list(PRICES)}, 'qty': {'type': 'integer'}},
              'required': ['item', 'qty'], 'additionalProperties': False}
    return not validate(x, schema)

rng = np.random.default_rng(0)
for constrained in (False, True):
    outs = [decode(rng, constrained) for _ in range(2000)]
    print(constrained, np.mean([is_valid(s) for s in outs]), outs[:2])
# False 0.1575 ['{"item": "lamps", "qty": sk', 'Sure']
# True 1.0 ['{"item": "chair", "qty": 3}', '{"item": "lamp", "qty": 3}']

# шаг маскирования после '{"item": "': логиты, разрешённые токены, вероятности до и после
z = toy_logits('{"item": "')
ok = np.array([w != '<eos>' and match('{"item": "' + w) and live('{"item": "' + w) for w in VOCAB])
p = np.exp(z) / np.exp(z).sum()
q = np.where(ok, p, 0) / p[ok].sum()
for w in ('lamps', 'lamp', 'Sure', 'chair', 'de', 'desk', '}'):
    i = VOCAB.index(w); print(f'{w:6s} {z[i]:5.1f} {int(ok[i])} {p[i]:.3f} {q[i]:.3f}')
print('other', round(float(p[~np.isin(VOCAB, ['lamps', 'lamp', 'Sure', 'chair', 'de', 'desk', '}'])].sum()), 3))
# lamps    2.0 0 0.437 0.000
# lamp     1.5 1 0.265 0.613
# Sure     0.5 0 0.098 0.000
# chair    0.2 1 0.072 0.167
# de       0.0 1 0.059 0.137
# desk    -0.5 1 0.036 0.083
# }       -1.0 0 0.022 0.000
# other 0.011

# 6. маскирование токен за токеном — не условие допустимости: допустимы только строки 'ab' и 'cd'
p1 = {'a': 0.5, 'c': 0.5}; p2 = {'a': {'b': 0.1}, 'c': {'d': 0.9}}     # P(второй токен | первый); остальное недопустимо
joint = {f + s: p1[f] * p2[f][s] for f in p1 for s in p2[f]}
print({k: round(v / sum(joint.values()), 3) for k, v in joint.items()}, {f + s: p1[f] for f in p1 for s in p2[f]})
# {'ab': 0.1, 'cd': 0.9} {'ab': 0.5, 'cd': 0.5}
```
