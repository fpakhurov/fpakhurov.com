[Предыдущая заметка](/ru/notes/agents/what-an-agent-is) классифицировала агентов по тому, сколько они вычисляют, прежде чем действовать. Агент, основанный на цели, знает, какие состояния ему нужны, и сам находит, как их достичь. Когда мир полностью наблюдаем, детерминирован и известен, это можно сделать целиком заранее: агент перебирает в воображении последовательности действий с помощью своей модели мира, находит ту, что заканчивается в цели, и затем выполняет её, не глядя. Нахождение такой последовательности — это **поиск** (search). В этой заметке мы ставим задачу поиска, решаем её тремя алгоритмами возрастающей изобретательности, доказываем, что последний из них, A\*, возвращает оптимальное решение, а затем описываем языки планирования, которые позволяют одной постановкой охватить целое семейство задач. Обе идеи вернутся позже в курсе — внутри агентов на языковых моделях.

**Обозначения.** Состояние — $s$, действие — $a$; $\mathrm{Actions}(s)$ — множество действий, применимых в $s$, $\mathrm{Result}(s, a)$ — состояние, к которому они ведут, а $c(s, a, s') > 0$ — стоимость шага. **Узел** (node) $n$ поиска — состояние вместе с путём, которым оно достигнуто; $g(n)$ — стоимость этого пути, $g^\star(n)$ — стоимость самого дешёвого пути в состояние узла $n$, $h(n)$ — эвристическая оценка наименьшей стоимости пути от $n$ до цели, а $h^\star(n)$ — сама эта наименьшая стоимость. $C^\star$ — стоимость оптимального решения. $b$ — коэффициент ветвления (branching factor, число потомков узла), $d$ — глубина самой мелкой цели, $\varepsilon > 0$ — наименьшая стоимость шага.

## Постановка задачи \{#formulating-a-problem\}

Задача поиска состоит из пяти частей ([Russell and Norvig, 2021](#references), раздел 3.1):

1. множество **состояний** и **начальное состояние** $s_0$;
2. **проверка цели** (goal test), которая говорит, является ли состояние целью (множество целевых состояний или предикат);
3. **действия** $\mathrm{Actions}(s)$, доступные в каждом состоянии;
4. **модель переходов** (transition model) $\mathrm{Result}(s, a)$;
5. **стоимость действия** (action cost) $c(s, a, s')$.

**Решение** — последовательность действий, которая ведёт из $s_0$ в целевое состояние; у **оптимального** решения наименьшая суммарная стоимость $C^\star$. Состояния и действия образуют ориентированный граф — **пространство состояний** (state space), и каждое решение — путь в нём. На карте дорог состояния — города, действия — дороги, стоимости — длины. В головоломке «8» (8-puzzle), где восемь пронумерованных фишек лежат на доске 3 × 3 с одной пустой клеткой, состояние — расположение фишек, действие сдвигает фишку на пустое место, и каждое действие стоит 1; из любого расположения достижима половина из $9!$ расположений, так что в пространстве состояний $9!/2 = 181\,440$ состояний.

Постановка задачи — это выбор абстракции. Планировщик маршрута не учитывает погоду, радио и точное положение руля; абстракция хороша, если каждое абстрактное решение можно превратить в настоящее, а абстрактная задача намного меньше настоящей.

Алгоритм поиска исследует пространство состояний из $s_0$, не строя его целиком. Он хранит **границу** (frontier) — узлы, которые достигнуты, но ещё не раскрыты, — и раз за разом **раскрывает** (expands) один из них: убирает его с границы и добавляет узлы для всех его потомков. Поскольку одно и то же состояние может быть достигнуто несколькими путями, **поиск в графе** (graph search) ещё и помнит, какие состояния он уже достиг, и хранит для каждого только самый дешёвый известный путь. Алгоритмы ниже различаются лишь одним: какой узел границы они раскрывают следующим.

## Отправная точка: поиск в ширину \{#baseline-breadth-first-search\}

**Поиск в ширину** (breadth-first search) раскрывает сначала самый мелкий узел, используя в качестве границы очередь «первым пришёл — первым ушёл» (FIFO). Он достигает всех состояний на глубине 1 раньше любого на глубине 2 и так далее, поэтому первая достигнутая им цель лежит на наименьшей глубине $d$; проверять цель можно сразу при порождении узла. Когда все действия стоят одинаково, самая мелкая цель — она же самая дешёвая, и поиск в ширину оптимален.

Платить приходится памятью. При $b$ потомках у каждого узла он порождает

$$
1 + b + b^2 + \dots + b^d = O(b^d)
$$

узлов и хранит их все, потому что каждое достигнутое состояние нужно помнить. При $b = 10$ и $d = 12$ это $10^{12}$ узлов — гораздо больше, чем вмещает компьютер. И как только стоимости различаются, он перестаёт быть оптимальным: путь из двух дорогих дорог может быть мельче пути из трёх дешёвых.

## Поиск по критерию стоимости \{#uniform-cost-search\}

**Поиск по критерию стоимости** (uniform-cost search) раскрывает узел с наименьшей стоимостью пути $g(n)$, используя в качестве границы приоритетную очередь. Это алгоритм Дейкстры для кратчайших путей ([Dijkstra, 1959](#references)), запущенный из одного источника и остановленный на цели. Важны две детали.

- **Цель проверяется при раскрытии узла, а не при его порождении.** На графе рисунка ниже поиск по критерию стоимости сначала достигает G через C с $g = 8$ и лишь позже — через D с $g = 7$. Остановка на первом порождённом G вернула бы худший путь.
- **Стоимости шагов должны быть положительны**, не меньше некоторого $\varepsilon > 0$. Тогда стоимости раскрываемых узлов не убывают, первая раскрытая цель оптимальна, и поиск завершается. С циклами нулевой стоимости он мог бы работать вечно; с отрицательными стоимостями рассуждение Дейкстры не проходит.

Поиск по критерию стоимости оптимален при любых положительных стоимостях, но он слеп: он расходится от $s_0$ во все стороны в порядке стоимости, ведёт ли направление к цели или нет. Его работа растёт как $b^{1 + \lfloor C^\star / \varepsilon \rfloor}$.

## A\*: догадка об оставшейся стоимости \{#a-guessing-the-remaining-cost\}

<aside class="callout"><strong>Ключевая идея.</strong> Прибавим к уже уплаченной стоимости оценку той, что ещё предстоит заплатить, и будем раскрывать узел с наименьшей суммой: $f(n) = g(n) + h(n)$. Если оценка никогда не завышает истинную оставшуюся стоимость, первая раскрытая цель оптимальна, и чем лучше оценка, тем меньше узлов раскрывает поиск.</aside>

Поиск **A\*** ([Hart, Nilsson and Raphael, 1968](#references)) раскрывает узел границы с наименьшим

$$
f(n) = g(n) + h(n),
$$

то есть с наименьшей оценкой стоимости самого дешёвого решения, проходящего через $n$. При $h = 0$ это поиск по критерию стоимости. Что гарантирует A\*, определяют два свойства $h$:

- $h$ **допустима** (admissible), если она никогда не завышает: $h(n) \le h^\star(n)$ для каждого $n$, а значит, $h = 0$ в целях.
- $h$ **согласована** (consistent), если на каждом шаге выполняется неравенство треугольника:

$$
h(n) \le c(n, a, n') + h(n') \qquad \text{для каждого действия } a \text{ из } n \text{ в } n' = \mathrm{Result}(n, a), \qquad h(\text{цель}) = 0 .
$$

Из согласованности следует допустимость. Возьмём самый дешёвый путь $n = n_0, n_1, \dots, n_k$ из $n$ в цель $n_k$ и применим неравенство $k$ раз: $h(n_0) \le c(n_0, n_1) + h(n_1) \le c(n_0, n_1) + c(n_1, n_2) + h(n_2) \le \dots \le \sum_{i} c(n_i, n_{i+1}) + h(n_k) = h^\star(n)$. Обратное неверно, но большинство допустимых эвристик, встречающихся на практике, ещё и согласованы.

**Разобранный пример.** В графе семь вершин; эвристика, указанная у каждой вершины, согласована на каждом ребре:

<AStarTrace />

1. **Раскрываем S** ($g = 0$, $f = 0 + 6 = 6$). На границу попадают A с $f = 2 + 5 = 7$ и B с $f = 3 + 4 = 7$. При равенстве выбираем более глубокий узел, B.
2. **Раскрываем B** ($g = 3$, $f = 7$). На границу попадают C с $g = 4$, $f = 4 + 4 = 8$ и E с $g = 5$, $f = 5 + 5 = 10$.
3. **Раскрываем A** ($g = 2$, $f = 7$). На границу попадает D с $g = 6$, $f = 6 + 1 = 7$. A предлагает и путь в C стоимостью 5, хуже уже известного 4, поэтому он отбрасывается.
4. **Раскрываем D** ($g = 6$, $f = 7$). На границу попадает G с $g = 7$, $f = 7 + 0 = 7$.
5. **Раскрываем G**: это цель, стоимость 7, путь S–A–D–G.

C и E так и не раскрываются: их значения $f$, 8 и 10, больше $C^\star = 7$. Поиск по критерию стоимости на том же графе раскрывает все семь вершин.

### Почему A\* возвращает оптимальное решение \{#why-a-returns-an-optimal-solution\}

Рассуждение для поиска в графе с согласованной эвристикой состоит из трёх шагов.

**Шаг 1: $f$ не убывает вдоль пути.** Если $n'$ — потомок $n$, то

$$
\begin{aligned}
f(n') &= g(n') + h(n') && \text{определение } f \\
&= g(n) + c(n, a, n') + h(n') && \text{путь в } n' \text{ продолжает путь в } n \\
&\ge g(n) + h(n) && \text{согласованность: } c(n, a, n') + h(n') \ge h(n) \\
&= f(n) .
\end{aligned}
$$

**Шаг 2: когда A\* раскрывает узел, самый дешёвый путь к нему уже найден.** Пусть A\* собирается раскрыть узел $n$ с $g(n) > g^\star(n)$. Рассмотрим самый дешёвый путь из $s_0$ в состояние узла $n$. Его первый узел раскрыт (это $s_0$), а последний нет, поэтому на нём есть узел $n''$, который лежит на границе, причём все его предшественники на этом пути раскрыты; а поскольку $n''$ достигнут по самому дешёвому пути, $g(n'') = g^\star(n'')$. Тогда

$$
\begin{aligned}
f(n'') &= g^\star(n'') + h(n'') && n'' \text{ лежит на самом дешёвом пути} \\
&\le g^\star(n) + h(n) && \text{шаг 1 вдоль остатка этого пути} \\
&< g(n) + h(n) = f(n) && \text{предположение } g(n) > g^\star(n),
\end{aligned}
$$

так что A\* раскрыл бы $n''$ раньше $n$ — противоречие. Значит, при раскрытии $g(n) = g^\star(n)$.

**Шаг 3: первая раскрытая цель оптимальна.** Применим шаг 2 к первому целевому узлу, который раскрывает A\*: его $g$ — наименьшая стоимость пути к этой цели. У любой другой цели, достигнутой позже, по шагу 1 значение $f$ не меньше, а в цели $f = g$, потому что там $h = 0$. Следовательно,

$$
\boxed{\; \text{при согласованной } h, \text{ A* раскрывает узлы в порядке неубывания } f, \text{ и стоимость первой раскрытой им цели равна } C^\star \;}
$$

Отсюда два следствия. A\* раскрывает каждый узел с $f(n) < C^\star$ и ни одного с $f(n) > C^\star$: множество раскрытых узлов — контур $f$ вокруг старта, как на рисунке, где C и E лежат вне контура $f = 7$. И никакой другой оптимальный алгоритм, получивший ту же эвристику и продолжающий пути от старта, не может быть уверен в оптимальности, пропустив узел с $f(n) < C^\star$, потому что оставшаяся стоимость может оказаться такой же низкой, как обещает $h$; в этом смысле A\* **оптимально эффективен** (optimally efficient) — с точностью до равенств при $f = C^\star$ ([Russell and Norvig, 2021](#references), раздел 3.5).

Для поиска в дереве (tree search), который не помнит достигнутых состояний, достаточно одной допустимости. Если на границе лежит неоптимальная цель $G_2$ с $g(G_2) > C^\star$, то на границе есть и некоторый узел $n$ оптимального пути, и $f(n) = g(n) + h(n) \le g(n) + h^\star(n) = C^\star < g(G_2) = f(G_2)$, так что $n$ раскрывается первым; повторяя рассуждение, получаем, что оптимальная цель раскрывается раньше $G_2$.

### Откуда берутся эвристики \{#where-heuristics-come-from\}

Хорошая эвристика — это точная стоимость **ослабленной задачи** (relaxed problem), в которой сняты некоторые ограничения. На сетке со стенами снятие стен даёт манхэттенское расстояние $|r - r_G| + |c - c_G|$. В головоломке «8», если разрешить фишке переходить на любую соседнюю клетку, занятую или нет, получается сумма манхэттенских расстояний фишек до их мест. У ослабленной задачи больше решений, поэтому её оптимальная стоимость не может превышать настоящую: эвристика допустима. Она и согласована, потому что это точная стоимость в задаче с теми же ходами и большей свободой, а точные стоимости удовлетворяют неравенству треугольника.

Если $h_2(n) \ge h_1(n)$ для каждого $n$ и обе допустимы, то $h_2$ **доминирует** (dominates) над $h_1$, и A\* с $h_2$ никогда не раскрывает узел, который A\* с $h_1$ оставляет нетронутым (с точностью до равенств): у каждого узла с $f_2(n) = g(n) + h_2(n) < C^\star$ также $f_1(n) < C^\star$. Идеальная эвристика — сама $h^\star$, которая ведёт A\* прямо к цели; но вычислить её стоит столько же, сколько решить саму задачу, и искусство в том, чтобы найти дешёвую функцию, близкую к ней.

Поиск в ширину, оптимальный здесь, потому что все стоимости равны 1, достигает 139 состояний, прежде чем остановиться. Вес $w > 1$ даёт **взвешенный A\*** (weighted A\*) ([Pohl, 1970](#references)): эвристика весит больше уплаченной стоимости, поиск становится жаднее, и $f$ больше не нижняя оценка. ## Классическое планирование: STRIPS и PDDL \{#classical-planning-strips-and-pddl\}

Каждая задача выше приходила со своим кодом для $\mathrm{Actions}$ и $\mathrm{Result}$. Языки планирования описывают целое семейство задач одним **факторизованным** (factored) представлением, так что один общий алгоритм может решать их все, а по самому описанию можно автоматически выводить эвристики.

В представлении **STRIPS** ([Fikes and Nilsson, 1971](#references)) состояние — множество конкретных фактов, например `on(C, A)` и `clear(B)`; каждый факт, не входящий в множество, ложен. **Схема действия** (action schema) имеет параметры и три списка фактов:

- **предусловия** (preconditions), которые все должны выполняться, чтобы действие было применимо;
- **список добавления** (add list) — факты, которые становятся истинными;
- **список удаления** (delete list) — факты, которые становятся ложными.

Для применимого действия модель переходов сводится к операциям над множествами:

$$
\mathrm{Result}(s, a) = \big(s \setminus \mathrm{Del}(a)\big) \cup \mathrm{Add}(a), \qquad \text{применимо, если } \mathrm{Pre}(a) \subseteq s .
$$

**PDDL**, Planning Domain Definition Language ([McDermott et al., 1998](#references)), — стандартный синтаксис таких описаний, который с 1998 года используется на International Planning Competition. **Файл домена** (domain file) определяет предикаты и схемы действий; **файл задачи** (problem file) перечисляет объекты, начальное состояние и цель. В мире блоков (blocks world) блоки стоят на столе или друг на друге, и за раз можно переставить один свободный блок. Одно из трёх его действий, записанное на PDDL:

```lisp
(:action move-to-table
  :parameters (?x ?y)
  :precondition (and (on ?x ?y) (clear ?x))
  :effect (and (on-table ?x) (clear ?y) (not (on ?x ?y))))
```

Два других переставляют свободный блок с блока или со стола на другой свободный блок. Задача:

```lisp
(:init (on C A) (on-table A) (on-table B) (clear C) (clear B))
(:goal (and (on A B) (on B C)))
```

**Разобранный пример.** Поиск в ширину по множествам фактов из этого начального состояния применяет 18 конкретных действий для трёх блоков и находит план из трёх шагов: переставить C на стол, переставить B на C, переставить A на B. По пути он достигает всех 13 состояний мира из трёх блоков, как печатает раздел «Код». Эта маленькая задача, **аномалия Зуссмана** (Sussman anomaly), знаменита по другой причине. Планировщик, который достигает целей по одной, на ней проваливается: если сначала поставить A на B, нужно снять C с A, а затем поставить A на B, после чего B нельзя поставить на C, не сняв снова A; если сначала поставить B на C, A окажется погребённым под C и B. Цели взаимодействуют, и план находит только поиск по целым состояниям.

Число состояний мира блоков растёт быстрее экспоненты: 13 для трёх блоков, 501 для пяти, 58 941 091 для десяти. Поэтому планировщики ищут с эвристиками, а факторизованная форма даёт их даром. Самое полезное ослабление **игнорирует списки удаления** (ignores the delete lists): однажды ставший истинным факт остаётся истинным. Стоимость оптимального ослабленного плана, $h^+$, допустима, но её вычисление NP-трудно; её приближения — допустимая $h_{\max}$ и более информативные, но недопустимые $h_{\text{add}}$ и эвристика FF — сделали эвристический прямой поиск основным подходом к классическому планированию ([Bonet and Geffner, 2001](#references); [Hoffmann and Nebel, 2001](#references)).

## Почему это важно для планировщиков на языковых моделях \{#why-this-matters-for-language-model-planners\}

Языковая модель, которую просят спланировать в тексте, ничего из этого явно не делает: она пишет план за один проход, без границы, без проверки цели и без возвратов. На задачах, которые требуют поиска, например в мире блоков с большим числом блоков, её планы часто недопустимы ([Valmeekam et al., 2023](#references)). Идеи этой заметки возвращаются тремя путями, и каждый развивается в заметке [Планирование с языковыми моделями](/ru/notes/agents/planning-with-language-models).

- **Модель ставит задачу, планировщик ищет.** В LLM+P ([Liu et al., 2023](#references)) модель переводит задачу, сформулированную на естественном языке, в файл задачи PDDL, классический планировщик находит план, а модель переводит план обратно. Планировщик вносит гарантии этой заметки; модель вносит постановку — ту часть, которую людям трудно автоматизировать.
- **Модель — это функция потомков и эвристика.** Tree of Thoughts ([Yao et al., 2023](#references)) запускает поиск в ширину или в глубину по частичным решениям — «мыслям». Модель предлагает потомков узла и сама же оценивает, насколько многообещающ каждый из них, играя роль $h$. На «Игре 24» (Game of 24), где четыре числа нужно соединить арифметическими действиями так, чтобы получилось 24, GPT-4, которую просили рассуждать шаг за шагом, решила 4% тестовых задач, а та же модель внутри поиска в ширину, который на каждом шаге сохраняет пять лучших частичных решений, — 74% (собственный тестовый набор статьи из 100 трудных головоломок, 2023). Оценки модели не допустимы, поэтому приведённое выше рассуждение об оптимальности неприменимо; вместо этого поиск делает ошибки модели исправимыми.
- **Что-то должно проверять план.** Эвристика может ошибаться; проверка цели и предусловия каждого действия — нет. Системы, в которых модель предлагает, а внешний верификатор проверяет, — шаблон «LLM-Modulo» ([Kambhampati et al., 2024](#references)), — это вариант для планирования разделения между агентом и его средой.

Вернёт ли A\* по-прежнему S–A–D–G? (2) Почему максимум $\max(h_1, h_2)$ двух допустимых эвристик допустим и почему он доминирует над обеими? Поиск раскрывает S, затем B (f = 7), затем A (f = 7), при этом D теперь получает $f = 6 + 3 = 9$; следующим раскрывается C (f = 8), который кладёт на границу G с $f = 8$, и G раскрывается раньше D: A\* возвращает S–B–C–G стоимостью 8, не оптимальный путь. ## Что изменилось \{#what-changed\}

| | поиск в ширину | поиск по критерию стоимости | A\* |
| --- | --- | --- | --- |
| что раскрывает следующим | самый мелкий узел | наименьшее $g(n)$ | наименьшее $g(n) + h(n)$ |
| когда оптимален | все стоимости шагов равны | стоимости шагов не меньше $\varepsilon > 0$ | $h$ согласована (поиск в графе) или допустима (поиск в дереве) |
| проверка цели | при порождении | при раскрытии | при раскрытии |
| использует знание о цели | нет | нет | да, через $h$ |
| на сетке | достигнуто 139 состояний | раскрыто 136 клеток | раскрыто 80 клеток |

И переход от кода под конкретную задачу к планированию: факторизованное состояние из фактов, схемы действий с предусловиями, списками добавления и удаления, один общий поиск и эвристики, вычисленные по самому описанию.

## Ограничения \{#limitations\}

- **Память.** A\* хранит каждое достигнутое состояние. Время его работы может быть приемлемым, а память — нет; варианты вроде A\* с итеративным углублением (iterative-deepening A\*) обменивают время на память.
- **В конечном счёте экспоненциально.** Эвристика уменьшает показатель экспоненты, но редко устраняет её: когда ошибка эвристики растёт пропорционально истинной оставшейся стоимости, как у большинства практических эвристик, число узлов, которые раскрывает A\*, всё равно растёт экспоненциально с длиной решения.
- **Предположения сильны.** Полная наблюдаемость, детерминированность и известная модель редко встречаются за пределами головоломок, игр против природы и логистики. Когда исходы случайны, план должен ветвиться; это тема [следующей заметки](/ru/notes/agents/markov-decision-processes).
- **Постановку делают люди.** Пространство состояний, действия и стоимости даны; решить, что опустить, — самая трудная часть, и именно её теперь просят сделать языковую модель.
- **Языки планирования жёстки.** Классический STRIPS не может выразить время, ресурсы или неопределённость; расширения PDDL могут — ценой более трудного планирования.

## Что нужно запомнить \{#what-you-should-remember\}

- Задача поиска — это пространство состояний с начальным состоянием, проверкой цели, действиями, моделью переходов и стоимостями действий; решение — путь, оптимальное решение — самый дешёвый путь.
- Поиск в ширину оптимален только при равных стоимостях; поиск по критерию стоимости оптимален при положительных стоимостях и проверяет цель при раскрытии узла.
- A\* раскрывает узел с наименьшим $f = g + h$. При согласованной $h$ значение $f$ не убывает вдоль пути, каждый узел раскрывается с наименьшим $g$, и первая раскрытая цель оптимальна. Для поиска в дереве достаточно допустимости.
- Хорошие эвристики — точные стоимости ослабленных задач; доминирующая эвристика раскрывает меньше узлов. Умножение $h$ на вес $w > 1$ экономит работу ценой ухудшения стоимости не более чем в $w$ раз.
- STRIPS и PDDL описывают состояния как множества фактов, а действия — предусловиями, списками добавления и списками удаления; игнорирование списков удаления даёт эвристики для планирования. Планировщики на языковых моделях заново используют эти части: модель ставит задачу, предлагает или оценивает, а поиск или верификатор даёт гарантии.

## Код \{#code\}

Поиск по первому наилучшему с $f = g + w\, h$ (поиск по критерию стоимости, A\* и взвешенный A\*) на графе разобранного примера и на сетке, поиск в ширину на сетке и планировщик STRIPS для мира блоков. Только NumPy и стандартная библиотека; скрипт работает гораздо быстрее секунды и не содержит случайности.

```python
import heapq, itertools
from collections import deque
from math import comb, factorial
import numpy as np

# 1. поиск по первому наилучшему: f = g + w h. w = 0 — поиск по критерию стоимости, w = 1 — A*, w > 1 — взвешенный A*
def best_first(start, goal, neighbours, h, w=1.0):
    tie = itertools.count()
    frontier = [(w * h(start), 0, next(tie), start)]          # (f, -g, порядок вставки, состояние): при равенстве — более глубокий узел
    g, parent, closed = {start: 0}, {start: None}, []
    while frontier:
        f, _, _, n = heapq.heappop(frontier)
        if n in closed: continue                               # устаревшая запись: n уже был достигнут дешевле
        closed.append(n)
        if n == goal:                                          # проверка цели — при раскрытии
            path = [n]
            while parent[path[-1]] is not None: path.append(parent[path[-1]])
            return path[::-1], g[n], closed
        for m, cost in neighbours(n):
            if m not in closed and g[n] + cost < g.get(m, np.inf):
                g[m], parent[m] = g[n] + cost, n
                heapq.heappush(frontier, (g[m] + w * h(m), -g[m], next(tie), m))
    return None, np.inf, closed

# 2. граф разобранного примера с согласованной эвристикой
edges = {('S','A'): 2, ('S','B'): 3, ('A','C'): 3, ('B','C'): 1, ('A','D'): 4, ('C','G'): 4, ('D','G'): 1, ('B','E'): 2, ('E','G'): 6}
adj = {}
for (u, v), c in edges.items():
    adj.setdefault(u, []).append((v, c)); adj.setdefault(v, []).append((u, c))
H = dict(S=6, A=5, B=4, C=4, D=1, E=5, G=0)
assert all(H[u] <= c + H[v] and H[v] <= c + H[u] for (u, v), c in edges.items())   # согласована
for w in (0, 1):
    path, cost, closed = best_first('S', 'G', lambda n: adj[n], H.get, w)
    print(w, path, cost, ''.join(closed))
# 0 ['S', 'A', 'D', 'G'] 7 SABCEDG
# 1 ['S', 'A', 'D', 'G'] 7 SBADG

# 3. сетка со стенами: 4 хода стоимостью 1, эвристика — манхэттенское расстояние
MAP = ["................",
       "...........#....",
       ".....####..#....",
       "........#..#....",
       "........#..#....",
       ".S......#..#..G.",
       "........#..#....",
       "........#.......",
       ".....####.......",
       "................"]
wall = np.array([[ch == '#' for ch in row] for row in MAP])
S = next((r, c) for r, row in enumerate(MAP) for c, ch in enumerate(row) if ch == 'S')
T = next((r, c) for r, row in enumerate(MAP) for c, ch in enumerate(row) if ch == 'G')
def grid_neighbours(n):
    for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
        r, c = n[0] + dr, n[1] + dc
        if 0 <= r < wall.shape[0] and 0 <= c < wall.shape[1] and not wall[r, c]:
            yield (r, c), 1
manhattan = lambda n: abs(n[0] - T[0]) + abs(n[1] - T[1])
for w in (0, 0.5, 1, 1.5, 2, 3, 5):
    path, cost, closed = best_first(S, T, grid_neighbours, manhattan, w)
    print(w, cost, len(closed), end=' | ')
print()
# 0 21 136 | 0.5 21 123 | 1 21 80 | 1.5 23 75 | 2 25 68 | 3 25 65 | 5 25 60     (w, стоимость пути, раскрыто клеток)

def bfs(start, goal, neighbours):                              # здесь оптимален: каждый шаг стоит 1
    depth, queue = {start: 0}, deque([start])
    while queue:
        n = queue.popleft()
        if n == goal: return depth[n], len(depth)
        for m, _ in neighbours(n):
            if m not in depth: depth[m] = depth[n] + 1; queue.append(m)
print(bfs(S, T, grid_neighbours))                              # (21, 139): длина пути, достигнуто состояний

# 4. STRIPS: состояние — множество фактов; у действия есть предусловия, список добавления и список удаления
blocks = 'ABC'
def actions():
    for x, y, z in itertools.permutations(blocks + 'T', 3):    # переставить блок x с y на z; T — стол
        if x == 'T': continue
        pre = {f'on {x} {y}', f'clear {x}'} | ({f'clear {z}'} if z != 'T' else set())
        add = {f'on {x} {z}'} | ({f'clear {y}'} if y != 'T' else set())
        dele = {f'on {x} {y}'} | ({f'clear {z}'} if z != 'T' else set())
        yield f'move({x},{y},{z})', frozenset(pre), frozenset(add), frozenset(dele)
ACTIONS = list(actions())
init = frozenset({'on C A', 'on A T', 'on B T', 'clear C', 'clear B'})   # C стоит на A; A и B на столе
goal = {'on A B', 'on B C'}
def plan_bfs(init, goal):
    parent, queue = {init: None}, deque([init])
    while queue:
        s = queue.popleft()
        if goal <= s:
            plan = []
            while parent[s]: s, a = parent[s]; plan.append(a)
            return plan[::-1], len(parent)
        for name, pre, add, dele in ACTIONS:
            if pre <= s:                                       # применимо: Pre(a) — подмножество s
                t = (s - dele) | add                           # Result(s, a) = (s без Del(a)) объединить с Add(a)
                if t not in parent: parent[t] = (s, name); queue.append(t)
print(len(ACTIONS), plan_bfs(init, goal))
# 18 (['move(C,A,T)', 'move(B,T,C)', 'move(A,T,B)'], 13)

# число состояний мира блоков: способы разложить n помеченных блоков по стопкам
print([sum(factorial(n) // factorial(k) * comb(n - 1, k - 1) for k in range(1, n + 1)) for n in (3, 5, 10)])
# [13, 501, 58941091]
```

## Дальше \{#next\}

Поиск предполагал, что у каждого действия один известный исход, так что план — фиксированная последовательность, которую можно выполнить с закрытыми глазами. В большинстве миров, с которыми сталкиваются агенты, действие может не удаться или иметь несколько исходов, и агент должен решить, что делать в каждом состоянии, в котором он может оказаться, взвешивая исходы по их вероятностям и наградам, приходящим со временем. [Следующая заметка](/ru/notes/agents/markov-decision-processes) ставит эту задачу как марковский процесс принятия решений и решает её с помощью уравнений Беллмана.
