Две предыдущие заметки дали стратегии две способности по отдельности. [Цепочка рассуждений](/ru/notes/agents/chain-of-thought) позволяет ей вычислять до ответа, но только с тем, что она уже знает. [Использование инструментов](/ru/notes/agents/tool-use-and-function-calling) позволяет ей добывать информацию и действовать, но ничего не говорит о том, как решить, какой вызов сделать следующим и что извлечь из результата. Агенту нужно и то, и другое в одном цикле: он рассуждает о том, что увидел, действует, читает наблюдение и снова рассуждает. Курс NLP показал этот шаблон в [первом цикле агента](/ru/notes/nlp/tools-and-agents#agents-a-loop-around-tool-calls). Эта заметка строит его тщательно. Она излагает постановку ReAct и то, что в ней было измерено в сравнении с одним действием и одним рассуждением, разбирает полную трассу (trace), а затем переходит к вопросам, на которые должен ответить любой цикл: когда остановиться, как вырваться из зацикливания, как восстановиться после неудачного шага, когда планировать всё заранее и сколько стоит цикл по мере роста контекста.

**Обозначения.** $\mathcal A$ — множество действий в среде, $\mathcal L$ — множество строк языка. Контекст $c_t$ — это инструкции, примеры, вопрос и каждая прошлая мысль, действие и наблюдение. Шаг пишет $\hat a_t \in \hat{\mathcal A} = \mathcal A \cup \mathcal L$. $T_{\max}$ — бюджет шагов. В модели затрат $L_t$ — число токенов, которые модель читает на шаге $t$, $s$ — токены до первого шага (инструкции, определения инструментов, примеры и задача), $u$ — токены, которые модель пишет за шаг (мысль и действие), $o$ — токены одного наблюдения, и $d = u + o$.

## Отправная точка: только действовать или только рассуждать \{#baseline-acting-alone-or-reasoning-alone\}

Две более простые стратегии не справляются противоположным образом.

**Только действие** (act only). Модели дают промпт с примерами траекторий «действие — наблюдение», и она пишет одно действие за другим. Она может добывать информацию, но ей негде записать, что она узнала, что ещё осталось найти и почему последний поиск не удался. На вопросе, которому нужны факты с двух страниц, ей приходится держать план неявно, в самой последовательности действий.

**Только рассуждение** (reason only). Модель пишет цепочку рассуждений и отвечает по памяти. Она хорошо планирует и свободно выдумывает: ничто вне модели не проверяет факты, на которые опирается её цепочка.

Yao et al. ([2023](#references)) сравнили обе стратегии с их сочетанием на двух задачах, требующих знаний, дав PaLM-540B промпт с шестью примерами для HotpotQA (вопросы, которым нужны две страницы Википедии) и тремя для FEVER (утверждения, которые нужно проверить); агент действовал через интерфейс Википедии:

| метод | HotpotQA, точное совпадение | FEVER, доля правильных ответов |
| --- | --- | --- |
| стандартный промпт | 28.7 | 57.1 |
| только рассуждение: цепочка рассуждений | 29.4 | 56.3 |
| только рассуждение: цепочка рассуждений с самосогласованностью | 33.4 | 60.4 |
| только действие | 25.7 | 58.9 |
| ReAct | 27.4 | 60.9 |
| цепочка рассуждений с самосогласованностью, затем ReAct | 34.2 | 64.6 |
| ReAct, затем цепочка рассуждений с самосогласованностью | 35.1 | 62.0 |

ReAct обошёл одно действие на обеих задачах. В сравнении с одним рассуждением результат оказался смешанным: лучше на FEVER, немного хуже на HotpotQA. Лучшие результаты дало сочетание обоих методов, что объясняет анализ ошибок ниже. Системы того времени, обученные с учителем, набирали 67.5 и 89.5 — намного больше всех методов на промптах.

<aside class="callout"><strong>Ключевая идея.</strong> Пространство действий стратегии включает мысли: текст, который меняет только контекст, а не среду. Мысль не стоит шага среды, но меняет то, что стоит в условии следующего действия. Если чередовать мысль, действие и наблюдение, стратегия может разложить задачу на части, прочитать каждое наблюдение, следить за своим продвижением и реагировать на неожиданности, а каждый факт, которым она пользуется, приходит из среды.</aside>

## ReAct: мысли как действия \{#react-thoughts-as-actions\}

ReAct ([Yao et al., 2023](#references)) расширяет пространство действий до $\hat{\mathcal A} = \mathcal A \cup \mathcal L$. На каждом шаге стратегия пишет $\hat a_t \sim \pi(\cdot \mid c_t)$, и контекст растёт одним из двух способов:

$$
\boxed{\;c_{t+1} = \begin{cases} (c_t,\, \hat a_t) & \text{если } \hat a_t \in \mathcal L \quad \text{(мысль: наблюдения нет)}, \\ (c_t,\, \hat a_t,\, o_{t+1}) & \text{если } \hat a_t \in \mathcal A \quad \text{(действие: среда отвечает)}. \end{cases}\;}
$$

Мысль — действие, которое влияет только на собственный контекст агента: контекст — память агента, а мысль — запись в неё. Среда остаётся нетронутой, поэтому мысль никогда не может оказаться ошибочной так, как может действие, но может оказаться ошибочной как рассуждение, а её читает каждый следующий шаг.

Для задач, требующих знаний, в $\mathcal A$ было три действия: `search[entity]` возвращает первые пять предложений страницы Википедии о сущности или пять похожих заголовков, если страницы с таким названием нет; `lookup[string]` возвращает следующее предложение текущей страницы, содержащее строку, как Ctrl+F в браузере; `finish[answer]` завершает эпизод. Примеры в промпте были написанными людьми траекториями, в которых мысли выполняют несколько задач: раскладывают вопрос на части, извлекают нужный факт из наблюдения, отмечают, что известно и чего ещё не хватает, переформулируют неудачный поиск и решают, что ответ готов. В задачах, требующих знаний, перед каждым действием стоит мысль — *плотные* (dense) мысли. Для задач принятия решений со многими шагами примеры ставили мысли только там, где они важны, — *разреженные* (sparse) мысли, и модель сама решала, когда её написать.

<ReActLoop />

1. **Чтение.** Модель читает контекст $c_t$: инструкции, примеры траекторий, вопрос и каждый прошлый шаг.
2. **Мысль.** Она пишет мысль, которая добавляется в контекст. Среда не вызывается.
3. **Действие.** Она пишет действие, например `search[Dunmore]`.
4. **Проверка.** Среда выполнения (runtime) разбирает действие и применяет правила остановки: действие `finish`, исчерпанный бюджет шагов, вызов, повторённый с тем же результатом.
5. **Наблюдение.** Инструмент выполняется, и его наблюдение добавляется в контекст. Цикл возвращается к шагу 1.

### Что показывает анализ ошибок \{#what-the-error-analysis-shows\}

Авторы вручную разметили 200 траекторий HotpotQA — по 50 правильных и 50 неправильных от ReAct и от цепочки рассуждений ([Yao et al., 2023](#references), таблица 2). Среди неудач цепочки рассуждений 56% составили выдуманные факты или рассуждения, а среди неудач ReAct — 0%. Неудачи ReAct были другого рода: 47% — ошибки рассуждения, включая застревание на повторении одной и той же мысли и одного и того же действия, и 23% — поиски, которые не вернули ничего полезного, после чего модель не смогла вернуться на правильный путь. Среди успехов 14% правильных ответов цепочки рассуждений опирались на выдуманную трассу против 6% у ReAct.

Два метода ошибаются взаимодополняющим образом, поэтому их сочетание и сработало лучше всего. *ReAct, затем цепочка рассуждений с самосогласованностью* переходит к 21 сэмплированной цепочке рассуждений с голосованием при температуре 0.7, когда ReAct не ответил за 7 шагов на HotpotQA или за 5 на FEVER. *Самосогласованность, затем ReAct* переключается на ReAct, когда самый частый из 21 ответа получил меньше половины голосов, — признак того, что собственные знания модели ненадёжны.

### Задачи принятия решений и дообучение \{#decision-making-tasks-and-fine-tuning\}

В ALFWorld, текстовых играх, в которых агент должен выполнить бытовые задачи вроде того, чтобы положить куда-нибудь вымытый предмет, ReAct с разреженными мыслями добился успеха в 71% из 134 игр, не встречавшихся при обучении, с лучшим из шести промптов и в 57% в среднем по ним против 45% у одного действия с его лучшим промптом и 37% у BUTLER — агента, обученного подражанием на экспертных траекториях. В WebShop, где нужно найти и купить в симулированном интернет-магазине товар, соответствующий запросу, ReAct справился с 40.0% задач против 30.1% у одного действия и 28.7% у модели, обученной подражанием и обучением с подкреплением; люди-эксперты достигли 59.6%. Все эти результаты на промптах получены с PaLM-540B. Дообучение на 3000 траекторий ReAct с правильными ответами изменило картину масштаба: дообученная PaLM-8B обошла все методы на промптах с PaLM-62B, а дообученная PaLM-62B — все методы на промптах с PaLM-540B на HotpotQA. Современные модели для агентов по умолчанию обучают на таких траекториях.

## Полная трасса \{#a-complete-trace\}

Раздел «Код» запускает цикл на игрушечной базе знаний из пяти страниц о вымышленной речной долине с инструментами `search`, `lookup` и `calculate` под управлением заскриптованной стратегии. Вопрос: *How many years after the founding of the town on the Kessa River was its old mill built?* («Через сколько лет после основания города на реке Кесса была построена его старая мельница?») Запуск занимает семь шагов.

```
Thought 1: I need the town on the Kessa River, the year it was founded and the year its old mill was built.
Action 1: search[Kessa River]
Observation 1: The Kessa River is a river of the northern valley. It is 412 km long. It flows through the town of Dunmore before it reaches the sea.
Thought 2: The town is Dunmore. Next, when it was founded.
Action 2: search[Dunmore]
Observation 2: Dunmore is a market town in the northern valley. It lies on the Kessa River. It is known for its wool trade.
Thought 3: The first sentences do not give the founding year; look it up in the page.
Action 3: lookup[founded]
Observation 3: (Result 1 / 1) Dunmore was founded in 1312 by a charter of the duke.
Thought 4: Dunmore was founded in 1312. Now the old mill.
Action 4: search[Old Mill]
Observation 4: Could not find Old Mill. Similar: ['Old Mill of Dunmore', 'Old Harbour', 'Kessa River'].
Thought 5: There is no page Old Mill, but Old Mill of Dunmore is suggested; that is the mill of Dunmore.
Action 5: search[Old Mill of Dunmore]
Observation 5: The Old Mill of Dunmore is a watermill on the Kessa River. It was built in 1561. It ground grain until 1950.
Thought 6: The mill was built in 1561 and Dunmore was founded in 1312.
Action 6: calculate[1561 - 1312]
Observation 6: 249
Thought 7: The mill was built 249 years after the town was founded.
Action 7: finish[249]
```

Шаг за шагом:

1. **Декомпозиция.** Первая мысль превращает один вопрос в три факта, которые нужно найти, в таком порядке, что каждый зависит от предыдущего: город, затем год его основания, затем мельница.
2. **Извлечение.** Наблюдение — три предложения текста; мысль вытаскивает из него единственный нужный факт, название *Dunmore*, и формулирует следующую подцель.
3. **Смена инструмента.** Года основания в первых предложениях нет. Мысль замечает пробел, и действие переключается с `search` на `lookup` внутри открытой страницы.
4. **Отслеживание продвижения.** Мысль записывает 1312, и это число теперь остаётся в контексте до конца эпизода, и переходит к последней подцели. Поиск не удаётся.
5. **Восстановление.** Неудача — такое же наблюдение, как любое другое. В ней перечислены похожие заголовки, и мысль выбирает тот, что соответствует городу, используя факт из шага 2.
6. **Вычисление.** Мысль собирает оба года; арифметика уходит инструменту, а не делается «в уме» модели.
7. **Остановка.** Ответ готов, и стратегия сама завершает эпизод.

Мысли несут состояние задачи: какие факты известны, какой нужен следующим, почему поиск не удался. Стратегии, которая только действует, пришлось бы на каждом шаге выводить всё это из сырой последовательности действий и наблюдений. Контекст, который читает модель, вырос с 78 до 387 токенов по грубому подсчёту из кода — примерно на 50 за шаг; раздел о стоимости ниже прослеживает этот рост.

## Остановка, бюджеты и циклы \{#stopping-budgets-and-loops\}

Циклу нужны правила завершения, которые не зависят только от суждения модели.

- **Завершающее действие.** Модель заканчивает эпизод действием `finish[answer]` или ответом без вызова. Это единственное успешное завершение.
- **Бюджет шагов** $T_{\max}$. ReAct использовал 7 шагов на HotpotQA и 5 на FEVER, прежде чем перейти к цепочке рассуждений. Бюджет лучше всего выбирать по успешным запускам: если успешные запуски задачи в 95% случаев занимают не больше 9 шагов, бюджет около 12 останавливает убегающие запуски и отсекает немного хороших.
- **Бюджеты токенов, стоимости и времени** — по той же причине, ведь шаги различаются по длине.
- **Повтор.** Одно и то же действие, возвращающее одно и то же наблюдение, означает отсутствие продвижения. Среда выполнения может точно обнаружить повтор, отметить его в наблюдении и остановить запуск, когда он случится снова.
- **Нет продвижения.** Более слабый сигнал, например много шагов без нового факта или изменённого файла, может запустить остановку или просьбу о помощи.

**Почему возникают циклы.** При нулевой температуре стратегия — детерминированная функция своего контекста. Если действие не удалось, а наблюдение мало что добавило к контексту, следующий контекст почти такой же, как предыдущий, и следующее действие тоже. Агент приходит в неподвижную точку: тот же поиск, та же неудача, та же мысль. Авторы ReAct связали этот сбой с жадным декодированием. Изменение контекста разрывает цикл, поэтому пометка вроде *Repeated action with the same result: try something else* («повторное действие с тем же результатом: нужно попробовать что-то другое») работает там, где молчаливый повтор не помогает. В разделе «Код» стратегия, которая один раз повторяет неудачный поиск, получает пометку на второй попытке, следует подсказке на третьей и заканчивает за 8 шагов вместо 7. Когда нужной ей страницы не существует, стратегия чередует два поиска, среда выполнения замечает второй повтор и останавливает запуск после 6 шагов; при бюджете 4 исходная задача останавливается раньше, чем появляется ответ.

Когда бюджет исчерпан, у цикла есть три честных варианта: вернуть лучший частичный ответ с пометкой, что он неполон, перейти к другому методу (как ReAct переходит к самосогласованности) или спросить пользователя. Вернуть догадку так, как будто это ответ, — не из их числа.

## Восстановление после ошибок \{#error-recovery\}

Курс NLP отмечает, что надёжность перемножается: при десяти шагах, каждый из которых должен удаться с вероятностью $0.95$, задача удаётся с вероятностью $0.95^{10} = 0.599$ ([Использование инструментов и агенты](/ru/notes/nlp/tools-and-agents#limitations)). Восстановление меняет эту арифметику. Пусть шаг идёт не так с вероятностью $e$, а неверный шаг замечается и исправляется с вероятностью $\rho$ ценой одного дополнительного шага. Тогда шаг окончательно проваливается с вероятностью $e(1 - \rho)$:

$$
\begin{aligned}
P(\text{успех}) &= \big(1 - e\,(1 - \rho)\big)^{n}, \\
e = 0.05,\ \rho = 0.6,\ n = 10: \quad P(\text{успех}) &= 0.98^{10} = 0.817 \quad \text{вместо } 0.599, \\
\mathbb E[\text{лишние шаги}] &= n\,e\,\rho = 10 \times 0.05 \times 0.6 = 0.3 .
\end{aligned}
$$

Восстановление стоит гораздо больше, чем обходится в шагах, и бо́льшую его часть дают несколько механизмов.

- **Информативные наблюдения.** Неудачный поиск, который перечисляет похожие заголовки, ошибка проверки, которая называет допустимые значения ([Использование инструментов и вызов функций](/ru/notes/agents/tool-use-and-function-calling#errors-and-retries)), упавший тест с трассировкой стека. Наблюдение — единственное свидетельство агента о том, что что-то пошло не так.
- **Мысли, которые читают неудачу.** Шаг 5 трассы — это восстановление: мысль истолковывает неудачу и выбирает другое действие.
- **Переход к запасному методу** (fallback), когда цикл застревает, как в сочетании ReAct с самосогласованностью.
- **Перепланирование и рефлексия.** Пересмотр плана, когда наблюдение ему противоречит, и запись после неудачной попытки того, что пошло не так, для следующей попытки — темы заметок [Планирование с языковыми моделями](/ru/notes/agents/planning-with-language-models) и [Рефлексия и самокоррекция](/ru/notes/agents/reflection-and-self-correction).

Восстановление зависит от того, замечена ли ошибка. Неверный, но правдоподобно выглядящий шаг, например правдоподобное число, прочитанное не с той страницы, никогда не исправляется, и на практике это обычный случай.

## Сначала план, потом выполнение \{#plan-first-then-execute\}

ReAct решает по одному шагу за раз, и каждый шаг перечитывает весь контекст. Альтернатива — спланировать всё заранее. В схемах **«сначала план, потом выполнение»** (plan-and-execute) вызов-планировщик пишет всю последовательность вызовов инструментов с заполнителями для результатов, которые используют последующие вызовы; исполнители выполняют вызовы, не обращаясь к модели; а последний вызов составляет ответ из результатов. Так устроен ReWOO ([Xu et al., 2023](#references)), в котором переменные свидетельств `#E1`, `#E2` обозначают результаты. На HotpotQA с `gpt-3.5-turbo` он достиг доли правильных ответов 42.4% при 1986 токенах на вопрос против 40.8% при 9795 токенах у ReAct: примерно в пять раз меньше токенов, потому что модель вызывается для плана и для ответа, а не на каждом шаге. Аналог на уровне промпта, plan-and-solve ([Wang et al., 2023](#references)), просит модель в одной цепочке рассуждений сначала составить план, а затем выполнить его шаг за шагом.

Цена — адаптивность. План, написанный до любого наблюдения, не может отреагировать на неожиданность, такую как неудачный поиск в шаге 4 трассы, если в схему не добавлен шаг перепланирования на случай, когда результата нет или он неожиданный. «Сначала план, потом выполнение» подходит задачам, структура которых известна заранее и инструменты которых редко отказывают; пошаговый цикл подходит для исследования. Сторону планирования развивает заметка [Планирование с языковыми моделями](/ru/notes/agents/planning-with-language-models).

## Стоимость и задержка цикла \{#the-cost-and-latency-of-a-loop\}

Каждый шаг заново отправляет модели весь контекст. В обозначениях заметки [Контекст и память](/ru/notes/agents/context-and-memory) до первого шага идут $s$ токенов, а каждый шаг добавляет $d = u + o$ токенов: $u$ пишет модель — свои мысль и действие, — и $o$ приходится на наблюдение. На шаге $t$ модель читает $L_t = s + (t - 1)\,d$ токенов, а за $T$ шагов

$$
\boxed{\;\sum_{t=1}^{T} L_t = T s + d\,\frac{T(T - 1)}{2}\;}
$$

входных токенов, при том что пишет она только $T u$. Первое слагаемое растёт линейно с числом шагов, второе — квадратично; второе обгоняет первое, как только $T - 1 > 2s / d$. Разбиение $d$ важно, потому что две части стоят по-разному: написанные токены генерируются по одному и стоят дороже, а токены наблюдений только читаются.

**Разобранный пример.** Возьмём $s = 2\,000$ токенов инструкций, определений инструментов и задачи, $u = 80$ токенов мысли и действия и $o = 220$ токенов наблюдения на шаг, так что $d = 300$. Квадратичное слагаемое обгоняет линейное после $1 + 4\,000 / 300 = 14.3$ шага.

- **10 шагов.** Последний шаг читает $L_{10} = 2\,000 + 9 \times 300 = 4\,700$ токенов. Всего модель читает $10 \times 2\,000 + 300 \times 45 = 33\,500$ токенов и пишет $800$.
- **40 шагов.** Последний шаг читает $13\,700$ токенов, а сумма равна $40 \times 2\,000 + 300 \times 780 = 314\,000$ прочитанных токенов на $3\,200$ написанных: почти сто прочитанных токенов на каждый написанный.

По иллюстративным ценам 3 доллара за миллион входных токенов и 15 за миллион выходных запуск из 10 шагов стоит $0.1005 + 0.012 = 0.11$ доллара, а запуск из 40 шагов — $0.94 + 0.05 = 0.99$ доллара: вчетверо больше шагов, в девять раз больше стоимость. Кэширование промпта (prompt caching) берёт за повторяющийся префикс долю цены; если чтение из кэша стоит десятую часть, а новые токены — полную цену, запуск из 40 шагов стоит $0.18$ доллара вместо $0.99$. Заметка [Контекст и память](/ru/notes/agents/context-and-memory#prompt-caching-as-economics) выводит общую формулу с ценой записи в кэш и разбирает, что делает кэш недействительным.

**Задержка** складывается по шагам. При иллюстративной скорости предзаполнения (prefill) 5000 токенов в секунду, генерации 50 токенов в секунду и половине секунды на вызов инструмента шаг $t$ занимает $L_t / 5\,000 + 80 / 50 + 0.5$ секунды. Запуск из 10 шагов занимает $33\,500 / 5\,000 + 10 \times 2.1 = 27.7$ секунды; если кэшированный префикс не вычисляется заново — $21.9$. Здесь преобладают генерация и инструменты, и кэширование их не сокращает; их сокращают меньшее число шагов, параллельные вызовы и более короткие мысли.

<ContextGrowth />

Два следствия определяют следующие заметки. Контекст не может расти без предела: при 300 токенах на шаг окно в 128 000 токенов заполняется примерно за 420 шагов — задолго до конца многих задач программирования, а информацией в середине длинного контекста модели пользуются менее надёжно, чем в его начале или конце ([Liu et al., 2024](#references); [Контекст и память](/ru/notes/agents/context-and-memory#why-order-matters-lost-in-the-middle)). И стоимость шага растёт на протяжении эпизода, поэтому длинным задачам нужно, чтобы контекст сокращался, урезался или переносился во внешнюю память, — это тема следующей заметки.

## Что изменилось \{#what-changed\}

| | только действие | только рассуждение | ReAct |
| --- | --- | --- | --- |
| пространство действий | $\mathcal A$ | $\mathcal L$, затем ответ | $\mathcal A \cup \mathcal L$ |
| источник фактов | среда | память модели | среда |
| где живёт план | неявно в действиях | в цепочке | в мыслях, пересматриваемых по наблюдениям |
| типичный сбой | теряет нить, не может истолковать результаты | выдуманные факты | ошибки рассуждения, циклы, бесполезные поиски |
| что можно проверить | действия | цепочку | всю траекторию |
| стоимость шага | один вызов | один вызов на всё | один вызов на шаг на растущем контексте |

## Ограничения \{#limitations\}

- **Мысли могут быть ошибочными, и им верят.** Их читает каждый следующий шаг; ошибочная мысль в начале траектории направляет всё остальное, а, как показала предыдущая заметка, мысль не обязана отражать то, что определило действие.
- **Циклы и застревание.** Детерминированное декодирование и неинформативные наблюдения порождают зацикливание, которое может разорвать только среда выполнения.
- **Контекст растёт с каждым шагом.** Без кэширования стоимость растёт квадратично с числом шагов, и окно в конце концов заполняется.
- **Жадно, по одному шагу.** ReAct не планирует вперёд и не возвращается назад иначе как новыми мыслями; поиск по траекториям — другая схема.
- **Результаты зависят от интерфейса.** Одна и та же модель набирает разные результаты с инструментом поиска, который возвращает пять предложений или целую страницу, и числа бенчмарков плохо переносятся между реализациями инструментов.
- **ReAct на промптах слабее обученного ReAct.** Результаты дообучения показывают, что небольшая модель, обученная на траекториях, обходит большую модель с промптом из нескольких примеров; агентов теперь обучают, а не только дают им промпты.

## Что нужно запомнить \{#what-you-should-remember\}

- ReAct добавляет мысли в пространство действий: $\hat{\mathcal A} = \mathcal A \cup \mathcal L$. Мысль только расширяет контекст; действие ещё и возвращает наблюдение.
- По сравнению с одним действием мысли раскладывают задачу на части, извлекают факты из наблюдений, отслеживают продвижение и справляются с неудачами. По сравнению с одним рассуждением каждый факт приходит из среды: в анализе ошибок ReAct выдумки стали причиной 56% неудач цепочки рассуждений и ни одной неудачи ReAct.
- С PaLM-540B на промптах: HotpotQA — 27.4 (ReAct) против 29.4 (цепочка рассуждений) и 25.7 (только действие); FEVER — 60.9 против 56.3 и 58.9; ALFWorld — 71% против 45% у одного действия (лучший из шести промптов); сочетание ReAct с самосогласованностью дало лучшие результаты.
- Останавливаться на завершающем действии, по бюджету шагов, бюджетам токенов, стоимости или времени и при точном повторе; отмечать повтор в наблюдении, чтобы изменить контекст, и останавливаться, когда он повторяется снова.
- Восстановление умножает надёжность: $(1 - e(1 - \rho))^n$ вместо $(1 - e)^n$. Ему нужны информативные наблюдения и мысли, которые их читают.
- «Сначала план, потом выполнение» пишет все вызовы заранее и экономит токены (ReWOO: примерно в пять раз меньше на HotpotQA) ценой того, что на неожиданности оно реагирует только перепланированием.
- Цикл читает $T s + d\, T(T-1)/2$ входных токенов за $T$ шагов и пишет только $T u$; кэширование промпта дёшево берёт за повторяющийся префикс; задержку определяют генерация и инструменты.

## Код \{#code\}

Полный цикл ReAct над игрушечной базой знаний из пяти страниц с инструментами `search`, `lookup` и `calculate`, парсером действий вида `tool[argument]`, бюджетом шагов и проверкой повторов, под управлением заскриптованной стратегии, которая читает свой контекст регулярными выражениями и пишет мысль и действие. Последняя часть вычисляет модель затрат из разобранного примера. С настоящей моделью `toy_policy` становится вызовом модели с контекстом в качестве промпта и стоп-последовательностью после строки действия; среда, парсер, правила остановки и учёт токенов остаются как есть. В скрипте нет случайности, и он работает за доли секунды.

```python
import ast, operator, re

# 1. среда: игрушечная база знаний с поиском, просмотром страницы и калькулятором
PAGES = {
    'Kessa River': 'The Kessa River is a river of the northern valley. It is 412 km long. It flows through the town of '
                   'Dunmore before it reaches the sea. Its main tributary is the Brann. It freezes in most winters.',
    'Dunmore': 'Dunmore is a market town in the northern valley. It lies on the Kessa River. It is known for its wool '
               'trade. Its population was 18,400 in 2020. Dunmore was founded in 1312 by a charter of the duke.',
    'Old Mill of Dunmore': 'The Old Mill of Dunmore is a watermill on the Kessa River. It was built in 1561. '
                           'It ground grain until 1950. Today it is a museum.',
    'Brann': 'The Brann is a river of the northern valley and a tributary of the Kessa River.',
    'Old Harbour': 'The Old Harbour is the port at the mouth of the Kessa River.',
}
OPS = {ast.Add: operator.add, ast.Sub: operator.sub, ast.Mult: operator.mul, ast.Div: operator.truediv}
def arith(n):
    if isinstance(n, ast.Constant) and isinstance(n.value, (int, float)): return n.value
    if isinstance(n, ast.BinOp) and type(n.op) in OPS: return OPS[type(n.op)](arith(n.left), arith(n.right))
    raise ValueError('only numbers and + - * /')

class KnowledgeBase:
    def __init__(self, pages): self.pages, self.page, self.hits = pages, None, []
    def sentences(self, title): return re.findall(r'[^.]+\.', self.pages[title])
    def step(self, tool, arg):
        if tool == 'search':
            if arg in self.pages:
                self.page = arg
                return ' '.join(s.strip() for s in self.sentences(arg)[:3])      # первые три предложения
            words = set(arg.lower().split())
            similar = sorted(self.pages, key=lambda t: -len(words & set(t.lower().split())))[:3]
            return f'Could not find {arg}. Similar: {similar}.'
        if tool == 'lookup':
            if self.page is None: return 'No page is open.'
            hits = [s.strip() for s in self.sentences(self.page) if arg.lower() in s.lower()]
            return f'(Result 1 / {len(hits)}) {hits[0]}' if hits else 'No more results.'
        if tool == 'calculate':
            try: return str(arith(ast.parse(arg, mode='eval').body))
            except (SyntaxError, ValueError) as e: return f'Error: {e}'
        return f'Unknown action {tool}.'

# 2. заскриптованная замена модели: она читает свой контекст и пишет мысль и действие
QUESTION = 'How many years after the founding of the town on the Kessa River was its old mill built?'
def toy_policy(context, stubborn=False):
    obs = re.findall(r'Observation \d+: (.*)', context)
    last = obs[-1] if obs else ''
    town = re.search(r'flows through the town of (\w+)', context)
    founded = re.search(r'founded in (\d{4})', context)
    built = re.search(r'built in (\d{4})', context)
    if not obs:
        return 'I need the town on the Kessa River, the year it was founded and the year its old mill was built.', 'search[Kessa River]'
    if last.startswith('Could not find'):
        if stubborn and 'Repeated' not in context:                  # жадное декодирование, неизменный контекст: снова то же действие
            return 'Let me search for the old mill.', 'search[Old Mill]'
        title = next(t for t in re.findall(r"'([^']+)'", last) if town.group(1) in t)
        return f'There is no page Old Mill, but {title} is suggested; that is the mill of {town.group(1)}.', f'search[{title}]'
    if built and founded:
        if re.fullmatch(r'\d+', last):
            return f'The mill was built {last} years after the town was founded.', f'finish[{last}]'
        return f'The mill was built in {built.group(1)} and {town.group(1)} was founded in {founded.group(1)}.', \
               f'calculate[{built.group(1)} - {founded.group(1)}]'
    if founded:
        return f'{town.group(1)} was founded in {founded.group(1)}. Now the old mill.', 'search[Old Mill]'
    if town and town.group(1) in PAGES and f'{town.group(1)} is' in last:
        return 'The first sentences do not give the founding year; look it up in the page.', 'lookup[founded]'
    if town:
        return f'The town is {town.group(1)}. Next, when it was founded.', f'search[{town.group(1)}]'
    return 'I am stuck.', 'finish[unknown]'

# 3. цикл: разобрать, действовать, наблюдать, дописать; остановиться на finish, по бюджету шагов или при повторе действия
def tokens(text): return len(re.findall(r'\w+|[^\w\s]', text))       # грубый подсчёт токенов
SYSTEM = ('Answer the question by interleaving Thought, Action and Observation steps. Actions: search[entity] returns '
          'the first sentences of a page, lookup[keyword] the next sentence of the open page that contains the keyword, '
          'calculate[expression] does arithmetic, finish[answer] ends the task.')

def react(question, pages, max_steps=8, max_repeats=2, stubborn=False):
    env, context, seen, sizes, repeats = KnowledgeBase(pages), f'{SYSTEM}\nQuestion: {question}\n', set(), [], 0
    for t in range(1, max_steps + 1):
        sizes.append(tokens(context))                                 # то, что модель читает на этом шаге
        thought, action = toy_policy(context, stubborn)
        m = re.fullmatch(r'(\w+)\[(.*)\]', action)
        if m is None:
            obs = 'Invalid action; write tool[argument].'
        elif m.group(1) == 'finish':
            context += f'Thought {t}: {thought}\nAction {t}: {action}\n'
            return m.group(2), t, 'finish', context, sizes
        else:
            obs = env.step(m.group(1), m.group(2))
            if (action, obs) in seen:                                 # тот же вызов с тем же результатом
                repeats += 1
                if repeats == max_repeats: return None, t, 'loop', context, sizes
                obs += ' Repeated action with the same result: try something else.'
            seen.add((action, obs.split(' Repeated')[0]))
        context += f'Thought {t}: {thought}\nAction {t}: {action}\nObservation {t}: {obs}\n'
    return None, max_steps, 'budget', context, sizes                  # бюджет шагов исчерпан

answer, steps, reason, trace, sizes = react(QUESTION, PAGES)
print(trace)                                                          # трасса, напечатанная в заметке
print(answer, steps, reason, sizes)
print(react(QUESTION, PAGES, stubborn=True)[:3])                      # повторный поиск пойман, затем исправлен
print(react(QUESTION, PAGES, max_steps=4)[:3])                        # бюджет останавливает запуск, которому нужно 7 шагов
print(react(QUESTION, {k: v for k, v in PAGES.items() if k != 'Old Mill of Dunmore'})[:3])   # страницы нет
# 249 7 finish [78, 145, 195, 243, 295, 358, 387]
# ('249', 8, 'finish')
# (None, 4, 'budget')
# (None, 6, 'loop')

# 4. стоимость цикла: s токенов до первого шага, u написанных и o наблюдаемых токенов на шаг
def loop_cost(T, s=2000, u=80, o=220, p_in=3e-6, p_out=15e-6, cached=0.1, prefill=5000, decode=50, tool=0.5):
    L = [s + (t - 1) * (u + o) for t in range(1, T + 1)]            # длина контекста L_t, читаемая на шаге t
    inp, new = sum(L), L[-1]                                          # с кэшированием по полной цене читается только L_T
    cost = inp * p_in + T * u * p_out
    cost_cached = new * p_in + (inp - new) * cached * p_in + T * u * p_out
    latency = inp / prefill + T * (u / decode + tool)
    latency_cached = new / prefill + T * (u / decode + tool)
    return L[-1], inp, round(cost, 4), round(cost_cached, 4), round(latency, 1), round(latency_cached, 1)

for T in (10, 40): print(T, loop_cost(T))
# 10 (4700, 33500, 0.1125, 0.0347, 27.7, 21.9)
# 40 (13700, 314000, 0.99, 0.1792, 146.8, 86.7)
#   (шаги; токенов прочитано на последнем шаге; всего прочитано; доллары; с кэшированием; секунды; с кэшированием)
```
