[Цепочка рассуждений](/ru/notes/agents/chain-of-thought) просила фиксированную модель выписать шаги перед ответом, а [предыдущая заметка](/ru/notes/agents/rl-for-language-models) обучала модель наградами, которые проверяет программа. Соединим одно с другим, позволим цепочке расти настолько, насколько хочет модель, и будем награждать только итоговый ответ: модель сама научится писать цепочки длиной в тысячи токенов, в которых она пробует подход, проверяет его, замечает ошибку и начинает заново. Модели, обученные так, начиная с o1 от OpenAI в сентябре 2024 года и DeepSeek-R1 в январе 2025 года, называют **рассуждающими моделями** (reasoning models). Их доля правильных ответов растёт с числом токенов, потраченных до ответа, и это превращает вычисления во время вывода (test-time compute) в ресурс, который нужно распределять, наравне с вычислениями на обучение. В этой заметке мы описываем, что известно об обучении таких моделей; точно вычисляем, что дают основные способы тратить вычисления при выводе (больше сэмплов, голосование, верификатор, который выбирает лучший ответ, верификатор, который проверяет каждый шаг); показываем, как делить бюджет между вопросами разной трудности; и разбираем дистилляцию в малые модели и цену слишком долгих размышлений.

**Обозначения.** Вопрос $x$; цепочка рассуждений $z$ и итоговый ответ $y$, считываемый с её конца. Для одного вопроса $p$ — вероятность того, что сэмплированный ответ верен, а $n$ — число сэмплов. **pass@$n$** — вероятность того, что хотя бы один из $n$ сэмплов верен, **cons@$n$** (или maj@$n$) — доля правильных ответов голосования большинством по $n$ сэмплам, а **pass@1** — доля правильных ответов (accuracy) одного сэмпла, обычно оцениваемая усреднением по нескольким. Верификатор ставит ответу оценку $S$; $\Phi$ — функция распределения стандартного нормального распределения. В игрушечной задаче об обучении по процессу решение состоит из $T$ шагов, каждый из которых верен с вероятностью $q$, а верификатор принимает верный объект с вероятностью $a$ и неверный — с вероятностью $b$, как в заметке [Рефлексия и самокоррекция](/ru/notes/agents/reflection-and-self-correction#generate-and-verify).

## Отправная точка: фиксированная модель, которую просят подумать \{#baseline-a-fixed-model-prompted-to-think\}

Заметка о цепочке рассуждений просила фиксированную модель рассуждать и тратила больше вычислений, сэмплируя несколько цепочек и голосуя. У обоих приёмов есть потолок. Цепочка по промпту имеет ту же длину, что и демонстрации, которым она подражает, — обычно несколько сотен токенов, — и у модели нет причин продолжать, когда ответ уже написан, даже неверный. Голосование прибавляет долю правильных ответов, только пока верный ответ — самый частый, и останавливается на доле вопросов, где это так. На AIME 2024 — 30 задачах американской математической олимпиады American Invitational Mathematics (AIME) 2024 года, у каждой из которых целочисленный ответ, — GPT-4o (версия мая 2024 года) решила 9.3% задач одним сэмплом и 13.4% голосованием по 64 сэмплам в оценке DeepSeek-AI ([2025](#references), таблица 5). Её доля правильных ответов не масштабировалась с вычислениями при выводе, потому что ничто в её обучении не поощряло хорошо использовать эти вычисления.

<aside class="callout"><strong>Ключевая идея.</strong> Обучать стратегию с подкреплением на задачах, ответы которых можно проверить, награждая только итоговый ответ и позволяя цепочке быть такой длинной, какая нужна. Любое поведение, которое повышает шанс верного ответа, — проверка шага, попытка другого подхода, продолжение после неудачной первой попытки — подкрепляется, если модель хоть раз так поступит. Модель учится превращать токены при выводе в долю правильных ответов, и вычисления во время вывода становятся второй осью масштабирования наравне с вычислениями на обучение.</aside>

## От цепочек по промпту к обученному рассуждению \{#from-prompted-chains-to-trained-reasoning\}

**OpenAI o1** была анонсирована 12 сентября 2024 года, и в тот же день вышли o1-preview и o1-mini ([OpenAI, 2024](#references)). OpenAI сообщила, что модель обучали крупномасштабным обучением с подкреплением продуктивно думать с помощью цепочки рассуждений и что её результаты плавно улучшались как с вычислениями на обучение (больше RL), так и с вычислениями во время вывода (больше времени на размышления) — на графиках против логарифма каждой из величин. На двух вариантах AIME 2024, по 15 задач в каждом, GPT-4o решала в среднем 12% (1.8 из 15); o1 решала 74% (11.1 из 15) одним сэмплом на задачу, 83% (12.5) консенсусом 64 сэмплов и 93% (13.9), когда 1000 сэмплов переранжировались выученной функцией оценки. Исходные цепочки рассуждений скрыты от пользователей, которые видят их краткое изложение. Алгоритм, награды, данные и размер модели не раскрывались.

**DeepSeek-R1-Zero** в январе 2025 года показала, что рецепт можно воспроизвести открыто ([DeepSeek-AI, 2025](#references), раздел 2.2). Отправной точкой была DeepSeek-V3-Base — модель со смесью экспертов (mixture of experts) с 671 млрд параметров, из которых на каждый токен активны 37 млрд, — без обучения с учителем. Обучение использовало GRPO, алгоритм из [предыдущей заметки](/ru/notes/agents/rl-for-language-models#grpo-the-group-as-the-baseline), с двумя наградами на основе правил: наградой за правильность (итоговый ответ сверяется с эталонным, а код проверяется тестами) и наградой за формат — за то, что рассуждение заключено между тегами `<think>` и `</think>`. Шаблон промпта лишь просил рассуждение, за которым следует ответ, без примеров и без указаний, как рассуждать. В ходе обучения:

- **Доля правильных ответов.** Pass@1 на AIME 2024, усреднённая по 16 сэмплам на вопрос, выросла с 15.6% до 71.0%; голосованием по 64 сэмплам модель достигла 86.7%.
- **Длина.** Средняя длина ответов на обучающих задачах неуклонно росла — от сотен до тысяч токенов; ни одна награда длины не требовала.
- **Поведение.** В цепочках появились рефлексия над предыдущими шагами и исследование альтернативных подходов. В одной промежуточной контрольной точке модель прервала собственную алгебру словами "Wait, wait. Wait. That's an aha moment I can flag here" и заново вывела шаг; авторы представили это как «момент озарения» (aha moment).
- **Проблемы.** Цепочки было трудно читать, и в них смешивались языки.

**DeepSeek-R1** сохраняет обучение с подкреплением и добавляет вокруг него этапы, которые устраняют эти проблемы:

<R1Pipeline />

1. **Холодный старт** (cold start). DeepSeek-V3-Base дообучают на тысячах длинных примеров цепочек рассуждений в читаемом формате, чтобы RL не начиналось с неустойчивой основы.
2. **RL на рассуждениях.** GRPO с наградами на основе правил на математике, коде, естественных науках и логике плюс награда за языковую согласованность — доля слов целевого языка в цепочке. В абляциях дополнительная награда немного снижала долю правильных ответов, и её оставили ради читаемости.
3. **Выборка с отклонением** (rejection sampling). Контрольная точка RL генерирует по нескольку ответов на промпт, и сохраняются только верные, а цепочки, в которых смешиваются языки или которые трудно читать, отфильтровываются: около 600 000 примеров рассуждений. К ним добавляют около 200 000 примеров письма, фактических вопросов и перевода из собственных данных SFT модели DeepSeek-V3.
4. **SFT.** DeepSeek-V3-Base дообучают две эпохи на этих 800 000 примерах.
5. **RL для всех сценариев.** Второй этап RL объединяет награды на основе правил для рассуждений с моделями вознаграждения за полезность, которую судят только по итоговому изложению, и за безвредность, которую судят по всему ответу.
6. **Дистилляция.** Те же 800 000 примеров дообучают меньшие модели Qwen2.5 и Llama 3, от 1.5 до 70 млрд параметров, только методом SFT.

В оценке DeepSeek, с ответами до 32 768 токенов, температурой 0.6, top-$p$ 0.95 и pass@1, усреднённой по 4–64 сэмплам на вопрос, DeepSeek-R1 достигла 79.8% на AIME 2024 и 97.3% на MATH-500 против 79.2% и 96.4% у OpenAI-o1-1217, приведённых в той же таблице (таблица 4). Эти числа для o1 — данные OpenAI в её собственной постановке; сравнение близкое, но не точное.

**Сколько на самом деле «возникло».** Три линии более поздних работ уточняют эту историю.

- **Базовая модель уже рефлексирует.** Liu et al. ([2025](#references)) сэмплировали DeepSeek-V3-Base на 500 вопросах MATH с шаблоном R1 и обнаружили саморефлексию, включая слова "aha" и "wait", до всякого RL. В ответах R1-Zero саморефлексия встречалась чаще, но не была положительно связана с долей правильных ответов. RL усилило поведение, которое заложило в модель предобучение, а не создало его.
- **RL скорее заостряет, чем расширяет.** Yue et al. ([2025](#references)) сравнили базовые модели и модели, обученные RLVR, в нескольких семействах моделей, с шестью алгоритмами RL, на математике, коде и визуальных рассуждениях, по pass@$k$ при больших $k$. Обученные модели были лучше при малых $k$, но базовые модели достигали более высокого pass@$k$ при больших $k$. Авторы делают вывод, что нынешнее обучение с подкреплением с проверяемыми наградами (RLVR) заставляет модель чаще сэмплировать решения, которые она и так могла найти, тогда как дистилляция из более сильного учителя может добавить схемы рассуждения, которых у ученика не было. DeepSeekMath сообщала то же для GRPO: Maj@K улучшилась, Pass@K — нет.
- **Часть длины — артефакт.** Предыдущая заметка показала, что деление на длину ответа в GRPO штрафует длинные неверные ответы меньше в пересчёте на токен; часть роста длины может идти от целевой функции, а не от полезных размышлений ([Liu et al., 2025](#references)).

Почему более длинная цепочка вообще помогает? Заметка о цепочке рассуждений дала архитектурную причину: каждый сгенерированный токен добавляет полный проход последовательных вычислений. Обучение с подкреплением добавляет причину этим пользоваться. Цепочка, которая может проверить промежуточный результат и попробовать снова, — это последовательный поиск внутри одного сэмпла; если каждая попытка удаётся с вероятностью $p$ и модель распознаёт неудачную попытку, то $k$ попыток удаются с вероятностью $1 - (1 - p)^k$, и награда из предыдущей заметки платит именно за это. Параллельные методы следующего раздела ведут тот же поиск по сэмплам, а не внутри одного сэмпла.

## Как тратить вычисления при выводе \{#spending-compute-at-inference\}

Если модель дана, потратить больше вычислений на один вопрос можно двумя способами. **Параллельные** методы берут $n$ независимых сэмплов и выбирают один ответ. **Последовательные** методы ставят каждую новую попытку в зависимость от предыдущих. Их пределы задают три величины: покрытие, правило выбора и верификатор.

**Покрытие** (coverage) — это pass@$n = 1 - (1 - p)^n$, вероятность того, что какой-то сэмпл верен. Это потолок любого параллельного метода, и это доля успехов, когда верификатор безошибочно распознаёт верные ответы, как это умеют модульные тесты или программа проверки доказательств. [Заметка о рефлексии](/ru/notes/agents/reflection-and-self-correction#generate-and-verify) вычислила, что с покрытием делает неидеальный верификатор, который принимает или отвергает ответ: кривая выходит на плато на уровне точности (precision) верификатора. Распространены ещё два правила выбора.

**Голосование большинством** (majority vote) возвращает самый частый ответ; ему не нужен верификатор, нужны лишь ответы, которые можно сравнивать, а [заметка о цепочке рассуждений](/ru/notes/agents/chain-of-thought#how-much-the-vote-helps) вычислила его точную долю правильных ответов. Оно сходится к верному ответу ровно тогда, когда этот ответ — мода распределения ответов модели.

**Best-of-$n$ с оценивающим верификатором** возвращает сэмпл с наибольшей оценкой, которую даёт выученная модель вознаграждения, часто называемая моделью вознаграждения за результат (outcome reward model, ORM). Её доля правильных ответов следует из распределения оценок. Пусть у верных ответов плотность оценки $f_c$, а $F(s) = P(S \le s)$ — функция распределения оценки одного сэмпла, смешанная по верным и неверным. Оставленный сэмпл верен, когда какой-то сэмпл $i$ верен и все остальные сэмплы оценены ниже него:

$$
\begin{aligned}
P(\text{best-of-}n \text{ верен}) &= \sum_{i=1}^{n} P\big(\text{сэмпл } i \text{ верен}, \ S_j < S_i \text{ для всех } j \ne i\big) && \text{несовместные события, непрерывные оценки} \\
&= n \int P(\text{верен})\, f_c(s)\, P(S_j < s)^{\,n - 1}\, ds && \text{сэмплы независимы и одинаково распределены} \\
&= \boxed{\; n\, p \int f_c(s)\, F(s)^{\,n-1}\, ds . \;}
\end{aligned}
$$

При $n = 1$ интеграл равен $\int f_c = 1$, и формула даёт $p$. С ростом $n$ множитель $F(s)^{n-1}$ близок к 0 везде, кроме самых высоких оценок, так что ответ определяется тем, какой вид ответов преобладает в верхнем хвосте распределения оценок, а не тем, как часто сэмплируется каждый вид.

**Разобранный пример.** Один вопрос, три вида сэмплированных ответов. Верный ответ имеет вероятность $p = 0.35$. Общее заблуждение — каждый раз одно и то же неверное число — имеет $0.25$. Случайные ошибки, каждая со своим неверным числом, имеют $0.40$. Верификатор оценивает верные ответы как $\mathcal N(1, 1)$, ошибки как $\mathcal N(0, 1)$, а заблуждение как $\mathcal N(1.4, 1)$: уверенный неверный вывод кажется ему убедительнее верного — это систематическая ошибка, а не шум. Раздел «Код» вычисляет три правила выбора точно:

| $n$ | 1 | 4 | 8 | 32 | 256 |
| --- | --- | --- | --- | --- | --- |
| покрытие, pass@$n$ | 0.350 | 0.821 | 0.968 | 1.000 | 1.000 |
| best-of-$n$ по оценке верификатора | 0.350 | 0.424 | 0.420 | 0.383 | 0.320 |
| голосование большинством | 0.350 | 0.478 | 0.630 | 0.768 | 0.981 |

Best-of-$n$ сначала выигрывает, потому что верификатор ставит ошибки ниже всего остального, а затем проигрывает, потому что среди многих сэмплов наибольшая оценка всё чаще достаётся заблуждению, которое он переоценивает. Это кривая переоптимизации из предыдущей заметки, только во время вывода: чем сильнее отбор против суррогата, тем вернее он находит ошибки суррогата. Голосование не затронуто смещением верификатора и поднимается до 0.981, потому что верный ответ — самый частый отдельный ответ. Верификатор не бесполезен; его используют неправильно. Взвешивание каждого голоса его оценкой или голосование среди сэмплов с наибольшими оценками объединяет оба подхода, и 93% у o1 получены переранжированием 1000 сэмплов функцией оценки, достаточно хорошей для этого.

**Последовательное исправление** (sequential revision). Модель можно также просить исправлять: каждая новая попытка видит предыдущие. Snell et al. ([2024](#references)) дообучили PaLM 2-S* исправлять собственные неверные ответы на MATH и обнаружили, что при одинаковом числе сгенерированных ответов последовательные исправления немного превосходили параллельные сэмплы — будь итоговый ответ выбран верификатором или голосованием. Рассуждающая модель исправляет себя внутри цепочки, а длиной цепочки можно управлять извне. s1 ([Muennighoff et al., 2025](#references)) дообучили Qwen2.5-32B-Instruct на 1000 вопросов с трассами рассуждений и затем применили **принудительный бюджет** (budget forcing): когда модель пыталась закончить размышления, к её цепочке дописывалось слово "Wait", а когда бюджет исчерпывался, конец размышлений вызывался принудительно. Продление размышлений таким способом подняло её долю правильных ответов на AIME 2024 с 50% до 57%.

## Оптимальное по вычислениям распределение \{#compute-optimal-allocation\}

Snell et al. ([2024](#references)) спросили, как тратить фиксированный бюджет вычислений при выводе, на PaLM 2-S*, дообученной как модель исправления и как верификатор процесса на MATH. Ответ зависит от вопроса. Они разбили вопросы на пять уровней трудности по pass@1 базовой модели, оценённой по 2048 сэмплам на вопрос (или, без эталонных ответов, по оценкам верификатора на этих сэмплах), и выбирали лучшую стратегию для каждого уровня. На лёгких вопросах больше всего давало последовательное исправление; на трудных — смесь исправления и параллельного сэмплирования или поиска; на самых трудных почти ничего не помогало. Выбор по уровню трудности сравнялся по доле правильных ответов с базовой линией best-of-$N$ примерно при вчетверо меньших вычислениях во время вывода — и для исправлений, и для поиска. В сравнении при равных FLOP вычисления во время вывода на меньшей модели обходили модель с примерно в 14 раз большим числом параметров на лёгких и средних вопросах, когда на вывод приходилась малая доля общих вычислений, тогда как на самых трудных вопросах или когда модель обслуживает гораздо больше токенов, чем видела при обучении, лучшим вложением вычислений было дополнительное предобучение.

Та же логика в простейшем виде: вопросы различаются по $p$, а сэмпл ценнее всего там, где он сильнее всего повышает шанс решения. **Разобранный пример.** 100 вопросов с $p_i = ((i + 0.5)/100)^3$, в основном трудных (среднее 0.25); верификатор идеален, так что вопрос решён, если верен любой из его сэмплов; всего 800 сэмплов. Ожидаемое число решённых вопросов равно $\sum_i (1 - (1 - p_i)^{n_i})$, а ещё один сэмпл на вопрос $i$ прибавляет $p_i (1 - p_i)^{n_i}$, что убывает с ростом $n_i$. Поскольку выигрыш на каждом вопросе убывает, отдавать каждый следующий сэмпл вопросу с наибольшим выигрышем оптимально.

| распределение 800 сэмплов | ожидаемое число решённых вопросов |
| --- | --- |
| равномерное, по 8 на вопрос | 56.5 |
| по истинной трудности | 63.2 |
| по трудности, оценённой по 4 пробным сэмплам на вопрос | 60.9 |

Оптимальное распределение не даёт 26 вопросам ни одного сэмпла, потому что их $p$ так мало, что любой сэмпл лучше потратить в другом месте, а одному вопросу даёт до 22 сэмплов. Распределение по оценке возвращает бо́льшую часть выигрыша ценой пробных сэмплов. Урок тот же, что у Snell et al., в игрушечном масштабе: вычисления при выводе ценнее всего на вопросах средней трудности, а самым трудным нужна лучшая модель, а не больше сэмплов.

## Модели вознаграждения за процесс и за результат \{#process-and-outcome-reward-models\}

Модель вознаграждения за результат оценивает законченное решение. **Модель вознаграждения за процесс** (process reward model, PRM) оценивает каждый шаг, так что поиск может отсечь неверное частичное решение, как только оно пошло не так, а не после того, как оно закончено. **"Let's verify step by step"** ([Lightman et al., 2023](#references)) сравнили их для генератора на основе GPT-4 на MATH. Разметчики помечали каждый шаг решений, написанных моделью, как положительный, отрицательный или нейтральный — до первой ошибки, что на верных решениях не даёт PRM никакой информации сверх ORM, а на неверных даёт только место ошибки. Опубликованный набор данных **PRM800K** содержит 800 000 меток шагов для 75 000 решений 12 000 задач; выбор решений для разметки активным обучением сделал разметку примерно в 2.6 раза эффективнее по данным. Оценка решения в PRM — произведение вероятностей правильности его шагов. При выборе лучшего из 1860 сэмплов на 500 тестовых задачах MATH PRM решила 78.2%, ORM — 72.4%, а голосование большинством — 69.6%; эти числа заметка о рефлексии использовала для сравнения верификаторов. Человеческая разметка шагов дорога и плохо переносится между моделями: Snell et al. обнаружили, что PRM, обученную на PRM800K, легко эксплуатировать отбором best-of-$N$ на сэмплах PaLM 2, и вместо этого обучили свою PRM на правильности шагов, оценённой методом Монте-Карло по продолжениям (rollouts) от каждого шага, вслед за Math-Shepherd ([Wang et al., 2024](#references)).

Почему проверка шагов помогает, проще всего увидеть на точных числах. Возьмём решения из $T = 8$ шагов, каждый из которых верен с вероятностью $q = 0.8$, причём один неверный шаг портит ответ, так что всё решение верно с вероятностью $q^8 = 0.168$. Дадим обоим методам верификатор одного качества, $a = 0.9$ и $b = 0.1$, и одинаковый бюджет в $8n$ сгенерированных шагов:

- **ORM, лучшее из $n$ решений.** Берём $n$ законченных решений и возвращаем первое, которое принял верификатор. При $p = 0.168$ формула из заметки о рефлексии даёт потолок $\frac{pa}{pa + (1 - p)b} = 0.645$.
- **PRM, поиск на уровне шагов.** На каждом шаге берём $n$ кандидатов на следующий шаг и оставляем первого, которого принял верификатор. Теперь каждый шаг удаётся по той же формуле при $p = q = 0.8$, потолок которой равен $0.973$, а решение удаётся, если удаются все 8 шагов: не больше $0.973^8 = 0.803$.

<PrmVsOrm />

С 4 кандидатами на шаг поиск на уровне шагов достигает 0.783 против 0.431 у лучшего из 4 законченных решений, и его кривая уже близка к потолку 0.803, тогда как best-of-$n$ ещё поднимается к 0.645. Проверять легче там, где объект скорее всего верен: принятый шаг верен с вероятностью 0.973, а принятое решение — лишь с 0.645, потому что неверных решений большинство, и 10% ложноположительных срабатываний пропускают многие из них. Сравнение предполагает, что судить о шаге так же надёжно, как о решении, и берёт с PRM один вызов верификатора на каждого кандидата шага — $8n$ вызовов против $n$; оба допущения благоприятны для PRM, и реальные сравнения должны их измерять.

DeepSeek-R1 относит PRM к своим неудачным попыткам ([DeepSeek-AI, 2025](#references), раздел 4.2): «шаг» трудно определить в общем рассуждении, оценку промежуточного шага трудно автоматизировать и дорого размечать, а PRM на основе модели, используемая как награда в крупномасштабном RL, провоцирует взлом награды (reward hacking). Авторы нашли PRM полезными для переранжирования и управляемого поиска при выводе, но не стоящими своей цены в роли обучающего сигнала; поиск по дереву методом Монте-Карло (MCTS) по шагам — другой метод, который они пробовали, — тоже не масштабировался, потому что пространство последовательностей токенов гораздо больше, чем у игры, а модель ценности, которая направляет поиск, было трудно обучить.

## Дистилляция рассуждений в малые модели \{#distilling-reasoning-into-small-models\}

Обучение с подкреплением на малой модели дорого и, по измерениям DeepSeek, не лучший способ потратить вычисления. Дистилляция — это обычное SFT на трассах рассуждений более сильной модели, здесь на 800 000 примерах этапа 3, без RL ([DeepSeek-AI, 2025](#references), разделы 2.4, 3.2 и 4.1). В оценке DeepSeek (постановка выше):

| модель | AIME 2024 pass@1 | MATH-500 pass@1 |
| --- | --- | --- |
| GPT-4o-0513 | 9.3% | 74.6% |
| DeepSeek-R1-Distill-Qwen-1.5B | 28.9% | 83.9% |
| DeepSeek-R1-Distill-Qwen-7B | 55.5% | 92.8% |
| DeepSeek-R1-Distill-Qwen-32B | 72.6% | 94.3% |
| DeepSeek-R1-Zero-Qwen-32B (RL на Qwen2.5-32B, более 10 000 шагов) | 47.0% | 91.6% |
| DeepSeek-R1 | 79.8% | 97.3% |

Информативно сравнение в пятой строке: та же базовая модель на 32 млрд параметров достигла 47.0% на AIME собственным крупномасштабным RL и 72.6% — подражая R1. Авторы заключают, что дистиллировать более сильную модель гораздо дешевле, чем открывать её поведение обучением с подкреплением в меньшей, тогда как чтобы превзойти сильнейшую модель, по-прежнему нужны более сильная база и больше RL. Дистилляции хватает немногих примеров, когда ученик силён: 1000 трасс s1 хватило, чтобы превратить Qwen2.5-32B-Instruct в модель, которая рассуждает подолгу. Это также механизм, которым рассуждающее поведение распространяется от одной модели ко многим, поскольку опубликованные трассы любой модели могут служить данными для SFT.

## Чрезмерное обдумывание и цена длины \{#overthinking-and-the-cost-of-length\}

Длинная цепочка стоит времени и денег на каждом вопросе, включая лёгкие. Chen et al. ([2024](#references)) спрашивали модели в стиле o1 "what is the answer of 2 plus 3?". QwQ-32B-Preview написала 901 токен с 13 отдельными решениями, первое из которых было верным уже через 39 токенов; на этом вопросе модели в стиле o1 в среднем тратили на 1953% больше токенов, чем обычные модели, чтобы прийти к тому же ответу. На их математических бенчмарках среди ответов, содержавших верный ответ, первое решение в цепочке было верным уже более чем в 92% случаев, а последующие раунды почти не добавляли ни доли правильных ответов, ни разнообразия. Длиннее — не всегда даже точнее. Gema et al. ([2025](#references)) построили задачи — например, подсчёт с отвлекающей информацией и регрессию с ложными признаками, — на которых доля правильных ответов нескольких рассуждающих моделей падала, когда им позволяли рассуждать дольше; при более длинных рассуждениях одна модель к тому же чаще выражала стремление к самосохранению в оценке рисков ИИ.

Затраты складываются просто. Цепочка генерируется токен за токеном, поэтому её задержка — это её длина, делённая на скорость декодирования: 10 000 токенов при 50 токенах в секунду занимают 200 секунд до первого слова ответа. Цена линейна по токенам, и агент платит её на каждом шаге своего цикла ([ReAct и цикл агента](/ru/notes/agents/react-and-the-agent-loop#the-cost-and-latency-of-a-loop)). Поэтому провайдеры предоставляют бюджет размышлений или настройку усилия, а обучение добавляет давление в сторону краткости — например, штрафы за длину или награды за более ранний приход к ответу. Правильная длина — свойство вопроса, и это довод об оптимальном по вычислениям распределении из предыдущего раздела, применённый внутри одной цепочки.

## Ограничения \{#limitations\}

- **О ведущих моделях раскрыто мало.** Обучение o1 описано в нескольких предложениях; открытые воспроизведения опираются на отчёт DeepSeek и на более поздние анализы, которые местами расходятся.
- **Только проверяемые области.** Рецепту нужна проверка; у математики и кода она есть, у большинства других задач — нет, и выигрыш за их пределами меньше и труднее поддаётся измерению.
- **Заострение, а не открытие.** При большом числе сэмплов базовые модели могут решить столько же задач, сколько их версии, обученные RL; RL делает успех вероятнее на том, что и так было достижимо.
- **Верификаторы — суррогаты.** У отбора выученной функцией оценки есть кривая переоптимизации из предыдущей заметки; PRM, обученные на решениях одной модели, эксплуатируются решениями другой.
- **Длина дорога и иногда вредна.** Длинные цепочки добавляют задержку и стоимость на лёгких вопросах, а на некоторых задачах доля правильных ответов с длиной падает.
- **Бенчмарки стареют.** Олимпиадные задачи утекают в обучающие данные, и числа на них по самой своей природе привязаны к дате.
- **Достоверность.** Длинные цепочки по-прежнему не гарантируют, что показывают то, что на самом деле определило ответ, как обсуждалось в [заметке о цепочке рассуждений](/ru/notes/agents/chain-of-thought#is-the-chain-of-thought-faithful).

## Что нужно запомнить \{#what-you-should-remember\}

- Рассуждающие модели обучают с подкреплением на проверяемых задачах, награждая итоговый ответ; длинные цепочки, самопроверка и повторные попытки подкрепляются, потому что повышают награду. o1 (сентябрь 2024) это показала, DeepSeek-R1-Zero (январь 2025) открыто воспроизвела с GRPO и наградами на основе правил на базовой модели: с 15.6% до 71.0% pass@1 на AIME 2024.
- R1 добавляет SFT холодного старта, награду за языковую согласованность, выборку с отклонением, дающую 800 000 примеров для SFT, и финальный этап RL с моделями вознаграждения; те же примеры дистиллируют рассуждения в модели от 1.5 до 70 млрд параметров.
- Более поздние анализы: базовые модели уже проявляют саморефлексию; RLVR улучшает pass@1 и голосование сильнее, чем pass@$k$ при больших $k$; часть роста длины идёт от целевой функции.
- Параллельные вычисления ограничены покрытием $1 - (1 - p)^n$. Best-of-$n$ по оценке равен $n p \int f_c F^{n-1}$: его определяет верхний хвост оценок, поэтому смещённый верификатор заставляет его падать с ростом $n$. Голосование сходится к моде.
- Оптимальное по вычислениям распределение зависит от трудности: класть сэмплы туда, где предельный выигрыш наибольший; исправления — для лёгких вопросов, поиск — для средних, а для самых трудных — лучшая модель. Snell et al. сравнялись с best-of-$N$ примерно при вчетверо меньших вычислениях.
- Модели вознаграждения за процесс проверяют шаги, где объект чаще верен, а ошибки ловятся рано; PRM на PRM800K обошла ORM и голосование (78.2%, 72.4%, 69.6%), но PRM дорого размечать, и как награды в RL они поддаются взлому.
- Дистилляция через SFT на трассах более сильной модели обходит RL на самой малой модели (72.6% против 47.0% для Qwen2.5-32B на AIME 2024).
- Чрезмерное обдумывание тратит токены на лёгких вопросах; задержка — это длина, делённая на скорость декодирования.

## Код \{#code\}

Три точных вычисления и их симуляции на NumPy: покрытие, best-of-$n$ по оценке смещённого верификатора и голосование относительным большинством с тремя видами ответов; проверка по результату против проверки по процессу с правилом «первый принятый»; и распределение бюджета сэмплов между вопросами разной трудности — по истинной и по оценённой трудности. С настоящей моделью `p`, распределения оценок и доля правильных шагов неизвестны и оцениваются по сэмплам на отложенных вопросах; формулы и жадное распределение используются так, как записаны. Начальные значения генератора фиксированы; точные числа могут немного различаться на разных платформах и версиях библиотек. Скрипт работает около двух секунд.

```python
import numpy as np
from math import erf, exp, lgamma, log, sqrt, pi as PI

# 1. один вопрос, три вида сэмплированных ответов: верный (p = 0.35), одно общее заблуждение (0.25)
#    и разрозненные ошибки (0.40), каждая ошибка — своё неверное число. Выученный верификатор оценивает каждый ответ:
#    N(1, 1), если он верен, N(1.4, 1) для заблуждения, которое он переоценивает, N(0, 1) для ошибки.
p, qm = 0.35, 0.25; qs = 1 - p - qm
MU = {'correct': 1.0, 'misconception': 1.4, 'slip': 0.0}
Phi = np.vectorize(lambda x: 0.5 * (1 + erf(x / sqrt(2))))
s = np.linspace(-8, 10, 18001); ds = s[1] - s[0]
f_correct = np.exp(-0.5 * (s - MU['correct']) ** 2) / sqrt(2 * PI)
F = p * Phi(s - MU['correct']) + qm * Phi(s - MU['misconception']) + qs * Phi(s - MU['slip'])

def coverage(n): return 1 - (1 - p) ** n                   # pass@n: какой-то сэмпл верен (идеальный верификатор)
def best_of(n):                                            # сэмпл с наибольшей оценкой верен
    return float((n * p * f_correct * F ** (n - 1)).sum() * ds)
def vote(n):                                               # голосование относительным большинством, ничьи разрешаются равновероятно
    total = 0.0
    for kc in range(1, n + 1):
        for km in range(n - kc + 1):
            ks = n - kc - km
            top = max(kc, km, 1 if ks else 0)
            if kc < top: continue
            ties = 1 + (km == top) + (ks if top == 1 else 0)   # каждая ошибка — отдельный ответ с одним голосом
            lp = (lgamma(n + 1) - lgamma(kc + 1) - lgamma(km + 1) - lgamma(ks + 1)
                  + kc * log(p) + km * log(qm) + ks * log(qs))
            total += exp(lp) / ties
    return total
for n in (1, 2, 4, 8, 16, 32, 64, 128, 256):
    print(f'n {n:3d}  coverage {coverage(n):.3f}  best-of-n {best_of(n):.3f}  vote {vote(n):.3f}')
# n   1  coverage 0.350  best-of-n 0.350  vote 0.350
# n   2  coverage 0.577  best-of-n 0.403  vote 0.350
# n   4  coverage 0.821  best-of-n 0.424  vote 0.478
# n   8  coverage 0.968  best-of-n 0.420  vote 0.630
# n  16  coverage 0.999  best-of-n 0.404  vote 0.697
# n  32  coverage 1.000  best-of-n 0.383  vote 0.768
# n  64  coverage 1.000  best-of-n 0.361  vote 0.850
# n 128  coverage 1.000  best-of-n 0.340  vote 0.929
# n 256  coverage 1.000  best-of-n 0.320  vote 0.981

rng = np.random.default_rng(0)                              # симуляция согласуется с точными числами при n = 8
kinds = rng.choice(3, size=(100_000, 8), p=[p, qm, qs])
scores = rng.normal(np.array([1.0, 1.4, 0.0])[kinds], 1.0)
print(round(float(np.mean(kinds[np.arange(100_000), scores.argmax(1)] == 0)), 3))
# 0.42

# 2. проверка по результату против проверки по процессу, точно. Решение состоит из T = 8 шагов; каждый шаг верен
#    с вероятностью q = 0.8, и один неверный шаг портит ответ. Верификатор принимает верный объект с вероятностью a = 0.9,
#    а неверный — с b = 0.1. ORM: лучшее из N целых решений. PRM: на каждом шаге берём k кандидатов и оставляем первого,
#    которого принял верификатор. Оба возвращают первого принятого кандидата или первого кандидата, если не принят ни один.
def first_accepted(p, a, b, n):                             # формула из заметки о рефлексии
    q1, q0 = p * a, (1 - p) * b; r = 1 - q1 - q0
    return q1 / (q1 + q0) * (1 - r ** n) + p * (1 - a) * r ** (n - 1)
T, q, a, b = 8, 0.8, 0.9, 0.1
for n in (1, 2, 4, 8, 16, 64):                              # n решений или n кандидатов на шаг: в каждом случае n * T шагов
    print(n, round(first_accepted(q ** T, a, b, n), 3), round(first_accepted(q, a, b, n) ** T, 3))
# 1 0.168 0.168
# 2 0.279 0.55
# 4 0.431 0.783
# 8 0.571 0.803
# 16 0.636 0.803
# 64 0.645 0.803

def prm_search(k, rng):                                     # тот же поиск, симулированный шаг за шагом
    for _ in range(T):
        cands = rng.random(k) < q
        accepted = np.where(cands, rng.random(k) < a, rng.random(k) < b)
        pick = cands[np.argmax(accepted)] if accepted.any() else cands[0]
        if not pick: return False
    return True
print(round(np.mean([prm_search(4, rng) for _ in range(50_000)]), 3))
# 0.785

# 3. оптимальное по вычислениям распределение: 100 вопросов разной трудности, идеальный верификатор (модульные тесты),
#    всего 800 сэмплов. Равномерно: по 8 на вопрос. Адаптивно: каждый следующий сэмпл идёт туда, где он сильнее всего
#    повышает ожидаемое число решённых вопросов, по истинной трудности или по трудности, оценённой по 4 пробным сэмплам.
P = ((np.arange(100) + 0.5) / 100) ** 3                    # большинство вопросов трудные: среднее P равно 0.25
def solved(n): return float(np.sum(1 - (1 - P) ** n))
def allocate(p_hat, budget, n0):
    n = n0.copy()
    for _ in range(budget):
        gain = p_hat * (1 - p_hat) ** n                     # выигрыш от ещё одного сэмпла на каждом вопросе
        n[np.argmax(gain)] += 1
    return n
uniform = np.full(100, 8)
oracle = allocate(P, 800, np.zeros(100, int))
pilot = rng.binomial(4, P)                                  # сначала по 4 сэмпла на вопрос, затем 400 по оценке
est = allocate((pilot + 0.5) / 5, 400, np.full(100, 4))
solved_est = float(np.mean([np.sum((pilot > 0) | (rng.random(100) > (1 - P) ** (est - 4))) for _ in range(20_000)]))
print(round(solved(uniform), 1), round(solved(oracle), 1), round(solved_est, 1), int((oracle == 0).sum()), int(oracle.max()))
# 56.5 63.2 60.9 26 22
```
