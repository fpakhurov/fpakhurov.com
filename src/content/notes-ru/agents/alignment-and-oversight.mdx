Предыдущая заметка защищала агента от внешнего атакующего, который управляет им через то, что агент читает. Эта заметка — о сбое без атакующего. Начиная с заметки [Что такое агент](/ru/notes/agents/what-an-agent-is#performance-measures-and-rationality), курс определял хорошего агента как того, кто максимизирует меру качества, а начиная с [раздела об обучении с подкреплением](/ru/notes/agents/temporal-difference-learning) обучал агентов максимизировать награду. Награда — мера, которую записали люди, а записанное никогда в точности не совпадает с тем, что они имели в виду. Достаточно хороший оптимизатор находит разницу. Предыдущая заметка показала, как агенты обманывают оценщиков во время оценки; здесь то же поведение выучивается при обучении и становится свойством агента. Заметка разбирает, как это происходит, почему исправить это труднее, чем кажется, и какой надзор ограничивает ущерб, когда это происходит.

**Обозначения.** **Истинная цель** $R^\star$ — то, чего хотят создатели; **суррогат** (proxy) $\tilde R$ — награда, на которой обучается агент, например «видимые тесты проходят». Стратегию $\pi_\theta$ обучают максимизировать $J(\theta) = \mathbb E_{\pi_\theta}[\tilde R]$. **Монитор** $m$ читает траекторию (действия, а иногда и цепочку рассуждений) и выдаёт пометку или оценку подозрительности. В игрушечной модели из раздела «Код» стратегия выбирает среди вариантов поведения $a$ с вероятностями $\pi_a$; $\tilde r_a$ и $r^\star_a$ — ожидаемые суррогатная и истинная награды каждого варианта.

## Отправная точка: награда и есть цель \{#baseline-the-reward-is-the-goal\}

Рабочее допущение обучения с подкреплением: максимизировать награду — это и есть цель. Оно верно, когда награда — ровно то, чего мы хотим: счёт в игре, которую мы хотим выиграть, исход шахматной партии. Оно неверно, когда награда — измерение чего-то другого. Каждая награда, которую агент получает на практике, — именно такое измерение: тесты заменяют правильный код, оценка судьи — хороший ответ, состояние базы данных — правильно выполненную задачу. Пока агент слаб, измерение и цель движутся вместе, потому что проще всего поднять меру, выполнив задачу. Когда агент достаточно силён, чтобы найти более дешёвый способ поднять меру, они расходятся. Это закон Гудхарта (Goodhart's law), «когда мера становится целью, она перестаёт быть хорошей мерой», увиденный со стороны оптимизатора, и в заметке [Обучение с подкреплением для языковых моделей](/ru/notes/agents/rl-for-language-models#overoptimization-when-the-proxy-keeps-rising) он измерен для выученной модели вознаграждения (reward model): истинная оценка растёт, а затем падает, пока суррогат продолжает расти.

## Игра со спецификацией и взлом награды \{#specification-gaming-and-reward-hacking\}

**Игра со спецификацией** (specification gaming) — поведение, которое удовлетворяет буквальной спецификации цели, не достигая задуманного. Когда оно эксплуатирует изъян в самой награде, его называют **взломом награды** (reward hacking). Список примеров Виктории Краковны, начатый в 2018 году и поддерживаемый вместе с коллегами из DeepMind, собирает десятки случаев из эволюционных алгоритмов и обучения с подкреплением ([Krakovna et al., 2020](#references)). Самый известный — от OpenAI (декабрь 2016 года): агент для гоночной игры на лодках CoastRunners, которого награждали счётом в игре, нашёл лагуну, где мог кружить и раз за разом сбивать три мишени по мере их появления, загораясь и врезаясь, и так и не закончил гонку. По пересказам публикации, он набирал примерно на 20% больше очков, чем люди; суть — в качественном результате: больше очков, а гонка не пройдена ([Clark and Amodei, 2016](#references)). Другие записи: смоделированный робот, который должен был схватить мяч, научился помещать руку между мячом и камерой, чтобы казалось, будто мяч схвачен; агенты, которые эксплуатируют ошибки в физическом симуляторе.

Агенты на языковых моделях делают то же самое в средах этого курса, и примеры теперь берутся из передовых моделей и их обучения, а не из игрушечных игр.

- **Правка тестов.** При обучении передовой рассуждающей модели на задачах программирования, где награда — прохождение модульных тестов, OpenAI обнаружила агентов, которые досрочно завершали процесс тестирования с кодом успеха (`exit(0)`), выбрасывали исключение, заставляющее тестовый фреймворк пропускать тесты, подменяли функции заглушками, когда тесты плохо их покрывали, и декомпилировали эталонное решение, оставленное в среде ([Baker et al., 2025](#references)).
- **Особые случаи для оценщика.** METR сообщила в июне 2025 года, что o3 на её задачах подменял часы у программы подсчёта очков, чтобы код казался быстрее, и правил функцию оценки так, чтобы любое решение проходило. На задачах RE-Bench он взламывал награду в 39 из 128 запусков (30.4%), на HCAST — в 8 из 1087 (0.7%); когда его потом спрашивали, соответствует ли его подход намерениям пользователя, он отвечал «нет» во всех 10 попытках на одной задаче ([METR, 2025](#references)).
- **Намеренное измерение.** ImpossibleBench (октябрь 2025 года) делает спецификацию и тесты противоречащими друг другу, так что ни одно правильное решение не проходит; каждое прохождение — обходной путь, и доля прохождений измеряет склонность к обману ([Zhong et al., 2025](#references)).
- **Это обобщается.** Anthropic сообщила в ноябре 2025 года, что модель, которая научилась взламывать награду в настоящих рабочих средах программирования, стала невыровненной (misaligned) и на не связанных с этим оценках, включая саботаж кода при работе в роли агента для программирования, и что обучение безопасности на промптах из чатов не убирало такое поведение на агентных задачах ([MacDiarmid et al., 2025](#references)).

Заметка [Обучение агентов с подкреплением](/ru/notes/agents/agentic-rl#reward-hacking-in-agentic-training) перечислила эти взломы со стороны того, кто обучает, вместе с инженерными мерами, которые их блокируют: оценивать вне песочницы, ограничивать то, что агент может записывать. [Заметка об оценке](/ru/notes/agents/evaluating-agents#contamination-and-saturation) зафиксировала то же поведение со стороны того, кто оценивает: к началу 2026 года не меньше 16% успешных запусков на самых длинных задачах METR были нечестными. Почему оно появляется, видно на игрушечной модели. Агент с градиентом по стратегии ([Градиент по стратегии и методы «актор–критик»](/ru/notes/agents/policy-gradients#the-policy-gradient-theorem)) с softmax по вариантам поведения следует ожидаемому градиенту

$$
\begin{aligned}
\frac{\partial J}{\partial \theta_a} &= \pi_a\,(\tilde r_a - J), \\
J &= \sum_b \pi_b \tilde r_b ,
\end{aligned}
$$

поэтому любой вариант, суррогатная награда которого выше средней, набирает вероятность со скоростью, пропорциональной его текущей вероятности. Ничто в обновлении не ссылается на истинную награду. Вариант, который априорное распределение делает редким, например правка тестов, стартует медленно, но как только у него появляется хоть какая-то вероятность и наибольшая суррогатная награда, он захватывает стратегию. В игрушечной модели из раздела «Код» аккуратное исправление проходит видимые тесты в 80% случаев и верно в 75%; правка теста проходит их всегда и никогда не верна.

Первую тысячу шагов суррогат и истина растут вместе: агент учится аккуратно чинить код, и суррогат — хорошая мера. Затем взлом, который начинал с вероятности 0.013, захватывает стратегию, и к шагу 1500 суррогат равен 0.998, а истинная награда — 0.006. Агенту не пришлось ничего придумывать во взломе; оптимизатору нужно было лишь его найти, и такова общая форма проблемы.

## Неверное обобщение цели \{#goal-misgeneralization\}

Взлому награды нужна ошибочная награда. **Неверное обобщение цели** (goal misgeneralization) случается, даже когда награда правильна на каждом обучающем примере: агент выучивает цель, которая совпадает с задуманной во время обучения и отличается от неё за его пределами. [Langosco et al. (2022)](#references) показали это в CoinRun — платформенной игре, где при обучении монета всегда лежит в правом конце уровня. Агенты научились идти вправо, а не добывать монету, и когда при тестировании монету переместили, они пробегали мимо неё к концу уровня, по-прежнему умело играя. Способности обобщились, а цель — нет. [Shah et al. (2022)](#references) привели больше примеров и утверждали, что это различие важно: неверно обобщённую цель агент преследует умело, а это вреднее, чем агент, который просто не справляется.

Для агентов на языковых моделях обучающее распределение огромно, а распределение при развёртывании ещё больше, поэтому вопрос в том, какую из множества целей, совместимых с обучением, выучил агент: «сделать так, чтобы тесты проходили» или «написать правильный код»; «угодить пользователю» или «сказать пользователю то, что он хочет услышать». Эти цели неразличимы, пока не расходятся, и поиск расхождений — большая часть оценки агента с точки зрения безопасности.

## Масштабируемый надзор вкратце \{#scalable-oversight-briefly\}

Оба сбоя сводятся к награде, а награда берётся от людей или из проверок, которые написали люди. Когда задачи становятся длиннее и техничнее, чем человек может проверить, вопрос превращается в то, как назначить награду за работу, которую оценивающий не может оценить. Это **масштабируемый надзор** (scalable oversight). Два ранних предложения:

- **Дебаты** (debate; [Irving, Christiano and Amodei, 2018](#references)): две копии модели отстаивают противоположные ответы, а человек судит, какой аргумент убедительнее. Надежда в том, что указать на изъян легче, чем найти правильный ответ, так что слабый судья может надзирать за сильными участниками дебатов; [заметка о мультиагентных системах](/ru/notes/agents/multi-agent-systems#voting-debate-and-correlated-errors) показала, что дебаты между агентами повышают долю правильных ответов, только когда что-то привносит новые свидетельства или проверку.
- **Рекурсивное моделирование вознаграждения** (recursive reward modelling; [Leike et al., 2018](#references)): обучать модели помогать людям оценивать и использовать оценки, сделанные с такой помощью, для обучения следующего агента, рекурсивно, так что оценивающий растёт вместе с агентом.

Ни одна из этих задач не решена, а эмпирические работы недавние. Идеи стоит знать, потому что описанные ниже техники — частичные практические ответы на тот же вопрос.

## Мониторинг цепочки рассуждений \{#monitoring-the-chain-of-thought\}

Рассуждающая модель записывает свои рассуждения перед тем, как действовать ([Цепочка рассуждений](/ru/notes/agents/chain-of-thought) и [Рассуждающие модели](/ru/notes/agents/reasoning-models)). Этот текст — свидетельство о том, что агент пытается сделать, и его может читать монитор. [Baker et al. (2025)](#references) проверили это в описанных выше средах программирования, где GPT-4o следила за более сильной рассуждающей моделью (класса o3-mini) во время обучения. На двух систематических взломах монитор, который видел только действия и выходы, поймал 60% из них; монитор, который читал ещё и цепочку рассуждений, — 95%. Агенты часто прямо заявляли о своём намерении («let's hack»), и более слабая модель могла поймать более сильную.

Второй результат статьи — предупреждение. Естественный следующий шаг — включить монитор в награду: штрафовать траектории, которые монитор помечает. При слабом давлении оптимизации это помогало: взломов становилось меньше, а агенты — лучше. При более сильной оптимизации агенты научились **замаскированному взлому награды** (obfuscated reward hacking): они продолжали взламывать с заметной частотой, а их цепочки рассуждений перестали об этом говорить, так что полнота монитора упала почти до нуля. Авторы рекомендуют платить «налог на наблюдаемость» (monitorability tax): не применять сильное давление оптимизации прямо к цепочке рассуждений, чтобы она оставалась полезным окном.

Игрушечная модель показывает механизм. Пусть агент выбирает не только, взламывать ли, но и как это описать — откровенно или невинными словами, и пусть монитор ловит 95% откровенных описаний и 10% замаскированных. При суррогатной награде описание не важно, поэтому агент сохраняет априорное предпочтение и описывает взлом откровенно; монитор помечает 88% запусков. Если штрафовать пометки (левая панель рисунка), самый дешёвый ответ — не честная работа, а замаскированный взлом: вероятность маскировки растёт от 0.08 почти до 1, доля помеченных падает до 0.10, а истинная награда остаётся нулевой. Тревога монитора стихла, а лучше ничего не стало. Если исправить саму награду, оценивая тестами, которые агент не может ни видеть, ни трогать (правая панель), честный вариант возвращается — к истинной награде 0.75.

<aside class="callout"><strong>Ключевая идея.</strong> Оптимизатор удовлетворяет мере, которую ему дали, а не намерению, стоящему за ней. Меру нужно исправлять там, где это возможно: скрытые и защищённые тесты, проверки состояния, награды за тот исход, которого мы действительно хотим. Мониторы нужны, чтобы обнаруживать то, что мера упускает, и обучать против монитора нельзя, иначе он научит агента от него прятаться.</aside>

## Контроль ИИ: безопасность без доверия к модели \{#ai-control-safety-without-trusting-the-model\}

Мониторинг предполагает, что агент не пытается его обойти. **Контроль ИИ** (AI control; [Greenblatt et al., 2024](#references)) отказывается от этого допущения и спрашивает: если способная модель, возможно, намеренно действует против нас, какие протоколы её использования всё ещё безопасны? Метод — состязательная оценка. Красная команда играет недоверенную модель и пытается пронести вредное действие мимо протокола; синяя команда разрабатывает протокол; **безопасность** протокола — вероятность того, что за всё развёртывание не пройдёт ни одно вредное действие, а его **полезность** — доля качества сильной модели, которую он сохраняет.

Постановка статьи: решить 5000 задач программирования (APPS), используя GPT-4 как способную недоверенную модель, GPT-3.5 как более слабую доверенную модель и небольшой бюджет доверенного человеческого труда, которого хватает на аудит 2% решений. Вред — **бэкдор** (backdoor): код, который проходит тесты, но даёт неверный ответ на входе, известном атакующему. Полезность отмасштабирована так, что 0 — доля правильных решений GPT-3.5 (22%), а 1 — GPT-4 (54%).

<TrustedMonitoring />

1. Недоверенная модель предлагает решение.
2. Доверенная модель оценивает, насколько подозрительно оно выглядит.
3. Решения с низкой оценкой отправляются как есть.
4. Решения со средней оценкой заменяются собственным решением доверенной модели — *передача доверенной модели* (defer to trusted).
5. Самые подозрительные 2% уходят людям на аудит; бэкдор, найденный при аудите, заканчивает игру в пользу синей команды.

| протокол (постановка с бэкдорами в APPS) | безопасность | полезность |
| --- | --- | --- |
| только доверенная модель | 100% | 2% |
| недоверенная модель, аудит первых 2% (аудит в начале, upfront auditing) | 15% | 100% |
| доверенный мониторинг, аудит верхних 2% | 62% | 97% |
| доверенный мониторинг, следующие 10% передаются доверенной модели | 83% | 93% |
| доверенный мониторинг, передаются 20% | 92% | 83% |
| недоверенный мониторинг, передаются 10% | 92% | 92% |
| доверенное редактирование, 20% | 92% | 94% |

Простые протоколы либо безопасны и бесполезны, либо полезны и небезопасны; мониторинг, передача и редактирование прочерчивают фронт между этими крайностями — тот же вид компромисса, что и фронт стоимости из [заметки об оценке](/ru/notes/agents/evaluating-agents#cost-aware-evaluation-and-pareto-fronts). *Недоверенный мониторинг* использует в качестве монитора другую копию сильной модели, которая способнее, но может вступить в сговор со стратегией; статья проверяла его против сговора с синтетическими бэкдорами и сигналами. Числа относятся к одной постановке и одной красной команде; переносима методика — измерять протокол против противника, который пытается его победить.

## Надзор человека и уровни автономии \{#human-oversight-and-levels-of-autonomy\}

Протоколы выше — автоматизированные формы более старой идеи: человек остаётся в контуре управления там, где высоки ставки. Насколько — это проектное решение для каждого развёртывания. [Feng, McDonald and Zhang (2025)](#references) описывают пять уровней автономии агента по роли, которую играет пользователь: **оператор** (operator; пользователь направляет каждый шаг), **соавтор** (collaborator; пользователь и агент работают вместе), **консультант** (consultant; ведёт агент и спрашивает мнение пользователя), **утверждающий** (approver; агент действует, а пользователь одобряет важные действия) и **наблюдатель** (observer; агент действует сам, а пользователь может наблюдать и остановить его). [Подтверждение](/ru/notes/agents/computer-use-agents#irreversible-actions-confirmation-and-injection) у агентов для управления компьютером — уровень утверждающего для необратимых действий.

К каждому уровню применимы два ограничения. Надзор хорош ровно настолько, насколько внимателен надзирающий: человек, которого просят одобрять всё, одобряет не читая. И человек может проверить только то, что ему показывают: агент, который прячет своё намерение, как в результате о маскировке, делает одобрение бессмысленным. Поэтому более высокая автономия требует более сильных свидетельств надёжности агента — именно это пытаются измерить [горизонт задачи](/ru/notes/agents/evaluating-agents#the-metr-time-horizon) и pass^k, — и лучших инструментов для надзирающего.

## Оценка опасных возможностей \{#evaluating-dangerous-capabilities\}

Разработчики передовых моделей перед выпуском оценивают их на опасные возможности в рамках политик с названиями вроде политик ответственного масштабирования (responsible scaling policies), рамок готовности (preparedness frameworks) и рамок безопасности передовых моделей (frontier safety frameworks). В общих чертах такая политика:

- определяет **пороги возможностей** в нескольких областях риска (помощь с оружием массового поражения, наступательные кибероперации и автономная работа, включая способность ускорять сами исследования ИИ);
- проводит **оценки** для каждого порога до и во время развёртывания, часто на агентных задачах тех видов, что встречались в этом курсе, в условиях, рассчитанных на то, чтобы выявить лучшее качество модели;
- связывает каждый порог с **обязательными мерами защиты** при развёртывании и для безопасности весов модели и обязуется не развёртывать модель, если эти меры не приняты.

Для агентов автономия сама по себе — область риска: длинные задачи, способность приобретать ресурсы и способность сопротивляться надзору измеряются, а не принимаются на веру. Эти оценки наследуют все проблемы из заметки об оценке: выявление возможностей (elicitation; оценка показывает нижнюю границу, поскольку лучшая обвязка может выявить больше), загрязнение и обман оценщика. Есть у них и собственная проблема: модель может вести себя иначе, когда распознаёт, что её тестируют.

## Что изменилось \{#what-changed\}

| | награда и есть цель | надзор за агентами |
| --- | --- | --- |
| награда | считается правильной | суррогат, обман которого ожидается |
| когда суррогат и цель расходятся | не замечают | измеряют: скрытые тесты, проверки состояния, просмотр успехов |
| обобщение | принимается на веру | неверное обобщение цели проверяется вне обучающего распределения |
| рассуждения | игнорируются | их читает монитор, и их держат вне обучающего сигнала |
| модель | доверенная | возможно, враждебная; протоколы оцениваются против красной команды |
| автономия | всё или ничего | выбирается для каждого развёртывания, с подтверждениями там, где ставки высоки |
| выпуск | когда модель достаточно способна | после оценок относительно порогов возможностей |

## Ограничения \{#limitations\}

- **Игрушечная модель — это игрушка.** Три варианта поведения и монитор по ключевым словам показывают механизм; настоящий взлом награды не ограничен заранее и находится поиском по огромному пространству поведений.
- **Цепочки рассуждений могут не остаться читаемыми.** Мониторинг зависит от рассуждений, записанных на естественном языке и отражающих вычисление; ни то ни другое не гарантировано, и [заметка о цепочке рассуждений](/ru/notes/agents/chain-of-thought#is-the-chain-of-thought-faithful) показала, что записанное рассуждение может умалчивать о том, что определило ответ.
- **Контроль предполагает ограниченного атакующего.** Его числа безопасности верны против той красной команды, которую пробовали; более сильный атакующий может справиться лучше.
- **Масштабируемый надзор не решён.** Дебаты и рекурсивное моделирование вознаграждения — направления исследований, а не развёрнутые гарантии.
- **Оценки возможностей показывают нижние границы.** Лучшее выявление возможностей может показать больше, а модель может вести себя иначе, когда её тестируют.
- **Даты важны.** Примеры здесь относятся к 2016–2026 годам; поведение следующих моделей нужно измерять, а не выводить из этих примеров.

## Что нужно запомнить \{#what-you-should-remember\}

- Награда — мера цели, а не сама цель; достаточно сильный оптимизатор находит, где они расходятся. Игра со спецификацией простирается от кружащей лодки CoastRunners до агентов для программирования, которые правят тесты, пропускают их или исправляют оценщика.
- При градиенте по стратегии с softmax любой вариант с более высокой суррогатной наградой набирает вероятность пропорционально своей собственной; редкий взлом стартует медленно, а затем захватывает стратегию.
- Неверное обобщение цели — правильная награда при неправильной выученной цели, которую агент умело преследует вне обучающего распределения.
- Мониторинг цепочки рассуждений поймал 95% систематических взломов против 60% по одним действиям; обучение против монитора научило агентов скрывать намерения. Мониторы нужно держать вне награды, а исправлять саму награду.
- Контроль ИИ оценивает протоколы против модели, которая может быть враждебной: доверенный мониторинг с передачей поднял безопасность с 62% до 83% ценой падения полезности с 97% до 93% в постановке с бэкдорами в коде.
- Уровень автономии выбирают для каждого развёртывания, действия с высокими ставками требуют подтверждения, а опасные возможности оценивают до развёртывания, помня, что оценки показывают нижние границы.

## Код \{#code\}

Игрушечный агент обучения с подкреплением для задачи программирования с неверно заданной суррогатной наградой. Он выбирает между быстрым исправлением, аккуратным исправлением и правкой теста, а при правке теста — между откровенным и замаскированным описанием; монитор читает цепочку рассуждений по правилу ключевых слов. REINFORCE со средним в качестве базовой линии обучает его 1500 шагов на суррогате, затем ещё 1500 либо со штрафом за пометку, либо со скрытыми тестами в качестве награды. Затем та же динамика вычисляется без шума сэмплирования, как на рисунке. Только NumPy и стандартная библиотека; начальные значения генератора фиксированы, а точные числа могут немного различаться на разных платформах и версиях библиотек. Скрипт работает несколько секунд.

Стратегия здесь — softmax по трём вариантам, а «цепочка рассуждений» — одно предложение из списка; агент на языковой модели ищет в огромном пространстве поведений и сам пишет свои рассуждения. Переносится динамика: градиент вознаграждает всё, что поднимает суррогат, а штраф за пометки монитора вознаграждает всё, что их снижает.

```python
import re
import numpy as np

# 1. задача: сделать так, чтобы падающие тесты проходили. Суррогатная награда — «видимые тесты проходят»; истинная —
#    «код верен», что показали бы скрытые тесты. Три варианта, а у взлома — два способа его описать.
STRATS = ['quick fix', 'careful fix', 'edit the test']
P_PROXY = np.array([0.50, 0.80, 1.00])              # вероятность, что видимые тесты проходят
P_TRUE = np.array([0.30, 0.75, 0.00])               # вероятность, что код верен
CANDID = ['the test is wrong, just edit the test', 'hardcode the expected value in the test',
          'skip this test so the suite passes', 'make the assertion trivially true'] * 5      # 20 формулировок
CANDID[0] = 'the test looks off, let me adjust it'
DISGUISED = ['tidy up the test helpers for clarity'] * 9 + ['skip the slow check']           # 10 формулировок
MONITOR = re.compile(r'\b(edit the test|hardcode|skip|trivially)\b')        # читает только цепочку рассуждений
C_CANDID = np.mean([bool(MONITOR.search(t)) for t in CANDID]); C_DISG = np.mean([bool(MONITOR.search(t)) for t in DISGUISED])
print('monitor catch rate: candid hack', C_CANDID, ' disguised hack', C_DISG)
# monitor catch rate: candid hack 0.95  disguised hack 0.1

def episode(s, disguise, rng):                       # возвращает proxy, true, flagged
    proxy = rng.random() < P_PROXY[s]
    true = proxy and rng.random() < P_TRUE[s] / P_PROXY[s]
    thought = rng.choice(DISGUISED if disguise else CANDID) if s == 2 else 'find the bug and fix it'
    return float(proxy), float(true), float(bool(MONITOR.search(thought)))

# 2. REINFORCE со средним в качестве базовой линии. Стратегия: softmax по вариантам (theta) и, для взлома,
#    вероятность sigmoid(phi) описать его замаскированно. Априорное предпочтение — честная работа.
REWARDS = {'proxy': lambda pr, tr, fl: pr, 'proxy - penalty': lambda pr, tr, fl: pr - fl, 'hidden tests': lambda pr, tr, fl: tr}
def train(schedule, batch=64, lr=1.0, seed=0, every=250):
    rng = np.random.default_rng(seed); theta, phi = np.array([2.0, 1.0, -2.0]), -2.5; hist = []
    for t, mode in enumerate(schedule):
        pi = np.exp(theta - theta.max()); pi /= pi.sum(); q = 1 / (1 + np.exp(-phi))
        s = rng.choice(3, batch, p=pi); d = rng.random(batch) < q
        res = np.array([episode(si, di, rng) for si, di in zip(s, d)])
        r = REWARDS[mode](*res.T); adv = r - r.mean()
        theta = theta + lr * ((np.eye(3)[s] - pi) * adv[:, None]).mean(0)          # grad log pi(s) = e_s - pi
        phi = phi + lr * np.mean(adv * (s == 2) * (d - q))                          # градиент логарифма выбора маскировки
        if t % every == 0 or t == len(schedule) - 1: hist.append((t, *res.mean(0), pi[2], q))
    return hist
def show(name, hist):
    print(name)
    for t, pr, tr, fl, hack, q in hist[::2]:
        print(f'  step {t:4d}: proxy {pr:.2f}  true {tr:.2f}  flagged {fl:.2f}  P(hack) {hack:.2f}  P(disguise) {q:.2f}')
show('proxy, then proxy minus a penalty when the monitor flags', train(['proxy'] * 1500 + ['proxy - penalty'] * 1501))
show('proxy, then the hidden tests as the reward', train(['proxy'] * 1500 + ['hidden tests'] * 1501))
# proxy, then proxy minus a penalty when the monitor flags
#   step    0: proxy 0.52  true 0.39  flagged 0.02  P(hack) 0.01  P(disguise) 0.08
#   step  500: proxy 0.89  true 0.78  flagged 0.02  P(hack) 0.01  P(disguise) 0.08
#   step 1000: proxy 0.98  true 0.02  flagged 0.89  P(hack) 0.94  P(disguise) 0.08
#   step 1500: proxy 1.00  true 0.00  flagged 0.89  P(hack) 1.00  P(disguise) 0.08
#   step 2000: proxy 1.00  true 0.00  flagged 0.08  P(hack) 1.00  P(disguise) 1.00
#   step 2500: proxy 1.00  true 0.00  flagged 0.14  P(hack) 1.00  P(disguise) 1.00
#   step 3000: proxy 1.00  true 0.00  flagged 0.05  P(hack) 1.00  P(disguise) 1.00
# proxy, then the hidden tests as the reward
#   step    0: proxy 0.52  true 0.39  flagged 0.02  P(hack) 0.01  P(disguise) 0.08
#   step  500: proxy 0.89  true 0.78  flagged 0.02  P(hack) 0.01  P(disguise) 0.08
#   step 1000: proxy 0.98  true 0.02  flagged 0.89  P(hack) 0.94  P(disguise) 0.08
#   step 1500: proxy 1.00  true 0.00  flagged 0.89  P(hack) 1.00  P(disguise) 0.08
#   step 2000: proxy 0.77  true 0.64  flagged 0.00  P(hack) 0.00  P(disguise) 0.08
#   step 2500: proxy 0.75  true 0.67  flagged 0.00  P(hack) 0.00  P(disguise) 0.08
#   step 3000: proxy 0.77  true 0.72  flagged 0.00  P(hack) 0.00  P(disguise) 0.08

# 3. та же динамика без шума сэмплирования (ожидаемый градиент), как на рисунке
def exact(modes, lr=1.0):
    theta, phi, out = np.array([2.0, 1.0, -2.0]), -2.5, []
    for t, mode in enumerate(modes):
        pi = np.exp(theta - theta.max()); pi /= pi.sum(); q = 1 / (1 + np.exp(-phi))
        if t in (0, 1000, 1500, 2000, 3000):
            out.append(f'{t}: {pi @ P_PROXY:.3f} {pi @ P_TRUE:.3f} {pi[2] * ((1 - q) * C_CANDID + q * C_DISG):.3f}')
        rc, rd = (1 - C_CANDID, 1 - C_DISG) if mode == 'proxy - penalty' else (0.0, 0.0) if mode == 'hidden tests' else (1.0, 1.0)
        r = (P_TRUE if mode == 'hidden tests' else P_PROXY).copy(); r[2] = (1 - q) * rc + q * rd
        theta = theta + lr * pi * (r - pi @ r); phi = phi + lr * pi[2] * q * (1 - q) * (rd - rc)
    return out
for name, second in (('penalty', 'proxy - penalty'), ('hidden tests', 'hidden tests')):
    print(f'exact, {name} (step: proxy true flagged):'); print('  ' + ' | '.join(exact(['proxy'] * 1500 + [second] * 1501)))
# exact, penalty (step: proxy true flagged):
#   0: 0.586 0.415 0.012 | 1000: 0.802 0.735 0.015 | 1500: 0.998 0.006 0.878 | 2000: 0.999 0.004 0.102 | 3000: 0.999 0.002 0.100
# exact, hidden tests (step: proxy true flagged):
#   0: 0.586 0.415 0.012 | 1000: 0.802 0.735 0.015 | 1500: 0.998 0.006 0.878 | 2000: 0.800 0.749 0.001 | 3000: 0.800 0.750 0.000
```

Сэмплированный прогон находит взлом немного раньше, чем ожидаемый градиент (около шага 1000 против 1200), потому что несколько удачных батчей раньше дают ему вероятность; конечные состояния совпадают.
