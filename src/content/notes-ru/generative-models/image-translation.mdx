Вот четыре запроса, которые может получить модель перевода. Перерисовать эту кошку в собаку и показать несколько разных собак. Превратить эту лошадь в зебру, не обучая вторую сеть для обратного превращения. Отрисовать фотографию по карте, на которой написано «здесь небо, там дорога, слева машина». Сделать эту миниатюру $64 \times 64$ резкой в разрешении $256 \times 256$.

[StarGAN v2](/ru/notes/generative-models/stargan) ответил на первый запрос кодом стиля и циклом. **MUNIT** отвечает на него, разделяя изображение на содержание и стиль, **CUT** отвечает на второй контрастной функцией потерь между фрагментами, а **SPADE** на третий — позволяя карте меток перестраивать каждый слой. Сверхразрешение (super-resolution) сталкивается со старейшей проблемой перевода: изображение с наименьшей попиксельной ошибкой — это размытое среднее всех правдоподобных ответов.

## MUNIT: одно пространство содержания, по пространству стилей на домен \{#munit-one-content-space-a-style-space-per-domain\}

### Два автоэнкодера с общим кодом содержания \{#two-autoencoders-with-a-shared-content-code\}

MUNIT ([Huang et al., 2018](#references)) предполагает, что изображение домена $i$ составлено из двух кодов. **Код содержания** (content code) $c$ общий для обоих доменов и описывает пространственную структуру, например позу и расположение кошки. **Код стиля** (style code) $s_i$ свой у каждого домена и описывает отрисовку, например шерсть и окрас. Соответствующие изображения имели бы вид $x_1 = G^*_1(c, s_1)$ и $x_2 = G^*_2(c, s_2)$ с одним и тем же $c$. Поскольку $s_2$ случаен, у одного $x_1$ целое распределение переводов.

У каждого домена $i$ есть энкодер содержания $E^c_i$, энкодер стиля $E^s_i$ и декодер $G_i$. Перевод сохраняет содержание и меняет декодер:

$$
\begin{aligned}
x_{1 \to 2} &= G_2\big(E^c_1(x_1),\, s_2\big), \\
s_2 &\sim \mathcal N(0, I).
\end{aligned}
$$

Новый $s_2$ даёт новый выход. Если взять $s_2 = E^s_2(x_2)$ с настоящего изображения целевого домена, получится перевод по образцу (example-guided translation), который копирует стиль образца.

Коды разделяет во многом их форма. Содержание — карта признаков $64 \times 64 \times 256$ для изображения $256 \times 256$, вычисленная с нормализацией по экземпляру (instance normalization). Эта нормализация убирает среднее и разброс каждого канала — статистики, которые несут значительную часть стиля. Стиль — вектор из 8 чисел после глобального усредняющего пулинга, без пространственного расположения и без нормализации по экземпляру. Декодер встраивает стиль через [AdaIN](/ru/notes/generative-models/stylegan#styles-through-adain), а масштабы и сдвиги вычисляет по $s$ MLP.

### Функции потерь в пространстве изображений и в латентном пространстве \{#losses-in-image-and-latent-space\}

MUNIT обучает энкодеры и декодеры быть обратными друг к другу в обоих направлениях. Пусть $c_1 = E^c_1(x_1)$ для настоящего $x_1$ и $s_2 \sim \mathcal N(0, I)$:

$$
\begin{aligned}
\mathcal L^{x_1}_{\mathrm{recon}} &= \mathbb E\, \big\|G_1\big(E^c_1(x_1), E^s_1(x_1)\big) - x_1\big\|_1, \\
\mathcal L^{c_1}_{\mathrm{recon}} &= \mathbb E\, \big\|E^c_2\big(G_2(c_1, s_2)\big) - c_1\big\|_1, \\
\mathcal L^{s_2}_{\mathrm{recon}} &= \mathbb E\, \big\|E^s_2\big(G_2(c_1, s_2)\big) - s_2\big\|_1,
\end{aligned}
$$

а также те же три слагаемых с переставленными доменами и состязательные функции потерь наименьших квадратов, в которых $D_2$ отличает настоящие изображения второго домена от переводов $G_2(c_1, s_2)$. Веса: $\lambda_x = 10$ для слагаемых по изображениям и $\lambda_c = \lambda_s = 1$ для слагаемых по содержанию и стилю.

Реконструкция изображения делает каждую пару $(E_i, G_i)$ автоэнкодером своего домена. Реконструкция содержания привязывает выход к входу: энкодер целевого домена должен прочитать $c_1$ обратно по $x_{1 \to 2}$. Реконструкция стиля заставляет перевод использовать $s_2$. Без неё декодер игнорировал бы этот код, как генератор pix2pix научился игнорировать шум, поданный рядом с входным изображением ([Isola et al., 2017](#references), раздел 3.1).

### Почему у MUNIT нет цикловой функции потерь \{#why-munit-has-no-cycle-loss\}

Цикловая функция потерь вынуждает перевод быть детерминированным ([Huang et al., 2018](#references), предложение 5). Пусть перевод случаен в обоих направлениях, переводы попадают в другой домен и оба цикла выполняются точно: любой выход $x_1$, переведённый обратно, возвращает $x_1$, а любой выход $x_2$, переведённый обратно, возвращает $x_2$.

Пусть $a$ и $b$ — два возможных перевода одного входа $x^*_1$. Любой обратный перевод $a$ в первый домен равен $x^*_1$ по прямому циклу из $x^*_1$. Тогда любой прямой перевод этого $x^*_1$ должен вернуть $a$ по обратному циклу из $a$. Но $x^*_1$ может дать и $b$. Значит, $a = b$, и у перевода единственный выход. Это формальная версия [одного выхода на вход](/ru/notes/generative-models/cyclegan#limitations) у CycleGAN.

MUNIT сохраняет более слабый цикл, который переносит стиль с собой (предложение 4). Переведём $x_1$ со случайным $s_2$, а затем обратно с собственным стилем оригинала $E^s_1(x_1)$: получится $x_1$. Этот **цикл, дополненный стилем** (style-augmented cycle), выполняется в оптимуме функций потерь реконструкции. Цикл StarGAN v2, который возвращается со стилем входа $E_y(x)$, — та же идея.

### Где это ломается: разнообразие, которое оказывается шумом \{#where-it-breaks-diversity-that-is-noise\}

На задаче границы → обувь Huang et al. измеряли разнообразие средним расстоянием [LPIPS](/ru/notes/generative-models/lpips#where-it-is-used) между выходами для одного и того же входа, а качество — долей оценщиков, которые предпочли выход метода выходу MUNIT, так что сам MUNIT получает 50% (таблица 1):

| Метод | Качество | Разнообразие |
| --- | --- | --- |
| CycleGAN | 36.0% | 0.010 |
| MUNIT без реконструкции изображения | 6.0% | 0.213 |
| MUNIT без реконструкции стиля | 28.6% | 0.070 |
| MUNIT | 50.0% | 0.109 |
| настоящая обувь | – | 0.293 |

CycleGAN почти не меняет свои выходы. Без реконструкции стиля многие выходы почти одинаковы: декодер учится игнорировать бо́льшую часть $s$. Самая разнообразная модель из абляционного исследования оказывается худшей. Без реконструкции изображения выходы различаются вдвое сильнее, чем у MUNIT, а предпочитают их лишь в 6% сравнений: артефакты делают выходы непохожими, и метрика разнообразия их засчитывает. Число разнообразия что-то значит только рядом с числом качества.

## CUT: контрастная функция потерь вместо цикла \{#cut-replacing-the-cycle-with-a-contrastive-loss\}

### Зачем отказываться от цикла? \{#why-drop-the-cycle\}

Цикл предполагает, что два домена находятся во взаимно однозначном соответствии, а многие домены ему не подчиняются: фотография содержит больше, чем её карта меток, а лошадь может стать многими зебрами. К тому же цикл стоит второго генератора и второго дискриминатора, которые лишь проверяют первые. CUT ([Park et al., 2020](#references)) оставляет один генератор, $\hat y = G(x)$, и требует связи другого рода: фрагмент выхода должен указывать, из какого фрагмента входа он получился. Лоб зебры должен прослеживаться до лба лошади и больше ни до чего на фотографии.

На языке теории информации у соответствующих фрагментов входа и выхода должна быть большая взаимная информация (mutual information). Поскольку $I(X; \hat Y) = H(X) - H(X \mid \hat Y)$, а $H(X)$ не зависит от $G$, это то же самое, что сделать вход легко восстановимым по выходу, — цель, которой цикл добивается через вторую сеть. CUT добивается её напрямую, с помощью контрастной оценки.

### InfoNCE: выбрать позитивный пример среди негативных \{#infonce-pick-the-positive-among-negatives\}

**InfoNCE** ([van den Oord, Li and Vinyals, 2018](#references)) превращает вопрос «связан ли $v^+$ с $v$?» в классификацию. **Запрос** (query) $v$, его **позитивный пример** (positive) $v^+$ и $N$ **негативных примеров** (negatives) $v^-_1, \dots, v^-_N$ — единичные векторы в $\mathbb R^K$, и softmax по их скалярным произведениям должен выбрать позитивный пример:

$$
\ell(v, v^+, v^-) = -\log \frac{e^{v \cdot v^+ / \tau}}{e^{v \cdot v^+ / \tau} + \sum_{n=1}^{N} e^{v \cdot v^-_n / \tau}} .
$$

Это кросс-энтропия для классификации с $(N + 1)$ вариантами и температурой $\tau = 0.07$. Она — многоклассовый родственник [шумоконтрастного оценивания](/ru/notes/generative-models/energy-based-models#noise-contrastive-estimation-learning-z-by-classification) (noise-contrastive estimation, NCE), которое отличает данные от шума логистической регрессией.

Почему низкое значение функции потерь означает зависимость? Если бы кандидаты не несли никакой информации о запросе, позитивный пример был бы так же вероятен, как любой негативный, и лучший классификатор мог бы выдать для него только $1/(N + 1)$, то есть функцию потерь $\log(N + 1)$. Van den Oord et al. превращают это в оценку $I(v; v^+) \ge \log(N + 1) - \mathbb E\,\ell$. Они выводят её в приложении A.1 с приближением, которое становится точным с ростом $N$. Значение функции потерь намного ниже уровня случайного угадывания требует взаимной информации.

**Разобранный пример (игрушечные числа).** Косинус запроса с позитивным примером равен $0.5$, а с тремя негативными — $0.45$, $0.2$ и $-0.1$. При $\tau = 1$ softmax даёт позитивному примеру вероятность всего $0.309$, и функция потерь равна $1.176$, что близко к уровню случайного угадывания $\log 4 = 1.386$. При $\tau = 0.07$ разрыв $0.05$ между позитивным примером и ближайшим негативным превращается в логитах в $0.71$, и позитивный пример получает $0.665$, а функция потерь равна $0.408$. Малая температура делает функцию потерь чувствительной к малым различиям сходства, и в градиенте доминирует самый трудный негативный пример.

### PatchNCE: соответствующие фрагменты, негативные примеры из того же изображения \{#patchnce-corresponding-patches-negatives-from-the-same-image\}

CUT применяет InfoNCE к фрагментам нескольких масштабов. Энкодерная половина генератора, $G_{\mathrm{enc}}$, вычисляет стопку карт признаков, и каждая позиция карты слоя $l$ описывает фрагмент входа; более глубокие слои описывают более крупные фрагменты. CUT берёт $L = 5$ слоёв, от RGB-пикселей до пятого остаточного блока. Небольшой двухслойный MLP $H_l$, свой для каждого слоя, отображает каждый вектор признаков в единичный вектор, как проекционная голова [SimCLR](/ru/notes/deep-learning/self-supervised-learning#simclr-two-views-an-encoder-and-a-projection-head).

Один и тот же энкодер встраивает вход и выход: $z_l = H_l(G^l_{\mathrm{enc}}(x))$ и $\hat z_l = H_l(G^l_{\mathrm{enc}}(\hat y))$. В $S_l = 256$ случайных позициях $s$ каждого слоя признак выхода $\hat z^s_l$ служит запросом, признак входа в той же позиции $z^s_l$ — позитивным примером, а признаки входа в остальных 255 позициях $z^{S \setminus s}_l$ — негативными:

$$
\mathcal L_{\mathrm{PatchNCE}} = \mathbb E_{x} \sum_{l=1}^{L} \sum_{s=1}^{S_l} \ell\big(\hat z^s_l,\, z^s_l,\, z^{S \setminus s}_l\big).
$$

Негативные примеры берутся из того же входного изображения. Нога зебры на выходе должна быть ближе к ноге лошади в той же позиции, чем к спине лошади, небу или траве той же фотографии. Негативные примеры из других изображений работали хуже: с ними энкодеру пришлось бы моделировать различия между изображениями, безразличные для перевода, например между белыми и гнедыми лошадьми.

Что мешает генератору схитрить? Если бы выход не сохранял никакого следа входа, $\hat z^s_l$ был бы так же близок к негативному примеру, как к позитивному, и функция потерь держалась бы около $\log 256 = 5.545$ на запрос. Энкодер сам учится тому, что значит «соответствующий» при переходе между доменами: сопоставлять формы и части, а текстуры не учитывать. Фиксированное расстояние между $x$ и $\hat y$ штрафовало бы сами полосы.

### Целевая функция и FastCUT \{#the-objective-and-fastcut\}

Генератор и MLP минимизируют

$$
\begin{aligned}
&\mathcal L_{\mathrm{GAN}}(G, D) + \lambda_X\, \mathcal L_{\mathrm{PatchNCE}}(G, H, X) \\
&\quad + \lambda_Y\, \mathcal L_{\mathrm{PatchNCE}}(G, H, Y),
\end{aligned}
$$

а дискриминатор ведёт состязательную игру. Последнее слагаемое пропускает через $G$ настоящие изображения $y$ целевого домена и требует, чтобы $G(y)$ пофрагментно соответствовало $y$. Это контрастная версия [функции потерь тождественного отображения](/ru/notes/generative-models/cyclegan#identity-loss) из CycleGAN. CUT использует $\lambda_X = \lambda_Y = 1$; FastCUT убирает второе слагаемое и даёт первому вес 10. Сети и обучение взяты из CycleGAN.

На задаче лошадь → зебра FID падает с 77.2 у CycleGAN до 45.5 у CUT, а итерация занимает 0.24 с вместо 0.40 ([Park et al., 2020](#references), таблица 1).

### Где это ломается: подгонка под статистики целевого домена \{#where-it-breaks-matching-the-statistics-of-the-target\}

Без цикла CUT может менять изображение сильнее и пользуется этой свободой, чтобы подогнать выход под статистики целевого домена. На обучающих фотографиях задачи лошадь → зебра зебры занимают 36.8% пикселей, а лошади — 17.9%. Переводы CUT увеличивают животных до 30.8% пикселей, CycleGAN оставляет их на уровне 19.1% (приложение C.4). Состязательная функция потерь видит, что на настоящих фотографиях зебр в основном зебра, а PatchNCE ничем не запрещает фрагменту лошади покрываться полосами за пределами её контура.

Это помогает в задаче кошка → собака, где нужны изменения формы, и вредит в задаче лошадь → зебра, когда полосы появляются на фоне. Внутренние негативные примеры добавляют вторую цену: два фрагмента одного неба похожи, но один служит негативным примером для другого, и функция потерь их расталкивает.

## Семантический синтез изображений по карте меток \{#semantic-image-synthesis-from-a-label-map\}

**Семантический синтез изображений** (semantic image synthesis) превращает маску сегментации $m$ — метку класса для каждого пикселя — в фотографию. Обучающие данные — пары из фотографии и её маски, так что задача, как у pix2pix, решается обучением с учителем. Нового здесь две вещи: маски уличных сцен имеют размер $2048 \times 1024$, а маска состоит в основном из больших однородных областей, которые стираются слоями нормализации стандартного генератора.

### pix2pixHD: многомасштабные дискриминаторы и сопоставление признаков \{#pix2pixhd-multi-scale-discriminators-and-feature-matching\}

**pix2pixHD** ([Wang et al., 2018a](#references)) достигает $2048 \times 1024$ с помощью генератора «от грубого к точному» (coarse-to-fine): глобальная сеть работает при половинном разрешении, а локальный улучшитель (local enhancer) удваивает его.

Чтобы судить такое изображение, нужно большое рецептивное поле, а более глубокий дискриминатор даёт его дорогой ценой. Вместо этого pix2pixHD запускает три одинаковых PatchGAN $70 \times 70$ на изображении, уменьшенном в 1, 2 и 4 раза. То же окно покрывает в четыре раза более широкую область самого грубого изображения, поэтому $D_3$ судит о глобальной структуре, а $D_1$ — о мелких деталях. С одним дискриминатором авторы видели повторяющиеся узоры.

Генератор должен также совпадать с настоящей фотографией $x$ по внутренним признакам дискриминаторов:

$$
\begin{aligned}
\mathcal L_{\mathrm{FM}}(G, D_k) = \mathbb E_{(m, x)} \sum_{i=1}^{T} \frac{1}{N_i}\, \Big\| & D^{(i)}_k(m, x) \\
& - D^{(i)}_k\big(m, G(m)\big)\Big\|_1 ,
\end{aligned}
$$

где $D^{(i)}_k$ — слой $i$ дискриминатора $k$, содержащий $N_i$ элементов, а дискриминатор видит маску вместе с изображением. Вес равен $\lambda = 10$, функции потерь GAN — наименьших квадратов. Это перцептивная функция потерь (perceptual loss) с признаками, выученными на этих же данных, и ей нужны пары.

### Как нормализация смывает карту меток \{#how-normalization-washes-out-the-label-map\}

pix2pixHD подаёт маску в виде one-hot-векторов на первый слой генератора, а генератор после каждой свёртки применяет нормализацию по экземпляру. Нормализация вычитает среднее каждого канала по позициям и делит на его разброс. Маска кусочно-постоянна, поэтому после одной свёртки большая часть её информации заключена именно в этих статистиках ([Park et al., 2019](#references)).

Однородная маска стирается. Пусть у всех пикселей одна и та же метка. Свёртка постоянного входа постоянна вдали от границ, а при дополнении отражением — везде: канал $c$ содержит одно значение $a_c$ во всех позициях. Нормализация по экземпляру делит на $\sqrt{\sigma^2 + \varepsilon}$ с малым $\varepsilon > 0$, а здесь $\sigma = 0$, так что канал превращается в $(a_c - a_c)/\sqrt{\varepsilon} = 0$, какой бы ни была метка. Маска «вся трава» и маска «всё небо» дают одинаковые активации. Из-за этого же эффекта StarGAN [дополняет нулями](/ru/notes/generative-models/stargan#how-the-generator-reads-the-label).

**Разобранный пример (игрушечные числа).** Маска — небо на доле $p$ пикселей и трава на остальных. После свёртки $1 \times 1$ канал содержит $a_{\mathrm{sky}}$ на небе и $a_{\mathrm{grass}}$ на траве. Его среднее равно $p\,a_{\mathrm{sky}} + (1 - p)\,a_{\mathrm{grass}}$, а стандартное отклонение — $\sqrt{p(1 - p)}\,|a_{\mathrm{sky}} - a_{\mathrm{grass}}|$, поэтому при $a_{\mathrm{sky}} > a_{\mathrm{grass}}$ нормализация по экземпляру даёт

$$
\begin{aligned}
\text{небо:}\quad & +\sqrt{(1 - p)/p}, \\
\text{трава:}\quad & -\sqrt{p/(1 - p)} .
\end{aligned}
$$

При $p = \tfrac14$ значения равны $1.732$ и $-0.577$ — одинаково для весов $(2, -1)$, $(0.3, 0.1)$ и $(5, 4)$. Каждый канал сохраняет расположение, то есть где проходит граница и какая область больше, и теряет величину разности. Конкатенация маски со входом каждого слоя этого не исправляет, поскольку каждая копия снова проходит свёртку и нормализацию.

### SPADE: попиксельные масштаб и сдвиг по маске \{#spade-per-pixel-scale-and-shift-from-the-mask\}

**SPADE** (spatially-adaptive denormalization, пространственно-адаптивная денормализация; [Park et al., 2019](#references)) впускает маску после нормализации, где её уже ничто не может убрать. Активации $h$ слоя нормализуются без обучаемых параметров, поканальным средним $\mu_c$ и стандартным отклонением $\sigma_c$ по батчу и всем позициям, как в [батч-нормализации](/ru/notes/deep-learning/normalization-and-initialization#batch-normalization-in-training-and-in-evaluation) (batch normalization). Затем карты, вычисленные по маске, масштабируют и сдвигают их:

$$
\mathrm{SPADE}(h, m)_{n, c, y, x} = \gamma_{c, y, x}(m)\, \frac{h_{n, c, y, x} - \mu_c}{\sigma_c} + \beta_{c, y, x}(m).
$$

В батч-нормализации $\gamma_c$ и $\beta_c$ — по одному обучаемому числу на канал, а в AdaIN $\gamma_c(s)$ и $\beta_c(s)$ зависят от вектора стиля, но не от позиции. У масштаба и сдвига SPADE есть пространственные измерения: своё значение в каждом пикселе, определяемое метками вокруг него. Их вычисляет небольшая свёрточная сеть по маске, приведённой к разрешению слоя: свёртка $3 \times 3$ с ReLU, а затем две свёртки $3 \times 3$ для $\gamma$ и $\beta$.

<SpadeFlow />

Однородная маска теперь даёт однородные, но зависящие от метки $\gamma$ и $\beta$, так что небо и трава различаются. Маска входит в каждый слой, поэтому генератору не нужен для неё энкодер: он повышает разрешение случайного вектора через остаточные блоки со SPADE, и этот вектор делает синтез мультимодальным.

Функции потерь взяты из pix2pixHD, только наименьшие квадраты заменены кусочно-линейной функцией потерь (hinge loss). На COCO-Stuff проверка сегментацией на сгенерированных фотографиях даёт средний IoU 37.4 против 14.6 у pix2pixHD ([Park et al., 2019](#references), таблица 1). В абляционном исследовании тот же декодер достигает 35.2 со SPADE и 31.9 с маской, конкатенированной на каждом слое (таблица 3): важно то, где входит маска.

## Сверхразрешение: почему среднее выглядит размытым \{#super-resolution-why-the-average-looks-blurry\}

### Оптимум MSE — условное среднее \{#the-mse-optimum-is-the-conditional-mean\}

**Сверхразрешение по одному изображению** (single-image super-resolution) восстанавливает изображение высокого разрешения $x^{\mathrm{HR}}$ по уменьшенному $x^{\mathrm{LR}}$, обычно в $4\times$ по каждой стороне, так что на каждый пиксель входа приходится 16 пикселей выхода. Обучающие пары достаются даром: достаточно уменьшить любую фотографию. Трудность в функции потерь. Одно изображение низкого разрешения согласуется со многими изображениями высокого разрешения, которые различаются именно той мелкой текстурой, которую удалило уменьшение.

Выход, минимизирующий ожидаемую квадратичную ошибку для данного входа, — это [условное среднее](/ru/notes/probability/conditional-expectation#the-best-predictor) $\mu = \mathbb E[x^{\mathrm{HR}} \mid x^{\mathrm{LR}}]$, а его ожидаемая ошибка равна суммарной условной дисперсии $\operatorname{tr} \operatorname{Cov}(x^{\mathrm{HR}} \mid x^{\mathrm{LR}})$. **PSNR** (peak signal-to-noise ratio, пиковое отношение сигнала к шуму), стандартная метрика сверхразрешения, определяется как $10 \log_{10}(\text{peak}^2/\mathrm{MSE})$ — убывающая функция MSE, поэтому оптимальный по PSNR выход — то же среднее. Когда правдоподобные ответы различаются текстурой, их среднее — гладкое изображение, не совпадающее ни с одним из них.

Даже идеальный генератор не может исправить значение метрики. Пусть $x'$ — сэмпл из истинного условного распределения, взятый независимо от $x^{\mathrm{HR}}$ при данном $x^{\mathrm{LR}}$. Запишем оба как отклонения от $\mu$ и раскроем квадрат; перекрёстный член обращается в нуль, потому что два отклонения независимы и имеют нулевое среднее:

$$
\begin{aligned}
\mathbb E\,\|x^{\mathrm{HR}} - x'\|^2
&= \mathbb E\,\|(x^{\mathrm{HR}} - \mu) - (x' - \mu)\|^2 \\
&= \mathbb E\,\|x^{\mathrm{HR}} - \mu\|^2 + \mathbb E\,\|x' - \mu\|^2 \\
&= 2 \operatorname{tr} \operatorname{Cov}(x^{\mathrm{HR}} \mid x^{\mathrm{LR}}) .
\end{aligned}
$$

У идеального сэмплера MSE ровно вдвое больше, чем у среднего, а PSNR на $10 \log_{10} 2 = 3.01$ дБ меньше — на любых данных. Метод, создающий реалистичную текстуру, обязан терять PSNR.

<MeanVsSample />

В игрушечном примере оптимум MSE — ровный серый цвет с MSE 0.25, а сэмпл — резкий полосатый узор с вдвое большей ошибкой. Функция потерь $L_1$ здесь не лучше: в каждом пикселе половина кандидатов равна 0, а половина — 1, поэтому любое значение между 0 и 1 — попиксельная медиана, в том числе ровные 0.5.

### SRGAN: функция потерь содержания на признаках VGG и состязательная функция потерь \{#srgan-a-vgg-content-loss-and-an-adversarial-loss\}

**SRGAN** ([Ledig et al., 2017](#references)) заменяет квадратичную ошибку **перцептивной функцией потерь** из двух частей:

$$
\begin{aligned}
l^{\mathrm{SR}} &= l^{\mathrm{SR}}_{\mathrm{VGG}} + 10^{-3}\, l^{\mathrm{SR}}_{\mathrm{Gen}}, \\
l^{\mathrm{SR}}_{\mathrm{VGG}} &= \frac{1}{WH} \sum_{u, v} \big(\varphi(x^{\mathrm{HR}})_{u,v} - \varphi(G(x^{\mathrm{LR}}))_{u,v}\big)^2 ,
\end{aligned}
$$

где $\varphi$ — глубокая карта признаков предобученной сети VGG19 размера $W \times H$, как в работе [Johnson, Alahi and Fei-Fei (2016)](#references), а $l^{\mathrm{SR}}_{\mathrm{Gen}} = -\log D(G(x^{\mathrm{LR}}))$ — [ненасыщающаяся](/ru/notes/generative-models/gans#which-generator-loss-is-used-in-practice) состязательная функция потерь. Глубокие признаки менее чувствительны к точным значениям пикселей, поэтому функция потерь содержания терпит текстуру, отличающуюся в деталях. Дискриминатор же толкает выход к естественным изображениям, среди которых среднее нескольких текстур не лежит.

На тестовом наборе BSD100 при $4\times$ 26 оценщиков ставили изображениям баллы от 1 (плохо) до 5 (отлично) ([Ledig et al., 2017](#references), таблица 2):

| | бикубическая интерполяция | SRResNet (MSE) | SRGAN | оригинал |
| --- | --- | --- | --- | --- |
| PSNR, дБ | 25.94 | 27.58 | 25.16 | ∞ |
| средний балл (mean opinion score) | 1.47 | 2.29 | 3.56 | 4.46 |

У SRGAN самый низкий PSNR, на 2.42 дБ ниже, чем у SRResNet, и ниже даже, чем у бикубической интерполяции, и намного лучший средний балл. Потеря PSNR того же порядка, что предсказывает рассуждение выше для сэмплера по сравнению со средним. PSNR упорядочивает эти методы неправильно, и поэтому перцептивные метрики, такие как [LPIPS](/ru/notes/generative-models/lpips), позднее подогнали к суждениям людей.

### ESRGAN: RRDB, релятивистский дискриминатор и признаки до активации \{#esrgan-rrdb-a-relativistic-discriminator-and-features-before-activation\}

**ESRGAN** ([Wang et al., 2018b](#references)) сохраняет устройство SRGAN и меняет каждую из трёх его частей. Генератор отказывается от батч-нормализации, статистики которой при обучении и тестировании расходятся и порождали артефакты, и вкладывает плотные блоки в два уровня остаточных связей. Перцептивная функция потерь берёт признаки VGG до ReLU, поскольку после неё на одном тестовом изображении активны лишь 11.17% признаков, то есть 88.83% равны нулю. Дискриминатор становится релятивистским усреднённым дискриминатором (relativistic average discriminator) из работы [Jolicoeur-Martineau (2018)](#references). Если $C$ — необработанный выход, он оценивает вероятность того, что настоящее изображение реалистичнее подделок батча в среднем:

$$
D_{\mathrm{Ra}}(x_r, x_f) = \sigma\big(C(x_r) - \mathbb E_{x_f}[C(x_f)]\big).
$$

Тогда функция потерь генератора содержит и настоящие изображения: по мере улучшения подделок настоящие изображения выглядят на их фоне менее настоящими. Наконец, **интерполяция сетей** (network interpolation) смешивает веса генератора, обученного на PSNR, и генератора, обученного как GAN, $\theta = (1 - \alpha)\,\theta_{\mathrm{PSNR}} + \alpha\,\theta_{\mathrm{GAN}}$, и позволяет во время тестирования обменивать PSNR на текстуру без повторного обучения.

Текстура, которую добавляют эти модели, правдоподобна, но выдумана. Для фотографии это допустимо, а там, где детали служат доказательством, недопустимо, как авторы SRGAN отмечают для медицинских изображений и видеонаблюдения.

## Что нужно запомнить \{#what-you-should-remember\}

- MUNIT: пространственный код содержания, общий для двух доменов, и стиль из 8 чисел для каждого домена; новый стиль даёт новый выход.
- Точный цикл при совпадающих маргинальных распределениях вынуждает один выход на вход; цикл, дополненный стилем, — нет.
- InfoNCE — кросс-энтропия с $(N + 1)$ вариантами; значение функции потерь намного ниже $\log(N + 1)$ требует взаимной информации.
- CUT: каждый фрагмент выхода должен выбрать свой фрагмент входа среди 255 других фрагментов того же изображения.
- Нормализация стирает однородную маску; SPADE ставит маску после неё, в виде попиксельных $\gamma(m)$ и $\beta(m)$.
- Оптимум MSE — условное среднее; у идеального сэмплера MSE вдвое больше, а PSNR на 3.01 дБ меньше.

## Код \{#code\}

Реализация функций потерь InfoNCE и PatchNCE на NumPy, проверенная на разобранном примере и на случайных признаках:

```python
import numpy as np

def info_nce(q, pos, negs, tau=0.07):
    """One query: unit vectors q, pos [K] and negs [N, K]; returns the loss and p(positive)."""
    logits = np.r_[q @ pos, negs @ q] / tau
    logits -= logits.max()
    p = np.exp(logits) / np.exp(logits).sum()
    return -np.log(p[0]), p[0]

def patch_nce(f_out, f_in, tau=0.07):
    """f_out, f_in: [S, K] unit features at S sampled locations of the output and the input.
    Query s is f_out[s]; its positive is f_in[s]; the other S - 1 input locations are its negatives."""
    logits = f_out @ f_in.T / tau                  # [S, S]; на диагонали стоят позитивные примеры
    logits -= logits.max(axis=1, keepdims=True)
    log_p = logits - np.log(np.exp(logits).sum(axis=1, keepdims=True))
    return -np.mean(np.diag(log_p))

unit = lambda a: a / np.linalg.norm(a, axis=-1, keepdims=True)

# разобранный пример: косинусы 0.5 (позитивный) и 0.45, 0.2, -0.1 (негативные), для наглядности в 2-D
q = np.array([1.0, 0.0])
cosv = lambda c: np.array([c, np.sqrt(1 - c * c)])
pos, negs = cosv(0.5), np.stack([cosv(c) for c in (0.45, 0.2, -0.1)])
for tau in (1.0, 0.07):
    loss, p = info_nce(q, pos, negs, tau)
    print(f"tau={tau}: p(positive)={p:.3f}, loss={loss:.3f}")
# tau=1.0: p(positive)=0.309, loss=1.176
# tau=0.07: p(positive)=0.665, loss=0.408

# 256 позиций с 256-мерными признаками: точная копия, зашумлённая копия, несвязанные признаки
rng = np.random.default_rng(0)
f_in = unit(rng.standard_normal((256, 256)))
for name, f_out in [("copy", f_in),
                    ("noisy copy", unit(f_in + 3.0 * unit(rng.standard_normal((256, 256))))),
                    ("unrelated", unit(rng.standard_normal((256, 256))))]:
    print(f"{name:>10}: PatchNCE = {patch_nce(f_out, f_in):.3f}")
print(f"log 256 = {np.log(256):.3f}")
#       copy: PatchNCE = 0.000
# noisy copy: PatchNCE = 1.725
#  unrelated: PatchNCE = 5.903
# log 256 = 5.545
```

У зашумлённой копии косинус с позитивным примером около 0.31. Позитивный пример — самый похожий кандидат для 255 из 256 запросов, и всё же softmax даёт ему в среднем вероятность лишь около 0.2, потому что 255 негативных примеров с косинусами около нуля делят между собой остальное: функция потерь продолжает давить, пока зазор не станет большим по сравнению с $\tau$. Несвязанные признаки дают около $\log 256$ или чуть больше, поскольку некоторые негативные примеры случайно оказываются похожее на запрос, чем его позитивный пример.
