Цветное изображение $256 \times 256$, прочитанное значение за значением, — это последовательность из $196\,608$ чисел. PixelCNN предсказывает каждое из них по фиксированной окрестности. Языковая модель семейства GPT предсказывает каждое слово по *всем* предыдущим и справляется с последовательностями в несколько тысяч токенов. Можно ли генерировать изображения так же, как GPT генерирует текст?

Мешает длина. Self-attention сравнивает каждую позицию с каждой предыдущей, поэтому последовательность в 100 раз длиннее обходится одному слою в 10 000 раз дороже. Обходной путь — изменить то, что считается токеном: в ImageGPT это цвет палитры у маленького изображения, в VQGAN, DALL·E и Parti — код обученного дискретного автоэнкодера. Когда изображение стало короткой последовательностью кодов, генерация по тексту превращается в продолжение подписи.

## От свёрток к вниманию \{#from-convolutions-to-attention\}

Трансформер, состоящий из одного декодера, — это стопка блоков: в каждом слой self-attention, а за ним небольшая сеть, применяемая к каждой позиции отдельно, оба с остаточными связями. Self-attention — это блок из [SAGAN](/ru/notes/generative-models/gan-scaling#the-self-attention-block): каждая позиция берёт взвешенное среднее значений (values) видимых ей позиций с весами softmax от оценок «запрос — ключ». Здесь у него есть **каузальная маска** (causal mask): оценки более поздних позиций перед softmax заменяются на $-\infty$, их веса равны $e^{-\infty} = 0$, и выход первого слоя в позиции $i$ зависит только от позиций $1, \dots, i$. Сеть, применяемая к каждой позиции, и остаточные связи ничего не смешивают между позициями, поэтому по индукции по слоям то же верно для каждого слоя. Если вы прошли курс NLP, его [заметка о внимании](/ru/notes/nlp/attention#masks) подробно выводит self-attention и маски; здесь это необязательный фон.

Сеть моделирует последовательность токенов $s = (s_1, \dots, s_N)$ из словаря размера $K$ по формуле умножения вероятностей из [предыдущей заметки](/ru/notes/generative-models/autoregressive-models#the-chain-rule-as-a-model), $p(s) = \prod_i p(s_i \mid s_{<i})$. Сетка из $h \times w$ токенов читается построчно, так что $N = hw$. Обучение такое же, как в [предыдущей заметке](/ru/notes/generative-models/autoregressive-models#parallel-training-sequential-sampling): один параллельный проход с teacher forcing и кросс-энтропия в каждой позиции.

Две детали соответствуют PixelCNN. Маска не пускает более поздние токены, а **сдвиг** не пускает саму цель: вход — $(\text{BOS}, s_1, \dots, s_{N-1})$ с начальным токеном BOS, и выход во входной позиции $i$, который видел $(\text{BOS}, s_1, \dots, s_{i-1})$, предсказывает $s_i$. Маска A в PixelCNN делала и то и другое сразу, скрывая центр. И [слепого пятна](/ru/notes/generative-models/autoregressive-models#the-blind-spot) нет: каждый слой может обратиться к любой предыдущей позиции.

Платить приходится числом пар. Позиция $i$ обращается к $i$ позициям, так что один слой сравнивает

$$
\sum_{i=1}^{N} i = \frac{N(N+1)}{2}
$$

пар. Эта стоимость растёт как квадрат длины последовательности, и она решает, какими могут быть токены изображения.

<SequenceLengths />

Сэмплирование умножает стоимость ещё раз. Если для токена $t$ заново прогонять сеть по всему префиксу длины $t$, на слой сравнивается $t(t+1)/2$ пар. Чтобы просуммировать по $t$, разложим разность двух соседних произведений:

$$
\begin{aligned}
&t(t+1)(t+2) - (t-1)t(t+1) \\
&\quad = t(t+1)\big[(t+2) - (t-1)\big] \\
&\quad = 3\,t(t+1) .
\end{aligned}
$$

При суммировании от $t = 1$ до $N$ левая часть телескопически сокращается до $N(N+1)(N+2) - 0$, так что $\sum_{t=1}^{N} t(t+1) = N(N+1)(N+2)/3$; половина этого — итог без кэша. С кэшем шаг $t$ сравнивает один новый запрос с $t$ ключами:

$$
\begin{aligned}
\text{без кэша:}\quad \sum_{t=1}^{N} \frac{t(t+1)}{2} &= \frac{N(N+1)(N+2)}{6}, \\
\text{KV-кэш:}\quad \sum_{t=1}^{N} t &= \frac{N(N+1)}{2} .
\end{aligned}
$$

Ключи и значения прежних позиций не меняются, когда добавляется токен: по индукции выше состояние позиции $j$ в каждом слое зависит только от токенов $1, \dots, j$. Поэтому **KV-кэш** (KV cache) хранит их и вычисляет внимание только для нового запроса. Для сетки из $N = 1024$ токенов это 179 481 600 пар на слой без кэша и 524 800 с ним, в $(N+2)/3 = 342$ раза меньше. Расплата памятью — два вектора на слой и позицию.

Предсказанное распределение превращают в сэмпл три настройки. **Температура** (temperature) $T$ делит логиты на $T$ перед softmax; при $T < 1$ разрывы между логитами растут, и масса переходит к самым вероятным значениям. **Top-$k$** оставляет $k$ самых вероятных значений, а **top-$p$** — наименьший набор самых вероятных значений, сумма вероятностей которых не меньше $p$; оставленные значения перенормируются. Все три реализованы в разделе с кодом. На изображениях они действуют как [трюк усечения](/ru/notes/generative-models/gan-scaling#the-truncation-trick) у GAN, что видно по результатам VQGAN ниже.

## Пиксели как токены: ImageGPT \{#pixels-as-tokens-imagegpt\}

ImageGPT ([Chen et al., 2020](#references)) применяет GPT-2 к изображениям с минимумом изменений. Изображение $224 \times 224 \times 3$ — это $150\,528$ значений; по сравнению с контекстом GPT-2 из 1024 токенов матрица внимания была бы в $(150\,528 / 1024)^2 = 147^2 = 21\,609$ раз больше. Поэтому изображение сначала уменьшают до $32 \times 32$ или $48 \times 48$, а три канала каждого пикселя заменяют ближайшим из 512 цветов, найденных [k-means](/ru/notes/ml/clustering): получается последовательность из 1024 или 2304 токенов над словарём из 512. Палитра — простейший токенизатор, VQ-VAE с тождественными энкодером и декодером. Самая большая модель, iGPT-L, — это GPT-2 с 48 слоями и шириной 1536, 1.4 миллиарда параметров.

Статью прежде всего интересует представление. Модель, обученная только предсказывать следующий пиксель, выучивает признаки, по которым линейный классификатор поверх них даёт на CIFAR-10 долю правильных ответов (accuracy) 96.3%, а после дообучения — 99.0%. Её последовательности описывают лишь изображения $32 \times 32$ или $48 \times 48$: пиксельные токены не масштабируются до больших размеров.

## Обученные токены: двухэтапный рецепт \{#learned-tokens-the-two-stage-recipe\}

Выход уже был в [VQ-VAE](/ru/notes/generative-models/vae-variants#where-the-prior-went): сначала обучить дискретный автоэнкодер, затем авторегрессионную модель над его кодами. При коэффициенте понижения разрешения $f$ изображение $H \times W$ становится сеткой из $(H/f) \times (W/f)$ токенов, и трансформер не видит ни одного пикселя.

<TwoStage />

Два этапа делят работу так же, как в [латентной диффузии](/ru/notes/generative-models/latent-diffusion), которая появилась позже в той же группе, что и VQGAN: токенизатор отвечает за текстуры и мелкие детали, трансформер — за композицию. Поэтому токенизатор должен сильно сжимать и всё же восстанавливать резкие изображения, а обычный VQ-VAE с квадратичной функцией потерь этого не умеет.

### VQGAN \{#vqgan\}

VQGAN ([Esser, Rombach and Ommer, 2021](#references)) сохраняет векторный квантизатор, кодовую книгу и слагаемые commitment из VQ-VAE и меняет функцию потерь реконструкции. Квадратичная ошибка заменяется перцептивной функцией потерь, как в [LPIPS](/ru/notes/generative-models/lpips), а дискриминатор по патчам решает, настоящие ли небольшие фрагменты реконструкции. Масштабы двух функций потерь сильно различаются, и состязательная получает адаптивный вес

$$
\lambda = \frac{\lVert \nabla_{G_L} \mathcal L_{\text{rec}} \rVert}{\lVert \nabla_{G_L} \mathcal L_{\text{GAN}} \rVert + \delta},
$$

где $G_L$ — последний слой декодера, а $\delta = 10^{-6}$ защищает от деления на ноль. До $G_L$ доходит градиент $\nabla \mathcal L_{\text{rec}} + \lambda \nabla \mathcal L_{\text{GAN}}$, и при таком $\lambda$ норма второго слагаемого равна $\lVert \nabla \mathcal L_{\text{rec}} \rVert \cdot \lVert \nabla \mathcal L_{\text{GAN}} \rVert / (\lVert \nabla \mathcal L_{\text{GAN}} \rVert + \delta) \approx \lVert \nabla \mathcal L_{\text{rec}} \rVert$: ни одна функция потерь не подавляет другую.

При $f = 16$ изображение $256 \times 256$ становится сеткой $16 \times 16$, а кодовая книга по умолчанию в статье содержит $K = 1024$ кода:

| Величина | Значение |
| --- | --- |
| токенов на изображение | $16 \cdot 16 = 256$ |
| бит на токен, $\log_2 1024$ | 10 |
| бит на изображение | 2560 |
| исходные пиксели, $256 \cdot 256 \cdot 3 \cdot 8$ | 1 572 864 бита |

В токенах примерно в 614 раз меньше бит, чем в пикселях. Второй этап — трансформер GPT-2 medium с 307 миллионами параметров, и 256 токенов были самой длинной последовательностью, при которой его обучение помещалось на GPU с 12 ГБ. Условия добавляются в начало как токены: метка класса или коды карты сегментации либо карты глубины, полученные вторым VQGAN. Изображения мегапиксельного размера генерируются со скользящим окном внимания: каждый токен предсказывается по окрестности $16 \times 16$ кодов.

### Настройки сэмплирования на изображениях \{#sampling-knobs-on-images\}

Модель VQGAN для ImageNet с условием на класс и 16 384 кодами показывает, как много значат настройки сэмплирования ([Esser, Rombach and Ommer, 2021](#references), таблица 4):

| Сэмплирование | FID |
| --- | --- |
| top-$k$, $k = 973$ | 29.20 |
| top-$k$, $k = 250$ | 15.98 |
| top-$k$ 973 и top-$p$ 0.88 | 15.78 |
| смешанные $k$, лучшие 5% по классификатору ResNet-101 | 5.88 |
| BigGAN для сравнения | 7.53 |

Строки фильтруют по разным оценкам. Top-$k$ и top-$p$ на каждом шаге отбрасывают коды, которые сама модель считает маловероятными. Строка с классификатором вытягивает целые изображения и оставляет 5% с наибольшей оценкой ResNet-101 для их класса: она фильтрует по уверенности классификатора, а не по правдоподобию модели. Каждая строка лишь убирает или перевзвешивает сэмплы самой модели, поэтому ни одна не добавляет сэмплов там, где у модели нет массы; такая фильтрация меняет [полноту на точность](/ru/notes/generative-models/precision-recall#where-the-trade-off-appears). FID улучшается потому, что оставшиеся сэмплы типичнее для своего класса; данные модель охватывает не лучше.

## Текст в изображение: DALL·E \{#text-to-image-dalle\}

DALL·E ([Ramesh et al., 2021](#references)) применяет рецепт в большом масштабе. Его токенизатор, дискретный VAE, переводит изображение $256 \times 256$ в сетку $32 \times 32$ над 8192 кодами: 1024 токена вместо $196\,608$ значений, в 192 раза меньше. Подпись кодируется не более чем 256 BPE-токенами из словаря на 16 384, и токены текста и изображения склеиваются в одну последовательность. Весь поток моделирует один трансформер-декодер с 12 миллиардами параметров и разреженным вниманием, обученный на 250 миллионах пар «изображение — подпись». Генерация — это продолжение подписи: подаём токены текста и вытягиваем 1024 токена изображения.

Сэмплы вытягиваются пачками и ранжируются заново: контрастная модель изображений и текстов ([CLIP](/ru/notes/deep-learning/vision-transformers#clip-contrastive-pretraining-on-images-and-captions)) оценивает каждого из 512 кандидатов по соответствию подписи, и остаются лучшие. В сравнении с DF-GAN, GAN, обученной на MS-COCO, люди сочли сэмпл DALL·E более реалистичным в 90.0% случаев и лучше соответствующим подписи в 93.3%, хотя DALL·E никогда не обучалась на подписях MS-COCO.

## Parti: энкодер–декодер в большом масштабе \{#parti-an-encoder-decoder-at-scale\}

Parti ([Yu et al., 2022](#references)) рассматривает генерацию по тексту как перевод. Энкодер читает подпись, а декодер генерирует 1024 токена изображения ViT-VQGAN, то есть VQGAN, у которого энкодер и декодер — визуальные трансформеры, с 8192 кодами. Небольшая сеть сверхразрешения (super-resolution) поднимает декодированные изображения $256 \times 256$ до $1024 \times 1024$. Качество и соответствие тексту продолжают расти от 350 миллионов до 20 миллиардов параметров; самая большая модель достигает на MS-COCO FID 7.23 без обучения на нём (zero-shot).

Сэмплы улучшают два инструмента из других семейств. [Classifier-free guidance](/ru/notes/generative-models/latent-diffusion#classifier-free-guidance) работает на логитах так же, как на score: модель обучают, иногда выбрасывая подпись, а при сэмплировании безусловное и условное предсказания комбинируются с весом больше единицы. Из какого распределения это сэмплирует, выводится в [заметке о звуке](/ru/notes/generative-models/audio-generation#classifier-free-guidance-on-logits). Переранжирование оставляет лучший из 16 сэмплов на запрос вместо 512 у DALL·E. Статья о Parti также ввела PartiPrompts — набор из более чем 1600 запросов, описанный в [заметке об оценке людьми](/ru/notes/generative-models/human-evaluation#how-good-and-does-it-match).

## Где это ломается \{#where-it-breaks\}

Токенизатор ограничивает то, что может выдать трансформер, потому что каждый сэмпл — выход декодера. В VQGAN с $f = 16$ один токен заменяет фрагмент $16 \times 16$, то есть $16 \cdot 16 \cdot 3 \cdot 8 = 6144$ бита пикселей, и несёт 10 бит. Детали, которые кодовая книга не может выразить, например мелкий текст или маленькое лицо в толпе, теряются в каждом сэмпле. На ImageNet реконструкции через сетку $16 \times 16$ имеют [FID](/ru/notes/generative-models/fid) 7.94 относительно валидационных изображений при 1024 кодах и 4.98 при 16 384, против 32.01 у токенизатора DALL·E — сетки $32 \times 32$ из 8192 кодов, обученной без перцептивной и состязательной функций потерь ([Esser, Rombach and Ommer, 2021](#references), таблица 5). Статья о VQGAN считает это число оценкой FID, достижимого на втором этапе. Это эмпирический ориентир: он измеряет реконструкции, а априорная модель, которая иначе распределяет массу по выходам декодера, может получить FID и выше, и ниже.

Второе ограничение — порядок сэмплирования. Вытянутый токен больше не пересматривается, и ранняя ошибка в левом верхнем углу определяет всё, что идёт после неё. Диффузионная модель уточняет весь латент за 20–50 шагов и может себя исправить; авторегрессионной модели нужно 1024 последовательных прохода для сетки $32 \times 32$. Остальное у двух семейств теперь общее: отдельно обученный автоэнкодер, условие на текст через внимание и classifier-free guidance. Авторегрессионное семейство добавляет к этому точное правдоподобие токенов, а также архитектуру, код обучения и поведение при масштабировании, общие с языковыми моделями.

## Что нужно запомнить \{#what-you-should-remember\}

- Каузальный трансформер — это PixelCNN без слепого пятна; один слой стоит $N(N+1)/2$ пар.
- KV-кэш сокращает наивное сэмплирование с $N(N+1)(N+2)/6$ пар на слой до $N(N+1)/2$.
- ImageGPT укорачивает последовательности пикселей маленьким изображением и палитрой из 512 цветов.
- Два этапа: дискретный автоэнкодер делает токены, трансформер их моделирует.
- VQGAN: перцептивная и состязательная функции потерь с адаптивным весом делают токены $16 \times 16$ резкими.
- DALL·E помещает подпись в последовательность, Parti — в энкодер; top-$k$, top-$p$ и переранжирование меняют разнообразие на типичность сэмплов.

## Код \{#code\}

Небольшой трансформер-декодер на NumPy с каузальной маской, KV-кэшем и фильтрами сэмплирования. Он проверяет, что логиты с кэшем и без него совпадают, что изменение более позднего токена не меняет более ранних предсказаний, и печатает числа пар для $N = 1024$.

```python
import numpy as np

rng = np.random.default_rng(0)
V, d, L, max_len = 16, 32, 2, 64                   # словарь, ширина, слои, позиции
emb, pos = rng.normal(size=(V, d)), rng.normal(size=(max_len, d))
Wq, Wk, Wv, Wo = (rng.normal(size=(L, d, d)) / np.sqrt(d) for _ in range(4))
head = rng.normal(size=(d, V)) / np.sqrt(d)

def softmax(z):
    z = np.exp(z - z.max(-1, keepdims=True))
    return z / z.sum(-1, keepdims=True)

def forward(tokens, cache=None, start=0):
    """Logits for tokens at positions start .. start+T-1; cache holds keys and values of earlier positions."""
    x = emb[tokens] + pos[start:start + len(tokens)]
    for l in range(L):
        q, k, v = x @ Wq[l], x @ Wk[l], x @ Wv[l]
        if cache is not None:
            k = np.concatenate([cache[l]['k'], k]) if cache[l] else k
            v = np.concatenate([cache[l]['v'], v]) if cache[l] else v
            cache[l] = {'k': k, 'v': v}
        scores = q @ k.T / np.sqrt(d)               # [T, S]: новые запросы против всех видимых ключей
        qpos = start + np.arange(len(tokens))[:, None]
        scores[np.arange(k.shape[0])[None, :] > qpos] = -np.inf   # каузальная маска: без более поздних ключей
        x = x + softmax(scores) @ v @ Wo[l]
    return x @ head

def filter_logits(z, temperature=1.0, top_k=None, top_p=None):
    z = z / temperature
    if top_k is not None:                           # оставить k наибольших логитов
        z = np.where(z < np.sort(z)[-top_k], -np.inf, z)
    if top_p is not None:                           # наименьший набор, вероятность которого достигает top_p
        order = np.argsort(-z)
        p = softmax(z)[order]
        drop = np.cumsum(p) - p >= top_p            # масса до этого токена уже достигает top_p
        z[order[drop]] = -np.inf
    return z

# сгенерировать 20 токенов с кэшем, по одному новому токену за проход
cache = [{} for _ in range(L)]
seq = [1, 2, 3]
logits = forward(np.array(seq), cache)
for _ in range(20):
    probs = softmax(filter_logits(logits[-1], temperature=0.7, top_k=5))
    seq.append(int(rng.choice(V, p=probs)))
    logits = forward(np.array(seq[-1:]), cache, start=len(seq) - 1)

full = forward(np.array(seq[:-1]))                 # все позиции пересчитаны заново
c = [{} for _ in range(L)]                         # те же позиции, по одному токену за проход
step = np.concatenate([forward(np.array([t]), c, start=i) for i, t in enumerate(seq[:-1])])
print('max |cached - full| =', float(np.abs(full - step).max()))
a = np.array(seq[:10]); b = a.copy(); b[7] = (b[7] + 1) % V
print('earlier logits unchanged:', np.allclose(forward(a)[:7], forward(b)[:7]))

N = 1024                                           # пар на слой при сэмплировании N токенов
print(N * (N + 1) * (N + 2) // 6, N * (N + 1) // 2, (N + 2) / 3)

z = np.array([2.0, 1.5, 1.0, 0.0, -1.0])
for kw in [{}, {'temperature': 0.7}, {'top_k': 3}, {'top_p': 0.7}]:
    print(kw, softmax(filter_logits(z.copy(), **kw)).round(3))
```
