В слое интеграции товар 7 означает пачку чая. Новый источник начинает передавать материал упаковки. У старых записей есть название и масса, а материала нет. Нужны место для новых фактов и способ по-прежнему читать товары без этого свойства.

## Отделяем идентификатор от каждого атрибута \{#separate-identity-from-each-attribute\}

**Якорь** (anchor) представляет идентичность объектов одного вида. В якоре товара есть идентификатор 7. Таблица **атрибута** связывает идентификатор с одним свойством. Неизменную массу можно записать один раз. У названия с историей несколько значений с разными датами. **Связь** (tie) соединяет идентификаторы, например магазин 11 и товар 7 в ассортименте. **Узел** (knot) представляет общий набор значений. Граммы и миллилитры можно задать в узле вместо произвольного текста у каждого товара. [Rönnbäck и др., 2010](#references)

Сравним детализацию с Data Vault. Таблица атрибута Anchor описывает одно свойство. Сателлит Vault обычно группирует свойства, которые приходят из одного источника или меняются вместе. Раздельные свойства дают независимую историю и схему, а для широкой выдачи могут понадобиться дополнительные соединения. [Rönnbäck и Hultgren, 2013](#references)

## Читаем товар на выбранную дату \{#read-the-product-at-a-chosen-time\}

Даты ниже задают время действия. Считаем, что у товара одно значение на дату начала и что старые даты не исправляли позже. Для 4 ноября последнее подходящее название действует с 1 ноября. В примере таблица материала пуста. Внешнее соединение сохраняет товар 7 без строки о материале.

```sql
WITH product(product_id) AS (VALUES (7)),
product_name(product_id, valid_from, name) AS (
    VALUES (7, DATE '2026-11-01', 'Tea 50 g'),
           (7, DATE '2026-11-05', 'Black tea 50 g')
),
product_material(product_id, material) AS (
    SELECT 7, 'paper'::text WHERE FALSE
)
SELECT p.product_id, n.name, m.material
FROM product AS p
LEFT JOIN LATERAL (
    SELECT name
    FROM product_name
    WHERE product_id = p.product_id
      AND valid_from <= DATE '2026-11-04'
    ORDER BY valid_from DESC
    LIMIT 1
) AS n ON TRUE
LEFT JOIN product_material AS m USING (product_id);
```

Получаем `(7, 'Tea 50 g', NULL)`. Подзапрос `LATERAL` может обратиться к текущему идентификатору товара. Без условия по времени соединение с обоими названиями могло бы дать две строки для товара 7. Представление может отдавать собранный товар с фиксированным набором столбцов, а новый потребитель может выбрать более широкое представление. [PostgreSQL 18, §7.2.1](#references)

В примере важно различать время действия названия и момент, когда оно стало известно. Чтобы спросить, что 4 ноября хранилище знало о названии, действующем с 1 ноября, нужна также история поступления или утверждений. Разделение атрибутов само по себе её не создаёт. Нужны правила и ключи для второй временной оси.
