Начальная выгрузка читает заказ 101 на 700 копеек. Пока она копирует другие заказы, касса меняет сумму на 900. Если начать следить за изменениями только после окончания выгрузки, у приёмника могут навсегда остаться 700. Копии нужна согласованная позиция, начиная с которой доступны более поздние изменения.

## Связываем снимок и журнал \{#couple-the-snapshot-and-the-log\}

**Захват изменений** (change data capture, CDC) представляет изменения базы в виде записей, которые потребитель может применить. При захвате из журнала читатель интерпретирует журнал базы вместо сравнения последовательных выгрузок. Логическое декодирование PostgreSQL преобразует сведения WAL в упорядоченный поток логических изменений для клиента. MySQL использует двоичный журнал для похожей задачи. Форматы на уровне команд и строк записывают разные сведения. Коннектор CDC должен понимать представление источника. [PostgreSQL 18, §47.2](#references) [MySQL 8.4, §7.4.4](#references)

Начальный снимок задаёт исходное содержимое. Протокол источника связывает снимок с позицией журнала, с которой нужно продолжить чтение. При стандартном начальном снимке коннектор Debezium для PostgreSQL запоминает позицию и читает нужные строки из согласованного снимка. Затем он передаёт изменения с соответствующей точки. Протокол закрывает разрыв из начала конспекта. Независимое чтение текущего конца WAL после снятия копии такой гарантии не даёт. [Debezium, Snapshots](#references)

Возьмём три условные позиции одной истории источника. На границе снимка 20 сумма заказа 101 равна 700. Зафиксированное обновление в 21 меняет её на 900. Зафиксированное удаление в 22 убирает заказ. После загрузки снимка и применения журнала в порядке источника приёмник показывает сначала 700, потом 900, затем заказ 101 отсутствует.

## Применяем операции по их смыслу \{#apply-each-operation-by-its-meaning\}

Запись снимка сообщает о существовании строки на границе снимка. Обновление может заменить целевую строку по ключу её новыми значениями. Удаление требует убрать ключ или записать факт удаления согласно модели приёмника. В записях Debezium для PostgreSQL коды операций различают чтение снимка, вставку, обновление и удаление. Наличие прежних значений зависит от replica identity источника и настроек коннектора. Полная прежняя строка присутствует не при каждом удалении. [Debezium, Data change events and Replica identity](#references)

После удаления Debezium также может выдать Kafka tombstone. Удаление описывает изменение источника. Tombstone — запись с тем же ключом и значением null, используемая при уплотнении журнала Kafka. Если присутствуют обе формы, потребителю нужно правило для каждой.

Позиция источника указывает коннектору, где продолжить в конкретной истории. Одна транзакция может дать несколько изменений строк. Для устранения повторов отдельных изменений нужен идентификатор, различающий их в пределах истории. Помимо транзакции или позиции журнала могут понадобиться идентификатор источника и порядковый номер изменения внутри транзакции.

## Сохраняем возможность повтора \{#keep-replay-possible\}

Слот логической репликации PostgreSQL может удерживать WAL, который нужен потребителю. Поэтому остановившийся потребитель способен косвенно занять место на диске удержанными сегментами. Если нужная история удалена или слот стал недействительным, старый курсор сам её не восстановит. Коннектору понадобится новый согласованный старт или другой источник пропущенного интервала. [PostgreSQL 18, §47.2](#references)

После сбоя источника логический слот может вернуться к более ранней позиции. Отдельный сбой возможен между публикацией изменения коннектором и сохранением его позиции. Недавние изменения могут поступить повторно, если для всего пути коннектора не задана более строгая гарантия. Немедленный повтор обновления 21 поверх той же версии может оставить 900. Если применить его после удаления, строка появится заново. Потребителю, который допускает повторы с нарушением порядка, нужны сведения о версиях, включая состояние удаления, чтобы отклонять устаревшие изменения. [PostgreSQL 18, §47.2](#references) [Debezium, Behavior when things go wrong](#references)
