В выгрузке продаж десять полей на заказ. Загрузчик кассы читает все поля. Аналитику для суммы по одному магазину нужны только идентификатор магазина и сумма. Логические записи одни и те же. Размещение байтов определяет, сколько придётся передать и декодировать.

## Закодируем запись целиком \{#encode-one-record-at-a-time\}

**Сериализация** (serialization) переводит типизированные значения в байты. Avro задаёт значения и их порядок схемой писателя. Для записи с полями `order_id`, `shop_id` и `amount_cents` двоичное кодирование записывает поля в порядке схемы. Имена полей не дублируются в каждой двоичной записи. Контейнерный файл Avro хранит схему писателя в заголовке и размещает записи в блоках, которые могут сжиматься. Маркеры синхронизации отмечают границы блоков и помогают разделить файл для параллельного чтения. ([Apache Avro 1.12.0, Binary Encoding и Object Container Files](#references))

Новый читатель может ожидать поле `channel`, которого нет в старых записях. При **согласовании схем** (schema resolution) читатель интерпретирует старые байты по схеме писателя и сопоставляет поля с запрошенной схемой. Если в схеме читателя есть значение по умолчанию, например `"unknown"`, оно заполняет отсутствующее поле. Без подходящего значения по умолчанию пропуск обязательного для читателя поля даёт ошибку. Значение по умолчанию не меняет старый файл и не разрешает писателю пропускать поле собственной схемы. ([Apache Avro 1.12.0, Schema Resolution](#references))

При размещении по записям значения полей одного заказа лежат рядом. Это удобно, когда потребитель декодирует заказ целиком. Читатель может не передавать лишние поля приложению, хотя сжатые блоки Avro не выделяют каждому столбцу отдельный непрерывный диапазон байтов.

## Прочитаем столбцы в каждой группе строк \{#read-columns-in-each-row-group\}

Parquet делит файл на **группы строк** (row groups). Внутри группы значения одного столбца занимают **фрагмент столбца** (column chunk). Фрагмент содержит **страницы** (pages), на которых значения кодируются и могут сжиматься. Читатель загружает метаданные из хвоста файла и находит фрагменты. Для суммы с фильтром по магазину нужны `shop_id` для условия и `amount_cents` для агрегата. Остальные восемь столбцов можно пропустить. ([Apache Parquet, File Format](#references))

Пусть учебный файл содержит 300 МиБ данных, поровну распределённых между десятью столбцами. Для чтения двух столбцов во всех группах нужно $300\cdot2/10=60$ МиБ полезных данных без хвоста и накладных расходов запросов. Экономию даёт **проекция столбцов** (column projection). Мы ещё не предполагаем, что можно пропустить какую-либо группу строк. Реальные фрагменты имеют разные размеры, а фильтр по дополнительному столбцу может увеличить объём чтения.

В столбце собраны значения одного поля, поэтому кодирование может использовать повторы или малые различия. Например, словарное кодирование хранит повторяющиеся идентификаторы магазинов как коды из словаря. Сжатие может дополнительно уменьшить закодированный объём. Само размещение по столбцам не задаёт коэффициент сжатия. При большом числе различных значений неподходящее кодирование мало помогает, а при чтении всех полей пропадает выигрыш от проекции. ([Apache Parquet, Encodings и Compression](#references))

## Сохраним границы вложенных записей \{#preserve-nested-record-boundaries\}

У заказа может быть список товаров. По одному столбцу цен товаров нельзя понять, где заканчивается один заказ и начинается следующий. Вложенное кодирование Parquet хранит **уровни повторения** (repetition levels), которые показывают, где снова начинается повторяемая часть пути поля, и **уровни определения** (definition levels), которые показывают, до какой глубины существует путь к значению. По этим сигналам читатель восстанавливает нужную структуру записи. В Dremel описано это представление и чтение выбранных полей вложенных записей. ([Apache Parquet, Nested Encoding](#references), [Melnik et al., §§3–4](#references))

Формат даёт читателю размещение внутри одного файла. Чтобы работать с целым набором, ещё нужно определить, какие файлы в него входят и как они разделены по датам.
