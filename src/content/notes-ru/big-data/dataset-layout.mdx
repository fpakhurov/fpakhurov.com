Аналитику нужны продажи магазина 150 за один день. Чтение двух столбцов из каждого файла всё равно затрагивает неделю данных. Удачное размещение позволяет исключить по дате шесть дней, а по идентификатору магазина — большую часть оставшихся файлов до передачи их содержимого.

## Пропустим части, которые не могут подойти \{#skip-parts-that-cannot-match\}

**Партиция набора данных** (dataset partition) группирует данные по значению или преобразованию, например по торговому дню, полученному из метки времени. Планировщик может исключать файлы по предикату. Это отдельная задача от назначения владельца шарду в [партиционировании и перераспределении](/ru/notes/big-data/partitioning). У одного дня может быть много файлов, которые читают разные исполнители.

Пусть есть семь дней, по четыре файла на 128 МиБ в каждом, а запросу нужен один полный день. Без отбора это $7\cdot4=28$ файлов и $28\cdot128=3584$ МиБ. Если метаданные указывают день каждого файла, движок оставит четыре кандидата на 512 МиБ при чтении целиком. Проекция столбцов может сократить объём дальше. Iceberg называет преобразование предиката исходного столбца в ограничения на значения партиции **скрытым партиционированием** (hidden partitioning). Запрос фильтрует метку времени, а метаданные описывают преобразование в день. Если фильтр отсекает только часть партиции, оставшиеся строки всё равно нужно проверить. ([Apache Iceberg 1.10.0, Partitioning](#references))

## Разложим диапазоны так, чтобы границы исключали файлы \{#arrange-ranges-so-bounds-can-exclude-files\}

Пусть четыре файла за нужный день имеют диапазоны идентификаторов магазина 1–99, 100–199, 200–299 и 300–399. Только второй может содержать магазин 150. Границы исключают ещё три файла. Они не доказывают наличие 150 в оставшемся. Читатель всё равно проверяет предикат. До проекции остаётся один кандидат на 128 МиБ.

Чтобы получить узкие границы файлов, размещаем близкие идентификаторы магазинов в одних файлах. Сортировка уже перемешанного файла может сузить границы групп строк или страниц, сохранив широкий диапазон целого файла. Для исключения работы нужны метаданные соответствующего уровня. Необязательные индексы страниц Parquet хранят статистику и смещения для пропуска страниц. Iceberg хранит сведения о партициях и метрики файлов в манифестах. Два уровня могут исключать разные чтения. ([Apache Parquet, Page Index](#references), [Apache Iceberg, Table Spec](#references))

Более дробный ключ полезен, если он заметно сокращает работу. Партиция по номеру заказа создала бы много маленьких групп, а отчёту за день пришлось бы прочитать множество групп. Партиция по дню оставляет фильтры по магазину размещению и статистике внутри дня. Выбор зависит от того, какие фильтры встречаются вместе и сколько данных записывается на группу.

## Объединим маленькие файлы, сохранив строки \{#merge-small-files-without-changing-the-rows\}

Множество маленьких файлов заставляет движок повторять открытия, чтение метаданных и планирование. Пусть одна партиция хранит 1000 МиБ в тысяче файлов по 1 МиБ. При уплотнении перепишем эти строки в восемь файлов по 125 МиБ. В учебном расчёте полезный объём остаётся прежним. При фиксированных 4 мс на открытие последовательная работа сокращается с $1000\cdot4=4000$ мс до $8\cdot4=32$ мс. Это подсчёт работы в модели. Параллельные открытия, кэш и ограничения запросов меняют фактическое время. Spark отдельно учитывает оценку стоимости открытия при группировке файловых входов в задачи. ([Apache Spark 4.0.0, Performance Tuning](#references))

**Уплотнение файлов** (compaction) расходует чтение и запись сейчас, чтобы уменьшить будущие накладные расходы. При одинаковом закодированном размере переписывание прочитает 1000 МиБ и запишет 1000 МиБ без учёта метаданных. Некоторым запросам нужны меньшие файлы ради параллельности или узких границ. Объединяем внутри подходящих групп или кластеризуем по частым предикатам, чтобы зря не расширять диапазоны. В Iceberg переписывание мелких файлов входит в операции обслуживания. ([Apache Iceberg 1.10.0, Maintenance](#references))

Замена также меняет набор файлов для чтения. Если прочитать и старую тысячу, и новые восемь, каждая строка повторится. Если убрать старые до публикации новых, возникнет пропуск. Читателю нужен полный набор файлов одной зафиксированной версии.
