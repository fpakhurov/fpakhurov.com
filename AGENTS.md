# Course content and source rights

Before writing or revising course content, read `docs/content/source-policy.md`.
It applies to every course, both languages, examples, figures, questions, hints,
notebooks, code, datasets and model assets. Read the local authoring guide too.

- Keep the existing curriculum IDs and prerequisite graph unless the user requests a structure change.
- Review and publish fpakhurov.com notes first; derive BIASED only from a pinned reviewed note revision.
- Public access, personal notes, a citation or a repository-wide license badge is not per-asset clearance.
- Do not reintroduce withdrawn text, code, data, examples or results through translation or paraphrase.
- Add current per-file provenance/review records. Do not regenerate the legacy baseline to bypass review.
- Preserve license notices and attribution. Check assets separately from libraries and repositories.
- Never describe inventory coverage, a link check or CI success as complete rights clearance.
- Run `npm run rights:check` and the normal content/build checks before publication.
