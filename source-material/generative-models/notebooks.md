## Source details to review before reuse

- **Historical wrapper name:** page 2 says “Distribution wrapper.” The reviewed `distances.ipynb` uses `create_distr` and `sample` helpers, plus mixture-target classes. The literal historical wrapper class remains unidentified. Black/pre-commit reminders are presenter tooling notes; they are not setup instructions supplied by this notebook.
- **Training-background implementation:** the AE first block uses a bias-free convolution and per-channel BatchNorm with default affine/running-statistics settings; VAE puts normalization after LeakyReLU in its normalized blocks. AE decoder upsampling is bilinear, while VAE uses nearest-neighbor upsampling. Architecture hyperparameters stay fixed while kernel values are learned. The selected blocks do not explicitly call a Xavier initializer. AE cell 17 has saved losses over five epochs, but neither snapshot records gradient norms or a causal BatchNorm comparison; the new derivative diagrams are analytic illustrations.
- **JS implementation:** `distances.ipynb` cell 21 sets the mixture to `(P + Q) / 2` but returns `0.7 KL(P || M) + 0.3 KL(Q || M)`. This differs from symmetric JS. The theoretical definition in the site retains equal weights. The model-side samples also come from `Q.sample()`, which does not create a differentiable path through the draws. Ordinary `backward()` misses the dependence of their sampling distribution on the model parameters; the source loop is not a complete JS-gradient estimator. See the [PyTorch discussion of score-function and pathwise estimators](https://docs.pytorch.org/docs/stable/distributions.html#pathwise-derivative).
- **Density MSE:** `distances.ipynb` cell 26 draws a new `x` but reuses an earlier `px`. Recompute the target density on the same points before presenting this as a coordinate-matched density comparison.
- **LPIPS preprocessing:** `metrics.ipynb` cell 13 only resizes a grayscale image and wraps its array as a tensor. It does not explicitly supply the documented RGB batch/channel layout or default input scaling. Notebook retrieval assertions are exercise criteria, not universal metric guarantees.
- **GAN labels and objectives:** `GANs.ipynb` cell 13 smooths both real discriminator labels and the generator's desired labels to `0.9`. The generator's BCE therefore differs from the ideal target-1 non-saturating objective in the scan. In the f-GAN section, cell 32 defaults to maximizing the fake score rather than using the fake term of the direct minimax objective.
- **WGAN constraints:** cells 11/13 explicitly omit Lipschitz enforcement. Attribute this as an unconstrained baseline; discuss gradient penalty and spectral normalization in their own sections. The SN critic in cell 23 includes affine InstanceNorm, so normalizing its convolution weights alone does not establish a global 1-Lipschitz guarantee.
- **VAE formula and reductions:** cell 16's component-wise Gaussian KL is consistent with the code in 17, but its final expression using an L1 norm of log standard deviations is incorrect. Preserve the signed component sum and factor 2; distinguish `logvar = log σ²` from `log σ`. The code floors exp(logvar) at 1e-8. Reconstruction is summed squared error divided by batch size, and KL is also a batch mean. Interpreting the squared-error coefficient as Gaussian NLL implies observation variance 1/2; that variance is not explicitly declared in the notebook.
- **VAE reporting and generation:** cell 18 divides already batch-averaged losses again for reporting, so recorded values are not the usual per-image negative ELBO. Generation in 18/23 draws prior codes and returns Tanh decoder outputs without observation noise. It uses `no_grad()` but not `eval()`, so BatchNorm retains training behavior. All code execution counts are null and output lists are empty. Residual progress-widget metadata does not establish a completed run or image quality. Cell 24's beta-VAE discussion is not a saved experiment; the training call uses beta = 1.
- **Flow convention and plot:** theory in cell 2 uses latent→data maps; implemented `model(x)` maps data→latent and adds `log_det`. Cell 19 drops that determinant when coloring the grid, so it displays prior density at transformed points rather than the complete data density. Correct data density is exp(prior_logprob + log_det). All code execution counts are null and output lists empty; plotted grids are procedures, not saved outcomes.
- **Flow implementation:** reviewed [flows.py](https://github.com/HSE-LAMBDA/DeepGenerativeModels/blob/42dd64b535f5bedf1d2b3db28f2f21ce96c9f09f/seminars/09_Normalizing-Flows/nflib/flows.py), [spline_flows.py](https://github.com/HSE-LAMBDA/DeepGenerativeModels/blob/42dd64b535f5bedf1d2b3db28f2f21ce96c9f09f/seminars/09_Normalizing-Flows/nflib/spline_flows.py) and nets.py. The chosen NSF_CL uses two rational-quadratic coupling stages that update both halves in sequence; each stage is triangular, their composition need not be. Affine Real NVP is theory context, not the active notebook layer. ActNorm initializes from the first batch, then learns fixed affine parameters. Linear mixing uses a raw learned LU diagonal that must remain nonzero; it is not structurally guaranteed by that parameterization.
- **Flow visualization details:** cell 13's prior.sample([128, 2]) adds an extra sample dimension and yields (128, 2, 2), rather than 128 two-coordinate points. The visualization loop in 17 declares 500 iterations but breaks at its first plotting step, after one optimizer update. model.sample(n) returns the full inverse trajectory; its last entry is generated data. These source details do not establish a completed experiment.
- **DDPM conventions and indexing:** cells 9/13/16 use β as variance and √β as noise amplitude, resolving the scan's ambiguous notation. Coefficient index i corresponds to mathematical t = i + 1; cell 16's label x_0 already refers to the first noisy marginal. The earlier iterative demonstration includes clean data at list index 0. Reverse plotting cells 33/48 select j*10 transitions but label j*100, inconsistent with the active 100-step setup. Separate direct marginal draws do not form a correlated Markov trajectory.
- **DDPM schedule:** cell 14 selects a 100-step sigmoid variance schedule from 1e-5 to 1e-2. Exact scalar calculation gives terminal alpha-bar about 0.604954, retained signal amplitude 0.777788 and conditional noise variance 0.395046. This is substantial remaining signal, rather than a nearly pure standard-normal conditional. The illustrative density sketches use separately stated noise levels. The initial constant-beta demonstration uses 100 steps at beta = 0.0005, retaining alpha-bar about 0.951218.
- **DDPM bound and endpoint:** cell 26's ratio identity and Jensen bound are sound. Cell 27's proposed full ELBO incorrectly includes a Gaussian KL at the degenerate endpoint and uses prior/entropy terms that do not reproduce the standard bound. Cell 38 supplies the correct terminal KL, interior KL sum from t = 2, and reconstruction term. Cell 18's supposedly clipped posterior log variance still takes log(0); cell 31 samples that boundary and uses an ordinary Gaussian KL. A final reconstruction decoder must be handled separately. For a fixed forward schedule, terminal KL is independent of denoiser parameters but need not vanish.
- **DDPM unfinished variational helper:** cell 41 calls a helper expecting four mean/log-variance outputs, while the epsilon model returns two outputs; it cannot unpack the expected two chunks as written. The discretized 8-bit image decoder also differs from the continuous Swiss-roll data. These are source-level issues, not recorded failures from an executed run. The active loop in cell 48 instead uses the working noise-MSE function from cell 43.
- **DDPM loss, sampler and EMA:** cells 42–43 supply unweighted `L_simple`, an attributed reweighting of the scan's weighted interior objective. The code averages squared error across batch and coordinates and uses complementary timestep pairs with uniform marginals. Cell 36 chooses reverse variance β and adds fresh noise at every index, including the last zero index; original DDPM Algorithm 2 uses no fresh noise at mathematical t = 1. EMA shadow weights are updated with active mu = 0.9 but never applied to the sampling model. Training loops traverse the full dataset per outer pass; names such as num_iterations do not mean one optimizer update. No saved outputs establish convergence, sample quality or use of EMA at generation time.
