## Source details to review before reuse

- **Historical wrapper name:** page 2 says “Distribution wrapper.” The reviewed `distances.ipynb` uses `create_distr` and `sample` helpers, plus mixture-target classes. The literal historical wrapper class remains unidentified. Black/pre-commit reminders are presenter tooling notes; they are not setup instructions supplied by this notebook.
- **JS implementation:** `distances.ipynb` cell 21 sets the mixture to `(P + Q) / 2` but returns `0.7 KL(P || M) + 0.3 KL(Q || M)`. This differs from symmetric JS. The theoretical definition in the site retains equal weights. The model-side samples also come from `Q.sample()`, which does not create a differentiable path through the draws. Ordinary `backward()` misses the dependence of their sampling distribution on the model parameters; the source loop is not a complete JS-gradient estimator. See the [PyTorch discussion of score-function and pathwise estimators](https://docs.pytorch.org/docs/stable/distributions.html#pathwise-derivative).
- **Density MSE:** `distances.ipynb` cell 26 draws a new `x` but reuses an earlier `px`. Recompute the target density on the same points before presenting this as a coordinate-matched density comparison.
- **LPIPS preprocessing:** `metrics.ipynb` cell 13 only resizes a grayscale image and wraps its array as a tensor. It does not explicitly supply the documented RGB batch/channel layout or default input scaling. Notebook retrieval assertions are exercise criteria, not universal metric guarantees.
- **GAN labels and objectives:** `GANs.ipynb` cell 13 smooths both real discriminator labels and the generator's desired labels to `0.9`. The generator's BCE therefore differs from the ideal target-1 non-saturating objective in the scan. In the f-GAN section, cell 32 defaults to maximizing the fake score rather than using the fake term of the direct minimax objective.
- **WGAN constraints:** cells 11/13 explicitly omit Lipschitz enforcement. Attribute this as an unconstrained baseline; discuss gradient penalty and spectral normalization in their own sections. The SN critic in cell 23 includes affine InstanceNorm, so normalizing its convolution weights alone does not establish a global 1-Lipschitz guarantee.
- **VAE formula and reductions:** cell 16's component-wise Gaussian KL is consistent with the code in 17, but its final expression using an L1 norm of log standard deviations is incorrect. Preserve the signed component sum and factor 2; distinguish `logvar = log σ²` from `log σ`. The code floors exp(logvar) at 1e-8. Reconstruction is summed squared error divided by batch size, and KL is also a batch mean. Interpreting the squared-error coefficient as Gaussian NLL implies observation variance 1/2; that variance is not explicitly declared in the notebook.
- **VAE reporting and generation:** cell 18 divides already batch-averaged losses again for reporting, so recorded values are not the usual per-image negative ELBO. Generation in 18/23 draws prior codes and returns Tanh decoder outputs without observation noise. It uses `no_grad()` but not `eval()`, so BatchNorm retains training behavior. All code execution counts are null and output lists are empty. Residual progress-widget metadata does not establish a completed run or image quality. Cell 24's beta-VAE discussion is not a saved experiment; the training call uses beta = 1.
- **Flow convention and plot:** theory in cell 2 uses latent→data maps; implemented `model(x)` in 10–13 maps data→latent and adds `log_det`. Cell 19 drops that determinant when coloring the grid, so it displays prior density at transformed points rather than the complete data density.
- **DDPM conventions:** cells 9/13/16 use β as variance and √β as noise amplitude, resolving the scan's ambiguous notation. Cell 42 supplies unweighted `L_simple`, which must be attributed to the notebook rather than silently inserted into the scan's weighted objective. Cell 36 chooses variance β and adds noise at the final zero-index step; identify this sampler choice and review it against the intended endpoint convention. The ELBO explanation still needs its own mathematical review.
